# 0030. 末日幻影详情页改为层级 / 星启子 tab

## 状态

`accepted`（**已实现**：末日幻影不再渲染顶部固定条，`padding-top` 归零；层级子 tab 作为**页内并列一行**排在赛季级「污染等级」区块下方，固定条只服务另外三种模式；新增 `levels.ts` 与 `EndgameLevelTabs.vue` / `EndgameLevelPanel.vue` / `EndgameBossFloor.vue`，抽出 `EndgameBuffGroup.vue` / `EndgameTraitGroup.vue` / `EndgameTargets.vue` / `EndgameFloorBuff.vue` 复用件；`sections.ts` 对 `boss` 只保留赛季级污染等级；`endgame-detail.css` 新增 `.nk-egd-tabs` / `.nk-egd-lvl*`；**决策 2 的区块归属被 [0044](0044-首领机制随敌方卡呈现.md) 修订**）

## 背景

用户要求「以 1~4 层以及星启模式为子 tab，改造页面。将赛季增益、首领特性全部放入这些子 tab 中」。三条事实决定了形态：

1. **页面天然是「层 × 场次」两级结构**：一期末日幻影 = 4 个难度层（等级 60/70/80/90），每层两场战斗（上半场/下半场 = 节点一/节点二，`EventIDList1/2` + `DamageType1/2`）；含星启的赛季在末层之后追加星启模式（节点 1/2 = 末层上下半场同关卡、节点 3 = 星启附加关）。旧页面把它摊成 5 个纵排区块（赛季增益 / 首领特性 / 污染等级 / 星启模式 / 关卡层级），读者要在区块之间来回跳才能拼出「这一层打什么、这层吃什么增益、有什么首领特性」。
2. **赛季增益与首领特性本就是按场次下发的**（`buff_groups` / `boss_traits` 的 `stage1/stage2/tierce`，ADR 0029）：把两份内容挂进层 tab 不是复制数据，而是把上游的「场次」维度还原到读者眼前。
3. **星启节点 1/2 与末层同关卡**（同 `StageID`）：旧页面里「第 4 层的阶段 3」与「星启节点 3」是同一场战斗被陈述两遍，而星启模式的 3 条增益只能待在赛季级区块里、离它所属的挑战很远。

## 决策

1. **导航层**：末日幻影**不渲染顶部固定条**（`.nk-egd-bar` 只在另外三种模式下出现），页面 `padding-top` 在 `data-mode="boss"` 下由 46px 归零；子 tab（`第 1 层 … 第 N 层` + `星启模式`，仅含星启的赛季出现星启 tab）作为**页内并列一行**排在赛季级「污染等级」区块下方，复用 `tokens.css` 的 `.nk-tab` 原语（`flex-wrap` 兜底，窄屏降一档内距保持单行）；点击切换面板并把该行滚回视口顶（`.nk-egd-tabs { scroll-margin-top: 12px }`）。常驻 chrome 只剩固定的「返回顶部」圆钮，滚动进度条随固定条一并退场。
2. **面板内容**：层 tab = 层级头（层号 + 等级/回合 + 污染徽标）+ **上下半场两个战斗节点**，各挂该场次的赛季增益 3 条与首领特性 4 条 + 该层可用增益（末法余烬）+ 挑战目标（节点口径**已被 [ADR 0031](0031-末日幻影层级敌方取实际战斗数据.md) 修订**：原按 `phases` 渲染、标签作「上半场 · 阶段 1」，现只渲染上下半场、敌方取 `stage1/stage2`）；星启 tab = 星启统计 + 星启模式 3 条赛季增益 + 挑战目标 + 3 节点（节点 3 内挂 4 条首领特性）+ 通关奖励。（**星启侧结构被 [ADR 0032](0032-星启节点按完整场次渲染.md) 修订**：3 节点各自是完整场次卡（推荐属性 + 敌方 + 等级/回合 + 该场次赛季增益与首领特性 + 可用增益），面板级那份「赛季增益」移入节点 3，节点编号与折叠交互退场。**再被 [ADR 0033](0033-星启模式改单节点看板.md) 修订**：星启 tab 内改为「节点子切换 + 单节点看板」，一次只渲染一个节点，块序按游戏内星启看板重排，首领特性改横向标签行，目标区改名「星级目标」；本条里的层 tab 部分不变。）
3. **赛季级区块收缩为污染等级**：它是跨层的赛季维度，保留在子 tab 内容之上；`buildEndgameSections` 对 `boss` 只产出该区块（其余模式口径不变），`#egd-pollution` 的区块序号由 03 变 01。
4. **渲染权收口**：`EndgameBuffs.vue` 不再渲染首领特性（它只服务另外三种模式），`boss_traits` 的唯一渲染点是子 tab；场次分组仍走 `renders.ts` 的 `endgameGroups`。抽出 `EndgameBuffGroup` / `EndgameTraitGroup` / `EndgameTargets` / `EndgameFloorBuff` 四个复用件，避免层面板与楼层/星启面板各写一份卡片模板。
5. **无障碍**：`role=tablist` / `role=tab` / `role=tabpanel` + `aria-selected` + roving tabindex + ←/→/Home/End 方向键；面板以激活 tab 的 id 作 `aria-labelledby`。
6. **默认与顺序**：层 tab 按 1→N 升序（与游戏内推进顺序一致），星启模式排在末位；切换赛季时若当前层号仍存在则保留。（**默认激活项被用户推翻**，见「被修订」：含星启的赛季默认停在**星启模式**，不含星启的赛季回退第 1 层——`levels.ts` 的 `defaultLevelKey`。）

## 后果

**正面**

- 一屏之内自洽：某一层打谁、吃什么增益、有哪些首领特性不再跨区块拼装；星启模式的 3 条增益首次与它所属的挑战同屏。
- 星启附加关的增益/特性不再在层 tab 重复陈述，星启 tab 完整承载该挑战（[ADR 0031](0031-末日幻影层级敌方取实际战斗数据.md) 进一步把末层那张重复的敌方卡也去掉：末层只余上下半场两场）。
- 末日幻影页首屏就是品牌带，不再有常驻横条遮挡内容（`padding-top` 归零后首屏多出 46px）；子 tab 与它要切换的面板处在同一阅读流里，位置关系一眼可读。
- 移动端 5 个 tab 单行放下（375px 下条内宽 343px），页面零横向溢出。

**负面**

- 非激活层的 DOM 不存在（tab 的语义使然）：客户端取证与页面内检索只能看到当前层；AI 快照不受影响（`/endgame/:mode/:id` 快照由 `*.catalog.json` 独立生成，本轮零改动）。
- 同一份赛季增益与首领特性在 4 个层 tab 里各渲染一次（仅当前层进 DOM）：这是「各难度共用同一份、上游未按难度下发」的直接后果（ADR 0029 负面条）；上游若改为按难度增量，层 tab 正好是落点。
- 污染等级区块与子 tab 行在深滚动后都会离开视口，读者需回到页面顶部切换层级；切 tab 时脚本会把 tab 行滚回视口顶作为补偿，层级头的半场徽标作为就地补偿。

**中性**

- 星启 tab 的 3 条增益不再带「星启模式」组标签（tab 即场次），仅保留「赛季增益」标题；层 tab 内保留「上半场/下半场」场次标签以区分两组。（**ADR 0032 后**：星启那份 3 条增益移入节点 3 的场次卡内，面板顶部不再有赛季增益分组。**ADR 0033 后**：星启 tab 内的节点子切换行以场次文案标识当前节点，看板内不再重复场次标签。）
- 「阶段 N」（源表逐项对应）与「上半场/下半场」（玩家口径）在同一标签里并列，两个口径都未废除。
- 页面内锚点只剩 `#egd-pollution`；旧锚点 `#egd-buffs` / `#egd-traits` / `#egd-tierce` / `#egd-floors` 在末日幻影下不再出现（另外三种模式仍在）。
- 末日幻影失去顶部滚动进度条（它长在固定条里），「返回顶部」圆钮仍在；固定条的高度契约（47px `bar` / 46px `padding-top`）在 boss 下不再适用，另外三种模式不变。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 子 tab 放顶部固定条内（第一版实现） | 用户第二轮反馈：删掉常驻顶栏，子 tab 挪到污染等级区块下方并列排布——固定条在末日幻影下只承载 tab 行，与页内一行重复 |
| 页内粘性子 tab 条（`position: sticky`） | 会重新造出一条常驻横条，与「移除顶部固定条」的诉求相反；切 tab 时把 tab 行滚回视口已覆盖可发现性 |
| 保持纵排区块 + 锚点导航（改造前形态） | 信息要跨 5 个区块拼装；星启增益与所属挑战相隔最远 |
| 每层 tab 各挂一份按难度复制的增益/特性 | 上游各难度 `TagList`、`BuffList1/2` 逐字相同，逐层复制只是把同一份文本写 8 遍（见 ADR 0029 替代方案表） |
| 把污染等级也拆进各层 tab | 污染汇总是跨层的赛季维度（`pollution.count` 按 `StageID` 去重，含星启与仲裁），拆进去会失去它作为赛季级正文的意义 |
| 第 4 层阶段 3 继续挂星启的增益/特性 | 与星启 tab 重复陈述同一场战斗（用户裁决归星启 tab） |
| 默认停在第 4 层（最高难度） | 与 tab 顺序（1→4）反向；新读者会先撞上最难层，且默认选中中间项在 Home/End 语义下也别扭 |
| 保留 `EndgameFloors` 的折叠楼层，只在其中塞增益/特性 | 折叠楼层与层 tab 是两套「同层级只保留一个可见」的机制，叠加后要维护两套展开状态 |
