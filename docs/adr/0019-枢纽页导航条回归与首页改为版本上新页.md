# 0019. 枢纽页导航条回归与首页改为版本上新页

## 状态

`accepted`（**已实现**：converter 打标管线 + 两枢纽页导航条回归 + 首页版本上新页 + e2e 断言重写均已落地并通过门禁，落地与验证记录见文末「相关」）

> 本决策**移除 [ADR 0018](0018-枢纽页改为工具化入口页.md) 的「无侧栏枢纽」形态**（`meta.bareNav` / `data-nav="bare"` / `--nk-content-offset` 的 bare 回退三件一并退场），
> **推翻 [ADR 0016](0016-枢纽页模式切换入口的落点分工.md) 决策 3**（`/currency` 的「枢纽返回行」），
> 并**取代 ADR 0018 决策 5 的首页形态**（`/` 的板块索引不再是首屏主体）。
> ADR 0018 决策 1（两页共享品牌带 `.nk-hub-brand`）、决策 2/3（移除 KV Spine / 背景视频与 poster）、决策 4（移除枢纽滚轮）**继续有效**；
> ADR 0016 决策 1（侧栏「交换」→ 对方图签页）继续有效，并因页内行退场成为两模式间**唯一**的可见切换入口。
>
> **2026-09-29 部分被取代（见 [0020](0020-货币战争枢纽页改为本赛季新增页.md)）**：本 ADR「后果」段中**「两枢纽页内容形态分叉」不再成立**——`/currency` 由「品牌带 + 5 行板块索引」改为「品牌带 + 本赛季新增两分区 + 页脚」。本 ADR 其余条款（导航条全断点回归、`/` 为版本上新页、跨模式只走侧栏「交换」、置换通道保留）**继续有效**；两页判据自此分工为「常规 = 版本增量 / 货币战争 = 赛季代际差集」。

## 背景

ADR 0018 之后，`/` 与 `/currency` 是 `meta.bareNav` 的「工具化入口页」：全断点不渲染导航条，页内板块索引就是全部导航；跨模式通路由两条页内行承担（`/` 的 `CW_GATEWAY` 网关行、`/currency` 的「枢纽返回行」）。

**数据侧硬事实**（用 `python tools/converter/query.py` 与仓库内已提交数据校验，可复现）：

| 事实 | 证据 |
| --- | --- |
| 只有遗器带版本号 | `RelicSetConfig.ReleaseVersion` → 索引 `relics.json` 的 `release_version`（如 `"4.6"`） |
| 角色 / 光锥没有版本号 | `AvatarConfig`（94 条）与 `EquipmentConfig`（170 条）只有 `Release` 布尔，且当前快照三类**全为 `true`**、无 `false` 记录——连「预载未实装」都区分不出来 |

**流程侧事实**：

- `.github/workflows/data-sync.yml` 用 `actions/checkout@v5` 的默认 `fetch-depth: 1` + vendor `git clone --depth 1`：**CI 里没有可用的 git 历史**；但工作树里就有已提交的上一版 `public/data/cn/*.json`（提交步骤本就靠 `git diff --cached --quiet` 判空）。
- 实测版本增量（相邻两版**已提交数据**的 id 差集）：

| 版本跳变 | 角色 | 光锥 | 遗器 |
| --- | --- | --- | --- |
| 4.4 → 4.5 | +2（知更鸟•晴歌 1512、砂金•戏浪 1513） | +4（21066 / 22008 / 23063 / 23064） | +0 |
| 4.5 → 4.6 | +1（真珠 1503） | +1（献给明日的色彩 23055） | +2（133 / 134，`ReleaseVersion` 均为 4.6） |

遗器的权威 `ReleaseVersion` 与 diff 在 4.6 上结果一致；4.5 版本没有新增遗器（既无 diff，也没有 `release_version="4.5"` 的套装）。另有一条 4.5 快照里已存在、4.6 只微调文案的光锥（23063「你将起身歌唱」）——它说明增量判据会把「上版预载、本版实装」的条目算在更早的版本上。

## 决策

1. **两个枢纽页都恢复导航条，全断点生效**（平板/桌面左侧竖栏 + 手机底部栏）。`route.meta.bareNav`、`<html data-nav="bare">`、`--nk-content-offset` 的 bare 回退三件一并删除；枢纽页内容区回到 148px 侧栏避让。
2. **首页 `/` 改为版本上新页**：品牌带 + **本版本新增角色 / 光锥 / 遗器**三个分区 + 页脚；全站板块索引退场，选路由导航条承担。
3. **「本版本」= `version.json` 的 `version_label`**（`game_version` 的主次版本号，如 `4.6.0` → `4.6`）；条目判据 = 该条目的 `release_version` **恰等于**该值。
4. **角色 / 光锥的版本号来源是版本增量**（与上一版数据快照的 id 差集）；**遗器用源数据权威 `ReleaseVersion`**。两者写在**同一个 `release_version` 字段**上，前端只读该字段、不关心它是推导还是权威。
5. **基线 = converter 覆盖输出前读取的「输出目录里已提交的上一版 JSON」**；条目一旦打标即**跨版本保留**（不每次重算）；无基线（首次转换 / 本地首跑）时 `release_version` 留空。
6. **两条页内跨模式行退场**（`/` 的 `CW_GATEWAY` 网关行与 `/currency` 的枢纽返回行）；跨模式只走侧栏「交换」，落点不变（对方图签页，ADR 0016 决策 1）。
7. **`/` ↔ `/currency` 的模式置换过渡通道保留**，判定改为**按路径对**判定——该通道的旧判据 `meta.bareNav` 已随决策 1 退场；`meta.depth` 相等仍成立，但**禁止**再以旗标或「depth 相等」作为判据（`/settings`、`/currency/settings`、404 亦为 depth 0）。
8. **首屏验收改写**：1920×1080 首屏内**品牌带 + 三个分区标题 + 各自首行卡片完整可见**；ADR 0018 的「首页 8 行入口首屏可见」断言作废。
9. **三分区各成一行横向卡片带，条数不设上限，无增量的分区不渲染**；卡片复用各目录配置的 `renderCard` 模板串与既有卡片 CSS（首页用静态容器 `v-html` 渲染），不新写首页专用卡片。
10. **三个分区皆无增量时**（基线缺失 / 本版本无新增），首页显示一行空态文案（品牌带与页脚保留）；不回退渲染板块索引、不自动改显「最近一次有增量的版本」。

## 后果

**正面**

- 全站外壳一致：导航高亮、工具组（设置 / 交换）、手机底部栏在任意页面行为相同，不再存在「同一站点里有两页没有导航」的特殊形态。
- 首页承接版本节奏：版本上线后首屏即本版本新增的角色 / 光锥 / 遗器，「数据展示型 wiki」的定位在入口页就能读到。
- 角色 / 光锥的版本号不再依赖任何人工清单，索引自身即归档；遗器走权威字段，不依赖基线完整性。
- 每页少一处形态：`/currency` 不再需要返回行，`/` 不再需要板块索引与网关行。

**负面**

- **首页不再承担全站选路**：入口密度下降，`/` 不再是「8 行板块入口一屏可达」；手机端原本「页内索引即导航、零滚动完成选路」的能力消失，改由底部栏承担。
- **两模式枢纽之间不再有直达通路**：「交换」的落点是对方**图签页**，停在 `/currency` 的用户回不到 `/`，只能经对方图签页中转。这是决策 6 的明确代价，不是遗漏。
- **两页内容形态分叉**：ADR 0018 建立的「两枢纽页结构角色相同」在**内容**上不再成立（外壳——品牌带、页脚、置换通道——仍同构）。
- **角色 / 光锥的版本号是推导值**，随基线演进而非源数据事实。可预期失真：CI 中断跨过多个版本时，多版新增会被一起算作「本版本」；上一版快照里已存在的预载条目（如 23063）会被算在更早的版本上，从而不出现在本版本上新里。
- **首页内容依赖增量数据**：基线缺失或本版本无新增时，首页只剩品牌带、空态行与页脚（决策 10 的兜底）。
- **作废的验收与豁免必须同批处理**，漏一处守卫就与实现互相打脸：`e2e/layout.spec.ts` 的 `data-nav="bare"` 断言与「首屏 8 行」断言、`e2e/visual.spec.ts` 的 `home.png` 像素基线、`tools/check-colors.mjs` 的「导航语义豁免」（首页网关行金色，失去消费方，条目与对应 CSS 一并删除）。
- **导航条回归会暴露既有 a11y 存量缺陷**：枢纽页首次渲染侧栏后，axe 在 `/` 与 `/currency` 报出激活态英文小字（`.ui-sidebar-link--active .ui-sidebar-link__en`，8px）对比度不足（赤陶 3.0:1 / 香槟金 4.08:1）。逐色阶复核为**存量问题**：10 套强调色在 55% 混色下 3.01–4.48，全部不达 WCAG 正文门槛。修复 = 混色 55% → **85%**（10 套色阶最低 5.19），并落为 `tokens.css` 硬约束注释与 `docs/agents/ui-design.md` §2 纪律——**禁止登记白名单了事**（该规则是真实可读性问题，且旧的 55% 在任何页面上都不达标，只是此前枢纽页没有侧栏才没被扫到）。

**中性**

- 品牌带 `.nk-hub-brand`、页脚 `.nk-hub-footer`、枢纽文字出场（三段错峰 0.2s / 0.35s / 0.5s）均为共享原语，本轮不动，两页仍必须同时序。
- 手机端枢纽页页脚的底部预留从 0 恢复到 56px 导航高度——底部栏回归的连带项。
- `nk-view-swap` 的位移与时长不动，只换判定依据。

## 替代方案

| 方案 | 为何未采用 |
| --- | --- |
| 只给 `/` 恢复导航条，`/currency` 维持 `bareNav` | 用户裁定两页一并恢复、保持同构；只改一页会让外壳规则与置换通道判定分叉 |
| 保留 `bareNav` 机制，仅在 `/` 上关闭 | 该机制的全部意义就是「全断点不渲染导航条」，留下不再被消费的旗标与 DOM 属性只会成为下一次误读的来源 |
| 保留板块索引，把版本上新插在索引之前 | 用户裁定上新区块**取代**索引；两者并存会让首屏出现两个并列的「入口区」 |
| 无增量时回退渲染板块索引 | 首页出现双形态，与「首页＝版本上新页」的定位矛盾，且让「无增量」表现为一次布局跳变 |
| 无增量时改显「最近一次有增量的版本」 | 标题版本号会与站点声明版本不一致，容易被读成「本版本上新」 |
| 角色 / 光锥维护人工版本映射清单 | 用户裁定走「与上一版数据对比」；人工清单是第二个需要每版本同步的事实源 |
| 遗器也统一走 diff | 遗器自带权威字段且不依赖基线完整性；用 diff 反而会在基线缺失时一起失效 |
| 遗器保留权威字段、前端按「有增量用增量、无增量用字段」混合判定 | 判据进前端等于把数据侧的不确定性推给渲染层；一个 `release_version` 字段即可覆盖 |
| CI 加深 git 历史（`fetch-depth ≥ 2`）后取上一提交作基线 | 引入对 CI 配置与历史深度的依赖，本地首次转换直接失效；工作树里已有上一版产物可用 |
| 保留两条页内跨模式行 | 导航条回归后「页内无通路」的立论消失；模式切换从任意页面一次点击可达 |
| 新增首页专用卡片组件 / 把目录卡抽成共享原语 | 前者与目录卡视觉必然漂移、构成重复实现；后者属跨模块公共基础改动，收益不抵本轮改动面（首页复用 `renderCard` 已足够） |
