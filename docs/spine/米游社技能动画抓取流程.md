# 米游社 Wiki 技能预览动画抓取流程

> 目标：角色详情页「技能预览」的动画素材来自米游社官方 Wiki（`act-api-takumi-static.mihoyo.com` 的 `sr_wiki` 黑板接口），
> 由 `spine-lab/tools/wiki-anim-scraper.mjs` 离线抓取为 `public/data/cn/skill_animations.json`，
> 前端运行期只读本地 JSON（动画图片仍直连米哈游上传域）。
> **覆盖数字以脚本末尾「覆盖报告」为准（wiki 侧随时增补），本文只记链路、口径与上游缺口成因。**

## 数据链路

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 抓取 | `spine-lab/tools/wiki-anim-scraper.mjs` | 离线脚本，写仓库根 `public/data/cn/skill_animations.json` |
| 加载 | `src/services/api/characters.ts` → `loadSkillAnimations` | 单例 Promise；失败静默（可选增强，不阻塞页面主体） |
| 编排 | `src/app/views/CharacterView.vue` | `charId` = 路由 id = 角色 4 位 avatarId |
| 消费 | `src/app/character/SkillsPanel.vue` + `SkillCard.vue` | 主技能按 `sk.type` 查表；忆灵技能按合成键 + `src/lib/skill-anim.ts` 分发 |

## 产出契约（标题令牌与语言包）

- **动画小标题命中官方技能名时写成名称令牌（`$t:<hash>`），不写 wiki 原文**：前端 `assignAnimEntries` 用
  `a.title === sk.name` 把动画挂到技能上，而 `sk.name` 是**按语言解析后**的正文 ⇒ 标题写死中文时非中文语言下
  匹配必然失败（动画被位置兜底挂错技能），切换器里也会露中文。命名的变体小标题（如「解放的金色王权」）无对应
  官方词条，保留原文。
- **同一脚本要写出本分组的 13 语言包**（`public/data/i18n/<语言>/skill_animations.json`，值借用 `characters` 分组、
  缺键回退缺省语言）：令牌按「同分组包」解析（`singletonLocalData('skill_animations.json')`），不写这一份则前端显示
  未解析的 `$t:…`，且 `check-i18n-packs.mjs` 会报缺包。
- **合并语义：url 定位条目、title 随最新抓取更新**。既有实现是「既有优先」⇒ 标题永远停在旧值（改标题那次踩到）；
  注意「既有条目沿用旧值」是双向的：联合模式保留旧 `title` 的同时，也要求末尾清洗掉非令牌残留，否则历史中文会一直在；
  需要整表覆盖时用 `--fresh`，但它会丢掉 wiki 页本轮不再下发的条目（主角页实测少 6 条）。

## 上游接口与提取口径

同一个接口有**两种下发形态**，两种都要解析——只看结构化字段会把模板型页面误判成「无数据」（椒丘 3058 即此坑）：

**① 结构化形态**（绝大多数页面）`data.content.rpg_new_tmp_content`：

1. 取「角色行迹」模块：`modules[]` 中 `id === '13'`；新角色页名带后缀（「角色行迹前瞻【请以正式版本为准】」），故以名称前缀兜底
2. `components[0].data` 是 JSON **字符串** → `points[]`，每点 `tag`（技能类型）+ `subList[].image`（动画媒体，逐条带 `subTitle`）
3. 键 = `rpg.base.userInfo.avatarId`；为 `0` / 缺失时查 `AVATAR_ID_FIX`（现仅「白露」→ `1211`）

**② OBC 预渲染模板形态**（老页面迁到新版渲染器后）`data.content.contents[].text` 的 HTML：

- 结构化 `rpg_new_tmp_content` 为空，行迹区落在 `<div data-part="trace" class="obc-tmpl-character__trace…">` 里；
  每个技能是一个 `<li class="obc-tmpl-character__trace__point">`：类型标签在 `__trace__name` 的 `span.colorful-tag`，
  演示动画是 `__trace__desc` 内的 `<img src>`（描述里的图标/表格**不算**，只取 `.gif/.webp`）
- **avatarId 在 `.obc-tmpl-character__trace__role`（如 `1218`）**，结构化字段为空时靠它建键
- 类型标签词表与结构化形态完全一致，故映射表/名称兜底共用一套
- 判定方法：`content/rpg_new_tmp_content` 为空 **且** `contents[].text` 含 `obc-tmpl-character__trace`；全部 99 页扫过，实测仅椒丘一处

只收 `.gif` / `.webp`：`.png` 是静态技能插画（如昔涟忆灵「献予…之诗」为 440×672 立绘），不属「技能预览动画」。
`.gif` 在前端按 OSS 实时转 webp 省带宽（`SkillCard.animSrc`）。

## 标签 → 键映射（新增 tag 必须在此表登记）

| wiki tag | JSON 键 | 备注 |
| --- | --- | --- |
| 普攻 / 战技 / 终结技 / 天赋 / 秘技 | `Normal` / `BPSkill` / `Ultra` / `Passive` / `Maze` | 与角色数据 `type` 同名对应 |
| 欢愉技 | `ElationDamage` | 欢愉命途角色（火花 / 爻光 / 绯英 / 银狼LV.999 / 真珠 / 砂金•戏浪 / 开拓者•欢愉…） |
| 忆灵技 | `Servant` | 忆灵主动技（角色数据 `type: 'Servant'`） |
| 忆灵天赋 | `ServantPassive` | 忆灵被动；角色数据 `type` 是空串，故用合成键（`SkillType` 已声明该值） |
| 额外能力 / 属性加成 / \*强化 / 角色晋阶 | — | `SKIP_TAGS`，非技能条目，不收也不计入告警 |

未知 tag 兜底：先按「角色数据技能名 → type」反查（读 `public/data/cn/characters/{avatarId}.json`），
支持 `A/B/C` 拼接形式（wiki 3124「开拓者·毁灭」页拿技能名当 tag，如「星尘王牌/全胜•再见安打/全胜•安息全垒打」）；
仍识别不了才计入脚本末尾「未识别标签」告警。

## 运行与写盘语义

```bash
node spine-lab/tools/wiki-anim-scraper.mjs            # 默认 delay 300ms，与既有文件合并
node spine-lab/tools/wiki-anim-scraper.mjs --delay=120
node spine-lab/tools/wiki-anim-scraper.mjs --pretty    # 缩进输出（仅调试；入库保持压缩单行）
node spine-lab/tools/wiki-anim-scraper.mjs --fresh     # 丢弃既有条目重建（无特殊理由不要用）
```

- **输出路径相对脚本必须是 `../../public/data/cn/`**。前端按 `/data/cn/skill_animations.json` 取数；
  写到 `spine-lab/` 下等于白跑（历史踩坑：脚本曾写 `../public/data/...`，落进不存在的 `spine-lab/public/`，
  数据文件因此长期停在旧快照，新角色整批缺席且无人察觉——这条禁止改回）。
- **默认合并（按 url 取并集）**：wiki 页面临时改版 / 缺图不得删掉已发布条目；
  本轮未抓到的键会在末尾以「沿用既有」列出，出现该告警要么是 wiki 侧变动、要么是脚本回归，必须人工定性。
- 脚本幂等：连续跑两次，第二次应报「新增 0 角色、0 条」。
- 末尾「覆盖报告」按 `characters.json` + 逐角色技能（与 `SkillsPanel` 同口径）列出仍缺预览的技能与原因。

## 上游缺口（wiki 侧没有，抓不到；不是脚本 bug）

- **天赋配图率低**：多数页面 `天赋` 点 `subList[].image` 为空（`imageMeta.image.url` 同样为空），老角色普遍没有天赋预览。
- **忆灵天赋配图极少**：`忆灵天赋` 点多数无图；`忆灵技` 相对完整。
- **页面零图**：黑塔(1013) / 雪衣(1214) 的行迹点全部无 `image`（结构化与模板两种形态都扫过，确认是 wiki 侧未配图）。
- **助战技无独立点**：姬子•启行(1510) 的助战技（`Assist`）混排进天赋点且该条无图，行迹模块没有独立点。
- 因此脚本会报「仍有缺口」——**不要为此改判据或伪造数据**；要补只能换数据源或游戏内录制。

**曾经的误判（已修）**：椒丘(1218) 一度被当成「残页」——它的 `content/info` 没有 `rpg_new_tmp_content`，
但数据完整地以 OBC 预渲染模板存在于 `contents[].text`（行迹 4 条演示图）。**教训：接口「结构化字段为空」≠「该页没有数据」**；
判定某角色无预览前，必须同时确认模板形态里也没有 `obc-tmpl-character__trace` 区块。

### 为什么这些缺口补不了（专项调研结论，勿重复调研）

- **媒体性质**：Wiki 的「技能演示」是**编辑手工录制的战斗实拍**，不是游戏内资产。抽查姬子天赋演示
  （`act-upload.mihoyo.com/sr-wiki/2025/07/05/197948068/a6b401ac…gif`：HTTP 200 / image/gif / 7,518,853 B /
  960×514 / 63 帧）画面含完整战斗 HUD（战技点、血条、伤害数字、右上「我方行动中」、ping、队伍头像），
  同页 `imageMeta` 尺寸不规则（959×522 / 893×486 / 960×514）= 录屏裁切。**客户端不含对应视频资产 → 无法解包**。
  媒体路径是扁平上传仓库 `sr-wiki/{日期}/{上传者UID}/{md5}_{随机}.gif|webp`（文件名=内容哈希，上传者因编辑而异），
  无目录列表 → **既不能按 avatarId 枚举/镜像，也做不到社区补漏**。
- **候选源实测全空**（勿再逐个试）：nanoka（只有 66 条 skel 的 manifest，角色页 0 媒体）、Project Yatta/Amber、
  StarRailRes（全树 0 媒体）、StarRailStaticAPI、gachabase、prydwen、官方站 puzzle 包、米游社其它频道（影音回廊 / 游戏图鉴）、
  HoYoWiki 国际版——HSR 词条**没有** `talent_img`/`talent_imgs` 字段（该字段只有原神词条有），技能区仅静态图标；
  homdgcat / hakush 在本机网络 TLS 不可达（未验证，该站性质为数值镜像）。
- **唯一「待机动作」增量**：HoYoWiki 国际版每角色 2 段待机动画 GIF（`wiki.hoyolab.com/pc/hsr/entry/{id}`，需爬虫 UA 取 SSR）
  与 bwiki「站立动作」GIF（黑塔 / 雪衣都有）——**不是技能演示**，若要接入必须另立类目，禁止当技能预览呈现。
- **结论：不存在可行替代源**。要补这些技能演示只能自行录制；否则保持「该技能无预览」，不得用静态插画/待机动作顶替。

## 前端消费要点

- 主技能：`SkillsPanel.animFor(main)` 按 `sk.type` 查表；同组技能由 `SkillCard` 按索引分发（父卡拿首条，其余按序给子卡，多段动画用 tab 切换）。
- 忆灵技能：面板平铺渲染（不像主技能那样父子嵌套），故 `SkillsPanel` 先按 `type_name` 分池，
  再用 `lib/skill-anim.ts::assignAnimEntries` 按「条目 `subTitle` = 技能名」匹配，未匹配的按技能顺序补位，
  条目多于技能时并入首卡 tab。
- 新增技能类型或 wiki tag 时两侧同改：抓取侧映射表 + 面板查表键（并在此表登记）。
