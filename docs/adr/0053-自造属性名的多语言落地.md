# 自造属性名（货币战争）的多语言落地：占位符协议 vs 令牌取包值

**Status**: Accepted（**已实现方案 A**：用户裁决「按建议做」）

## Context

多语言改造后，货币战争的词条描述里仍有 **15 类站内自造属性名**以**中文原文**出现在所有非中文语言的语言包中（实测：9 个非汉字语言包共 **1395 条**含这些串，占语言包残留的绝大部分；其余残留是配音演员专名与官方英文文本自带的汉字，均属有意保留）。

来源在转换器：`tools/converter/textmap.py` 解析 `<property type=X>` 标签时，先查官方词条（`_PROPERTY_HASH`，**17/32 项**可解析），查不到就回退站内中文标签表 `_PROPERTY_LABEL`（32 项）。

这 15 项的**官方文本表里没有干净词条**——实测 `TextMapCHS` / `TextMapEN` 的子串命中都是整句（如「治疗量提高」），取来会把句子塞进标签位：

| 属性 | 出现次数 | 属性 | 出现次数 |
| --- | --- | --- | --- |
| 全伤害 | 477 | 护盾量 | 72 |
| 量子共鸣 | 468 | 治疗量 | 63 |
| 幸运触发率 | 162 | 终结技伤害 | 54 |
| 追加攻击伤害 | 108 | 属性伤害 / 初始战技点 | 36 / 36 |
| 幸运伤害 | 90 | 战技点上限 / 普攻伤害 / 战技伤害 / 护盾量(RatioBase) | 其余 |

它们的 13 语言译文**只存在于前端 UI 词典**（`src/lib/i18n/messages/*.json` 的 `prop.*`，第 20 轮溯源/撰写）：其中 7 项已有键，另外 8 项需补键（`ExtraAllDamageTypeAddedRatio`、`ExtraHealRatio`、`ExtraMaxSP`、`ExtraUltraDamageAddedRatio`、`ExtraInsertDamageAddedRatio`、`ExtraNormalDamageAddedRatio`、`ExtraSkillDamageAddedRatio`、`ExtraElementDamageAddedRatio`）。

因此无论怎么修，都要在某处新增一处**跨层契约**：数据侧需要产出「按语言取值」的引用，而值住在 UI 词典里。

## Decision

**采用方案 A**（用户裁决）：转换器对无官方词条的属性发 `{PROP:<枚举键>}` 占位符，渲染端按 UI 词典解析——
`src/lib/html.ts::gameTagsToHtml`（与既有 `{NICKNAME}` 同一解析点）与 `tools/gen-ai-endpoints.mjs` 各一次。
实现要点：

1. `tools/converter/textmap.py::_property_name`：有官方词条的仍按语言取官方文本；**没有官方词条的 15 项发 `{PROP:<枚举键>}`**（缺省语言同样发，词典里的 cn 值就是中文）。
2. UI 词典新增 8 个 `prop.*` 键（`ExtraAllDamageTypeAddedRatio` / `ExtraElementDamageAddedRatio` / `ExtraHealRatio` / `ExtraInsertDamageAddedRatio` / `ExtraMaxSP` / `ExtraNormalDamageAddedRatio` / `ExtraSkillDamageAddedRatio` / `ExtraUltraDamageAddedRatio`，13 语言），另 7 项复用既有官方溯源键。
3. 渲染端解析占位符；**拉丁标签与相邻拉丁字母之间补空格**（源文本按 CJK 排版书写，实测 16 条会粘连成 `Lucky Strike DMGIncreases`），CJK 标签保持源排版。
4. 机检：AI 端点守卫新增「正文不得残留 `{PROP:…}`」；汉字棘轮按新基线收紧（`--write-baseline`）。
5. 效果：9 个非汉字语言包含汉字条目 **3039 → 1644**（-1395，剩余全是配音演员专名）；13 语言端到端冒烟新增断言——货币战争描述既无占位符残留、也无中文。

### 备选方案（当时评估，已否决）

- **A. 占位符协议**：转换器对无官方词条的属性发 `{PROP:<枚举键>}`，与既有 `{NICKNAME}` 同一形态；前端在渲染入口（`lib/html.ts` 的 `gameTagsToHtml`，已是 `{NICKNAME}` 的解析点）解析，AI 快照生成器 `tools/gen-ai-endpoints.mjs` 同步解析一次。
  - 代价：新增一种占位符（2 个消费者要同步）；需补 8 个词典键。
  - 优点：不动语言包生成链，不与前端源码产生构建期依赖。
- **B. 令牌 + 取包值**：转换器写 `$t:prop.<键>` 作**引用令牌**，并把 UI 词典的 `prop.*` 拷进语言包（`check-i18n-packs.mjs` 已有「借值分组须与源分组一致」的判据可复用）。
  - 代价：转换器在**构建期反向依赖前端源码**（层级倒置），需新增「UI 词典 → 语言包」的生成步骤与守卫。
  - 优点：前端零改动（令牌按同分组包解析已是既有能力）。


## 替代方案（否决）

- **在 Python 里再写一份 13 语言译文**：制造第二事实源，改一处漏一处——否决。
- **转换器直接读 `src/lib/i18n/messages/*.json`**：把前端词典变成转换器输入，等于承认 B 的层级倒置却不给守卫——否决（B 至少还经过语言包与守卫）。
- **前端对渲染后的 HTML 做中文串替换**：用中文当匹配键，脆弱且无法覆盖快照——否决。
- **保留中文不动**：与「全量多语言（UI 外壳文案 + 数据内容）」的既有裁决直接冲突——否决。

## Consequences

- 选 A 或 B 后，`check-i18n-packs.mjs` 的「非汉字语言包汉字条目数只降不升」棘轮会记录一次**下调**（需跑 `--write-baseline` 收紧基线）。
- 15 项清零后，非汉字语言包残留只剩：配音演员专名（官方专名，有意保留）与官方英文文本自带的中文（改即失真）。
- 回滚：A 回滚 = 转换器改回发中文标签 + 撤销前端/快照两处解析；B 回滚 = 转换器改回中文标签 + 删除借值分组（守卫判据保留无害）。
