# 角色转换模块字段分析

> **定位**：转换模块（converter）侧的角色字段活文档——逐字段说明"输出字段 → 源字段 → 转换逻辑 → 消费方 → 验证状态"。
> 与 [角色相关数据深挖](./角色相关数据深挖.md)（源数据侧全目录分布）互补：前者看"数据从哪来"，本文看"转换器怎么处理"。
>
> **本次深度审计**：2026-08-02（分支 `feature/character-converter-audit`）

## 一、范围与基准

### 范围

常规模式 4 个角色模块（货币战争角色模块下次单独审计）：

| 模块 | 输出文件 | 源数据 |
|------|----------|--------|
| `characters` | `characters.json` | AvatarConfig(+LD) |
| `character_ranks` | `character_ranks.json` | AvatarRankConfig |
| `character_skills` | `character_skills.json` | AvatarSkillConfig |
| `character_detail` | `characters/{id}.json`（95 个） | 19 个源文件联合 |

### 正确性基准

- **忠实性**：输出值与源数据一致（结构全量对比 95 角色 + 数值抽样 7 角色）
- **语义性**：字段含义正确（已知陷阱专项核查）
- 不引入外部数据基准（源数据即真相；特殊数值待人工核验时标注）

### 5.2 skills（技能字典）

结构：`{ SkillID: Skill }`，Skill 字段：

| 字段 | 类型 | 源字段 | 转换逻辑 | 验证 |
|------|------|--------|----------|------|
| `id` | number | `SkillID` | — | ✅ |
| `name` | string | `SkillName`(Hash) | TextMap | ✅ |
| `desc` / `simple_desc` | string | `SkillDesc` / `SimpleSkillDesc` | TextMap，**`clean=False`**（保留标签前端渲染） | ✅ |
| `type` | string | `SkillTriggerKey` 优先 → `AttackType` 兜底 | 映射表；`Skill31-34` 内部子技能过滤；`HideInUI` 过滤（**Assist 豁免**） | ✅ |
| `type_name` | string | `SkillTypeDesc` | TextMap | ✅ |
| `tag` | string \| null | `SkillEffect` | 原样，空转 null | ✅ |
| `sp_base` | number \| null | `SPBase`(Value) | `unwrap_value` | ✅ |
| `bp_need` / `bp_add` | number \| null | `BPNeed` / `BPAdd` | `unwrap_value` | ✅ |
| `show_stance_list` | number[] \| null | `ShowStanceList` | 逐项 `unwrap_value`，空转 null | ✅ |
| `skill_combo_value_delta` | number \| null | `SkillComboValueDelta` | 原样 | ✅ |
| `extra` | object | — | 预留 `{}` | ✅ |
| `level` | object | 同 SkillID 多等级记录 | `{ 等级: { level, param_list } }`，等级升序 | ✅ |

> 参数语义备忘：`ParamList` 逐项解包为纯数字，与描述文本中的 `#1[i]` 占位一一对应。

### 5.5 stats（突破属性）

结构：`{ "0"~"6": { attack_base, attack_add, defence_base, defence_add, hp_base, hp_add, speed_base, critical_chance, critical_damage, base_aggro, cost } }`

- 源：AvatarPromotionConfig(+LD)，按 `MaxLevel` 升序编号阶段 0-6
- 全部数值字段 `unwrap_value`；`cost` 为 PromotionCostList 原样
- 抽查 0/3/6 阶段 HPBase/AttackBase 与源一致 ✅

### 5.6 memosprite（忆灵）

| 字段 | 源字段 | 要点 | 验证 |
|------|--------|------|------|
| `name` | `ServantName`(Hash) | TextMap | ✅ |
| `icon` | `ActionServantHeadIconPath` | **原样未走 `map_icon_path`**（CDN 由前端拼接） | ✅ |
| `hp_base` / `speed_base` 等 | 原样（字符串） | 未解包（源即为字符串数字） | ✅ |
| `aggro` | `Aggro`(Value) | `unwrap_value` | ✅ |

> 归属规则：`ServantID - 10000 = 基础角色 ID`；开拓者 8xxx 同时分配给配对奇偶变体（18007 → 8007 & 8008）。

`{ avatar_id, set4_id_list, set2_id_list, property_list3~6, property_list[{relic_type, property_type}], sub_affix_property_list, score_rank_list }` —— 全部透传 AvatarRelicRecommend(+LD)，按 AvatarID 命中。✅

| `voicelines` | — | 占位 `[]` | ✅ |

### 5.9 占位/预留字段

`enhanced=null`、`unique={}`、`teams=[]`、`skin={}`、`chara_info.voicelines=[]`、`skill.extra={}`、`rank.extra={}`——CDN 兼容占位，前端按空值处理。✅

## 六、风险字段核查表（语义陷阱专项）

| # | 字段/机制 | 陷阱 | 处置 | 状态 |
|---|-----------|------|------|------|
| 1 | `SPNeed` | 部分角色（遐蝶 1407）**源无此字段**，此前输出 `{}` 破坏前端 `number` 类型契约 | 缺失输出 `null`，前端 `?? 0` 兜底 | ✅ 本次修复 |

| 4 | 跨 ID 图标引用 | 开拓者偶数变体（8002 等）无图标资产，引用配对奇数 ID | **不得归一**（8002 的图标保留指向 8001） | ✅ 已确认 |
| 5 | Assist 助战技 | 姬子•启行（1510）助战技带 `HideInUI=true`，直接过滤会丢技能 | Assist 豁免过滤 | ✅ 已确认 |

| 8 | `clean` 参数分工 | 详情文本 `clean=False`（保留 `<color>`/`<unbreak>`/`<i>`） | 前端富文本渲染；索引文本清洗为纯文本 | ✅ 分工确认 |
