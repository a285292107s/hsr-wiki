# 多语言站点架构：路径前缀 + 语言包（结构单份）

**Status**: Accepted（架构已定，实现进行中）

## Context

站点自建立即为单语言：数据由 `tools/converter` 从官方解包数据消费 `TextMapCHS.json` 产出 `public/data/cn/**`（[ADR 0005](0005-turnbasedgamedata-converter.md) 决策 5 明文「语言范围：仅简体中文」），UI 文案以中文字面量散落在 162 个源文件、3858 行里，路由无 locale 维度，AI 预渲染快照只有一套中文。

上游其实早已具备多语言能力，实测（vendor 固定 Dimbreath `8b178dd4` / OSPRODWin 4.6.0）：

- `ExcelOutput/AllowedTextLanguage.json` 声明 **13 种文本语言**（`TextLanguageKey` = cn / cht / de / en / es / fr / id / jp / kr / pt / ru / th / vi），`LanguageCultureCode` 给出 zh-CN / zh-TW / en-US / ja-JP / ko-KR / de-DE / es-MX / fr-FR / id-ID / pt-BR / ru-RU / th-TH / vi-VN；`AllowedLanguage.json` 的分区清单与之一致。
- `TextMap/` 下 13 种语言各约 474,000 条（`kr` / `ru` / `th` 被上游切成 `_0` / `_1` 两片需合并），另有 13 份 `TextMapMain*.json` 各 1,159 条 UI 文本。
- 对转换器实际消费的 16,854 条文本键做覆盖实测：**13 种语言全部 100% 命中、零空值**；与中文同文率 cht 7.5%、jp 1.3%、其余 ≤ 0.18%（只有专有名词重合）。
- `jp` 文本带 `{RUBY_B#…}` 注音标签（`clean_text()` 已在剥离）；开拓者名为 `{NICKNAME}` 占位符（无译名，需回退策略）。

真正的约束在体积。`public/data/cn` 实测 31.0 MB / 3152 文件，其中语言相关 25.6 MB、语言无关仅 5.5 MB（含 5.0 MB 的 `assets/cw-hero.mp4`）；`vendor/` 已 gitignore（为 Vercel 构建提速移出），转换产物必须入库：

- **按语言全树复制** ≈ 13 × 25.6 + 5.5 = **333 MB / 约 4 万文件**，且 `.github/workflows/data-sync.yml` 每日上游变更都会重提交一遍。
- 即便只复制「字符串值」（占 JSON 字节 45.1%），下界也要 151 MB。

插桩实测（拦截 `utils.save_json` 跑完 20 个转换模块、零落盘）：`resolve_text` 调用 148,718 次，**去重后真正消费的 TextMap 键只有 43,750 条**，其 CHS 原文合计 3.86 MB。也就是说文本在产物里被重复写了约 3 倍，而**键空间比产物字节小得多**——这才是可压缩的空间。

用户裁决：**全量多语言（UI 外壳文案 + 数据内容）· 13 种语言 · 路径前缀 · 引入 vue-i18n**。

## Decision

1. **语言清单以 vendor `AllowedTextLanguage.json` 为准，共 13 种**；站内语言代码直接采用上游 `TextLanguageKey`（不复自造），`LanguageCultureCode` 用作 `<html lang>` 与 hreflang。缺省语言 = `cn`。
2. **数据侧改为「结构单份 + 语言包」**：
   - 结构层（`public/data/cn/*.json`、`characters/<id>.json` 等）**语言无关、单份提交**，来自 TextMap 的文本值不再落最终文本，而是落**文本引用令牌**（字符串 `"$t:<TextMap 键>"`）。
   - 语言包按语言 × 分组切分提交：`public/data/i18n/<lang>/<group>.json`，内容 = `{<键>: <该语言文本>}`，只含被引用的键，与结构层同源生成。分组规则 = 数据文件相对路径的首段目录（或顶层文件名去 `.json`），前后端各一份实现、由**覆盖守卫**对着真实产物校验。
   - **文本变体**：同一个 TextMap 键有两种需求——默认**清洗后**正文（剥掉 `<unbreak>` `<color>` 等游戏标记）与**原样保留**（技能 / 剧情描述，交前端 `gameTagsToHtml` 渲染，即 `resolve_text(clean=False)`）。故令牌键带变体后缀（`~raw`），**语言包必须按变体分别加工**：包值存 TextMap 原文会让标签当正文上屏（实测被 AI 端点守卫的「正文残留游戏标记」断言拦下 68 个快照）。清洗函数由 `convert.py` 注入 `PackBuilder.write`，不从 `textpack` 反向 import `textmap`（避免循环依赖）。
   - **覆盖不变量**：结构层里出现过的令牌 = 必须被语言包覆盖的键，**与来源无关**。`endgame_catalog` 从已令牌化的 `maze*.json` 派生 catalog，拿到的是普通字符串令牌；只登记 `TextRef` 会让这 4 个分组缺包（前端解析即报缺键）。守卫 `tools/check-i18n-packs.mjs` 已进 `pnpm build` 前置。
   - **结构层目录保留 `public/data/cn/` 这一段**：令牌化后该目录已与语言无关，但改名要动 3,152 个产物文件与数十处**冻结文档**（ADR 正文、docs/data、docs/memory 里的历史路径）引用，收益仅是名称诚实——按「同一事实只在一处声明」与「改动范围最小化」取舍为**保留旧路径 + 在本 ADR 与 [CONTEXT.md](../../CONTEXT.md)「目标格式」词条标明其语义已变为「缺省语言结构层」**。
   - 前端在 `services/api/local.ts` 的取数层解析令牌（**先探测是否含令牌**，语言无关数据与未令牌化结构层零额外请求）；**缺键回退缺省语言的逻辑在转换期完成**，禁止运行期 join 到别的数据源。
   - 落地实测：结构层 28.0 MB（含 5.5 MB 语言无关 `assets/`；转换器产物本体约 23 MB）+ 语言包 75.5 MB / 260 文件（20 分组 × 13 语言，单语言 4.4–10.5 MB，泰 / 俄最大），合计 103.6 MB，相对 333 MB 的全树方案省 3.2 倍；令牌实例约 21.6 万处。
3. **转换器内硬编码中文一律下沉**：`config.py` 的枚举映射（`PATH_NAME_FALLBACK` / `ELEMENT_NAME_FALLBACK` / `RELIC_TYPE_MAP` / `PROPERTY_MAP`）、各 converter 里的中文标签，改为输出**稳定枚举键**，文案由语言包 / UI 词典承载。产物里禁止再出现写死的中文（守卫判据，见落地清单）。
4. **UI 文案引入 vue-i18n**（本决策放开 [ADR 0005](0005-turnbasedgamedata-converter.md) 时代的「运行时依赖仅三件」约束一次，新依赖仅此一项，同步 [tech-stack.md](../agents/tech-stack.md)）；词典按语言分文件，缺省语言 `cn`，缺键回退 `cn` 并在 dev 下告警。
5. **URL 用路径前缀**：缺省语言 `cn` 保持根路径（`/character`），其余 12 种为 `/{lang}/character`。**不做 `/cn/**` 别名**——缺省语言的规范化 URL 就是无前缀形态，否则同一内容出现两个可索引 URL。
6. **AI 可见性按语言各出一套**：预渲染快照 `dist/prerender/{lang}/**`、`vercel.json` rewrite 表与 sitemap 同步扩到 12 个前缀，并输出语言互指 `hreflang`。`tools/gen-ai-endpoints.mjs` 必须能按语言解析令牌与取 UI 词典——它此前直读 `public/data/cn/**` 且写死中文标签（`{ key: 'maze', label: '忘却之庭' }`），本决策下这些标签必须改从词典取。
7. **语言清单单一事实源 + 守卫**：转换器侧 `tools/converter/languages.py` 声明代码 / TextMap 分片 / culture / 输出目录；前端 `src/lib/i18n/locales.ts` 声明代码 / 母语名 / culture / 回退链。两侧同一份代码清单由 `tools/check-languages.mjs` 逐项比对，任何一侧新增语言而另一侧未跟进即失败。

## Considered Options

- **按语言全树复制 `public/data/<lang>/**`**（结构不动、前端只改 `LOCAL_DATA_BASE`）：改动最小，但 333 MB / 4 万文件入库且每日同步重复提交，直接否决。
- **只上 2–4 种语言**（cn + en 或 + jp/cht）：仓库 57–108 MB，实施成本可控；**被用户否决**——目标是 13 语言全量。
- **语言包按「数据集内联一份多语言字典」**（同一文件里 `{"name":{"cn":…,"en":…}}`）：结构单份、无令牌层，但每个数据集都要带全部 13 语言、页面加载即下载全部语言，且与现有 TS 类型（`name: string`）全面冲突。否决。
- **query 参数 `?lang=en` / 仅本地偏好**：改动最小，但同 URL 多语言内容对爬虫不友好、canonical 兜不住。**被用户否决**（选路径前缀）。
- **手写轻量 i18n（零新依赖）**：符合既有依赖政策，但复数、插值、日期数字格式化全要自建，且 vue-i18n 的 `$t` 模板集成度更高。**用户选择 vue-i18n**。
- **语言包压缩入库（gzip/brotli 存储 + 浏览器 `DecompressionStream` 解压）**：可把 94.6 MB 降到 ~23 MB，但引入解压路径、缓存与错误处理分支，且 Vercel 边缘已按内容协商自动 gzip。**本轮不做**，记为后续可选优化（若仓库体积成为实际痛点再启用）。

## Consequences

- 仓库从「31 MB 单语言数据」变为「~14 MB 结构层 + ~95 MB 语言包」，增量 ~78 MB；`data-sync.yml` 的每日提交体积显著上升（文本变更经 git 增量压缩后远小于单次全量，但仍需观察）。
- 前端多出一层令牌解析：所有 `services/api/**` 的返回对象形状不变（解析后仍是 `string`），因此 store / 视图 / 目录配置**不需要逐个改写**——这是选令牌而非改字段类型的直接收益。
- 首屏成本可控的前提是**语言包按数据集切分懒加载**：进入某个目录页只取该页所需的数据集语言包，禁止一次性拉全量语言包。
- 转换器新增「语言包生成」阶段，运行时长与磁盘写入量上升（13 份 TextMap 约 700 MB 需逐个读取）；增量机制需按语言维度重新评估，不能沿用现有模块签名。
- **既有 URL 不迁移**：`/`、`/character` 等仍是 cn；新增的 12 个前缀是纯增量，`vercel.json` rewrite 与 sitemap 条目相应扩张，`tools/check-ai-endpoints.mjs` 的覆盖率断言必须同步，否则末步守卫失败。
- 图片与 Spine 动画仍是语言无关的 CDN 资源，不在本决策范围内。
- 术语：`CONTEXT.md` 需新增「语言包」「文本引用令牌」「缺省语言」三条。
