# 文档与协作流程

> 本域 memory 补的是 `docs/agents/conventions.md`、`AGENTS.md`「文档分级」与各守卫工具的盲区：那些**规则已写明、但执行时仍会静默走偏**的地方——判据的由来、踩坑的具体形态、以及「工具报绿其实没查」的识别法。规则本身不在此复述。

## 渐进式披露与路由表

- **新增 `docs/agents/*.md` 子文件必须同步登记进 `AGENTS.md`「任务 → 必读」表，否则按需加载机制不可发现**：路由表是子文件的唯一入口；`node tools/doc-audit.mjs` 的第②条检查正是「`docs/agents/*` 必须在路由表登记」。`AGENTS.md`
- **子文件一律用相对 markdown 链接引用，禁止改回 `@path` 导入写法**：Qoder 等工具把 `@` 导入当 include 语义递归展开，等于把子文件全量塞进上下文，渐进式披露当场失效。`AGENTS.md`
- **AI 不可读的失效形态是「文件在但页面不显示」，不是报错**：`tools/check-doc-links.mjs` 第 4 行 `spine-lab/**/*.md` 里的 `*/` 提前闭合了块注释 ⇒ 该守卫**自身无法运行**，而它当时承担全部文档断链校验。守卫脚本改动后必须先跑一次确认它能跑。`tools/check-doc-links.mjs`
- **根文件禁写会漂移的目录/文件清单、日期、版本号、「已修复」类断言**：这些是易过期事实，抄一份就多一个会毒化上下文的源；需要时指向唯一落位文件。`AGENTS.md`

## ADR 门槛与编号

- **新增 ADR 前必须实查 `docs/adr/` 目录最大编号 + 逐条读「编号不复用」声明，不能只看索引 README 的概述句**：README 曾写「编号无其他缺号」，而 ADR 0016 明文「0017 已作废、编号不复用」，两者自相矛盾；只看概述句会直接撞号。`docs/adr/README.md`
- **ADR 的 Status 不会自动跟随实现，改到相邻代码时必须顺手回扫**：ADR 0026 的 status 与索引行仍写「待实现」，而产物与页面早已实现——同批改到该域时才发现。`docs/adr/README.md`
- **推断不得当既成结论写进 ADR 正文，否则下一轮多一次回扫**：曾把「赛季级污染区块保留，删掉会让『这期污染了谁』无从查起」作为结论写入补记，被用户直接否掉（真实诉求是「标签挂在怪物身上」）。ADR 的「后果/中性条」只能写数据能证的事。
- **推翻既有硬策略（断点策略、视觉形态契约）时必须同批同步全部文档**：只改代码不改文档 = 文档与实现互相打脸；历史 ADR 用「顶部演进指针 + 正文按原样保留」而非改正文。`AGENTS.md` / `docs/agents/ui-design.md`
- **ADR 的「替代方案」判据必须结构化，不认行文词汇**：宽正则含 `而非` / `旧版` 时，任何正文出现一次即通过（0040 凭 `而非×1`、0043 凭 `而不是×1` 过关，二者都不是否决字段）。只认 `## 替代方案（被否）` 一类标题或 `**Considered Options**` 一类加粗字段；只有行文暗示的报「疑似缺失待复核」。改用结构化判据后一次找出 10 篇真实缺失的 ADR，补写时**只搬运正文已有的被否方案与理由，禁止编造历史**。`tools/doc-audit.mjs`
- **「不开 ADR」不是「不登记」**：可逆展示迭代（数值/块序/形态/文案）落 `docs/memory/` 一段 + commit message 正文；契约变化（新目录页/新令牌类别/新 e2e 分层/新命令）落对应子文件。判据是「推翻它，返工是否只限展示层且不动下游契约」。`docs/agents/conventions.md`

## memory 写法

- **memory 只留判据与坑位，验证数字（用例数/耗时/断言计数/KB/百分比）进 commit message**：数字必然过期，留在 memory 里会让人按旧值判断现状。`docs/agents/conventions.md`
- **memory 按域组织，禁止按月/按日/按时序分片**：AI 检索时想的是「改这一域要注意什么」，不是「某天发生了什么」——时序编号对检索零价值。域文件超约 30 KB 时按域内主题分小节，整目录超红线则拆域。历史按月日志（约 750 KB）已按域折叠为 9 份。
- **「假 SSOT」比没有规则更糟**：只声明「唯一落位 X」而无工具校验的指针规则，会让两处同时漂移却无人发现（曾同时存在 4 个版本权威源）。**指针规则必须配一致性断言**，否则等于把漂移藏得更深。
- **豁免名单必须是显式输出，不是副作用**：检查器只覆盖 12/98 份时，「命中 0 条」会被读成「全部合规」。凡有豁免，运行时就要打印**覆盖面与豁免数**。
- **删源文件前必须先证明「内容已全部搬走」**：域重构后的时序源文件若**未纳入版本控制**，删除即永久丢失——先做覆盖审计（把源文件里的可迁移教训逐条对照新文件），再删；不能凭「抽取器说它读过了」就删。
- **可判定性自检是唯一的取舍判据**：写完一句问「删掉它，后续 AI 会不会据此改错？」——不会就删。同理适用于注释。`docs/agents/conventions.md`
- **代码改动清单、交付清单与过程叙事不是 memory 内容**：它们记录的是「做过了什么」，而 memory 的价值是「下次重做会在哪一步踩到」；说不出具体步骤的条目属流水账，只留判据与坑位。

## 注释政策

- **注释只允许写「代码与数据都推不出、且 `docs/adr/` 或 `docs/` 里也不存在」的事实**：允许保留的是外部资产客观状态（上游 404 / 占位贴图 / 需回退某源）、字段来源与映射规则、上游数据特殊形态（旧 id 形式、哨兵值语义）、异步时序陷阱、运行环境特例，以及 `# noqa` / `@ts-expect-error` 一类**指令注释**（指令不是文档，不得删）。`docs/agents/conventions.md`
- **「禁止…/必须…」类约束只要已被 ADR 或 `docs/` 承载，代码处即不得重复**：以「注释第一读者是 AI」为由在代码里复述文档，等于造第二事实源，两处必然漂移。
- **收口刻度/字号/圆角时必须同批收口注释，否则留下能骗人的文档**：收口后「1 字档 3.2rem × 1.12 = 57.34 → 3.58rem」式注释全部失效；改法是**引用令牌名**而非数值。凡注释里写了具体数值的，改动数值前先搜注释。`docs/agents/conventions.md`
- **可能频繁改动的内容（样式数值尤其）不得写注释**：过期注释会主动误导后续 AI，其害大于利。

## Agent Teams：并发上限与写入分工

- **Agent 并发上限随模型/provider 而定，不是通用规则；超限的部分既不运行也不报错**：实测 GLM-5.3-Flash 下主线程占 1 槽、子代理仅 2，第 3 个起从未运行——而 spawn 照常返回 running 态、事后没有任何通知。**「没收到报告」不能归因为「职责被别人覆盖」**：应 `list_agents` 看运行态，或对迟迟不返的成员直接 `send_message` 追问。fan-out 前先按当前会话模型确认额度，多代理任务分波下发（每波 ≤ 剩余额度，上一波交付后再发下一波）。
- **写入范围必须按文件/目录切分且互不重叠，并事先写进任务**：验证者的写入范围常不含 `e2e/`，此时防回流手段只能落在**改动处的注释禁令**（如「两枢纽必须同时序 / 禁止新增关键帧副本 / reduced-motion 必须降级」），不能靠新增断言。范围外缺陷记入「待用户裁决」，不自动修。
- **跨模块共享件（共享 composable / 共享样式 / services 核心）的改动属「跨模块公共基础」，须先确认再动手**：绕过时至少要记录理由并给出替代判据（如用全套下游回归作为替代）。
- **并行/串行之外的第三个变量：常驻 dev server 的年龄**：本机固定端口上可能有跨天常驻实例，`Test-NetConnection -InformationLevel Quiet` 对它会报假阴性（`Invoke-WebRequest` 才准）；排查端口占用别只信前者。旧实例不认识新建的 `public/` 资产 → 请求回退成 `index.html` → `fetchJSON` 报 `Invalid JSON` → **e2e 大面积全红（含毫不相干的用例）**。此时先查端口上是谁在服务，不是先怀疑自己的改动。

## 用户纠正与形态裁定

- **用户给出「形态词」时不要默认读成既有形态的近义**：说「平铺在**一张**卡片中」是要整组一张卡，而「逐条各一卡」正是当时层 tab 的既有形态——用户没必要强调「一张」。形态词有二义时分两个选项各写清「卡形归属」再问一次。
- **自然语言描述视觉缺陷 + 附图时，先用像素/计算样式把候选集穷举，再让他选**：实测「左侧有颜色的竖线」同时命中两条（6 设备像素的父子层级竖轨 / 4 设备像素的卡片左沿），凭「有颜色的」无法区分。列选项时必须写清「哪条属于哪个元素、动了它别处会不会跟着变」——共享几何（如 `nk-egd-children` 跨三处消费）只说「移除竖线」会让执行者顺手改掉另外两页。
- **只能看不能读的裁定（「反 AI 味」「效果不理想」）先用零成本对照图收口**：`page.addStyleTag` 原地改样式 + `locator.screenshot()` 出 2–3 版对照图，同一位置同一内容、零代码改动，用户一眼选定；比「文字确认 → 实现 → 被否 → 回滚」省一个往返。
- **「用户点名的那个视觉元素」与「它所在的几何契约」要分开处理**：用户说删竖线，只把轨宽归零、`--eg-indent` 缩进保留——多删一档就是超出授权的改动。
- **删除一个共享值前先数清它有几个用途**：「敌方配置下方多余空间」那 8px 同时是多波之间的间隔，整类删会把多波间隔从 17px 压到 9px。
- **「某功能很难被发现」几乎总能归到「入口数量为 1 且无提示性」（标题即链接）**：修法不是加大字号，而是在用户真实落点各加一个**带图标与文字的显式入口**（胶囊文字链），使其与「纯文本链接」在视觉上可区分。`src/styles/catalog.css`
- **批量代码变换（删/改注释）必须过真编译器的「语法错误数不得增加」闸门**：token 流比对与 `git diff --numstat` 都会被同一个坏扫描器两侧同误扫骗过（正则字面量里的 `//` 被当行注释、把 `replace(/^SpriteOutput\//i,'')` 截断成非法语法仍判「无变化」）。只能用 `parseDiagnostics`（TS）/ `tokenize` + `ast.dump`（Py，需 `PYTHONIOENCODING=utf-8`）；按行删多行注释还会留下括号不闭合的残句，须逐块自查配平。
- **派单文本（task 描述）是过程文本、不是验收依据**：其中的行号与「文件归属」都是快照或二手结论，必须写明「以实际文件为准」并允许实现者按 grep / 实测改判；**口径一旦改判必须同批写进仓库文档**，否则验收方会按旧文本报「契约偏差」。
- **推翻既有形态前先问「形态本身是否该存在」**：在「保留现有视觉形态」前提内做优化（收首屏高度、分阶段加载），可能根本不是用户要的方向——A+B 全部实现并验证通过后被整体回退重写为零。提「优化一点」类方案时应同时给出「形态本身是否该动」的选项。
- **用户反复「再迭代一下」同一控件时，按每轮给可断言的最小实现 + 截图**：同一处控件曾两轮内换三次形态，说明用户是在看着页面逐步逼近目标，一次猜终态的成本远高于小步迭代。
- **删/收窄式指令要先把该容器的每个住户列出来**：用户指着某元素说删，而容器里还住着别的东西（如无首领特性节点退回的污染徽标）——整块删掉 = 顺手删掉未被点名的信息。剩余住户给一个专属 `v-if` 容器。

## 交付流程与验证纪律

- **实测优于推断，且推断与事实必须分开写**：给用户的结论里，源字段事实与「我的解释」混写会让人把推断当数据（曾把某怪物称「幻象遭遇战」，那是推断）；解释要么明确标注为推断，要么不写。
- **「社区参考站」是判定「另一个实现怎么做」的一等证据**：仓内没有 ≠ 无据可验——本地 Chromium 读参考站渲染后页面即可逐项反推算法；但社群攻略表格要逐行对表再引用，不能整表照抄（文章版本与当前库版本不同，抽查 12 行有 1 行不吻合）。
- **数据派生断言 + 一条硬编码规则哨，缺一不可**：只加「UI == 数据」的断言时，数据自己带错值（如关卡名恰等于怪物名）断言照样绿；必须另有一条硬编码规则的哨，并做负测确认它会咬。**「守卫从不响」与「没有守卫」等价——新加断言必须负测一次。**
- **改共享容器/共享原语 = 把以它为锚点的全部断言过一遍**：往一个共享容器里加一栏，会让原先按整块取子元素的断言全部 strict mode 违规；删一个渲染位要看容器里还有没有别的住户。反向经验：**结构类断言写全量等值（枚举所有子元素类名）而不是 `toContain`**，这样删除类改动的回归成本为零。
- **删干净要顺着机制往上问一层**：删最后一个区块消费方 ≠ 删一个组件，而是删掉「区块序号」这件事本身（清单模块、`sectionIdxMap`、单测 describe 一并退场）；删最后一个原语消费方 = 删原语，但**要按类名/API 名分别 grep**——字号收口块里它可能只是选择器清单里的一行，手机档的重述可能在离基础档三百行的位置。
- **断言依赖其计算值的元素，要用「算出来为 0」删，不要用「不存在」删**：`content: none` 之下伪元素不生成，`getComputedStyle(el,'::before')` 不再反映声明，既有镜像断言当场翻红；改为把轨宽提成消费侧开关（`--eg-rail-w` 缺省 3px、覆写 0），同一探测点继续有效。
- **补上某字段 / 某形态后，先 grep「它的缺席被谁写成了前提」**：ADR 的正面清单与决策、字段映射表、索引行可能都还写着「当前没有这块」，下一轮读 ADR 的人会以为它仍然缺席。补齐动作与「消除缺席前提」必须同批。
- **契约跟着系统走，不是让系统迁就旧契约**：页面圆角从 4px 落档到 6px 后，把 4px 硬编码成契约常量的用例判红——改法是把契约也改为刻度派生，硬编码常量退场。
- **改默认选中项时，先 grep 所有「不点击就断言面板内容」的用例**：默认项换人会让这类隐含前提的用例全部失效。
- **验证耗时与降级的纪律**：同一会话内全量 e2e 最多一次、无关用例直接跳过、`visual.spec` 全量禁止；任何超预算降级/跳过/豁免必须写明原级别与原因，**禁止静默降级**（未记录视为漏测，并触发沉淀）。`AGENTS.md`
- **像素基线按「重构期模式」在收敛点一次性重建，禁止逐次刷新**：失败先修本层，低层失败不触发全量重跑；同一问题两次修复尝试未果就停下向用户说明，不自动重试。基线图是「这次改了什么」的证据，**通过 ≠ 逐像素相同**（5% 是整帧容差）。`AGENTS.md`

## 文档守卫与工具链

- **守卫的豁免必须是显式声明而非副作用，且必须回报覆盖面**：活文档规则（禁词/漂移/版本号）实际只覆盖 13/97 份，`docs/adr/`+`docs/memory/`+audit/data/spine 全在白名单外——放一份同时含 `Node 22+`、汇报腔、「已修复 N 处」的 md，命中 0 条。对历史档案豁免禁词是对的（抹平措辞等于篡改历史），错在它没被声明。**输出必须打印「0 命中 / N 份受管」与豁免数，否则「命中 0」会被误读成全覆盖。** `tools/doc-audit.mjs`
- **「唯一落位」若自身承认以别处为准，则 SSOT 是假的**：tech-stack.md 写「权威值以 `package.json`/`requirements.txt`/CI 为准」，而 `package.json` 的 `packageManager` 也是权威源 ⇒ 实际 4 个权威源却要求「唯一落位」；更糟的是原检查器把该文件自己列入豁免，等于唯一落位处无人校验。修法是规则反转为「**版本号禁入叙述性文档**」+ tech-stack 是唯一允许内联版本号处且必须**可机器校验**（`<!--ver:包名-->` 标记与权威源逐字比对）。**tech-stack 里一个具体数字都不该是手工维护的。** `tools/doc-audit.mjs`
- **手工抄本必然漂移，且「降低一处漂移」常会新建一处**：把版本号从 5 处文档改成指针，tech-stack.md 就成了三份权威源的手工抄本而无任何一致性检查。新增守卫后必须做负测确认它会响（注入错误版本 → exit 1 并指名不一致；还原后字节无差异）。
- **跳过名单/受管范围等价信息只能有一份实现**：`SKIP_DIR` 曾在两个工具各写一份，新增生成物目录必然只改一处——正是仓库「helper 先查再用、禁止重复实现」规则所禁的模式。抽 `tools/doc-scope.mjs` 作唯一来源后，合并过程中才浮出一个潜伏 Windows bug：`SKIP_FILE` 用正斜杠而调用处比较 `path.relative` 的原生分隔符，导致某文件的排除**从未生效**。**跨平台路径比较必须统一到正斜杠后再比。** `tools/doc-scope.mjs`
- **可机检守卫先划「断言位」，再谈阈值**：裸 px 扫描器首版把注释/用例标题/视口里的 px 一起计数（报 63 处，断言位真值 17），等于逼人「改注释或加豁免去凑绿」——守卫噪声本身就是 churn 来源。基线是兜底，行内豁免才是收口。
- **有计数基线的检查器会静默过期，且 `--write-baseline` 会把别人的漂移一起吞掉**：某 spec 在 HEAD 上实际已是 7 处而基线写着 5（该检查器默认只报告、不进 build/CI，漂移长期不可见）；拆文件时顺手重写基线等于把前人的漂移洗白。正确动作是**先回放 HEAD 版本单独计数、看清增量归属**，再决定是收口还是豁免。`tools/check-e2e-literals.mjs`
- **先修尺子，再量东西**：按行解析 CSS 的审计工具会漏掉多行选择器组（声明只记到最后一个选择器，真命中 5 条 → 修好后 93 条）、把跨行声明值当选择器（产出垃圾键）、因注释替换成单空格而丢换行导致**报告行号整体前移**。**CSS 的最小解析单元不是行，是 `{`/`}`/`;` 三个定界符**，必须写逐字符 tokenizer；`.vue` 只在所有 `<style>` 都带 scoped 时才算隔离，`.css` 一律视为全局。`tools/check-css-dup-selectors.mjs`
- **清理「被后写覆盖的声明」前先比特异性**：收口块通常是同特异性覆写，但特异性更高的那份从来不是死代码（0,2,0 的选择器收口块的 0,1,0 压不住，必须显式留下并写明理由）。
- **删覆盖型声明必须用「前后计算样式快照 diff」验收**：对多条路由 × 视口 × 选择器的 computed style 做 before/after 快照，结果为**零差异**才算纯删；肉眼看截图查不出 0.02rem 的差。
- **文档体量红线与拆分手法**：面向 AI 的单文件超过约 5 万 token 即失去整读价值；持续增长的生成物改成「总索引 + 按维度分片」且**分片逻辑要落在生成器里**（否则人工拆完又被重新生成合回单文件）。估算口径与分片细则见 `docs/agents/conventions.md`，此处不复述。
- **工具链移除时要留下防回流判据**：`skills-lock.json` 的 `computedHash` 只锁安装版本、**不是可用性校验**（算法 = 对目录内每个文件哈希 `sha256(相对路径 + 文件字节)`），所以「锁在文件就在」「锁没了 skill 就废」两种直觉都不对。项目约束的唯一来源是 `AGENTS.md`「强制规则」一节，**禁止再引入需要在仓库外维护镜像条目的「双视图」机制**。`AGENTS.md`
