# 角色（Avatar）相关数据深挖报告

> 分析对象：与「角色 / 可玩角色」有关的数据，跨 `ExcelOutput/`、`Config/ConfigCharacter/`、`Config/ConfigAbility/`、`Config/ConfigAnimEvents/`、`TextMap/`、`ItemConfig*` 等多个目录。
> 数据来源：StarRailData（《崩坏：星穹铁道》发行数据解包）

---

## 一、角色数据全景（跨目录分布）

一个可玩角色的数据**不是**集中在一个文件里，而是分散在多个目录、通过 ID 与路径拼接而成。各目录职责如下：

| 目录 | 角色相关内容 | 角色数据职责 |
| --- | --- | --- |
| `ExcelOutput/`（`Avatar*` 系列表，约 80 张） | 静态数值与配置：基础信息、突破、星魂、行迹、技能、属性、命途、阵营、来源、皮肤、语音、推荐 | **数值与文案索引**（扁平记录数组） |
| `Config/ConfigCharacter/Avatar/` | `Avatar_<Name>_00_Config.json` + `.layout.json`（每个角色一对） | **角色实体配置**（`CharacterConfig`：碰撞盒、技能列表、镜头、动画事件引用） |
| `Config/ConfigAbility/Avatar/` | `Avatar_<Name>_00_Ability.json` + `.layout.json` | **技能逻辑**（施法流程、伤害结算、触发条件的行为图） |
| `Config/ConfigAnimEvents/Avatar/` | `Audio/`(126) `Designer/`(246) `DesignerBaked/`(193) `Effect/`(250) | **动画事件**（按动画帧绑定音效/特效/表现） |
| `Config/ConfigAI/` | 少量（主要为敌人 AI；可玩角色 AI 极简或未单独配置） | 战斗 AI（敌方为主） |
| `TextMap/` | `TextMapCHS/EN/...` | **所有角色名称、技能描述、星魂文案**的 hash → 文本还原 |
| `ExcelOutput/ItemConfigAvatar*` | `ItemConfigAvatar`、`ItemConfigAvatarRank`、`ItemConfigAvatarSkin` | 角色专属材料 / 星魂材料 / 皮肤（作为物品） |

> 关键约定：角色实体文件命名形如 `Avatar_<英文名>_00_Config.json`；后缀含义：`_BE_` = Beta/测试、`_LD` = 低配精简表、`_layout.json` = 烘焙元数据（内容通常为空 `{"BakeInfoLayouts":[]}`）。

## 二、数据关联链路（一个角色如何被拼装）

```
ExcelOutput/AvatarConfig.json
  ├─ AvatarID / Rarity / DamageType(属性) / SPNeed
  ├─ JsonPath  ──────────────►  Config/ConfigCharacter/Avatar/Avatar_<Name>_00_Config.json
  │                              │  $type: RPG.GameCore.CharacterConfig
  │                              ├─ SkillList[].EntryAbility ─► Config/ConfigAbility/Avatar/Avatar_<Name>_00_Ability.json
  │                              └─ AnimEventConfigList[] ─────► Config/ConfigAnimEvents/Avatar/{Audio,Designer,DesignerBaked,Effect}/...
  ├─ RankIDList[] ───────────►  ExcelOutput/AvatarRankConfig.json        (星魂/命座)
  ├─ (技能槽) ───────────────►  ExcelOutput/AvatarSkillConfig.json        (普攻/战技/终结技/天赋)
  └─ AvatarID ───────────────►  ExcelOutput/AvatarSkillTreeConfig.json   (行迹/天赋树)
                                 ExcelOutput/AvatarPromotionConfig.json   (突破材料 + 属性曲线)
                                 ExcelOutput/AvatarPropertyConfig.json    (属性定义)
                                 ExcelOutput/AvatarBaseType.json          (命途/职业图标)
                                 ExcelOutput/AvatarCamp.json              (阵营)
                                 ExcelOutput/AvatarSourceConfig.json      (获取途径)
所有文本字段(Hash) ──────────►  TextMap/<语言>.json  还原中文/英文等
所有图片字段(*Path) ─────────►  SpriteOutput/...     资源本体不在本仓库
```

> 一句话：要还原「一个角色页」，主表是 `AvatarConfig`，数值细节在 `AvatarPromotion/Rank/SkillTree/SkillConfig`，底层逻辑在 `ConfigCharacter` + `ConfigAbility` + `ConfigAnimEvents`，文案统一在 `TextMap`。

## 三、ExcelOutput 中的角色表（约 80 张，分类详述）

### A. 主数据
- `AvatarConfig` —— **角色主表**：`AvatarID`、`AvatarName`(hash)、`AvatarFullName`、`Rarity`、`DamageType`(属性)、`SPNeed`、`JsonPath`(回链 ConfigCharacter)、`MaxPromotion`、`MaxRank`、`RankIDList`、`ExpGroup`。
- `AvatarConfigTrial` / `AvatarConfigEnhanced` / `AvatarConfigLD` / `AvatarTestConfig` —— 试用角色、增强形态、低配、测试用变体表。

### B. 突破 / 养成
- `AvatarPromotionConfig`（+`Trial`/`LD`）—— **突破配置**：`PromotionCostList`(材料+数量)、`MaxLevel`、`PlayerLevelRequire`、各属性 `AttackBase/Add`、`DefenceBase/Add`、`MaxHPBase/Add` 等成长曲线。
- `AvatarPromotionReward`、`AvatarExpItemConfig`（经验书）、`AvatarUseMaterialData`(+`LD`)、`UpgradeAvatar*`、`AvatarLevelSkillConfig`。

### C. 星魂 / 命座（Eidolon）
- `AvatarRankConfig`（+`Trial`/`LD`）—— **星魂表**：`RankID`、`Rank`(1~6)、`Name`/`Desc`(hash)、`UnlockCost`(星魂材料)、`Param`、`IconPath`、`RankAbility`。
- `AvatarEnhancedRank` / `AvatarEnhancedSeason` / `AvatarEnhancedHintConfig` / `AvatarEnhancedSkill` / `AvatarEnhancedSkillTree`、`ItemConfigAvatarRank`（星魂材料）。

### D. 行迹 / 天赋树（Trace）
- `AvatarSkillTreeConfig`（+`Trial`/`LD`）—— **行迹表**：`PointID`、`Level`、`AvatarID`、`PointType`、`AnchorType`、`MaxLevel`、`DefaultUnlock`、`PrePoint`(前置节点)、`LevelUpSkillID`、`IconPath`、`PointTriggerKey`、`ParamList`。
- `AvatarSpecialSkillTree`、`AvatarSkillLink`、`AvatarSkillPropertyOverride`。

### E. 技能（Skill）
- `AvatarSkillConfig`（+`Trial`/`LD`）—— **技能表**：`SkillID`、`SkillName`/`SkillDesc`(hash)、`SkillTypeDesc`、`Level`、`MaxLevel`、`SkillIcon`、`LevelUpCostList`、`RatedSkillTreeID`、`RatedRankID`、`ShowStanceList`。
- `AvatarUltraSkillConfig`（终结技）、`AvatarServantSkillConfig` / `AvatarServantSkillLink`（随从技能）、`AvatarCutinChangeConfig`（立绘切换）。

### F. 属性 / 数值 / 状态
- `AvatarPropertyConfig` —— **属性定义表**：`PropertyType`(MaxHP/Attack/Defence/Speed/CritRate…)、`PropertyName`(hash)、`IsDisplay`、`Order`、`IconPath`。
- `AvatarPropertyOverride` / `AvatarBreakDamage`（击破伤害）、`AvatarStatusConfig`(+`LD`)（状态）、`AvatarBaseType`（**命途/职业**：Warrior/Mage/… + 图标/文案）、`AvatarCamp`（阵营）、`AvatarTeamBuff`、`AvatarGlobalBuffConfig`、`AvatarDefaultMazeBuff`、`AvatarMazeBuff`、`AvatarDeliverConstValue`。

### G. 推荐 / 来源 / 获取
- `AvatarRelicRecommend`(+`LD`)、`AvatarEquipRecommend`(+`LD`)（遗器/光锥推荐）、`AvatarComefrom`(+`LD`)、`AvatarSourceConfig`(+`LD`)、`AvatarLinkConfig`。

### H. 外观 / 皮肤 / 语音
- `AvatarSkin`、`AvatarSkinSpecialAction`、`AvatarPlayerIcon`(+`LD`)、`AvatarVO`(+`LD`)（语音标签）、`AvatarCobrand`（联名）。

### I. 图鉴 / 展示
- `AvatarAtlas`、`AvatarDetailTabConfig`、`MultiplePathAvatarAtlas`（多命途图鉴）、`ItemConfigAvatarSkin`。

### J. 演示 / 引导
- `AvatarDemoConfig`、`AvatarDemoGuide`、`AvatarDemoGuideGroup`、`AvatarDemoEntrance`、`AvatarDemoConstValue`。

### K. 统计 / 其他
- `AvatarAbilityStatistics`（技能统计）、`AvatarPathItemTransfer`、`AvatarServantConfig`、`SpecialAvatar*`（特殊角色）、`ItemConfigAvatar`（角色作为物品的展示）。

## 四、ConfigCharacter：角色实体配置

路径：`Config/ConfigCharacter/Avatar/`，共 **260 个文件**（含 `_Config.json` 与 `_Config.layout.json` 成对出现，以及 `AetherDivide_*` 系列）。

典型结构（`Avatar_Arlan_00_Config.json`，`$type: RPG.GameCore.CharacterConfig`）：
```json
{
  "$type": "RPG.GameCore.CharacterConfig",
  "SomatoType": "MiddleAvatar",
  "HitBoxWidth": 0.3, "HitBoxHeight": 1.5,
  "AnimEventConfigList": [
    "Config/ConfigAnimEvents/Avatar/Designer/Avatar_Arlan_00_Designer_AnimEvent.json",
    "Config/ConfigAnimEvents/Avatar/Effect/Avatar_Arlan_00_Effect_AnimEvent.json",
    "Config/ConfigAnimEvents/Avatar/Audio/Avatar_Arlan_00_Audio_AnimEvent.json",
    "Config/ConfigAnimEvents/Avatar/DesignerBaked/Avatar_Arlan_00_Designer_AnimEvent_Baked.json",
    "Config/ConfigAnimEvents/Avatar/Designer/Avatar_Common_Designer_AnimEvent.json"
  ],
  "SkillList": [
    {
      "Name": "Skill01", "UseType": "SelectEntity",
      "TargetInfo": { "TargetType": "EnemySelect" },
      "ReadyAnimState": "Skill01_Ready",
      "CameraConfig": { "NormalConfig": { "CameraState": "SelectDarkTeamEntity", "AnchorOffset": {...}, "AimOffset": {...} } },
      "EntryAbility": "Avatar_Arlan_Skill01_Phase01"
    }
  ]
}
```
要点：
- `SkillList[].EntryAbility` 字符串 → 精确指向 `Config/ConfigAbility/Avatar/<Name>_Ability.json` 中的某个技能阶段（如 `Avatar_Arlan_Skill01_Phase01`）。
- `AnimEventConfigList` 引用 4 类动画事件文件（Audio/Designer/DesignerBaked/Effect）。

**可玩角色名册（节选，数据快照约 3.x~4.x 版本）**：
Acheron、Aglaea、Anaxa、Archer(✿Fate 联动)、Argenti、Arlan、Ashveil、Asta、Aventurine、Bailu、BlackSwan、Boothill、Bronya、Castorice、Cerydra、Cipher、Constance、Cyrene、DanHeng（含 IL/PT 形态）、Dr_Ratio、Evanescia、Evernight、Feixiao、Fugue、FuXuan、Gallagher、Gepard、Guinaifen、Hanya、Harscyline、Herta、Himeko、Hook、Huohuo、Hyacine、Jade、Jiaoqiu、Jingliu、JingYuan、Kafka、Klara、Lingsha、Luka、Luocha、Lynx、Mar_7th（三月七）、Misha、Moze、Mydeimos、Natasha、Pela、Phainon、PlayerBoy/PlayerGirl（**开拓者，含 00~40 多形态**）、Qingque、Rappa、Ren（刃）、Robin、RuanMei、Saber(✿Fate 联动)、Sam、Sampo、Seele… 等 **约 70+ 名**可玩角色。

> 注意：`AetherDivide_*`（`Avatar_AetherDivide_W1_*` 等）虽在 `Avatar/` 下，但属于「虚构宇宙」机兵/敌人，**非可玩角色**（用同一 `CharacterConfig` 基类）。`Gilgamesh` 仅有 `.layout.json`（尚未实装配置）。

## 五、ConfigAbility：技能逻辑

路径：`Config/ConfigAbility/Avatar/`，每个角色一个 `Avatar_<Name>_00_Ability.json`（+`.layout.json`），另有 `Avatar_Common_Ability.json`（通用）、`Avatar_AetherDivide_Common_Ability.json`。

结构（`Avatar_Arlan_00_Ability.json`）：
```json
{
  "AbilityList": [
    {
      "AbilityName": "Avatar_Arlan_Skill01_Phase01",
      "MixAbility": {
        "OnStart":   { "TaskList": [ { "$type": "RPG.GameCore.TriggerAbility", ... }, ... ] },
        "OnTick":    { "TaskList": [ ... ] },
        "OnFinish":  { "TaskList": [ ... ] }
      },
      "MixTrigger": { "TriggerList": [ { "$type": "RPG.GameCore.TriggerAbility", ... } ] }
    }
  ]
}
```
要点：
- 用 `$type`（如 `RPG.GameCore.TriggerAbility`）描述施法流程：触发镜头 → 播动画 → 结算伤害 → 上 buff。
- 与 `CharacterConfig.SkillList[].EntryAbility` 通过**能力名字符串**精确对应。

## 六、ConfigAnimEvents：动画事件

路径：`Config/ConfigAnimEvents/Avatar/`，共 **815 个文件**，分 4 个子目录：
- `Audio/` —— 126（音效触发）
- `Designer/` —— 246（设计层表现）
- `DesignerBaked/` —— 193（烘焙后表现）
- `Effect/` —— 250（特效触发）

每个角色的 `CharacterConfig.AnimEventConfigList` 引用其中若干文件（如 `Avatar_Arlan_00_{Designer,Effect,Audio}_AnimEvent.json` 与共用 `Avatar_Common_*`），实现「动画帧 → 音效/特效/逻辑」的绑定。

## 七、取数示例：还原一张「角色详情页」需要哪些数据

以角色「三月七（Mar_7th）」为例：
1. **基础信息**：`AvatarConfig` → 名称/稀有度/属性(`DamageType`)/命途(`AvatarBaseType`)/SP消耗。
2. **突破与属性曲线**：`AvatarPromotionConfig` → 各突破等级材料(`PromotionCostList`)与 `Attack/Defence/MaxHP` 成长值。
3. **技能**：`AvatarSkillConfig`（普攻/战技/终结技/天赋的图标、`ShowStanceList`）+ `AvatarUltraSkillConfig`（终结技）。
4. **行迹**：`AvatarSkillTreeConfig` → 天赋树节点、前置、解锁材料。
5. **星魂**：`AvatarRankConfig` → 6 个命座的名称/描述/解锁材料。
6. **底层逻辑/表现**：`ConfigCharacter/Avatar/Avatar_Mar_7th_00_Config.json`（镜头/碰撞盒）+ `ConfigAbility/..._Ability.json`（技能行为）+ `ConfigAnimEvents/...`（音画）。
7. **文案还原**：上述所有 `Hash` 字段 → `TextMap/TextMapCHS.json`（中文）、`TextMapEN.json`（英文）等。
8. **图标/立绘**：`SpriteOutput/AvatarIcon/...`、`SpriteOutput/SkillIcons/Avatar/...`、`SpriteOutput/LightConeFigures/...` 等资源路径（资源本体需另行对接）。

## 九、注意事项

1. **文本全为 hash**：角色名、技能描述、星魂文案均为 `{ "Hash": <数字> }`，必须配合 `TextMap/` 指定语言还原，且 `TextMap` 键使用 **xxhash**。
2. **图片为路径外链**：图标/立绘以 `SpriteOutput/...` 相对路径给出，资源本体不在本仓库，需对接资源库/CDN。
3. **大文件**：`AvatarConfig` 等含全量角色，体量较大；`ConfigCharacter`/`ConfigAbility` 单个角色文件较小（数 KB~数十 KB），适合按角色拆分加载。
4. **变体标识**：`_BE_`（测试）、`_LD`（低配）、`_layout.json`（烘焙元数据，多为空）应区别对待，避免误用。
5. **`AetherDivide_*` 与 `SpecialAvatar*`**：前者是虚构宇宙机兵（非可玩），后者是特殊角色，命名在 `Avatar/` 下但语义不同，wiki 归类时需甄别。
6. **开拓者多形态**：`PlayerBoy`/`PlayerGirl` 存在 `00~40` 多套配置（对应不同命途），应按形态分别处理。

## 十、一句话结论

角色数据呈「**主表(ExcelOutput) + 实体(ConfigCharacter) + 逻辑(ConfigAbility) + 表现(ConfigAnimEvents) + 文案(TextMap)**」五层结构，通过 `AvatarID`、`JsonPath`、能力名字符串与 hash 串联；其中 `ExcelOutput` 的 `AvatarConfig/PromotionConfig/RankConfig/SkillTreeConfig/SkillConfig` 是 wiki 角色页**最高优先级的取数表**，其余为底层还原与表现支撑。
