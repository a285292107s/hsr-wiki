# 0051. 终局赛季奖励进详情页：逐层通关奖励 + 累计星数奖励线

## 状态

`accepted`（**已实现**：`endgame` 模块读 `RewardData` 并解析三张 `*RewardLine` 与 `ChallengePeakReward`；四模式产物新增 `floor_details[].reward` 与赛季级 `star_rewards`；详情页层面板头部新增「通关奖励」列、关卡面板之后新增赛季级「星数奖励」阶梯；`EndgameReward.vue` 成为奖励 chips 的唯一渲染件（星启面板同批切到它）；`incremental.MODULE_SOURCES['endgame']` 补 5 个源表）

## Context

用户提问「是否能关联挑战目标和奖励之间的关系，达成哪个挑战目标获得什么奖励」，并授权可行时迭代对应板块。盘点上游四张目标表与六张奖励表后，结论是**一半可行、一半不可行**：

1. **逐目标奖励不可解析**：`ChallengeTargetConfig`（130+ 条，仅忘却之庭侧）每条都带 `RewardID`（1001xx 段），但**该段在 `RewardData`（9,515 条）里一条都没有**——`ItemConfig` 也无同号条目，属本版数据里的悬挂字段。虚构叙事 / 末日幻影的目标表（`ChallengeStoryTargetConfig` / `ChallengeBossTargetConfig`）连 `RewardID` 字段都没有，异相仲裁的目标走 `BattleTargetConfig`（战斗条件，无奖励字段）。
2. **可解析的是两条链**：
   - **逐层通关奖励**：`Challenge{Maze,StoryMaze,BossMaze}Config.RewardID` → `RewardData`（每层一条，实测内容多为同层族共用同一份）。
   - **累计星数奖励线**：分组表 `RewardLineGroupID` → `Challenge{Maze,Story,Boss}RewardLine`（`StarCount` → `RewardID`）→ `RewardData`；异相仲裁走 `ChallengePeakGroupConfig.RewardGroupID` → `ChallengePeakReward`（按 `RewardType` + `TypeValue` 分档）。
3. **官方文案把「目标 → 奖励」的真实口径写死在玩法说明里**（`endgame_guide.json` 已在站内）：「通关忘却之庭并达成指定条件，可以获得『印记星数』。累计获得一定的星数后，可以领取『印记馈赠』」「通关虚构叙事并达到指定分数，可获得【故事星数】，领取【故事馈赠】」「异相仲裁…达成特定条件还可以获取额外的星级奖励」；实测**每层恰好 3 个挑战目标**（`floors × 3 == ChallengeTargetID 总数`，四模式逐期成立），即「1 个目标 = 1 星」。
4. `RewardData.Hcoin` = 星琼：全表 9,515 行**无一行**把星琼写成 `ItemID_1`（`ItemConfig` 1 = 星琼），而 32.6% 的行用它记星琼数量。

## Decision

1. **数据层（转换器只读，不改上游语义）**：`RewardData` → `{RewardID: [{id, num}]}`（六槽位；`Hcoin` 并入星琼 = 物品 1）；`*RewardLine` → `{GroupID: [(星数, RewardID)]}`；`ChallengePeakReward` 只取**两类有官方文案的星数档**（`MOB_STAR_REWARD` = 骑士星数 / `BOSS_STAR_REWARD` = 王棋星数）。输出：逐层 `floor_details[].reward`、赛季级 `star_rewards: [{star, items, label?}]`。
2. **档位按本期可达星数上限截断**：同一奖励线 Group 被层数不同的多期共用（10 层期与 12 层期同为 Group 2），上限取该期 `Σ ChallengeTargetID`（= 层数 × 3），超出上限的档位本期不可达，不输出。
3. **展示层（2026-10-07 补记修订）**：
   - **层头部「通关奖励」列**（每层的 `Challenge*MazeConfig.RewardID`）：与星启面板「星级目标｜通关奖励」同形；虚构叙事因多一栏赛季规则而变三栏（`.nk-egd-head--triple`）。
   - **层头部跨行「星级奖励」栏**：本赛季阶梯**按层序切片**随层展示（一行一档）；异相仲裁无层切片，改为赛季级头部整块（子 tab 之上），见下方补记。
4. **不上屏的档位**：`ChallengePeakReward` 的通关档（`MOB_PASS_REWARD`）、极限档（`BOSS_STAR_LIMIT_REWARD`）、彩色目标档（`BOSS_COLOR_TARGET_REWARD`）语义无官方文案（后两者发的是「异相仲裁•兵卒/骑士/城堡/帝王」勋章，与哪一档对应只能靠推），按「宁缺不猜」不上屏。
5. **共享渲染件**：奖励 chips 抽成 `EndgameReward.vue`（层头部 / 星启头部 / 星数阶梯每档共用，物品 id 经 `items.json` 单例映射），星启面板同批从内联模板切过来，避免三处各写一份。

## Consequences

**正面**

- 详情页首次能回答「打通这层给什么」与「达到几星领什么」，且两条链上的物品名/数量全部由上游解析，无自造数值。
- 「每层 3 个目标 = 3 星」「本期上限 = 层数 × 3」在转换期成文（截断逻辑单点），前端不重算。

**负面**

- **逐目标奖励仍然无解**：用户最初问的「达成目标 A → 奖励 X」在本版数据里做不到（`ChallengeTargetConfig.RewardID` 悬空）；页面只能给「累计星数」口径。
- 逐层通关奖励内容实测高度重复（忘却之庭 1035 十二层同载荷、永屹之城遗秘十五层两种、末日幻影四层一种），列在每层出现的信息量偏低。
- 异相仲裁的 6/9 类奖励档里只上屏 2 类，`maze_peak.json` 里其余档位数据仍在（只是无消费方）。

**中性**

- AI 快照不同步（沿用 [ADR 0026](0026-污染等级进入终局玩法详情页.md) 取舍）：`/endgame/:mode/:id` 快照来自 `*.catalog.json` 轻量条目，新字段不进 catalog，末步守卫无变化。
- 奖励物品的**名称与图标**仍是运行期经 `items.json` 映射（沿用星启通关奖励既有口径），转换器只落 id/数量。

## Alternatives considered

| 方案 | 为何未采用 |
|---|---|
| 逐目标标注奖励（把 `ChallengeTargetConfig.RewardID` 硬映射到某段编号规则） | 目标奖励段在 `RewardData` 为空，任何映射都是自造编号；宁可整体不做 |
| 把奖励线按层切成「本层满星 → 该档奖励」 | 需要「层序 ↔ 档位」的推断（奖励线只按累计星数计），跨赛季层数不一致时容易误导 |
| 星数阶梯放在首屏（hero 与子 tab 之间） | 档位常见 6–15 行，会把关卡内容推到首屏之外；用户刚在上一轮收口过头部区块 |
| 异相仲裁把 5 类档位全上屏 | 通关 / 极限 / 彩色目标三档无官方档位文案，只能自拟标签 |
| 前端运行时读 `RewardData` 自行解析 | 违反「文本与事实来自数据源、前端不做映射」的既有分工（同 ADR 0026 决策 1 的理由） |

## 补记（2026-10-07：星级奖励改为「随关卡展示」，逐层切片）

用户裁决「检查一下忘却之庭的星级奖励领取要求，你展示的内容有问题，然后把它放进每个关卡 tab 中」。核对结论与落法：

1. **领取要求复核（口径不变，展示粒度改）**：官方文案（TextMap）「通关忘却之庭并达成指定条件，可以获得『印记星数』。累计获得一定的星数后，可以领取『印记馈赠』」+ 数据 `ChallengeMazeRewardLine`（3/6/9… 档，星琼 60→80）确认：**判据是累计总星数、星数跨关卡通用**，不是「某层单独 3 星」；每层 3 个挑战目标 = 3 星，故**截止期每层满星正好推进一档**（忘却之庭 12 层 = 3..36 档；虚构叙事 / 末日幻影每层 3 目标但奖励线每星一档，故每层 3 档 1..12）。
2. **展示粒度：赛季级长阶梯 → 每层切片**。`_season_floors` 按**层序累计目标数**把赛季阶梯切给各层（`floor_details[].star_rewards`，切片在转换期算，前端不推层序）：层 tabs 的头部新增跨满整行的「星级奖励」栏（不再另占一列把头部挤成四栏），一行一档「N★ + 该档物品」+ 口径注记。赛季级阶梯块自此只在异相仲裁保留（其奖励按星数口径分组，与关卡无关）。
3. **附带项**：`EndgameView` 的赛季级 `EndgameStarRewards` 收成「仅 peak」一个实例；终局详情页的「奖励」现在是两层语义——`通关奖励`（每层，`Challenge*MazeConfig.RewardID`）与 `星级奖励`（按累计星数，逐层切片）。星启（tierce）tab 不展示星级奖励：它的 3 星与常规末层共享记录，档位已在末层 tab 上。

## 补记二（2026-10-07：面板顶部合并为 2×2 奖励板，补上「通关条件」）

用户裁决「把星级目标、星级奖励、通关奖励合并在一起，重新排版」，并给出读序：**通关条件｜通关奖励 / 星级目标｜星级奖励**。

1. **为什么有「通关奖励」就有「通关条件」**：官方文案把两者并列为两种奖励（TextMap「请手动领取前置关卡的**通关奖励和星级奖励**」），且四个玩法的说明都写了通关判据——忘却之庭「击败关卡内所有敌人即为完成挑战，可以领取丰厚奖励」、虚构叙事「挑战关卡获得通关所需积分即为完成挑战」、末日幻影「挑战并击败 2 个首领即为完成当前难度挑战」、异相仲裁「完成关卡挑战即可领取丰厚奖励」。所以 `Challenge*MazeConfig.RewardID` 就是「完成该判据时领的那份」，判据本身在数据里分三种形态：
   - **回合上限**（`ChallengeCountDown` / 虚构叙事的 `TurnLimit`）：超过即挑战失败（忘却之庭层板 30、星启板 45）；
   - **通关分数线**（`ClearScore`）：虚构叙事层板 30000、虚构叙事星启关 45000（`tierce.score` 就是星启关自己的 `ClearScore`，与星级目标的第 4 档 99000 是两回事）；
   - **无数值门槛**（末日幻影 / 异相仲裁）：官方判据是「击败 N 个首领 / 完成关卡」，N 取该面板的实际场次数（末日幻影层板 2）或星启节点数（3）。
2. **落法**：面板顶部先改 **2×2 网格**（`nk-egd-head`，等宽两列；窄屏单列堆叠，读序不变），四格 = 通关条件（新件 `EndgameClearCondition`，值 + 口径标签，与旧「赛季规则」同一套 HUD 语言，故虚构叙事的赛季规则栏并入本格）/ 通关奖励 / 星级目标 / 星级奖励（新件 `EndgameStarRewardCell`）。层 tab 与星启 tab 同形。**（同日补记四修订：后两格已合并为「星级奖励列表」，一档一行，见上。）**
3. **星启板的星级奖励**：星启关的 3 星与常规末层**共享记录**（官方规则说明「和常规模式第 N 关共享 3 星挑战记录」），故取末层的切片；星启自己的第 4 档（满分/棱彩星）不进星数档，其额外奖励已在 `tierce.rewards`（含限时通关勋章）。
4. **未覆盖**：异相仲裁不套这块板——它的 tab 是「关卡」而非「层 / 星启」，且 `ChallengePeakConfig`（8 字段）与 `ChallengePeakConfig/HardTarget` 里既没有逐关奖励字段也没有轮限制/分数线，奖励全走 `ChallengePeakReward` 的分档（本轮只上屏骑士/王棋星数两类）。若日后要给它同一块板，得先解决那三类档位的语义（无官方文案）。

## 补记三（2026-10-07：星启板的「棱彩星」行 —— 满分档不是第 4 颗星）

用户指出官方规则说明「星启模式中第 4 关通关且获得 99000 分，即可以获得棱彩星和额外的新奖励」在页面上没体现。核对与落法：

1. **满分档早已在数据里，只是没有身份**：星启目标 = `OGEOMCGNNMP` 三档 + `GNGENMHNLAH`「满分档」（此前按 ADR 0032/0033 并入 targets 末位）。官方说明里的「99000 分 / 剩余 33 轮以上」正是这个满分档（虚构叙事 99000、末日幻影 10200、忘却之庭「获得 3 星且剩余 33 轮以上」）——它不是第 4 颗星，而是**棱彩星条件档**。
2. **棱彩星额外奖励也早就在数据里，只是被当成未消费字段**：星启表 `IMCMJHAMMKK` 是三模式各自的**奖励 ID**（忘却之庭 101913 / 虚构叙事 102113 / 末日幻影 101713，落在本模式奖励族里）→ `RewardData` = 星琼 100 + 信用点 20000 + 璧羽 100。它与 `EGEEJLHBALB`（通关奖励，含限时通关勋章 + 星琼 900 + 璧羽 700 + 材料 + 信用点 380000）**是两笔**，此前字段映射把它记作「未消费（语义未验证）」。
3. **落法**：转换器给满分档打 `prism`，并由 `IMCMJHAMMKK` 产出 `tierce.prism_reward`；前端 `EndgameTierce` 把星级目标拆成「3 档（＝3 星）」+ 第三行 **棱彩星（满分档条件，经 `targetHtml` 渲染）｜棱彩星奖励（chips）**。星启板因此是 2×2 + 1 行，且星级目标与星级奖励从此同数（3 档 ↔ 3 星档）。
4. **未单列**：官方还有一条「累计获得 N 星和棱彩星还可以获得本期限时通关勋章」——勋章本身就在通关奖励 chips 里（`ItemID 122001`），本轮不另起一行。

## 补记四（2026-10-07：星级目标与星级奖励合并为「一档一行」列表）

用户裁决「再优化一下星级目标和星级奖励的排版，现在不再是左右两栏」，并给出目标形态：每档一行 `★ 目标 ……… 该档奖励`。

1. **判据：奖励本来就是按档发的，目标与奖励应同行**。此前「星级目标」与「星级奖励」各占一栏（左条件右奖励），读者要在两栏之间自己找对应档位；改成 **一档一行** = 档位徽章 + 该档条件（星级目标，逐目标一行）+ 该档奖励 chips。该列表跨满面板宽度（`nk-egd-tierlist`），面板结构变为「通关条件｜通关奖励 两栏 + 星级奖励列表」。
2. **配对规则（`renders.ts → starTierRows` 纯函数）**：档位数与目标数不等时，目标按 `ceil(目标数 / 档数)` 成组挂到对应档。实测逐层恒为 3 个目标 ⇒ 忘却之庭（奖励线 3 星一档）1 档吃下 3 个目标；虚构叙事 / 末日幻影（每星一档）3 档各 1 个目标。奖励线缺失的期退化为每目标一行、不带奖励（不隐藏目标）。
3. **棱彩星档同形**：满分档（`prism`）作为末位一行追加，徽章走「棱彩星」（不是 `N★`），条件 = 该档文本、奖励 = `prism_reward`。星启板因此恒为「3 星档 + 1 棱彩星档」四行（忘却之庭星启只有 1 个星数档 ⇒ 两行）。
4. **组件收口**：`EndgameStarTargets.vue` / `EndgameStarRewardCell.vue` 删除，拆成 `EndgameTargetRow.vue`（单条目标行：语义胶囊或星标 + 文本）+ `EndgameStarTierList.vue`（列表本体，层 tab 与星启板共用），配对纯函数进 `renders.ts`。栏名 = 「星级目标 · 星级奖励」（含回合 / 减员档时仍按官方口径叫「挑战目标 · 星级奖励」）。
5. **条件与奖励之间连一条虚线**（用户追加：「有质感的虚线连接」）：行内加一个纯装饰的引导线格（`nk-egd-tier__lead`，`aria-hidden`），桌面端四轨网格 `auto | minmax(0, auto) | minmax(24px, 1fr) | auto`（条件按内容宽、引导线吃掉剩余空间、奖励右对齐）；图案是**长划 + 点两遍叠加**（`repeating-linear-gradient` 3/10px + `radial-gradient` 圆点）而不是单一点线——页内已到处是 1px 发丝线，单线会与它们同族（同 `tokens.css` 的「点阵而非直线网」判据），两遍交替才有引导线的质感；两端用 `mask` 淡出（右端更短，让虚线「落到」奖励上），颜色只用 `--line-2`。窄屏奖励落到条件之下，引导线 `display: none`。
6. **逐目标标星 + 徽章写「累计 N★」**（用户追加：「每个挑战目标对应一颗星的奖励，你优化一下展示」）：**一档吃多个目标**时（忘却之庭：奖励线只有 3★/6★… 档，一层 3 个目标 = 3 星才推一档）逐目标标出它那 1 星，档位徽章上的星数才看得出从哪来；**1 目标 1 档**的模式（虚构叙事 / 末日幻影，奖励线每星一档）不标——档位徽章本身就是那颗星，再画一颗是同一件事说两遍。同时徽章文案由 `N★` 改为**累计 N★**：`StarCount` 是**累计**星数（印记馈赠的领取判据），与「本层 3 个目标」不是同一层意思，不写「累计」会被读成「本层给 N 星」。
7. **括号标组、虚线仍只一条**（用户追加：「他和末日幻影的排版不一样……每个目标一行 ······ 该档奖励」→ 试用后回退：「效果不如之前的，回退到之前只有一条虚线的版本。不过可以在三个挑战目标右侧加一个涵盖三个挑战目标的括号」）：先试过「每个目标一行 + 奖励跨行居中」，实测版面对不上（三条虚线汇聚到同一块奖励，行高被拉长），**按用户裁决回退**到「目标在条件块内逐行堆叠 + 一条引导虚线 + 一份奖励」；补的是**条件块右侧一个跨越这些目标的括号**（`nk-egd-tier__brace`，纯装饰、`aria-hidden`）：右脊椎 + 上下两撇 + 右侧圆角，`align-self: stretch` 横跨条件块行高，颜色同档位徽章（`--eg-color` 42%）。**只在「一档吃多个目标」时渲染**（`row.targets.length > 1`，与逐目标标星同一判据）——1 目标 1 档的模式加括号是空话。括号外侧才接引导虚线：括号说「这几个目标同属一档」，虚线说「该档奖励是这份」。
8. **CSS 变量名踩坑**：写括号时用了不存在的 `var(--radius-sm)` / `var(--radius-2)`（真实令牌是 `--nk-radius-1/2/3/card`）。`var()` 未定义且无 fallback ⇒ 该声明在计算期失效、属性退回初始值（档位徽章的圆角因此一直是 0，没人发现），**构建三守卫不查变量是否存在**——`.nk-egd-tier__badge` / `__brace` 已改用真令牌。
