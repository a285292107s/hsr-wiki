# 0016. 枢纽页模式切换入口的落点分工

> 下方正文按当时决策原样保留（历史记录，勿据其推断现状）；因前提消失而失效的替代方案条目已在 0018 的「替代方案」表中逐条重述。

## 背景

两个枢纽页（`/` 与 `/currency`）是全屏 KV/视频展示页，页面本身可滚但不承载浏览目的；桌面态（≥768px）还**不渲染左侧导航栏**（`meta.bareNav`），页内只有板块索引与页脚。因此枢纽页上「怎么换模式、换过去落在哪」不能靠侧栏解决，必须由页内与手势分担。

历史上曾有四个模式切换入口并存，其中三个落点不同、一个完全重叠：

| 入口 | 曾用落点 |
|---|---|
| 侧栏「交换」按钮（`SWAP_ITEM`） | 对方模式**枢纽页** |
| 枢纽页 Hero 左上角「枢纽切换按钮」（`HubToggle.vue`） | 对方模式**枢纽页** |
| 枢纽滚轮**上滚**（`use-hub-wheel.ts`） | 对方模式**枢纽页** |
| 侧栏本模式枢纽项（`NORMAL_HUB_ITEM` / `CW_HUB_ITEM`） | 本模式枢纽页 |

三个入口全指向对方枢纽页，彼此完全重叠；而**没有任何入口指向对方模式的图签页**——用户想「换到另一个模式看角色」，必须先落到对方枢纽页、再点一次首项。这是本轮修订要解决的冗余与缺口。

## 决策

**模式切换入口按落点分工，每个入口的落点由它在页面层级中的位置决定：**

1. **侧栏「交换」**（`SWAP_ITEM`）→ 对方模式的**图签页**（`/` → `/currency/role`，`/currency` → `/character`）。它承担「我要去另一个模式」的主通路，一次点击直达数据。
2. **枢纽滚轮上滚**（`use-hub-wheel.ts` 的 `upPath`）→ 对方模式的**枢纽页**（`/` ↔ `/currency`），保持不变。它承担「我在枢纽页上，想看看另一个模式的枢纽」。
3. **货币战争枢纽页「枢纽返回行」**（`/currency` 板块索引区末行）→ 常规模式**首页** `/`。它是唯一新增的页内入口，补上 `bareNav` 桌面态「深链直达 `/currency` 后无法回到常规模式」的空档。
4. **页内「枢纽切换按钮」（`HubToggle.vue`）移除**——其职责被 1 与 2 覆盖，且它与「交换」的可见文案（「首页」/「货币战争」）与侧栏 Tab 标签（「首页」/「枢纽」）在语义上互相干扰。

滚轮手势的生效边界不变：**仅桌面断点（≥1024px）且在 Hero 元素范围内**；下滚 = 进入本模式图签页，上滚 = 对方枢纽页。

「交换」的可见与无障碍文案只写「前往<模式名>」，**不暴露落点粒度**——落点由本 ADR 与 `CONTEXT.md`「交换」词条定义，不写进 UI 文案（避免把「去图签」这个实现细节当成用户要记的规则）。

## 后果

**正面**

- 四个入口收敛为三个，各有单一落点，「我要换模式」有两条粒度不同的通路：**交换 = 直接看数据**，**上滚 = 先看对方枢纽**。
- `/currency` 在桌面态（无侧栏）恢复了可见的返回常规模式入口，「枢纽返回行」复用板块索引行原语，零新样式。
- 页内不再有第二个模式切换按钮，`HubToggle.vue` 与其冻结契约（`data-hub-toggle`、全断点渲染、`push` 可后退）一并退场，少一处需要同步维护的对外契约。

**负面**

- **上滚与「交换」落点不同，是一份需要记住的隐式规则**：同一次「我要换模式」的意图，点侧栏「交换」到对方图签页、在枢纽 Hero 里上滚到对方枢纽页。二者在桌面端点不冲突（桌面枢纽页无侧栏，不同时可见），但用户在两个入口间切换时需要重新建立预期。**这也是上滚不能一并改指图签页的原因**：移除 `HubToggle.vue` 后，上滚是桌面枢纽页**唯一的模式切换通道**，若它又只指图签页，则「换模式后先看对方枢纽」这一需求在桌面上再无通路（`CW_GATEWAY` 只存在于 `/`，`/currency` 不设对应网关行）。
- **手势方向被语义锁定**：改主意的代价是改变用户的手指记忆，不是改一个常量——这是本决策难以逆转的根源，也是它值得记录的原因。
- 触控板惯性反冲无保护（不设时序锁，沿用 `navDir` 方向过渡）：从图签页上滚返回枢纽页时，惯性余量可能被枢纽页当作「上滚」而立刻再切模式。该风险已知并接受。
- 手势不提供任何屏幕提示：只用鼠标的用户可能永远不知道存在这条通路。它被发现的前提是「顺手滚一下」。
- **「交换」落点变更使侧栏首项不再落在枢纽页**：用户从任意板块页点「交换」，会直接进入对方模式的图签页，跳过对方枢纽页——枢纽页作为「模式身份页」的曝光因此降低，其身份改由滚轮上滚与模式 Tab 承担。
- 文案与落点存在刻意的粒度差：「交换」的 `aria-label` 只说「前往常规模式 / 前往货币战争」，不说「角色图签」。**这是有意为之**（保留落地调整空间），代价是单看 UI 文案推断不出落点——禁止据 UI 文案反推落点后「修正」代码。
- `bareNav` 桌面态仍不渲染侧栏，页内工具组禁令继续生效；「枢纽返回行」是该禁令的**唯一例外**，`/` 不设对应行（跨模式入口由既有 `CW_GATEWAY` 网关行承担），禁止顺手对称补齐。

**中性**

- 每个方向只有一个落点，不随滚动距离或速度分级。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 保留 `HubToggle.vue`，只改「交换」落点 | 三个入口中有两个仍指向对方枢纽页，冗余未消；且按钮文案（「首页」/「货币战争」）与侧栏 Tab 标签（「首页」/「枢纽」）在同一屏语义打架 |
| 上滚改为指向对方**图签页**，与「交换」落点统一 | 桌面枢纽页将失去「先看对方枢纽」的通路（移除按钮后上滚是唯一通道），且下滚/上滚都会指向图签页，手势失去方向表达力 |
| 取消上滚通道（`upPath` 传 `null`） | 桌面枢纽页将无任何模式切换通道，深链直达 `/currency` 只能靠浏览器后退或改 URL |
| 不进 Hero 区，改为**侧栏枢纽项改指图签页** | 曾按此方向实施（ADR 0017）：两个模式的枢纽项与各自板块首项路径完全重复，侧栏出现两条同路由项（`v-for` 重复键、双 `aria-current="page"`、白占手机槽位）。用户裁定作废，ADR 0017 已删除、编号不复用 |
| 「枢纽返回行」做成独立返回按钮或页脚文本链接 | 独立按钮需新样式与新层级决策；页脚链接可发现性过低。复用板块索引行原语零成本且与页面视觉族一致 |
| 滚轮到底/到顶后再滚才跳（阈值 + 冷却） | 不夺走正常滚动，但「滚了就该跳」的直觉被削弱，且需额外定义阈值与冷却时长参数 |
| 「枢纽返回行」在 `/` 也对称补一行 | `/` 的跨模式入口已由 `CW_GATEWAY` 网关行承担，对称补齐属重复入口，违反「枢纽页身份是选路、工具组单一居所」的既有裁定 |
