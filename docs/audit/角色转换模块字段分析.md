# 角色转换模块字段分析（常规模式 + 货币战争）

> **定位**：转换模块（converter）侧的角色字段活文档——逐字段说明「输出字段 → 源字段 → 转换逻辑 → 消费方 → 验证状态」。
> 与 [角色数据探索](../data/角色数据探索.md)（源数据侧全目录分布）互补：前者看「数据从哪来」，本文看「转换器怎么处理」。
> **两模式共用的字段规则只在第七节写一次，货币战争（CW）差异以小节与「模式」列表达。**
> 深度审计：常规模式与货币战争均为 2026-08-02（分支 `feature/character-converter-audit` / `feature/currency-converter-audit`），后续字段勘正随文标注。

## 一、范围与基准

### 1.1 模块与输出

| 模式 | 模块 | 输出 | 审计级别 |
|------|------|------|----------|
| 常规 | `characters.py` | `characters.json`（全部可玩角色索引） | 核心 |
| 常规 | `character_detail.py` | `characters/{id}.json`（每个角色一份；19 个源文件联合） | 核心全量 |
| 常规 | ~~`character_ranks.py`~~ / ~~`character_skills.py`~~ | ~~`character_ranks.json` / `character_skills.json`~~ | **已废弃删除**（见第四节） |
| CW | `currency.py` | `currency/role.json` + `currency/role/{id}.json` | 核心全量 |
| CW | `currency_catalog.py` | `currency/traits.json`、`equipment.json`、`portals.json`、`augments.json`、`prop_icons.json` | 关联核查 |
| CW | ~~`season.py`~~ | ~~`currency/season.json`~~ | **已删除**（赛季扩充说明展示下线，随 ADR 0016 一并移除转换器与产物） |

### 1.2 正确性基准

- **忠实性**：输出值与源数据一致（常规：全量角色 JSON 结构对比 + 7 角色数值抽样；CW：全部 `role/*.json` 各层 key 对比 + 7 角色数值抽样）。
- **语义性**：字段含义正确（已知陷阱清单逐项核查）；**不引入外部数据基准**（源数据即真相，特殊数值标注待人工核验）。
- **CW 三层对比法**：`源字段全集 ⊇ 转换器读取 ⊇ 输出 ⊇ 前端消费`。
  「前端消费 ⊄ 输出」→ 直接影响 bug（当场修复）；「源字段 − 读取」→ 遗留字段（A/B/C 分级，见第十节）。

## 四、已废弃：`character_ranks.json` / `character_skills.json`

**结论（已执行删除）**：第二期 `character_detail` 在 `characters/{id}.json` 内自建了质量更高的星魂/技能数据（全等级参数、HideInUI 与内部技能过滤、保留富文本标签），前端已全面改用详情数据，两索引 grep 全库零引用。git 历史为第一期引入（`5d7e155`），ADR 0006 记录为「第一期只含 name/desc/icon」。

历史字段（留档，无消费方）：`character_ranks` = `id/rank/name/desc/icon`（源 `RankID/Rank/Name/Desc/IconPath`，desc 走 `clean_text` 清洗，与详情版 `clean=False` 不同）；`character_skills` = `id/name/tag/type/type_name/desc/simple_desc/icon/max_level`（同一 SkillID 只取第一条，`type` 未命中映射返回空串）。

**遗留质量缺陷无影响面**：688 个技能含 27 个 HideInUI + 13 个内部技能（Skill31-34）；112 个 `type` 为空串（AttackType 未命中映射，如忆灵技能）。因前端未消费，未造成线上影响，随模块删除一并消除。

## 七、共用字段规则（两模式一致，只在此处维护）

1. **`unwrap_value` 解包**：源字段的 `{ "Value": x }` 包装一律解包为纯数字（`SPBase` / `SPNeed` / `BPNeed` / `ShowStanceList[]` / `ParamList[]` / `Aggro` 等）。
2. **战技点语义（`BPNeed` / `BPAdd`，2026-08-15 勘正，两模式同一规则）**：`BPNeed = -1` 表示**不消耗**战技点（普攻/终结技/天赋），**不是产出**；正值 = 消耗 N。产出语义在 `BPAdd`（=1 表示获得 1 战技点；常规模式仅普攻有值，CW 仅 4 个角色普攻带值）。常规模式大世界终结技 1830 条全为 -1 佐证。
3. **SP / 能量字段**：常规 `SPBase`（技能能量）与技能级 `SPNeed`（忆灵终结技独有 + 5 个双段能量角色，2 倍关系）；CW `sp_base` = 能量产生值，`sp_need` = 终结技能量需求。`SPMultipleRatio`（全局常量 0.5）为充能倍率、无逐技能区分度，**两模式均不输出**。
4. **技能标签 `tag`**：取官方 `SkillTag` 中文直出（常规如「单攻」「召唤」，CW 如「群攻」），空转 null（方案 A，ADR 0008）；曾用 `SkillEffect` 枚举 + 前端映射，**已废弃**，前端不再维护 TAG 映射，韧性条独立 `STANCE_TAG`。
5. **削韧字段**：`ShowStanceList`（逐项解包）、`StanceDamageType`（削韧属性枚举）、`StanceDamageDisplay`（削韧显示值）——常规技能与 CW star 节点同义。
6. **技能类型 `type`**：常规取 `SkillTriggerKey` 优先 → `AttackType` 兜底（未知槽位透传 null）；CW 取 `SkillTypeDesc`（TextMap，空转 null）。
7. **富文本与清洗分工**：详情类文本走 `clean=False`，保留 `<color>`/`<unbreak>`/`<u>`/`\n` 交前端渲染（`gameTagsToHtml` / `fmtDesc`）；索引类文本走 `clean_text` 清洗为纯文本；`{F#}{M#}` 性别占位转换器保留原样、前端提取。标签与占位符全表见 `docs/data/hsr-rich-text-tags.md`。
8. **图标路径**：常规模式经 `map_icon_path` 前缀映射（行迹图标另有 `1{avatar_id}` 伪目录归一，`_normalize_tree_icon`）；CW 多为原样输出、由前端拼 CDN。
9. **token 类名称需 xxhash**：星魂名、行迹名是字符串 token（如 `AvatarRankName_130801`），不是数值 Hash，须先算 xxhash 才能命中 `TextMap`。
