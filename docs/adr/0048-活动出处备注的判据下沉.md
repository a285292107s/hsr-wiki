# 0048. 活动出处备注的判据下沉（`art_shared`）与文案收窄

## 状态

`accepted`（**已实现**：`monster_detail._art_shared` + `monsters.catalog_rows` 新增、详情 payload 增
`art_shared`；`MonsterDetailView.vue` 的备注块改名「活动出处」并重写三行文案、删掉旧 computed
`artSharedWith`（改读 payload）；`gen-ai-endpoints.mjs` 的等级区间与页面同口径；`pytest` 新增
`test_art_shared_prefers_same_figure_peer`；`e2e/layout-monster.spec.ts` 增美术复用断言与
「不得声称技能组复用」负向哨；`public/data/cn/monsters/*.json` 重生成）

## 1. 背景与问题

用户问：「『出没关卡』中这个备注内容是否也应该迭代？」盘点 42 个带 `event` 的目录条目后发现五处：

1. **标签「备注」无意义**（等于没起名）；
2. **活动名与样本 chip 重复**：29/42 页的 chip 已经写成「活动名 · 关卡名」，备注再报一次活动名；
3. **数字与上方重复**：6/42 页 `event.count` 恰等于「出现在 N 个关卡」的 `total`，同屏两个相同的数；
4. **假区间**：5/42 页全档同等级，文案渲染成「等级 85–85」；
5. **过度断言（最严重）**：旧文案「官方在该活动中直接复用「X」的模型、立绘与**技能组**」——
   实测逐维度核对：**技能集按 ID 全不同**（活动变体各有一套技能 ID），按「同名 + 同标签 + 同描述」
   比对也有 22/26 个活动敌人的技能集与同伴不同；**立绘**在按目录卡面图标分组的多名字组里有 2/90 组不同。
   即：这句在多数页面上把「同卡面」说成了「共用美术与技能组」。

## 2. 判定

**判据必须在数据层，不能留在视图**：视图只有自己的详情与目录的 `icon`，比不了同伴的立绘
（同伴的 `figure` 只在各自详情里）。旧实现用「图标 stem 相同」在视图里推「共用美术」，才写出那句
过度断言。故按仓规「判据下沉 + 页面只读 payload」处理。

## 3. 决策

1. **新增 payload `art_shared = {id, name, figure, forms}`**（`monster_detail._art_shared`，缺位＝没有
   这样的同伴，实测 **397/632** 有值）：
   - 分组判据 = **目录卡面图标同一份资源（`icon` 文件名相同）且名字不同**；全集用
     `monsters.catalog_rows()`（与目录页同一批可见条目，两处必须同源）；
   - `figure` = 被点名同伴的**立绘**是否与本形态相同，**优先点名立绘相同的同伴**；
   - `forms` = 同卡面形态数（含自己）。
2. **文案按两个维度分支**（页面）：`figure` 真 →「本形态没有独立美术：卡面与立绘与「X」共用（同卡面共 N 个形态）」；
   假 →「本形态与「X」等 N 个形态同卡面图标，立绘不同」。
3. **删除「技能组复用」这句**：站点没有可断言的「技能组相同」（见 §1.5），技能本身就在页面的
   「技能」区块里逐条列出，不需要一句站不住的转述。
4. **备注块改名「活动出处」**，并去掉句内重复的「活动出处：」前缀；**活动内关卡数只在 ≠ 上方总数时写**，
   相等时改说「全部关卡都在「X」活动里」（同屏不出现两个相同的数）；**等级单档不写区间**。
5. **AI 快照仍只出源文本事实**（活动名 / 页签 / 等级，等级区间与页面同口径），**不断言复用**——
   快照是事实表，美术复用是展示层解释。

## 4. 影响面

- `tools/converter/converters/monsters.py`：新增 `catalog_rows(facets=None)`（目录全集单点，
  `convert()` 改为调用它）。
- `tools/converter/converters/monster_detail.py`：新增 `_art_shared`，payload 增 `art_shared`。
- 数据：`public/data/cn/monsters/*.json` 重生成（397 个文件多出 `art_shared`；42 个 `event` 条目文案相关字段不变）。
- 前端：`MonsterDetailView.vue`（删 `artSharedWith` + `listRows` + `monsterIconStem` 引用，新增
  `eventLevelText`，重写备注块）、`src/services/types/monster.ts`（`MonsterArtShared`）。
- 快照：`tools/gen-ai-endpoints.mjs`（`eventLevelRange`）。
- 测试：`pytest`（`_art_shared` 三例：立绘相同的同伴优先 / 只有立绘不同的同伴时 `figure=false` / 无同伴不落键）；
  `e2e/layout-monster.spec.ts`（活动出处逐项 + 数量去重分支 + 无假区间 + 美术复用按维度表述 +
  **不得出现「技能组」**）。

## 5. 后果

- 备注块从「一句内部口径 + 一句过度断言」变成「活动出处（源文本事实）+ 美术复用（按数据给的两个维度）」，
  读者知道**为什么点进来立绘是别人**，而站点不再替官方宣称「技能组复用」。
- 「同卡面 ≠ 共用立绘」这条区分被显式建模：`figure=false` 的条目实测 **5 个**（无尽寒冬之槊的 4 个形态
  与「失控的飞霄」）。**注意**：备注块只在有 `event` 的页面渲染，而这 5 个当前都没有 `event`
  ⇒ 该分支**目前不会上屏**，它是给上游数据变化留的正确表述（比写死一句「共用美术」稳）。
  同卡面分组的 92 个多名字组里，90 组立绘一致、2 组不一致（`Monster_1002013` 无尽寒冬之槊族含
  「公司组长幻象」、`Monster_2035010` 飞霄族）。
- 备注块仍只在有 `event` 的 42 页出现；`art_shared` 本身是通用事实（397 条），若日后要在别处用，
  直接读 payload 即可，不必再在视图里按图标 stem 推。
