# UI 令牌与样式

> 本域补 [ui-design.md](../agents/ui-design.md) 的盲区：该文件写「规则是什么」，本文件只写规则推不出的**静默失效坑位**与**判据的理由**——为什么这样判、不这样判会在哪一步踩到。

以下判据已在 [ui-design.md](../agents/ui-design.md) §2/§4/§6 声明，本文件不复述：check-contrast 盲区、改底色与表面阶梯同批上移、`--nk-prose-max` 按字号缩放、守卫全绿 ≠ 语法正确、枢纽品牌带装饰退场、地面材质三判据、`background-attachment` 语义、eyebrow 候选上限、视差用能力查询。

## 静默失效：不报错但结果错

- **`:has()` 写完必须量「实测命中几条」**：它与 DOM 里有没有同级兄弟强耦合，视图加一个同级元素（如 `<aside>`）就永久失效，且完全静默——选择器合法、守卫全绿。`catalog.css`
- **结构性派生一律用 `:has(> …)`，不要用兄弟/位置伪类**：父级竖轨写成 `.nk-skill:has(> .nk-skill--child)` 才只在真有子卡时渲染，单卡族/无族退化路径不出悬空线；网格同理，否则对比模式复用同一 `__body` 时会被改成两列。`character-skills.css`
- **只给部分属性写缓动等于没写**：未写的静默回落浏览器默认 `ease`。改后要静态检测「裸时长」为 0。
- **`:hover` 改过的属性必须在 `@media (hover: none)` 里同步复位**，且展开态单独重新声明（`.open:hover`）：该媒体块在文件末尾，同特异性下会盖掉基态，触屏上展开中的按钮掉色回灰。
- **`focus-visible` 共享组里的 `border-radius` 会改按钮本体圆角**：组内该声明本意是给 outline 定形，对无可见盒子的文字按钮无害；按钮一旦有了圆角盒，聚焦瞬间跳形。此类必须单列复位、不进共享组。
- **同权重档位规则混写会让断点规则被非媒体规则反压**：两处档位规则权重相同时靠源序判定，把手机档规则写成非媒体查询 ⇒ 平板断点内两条并列命中、后写的非媒体规则胜出。**每个断点每一档只允许一条声明**。
- **清理「被后写覆盖的声明」前先比特异性**：特异性更高的那份从来不是死代码。终局页死声明里唯一必留的是 0,2,0 的那条，收口块压不住它——必须显式留下并登记为覆盖豁免（代码里不留解释性注释，与 [architecture.md](architecture.md)「跨文件重复实现」的有意覆盖同一条纪律）。
- **大字号的阈值不同**：≥24px（或 ≥18.66px 粗体）判 3:1 而非 4.5:1。hero 名称属此档，按 4.5:1 判会得出「名称也不达标」的假结论。
- **`region` 命中数 ≈ 页面内容块数，不是「个别元素」问题**：正文没有 landmark 时整页节点一起命中，读屏用户只能从头听到尾。修法是三种态外层包 `<main>`。
- **有可见文字的图片必须装饰化（`alt` 与可见文字二选一）**：否则读屏念两遍。同一模板里两类槽的策略必须分开判——看它旁边有没有可见文字。
- **`!important` 的 `transition` 简写会把 `transition-property` 整体限死为它列出的属性**：未列出的属性（opacity / transform）的插值被静默吃掉，表现为「动画没播」。判据 = computed `transition-property` 不含目标属性，**排查「动画没播」要先看 property，只看 duration / delay 会误判成「时长没生效」**；修法是收窄选择器（`*:not([class*="nk-view-"])`），不是拆成逐属性写法。`src/styles/tokens.css`、`src/app/App.vue`
- **删掉一个「死样式 / 死层」会改变它曾遮住的另一层的可见度**：纯 A/B 差值只反映净效果，看不出「原来是它挡着」——左右渐隐 `::before`（`z-index: 1`）画在 inset `box-shadow` 之上，删掉后最外圈暗角反而更明显。**判死代码前先查它是不是某层的唯一遮蔽物。**`src/styles/character-hero.css`
- **全局重置的双重静默失效**：① `#id 元素` 形态的重复副本特异性 (1,0,1) 会压死类选择器的间距；② 重置清单漏 `h4` / `h5` / `h6` 则 UA 的 `1.33em` 外边距泄漏。`src/styles/tokens.css`、`catalog.css`、`currency-hub.css`
- **删「页面级覆写」≠ 取消**：删掉整条规则会**回落到基线更重的值**（光锥 hero 的暗角是覆写基线两层更重的 inset，删规则反而更暗）。必须显式 `box-shadow: none` / `background: none`（`::before` 同理）。`src/styles/lightcone.css`
- **卡片文案里的字面 `\n` 是数据原样，不归一化就会印在界面上**：`public/data/cn/currency/traits.json` 的 `simple_desc`（正文已转 `$t:` 引用，真值在语言包）带反斜杠+n（换行转义未还原），直接插值即可见 `\n` 两个字符，且构建与守卫都不报。归一化口径与目录卡 `renderCard` 同一条：`\\n` → 空格 → 空白折叠 → trim。`src/app/composables/use-release-showcase.ts`
- **数字统一格式化时三类不得动**：① 标识符 ID（加千分位后更难核对）；② 数据正文里的数字（那是游戏原文，重排等于改写数据文本）；③ 已带单位的百分比 / 星级 / 费用。`src/lib/format.ts`
- **只在 hover / focus / active 才换色的元素，其文字对比度从未被默认态扫描覆盖**：「悬停后掉到 4.5:1 以下」只存在于交互态。须逐元素 `hover()` / `focus()` 后**在该状态**跑 `color-contrast`。
- **落在单轴滚动容器之外的伪元素不报错，只是永远不渲染**：`overflow-x: auto` 会把另一轴的 `visible` 按规范算成 `auto`，padding box 之外一律裁掉。`.nk-secnav__btn--active::after` 写 `bottom: -7px` 就从未渲染出激活下划线，静默到只剩颜色差；按钮高度又恒等于导航盒高度，故任何 `bottom: -N` 都落在盒外。修法是让落点进按钮盒内（`bottom: 0`），判据取**计算值** `parseFloat(getComputedStyle(el,'::after').bottom) >= 0`——**别拿 `scrollHeight > clientHeight` 当判据**：同宿主上还有一条 `::before` 隐式热区，它独自就能把 `scrollHeight` 顶高。
- **「挂载时算一次」的溢出 / 断点判定会永久停在初值：布局在挂载后还会变**：一次性计算会把「本来不溢出」的档永久挂上「还有内容」的渐隐——提示相反的事实。正解是跟着布局走（`ResizeObserver` 观察容器盒宽覆盖视口 / 滚动条、观察首个子项宽覆盖字型替换），**不能拿 `document.fonts.ready` 当布局稳定信号**（它在目标元素挂载前就已 resolve）。判据要挑**只有该档能观测到**的视口。
- **`min-height` 撑高的 flex 按钮里，`align-items: baseline` 会把内容钉在行首**：单行 flex 容器把基线组放在行首、多余空间全落到尾部 ⇒ 44px 触控按钮里文字墨迹贴着上沿。而「按钮高 44 + 条高 47」两条断言在贴顶与居中两种形态下都成立，抓不到它——判据必须取**墨迹的上留白与下留白之差**。修法只有 `align-items: center`：`align-content: center` 对 `flex-wrap: nowrap` 的单行容器无效。
- **删掉详情页里最后一个可聚焦元素＝滚动盒同时丢掉键盘入口与 axe 通过**：`.nk-page--detail` 是各详情视图根节点上的**独立滚动盒**（`position: absolute; inset: 0; overflow-y: auto`），与文档滚动无关 ⇒ 焦点不在其中时 PageDown / 方向键滚不动内容，axe 报 `scrollable-region-focusable`。判据：`document.activeElement` 落在容器内 + 按 PageDown 后容器 `scrollTop` 增长；修法是根节点挂 `tabindex="0"`（焦点环由 tokens 的 `[tabindex]:focus-visible` 白送）。`src/app/views/RelicView.vue`
- **滚动时间轴驱动的「入场」若带 opacity，会把未进视口的区块判成低对比度**：`animation-timeline: view()` 把视口外元素钉在 `from` 态，axe 量的是渲染后的**有效色**，于是正文被算成 2:1 量级的假失败。入场只用 `translate` / `transform`、不碰 opacity；改成单文档后每个区块都会进一次 view 时间轴，这个坑才显形。`src/styles/relic.css`
- **靠「滚动即关闭」收口的浮层有两类合法滚动会被误判成失焦，两个豁免缺一即「菜单自己滚一下就没了」**：① 监听挂在 `document` 的 capture 阶段时，`scroll` 不冒泡、任何后代的滚动都会冒到文档 ⇒ 必须放行浮层**自身**的滚动（长选项列表 `overflow-y: auto`；浮层 Teleport 到 body，与视图滚动容器隔离）；② 点击按钮瞬间浏览器会把按钮滚进视口，紧随其后的 `scroll` 会把刚打开的浮层立刻关掉 ⇒ 需开窗（本项目 120ms）吸收这段自动滚动。自动化点击同样触发 ②。`src/app/catalog/CatalogFilterSelect.vue`

## 令牌收口与迁移

- **改主题色 = 必须全仓搜「为旧主色明度写的对比补偿」**：一批「浅底深字」补偿（`color: var(--blk-900)`、进度条渐变、局部令牌覆盖）只为旧色的明度成立，静态审查看不出「这条只在旧色下才对」，可靠办法是让 e2e 跑一遍。（ADR 0041）
- **令牌链的消费方向要逐个查**：原始层五族由 `[data-accent]` 别名层消费，另有领域边直连（`currency-role-hero.css` / `SystemMapSection.vue`）；**领域色不得引用别名层**——遗器徽章从 `--th-300` 改语义位 `--metric-val` 即此类纠正。
- **`--elem-*` 七个令牌全仓零消费者**：故「让角色页用上属性身份色」是零新颜色、零四步评审的改动；但扩展成 hero 整块会撞单强调色通道，需单独裁决。
- **页面级共享原语改造必须作用域化**：`.nk-title` 被六个页面共享，改 `tokens.css` 等于同时改六个页面版面。「改了某页 CSS 会不会波及别页」的第一步应该是**数根类名的写入方**（某根类全仓只有一处写入 ⇒ 天然不外溢），而不是先跑全量 e2e。`src/styles/tokens.css`
- **`scrollbar-color` 写在 `#app` 上即可**（继承属性，一处覆盖全部滚动容器）；但**不要顺手加 `scrollbar-width: thin`**——细滚动条让容器宽出约 7px，虚拟网格格宽与像素基线连锁变化。
- **`::selection` 提为全局时页面级那份必须同时删除**（同一事实只留一处）；环境层同理收口成单点事实源，页面根转透明。
- **刻度收口后 `calc(刻度 ± n)` 是离刻度值的藏身处**：它字面上引用了令牌，却把结果推离刻度。**复审刻度一致性时要专门扫 calc 表达式**，不能只查字面量。

## 字阶与圆角刻度

- **容差必须按量纲分层，否则会「压平有意的设计」**：一律同一容差 ⇒ 响应式 `clamp` 与特写尺寸必然超差、全进人工裁决队列。验收要跑「全量数据 × 2 断点」的盒高中位数探针（抽样集会因新档位占比算错，某档在抽样里 0 只）；而「两态同高」必须由骨架与就绪**同源消费单一令牌**构造（就绪高 = `max(内容高, 令牌值)`），不靠「常量恰好等于内容高」这种级巧合。
- **刻度 codemod 只写「就近落档」、不做等距化**：目的是让取值来自刻度，而不是借收口之名重新设计字号。
- **动字号前先找「谁按字号算过尺寸」**（槽高、行盒、图标盒、骨架代理盒）：槽高 = 本档主字上限 × 行距，骨架屏靠它代理固定盒高，改字号不改槽高 ⇒ 骨架↔就绪错位。单字档与多字档各一个槽高（单字字号更大），都要查。
- **就绪态推进不能只等 `requestAnimationFrame`**：后台标签页的 rAF 不排期（回调要等页面可见才跑）⇒ 状态翻转与滚动定位被推迟到切回前台。判据 `document.visibilityState === 'hidden'` 时改用 `setTimeout(…, 0)` 兜底推进，把「等一帧」只留给可见路径。`src/app/views/EndgameView.vue`
- **同类交互的「写法不同」比「用哪个值」更值得修**：同一类悬停若横跨多族多种时长 + 多种曲线，时长分档就要由令牌承载，**契约从令牌读期望值**——改档不会让用例变红，只有组件自造值才会。
- **动效分档按「改哪些属性」归位**：卡片**表面**（border-color / box-shadow / transform / opacity）→ normal 档，**标签**与控件（color / background / filter）→ hover 档，图片放大 → zoom 档。
- **页面设计语言声明的档位必须能在实测里数出来**：头部声明三档圆角而实测出现七种是常态。归一要**按语义归类比脚本盲替可靠**——同一个 6px 落在图标、chip、按钮上应分别归到内联档与容器档。
- **契约要跟着语言收窄**：清理必须配契约（四值白名单、容器档期望值从页面令牌派生），否则只是「这次干净」。
- **全局 `--nk-radius-card` 与页面声明冲突时，第三条路是页面另立一名**：只动本页 CSS，不要为单页去改全局 token。`50%` 与胶囊是**形态**不是档位。

## 几何与形态判据

- **`<input>` 放进 flex 行必须写 `min-width: 0`**：表单控件的 `min-width: auto` 解析成**固有宽**（Chromium 下 `input[type=range]` 约 129px），flex 收缩下不去 ⇒ 窄视口（320px）上长译文标签把这一行顶出容器，再被页面根的 `overflow-x: hidden` 静默吃掉。`flex: 1` 不解决这件事——`flex-basis: 0%` 只作用于「可收缩」，收缩下限由固有宽决定。判据：横向溢出量不大且只在长译文语言出现时，先量「越界后代的固有宽」而不是调容器宽度。`.nk-skill__slider > input`
- **「元素类型差异」的可见性取决于布局是否把文字盒拉伸**：UA 给 `<button>` 声明 `text-align: center`，单行 / 收缩盒里它是空转，纵向 flex 把子项拉满时才显形。故不能靠读样式表判定，要跨标签比对计算样式 + 做「改掉这个值再量 ink 位移」的差分。
- **任何 `max-content` / `fit-content` 轨，只要轨内元素的固有宽度由懒加载图决定，就必须写确定值**：图未加载时塌成文字宽、到达后涨到固有宽 ⇒ 同分区两张卡宽度差数倍 + 首屏位移（CLS）。
- **flex item 的 `min-height: auto` 在 `overflow != visible` 时降为 0**：column flex 容器里唯一带 `overflow: hidden` 的子项会被压塌到几十像素——详情页 Hero 曾因此把页面主标题压到不可见，而既有 Hero 恰好都没写 `overflow: hidden` 所以从未暴露。修法是给该子项 `flex: none`。
- **`auto-fill` 与 `auto-fit` 在固定条目数下行为相反**：`auto-fill` 在建轨阶段按可用宽度铺满、末行空轨**不收回**（宽屏下留一大块空白）；`auto-fit` 空轨塌缩。本仓惯例是 `auto-fill`（几百条目的卡片墙），**固定条目页必须用 `auto-fit`**。改列数时还要连带检查基线的「跨列 / 满行」规则（如 `:last-child:nth-child(odd) { grid-column: 1/-1 }`）——项数 % 列数 ≠ 0 时必然把末项顶成独立整行。
- **「名字是最长字段」的卡片，列宽下限必须由数据里的最长值反推**：不逐页翻，而是**把数据集里会出现名字全量喂给浏览器按真实字体测宽**，再与各断点可用宽度比较。
- **滚动落点与命中判定不能取同一个边界值**：取同一个值会有亚像素抖动时判定翻转（「点附件、亮技能」）；修法是落点比偏移线多让出几像素——滚动少走几像素用户看不见。而**锚点规则本身无解时要显式建状态**：页尾短区块永远排在长区块之后且已到滚动上限，任何「顶边越线」类规则都判不出它，正解＝把「用户点到的就是当前的」建成显式状态。
- **定位伪元素的包含块原点必须用真实哑元元素实测，禁止靠名词推导**：「padding box」有「外缘 / 内容区」两种口语含义。实测结论：包含块是宿主 padding box 的**外缘**，页面坐标 = `hostRect.top + css top`，**不加 padding**。
- **相对另一元素定位的装饰线，坐标必须相对同一个原点表达**：折角 `top` 相对 padding box、而说明里的「行顶」指卡顶 ⇒ 实现出来比图标中线低一个间距。
- **间距 / 尺寸类需求先把「单位 = 哪个既有令牌的整数倍」问定，再谈数值**：只在数值层应答会让同一处缩进反复改；用户的模型是「缩进必须等于既有尺寸的整数倍」。
- **共享卡片自带的机器感会随页面一起被判罚，但只能在页面作用域内收敛**：`nk-idx-card` / `nk-lc-card` / `nk-relic-card` 内部的等宽字（星标数 / 技能名 / 套装标签）、`text-shadow`（艺术图上压字的投影）、渐变遮罩与稀有度渐变底，在首页登记区会被门禁逐个记成 mono / text-shadow / gradient / outlined-box。判据：这些是**共享原语**、目录页仍是原形态，故必须在承载页面的作用域内重述为「平色 + 正文体 + 无投影」——早期在 `#nk-home-app` 内重述，该首页形态已由 [ADR 0063](../adr/0063-首页改为版本入册页-清单在前与分区分构图.md) 取代，登记区再出现时按同一判据重新作用域化。`nk-relic-card__plate` 的 1px 上下双线尤其要留意——板宽一旦 ≥240px 就直接多出一条 hairline 判罚。
- **大图的「原分辨率」比「画布尺寸」重要，反过来小图也不能放大当大图用**：大图区的主图取 `avatarcutinfigures` 与 `lightconemaxfigures`，而不是卡片图源——后者在板宽上已经是向上采样（早期用例是首页单条目分区，该分区已随 [ADR 0063](../adr/0063-首页改为版本入册页-清单在前与分区分构图.md) 退场，图的度量事实不变）。选图前先量包围盒：`lightconemaxfigures` 的 alpha 包围盒等于整张画布（可直接用），`avatarcutinfigures` 只有画布的一半左右（必须裁，否则板上一半是空的）；UI 页签小图（144×144）用 `cover` 铺成大图必然糊，图标只在原尺寸内缩处用。
- **方位词（正下方 / 中间 / 之下）必须当场落到具体参考点（哪条 x、哪条边）并配对比图**：靠形容词定几何，同一处只会来回改。
- **判据的适用层级必须与需求问的层级对齐**：「小视口上只剩无承载物的结构就让结构退场」只适用于**数值与支撑物**层（留白 / 缩进 / 装饰结构）；「整张卡片长什么样」是**产品形态**层，用户要的是全断点一套。省空间是**手段**不是目标——当需求说「要同一套」时，任何「窄屏更省空间」的量化论证都不是理由。
- **断点专属形态退场时，必须顺着它把「为它而生的配套」一并退场，否则留下的是双重装饰**：手机行式目录卡是无底无框、靠发丝线分隔的，因此首页版本上新带里曾为它补过一层表面（`padding` / 边框 / `--card` 底 / 圆角）。卡回到网格卡（自带 `::after` 边框 + 3:4 立绘）后，这层补表面变成**双描边 + 立绘被 padding 挤变形**。查法 = 退场时 grep 该卡的**所有**手机档声明位（不止它自己那个文件，还有复用它 `renderCard` 的宿主）。
- **骨架与就绪的列数必须同源，两处不对称即静默跳档**：① 骨架元素同时带两个类（`nk-skeleton__grid nk-idx-grid`）、就绪网格只带一个 ⇒ 任何写在骨架族的通配规则（`--nk-grid-gap`、`grid-template-columns`）都命中骨架、命中不到就绪，须给骨架族加 `:not(<就绪网格类>)`；② `virtualMinColW`（TS 侧 `floor((宽+gap)/(minColW+gap))`）与 `--nk-grid-min`（CSS 侧 `minmax()`）是两个独立算列数的实现，**必须 `--nk-grid-min ≥ virtualMinColW`**，CSS 更小时会多挤一列。改一个必须同批改另一个（含各断点档）。`src/app/catalog/use-virtual-grid.ts`、`src/styles/catalog.css`
- **同一徽章的可见文本与 `aria-label` 承担不同职责，不能共用同一个带名模板**：读屏看不到「徽章紧邻模式名」的视觉相邻性，`aria-label` 必须自带名字；但可见文本若也带名，就与紧邻的名字重复、宽度涨成「名宽 + 前缀」，长语言下把列头撑出列框并压到相邻列上（单项即可超整行预算）。判据 = **可见文本用不含名的独立词典键，`aria` 用带名模板**。`src/app/catalog/pages/endgame.ts`
- **「同一套排版」的验收必须断言形态指纹，不能断言「有网格 + 无溢出」**：行式卡形态本身也是「网格的 1 列 + 无溢出」，故弱断言在改动前后**都满分通过**。可判定的指纹取「不随列宽变化」的四项：`display`、立绘框 `aspect-ratio`、文字层 `position`、`<picture>` 双源是否存在；列数只作**单调相对关系**断言（视口变窄不得增列），不写绝对值。
- **圆头像与商店立绘的同名陷阱**：`avatarroundicon/<id>` 与 `avatarshopicon/<id>` **文件名同形**，只有目录段不同。断言「图源没按断点切」时比文件名等于没比，必须比 `currentSrc` 的**目录段**。
- **`flex: 1` 会让 `flex-wrap` 永不触发**：`flex: 1` 是 `flex: 1 1 0%` ⇒ 假定尺寸（flex-basis）恒为 0，容器**永远**判定「放得下」，折行分支一次都走不到。表现为「加了 `flex-wrap: wrap` 却没有任何换行」。要让「放不下才折行」成立，项必须写 `flex: 1 1 auto`（basis `auto` ⇒ 假定尺寸 = max-content）。`src/styles/catalog.css`
- **`flex-wrap` 的换行单位是「直接子项」，且分隔标点不能自己当子项**：图标与文字之间只有 `gap` 时，行尾放不下会让图标留上一行、文字掉下一行（换行单位细到了「图标 / 文字」）；包成一个 `inline-flex` 项后换行单位才是「一项元信息」。分隔符写成独立子项时会独自留在行末或被推到行首——行首的 `·` 命中 CJK 行头禁则，正解是挂到**前一项的 `::after`** + `:not(:last-child)` 兜住无后继项的情形。
- **断点档位可能「倒挂」：更大屏的一档反而更窄**：`--nk-grid-min` 在 768~1023 档取 150 ⇒ 768 档实测列宽比 390 档还窄，同一张卡在平板上比手机上更挤。**断言「列数随视口变宽单调不回跳」不能发现它**——档位间的绝对值倒挂与单调性正交。判据 = 逐档记录**列宽绝对值**并跨档比对，而不是只比列数。
- **`overflow: hidden` 宿主里做斜向装饰，别让装饰盒本身旋转**：旋转后的包围盒会顶大祖先 `scrollWidth`，直接命中「`overflowX ∈ {hidden,clip}` 且 `scrollWidth > clientWidth` 且无 ellipsis/clamp」判据；斜向形状用 `clip-path: polygon()` 在轴对齐盒内切，只旋转文字。给中间层加 `overflow: clip` 只是把失败转给那一层。
- **星级行用 `cqw` 时，宿主必须显式声明 `container-type: inline-size`**：光锥卡的星级挂在 `__info` 上，而 `__info` 默认不是容器 ⇒ `cqw` 回落到视口单位，170px 卡上的 5 星会按视口宽算成几十像素、直接撑破卡面；角色卡能成立只是因为 `__body` 本来就为「窄卡只留图标」声明过容器。判据 = 逐档量星行 `fontSize` 与卡宽同向缩放。`src/styles/catalog.css`
- **星级必须独占一行，不能回到名字行**：星标与卡名同行时固定吃掉一截列宽，德语 / 俄语 / 葡语名普遍比中文长三成以上；独立行（`名称 → 星级 → 元信息`）让卡名保住整列宽，代价是信息层高 15px。判据 = 卡名 clamp 行数按语言统计 + 信息层仍盖住卡名墨迹。`src/styles/catalog.css`
- **「不换行 + ellipsis」不是长语言的解**：触屏没有 hover，被截的元信息就是永久读不到。改回 `flex-wrap: wrap` + `gap` + 收紧 `line-height` 后截断归零，代价只是卡体高一点。判据 = **换行代价为零时优先换行**。
- **版面指标里混着数据缺陷时，必须先剔掉数据缺陷再谈版面**：卡名 clamp 数这类跨语言指标会同时数进占位符串（未翻译的模板天然更长）与真长名。真名只需几行就能容纳、且有 `title` 复原，属**真名而非缺陷**；不先分类就会为不存在的问题改版。
- **`space-between` 在负剩余时静默退化**：它只在剩余为正时生效，负剩余会退回 `flex-start` 并把内容挤进 padding 区。「固定盒高 + 均分」必须同时保证内容总高 ≤ 盒内容高。
- **骨架只代理「盒子」，不代理「结构」**：写一个「结构忠实」的小骨架反而更糟——就绪面板在窄断点因换行会显著变高，忠实小骨架变成欠预留。正解 = 固定盒高（取实测中位数）+ 内距逐档对齐 + 间距交给 `space-between`。
- **两个宿主共用的版面事实（如底板）必须只声明一次**：分成两处必然漂移，表现为数据到位时凭空弹出一块暗板。盒高对齐前必须先对齐内距，否则会把内距差算成盒差。
- **「数据里有、UI 里没有」的查法与例外记账**见 [data-semantics.md](data-semantics.md)「目录卡字段与渲染」。
- **环境层只做光影、不做纹理（本项目类型的判据）**：纹理要成立，要么它是主角（满屏主视觉），要么它有足够强度被读成图案；本站内容密度高，纹理只能压到**页面发丝线 `--line-1/2` 之下**才不抢亮度，压到那个量级后它就在可感知下限附近。**判据**：一个视觉元素若必须压到「低于页面已有的最弱结构线」才能不冲突，它就不该存在——质感预算交给 `#app::after` 的纸感颗粒（`--grain-opacity`）与内容本身。（旧表述见 [ADR 0051](../adr/0051-终局赛季奖励进详情页.md) 对它的引用。）
- **参照站要分别量「UI 层」和「内容层」，别把插画的质感当成 UI 手法**：参照站若 UI 纯色区几乎无高频噪声而内容区噪声大一个量级，说明质感在插画里、不在 UI 系统里——照搬 UI 只会得到「白底 + 一张图」的占位感。**手法**：拿参照站时先分别量两处的高频噪声再判断。
- **跨站复刻素材的四个陷阱**：① 「线在两点中间渐隐」是**沿长度方向**变透明度，`radial-gradient` 只按距离、`conic-gradient` 只按角度，两者都没有这一维——只能烧进贴图；② 深色底上复刻「浅底暗线」要对齐的是**亮度差**而不是线色，同一支浅色照抄不透明度会从「底纹」变成「明显的亮网格」；③ 「看起来是透视」不一定是透视——均匀网格 + 低不透明度 + 小模数在缩略图里同样读成远处变密，判定必须查计算样式（`perspective` / `transform` / canvas 三处任一非空）而不是肉眼；④ 渲染摩尔纹（1px 线落在非整数 pitch 上与像素栅格错位）不是稳定设计特征，别去复刻。
- **素材层的推导参数必须有守卫，否则必然静默漂移**：贴图由脚本生成却把输出手抄进 CSS 时，改参数忘抄（或反之）会**继续用旧贴图、没有任何报错**；形态退化（如线中段衰减过狠导致交点变孤立亮点）时**所有既有守卫都不看贴图像素**。新增这类守卫必须实测两条失败路径都能拦住（构造漂移 + 构造退化）。
- **触控命中区要按命中区量，不按视觉盒**：靠 `::before { inset }` 扩热区时只有 `elementFromPoint` 自中心向外扫才量得真实值，**扫得的是「自中心的半径」，命中宽高 = `left + right + 1`**，把视觉盒与半径相加会得出假值；且命中盒不能只看元素自身几何——宿主是 `<label>` 时整块可点、是 `<div>` 时不可点，要用真实点击落点验证。
- **渐进增强的正确形态是「不支持 = 静态还原」，不是「不支持 = 停在末帧」**：`fill: both` + 时间轴驱动的动画在不支持滚动驱动动画的引擎上会跑完并停在末帧，媒体层位移永久偏移——这不是「少个视差效果」而是构图错位。凡此类动画都必须包 `@supports`。
- **横向溢出 / 越界取证的假绿与假红两面**（页根裁切让整页断言恒 0、判据须落到逐元素右缘、排除可横滚祖先、过渡残留）：见 [testing.md](testing.md)「溢出与几何取证」与「竞态与等待」。
- **纵向硬裁切必须「墨迹越界 或 元素布局盒越界」两档并取**：只看 `scrollHeight > clientHeight` 会把**已变换**后代（`rotate` 装饰 + 放大图）算进可滚动区 ⇒ 假阳性（该区域截图逐字节相同，即无内容被裁）；只要求「元素后代布局盒越界」则**漏报纯文本裁切**——文本节点没有元素后代，而 `line-height` 小于内容高这类缺陷正是如此。墨迹用 `Range.getClientRects()` 逐矩形比内容盒，自检要含四条路径：真装饰放行 / 纯文本裁切报出 / 「装饰撑高 + 内层真超框」报出 / 正常文本放行。
- **`-webkit-line-clamp` 的 `scrollHeight > clientHeight` 是设计内行为，不是硬裁切**：被 clamp 掉的第 3+ 行本就计入 `scrollHeight`。判据必须先 `isClamp` 排除再看墨迹，否则等于推翻既有的省略语义。
- **只写一个轴的 `overflow` 会静默改写另一个轴**：`overflow-y: visible` 与 `overflow-x: hidden` 并存时，规范把 `visible` **计算成 `auto`** ⇒ 容器仍可滚动。构造「不可滚动」的对照组必须写 `overflow: clip`（两个轴一起），否则实验臂与对照臂等价，会得出「修复无效果」的假结论。
- **「文字不溢出」只修了一半，另一半是「换行后内容变高，底部工具组是否还够得着」**：`margin-top: auto` 的尾组在视口变矮时被推出视口**且永久不可达**。可达性判据＝`scrollIntoView` 后 `elementFromPoint(中心)` 命中自身；`getBoundingClientRect` 在视口外仍给非零 rect，**不能**用作可达证据。
- **「只改文案」或「只改布局」常常单独都不够**：同一次溢出可能来自两条正交根因（文案固有宽、容器不换行），必须分别实测；长译文模式名自己就可能超过整行可用宽。
- **「加宽容器」不是万能解**：容器宽了，长译文也能长得更长。判据：先量「最坏语言下内容固有宽 / 可用宽」，若最坏项**单项**就超过整个可用宽，加宽只能靠牺牲列数换，应改换行 / 分档。
- **「参差」是整排性质，逐列治不好，必须让并排各项共用行轨**：列头「折几行」若由各列自己的内容决定，并排各列就各折各的。治法 = 列项跨父网格两条轨（列头 / 列表）+ `grid-template-rows: subgrid` 认领之，则轨高 = 该排最高列头。**只给容器加 `flex-wrap` 治不了**——它恰恰是参差的成因；**只把徽章压到第二行反而更糟**。`src/styles/endgame.css`
- **「整排统一」必须写成条件式（放得下就一行），别写成固定两行**：共用行轨只保证「同排等高」，**不保证**「该一行时就是一行」。列头内部若写成 `grid-template-rows: auto auto` + 徽章恒 `grid-row: 2`，那就是**无条件两行**。正确形态是**两列网格**：列 1 元信息（可换行）、列 2 徽章，行轨 `1fr` ⇒ 轨高由**共享轨**决定，整排放得下就一行，某列过长才整排等长——因此无需知道兄弟列内容、也不需要按语种写规则。**断言必须补「该排元信息视觉行数为 1」，只断言「参差 0 / 越界 0 / 徽章不被拉宽」时固定两行结构会满分通过。**`src/styles/endgame.css`、`e2e/layout-endgame.spec.ts`
- **列头里「价值不大」的项就是纯成本**：条目计数在这种「一行几个不可收缩项、可用宽 243~299px」的稀缺空间里既不帮决策也不帮导航，却占着一个不可收缩位、把元信息行右端顶住。**判据：列头每个元素都要能回答「它在帮用户做什么决定」**，答不出即是可删项——列头宽度是全站最紧张的一处，别把「有数据」当成「该展示」。`src/app/catalog/pages/endgame.ts`
- **数「文字行数」必须用 `Range.getClientRects()`，不能数子元素的盒底**：子项是 flex 项（blockified），**名字自己折成两行时它的盒底仍只有一个** ⇒ 按盒底去重恒得 1 行，判据把「两行」误判成「放得下」；而一个并排子项的存在会掩盖这个仪器 bug。`Range` 取到的是真正的文字行盒，按纵向重叠合并即得行数。**仪器错与布局错要分开归因**：先证明仪器在已知真值上读数正确，再拿它判布局。`e2e/layout-endgame.spec.ts`
- **`subgrid` 认领行轨后有两个静默塌陷**：① 列项的那一列必须显式钉成 `minmax(0, 1fr)`——只写 `subgrid` 时内部那一列是隐式 `auto` 轨，最小尺寸函数是 min-content，会被最长的列头项撑开 ⇒ **列头盒比列框还宽**；② `container-type: inline-size` 不能挂在 subgrid 子项上——挂了会让该元素成为容器、行轨塌陷。要按自身宽度做条件分支时，容器查询挂在内层（列头）上。`subgrid` 只约束**行**轨。
- **容器查询的阈值以容器内容盒为准，且换来的收益要按「列宽档」而不是「视口档」折算**：同是 4 列档，列宽随视口大幅变化，收益与列宽挂钩、与视口不挂钩（写视口断点必然在某几档空转）。列头内距要计入阈值换算。判据：阈值两侧都要有实测档位证明「该触发的触发、不该触发的分毫不动」。
- **窄列隐藏「全语言共有的占位项」能降高度，但容器查询选不出「真正受益的那些列」**：英文副题在四种模式下全语言都存在、是稳定的宽度开销，隐藏它确有效（并且它常常是「宽列能否回到一行」的前提）。**但阈值只能按列宽切，而「EN 是否多撑一行」还取决于模式名多长**——同列宽下只有部分语言真省一行，其余语言省 0 行却一并被隐藏。容器查询看不见「名多长」这个变量，故「隐藏」这一档**天然会误伤一部分语言**；收益是真的，精确性是假的。
- **三种「让 EN 收缩而不隐藏」的替代方案都不成立**：① `flex: 0 1 auto` + `min-width: 0` ⇒ `flex-wrap: wrap` 下 EN **优先换行**而不是收缩，收益 0；② `flex-wrap: nowrap` + EN 收缩 ⇒ 列头**更高**（名被迫折行）；③ `nowrap` + `min-width: 3ch` 同上。结论：在「`wrap` 容器里降行数」这个目标下，**只有 `display: none` 能真正减少行数**。**「省高度」与「都显示」二选一，没有第三态**。
- **别按语种写规则**——语种只是列宽的代理：同一个语言在不同档位有的是单行、有的是两行，按语种写必然在部分档位判错。
- **同一个组件的多个宿主宽来源不同 ⇒ 视口断点必然判错，此时容器查询不是优化而是正确性手段**：角色卡（`.nk-idx-card`）同时被目录网格（随 `--nk-grid-min` 与列数）与货币战争枢纽带（定宽 `190px`）复用，同一视口下副行宽度差近一倍——**同一视口、同一组件、两种结论**。判据：只要「一个组件被 ≥2 个宽度来源不同的宿主复用」，按视口写的条件就必在其中一处错。`catalog.css`
- **「放不下就换一种表达」比「让它折行」更能根治折行**：窄卡副行（属性 + 命途）在长语言下必然折行——去掉分隔点也没用，两个官方名光文字就超过手机 2 列档副行宽，**是文字自身放不下，不是装饰占位**。改为「副行窄于全语言叉积最坏需求宽时只留图标、文字转 sr-only」后折行归零。要点：① 阈值必须取**全语言叉积最坏值**而非当前语言实测值，否则切语言会改变卡片密度；② 文字转 sr-only 而非 `display: none`——`alt=""` 的语义是「此处无需替代文本」，它在窄卡上恰是唯一的属性文本载体；③ 容器查询块必须写在基础规则**之后**，它不提升特异性，写在前面会被同特异性基础规则静默盖掉。`catalog.css`
- **`flex-basis: 100%` 会把该 flex 项拉成整行宽，不是「让它单独占一行」**：主尺寸变成容器宽 ⇒ 徽章胶囊被拉成横条，而**子项越界类断言全绿**——被拉宽不是越界，这类变形只有量「元素自身宽 vs 自然宽」才看得见。要「贴到末行且保持自然宽」须用 grid：`align-self: end` + `justify-self: end`。`src/styles/endgame.css`
- **容器的「不透明底色」与页面底色同值时，唯一可见效果是把 fixed 背景的环境光裁成一块矩形**——那是缺陷不是材质。**给区块加底色前先问「这层底色的可见效果是什么」**。
- **网格里 `display: none` 的格子不占轨** ⇒ 自动布局的稀疏推进不可依赖；**后续格必须显式写 `grid-column`**，否则被甩回第一列并撑出横向溢出。`src/styles/endgame-levels.css`
- **flex 行内要让名称可压缩**：给 `overflow: hidden` 即取得自动最小尺寸 0；反向的 `flex-shrink: 0` 会让该元素的 ellipsis **完全失效**，整串越出列框压到相邻列。`src/styles/endgame.css`
- **显隐与高度都依赖异步数据的区块，必须等数据就位再渲染**：先渲染会「先显后隐」并把上方 hero 拽一下，异步补入的内容还会撑高区块、把下方整体推下去——这段高度会计入 CLS。故必须在「就绪态翻转」之前 await 取数。`src/app/composables/use-release-showcase.ts`、`src/app/views/MonsterDetailView.vue`
- **浮层用原生 `<dialog>` + `showModal()`，自绘遮罩会被 `#app { overflow: clip }` 裁切**：`showModal()` 进入 top layer，不受祖先 overflow 影响；ESC 关闭与焦点收束是浏览器行为，不必自写一套。`src/app/views/HomeView.vue`
- **CSS 分栏（`columns`）不要给子项覆写 `display` / `width`**：行本身是 flex 行，改成 block 会压成上下堆叠、整页反而变长；分栏只需 `break-inside: avoid`。`src/styles/endgame.css`
- **同一页同类区块必须同左缘，判据取「盒左缘」而不是文字左缘**：区块标题自带 `padding-left` + `border-left`，拿文字左缘比会假红。`src/styles/currency-trait-detail.css`
- **「横向可滚」不等于「用户能找到」**：横滚容器必须给溢出提示，且提示**只在真溢出时出现**（用 `mask-image` 渐隐，不引入新颜色块），并且**方向要对**——静态只挂一侧的渐隐是方向盲的：横滑到中段时左端文字被硬切，滑到末尾后右端又在已滑到头的末项上渐隐。状态由容器上的一条 `data-*`（start / middle / end / none）+ 被动滚动监听写入，CSS 按状态切三段渐变；**不要用 `animation-timeline: scroll()`**（滚动驱动动画 Firefox 不支持，缺 `@supports` 门时它按普通时间轴跑完并停在末帧）。`src/styles/catalog.css`、`src/styles/character-enhance.css`
- **横滚条里的「当前项」高亮必须由条自己滚进可视区**：高亮由页面滚动驱动而条不跟着滚 ⇒ 靠后的高亮**永远**在条外，用户读到哪一节在条上完全不可见。判据取「高亮项相对导航可视区的左右内缩都 ≥ 渐隐带宽度」，**不是「`scrollLeft > 0`」**；跟随还要给用户让路——手指按在条上或刚滚过时不抢位置。渐隐带宽在 JS（`NAV_FADE_EDGE`）与 CSS `mask-image` 各写一份，**必须同值**——JS 用它判「高亮项是否跑出可视区」、CSS 用它画渐隐，不同值时判定与看到的渐隐带错位。`src/app/views/CharacterView.vue`、`src/styles/character-enhance.css`
- **CLS 取证必须 dump 位移节点（`layout-shift.sources[].node`）**，只报数值查不出病根。图片**未解码时不产生盒子**：`max-width` 不定宽 ⇒ 首帧高 0、图到后整块下跳；修法是 `width: X%` + `aspect-ratio`，**不是 `min-height` 魔数**。
- **把文字放进「宽度由图片钉死的窄列」，两道换行规则缺一不可**：① 去掉 `nowrap`——`nowrap` 的文字按 max-content 撑 `auto` 轨，会把这一列连图带列一起撑宽、挤窄相邻列；② `overflow-wrap: anywhere`——`white-space: normal` **只在空格处断行**，德语复合词这类单字整体放不下就溢出列框，而该列无裁剪 ⇒ 直接压到相邻列上。`overflow != visible` 的溢出探针看不见它，只跑缺省语言的用例也看不见它。`src/styles/endgame-pollution.css`
- **`flex-wrap: wrap` 的容器里，一个 flex 项仍可能把容器撑破——因为「能换行」只保证它独占一行，不保证这一行装得下**：项默认 `min-width: auto`（= min-content）不可收缩，项自身 min-content 一旦超过容器可用宽，它就原样溢出（如「图标 26px 不可缩 + 名 + 徽标」组成的召唤行，min-content 232px > 可用 214px，长译文名让整行拒绝收缩）。给行内徽标加换行 / 列表改 `flex` / 行 `min-width: 0` 都无效——真正不可缩的是行内的名字；有效解是给该行加 `flex-wrap: wrap`，让**徽标**在名字需要整宽时落到次行。
- **「溢出清零」不等于「修好了」——断长词的两种写法会把行压成竖排，且溢出指标对此完全无感**：`overflow-wrap: anywhere` / `break-word` 确实能把溢出清零，代价是名字被压到 min-content 逐字断行，比原溢出更难读。**溢出是「量」的问题，断成竖排是「读不了」的问题。**故凡「让文字可断」的修法，必须同时量**该文字的渲染行数**与**它的可用宽是否被前一项挤没**；只看 `scrollWidth` 会把逐字竖排判成修好了。`src/styles/endgame-pollution.css`

## 宽幅桌面排版（专题页）

- **专题页的字号层级由「这一页在讲什么」决定，不由数据密度决定**：公式页若把数值当主角（大字号读数 + 账本 + 结果吸顶），它就成了计算器——公式缩在 13px 小字里，读者看到的是「算出来的数」而不是「怎么算的」。判据：**每个区块最大的字号必须是这块要讲的那个东西**，数值只能是它的注解。落地档位：区块标题 20 / 等式 17–20 / 结果 17 / 明细 15 / 账本 13；唯一的例外是 09 实战计算器——那一块讲的就是「算出来多少」，最终伤害 28px 不动。**档位只在桌面媒体查询里成立意味着窄屏会退回反序**：基态曾写「乘区名 fs-4 / 乘区公式 fs-3」，≥1024 才覆盖成「名 15 / 公式 20」⇒ 手机上公式比它的名字还小（11.5 < 13.1px），而这条断言只在 mobile project 里跑得到（夜间 layout 抓到的就是它）。判据：**字号层级必须写在基态**，媒体查询只许放大；基态公式取 fs-5。
- **公式行必须按「项」排版，不能拼成一个字符串**：`join(' × ')` 得到的整句放进一个 `<p>`，CJK 会在任意字间断行，术语被劈成两行（「韧性 / 减伤」），读起来像两个项。每项一个 `white-space: nowrap` 的 span、运算符单独成 span 并降到 `--text3`，换行只发生在项与项之间。
- **链路已展开的因子，不要再在链路下方补一条从属等式条**：同一条修饰区等式在流水乘步行与点选详情里已各有一份，第三条只剩重复读数；乘区结构由链路节点数 + 详情公式表达即可。
- **「本页不展开」是死指针**：读者要的是判据，不是范围声明；站内没有下一站时，这句话只会把一个错误版本的知识留在页面上。专题页凡「不展开」的机制，必须就地给最小可判据（一行基础式 + 一句乘区说明），否则干脆不提。**页面删掉这句话不等于删干净——AI 快照生成器里同一句若有独立兜底（`ui()` 第二参），会留在 9 个非汉字语言的分层快照里**（该句未入词典，兜底即中文），而汉字棘轮只报「文件数回涨」并把已坏状态写成基线；判据 = 删页面文案时同批 grep 生成器与词典键。`src/app/formula/BreakSection.vue`、`tools/gen-ai-endpoints.mjs`
- **布局改动会让方向词变成谎言**：把账本从「右侧」挪到下方后，引导句里的「右侧流水」就成了错误指路，而它是 13 个语言包各一句。方向词（右 / 左 / 上 / 下）属于排版契约，改版必须同批改文案，否则读者按字找位置。
- **满宽控件行会把「标签 ↔ 读数」拉开到失去归属**：单列满宽时 label 与 value 由 `justify-content: space-between` 推到两端，间距随视口线性增长，读数不再与它的标签成对。桌面档给控件行一条**窄轨**（列宽 `minmax(340px, …)` 或字段 `max-width`），不许靠 stretch 吃满栏；只有**账本类表格**可以满宽，且必须把「名称 + ×系数」成对留在左端、「本步值 + 增减」成对贴在右缘，中间留白而不是塞填充物。
- **账本行中间填「相对进度条」是假图表**：条长按 running 值取相对宽，既无共同标度、又与右侧数值重复，读起来是仪表盘装饰。判据：条的长度若回答不了「谁比谁大 / 占多少」，它就不是图。删条后同一屏只靠两组数值 + 留白，反而更像账本。
- **`em` 长度在 `grid-template-columns` 上按「行盒自身字号」解析**：账本行继承 16px，`10em` 就是 160px，不是按 13px 标签算出的 130px；想让列宽跟着标签字号走，得把列宽挂到内层元素。
- **双列区块 `align-items: start` 会把列高差变成空洞**：短列（控件）短于长列（账本）时空洞落在正文脚下。按代价排序三条解法：① 内容也分配（`justify-content: space-between`，适合有承载面的卡片）；② 短列收成窄轨、长列独占其余宽度；③ 接受空洞但**不给它承载面**——无底无框时留白读成呼吸。`stretch` 只是把空洞搬进卡片内部，仅当两列内容量相近时可用（治疗 / 护盾），差一倍以上必走 ①/②。
- **区块之间用留白量级分隔，别用发丝线平权**：9 个同构区块各挂一条 `border-top` 会得到 9 条等强线，读不出层级；桌面档改 68px 留白 + 20px 区块标题，发丝线只留在区块内部的表格行上。

## 排查路径

> 仪器与等待类坑位归 [testing.md](testing.md)，本文件不再登记。

- **删死声明的验收方式是「前后计算样式快照 diff」而非肉眼**：N 路由 × M 视口 × 逐选择器 computed style 做 before/after diff，零差异才算纯删——截图看不出 0.02rem 的差。且**命中不都是缺陷**：`focus-visible` 收掉投影、断点反向补偿、粘性表头底色、主题变量分组这类刻意变体会命中重复选择器检查；工具的价值是把「谁会静默吃掉谁」摆上台面。
- **验证过渡类改动必须同时断言两件事：① 类名命中；② 存在插值中间帧**。仅断言前者会漏掉「动画被全局规则静默吃掉」这一整类缺陷，而它恰好让观感问题**完全没被修好**。
- **判 hover 抖动要比 `offsetTop/offsetLeft/offsetWidth/offsetHeight`**（不受 transform 影响，有意动效不会被误判）。
- **「最坏单像素」是包络不是判据**：同一批数据里它能把「4% 的像素」讲成「整体不达标」，也能把「零遮挡」讲成「必须垫板」；结论必须取「全部样本的最坏像素」并按逐字形像素分布判（最坏值 + 失败占比并列），单一样本会给出乐观偏差。

## 坐标系与断点

- **base 改了 `display`，断点块里只写 `gap` 不会继承结构**：桌面网格化后手机断点必须显式回 `display: flex`。
- **走文档流的页不能用视口级 `margin: 0 auto`**：侧栏偏移后居中基准与侧栏避让页差一个侧栏宽，要用 `calc(offset + max(0px, (100vw - offset - detail-max)/2))`。
- **走文档流的详情页拿不到 `.nk-page--detail` 的侧栏避让，必须自己声明**：那份避让是 `position: absolute` + `left: var(--nk-content-offset)` 提供的，页面一旦改成文档流滚动，整页就退回「版心以视口居中」⇒ **768~1279 视口被侧栏压住**。修法：页面容器 `padding-left: var(--nk-content-offset)`（该令牌 <768 为 0，无需媒体查询）。**这类缺陷不会报错、只在特定视口可见** ⇒ 新增 / 改造文档流页面时同批补一条「内容左缘 ≥ 侧栏右缘」的几何断言（读令牌落值 + 比 rect，而不是写死 x）。`e2e/layout-monster.spec.ts`
- **避让一改，hero / 骨架的固定盒高就要按断点重标**：内容区左缘右移会压缩可用宽度，图列驱动的 hero 高度随视口线性变化；骨架屏不拆档就会在加载完成时整块下跳。
- **目录页骨架屏的尺寸不能从网格类名反推**：虚拟网格目录（/item、/monster、/achievement）的列数与行高由 JS 的 `virtualMinColW` / `virtualImgRatio` / `virtualInfoH` 决定，而真实卡是「图 + 下方 info 文本块」的复合结构（item 名称 + 副标题两行、monster 名称 / 弱点 / 类型三行、achievement 纯文本卡、货币战争目录是矮行卡而非竖幅图块）——统一 3:4 图块占位会让骨架行高与就绪态差到一倍，加载完成时整页跳。判据：骨架按卡型声明变体（`CatalogPageConfig.skeleton`），几何只按网格类与 `data-page` 限定；验收量「骨架 / 就绪同元素矩形差 ≤2px」，不拿截图肉眼判。
- **覆盖一个方向时必须只写该方向**：负外边距写成 `margin: -6px 0` 简写会把基线的 `margin-left: auto` 一起清成 0，靠右对齐的入口当场退回标签右侧。用 `margin-top/-bottom`。
- **改导航块序要连带查三处**：① 手机档分隔线是**按序画的**（修法是改画位置而非删线）；② 折叠算法按选择器量宽度预算，**改类名或换标签元素就会静默破坏底栏折叠**；③ 工具组在手机档是 `display: contents`，加减条目会改变底栏槽数，须按最窄档复测槽宽。
- **「改短文案」必须按最窄档复测**：底栏槽宽有隐性预算（`flex: 1 1 auto; min-width: 44px`、标签 `white-space: nowrap`），2 字变 4 字等于标签宽度翻倍。
- **布局算术的输入必须全部来自「视口 / 令牌 / 常量」这三类与自身状态无关的量**：读自身元素的 `offsetWidth` 来算折叠，而该盒的宽又由折叠结果决定，且量到的「固有宽」等于**该语言标签的像素宽** ⇒ 槽位数被译文长度决定；同理 `flex-basis: auto` 让「元素内容的长度」渗进布局分配，任何「按宽度取前 k 个」的算法都会随文案漂移。并列且需等分的槽位应写 `flex: 1 1 0`（并显式 `min-width: 0` 覆盖基类的 `min-width`）。`src/app/components/SidebarNav.vue`
- **预算里扣掉的必须是「盒宽」不是「线宽」**：分隔线写 `width: 1px` 但带 `margin`，实际占位远大于 1px；按 1px 扣会连续低估，槽宽悄悄落到 44px 触控下限以下而任何断言都不报错。
- **折叠项「留在 DOM 里用 CSS 藏」还是「不渲染」是契约级差异**：前者让 e2e 能用「底栏里找得到该 href」断言入口可达，后者必须改成「底栏直连 **或** 抽屉内可达」（`navEntryReachable`）。改成不渲染时，所有「`.ui-sidebar a[href=…]` 存在」式断言都会在窄档变红——**那不是缺陷，是判据过时**。`e2e/layout.shared.ts`
- **「全量放得下就不预留溢出入口」是有序的两段判断**：一上来就预留「更多」槽，会让原本刚好铺满的档位退化（CW 6 槽位 → 5 项 + 更多）。先判全域、再判折叠。

## 样式产物与分块坑位

- **`String.replace(re, (match, p1, p2) => …)` 的回调第一参是整个匹配**：写成 `(num, unit)` ⇒ `unit` 恒为数字串、`parseFloat('0.82rem') = 0.82`，于是**只有 px 声明被映射、全部 rem 声明静默落进 leftovers**。
- **PowerShell 的 `switch` 里 `continue` 只跳出 switch，不跳外层循环**：用它做「命中行 → 替换行」的 map 时替换后原文仍会被追加一次，静默产出**重复 CSS 声明**（后者覆盖前者）。改用显式标志或 `Hashtable.ContainsKey`。
- **整文件重写会污染「病态行尾」文件的 diff**：本仓四类行尾并存（`CR CR LF` 的源文件、每行尾多个 `CR` 的畸形态、正常 CRLF、纯 LF 的 `docs/**`）。用会整文件重写的编辑路径改前者，diff 会由几行膨胀到数百行。**病态行尾一律用「读原文 → 按原行尾切片 → 只替换目标行」的字节保真脚本。**
- **把单消费者原语从全局样式表迁出时，同批删除会连带带走同文件的响应式 / 断点块**：`catalog.css` 迁 `.nk-hub-release*` 到 `currency-hub.css` 时，同一次删除把尾部的目录网格断点（`--nk-grid-min` 的 768 / 1024 / 1280 / 1536 档）与手机档规则（`.nk-mob-card` 列表化、`.nk-relic-grid` 106px、`#nk-catalog-app` 内距）一起删掉，构建、单测、类型检查全绿，只有目录页在特定视口变形。判据：迁移后做「模板仍引用、样式表已无规则」的静态核对（类名集合差集），并对被删文件的每个 `@media` 断点各取一档几何快照（本仓 390 / 768 / 1440 三档足够暴露）。
- **拆分样式块按导入顺序级联，末块是唯一字号声明点**：终局详情 7 块（`endgame-frame` → `panels` → `monsters` → `levels` → `breakpoints` → `pollution` → `type-scale`）、角色详情 7 块（`skill-card` → `character-hero` → `skills` → `builds` → `enhance` → `compare` → `skeleton`）、货币战争角色 4 块（`currency-role-hero` → `sections` → `gear` → `skills`），顺序以对应视图的 `import` 为准。`endgame-type-scale.css` 必须最后导入，是终局详情页唯一的 `font-size` 声明点。唯一例外：`endgame-panels.css` 的 `.nk-egd-floor__row--mons > .nk-egd-floor__label` 特异性 (0,2,0) 高于收口块 (0,1,0)，收口块压不住它，那一处标题档只能留在 panels 块。
- **后导入块重述同一属性会静默吃掉前块**：`endgame-monsters.css` 在 `EndgameView` 的 import 序里排在 `endgame-panels.css` 之后 ⇒ 区块标题的对齐属性只能在 panels 块声明，在 monsters 块再写一遍等于把档位声明吃掉。反向诊断：前段重述同一属性的声明是死声明，**改它不生效**。
- **`--nk-egd-mon-fig` 是敌方立绘列宽的唯一声明点**（立绘图与之同宽，图下污染徽标以它为换行上界）；手机档只改令牌值（`endgame-breakpoints.css`），**不得再单独声明图片宽度**——列宽是 `auto` 轨被反撑的源头，重复声明会让长译文挤窄右侧数据列。
- **`--nk-nav-bar-h` 是手机底栏高度的唯一声明处，改它必须同步 4 个避让消费点**：`.ui-sidebar` 的高度、`.ui-more` 的底部偏移、`.nk-page--detail` 的 `bottom`、`monster-detail.css` 的 `.nk-mob-page` 页尾内距（该页走文档流，拿不到 `.nk-page--detail` 的避让）。避让值小于栏高 = 页尾内容被永久遮住，构建与测试都不报。
- **全局动效降级必须用 id 选择器 `#app *`，并把 `animation-delay` 一并归零**：组件的 `animation` 简写特异性会盖过 `:where(#app) *` 的零特异性规则 ⇒ reduce 对几乎所有真在动的组件失效；只压 `duration` 不压 delay 会让用 `backwards` 填充 + 错峰的入场动画先显示一片透明。
- **`prefers-reduced-motion` 管不住滚动时间轴驱动的位移**：它只压 `animation-duration`，而 `animation-timeline` 的进度不看 duration ⇒ 滚动驱动的位移必须在 reduce 块里显式关掉（特性不支持时的静态还原见「几何与形态判据」的渐进增强一条）。
- **报头与其下区块的间距由 `margin` 承担，不能用 `padding`**：e2e 用 `getBoundingClientRect().height` 判「报头是紧凑的一行文字」，padding 会把间距一起量进去。
- **排版双族分工**：`Noto Sans SC` 承载中文与正文（含 900 字重），`IBM Plex Mono` 承载全部拉丁标签 / 编号 / 读数——系统 mono 栈随操作系统漂移（同页在 macOS 与 Windows 上字形不同），装饰性科技体满足不了「读数与标签处处一致」。
- **手机档 `--nk-content-offset: 0`（侧栏变底栏）⇒ 目录页左侧留白必须显式补回**：否则工具栏 / 搜索框 / 卡片一起贴屏左缘（`--cat-pad-x` 只管条带出血与右内距）。`src/styles/catalog.css`
- **区块导航在「定高 flex 列 + 内容溢出」的页面里会被压扁**：`.nk-secnav` 基础样式是 `flex: 1 1 0%`——它只在父级「按内容分配余量」时才长高；父级一旦是定高 flex 列、内容靠 `overflow` 滚动，`basis: 0` 不参与增长，导航盒只剩 18px，按钮上下各被裁 4/6px，`--active::after` 的 2px 下划线整条落在裁剪框外，命中测试里 28px 有 10px 点不到。判据：专题页导航写 `flex: 0 0 auto` + `min-height` + `position: sticky`，e2e 断言「nav 盒高 ≥44 且滚 2 屏后 `top` 仍贴顶」。`src/styles/formula.css` / `e2e/layout-formula.spec.ts`
- **字号不得落在 `--nk-fs-1` / `--nk-fs-2`（0.5 / 0.625rem = 8 / 10px）上**：图表刻度、图例、滑杆标签与说明句用它们，实测 280 个文本节点里 241 个 <12px（最小 8px），读图与读数一起失效。判据：密集页在页内把刻度抬到 11px、正文说明 13px，字号只引用令牌名；字号断言要读 computed `font-size`，不是量盒子。
- **图表准入判据：不能改变玩家一个判断/操作的图不该存在**（用户口径）。`y = 1 + x` 这类线性图、常数参照线、按各自峰值归一后只剩“形状”的图、以及数字读数已给出全部答案的图（治疗/护盾 = 基础 × 修饰）都是装饰；量纲混合的三线图（HP 1500 与 DEF 573 同轴）会把次要线压成一条贴底的细线，比没有图更误导。真正值钱的图只有三种形态：**收益递减/递增的曲率**（增伤稀释、减防收益递增）、**阈值台阶**（行动次数随速度跃迁）、**结构分解**（乘区账本的发散条）。落地方式：把“不加无价值图”写成 e2e 契约（`[data-chart]` 计数 0），改一版删一版都有人守着。`e2e/layout-formula.spec.ts`
- **「读数 + 流水表」本身就是结构分解图，不必再配曲线**：击破/欢愉这类链路的可变量是**离散选项**（属性、韧性档、好活数），曲线只能画成台阶、玩家也读不出斜率含义；流水表逐行给「×系数 / 本步后伤害 / 增减绝对值」已经是结构分解，再加曲线是重复表达。判据：可变量是离散枚举 ⇒ 用 chip + 流水，不画图。
- **两卡并排时，高度差超过 3 倍就说明这两块不该并排**：一侧是长流水表（997px）、另一侧是关闭态说明条（202px），右侧会留出近 800px 空白，视觉上像漏渲染。改成**上下两块、每块内部再分「控件 | 流水」两列**（与相邻区块同构）后区块高从 1127 → 849px，空白消失。判据：并排前先估两列内容量级，差一个量级就改纵向。
- **流水/表格类块必须量「文字右缘到区块右缘」的留白，不能只量容器**：`padding` 落在容器上而 `text-align: right` 的末列贴着内边界时，数字看起来像被裁掉；实测该留白曾为 0px。修法给栅格末列加 `padding-right`，并用 `Range.getBoundingClientRect()` 量**文字墨迹**（不是盒子）到区块右缘的距离，≥16px。`src/styles/formula.css`
- **卡片正文用单列 `grid` 时隐式列按内容撑开 ⇒ 卡片 `overflow:hidden` 静默硬裁**：`.nk-cwrole` 的徽标名 `white-space: nowrap`、meta 的 `inline-flex` 行都不收缩，列被撑到 168px（容器 133px）；Windows 本机 390 档恰好不裁，Linux CI 字体窄 4px 就报 +4px。判据：卡片正文 grid 写 `grid-template-columns: minmax(0, 1fr)`，可能在无空格长词里越界的 chip 写 `max-width: 100%` + 其 nowrap 子项 `min-width: 0`（ellipsis 才真生效）。`src/styles/currency-hub.css`
- **`flex: none` 的标题在手机档会按 max-content 撑破容器**：`.nk-hub-release__title`（es「Novedades de la temporada」434px / 容器 350px）落在 `#nk-cwhub-app` 的 `overflow-x: hidden` 里静默裁切；风险语言子集不含 es/pt，所以夜间慢档一直绿，只有全语言矩阵才露。判据：文案随语言变长的标题一律 `flex: 0 1 auto; min-width: 0`，让它在负剩余空间收缩换行。`src/styles/currency-hub.css`
