# 项目约定 — 代码规范 / 注释规范 / 决策落位

> AGENTS.md 的按主题子文件（主文件「任务 → 必读」路由表经相对链接引用）。存放跨文件、跨会话的写码与流程约定。**硬约束（MUST）与色彩令牌收口在主文件「强制规则」节**；UI / 样式约定见 [ui-design.md](ui-design.md)；验证职责边界见 [verification.md](verification.md)。

## 代码约定

- Vue SFC 统一使用 `<script setup lang="ts">`。
- 路由使用 `createWebHistory`（History 模式）——Vercel 支持 SPA fallback；Vite `base` 为 `/`（部署于域名根路径）。
- **样式相关的全部约定**（BEM 双前缀 `nk-` / `ui-`、样式分层与懒加载、`tokens.css` 令牌、不使用 CSS 预处理器）**收口于 [ui-design.md](ui-design.md) §1**——本文件不复述，避免双事实源漂移。
- 项目**不配置 ESLint / Prettier**：代码风格靠 vue-tsc 类型检查 + 本文件与主文件约定 + 代码审查保证，**禁止擅自引入 lint 工具链**。

## 注释规范

**注释第一读者是后续接手的 AI**：注释本质是传递给未来 AI 代理的行为约束与领域知识，写成可执行指令形态（「禁止…」「必须…」「X 是唯一收口 / 单一事实源」）——AI 会字面执行注释内容。

- 只写可验证事实（数据映射规则、路径特例、架构约束、坑位）；无代码 / 数据证据不写「为什么」（防 AI 编造决策过程）。
- 禁止复述实现（不解释代码在做什么）。
- 禁止过期断言（日期、版本号、「已修复」——历史职能归 `docs/memory/`）。

**注释落位分层**：文件内局部约束就近注释在真相发生处；跨文件 / 跨会话约束进主文件或 `docs/memory/`；不可逆架构决策进 `docs/adr/`；术语进 `CONTEXT.md`。排查出的坑位（数据特例 / 时序陷阱 / 环境问题）**必须当场注释**——后续 AI 未被告知必重复踩坑。

**注释体积守门（机械执行）**：长散文块 / 超长文件头会随文件被无条件加载，等于绕开本仓库「按需加载」机制的变相全量注入，是 AI 读码的主要干扰源。因此注释**落位按事实单一来源（SSOT）**：

- 数据表字段映射 / ID 推算 / 枚举清单 / 架构决策 → 迁到 `docs/data/` / `docs/adr/`（按主文件「任务 → 必读」表登记），代码处只留 ≤12 行「硬约束 + 指针（`见 docs/...`）」。
- 踩坑与历史 → `docs/memory/`；当前生效的不变量与「禁止 / 必须」类硬约束**留在代码里**（这是资产，不是累赘）。
- 连续注释块 ≤ 20 行、文件头注释 ≤ 12 行；跨文件重复断言应合并为一处或抽成共享原语。
- 机械守卫：`node tools/check-comments.mjs`（report-only 先行，存量清零后接入 `pnpm build` 三守卫链）；护栏行数基线锁于 `tools/comment-baseline.json`，下降即红——**禁止为降体积批量删护栏注释**。

**已接受的跨文件统一措辞（非累赘，作为 SSOT 指针故意保留）**：以下 1 行注释在 3-4 个文件重复出现，属于「单一事实源指针」类硬约束，经评审保留为规范措辞，未来编辑须沿用同一句、不得另起变体扩散：
- `存储不可用（隐私模式/配额）：仅本次会话生效，忽略` —— 落位 `lib/trailblazer.ts` / `theme.ts` / `cw-theme.ts` / `cw-skill-desc.ts` 的 localStorage 降级点。
- `延迟显示骨架屏：加载超过阈值才呈现，缓存命中的快速切换不闪骨架屏` —— 落位各详情视图 `useDelayedSkeleton` 调用处。
- `板块编号（与吸顶条导航同源：sections.ts 单一事实源）` —— 落位 `endgame/` 各分区视图。
- `货币战争模式专属样式（随本路由 chunk 懒加载）` —— 落位 `/currency` 各视图头部。

## 决策落位（ADR 门槛）

ADR **仅用于「不可逆 / 跨模块架构决策」**——不符合该门槛的决策（单文件配置、数值调整、流程细节）写入 `docs/memory/` 复盘日志或 commit message 正文，**不新增 ADR**。

## commit message

使用 Conventional Commits 风格（`feat:` / `fix:` / `chore:` 等，与 data-sync 自动化提交一致）；流程细节类决策写入 message 正文。

## 字段筛选

字段筛选遵循 `docs/audit/字段价值审计流程.md`：AI 生成解读卡（字段名 → 人话语义 → 证据 → 置信度 → 价值建议），人工裁决分档。该流程为**三道防错闸门**，判据与分级符号以该文件为准，本文件不复述：

- 闸门 1（单向门）：AI 无权判「排除」档，只能建议「必收」与「待定」。
- 闸门 2（字段基线兜底）：StarRailRes / 官方 wiki 基线有而本地无的字段必须标「待定」。
- 闸门 3（误杀率校准）：误杀率超阈值即收紧 AI 排除权限。
