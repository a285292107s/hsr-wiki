## 2026-08-11

### 环境备忘（Windows + Git Bash / 沙箱）
- vitest 4.x 不识别 `--reporter=basic`（v3 遗留写法会被当自定义模块加载报错）；用默认或 `--reporter=dot`。
- Git Bash 下 `pnpm exec` / `vitest` 偶发 `[safe-delete] trash 操作失败` 与退出码异常，属环境噪音；可靠跑法：重定向到文件再读（`vitest run --reporter=dot > /tmp/out.txt 2>&1`）。
- safe-delete shim（`NODE_OPTIONS=--require=genie-safe-delete.cjs`）把 fs rm 劫持为移入回收站，非豁免路径 trash 失败会 fail-closed 抛错 → Playwright `outputDir` 必须放在 `os.tmpdir()` 下命中豁免通道，否则 e2e 清理阶段崩溃。

### 破图判定必须走独立 HTTP 探测，不能看渲染态
- 现象：character 页 301 张 CDN 图，jsDelivr burst 限流下部分 img 立即失败且浏览器不自动重试（等 40s 仍 80 张）；而单独 `new Image()` / curl 同 URL 成功。
- 结论（已固化进 `e2e/visual.spec.ts`）：页面失败图 URL 用 `page.request.head`（并发 6）独立探测，仅非 2xx 才算真死链。渲染态判断结构性不可行。
- 代理不是根因：Playwright headless 默认不继承系统代理；显式配代理（bypass localhost）后失败数不变 → 属 burst 限流。
- CI 数据中心 IP 的 HEAD 探测不可靠（img 加载成功但探测被拒）→ CI 跳过探测，由像素基线兜底。
- 像素容差 0.05 用于吸收 Linux/Windows 渲染与文案差异。

### jsDelivr 使用纪律（联网核实 + 实测）
- 不缓存 404（`no-cache, no-store`）：反复探测即反复回源 GitHub → 死链必须本地缓存。
- 突发高并发 429 限流 → 并发 3 + 退避重试；HEAD 支持良好；冷文件 200 直接回源或 302 到 raw。
- 文件上限 GitHub 50MB / npm 100MB；禁止图床与大文件托管；UA 需标识工具。

### Spine 双运行时是长期硬约束
- 探针取证（Range 读头部）：nanoka `.skel` 为自定义封装格式（非标准 spine 二进制头，前 32 字节内嵌明文 `4.1.23`），CDN 无任何 4.2 格式替代文件（5 种命名模式全 404）→ 4.2 运行时无法加载，双运行时（nanoka 4.1.23 / 官网 4.2.43）不可合并。

### playwright 包导入（重复踩坑 3 次，必须记住）
- `import { chromium } from 'playwright'` → `ERR_MODULE_NOT_FOUND`：package.json 仅直接依赖 `@playwright/test`，pnpm 严格结构下传递依赖不可从根 node_modules 解析，与脚本放置位置无关。
- 统一写 `import { chromium } from '@playwright/test'`（其入口全量 re-export playwright API）。禁止再写 `from 'playwright'`。

### Vite 8（rolldown-vite）dev transform 缓存永久陈旧（Windows 实证，代码注释引用本节）
- 现象：改 CSS/TS 后 dev server 永远返回旧内容，重启才恢复；「时有发生」非必现。
- 根因链（探针实证）：① rolldown-vite 8.1.5 内联自研 watcher，Windows 下「文件整写（O_TRUNC）后的紧邻变更事件」会被吞掉（writeFileSync→append 序列 0/3 丢失；append→append 全捕获）；② Vite transform 缓存无 mtime 兜底，事件丢失即该文件永久陈旧，不受后续无关请求影响；③「.vue 新鲜 .css 陈旧」是假象——取决于该文件最后一次成功事件与磁盘修改的先后，与扩展名无关。
- 自动方案全部废弃，禁止重试：`invalidateAll()`（打不通 rust 内核缓存）；`watcher.emit('change')`；`utimes`（rust 只认内容/size）；分轮「内容触碰」（单实例有效，但多进程 append+覆盖写竞争会破坏源文件——实测 compare.ts 被写成 787B 空白壳）。
- 最终防线（均已落地）：① `vite.config.ts` `server.watch.usePolling(300ms)` + ignored 追加 `public/data`（降低事件丢失率，不根除）；② 手动自愈工具 `tools/refresh-vite-cache.mjs`（读回→写回×2，手动按需、先保存再运行）；③ 排查顺序：curl 对比磁盘特征串 → 自愈工具 → 重启 dev server。
- 行为约束：dev 下怀疑「改了不生效」时禁止直接重启分析，先跑自愈工具，仍不生效再重启；**build 进行中禁止运行自愈工具**（写回源文件与 build 读取并发会破坏文件）。
- build 不受影响：`vite build` 独立进程同步全量读磁盘，无 watcher 事件链路与跨进程源码级增量缓存 → 产物必然反映磁盘内容；可反当「磁盘内容是否已更新」的诊断手段（产物流旧 = 文件未落盘）。
- 上游动态（2026-08-14 检索）：无官方成熟方案；vite 8.2 已入若干 HMR 修复，升级后重测，若彻底修复则自愈工具可退役。
- 附带实证：vite 8.1.5 的 `configureServer` 返回值会被立即调用（close 钩子语义失效），dev 插件清理必须挂 `server.httpServer.on('close')`。

### 虚拟网格探针的三个假象（探针返工 ≥2 轮的根因）
- 现象：溢出检测显示 36/36 卡均匀 +4px；hover 阴影捕获到全透明中间帧。
- 根因：① 卡片入场动画 `nk-card-in`（`from translateY(14px)` + `backwards`）在 delay 期/未 reveal 时恒为 `opacity:0 + translateY(14px)`，`getBoundingClientRect().bottom` 多出 14px；② `[].every(...)` 对空数组恒 true → `waitForFunction` 秒过。
- 处置：溢出统计过滤 `opacity==='1' && transform==='none'` 的卡片；等待条件必须带 `visible.length >= N` 前缀；hover 断言等阴影 alpha 特征（0.2/0.45）而非 `!== 'none'`。
- 门槛：虚拟网格首屏稳定 reveal 数 < 视口卡片总数（IntersectionObserver threshold 0.5，缓冲行不触发）——等待门槛不得高于稳定值（实测桌面 1440×900 = 18 张、手机 375 = 全量 10 张）。

### 判定型任务放 CI 前先实测 CI IP 是否被目标正常响应
- 事实：死链审计在 data-sync 跑 20min 超时；根因是 CI IP 对 jsDelivr 403 → 全部 URL 判 env（不 FAIL）+ env 缓存 1 天 → 每天重测、增量推进永远推不完 = 空转烧预算。
- 终局（用户拍板）：CI 移除死链审计；`tools/dead-links.test.ts` 保留，本机真实网络按需跑（死链是静态事实）。
- 保留的工具修复：角色详情审计 id 推导改用 `basename(f, '.json')`（详情文件无顶层 id 字段，原 `String(d.id)` 产生含 `undefined` 的 URL 并漏检全部星魂/技能）。
- 教训：依赖目标服务器对探测 IP 响应的判定型任务，上 CI 前先实测该 IP 可用性。

### CI 冗余判定标准
- 判据：删掉后是否有能力损失 + 是否有其他机制兜底。可删三类——与执行平台重复的守卫（Vercel 已跑 build）、与执行步骤重复的测试（convert 前 pytest）、低频变更的常驻测试。
- 必须保留「平台独有能力」（e2e）与「失败取证」（report / artifacts 上传）。
