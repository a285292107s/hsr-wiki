# 0020. 货币战争枢纽页改为「本赛季新增」页（赛季代际差集）

## 状态

`accepted`（**已实现**：converter 赛季代际差集打标 + 装备卫生过滤 + CW 枢纽页两分区 + 原语中性化 + e2e 断言重写均已落地，实现与验证记录见文末「相关」）

> 本决策**取代 [ADR 0019](0019-枢纽页导航条回归与首页改为版本上新页.md) 的「两枢纽页内容形态分叉」这一后果段**：`/currency` 不再是「品牌带 + 5 行板块索引」的入口页，改为「品牌带 + 本赛季新增两分区 + 页脚」。
> ADR 0019 的其余条款（导航条全断点回归、`/` 为版本上新页、跨模式只走侧栏「交换」、置换通道保留）**继续有效**。
> 两页的**判据口径自此明确分工**：常规模式首页 = 版本增量（`version_label`）；货币战争 = **赛季代际差集**。二者**禁止混用**（见 `CONTEXT.md`「本赛季新增」）。

## 背景

需求：`/currency` 也要展示「新版本内容」，通过对比新旧数据获得。

**先按版本差集试过，结论是不可行**（以已提交快照实测，`public/data/cn/currency/*.json`）：

| 版本跳变 | 角色 | 装备 | 环境 | 策略 | 羁绊 |
| --- | --- | --- | --- | --- | --- |
| 4.4 → 4.5 | +0 | +0 | +0 | +0 | +0（该次提交只改了 `version.json`） |
| 4.5 → 4.6 | +0 | **+1** | +0 | +0 | +0 |

4.6 那唯一一条「新装备」是**名称解析失败的占位**（`id 350108`，name/desc/category 全空、图标复用 350105，走转换器兜底分支）——即按版本差集，CW 侧在当前版本是空页。
根因：**该模式的内容在赛季上线时一次性下发**，赛季内的补充不落在五个图鉴域的数据里。

**改用赛季代际后结论反转**。源数据有两张并列名册快照表（每行以 `ExistSeason` 标代）：

- `GridFightRoleBasicInfoOld`（198 行，角色名册；按 `AvatarID` 去重后 代101=61 / 代102=64 / 代103=68 位）
- `GridFightTraitLayerOld`（378 行，羁绊层级；代101=34 / 代102=35 / 代103=37 个羁绊）
- 当前代名册在 `GridFightRoleBasicInfo`（当前代编号 1），当前羁绊表即 `traits.json`

代际差集实测（**与外部更新史逐批吻合**）：

| 代际 | 角色新增 | 对应外部更新史 |
| --- | --- | --- |
| 代101 → 102 | 火花、爻光、大丽花 | 4.0 第一次「赛季扩充」✅ |
| 代102 → 103 | 开拓者·欢愉、不死途、绯英、银狼LV.999 | 4.2 第二次「赛季扩充」（含新增欢愉羁绊）✅ |
| 代103 → 当前代 | 姬子•启行、千冶•刃、远坂凛、吉尔伽美什 | 4.4 第三次「赛季扩充」+ Fate 联动 ✅ |

羁绊同法：代102→103 新增 **欢愉**、头号玩家；代103→当前代新增 **领航员、师徒、命运圣杯**（命运圣杯 = 4.4 新增羁绊 ✅）。

**分辨率的边界（必须写明）**：代际内的小补充会被并入该代名册——4.3 的 Fate 联动第一弹 Archer 出现在**代103** 名册里，与 4.2 批次混在一起，数据无法单列；4.6 的「双倍晋升点 / 吞噬敌人词缀」在 CW 五个图鉴域的数据里**毫无痕迹**（词缀不在本模式图鉴域的表中）。

**其余三域无代际表**：全仓仅上述两张 `*Old` 表；装备 / 环境 / 策略既没有赛季字段（`equipment.json` 无、`GridFightSeasonPortal` 与 `GridFightSeasonAugment` 全为 SeasonID 1），版本差集又实测为 0。

另：`GridFightSeasonItem`（225 行）中有 **60 行 `SeasonID=2`** —— 客户端已预载下一赛季道具，说明赛季滚动时名册会整体换代。

## 决策

1. **`/currency` 改为「本赛季新增」页**：品牌带 + **角色图鉴 / 羁绊图鉴** 两分区 + 页脚；**5 行板块索引退场**（选路交给导航条，与 `/` 同策）。
2. **判据 = 赛季代际差集**：当前代名册 − **上一代**名册。「上一代」= `*Old` 表中 `ExistSeason` **最大**的一代（当前为 103）。
3. **覆盖域 = 角色 + 羁绊两域**（唯一有两张 `*Old` 代际表的域）；装备 / 环境 / 策略**本轮不进入该口径**，也不为它们新造判据。
4. **数据侧**：`tools/converter/converters/currency.py` 读两张 `*Old` 表算出差集，给 `role.json` 与 `traits.json` 的条目加布尔字段 **`is_season_new`**；前端只读该字段过滤（与首页「前端只读标记字段」同模式）。
   - `*Old` 表缺失或为空 → 全部为 `false`（即空集，走空态），**禁止**退化为「全部为 true」。
5. **文案写「本赛季新增」，不显示赛季号**：当前赛季在数据里编号为 1、旧代编号为 101/102/103，两套编号体系不一致，显示数字会误导（外部认知里 4.4 是「第三次扩充」）。
6. **空态与渲染规则**：与首页一致——无增量的分区不渲染；两分区皆空则显示一行空态文案（品牌带与页脚保留）。
7. **原语跨页共享**：分区结构复用首页的三分区原语，但**必须中性化命名并单点声明**（现名 `.nk-home-release*` 落在 `catalog.css`，被两页消费即违反「跨页复用原语必须中性命名 + 单点声明」纪律）。
8. **首屏验收与首页同口径**：1920×1080 内品牌带 + **每个已渲染分区**的标题与首行卡片底部 ≤1080；CW 页同样断言全断点渲染导航条、无 `data-nav`、无横向溢出。（**被 [ADR 0019](0019-枢纽页导航条回归与首页改为版本上新页.md) 决策 11 收窄**：只断言第一分区，后续分区随滚动进入。）
9. **顺带的数据卫生**（独立于上面的内容口径）：转换器过滤**名称解析失败**的 CW 装备条目，避免 `350108` 这类空壳卡出现在 `/currency/item` 与本页。

## 后果

**正面**

- CW 枢纽页首次有**真实内容**：当前代新增 4 位角色 + 3 个羁绊，且**完全由数据推导**，不需要人工维护清单。
- 判据与外部更新史可交叉验证（四代差集逐批命中），后续换代时页面自动跟随。
- 两页口径分工明确：常规 = 版本增量、货币战争 = 赛季代际，且都已落成 `CONTEXT.md` 术语，不再有「本版本/本赛季」混用的空间。

**负面**

- **代际内补充不可分辨**：4.3 的 Archer 并入代103（与 4.2 批次同代），4.6 的双倍晋升点 / 吞噬词缀完全不可见——**这一层只有外部更新公告能提供**，本决策明确不引入人工时间线。
- **三域缺席**：装备 / 环境 / 策略在本页没有位置，读者可能认为漏做；且本轮收回了「五域全上」的初版意向。
- **判据分两套**（版本增量 / 赛季代际），未来的维护者必须记住哪一页用哪一套，写错就静默出错（靠 `is_season_new` 字段名与术语 `_Avoid_` 约束）。
- **依赖 `*Old` 表的语义**：「上一代 = `ExistSeason` 最大值」是基于当前快照（101/102/103 + 当前代 1）的推定；若客户端改变 `*Old` 的写入策略（例如改成只存一代、或改用与当前代同一套编号），差集算法需重新核验。**这是本决策最脆的一点**，落地时必须在转换器里加防御（表缺失/代数少于 2 → 空集 + 日志告警），并在换代后实测一次。
- **同代内含轮换**：代103 的 7 个羁绊在当前羁绊表里已不存在（羁绊会轮换出），故「新增」只是单向差集，不代表「当前 = 上代 + 新增」。

**中性**

- 品牌带、页脚、枢纽文字出场等共享原语不动，两页仍同时序。
- `is_season_new` 是纯展示标记，不参与目录页排序（`/currency/role`、`/currency/trait` 列表顺序不变）。
- `e2e/layout.spec.ts` 的 `/currency` 用例（现断言 `.nk-cwhub-index__row ≥ 5`）必须随索引退场重写。

## 替代方案

| 方案 | 为何未采用 |
| --- | --- |
| 沿用版本 id 差集（与首页同一机制） | 实测无效：4.4→4.5 五域全 0、4.5→4.6 仅 1 条空壳——CW 页会长期是空页 |
| 五域全上 | 装备 / 环境 / 策略在源数据里既无 `*Old` 代际表、版本差集也为 0，摆上去只会长期空位（本轮已收回该意向） |
| 引入人工「扩充时间线」数据源（照外部公告维护） | 与「展示文本必须来自 converter 输出」的强制规则冲突，且引入第二个需人工同步的事实源；本决策只承认识别到代际粒度 |
| 三域改用赛季字段（`GridFightSeasonPortal` / `GridFightSeasonAugment`） | 实测这些表**全为 SeasonID 1**，判据会命中全量（环境 83 / 策略 334），等于把「全量目录」当「新增」展示 |
| 给条目加 `season_added`（首次出现的代号）+ 前端自行比较 | 前端要额外拿到「当前代」并做比较；本轮只需布尔，历史信息待有真实展示需求时再加字段 |
| 新增聚合文件 `currency/release.json` | 引入与首页不一致的第三种数据形态；字段级标记更贴近既有模式 |
| 显示赛季号（第 N 赛季） | 数据里当前代编号为 1、旧代 101/102/103，显示「第 1 赛季」与外部认知（4.4 是第三次扩充）冲突 |
| 保留 5 行板块索引，扩充内容与之并存 | 与 ADR 0019 首页同策相悖（首页已用内容取代索引）；首屏会被两套区块瓜分 |

## 实现与验证记录（2026-09-29 落地）

- **数据**：新增 `tools/converter/season_delta.py`（`generations` / `prev_generation` / `mark_season_new` / `apply_season_new`）+ `tests/test_season_delta.py`（19 例）。打标落在 **`converters/currency.py`（角色）** 与 **`converters/currency_catalog.py`（羁绊）**——落地清单原以为两域同在 `currency.py`，实测 `traits.json` / `equipment.json` 由 `currency_catalog.py` 产出，故 `MODULE_SOURCES` 也分别补两张 `*Old` 表（`test_incremental` 的 AST 依赖校验强制两边都补）。
- **装备卫生的真正位置**：空壳来自 `currency_catalog.py::_convert_equipment` 对 `GridFightItems` 的全量遍历（`ItemName` 解析为空即过滤 + `logger.warning` 打印 id）；`currency.py::_index_recommend` 里同形的 `name: ""` 兜底是**角色详情的引用占位**，与 `/currency/item` 无关，本轮未动。
- **锚点实测**（Lead 独立复核，非仅看汇报）：`role.json` 75 条、`is_season_new=true` 恰 4（姬子•启行 / 千冶•刃 / 远坂凛 / 吉尔伽美什）；`traits.json` 33 条、true 恰 3（领航员 / 师徒 / 命运圣杯）；`equipment.json` 166 → 165 且无空名条目。连跑两次转换，`currency/` 81 个文件 sha256 差异 0（幂等）。降级路径（表缺失 / 代数 < 2 → 全 false + WARNING）由 4 个单测覆盖（含 caplog 断言），**未做端到端缺表演练**（无法在真实 vendor 上制造）。
- **前端**：`CurrencyHubView.vue` 改为品牌带 + `.nk-hub-release` 两分区 + 页脚（5 行索引整块删除）；`use-release-showcase.ts` 新增纯函数 `pickSeasonNew` 与共用内核 `buildReleaseSectionsBy`（首页 `pickCurrentVersion` / `buildReleaseSections` / `useReleaseShowcase` 零回归）；`currency-role.ts` / `currency-trait.ts` 的 `fetchData` 透传 `is_season_new`（`renderCard` 与筛选未动）；CW 卡片样式经配置 `styles` 动态 import 引入，首页 chunk 未被 CW 配置污染。
- **原语中性化**：`.nk-home-release*` → `.nk-hub-release*`（37 处），保留在 `catalog.css` 单点声明（理由见决策 7 与 `ui-design.md` §1 登记行）。
- **卡片宽度分工（实现中发现，易再踩）**：`catalog.css` 只覆盖目录卡片（`.nk-idx-card` / `.nk-lc-card` / `.nk-relic-card` / `.nk-cw-card`）；CW 枢纽页两类卡片实际是 `.nk-crole-card`（currency-role.css）与 `.nk-cw-trait-card`（currency-catalog.css），其桌面 144px / 手机 116px 由 `currency-hub.css` 以 `#nk-cwhub-app` 作用域声明。**两处禁止各写一份**。
- **验证实测（冻结版本）**：`pnpm build` exit 0；`pnpm test` **298 passed**（新增 15 例）；`pytest`（tools/converter）**229 passed**（新增 19 例）；`check-colors --strict` / `check-contrast --strict` / `check-doc-links` 全 exit 0；`pnpm test:e2e:ci` **40 passed**——e2e 由 Lead 重写：删除 `.nk-cwhub-index` 三处旧断言与 10 处 `.nk-home-release*`，新增「/currency 两分区 + 卡片 href 指向图鉴详情页」「1920×1080 首屏内可见本赛季新增」「本赛季无新增时只显示一行空态」三用例，并把 0019 的客户端跳转改从侧栏 CW「角色图鉴」项发起（索引退场后无页内行可用）。
