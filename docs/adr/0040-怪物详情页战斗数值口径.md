# 0040 — 怪物详情页战斗数值口径（基准 × 维度修饰比 × 等级曲线）

## 状态

`accepted`（**已实现**；**被 [0045](0045-怪物数值合成链补上实例修正值与默认等级.md) 修订**：
决策 1 的算式扩展为四段——`… + MonsterConfig.{Stance,Speed}ModifyValue`（加在曲线之后，不再被缩放）；
决策 4 的「未含场景系数」收窄为「未含**关卡级**剧情与场景系数」；决策 6 的「默认等级 100」
改为「该难度组曲线的最高档」；**又被 [0049](0049-怪物数值合成链补上怪物侧精英组倍率.md) 修订**：
决策 1 的算式插入「精英组倍率」段、决策 4 的「场景系数」获得身份——即精英组倍率，
注记改述为「未含关卡侧精英组指派与剧情系数」）

## 1. 背景与问题

怪物详情页（`/monster/:id`）此前直出 `MonsterTemplateConfig.HPBase / AttackBase / DefenceBase / SpeedBase`
（`monster_common.py` 的 `stats` 字段）。实测典型值（`/monster/1002011` 冰锋）：
`HP 69.75 / ATK 18 / DEF 210 / SPD 100`。

- 这是**模板基准值**（社群逆向术语「无想面具线型单位」），不是任何等级下的战斗值——玩家会被这组数字
  与游戏内对不上的观感误导（把 69.75 读成「这只怪只有 69 点血」）。
- 数据侧完整合成链在仓内表里**三条腿都在**，只是转换器没有接上：
  1. `MonsterTemplateConfig.{HPBase,AttackBase,DefenceBase,SpeedBase}` — 模板基准；
  2. `MonsterConfig.{HP,Attack,Defence,Speed}ModifyRatio` — **同模板不同档位变体**的维度修饰比
     （`1002011 hpR=1`、`100201101 hpR=0.266667`，表现为不同档位的血量差）；
  3. `HardLevelGroup.json` — 难度组 → 等级（1..100）→ 四维曲线（745 条，`HPRatio/(0.8)` 等）。
- 外部佐证：3DM（社区逆向）《敌人最终生命值 = 基础生命值 × 基础线型标度值 × 生命值修饰值1 × 生命值修饰值2》
  （https://ol.3dmgame.com/gl/230717.html）；与仓内表结构逐字段对应。

## 2. 判定

**是本项目的口径缺陷，非官方数据错误。**修正方式是补全合成链，不改动上游数据。

## Considered Options

- **继续直出模板基准值（`*Base` 四维）**：放弃——玩家会把 69.75 读成「这只怪只有 69 点血」，与游戏内观感对不上。
- **转换期按固定等级写死战斗值**：放弃——写死等级就没有「等级档滑条」，且上游改曲线即需要重跑全部详情产物；改为前端按 `level_group` 现算。
- **详情 payload 内联等级曲线**：放弃——2722 份 × 45KB 不可承受；曲线单独落盘 `monster-level-curve.json` + 共享单例加载。
- **把 `*ModifyValue` 一并纳入合成（作为「修饰值 2」）**：当时放弃——理由是该系数在 Stage 配置区间采样离散、加法位置无据可验；**此判断后被 [0045](0045-怪物数值合成链补上实例修正值与默认等级.md) 推翻**（该值逐怪在 `MonsterConfig` 里，且加法位置已可验证）。
- **缺位按 0 处理**：放弃——会把一条 HP 显示成 0，比「没有数据」更误导；一律按中性 1 且缺位时回退降级态。

## 3. 决策

1. **战斗数值在前端合成**：`stat(level) = stats × stat_ratio × level_curve[level_group][level]`。
   前端合成而非转换期写死等级，画面才允许「等级档滑条」（与光锥页「叠影」滑条同语言），
   玩家在 1..100 内自由回看任意档。
2. **等级曲线单点落盘**：`public/data/cn/monster-level-curve.json`（{
group → level → {hp,atk,def,speed}}）；详情页 payload 不复制曲线（2722 份 × 45KB 不可承受），
由共享单例 `loadLocalMonsterLevelCurve()` 加载。
3. **详情 payload 增量**：`stat_ratio`（来自该 MonsterID 自己的 MonsterConfig 记录；模板自身记录缺省 1）
   与 `level_group`（MonsterConfig.HardLevelGroup，缺省 1）。
   - **alias 变体必须用自己那条 config 记录的修饰比/难度组**，不能沿用模板值——同模板的档位
     变体正是用这两个值区分的（实测 `1002011 hpR=1` vs `100201101 hpR=0.266667`）。
4. **口径注记必须与数字同屏**：数值是「模板基准 × 维度修饰比 × 等级曲线（难度组 N）」，**未含**
   剧情与场景系数（社群术语「生命值修饰值2」；该系数在 Stage 相关配置区间采样离散，不在本仓
   逐怪合成范围内）。禁止把数字渲染成「这就是游戏内血量」，口径文案随屏可见。
5. **缺位的静默中性化**：曲线/修饰比缺位按中性 1 处理并 write 日志/文案，不静默归零（0 会把
   一条 HP 显示成 0，比「没有数据」更误导）。难度组缺位（如组 4/5 无记录）⇒ 详情页回退到
   「仅展示档案基准值」的降级态（不假数值）。
6. **默认等级 = 100**：曲线表内最高等级；详情页滑条范围 = 1..maxLevel（本组实际可用等级）。

## 4. 影响面

- `MonsterDetailView.vue`：`基础数值` 区改名 `战斗数值`，等级滑条 + 合成显示 + 口径注记；
  曲线缺位的怪物保留基准值展示。
- `monster_common.py`：新增 `_stat_ratio_from_cfg` / `load_level_curve`；输出字段追加
  `stat_ratio` / `level_group`。
- `monster_detail.py`：新增 `monster-level-curve.json` 输出 + 详情 payload 增量。
- 前端：`src/lib/monster-stats.ts`（纯函数合成，vitest 单测）；
  `src/services/api/items.ts` 增 `loadLocalMonsterLevelCurve` 共享单例；
  `src/services/types/monster.ts` `MonsterDetail` 增两字段。
- **不动**：`monsters.json` 列表/`endgame` 赛季数据里的 `stats`（继续是模板基准值，列表页
  不展示这三项，无口径漂移）。
- 转换器的其他目标（`endgame.py` / `voracity.py` 消费 `load_monsters()`）对新增字段不受影响；
  结果形状仅追加键，不改既有键。

## 5. 后果

- 怪物详情的 `stats` 字段语义**不再单独呈现**——展示层一律走合成值；基准值保留为口径注记的
  对照段。
- 后端若新增其他战斗场合（如世界/深渊难度表），须更新这里的合成链（场景系数在 Stage 级配置，
  树状含义不同意逐怪覆盖——已按现状收敛）。
