# 0036. 召唤物并入召唤者卡片，并按污染等级标记受污染者

## 状态

`accepted`（**已实现**：`endgame.py` 建立 `MonsterConfig.SummonIDList` 索引，在 `_stage_waves_monsters` 收口处把每个敌方实例自己的召唤物挂到**该敌方条目**上（`monsters[].summons[]`，轻形态 `{id, tpl?, name, icon, polluted?}`），四份终局产物在层上下半场 / 星启节点 / 异相仲裁单关与绝境变体上一并生效；`EnemyCard` 卡内新增「召唤物」分区、`StageContent` 与 `EndgamePeak` 的图标格内嵌同一列表；`MazeSummonInfo` 类型、`EndgameSummons.vue` 共享件与 `.nk-egd-summons*` / `.nk-egd-floor__moncell` 中性原语同批落地。**修订（2026-10-02，用户裁决：并入召唤者卡片，见「修订」节）**——初版的「敌方配置之后另起一行」形态与场次级 `summons[]` 已作废）

## 背景

用户提出：末日幻影详情页有些首领带召唤物，而这些召唤物受「贪饕」污染，需要展示并**具体表明哪些怪物受污染**。取证后有六条事实决定了形态：

1. **末日幻影层级只登记首领**（[ADR 0031](0031-末日幻影层级敌方取实际战斗数据.md)），`StageConfig` 波次里没有召唤物——所以「敌方配置」天然不完整，读者只看到首领本体与一枚污染徽标。
2. **受污染者就是召唤物**：4 处末日幻影污染关卡（3020 第 3/4 层上半场、3021 与未发布的 3022 同名两场）的被污染怪物 6/6 命中该场次首领实例的 `MonsterConfig.SummonIDList`，且**逐层实例精确对应**（3020 层 3 = `202206017`/`202303203`，层 4 = `202206018`/`202303204`）。旁证：3021 首领特性「阵地转移」原文即「首领幻影召唤 2 个精英敌人协助战斗……将自身弱点属性传递给召唤物」。
3. **召唤表比污染名单大**：3020 每层 8 只召唤物只有 2 只受污染，3021/3022 每场 4 只只有 2 只受污染——「只有部分召唤物被污染」这件事本身就是信息。
4. **召唤物不是末日幻影独有**：全站有召唤物的场次块 = 末日幻影 191/191、忘却与虚构常规 881/1266、虚构叙事 109/228、异相仲裁 35/40（另有 7 个绝境变体）。而**存在受污染召唤物**的场次块只有 12 个（末日幻影 9、虚构 2027 层 4 下半场与其星启节点 2、忘却 1036 星启节点 3）。
5. **图鉴覆盖 100%**：全站被引用的召唤物实例（场次去重 2387 条，按召唤者分发 3005 条）全部已在 `monsters.json` 注册，可出名称与图标，无空项风险（老稿的 1446 条「未注册」是取模板 ID 的算式写错所致）。
6. `MonsterConfig.json` **已在 `incremental.py` 的 endgame 模块源表内**（`monster_common` 路径），本轮不新增增量登记。

## 决策

**我们把「召唤物」并入**它自己的召唤者**的敌方条目，并用污染等级标记其中受污染者**：

1. **归属＝召唤者**：一只召唤物只出现在**列出它的那个敌方实例**的条目里，不再作为场次级的独立行。末日幻影层看板 / 四模式星启看板经共享件 `StageContent` 渲染（卡内分区），异相仲裁的图标行在 `EndgamePeak` 两处内联同步（单关 + 绝境变体）——四模式字面一致，**零 `modeKey` 分支**。
2. **区块名与标记**：敌方条目内以「召唤物」小标签起段；受污染者挂现有 `.nk-egd-pollchip` 徽标（`污染等级 N`），**未挂徽标即未受污染**，不另加解释性文本。
3. **渲染触发＝该敌方实例有召唤表**（`SummonIDList` 非空且命中本场次）：全站约 2400 个场次块、3005 条引用带上召唤物；`invasion` 与召唤物各自独立——无污染场次照样列出召唤物，只是没有徽标。
4. **判据（前端禁止运行时 join）**：召唤关系取**该敌方实例**的 `MonsterConfig.SummonIDList`（实例级，逐层精确），**禁止**改用模板级并集或全库反查召唤者；污染标记取**同一场次** `invasion.monsters` 的实例 ID 命中，值为该场次 `InvasionID`。两者都在转换期算好。**同一召唤物被同场多个敌方列出时，就在各自条目里各出现一次**——这不是歧义：多个敌方各自都具备召唤该单位的技能（如幼蛰虫分裂出自己、银鬃尉官与布洛妮娅都能召出银鬃近卫）。
5. **数据形态**：敌方条目（`MazeMonsterInfo`）新增 `summons[]`，条目为**轻形态** `{id, tpl?, name, icon, polluted?}`（用户裁决）——条目内只消费图标 + 名称 + 徽标，弱点/抗性/韧性/速度/技能无消费方；未注册实例跳过；无召唤物不落该字段；**场次级 `summons[]` 不再产出**。
6. **AI 快照本轮不同步**：沿用 [ADR 0026](0026-污染等级进入终局玩法详情页.md) 的取舍（要同步需动 catalog 条目、生成器、守卫三处）。

## 后果

**正面**

- 末日幻影详情页能回答「这一场首领带哪些召唤物、其中哪几只受『贪饕』污染、污染等级几」——4 处受污染战斗各自在首领卡内列出全部召唤物并给 2 只挂徽标，「只有部分召唤物被污染」一眼可读。
- **归属一眼可读**：召唤物贴在召唤者身上，「谁召的谁」不需要读者在两条并行列表之间心算配对；多召唤者场景（同一只召唤物被同场多个敌方列出）也如实各自呈现，而不是被去重成一份无归属的清单。
- 「敌方配置只有首领」这一数据形态不再需要读者自行脑补：召唤物就在该首领卡内，二者同一张脸。
- 判据是实例级的，逐层区分（同一首领在层 3 与层 4 召唤的实例不同），不会把别层的召唤物算进来。

**负面**

- **面广**：全站约 2400 个场次块、3005 条召唤物引用进入产物；相对「场次去重出一行」的口径多 517 条重复引用、约 +22 KB（按召唤者分发是有意代价）。
- 忘却之庭 / 虚构叙事 / 异相仲裁原本用图标行表达敌方，现在带召唤物的图标格会向下长出一个小列表，行高不再齐平（末日幻影是纯 Boss 战、走卡片，不受影响）。
- 末日幻影的无污染场次也会在首领卡内列出召唤物，读者可能误以为「召唤物 = 受污染」，靠徽标区分。

**中性**

- 更早的判据「被污染小怪由机制额外加入」在本轮被收窄为「末日幻影侧即首领召唤物」；虚构叙事另有 3 只（`8012020`/`2012010`/`1002030`）既不在敌方配置里、也不由在场敌方召唤，它们**不出现在任何召唤物列表**，仍只由赛季级「污染等级」区块列出——这是判据的边界，不是遗漏。
- `CONTEXT.md` 的「污染关卡」词条与「召唤物」词条同步收口；`docs/data/转换器字段映射.md` 记录字段来源与判据。

## 修订（2026-10-02，用户看过页面后：并入召唤者卡片）

**用户原话**：「我认为存在多个召唤者的情况，是因为这些怪物都拥有召唤该召唤物的能力。因此，我希望把召唤物列表并入召唤者的怪物卡片中展示，这样结构最清晰。」

- **被推翻的是初版的「另起一行」，不是判据**：初版把召唤物做成「敌方配置」之后的一行、按场次求并去重，于是**多召唤者被压成一份无归属清单**；用户指出那些「多召唤者」恰恰是各自都能召唤该单位的技能（幼蛰虫分裂自身复制体、银鬃尉官与布洛妮娅都能召出银鬃近卫），去重反而抹掉了归属信息。改为在 `_stage_waves_monsters` 收口处按召唤者分发，`endgame.py` 的 `_stage_summons`（场次求并）随之删除，`MazeStageDetail.summons` / `PeakLevelInfo.summons` / `hard.summons` 三个字段一并退场。
- **判据的边界再次被看清**：全库反查召唤者会撞上「同模板多实例共用同一张 `SummonIDList`」（570 个被召唤实例里 200 个有多个召唤者，3021 那两只就有 5 个候选召唤者：`2004014` 本体 + 4 个实例），**只有同场次求交才能唯一化**；实例级判据因此继续有效。
- **改判据而不放宽断言**：召唤物从「场次末行」回到「敌方条目内」后，敌方配置重新成为场次块末行，几何断言从「下方只留下内距与发丝线」改回「下方余白 = 0」，并新增一条 `lastIsMons` 守卫锁住「谁在末行」这件事本身；`--summons` 行类名与相关行结构断言整体删除。
- **验证**：`python -m pytest tests/ -q` 301 passed；`pnpm test` 349 passed（27 文件）；`pnpm build` exit 0（三守卫 + `vue-tsc -b` + AI 端点快照 1200 + 守卫 7/7）；`npx playwright test e2e/layout.spec.ts --grep "3020|3021|另两种污染形态"` 10 passed；`npx playwright test e2e/layout.spec.ts e2e/accessibility.spec.ts --grep "endgame|终局"` 21 passed；`node tools/check-doc-links.mjs` PASS。
- **降级/未做**：① `visual.spec` / 像素基线未跑（终局详情页本就无基线）；② 未跑全量 `pnpm test:e2e:ci`（按 T2 收敛到 endgame 定向 + a11y）；③ AI 快照仍不同步（沿用决策 6）；④ 图标格内长出召唤物列表后的行高不齐、卡内 8 只召唤物的换行密度**交用户 RunPreview**。

## 补记（2026-10-12：召唤物名允许断长词，收口手机档长译文溢出）

用户点名「移动端多语言下召唤物列表横向溢出」。**判据、数据形态与归属规则一字未动，只修行内文字的收缩性**：

1. **根因**：`.nk-egd-summon`（图 26px 不可缩 + 名 + 徽标）是 `inline-flex`，行长由三者共同决定；flex 项默认 `min-width: auto` 不可收缩。长译文名（es `Mnemoduende de Sangre Dorada: Faisán`）把该行 min-content 顶到 232px > 手机档可用 214px，整行拒绝收缩，溢出沿 `.nk-egd-summon__list → .nk-egd-summons → .nk-egd-mon__data` 撑破敌方卡。实测 en 4 / es 40 / fr 28 / pt 25 / ru 21px（de 列表 14px）。
2. **修法**：`.nk-egd-summon { flex-wrap: wrap }`——名字要整行宽时**污染徽标落到次行**，而不是压缩名字。**三个「看起来该有用」的修法实测均无效**（给行内徽标加换行 / 列表 `inline-flex` 改 `flex` / 行 `min-width: 0`——真正不可缩的是名字，不是行）。
3. **曾走错一步，留档以免重走**：先用了 `overflow-wrap: anywhere` 断名字——它确实把溢出清零，但名字被压到 min-content **逐字竖排**（实测 es 名宽 34px / **12 行**，en / de 6 行），比原溢出更难读。**「溢出清零」不等于「修好了」**：溢出是量的问题，断成竖排是读不了的问题。改这类规则必须同时量**名称的渲染行数**，只看 `scrollWidth` 会把竖排判成修好。**同批还踩过取证坑**：A/B 对照时未真正撤下被测声明，把「改动已生效」的页面当基线，差点据此保住错解。
4. **可见性极差（故单列一条契约）**：`html` 上有 `overflow: clip` ⇒ **页面级横向溢出恒为 0**，既有溢出守卫与 `noUnknownOverflow` 全绿。判据只能逐容器量 `scrollWidth`，故新增 `e2e/layout-endgame.spec.ts` 用例「敌方卡内不横向溢出（长译文语言的召唤物行）」：**8 长译文语言 × 两个落点**（忘却之庭 `maze/1036` 逐星启节点 + 末日幻影 `boss/3020` 逐层 × 半场），卡与列表两级都量。**该用例已实测可红**——撤下声明即报出 `de maze/1036 节点3 14px`、`ru maze/1036 节点3 21/37px`、`de boss/3020 17px`、`ru boss/3020 19/35px`，非恒真断言。**两个落点都要留**：只覆盖 `maze/1036` 时 `boss/3020`（召唤物名最长的一页）整类漏测。
5. **验收**：修正后 13 语言 × 4 模式全 tab 与子 tab 扫描，卡内 / 列表 / 页面溢出均为 0；名称渲染行数最大 2 行（`maze/1036` es 与 `boss/3020` ru 均 2 行，无逐字竖排）；`pnpm test` 463 passed；`pnpm build` 七守卫全绿；受影响 e2e（endgame layout 32 + 手机档 10 + i18n-overflow/a11y 25）全绿。
6. **验收时的取证纪律（写进 memory）**：本条的中间过程两次差点把结论写错——① 逐 tab 扫描点完不等稳定就采样，把 reflow 中间态记成溢出（`boss/3020` 一度报 19/35px 又复现不出）；② A/B 对照未真正撤下被测声明，把「改动已生效」的页面当基线。**最终判据一律取稳定态 + 真撤声明**：该用例内的 `measure()` 先等 600ms 再量，撤声明后仍能稳定报红。
7. **记账（本范围外，未改）**：异相仲裁 `/endgame/peak/9` 的**效果抵抗行**在 ru 下溢出（卡 4px / 行 20px，标签 `Сопротивление эффектам` 宽 162px 且 `flex-shrink: 0`）。**基线同值**（已 stash 对照实测），与召唤物无关，故不在本轮修。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 场次级独立一行（**初版形态**） | 实现最简单、行高恒定，但把多召唤者压成一份无归属清单，读者要在两条并行列表之间自行配对；用户看过页面后改判为并入召唤者卡片 |
| 同一召唤物只分给「首个召唤者」 | 产物与视觉都不重复，但会隐去其他同样具备该召唤能力的敌方，等于对数据撒谎 |
| 仅在「本场存在受污染召唤物」时渲染 | 全站只落 12 个场次块、零 carpet，但用户明确选了字面全量口径：非污染场次也要能看到首领带谁 |
| 末日幻影全量渲染 + 其他三模式仅受污染时渲染 | 契合「末日幻影敌方配置天然只有首领」的形态差异，但要引入 `modeKey` 分支，与三模式同构、共享组件的既有先例相悖 |
| 召唤物条目用完整敌方对象（226 B/条） | 为「召唤物也看弱点抗性」留余地，但条目内无消费方，产物要多付约 320 KB |
| 只在 `EndgameBoard` 内做（末日幻影层看板 + 星启看板） | 忘却 1036 星启节点 3 与虚构 2027 的两只受污染召唤物会漏标，与「判据驱动、四模式共用」冲突 |
| 转换器只给 `invasion.monsters[].summon` 布尔，前端求交 `invasion.monsters` | 同一关系在两处表达、需防漂移；且拿不到「未受污染的召唤物」，与「列出全部召唤物」冲突 |
| 全库反查召唤者（不限同场次） | 同模板多实例共用一张 `SummonIDList`，570 个被召唤实例里 200 个会有多个候选召唤者，归属无法唯一化 |
| 同步进 AI 快照（本轮不做） | 需把 summon 维度写进 `*.catalog.json` 并按模型同步生成器与守卫，超出本轮范围；记为取舍而非否决 |
