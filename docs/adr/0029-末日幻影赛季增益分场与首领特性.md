# 0029. 末日幻影详情页的赛季增益分场与首领特性

## 状态

`accepted`（**已实现**：`endgame` 模块新增 `buff_groups` 与 `boss_traits` 两个赛季级字段；`EndgameBuffs.vue` 的「赛季增益」按场次分组并新增「首领特性」区块；`incremental.py` 的 `endgame` 模块登记 `MonsterGuideConfig.json` / `MonsterGuideTag.json`。**决策 3 的展示层落点已被 [ADR 0030](0030-末日幻影详情页层级星启子tab.md) 修订**——两节内容改由层级/星启子 tab 承载，数据层与术语裁决不变。**决策 2 / 3 已被 [ADR 0044](0044-首领机制随敌方卡呈现.md) 修订**：`boss_traits` 退役、改按敌方模板键的赛季级 `boss_guides`（首领特性 + 阶段机制），命中登记的波次敌方带 `boss_guide` 指针，展示落点为敌方卡内两个分区；本节「按场次取末层」的取法与「赛季级区块 / 子 tab 区块」的落点描述随之作废，术语裁决与 `Tag.SkillID // 100` 唯一反查判据继续有效）

## 背景

用户以对照站（`hsr.nanoka.cc/boss/3020`）指出本页两处缺口：

1. **赛季增益没有分场**：源表 `ChallengeBossGroupExtra` 的增益按场次下发——`BuffList1`（第一场 / 上半场）、`BuffList2`（第二场 / 下半场）各 3 条，`BuffList3`（星启模式）3 条。本站当时把 1+2 合并成一串 6 条，读者看不出「哪三条属于哪一场」，星启模式的 3 条则完全没有落地。
2. **首领特性缺失**：页面只有楼层内的「可用增益」（`ChallengeBossMazeConfig.MazeBuffID` = 当期「末法余烬」），没有首领的战斗机制条目（如「坚防守备：首领幻影受到的伤害降低 50%……弱点击破后，行动额外延后，受到的伤害提高 100%」）。

三条事实决定了形态：

1. **机制条目按敌方模板登记、且配置表的敌方 ID 未必等于战斗敌方**：`MonsterGuideConfig.MonsterID`（= 模板 ×100 + 实例序号）→ `TagList` → `MonsterGuideTag`（名称 + 简述 + `ParameterList`）。同一模板的各难度实例 `TagList` 逐字相同，故按模板聚合即可、不必逐层。**但**业火焚心的影将军战斗模板是 `2035012`，配置表里登记的是蚀心兽 `2033022`（同图标 `Monster_2033020`、同机制组），直接按模板 join 会让「天狼」系赛季的下半场整场漏掉机制。
2. **技能 ID 可作模板反查，但会被跨首领共享**：`MonsterGuideTag.SkillID // 100` = 技能持有者的模板（`203501211 → 2035012`）。同组的另 3 条 tag 无 `SkillID`，且 `100401410` 这类技能被多个首领复用——反查必须**唯一**才可用。
3. **术语必须按官方文案**：游戏内教程（TextMap `7039255158974959772`）「◆ 末法余烬 ◆」把每期 `MazeBuff` 称「关卡效果」（`12677071358133122013`：「此处可查看『末法余烬』，即战斗中生效的关卡效果」），而「◆ 首领特性 ◆」段明确「首领强敌的投影会与常规首领存在差异……**随着难度的提升，首领会添加新的特性**」——即本类机制条目的官方名是**首领特性**。对照站把后者也标成「关卡效果」，属该站的用词。

## 决策

**我们把「赛季增益分场」与「首领特性」作为末日幻影详情页的两个原生维度**：

1. **数据层·分场增益**：`endgame.py` 的 `_group_extra_buff_groups` 按 `BuffList1/2/3 → stage1/stage2/tierce` 分组，写入赛季级 `buff_groups`；扁平 `buffs` **口径不变**（仍是 `BuffList1+2` 的并集 = 6 条），以免目录卡胶囊与 AI 快照的「N 项赛季增益」口径被连带改写。
2. **数据层·首领特性**：`_load_guide_traits` 把 `MonsterGuideConfig × MonsterGuideTag` 聚合为 `{敌方模板: [机制条目]}`（配置表缺失的模板用 `Tag.SkillID // 100` **唯一**反查补齐）；`_attach_boss_traits` 取**末层**两个场次 + 星启节点 3，写入赛季级 `boss_traits`。前端**禁止**运行时 join 这两张表（单一事实源）。（**已被 [ADR 0044](0044-首领机制随敌方卡呈现.md) 修订**：聚合判据与唯一反查不变，但落点改为赛季级 `boss_guides` 的**模板键** + 敌方条目 `boss_guide` 指针，且同批接上 `MonsterGuidePhase` 阶段链路。）
3. **展示层**：「赛季增益」按场次分组渲染（组标签 上半场 / 下半场 / 星启模式，空组不渲染），随后新增「首领特性」区块，进 `buildEndgameSections` 的 section 序号（`buffs → traits → pollution → tierce → floors`）。场次分组统一走 `renders.ts` 的 `endgameGroups`，其余模式（忘却之庭 / 虚构叙事）降级为单个**无标签**分组，模板与模板字符串不变。
4. **术语层（用户裁决）**：区块名、数据字段、类型与 CSS 类一律用官方术语**首领特性**／`boss_traits`；「关卡效果」一词在站点内**不指本词条**（它指游戏内的每期「末法余烬」，本站楼层内呈现为「可用增益」）。`CONTEXT.md` 新增「首领特性」词条并写明该同名不同指。

## 后果

**正面**

- 末日幻影详情页能回答「这一场可选哪 3 条增益、这一场有哪些首领特性、参数是多少」，与对照站逐条对齐（3020 三个场次共 12 条特性、9 条增益）。
- 分场口径来自上游结构本身（`BuffList1/2/3` 与 `EventIDList1/2`、`DamageType1/2` 同构），不是为展示而切分；星启模式的 3 条增益也因此首次进入页面。
- 反查规则有明确的唯一性闸门，宁缺勿错挂；命中覆盖率实测 21 个已发布赛季 × 上/下半场全绿（`杰帕德` 一类未登记机制的护卫不产出）。
- 术语与官方文案一致后，站点与游戏内教程、搜索口径不再打架。

**负面**

- `endgame` 模块的 `MODULE_SOURCES` 再增两张表，两张表更新会触发四份终局 JSON 全量重转。
- 首领特性与赛季增益**同为赛季级**，但语义上是「按场次 × 按难度」的：当前各难度共用同一份清单（上游实测如此），一旦上游改为按难度增量下发，现有「取末层」的取法会静默取到最高难度的一份，需要改成逐层字段。
- 新增一个 section 会改动 `buildEndgameSections` 的序号，既有页面内锚点与区块数断言随之位移。

**中性**

- **AI 快照本轮不同步**（同 [ADR 0026](0026-污染等级进入终局玩法详情页.md) 的取舍）：`/endgame/:mode/:id` 快照由 `*.catalog.json` 生成，要带上分场增益与首领特性须把两个字段汇进 catalog 条目 + 生成器 + 守卫三处；本轮按最小面不做，代价是 AI 侧看不到该维度。
- 星启模式的 3 条增益按「星启模式」组渲染在赛季级区块里，而对照站把它挂在星启节点下；两边内容一致、归属层级不同，页面结构差异属有意保留（本站星启区块已有独立节点渲染，不重复承载）。
- 场次标签用「上半场 / 下半场」（用户口径），游戏内文案作「节点一 / 节点二」；两者指同一结构，见 `CONTEXT.md`。**未改**：楼层内的「可用增益」（末法余烬）保持原名，改名会与「首领特性」区块的检索词混淆。（**本条已被 [ADR 0033](0033-星启模式改单节点看板.md) 决策 8 修订**：用户裁决全站移除「可用增益」标签，末法余烬只显示增益名与效果描述。）
- 对照站与部分社区内容把首领特性写作「关卡效果」：这是**他站用词**，站点按官方术语走，不做两套标题。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 前端运行时 join `MonsterGuideConfig` / `MonsterGuideTag` | 浏览器端要额外拉两张源表并复制 join 逻辑，与「转换期算好、前端只读字段」的现有分工相悖 |
| 用 `ChallengeBossMazeExtra` 的 `phases` 做场次↔机制映射 | 该表的第二项在下半场为影将军时登记的是蚀心兽 `2033022`（指南别名），按序号取值会把「战斗敌方」换成「指南敌方」；按模板 + 技能反查才是稳定判据 |
| 逐层下发 `boss_traits`（4 层 × 2 场次） | 各难度 `TagList` 逐字相同，逐层复制只是把同一份文本写 8 遍（约 4KB/赛季），且会让读者以为「这层专属」 |
| 只做分场增益、不做首领特性 | 用户明确指出的缺口；对照站可见的机制条目（坚防守备等）正是玩家判断打法所依赖的信息 |
| 沿用「关卡效果」作区块名（对照站与用户原话用词） | 游戏内「关卡效果」实指每期「末法余烬」，两义共存会让同一页出现两个「关卡效果」；用户裁决采用官方术语「首领特性」 |
| 顺带把楼层内「可用增益」改名为「关卡效果」 | 末法余烬确为游戏内文案的「关卡效果」，但该词与 `ChallengeMazeConfig`/`ChallengeStoryMazeConfig` 的层级增益共用同一渲染位，改名会让非末日幻影楼层也宣称自己是「关卡效果」，超出本轮范围 |
