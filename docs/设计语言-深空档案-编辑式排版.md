# 设计语言：深空档案 · 编辑式排版

> 角色详情页（/character/:id）的视觉语言规范。
> 目标：**高端、有品味、无 AI 味**。以「档案陈列馆」为隐喻，用编辑式排版与克制的材质营造质感。
> 状态：**全局化升级中**——已确认原则见 §13（语法全局统一、身份页面分层）；正文各节为角色页实现来源。

## 1. 设计哲学

**「深空档案」**：页面是一份深色背景上的角色档案——数据以规格表、编号章节、细线分隔呈现，像一份严谨的展览图录；立绘与 Spine 是展品，信息是档案，两者并列而不互相干扰。

**反「AI 味」清单**（本设计刻意回避的旧有特征）：

| 旧特征（AI 味） | 替代方案 |
|---|---|
| 每区块重复「渐变竖条 + HUD 标题」模板 | 自动编号章节标题 + 延伸线（编辑式目录） |
| 全页紫色边框卡片 + hover 浮起 | 中性细线卡片 + 仅边框/背景亮度变化 |
| 属性等权网格 | 行式规格表（末行去底线、等宽数字右对齐） |
| 霓虹 text-shadow / glow | 无 shadow 的大字标题 + 墨色分层 |
| 半透明吸顶条透出内容 | 近实底（0.97）+ blur |
| 卡片内杂乱的容器化控件 | 纯文本链接式披露控件（▶） |

## 2. 核心原则

1. **克制用色**：主色（Purple Heart 500）只出现在编号、激活态、进度条、E 徽章等关键强调；大面积结构一律中性细线（`--line-1/--line-2`）。
2. **编辑式排版**：章节编号（01-09）、编号右侧细分隔线、标题延伸线——目录式层级，编号与吸顶导航严格对齐。
3. **规格表数据**：行式数据 + 1px 中性分割线 + Orbitron 等宽数值右对齐 + `tabular-nums`；每列末行去底线（表格收束不悬空）。
4. **无浮起卡片**：hover 仅提升边框亮度与背景微亮，禁止 `translateY` 位移与扩散阴影。
5. **材质不干扰阅读**：任何背景材质（纹理/光晕）不得在文字下方形成结构噪音；材质演进见 §11。
6. **分层结构**：吸顶工具条 fixed 提升至视口级，滚动容器 left 避让侧栏，内容与吸顶条内部精确对齐。

## 3. 色彩体系

基于 `src/styles/tokens.css` 三层令牌（原始层 → 语义层 → 领域层）。

### 中性细线（语义层，随主题适配）

| 令牌 | 常规模式 | CW 主题 |
|---|---|---|
| `--line-1` | `rgba(255,255,255,0.07)` | `rgba(255,248,230,0.08)` |
| `--line-2` | `rgba(255,255,255,0.13)` | `rgba(255,248,230,0.15)` |

用于：卡片边框、规格表行线、章节延伸线、分隔线、图标边框。**禁止在页面 CSS 内联裸色值**（豁免见 ADR 0012：纯中性灰阶/黑/白三分量差 ≤4 + SVG 内联白；深底色一律走 `--blk-*` 派生，假中性不再豁免；`var()` fallback 不得含裸色值）。

### 主色使用边界（仅限）

- 章节编号、吸顶导航激活态、进度线
- 星魂 E 编号徽章、技能类型竖条（`--sk-accent`）
- 等级条填充、数据表激活行（7% 淡底）、属性加成数值
- 焦点环（`outline: 2px solid var(--primary)`）

### 强化金（领域色豁免）

强化角标（✦）、强化摘要关键词：**领域色豁免**（ADR 0011 §4）——常规模式保持金色，CW 模式随领域金降阶暗铜哑光；数据语义色不参与双色约束。

## 4. 排版体系

### 章节标题（`.nk-title`，CSS counter 自动编号）

```
01 │ SKILLS ━━━━━━━━━━━━━━━━━━╸
```

- 编号由 `counter(nk-sec, decimal-leading-zero)` 生成，**与吸顶导航 01-09 严格同序**（导航顺序 = DOM 顺序）
- 编号与标题之间：`1px var(--line-2)` 细分隔线（目录式）
- 标题右侧：双段延伸线（实线收束 48% 后渐隐）
- 区块顺序：01 技能 → 02 附加 → 03 星魂 → 04 属性 → 05 光锥 → 06 队伍 → 07 遗器 → 08 档案 → 09 配音

### 字体层级

| 用途 | 字体 | 规格 |
|---|---|---|
| 章节编号 | Orbitron | 0.6rem / 700 / primary |
| 章节标题 | Orbitron | 0.72rem / 700 / 0.24em 字距 |
| Hero 名字 | 正文 | 2.75rem / 900（桌面），1.75rem（移动） |
| 属性标签 | 正文 | 0.72rem / text3 / 0.05em |
| 属性数值 | Orbitron | 0.85rem / 700 / tabular-nums / 右对齐 |
| 技能描述 | 正文 | 0.8125rem / 1.85 行高 |
| HUD 辅助标签 | Orbitron | 0.45–0.6875rem / 0.05–0.3em 字距 |

### 数据表格（技能参数表）

- 表头：`0.1em` 字距、text3、中性细线下线
- 首列等级：弱化为表头同级（text3），激活行时提亮主色
- 激活行：主色 7% 淡底 + 主色数值
- 全表 `tabular-nums`；展开后允许横向滚动

## 5. Hero 档案陈列

### 结构（桌面 ≥1024px）

```
┌─────────────────────────────────────────────┐
│ 视觉区 44%（540px 高）   │  档案面板 56%（透明）     │
│  立绘 + Spine 双通道      │  ① meta 行：阵营 + 星级    │
│  └ ARCHIVE · № 1001      │  ② 名字（2.75rem/900）    │
│  └ 动画开关（右上）        │  ③ 横排徽章：元素/命途     │
│                           │  ④ 一句话介绍            │
│                           │  ⑤ 属性规格表（2 列 8 行） │
│                           │  ⑥ 等级条（3px 细轨道）    │
└─────────────────────────────────────────────┘
```

### 关键规范

- **档案角标**：`ARCHIVE · № {id}`，Orbitron 0.5rem / 0.3em 字距 / 半透明白，左下角，深底 + 细线 + blur
- **meta 行**：阵营（前缀短线）+ 星级（金色）同排，位于名字上方；名字无 text-shadow（去霓虹）
- **横排徽章**：元素/命途为方形细线徽章（图标 + 文字），取代原竖排标签
- **视觉区过渡**：左缘 10% 渐入页面底色（防贴边）；右缘 18% 宽幅渐入 + `inset -150px` 暗化层（立绘融底，消除色块拼接）
- **面板材质**：完全透明（内容直接落在页面底色）；材质演进见 §11
- **规格表**：2 列、行高 ~36px、`:nth-child(4n)` 去底线、行 hover 微亮

## 6. 组件规范

### 卡片体系（统一基底）

```css
.nk-skill / .nk-eidolon / .nk-ability / .nk-story
.nk-build__team / .nk-build__set / .nk-relic-slot / .nk-relic-sub
```

- 背景 `rgba(255,255,255,0.016)`（微亮而非紫卡）、边框 `1px var(--line-1)`、圆角 10px
- hover：边框 `--line-2` + 背景 `0.03`，**无位移无阴影**

### 星魂 E 编号徽章

- Orbitron 1.5rem / 700 / primary，右侧 `1px --line-2` 分隔线，min-width 56px
- 常态 opacity 0.85，卡片 hover 时提亮至 1（区块签名响应）

### 技能类型标识

- `3 × 16px` 竖条（`--sk-accent` 类型色 + 顶部 1px 白色内高光），与 E 编号分隔线同语言
- 类型色仅存在于竖条与类型徽章，卡片整体保持中性

### 属性加成（数据表格）

- 1px 网格线表格：容器 `gap: 1px; background: var(--line-1)`，单元格深底
- 行内布局：图标 → 名称（flex:1）→ 数值（右对齐），`order` 控制
- 数值金色高亮（diff 语义色）保留于 `--gold-300` 体系

### 配队（TEAMS 独立区块）

- 独立 `data-panel="teams"`，位于光锥区块之后（v-if 有数据才渲染）
- 头像：52px 圆形，主位主色 ring；hover 无缩放（克制）；点击跳转角色页，键盘焦点环

### 骨架屏

- 属性占位为**行式**（20px 条，2 列），与规格表形态一致

## 7. 交互规范

### 克制 hover（完整清单）

| 元素 | 反馈 |
|---|---|
| 卡片 | 边框提亮 + 背景微亮 |
| 技能图标 | 上浮 1px（卡片 hover 时，无位移卡片本身） |
| 星魂 E 编号 | opacity 0.85 → 1 |
| 故事箭头 | 提亮；展开时转 45° + 主色 |
| 返回顶部 | 箭头微升 1.5px + 主色边框 |
| 规格表行 | 背景微亮 |

### 披露控件（纯文本链接式，去容器化）

`▶ 技能预览` / `▶ 技能数据表` / `▶ 强化关联`：

- 无背景/边框/圆角，0.625rem / 500 字重，`▶` 旋转 90° 表示展开
- 展开动画：`grid-template-rows: 0fr → 1fr`（0.3s）
- 触控热区 `::after` 扩展至 ≥44px

### 无障碍

- `prefers-reduced-motion`：禁用全部位移/过渡（卡片、图标、箭头、进度线）
- `hover: none`：重置粘滞 hover，触屏无幽灵态
- 交互元素 `focus-visible`：2px 主色焦点环
- `::selection`：主色 32% 底 + 亮白字

## 8. 结构规范

### 分层布局（角色页专用）

```
┌──────────────────────────────────────┐
│ 吸顶工具条（fixed，全屏横贯）             │ ← 视口级，不随内容滚动
│  └ 区块导航（01-09）+ 阅读进度线          │    背景 rgba(9,9,22,0.97) 近实底
├──────────────┬───────────────────────┤
│ 左侧导航条     │ 滚动容器（left 避让）       │ ← 平板 72px / 桌面 88px
│ (fixed 浮层)  │  padding-top: 45px 占位   │
└──────────────┴───────────────────────┘
```

- 吸顶条：`position: fixed; left: 0; right: 0`；内容区 `padding-left` 72/88 后居中 1000px，**与滚动容器内容精确对齐**
- 近实底背景（0.97）+ blur：滚动时立绘亮色不透出（避免「长条断裂感」）
- 进度线：三段渐变（55% 透明主色 → 主色 → 亮紫），2px

### 宽度体系

| 层级 | 宽度 | 应用 |
|---|---|---|
| 展示层 L1 | 1000px（`--nk-detail-wide-max`） | Hero、内容面板 |
| 阅读层 L3 | 800px（`--nk-prose-max`） | 技能/星魂/附加/属性/档案文本卡片，`margin: 0 auto` |

### 三端断点

- 移动 <768：吸顶条全宽无避让，Hero 纵向堆叠（视觉区 16:9）
- 平板 768–1023：容器 left 72，Hero 视觉区 21:9
- 桌面 ≥1024：容器 left 88，Hero 左右结构（44%/56%，min-height 540px）

## 9. 强化模式（官方模式）

> 对应 ADR：官方模式，无 diff 对比（取代早期「旧值红删除线 + 新值绿」的 diff 体系）。

- **模块位置**：吸顶条只保留导航 + 进度线；强化模式切换（原始/强化 Vn）+ 摘要横幅下沉为独立模块，位于 SKILLS 区块上方
- **强化角标**：被强化卡片右上角 `✦ 强化`（gold-300 淡底 + 描边），技能与星魂共用
- **强化关联**：折叠式披露控件，展开后按星魂（E）/行迹（树）分组列出条目（名称 + 描述），条目名分别以主色/类型色标识
- **摘要横幅**：强化内容列表，`<color>` 强调词以 gold-300 渲染

## 13. 全局化升级 · 原则确认清单

> 升级方针：**语法全局统一，身份页面分层**——全局共享「材料、砌法、验收标准」，页面保留各自隐喻。以下为已确认原则（逐条裁决，可追溯）。

### 13.1 语言定位原则（✅ 已确认）

- 「深空档案」不定义页面长什么样，定义页面「怎么做材料」：质感语法全局共享，身份表达页面自治
- 判定口诀：**别处也会用到 → 全局语法；只有这里需要 → 页面身份；随模式变化 → 主题参数**
- 不违背两期演进战略：全局化是 Gaming HUD 精修方向，非换语言

### 13.2 双主题适配原则（✅ 已确认）

- **「主色 = 唯一强调位」恒等式跨主题成立**：主色是语义位而非具体颜色，色相随主题映射（常规 `--ph-500` / CW `--gold-500`）
- **主题金与语义金永不重叠**：CW 落地任务 = 金阶拆族 + 明度翻转（主题金 = 最亮金且唯一发光；语义金 = 暗铜阶哑光）
- `--line-1/--line-2` 与领域色不随主题（语法与主题正交）

### 13.3 编号系统原则（✅ 已确认）

- **编号 = 身份，不是计数**：章节编号固定（01-09），数据缺失保留编号缺口，不随数据漂移
- **单一事实源**：`sectionDefs` 配置表统一管理编号，废除 CSS counter 自动递增（双源是错位根因）
- 缺数据区块：标题与导航同步隐藏缺口；强化模块「00」须显式声明（金色，不参与章节序列）
- 编号分级：章节级（主色 / 身份锚点）vs 条目级（灰色弱化）

### 13.4 色彩边界原则（✅ 已确认）

- **清单分层**：主色强调位（主题层）与领域语义色（领域层）分开声明；技能类型竖条 `--sk-accent` 属领域层
- **主色边界补全**：披露控件 hover、故事展开编号、Hero 属性区段短横线、配队主位 ring、动画开关圆点、滚动条滑块（`--border2`）均为合法强调位
- **属性加成数值 = 语义金**（`--gold-300`）：数据数值与星级/强化同属数值语义族；当前实现未定义颜色，需补 `color` 定义
- **`--highlight` 并入 gold 族**：作为「文本高亮」语义位映射 gold-300 系（消除游离色 #f29e38 与跨模式不一致）
