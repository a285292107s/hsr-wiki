# 测试体系

> AGENTS.md 的按主题子文件（主文件「任务 → 必读」路由表经相对链接引用，按需读取）。本文件是**测试三件套与 e2e 分层归属的唯一事实源**。验证级别、预算与执行纪律见主文件「验证流程」节与 [verification.md](verification.md)；测试命令与像素基线刷新方式见 [commands.md](commands.md)。

- **全语言冒烟 `e2e/layout-locales-smoke.spec.ts`**：两级覆盖——① 13 语言 ×「首页 + 一个角色详情」，断言**正文与 `<title>` 都无未解析 `$t:` 令牌**、`<html lang>` 等于该语言 culture、首页 `<meta name="description">` 等于该语言词典值（站点描述随语言的回归锁）、首页无非中日韩中文残留（原本给 `kr` 留的「括号内汉字」豁免实测**不需要**——kr 的汉字只出现在角色详情的配音演员专名里，首页为零 ⇒ 已收紧为 10 个非中日韩语言一律零汉字）、无未捕获 JS 异常；并对**货币战争角色页的属性行**单独断言「非缺省语言下不得露中文、也不得露原始枚举键」——结构层的属性名表里 `SpeedAddedRatio` / `MaxSP` 两条官方无独立词条、按设计落中文回退，该断言证明这些回退是惰性的；② 标记风险最高的四种语言（cn/de/jp/ru）× **全部路由族**（25 条路径）。此外①全程收集 **vue-i18n 缺键告警**（`[intlify] Not found …`）并要求为空；②**按语言测溢出**：首页/详情用元素级 `expectNoUnknownOverflow`（字体就绪后测），全路由用整页级 `scrollWidth − clientWidth ≤ 1`——译文长度差异最大的一档（德语/俄语比中文长约三成）最容易撑破容器，而既有溢出断言只在缺省语言上跑过。**别把元素级断言用到有横向滚动容器的页面**：`.nk-guide-link`（列头链，`white-space:nowrap`）在 1280 视口下 `right=1422`、整页却不溢出，属检测口径问题；`KNOWN_OVERFLOWS` 按纪律不得为「修绿」堆条目——模板拼接的键（`t('itemType.' + v)`）静态守卫看不到，缺键时界面会显示原始键名。本轮它先后抓到德语页 vue-i18n 编译异常与四类缺键，是目前投入产出比最高的一条 e2e。

## 前端单元（Vitest + happy-dom）

- 配置：`vitest.config.ts`（独立于 `vite.config.ts`），`include: src/**/__tests__/**/*.test.ts`
- 范围：纯逻辑——数据层（缓存、API 契约、CDN 解析与健康探测）、`lib/` 与 `spine/` 纯函数、组合式函数、路由注册表、调试台引擎；**不挂载组件**（项目无组件测试运行器，禁止为此引入依赖）
- **环境归属**：不依赖 DOM 的单测文件第一行加 `// @vitest-environment node`（happy-dom 环境启动实测约 0.3s/文件，node 下 environment 0ms）。判定依据：被测生产模块或测试本体是否触碰 `document` / `window` / `localStorage` / `HTMLElement` / `FileReader` / `MutationObserver`；拿不准就加 pragma 实测该文件，跑红即还原并保留 happy-dom
- 跨刷新持久化由 HTTP 缓存承担，无 IndexedDB 持久层

## 前端 e2e（Playwright / 布局验收层）

- 配置：`playwright.config.ts`；`webServer` 起 `pnpm dev` 并复用已有 6188 实例（非 CI）。**三个 project，firefox 排在数组最前**（Playwright 按项目顺序分派文件；最长单元若排在末尾，会被留成单 worker 尾巴——2026-10 实测正是这条让 168s 墙钟只有一个 worker 在跑）：`firefox-layout-contract`（Firefox）只收集 `@cross-engine`——判定可能随引擎差异变化的用例（滚动驱动动画 / mask-image 渐变 / 焦点环 / 极端视口溢出），Firefox 不支持滚动驱动动画，跨引擎契约靠它锁；`chromium`（全部 spec）；`mobile-chromium`（Pixel 7）仅跑 layout（溢出 / 结构 / console 守卫），`testIgnore` 排除 visual 与 accessibility，`grepInvert` 排除**自行 `setViewportSize` 固定视口**的 `@viewport-pinned` 用例（其视口已由用例钉死，重复执行同一断言）与断言与断点无关（数据 / 结构 / 网络来源）的 `@viewport-independent` 用例——手机档只补「非固定视口下的手机断点面」。**三个标签都必须静态写在 `test(...)` 第二参**，动态 annotation 对收集期过滤无效（标签纪律见任一 `e2e/layout-*.spec.ts` 头部）。覆盖面收窄的裁决与未覆盖范围（WebKit 未入 CI）见[验收标准](../audit/角色详情页验收标准.md) B3
- **`@viewport-pinned` 的两种合法用法**：① 用例自钉视口（体内 `page.setViewportSize`）；② 断言只在项目默认（桌面）视口下成立。两者对 `mobile-chromium` 的效果相同（不收集），但**用法 ① 漏标是有代价的**：mobile 会用 Pixel 7（`isMobile` + 触摸仿真）重跑一条本已钉死桌面视口的契约，实测在 CI 上把用例拖成 **30s 超时 × 3 次重试**（e2e job 直接红）。**标签必须与 `mobile-chromium` 的 `grepInvert` 成对存在**——只删后者时收集量从 425 涨到 611、5 条桌面契约确定性翻红（实测连红两个 schedule run，而 push 档不跑 layout 故一直全绿）。两条都由 `node tools/check-e2e-viewport-tags.mjs --strict` 机检（**已进 CI `static` job**，纯文本扫描）；唯一豁免是 `e2e/layout-debug.spec.ts` 的手机档哨兵（行内 `// e2e-viewport-ok: 理由`——它的 `isMobile` 就是被测对象）。
- **取值前的就绪门统一走 `e2e/helpers.ts → waitForSettled`（字体 + **视图挂载** + 骨架退场 + 两帧）**：三件事各自会「假真」——`document.fonts.status` 在入口 CSS 未应用时即为 `'loaded'`；`!document.querySelector('.nk-skeleton')` 在**懒加载路由 chunk 执行前**为空真（此时 `#app` 只有外壳 `nav.ui-sidebar` + `div.nk-toast-container`、正文约 165 字符，挂载后正文数千字符）。故挂载判据是「`#app` 出现非外壳子节点」（`SHELL_OWNED` 清单随外壳组件增删同步，漏同步即退化成空真）。所有等待都设上限且**不抛错**：等待不负责报缺陷，页面缺陷由用例自己的断言暴露。**就绪门不替代「等被测对象」**——紧跟就绪门读取具体内容（某链接 / 某计数）的用例仍应先 `await expect(locator).toBeVisible()`。
- **判「滚动中的位置」不要用 `boundingBox()`**：该 API 会等元素「稳定」，平滑滚动期间可能长时间不返回，把用例拖成超时且超时信息里看不到断言值；改用 `locator.evaluate((el) => el.getBoundingClientRect().y)`——轮询值不该有稳定性前置条件。
- **新增 project 必须同步 `.github/workflows/ci.yml` 的 `playwright install` 浏览器清单**（当前 `chromium firefox`；`mobile-chromium` 复用 chromium 二进制）：CI 只装清单内的浏览器，漏登记时该 project 的全部用例以 `browserType.launch: Executable doesn't exist` 告负——而本机浏览器齐全故恒绿，**该缺口只有 CI 能显形**（不装浏览器的项目 = 零覆盖，但仍占 `test:e2e:ci` 的用例数）
- **`@font-calibrated` = 判定依赖平台字体度量的断言，CI 层不收集**（当前 2 条：`layout-character-hero-motion.spec.ts` 的桌面 / 平板「骨架↔就绪同框」）：它们比「骨架盒高 == 就绪面板内容高」，而就绪内容高 = 若干 `line-height: normal` 行盒之和，比例随**实际解析到的回退字体**变——Linux runner 的 Firefox 实测内容高 242.82 / 平板 264.5，比标定源（Windows 239.813 / 262.453）高 3.0 / 2.0px，故在 CI 恒差。`playwright.config.ts` 三个 project 都按 `process.env.CI` 收起该标签（本机 `pnpm test:e2e` 全量仍判；CI 报告里显示为未收集而非失败）。**这是有意的覆盖率收窄**，理由与「像素基线移出 CI」同一条（判定依赖环境，见 `ci.yml` 注释）——**新增判定依赖字体度量的断言必须打此标签**，否则 CI 会在 Linux runner 上翻红；反之，**禁止**为了把它留在 CI 而把面板几何抬到跨平台上界（那是拿全局视觉位移换一条 3px 级加载瑕疵的消音，实测记录见 docs/memory/2026-10.md）。
- **全语言长文案排版 `e2e/layout-i18n-overflow.spec.ts`**：ADR 0052 落地后，译文长度差异（德语/俄语比中文长约三成、泰语无词间空格）让原先按中文长度调好的容器成片失效，而**既有溢出断言只在缺省语言上跑**，且只查「元素越出视口」——查不到「文本被容器吃掉」（`overflow: hidden` 不产生布局越界）。本文件补这一层，三类判据：① **硬裁切 / 外溢**（`overflow != visible` 且 `scrollWidth > clientWidth` 且无 ellipsis；`nowrap` + `overflow: visible` 的横向外溢；纵向硬裁切）；② **导航骨架不得被省略**（侧栏/底栏/区块导航/页签——被截的导航等于失效导航，见 `UI质量验收标准.md` 处置分级 P3）；③ **截断必须有复原手段**（被截断的叶子须在自身或 5 层祖先上找到含该文本的 `title` / `aria-label`；触屏没有 hover，否则那段字永久读不到——判据与 `layout-catalog.spec.ts` 同源，本文件把它扩到长文案语言与迭代全范围）。取值域为迭代范围（`UI质量验收标准.md` §6）的 10 个目录/枢纽族 + 5 个详情族（id 从结构层派生），风险语言 `cn/de/ru/th/vi`（`I18N_OVERFLOW_ALL=1` 扫全部 13 种），视口含桌面、390 与 **320 最窄档**（320 那条只跑详情族：该档残留的根因——窄容器里不收缩的短标签、索引条项内 `nowrap`——恰好只出现在详情族，且**按语言分化**：cn 恒 0 而 fr/ru 最重，故必须逐语言跑）。**就绪门是本文件的要件**：骨架退场不等于内容到位（目录卡在数据取回后才渲染），只等骨架会把「卡片还没渲染」记成「零缺陷」——实测因此漏掉过整批卡名截断，故轮询正文长度到连续两轮不变再取样。
- 用例：`e2e/guards.spec.ts`（不变量，见下「三层归属」）/ `e2e/shell.spec.ts`（**应用外壳契约**：字体链路走同源入口 CSS 的 `@font-face`（`src/styles/fonts.css` + `/fonts/*.woff2`），**不得退回跨域 Google Fonts** 且 CSS 内禁止 `@import`；`color-scheme: dark` 已声明；输入框 `caret-color` 随 `--primary`）/ `e2e/layout-*.spec.ts` 分域文件——按页面族各一（`home` / `nav` / `hub` / `footer` / `debug` / `currency` / `voracity` / `lightcone` / `monster` / `catalog` / `i18n`）+ 终局按「目录页 / boss 层级看板 / maze·story·peak 层级看板 / 敌方卡溢出 / 玩法常青页 / 赛季详情页」拆成六个 + 角色详情页按域拆成 `layout-character-{hero,hero-motion,panel,skill-family,skill-data,lightcone,nav}` 七个；`accessibility.spec.ts`（axe-core WCAG 扫描）/ `visual.spec.ts`（像素基线）；公共工具在 `e2e/helpers.ts`，跨文件共用的取值原语与数据派生在 `e2e/layout.shared.ts` / `i18n-overflow.shared.ts` / `locales-smoke.shared.ts`（只放取值与派生，不放 `test()`/`expect()`）。**具体文件名不在此逐一登记**（会随拆分漂移），以 `ls e2e/layout-*.spec.ts` 为准
- **layout 必须按 `describe` 边界分文件**：`fullyParallel: false` 只禁**文件内**并行，文件级并行始终生效——单文件 layout 曾把 74 用例 / 469s 串成一个调度单元，全量墙钟锁死 6.6 分钟。**这条纪律会随用例增长复发**：全量 180 用例 / 361.6s 时 `layout-character.spec.ts` 又长回 39 用例单文件，且 firefox 项目只跑它、它又排在项目末尾 ⇒ 末段 168s（占墙钟 46%）只有 1 个 worker 在跑。故再按域拆成七个 `layout-character-*.spec.ts`，并把 firefox 提到项目最前。同一条纪律**反复复发**：`layout-endgame.spec.ts` 长回 24 用例后拆成三个按玩法分文件；后又长回 22 用例 / 251s（占 layout 层三分之一），再按目录页 / 层级看板拆；`layout-endgame-board.spec.ts` 又长回 16 条 / 183s（layout 层最慢单元），再按 boss / maze·story·peak 拆成两个。**判据**：文件级并行是唯一被采纳的提速手段（提高并发度换 flake 已被否决，见 [commands.md](commands.md)）；新增 layout 用例归入对应域文件，**单文件超过约 15 条、或成为该层最慢调度单元时就该再拆**——文件级调度单元的时长就是墙钟下界。
- **分层**：CI 层 = `pnpm test:e2e:ci`（**guards + shell + accessibility + layout**，零外部依赖、环境无关）= `ci.yml` 的慢档 job 集，不再每次 push 跑（触发条件见下方「门禁分层」）；像素基线回本机（判定依赖环境——CI IP 对 jsDelivr burst 限流 + Linux/Windows 渲染差异，见 `ci.yml` 注释），**禁止把 `visual.spec` 加回 CI**
- **门禁分层（2026-10 起）：push 档与慢档**。`ci.yml` 的 job 分两档，慢档四个 job 各自在 `if:` 里声明同一触发条件（`schedule` / `pull_request` / `workflow_dispatch`）——**条件必需写在各 job 上**：顶层 `env` 里塞 `${{ github.event_name … }}` 会让整个 workflow 在 GitHub 侧解析失败（run 0 秒结束、`jobs=0`、无任何 annotation，本地 YAML 解析却正常），排查时直接看「run 是否创建了 job」。
  - **push 档（每次 push，约 70s）**：`static`（七守卫 + e2e 视口标签/收集过滤 + `vue-tsc -b`）/ `unit-tests`（Vitest）。准入即「失败不可逆 + 信号稳定 + 可定位」（站点白屏 / 数据错 / 类型错 / 色彩与对比度不合规 / 桌面契约被移动仿真重跑）。视口标签检查是**唯一进 push 档的 e2e 相关检查**，理由：它是纯文本扫描，且它判的失效（标签或 `grepInvert` 少一半）只能在夜间 layout 显形——push 档不跑 layout 时无人能发现。判据与动机见 [memory](../memory/testing.md#门禁复杂度与迭代节奏门禁该守什么不该守什么)。
  - **慢档（`schedule` 每日 18:00 UTC + 手动 + PR）**：`invariants`（guards + shell + a11y，2 分片）/ `layout`（6 分片 × 2 worker，只装 chromium + mobile-chromium）/ `firefox`（11 条 `@cross-engine`）/ `smoke`（8 个重文件，4 分片）。**慢档不是删除**：用例一条不减，发布前用 `workflow_dispatch`（`e2e_scope=full`）随时取全量结果；手动只跑不变量层用 `e2e_scope=invariants`。
  - **push 档变更的准入**：新增检查要进 push 档，必须说明「漏掉它的不可逆损失是什么」；答不上来的一律进慢档。**禁止**把布局契约类断言（跟"和上一版长得一样"有关）加回 push 档——它们保护的是稳定，而重构期的目标是变化。
  - 墙钟靠**分片（机器维度）**换，`workers` 恒为 2——提高单机并发度换 flake 已被否决（见 [commands.md](commands.md)）。job 级 `timeout-minutes` 兜底，`retries` 为 0（重试会把真红转绿，仓库纪律禁止）。**firefox 独立成 job 的判据不是「用例多」而是「装了没人用」**：`@cross-engine` 共 11 条，`--shard` 按组均分后全落在第 1 片，而那时 6 个分片**每个都要装 firefox**（~100MB + 解压）才轮得到它——5 台 runner 白装。拆成独立 job 后 layout 六片只装 chromium，firefox 只装一台。同类判断：**浏览器清单是 per-job 的安装成本**，一个 project 的用例若只落在少数分片里，就该单独成 job 而不是留在共享矩阵里。
- **片数由「最慢文件」定，不由条数定**：`--shard` 的切分单位是「**文件 × project** 组」，不是文件里的用例——同一文件的多条用例永远落在同一片。所以：① 调片数前先取「每文件实测耗时」（`--reporter=json` 后按 `file` 聚合），按 `片数 × 单机可用时长 ≥ 最慢文件时长` 定下界；**一个巨型文件就是墙钟下界**，片数给到再高也只能让它独占一台 runner。② **片数不得超过「文件 × project」组数**——超过的部分空跑（实测 smoke job 只有 2 个文件、分 2 片，结果 15 条全挤进第 1 片、第 2 片 0 条）。要让一个 job 真正并行，唯一手段是**继续拆文件**。
- **冒烟族独立成 job**：`layout-locales-*` / `layout-i18n-overflow*` / `layout-endgame-overflow*` 各自是单文件串行（`fullyParallel: false`），留在 layout 分片里会把某一片拖成两倍墙钟。分片 job 用 glob 排除这组文件（`e2e/layout-*.spec.ts | grep -v`），新增 layout 文件自动纳入；**排除模式必须与 smoke job 的文件清单同源**——smoke 新增文件而这里没加排除时，该文件会同时被两个 job 跑到
- **「一个文件一条 gross 用例」等于把 N 份工作焊死在一片上，连拆文件都救不了均摊**：`layout-endgame-overflow*` 原为「一条用例循环 4 语言」，两个文件各 61s ⇒ 无论怎么分片，这两块都只能整块落某一片（实测两片撞一起时该片 125s、其余 5~49s）。改成一语言一条后同批 8 条各约 15s，4 片变成 66/67/53/46s。判据：**拆文件解决「调度单元太大」，拆用例解决「均摊粒度太粗」，两者不可互相替代**——先看该文件是「多条」还是「一条循环多值」。
- **`@font-calibrated` 用例在本机会红，那不是缺陷**：它们比「骨架盒高 == 就绪面板内容高」，而内容高 = 若干 `line-height: normal` 行盒之和，比例随解析到的回退字体变。本机（Windows）与 Linux runner 都会在**某些**字体状态下差 2~3px，故 CI 按 `process.env.CI` 收起、本机全量仍判。看到 `layout-character-hero-motion` 的「平板档：文字与媒体并排且骨架同框」变红时，**先确认它是否带该标签**再判红——`--list` 在 `CI=1` 下条数会少 2。
- **`--list` 三种命令形态的收集结果都不同，核对覆盖率必须选对那一种**：单 `--list` 是**跨 project 的并集**（同一 `test()` 在 chromium 与 mobile 各算一条）；`--list --project=<p>` 才反映该 project 的真实收集；而 CI 的 layout 步骤用的是**显式多 project**（`--project=chromium --project=mobile-chromium`），它的收集集既不是并集也不是单 project——用单 `--project` 的条数去估分片会把用例算到错片，用不带 `--project` 的并集去核对则会得出「收集正常」的假结论。核对 CI 覆盖率一律复刻 CI 的命令形态（`CI=1` + 两个显式 project + 同一 `--shard`）。
- **全语言矩阵的覆盖收窄（登记在案）**：每次 push 的 `smoke` job 只跑**风险语言子集**（`SMOKE_SCOPE=fast` = cn/de/jp/ru，判据同 `SMOKE_FAST`；长文案 job 跑的是 `RISK_LOCALES` 的 cn/de/ru/th/vi，两套子集不同）；13 语言的冒烟与**三档长文案（桌面 1280 / 手机 390 / 最窄 320）**全量由 `.github/workflows/ci-full.yml` **周跑**（`schedule` + 手动 `workflow_dispatch`）承担，分片分母必须等于矩阵长度。**收窄不等于失覆盖**：全量矩阵每周仍跑一次；判 `$t:` 令牌与缺键的更强覆盖仍在构建期（i18n 守卫 + 1432 份预渲染快照 × 11 项断言）
- **`invariants` 层此前不在 CI 里**（2026-10 修复）：`pnpm test:e2e:ci` 旧形态为 `playwright test e2e/layout- e2e/accessibility.spec.ts`——那个**路径前缀过滤**把 `guards.spec.ts` 与 `shell.spec.ts` 静默排除了（0 次执行），实测 `shell.spec.ts` 因此带着一条过期断言在 main 上红了两天。新增这一层时必须确认「选中的文件集」而不是「看起来在跑」
- **用例粒度也是墙钟参数：一条 gross 用例循环 N 个语言，等于把 N 份工作钉死在同一条里**。`--shard` 均分的是**条数**，所以「一语言一条」的形态才可被摊开——拆前 `layout-i18n-overflow.spec.ts` 是一条循环 5 语言的用例（68.5s 起），拆后每条 ≤ 20s，同一批断言从「一片独占」变成「四片摊开」。判据：新增跨语言 / 跨视口的扫描用例时**写成参数化生成的多条 `test()`**，不要写成一条里套 `for`。反例：文件级拆分的收益到此为止——`fullyParallel: false` 下再拆文件也不会让**同一文件内**的多条并行。
- 基线：截图提交 git（`e2e/snapshots/`），本机刷新用 `pnpm test:e2e:update`（详细约束见 [commands.md](commands.md)）
- 断言能力已固化「验证流程」各级别：`toHaveCSS` / `toHaveText` / `toHaveCount`（T1b/T2）、横向溢出检测 `findHorizontalOverflow`（L3）、`toHaveScreenshot`（L4）、axe-core（a11y）、`pageerror` 硬断言（`console` error 仅收集记录：CDN 等环境性失败不硬断言，由截图 / aria 基线兜底；`ResizeObserver loop` 噪声已在收集侧过滤）
- a11y 既有缺陷登记在 `accessibility.spec.ts` 的 `KNOWN_VIOLATIONS`（命中降级 warning，新增违规仍失败；登记带超期复查提示）——修复后须人工裁决并从清单移除。**登记前必须先实测**：只有 axe impact 为 `serious`/`critical` 的违规才进入断言路径，`moderate` 级登记进去等于永不生效的白名单（曾有一条此类死条目，已删）。扫描集 = `WCAG_TAGS`（2.2 A/AA）**+ 显式开启 `target-size`**——它挂在 `wcag22aa` 标签下却 `enabled: false`，只写 `withTags` 时 2.5.8 从不执行（「声称 2.2 AA 目标尺寸」的声明曾因此长期未验证，见 [memory](../memory/ui-tokens.md)（可达名与扫描面））。
- 枢纽页：`/` 与 `/currency` 为静态品牌带 + 板块索引（无 WebGL / 视频帧），像素基线直接稳定——旧的双枢纽 Hero 媒体层隐藏块已随 [ADR 0018](../adr/0018-枢纽页改为工具化入口页.md) 删除（那些元素已不存在，保留会让 `evaluate` 直接失败）。`/` 首屏入口行数由 `e2e/layout-home.spec.ts` 的可执行断言锁定

### e2e 断言三层归属（不变量 / 契约 / 规格；与上方 CI / 本机归属正交）

| 层 | 职责 | 更新时机 | 落点与机检 |
|---|---|---|---|
| **guards 不变量层** | 页面可达、无未捕获 JS 异常、无未知横向溢出 | **永不**因展示改动（数值 / 块序 / 形态 / 文案）而改；新增页面才补条目 | `e2e/guards.spec.ts` → `pnpm test:e2e:guards`（= guards + shell + a11y，CI 的 `invariants` job，永远可跑） |
| **contracts 语义契约层** | 语义与跨会话契约：数据驱动的真值、跨模块共享的避让 / 断点 / 尺寸下限 | 契约本身变更时改（即 ADR 或子文件登记过的口径变化） | 与规格层同由 `e2e/layout-*.spec.ts` 承载，按域分文件（`home` / `nav` / `hub` / `footer` / `debug` / `endgame` / `currency` / `character` / `voracity`），每个文件内仍按 `describe` 分组 |
| **specs 数值规格层** | 尺寸 / 间距 / 字号 / 圆角等展示取值 | 随展示迭代改 | 同上；裸 px 由字面量工具扫描（命令与退出码见 [commands.md](commands.md)） |

- **数值断言硬规则（specs 层，可机检）**：禁止裸 px 断言——数值断言必须**令牌派生**（`e2e/helpers.ts → readToken`）或**相对序**（如 `scale.card > scale.groupTitle > scale.label`）；内容真值（首领名 / 污染等级 / 目标分数 / 节点数等）优先从 `public/data/cn/` 的产物 JSON 派生，不在断言里写死页面文案（**派生一律走 `e2e/helpers.ts → readJson`**：结构层里的文本是引用令牌，该函数按缺省语言解析后再交给断言；裸 `readFileSync + JSON.parse` 只允许用在 `page.route` 把文件喂给浏览器的场合——那时必须保留原始令牌，由页面自己解析）。真正不可漂移的契约值（令牌单点声明值、`0px` 直角 / `1px` 发丝线的**语义即值**类）允许保留字面量，二选一收口：行内标 `// e2e-literal-ok: 理由`，或由基线计数兜底（`tools/e2e-literal-baseline.json`）。**只有两类内容无法从数据派生、允许写死并须注明理由**：站点自创文案（如 H1「贪饕污染」、区块标题「首领特性」）与 UI 格式拼装（`第 N 层` / `污染等级 N` / `NO.<id>`）。扫描器只统计**断言调用里的** px——注释 / 用例标题 / 视口声明不进计数，避免守卫对着注释报警再逼人改注释。
- **改动路由**：展示迭代只需跑 guards 层 + 受影响用例（`pnpm test:e2e:affected`）；**禁止**为过测修改 guards 层——它变红即不变量被破坏，是代码问题而非断言问题。`pnpm test:e2e:ci` 覆盖 guards + shell + a11y + layout（**减去 `@font-calibrated` 那 2 条**——该收窄是登记在案的例外），它对应 CI 的**慢档**整体，而不是单条 push job：push 只跑 `static` + `unit-tests`，布局契约与不变量层在 `schedule` / 手动 / PR 档跑；**发布前必须手动跑一次全量**（`workflow_dispatch`）。**覆盖率不得下降的约束作用于慢档，不作用于推送频率**——把一条慢档 job 降频率不等于收窄覆盖；反过来，把慢档用例删掉或标 skip 才算收窄。
