# 角色强化展示范式：官方模式 + diff 链路下线

## Status: accepted

## Context

3.4「砺烁新辉」角色强化系统的数据源确认存在（`AvatarConfigEnhanced` 注册 10 角色，`AvatarSkillConfig`/`AvatarRankConfig` 含 1100xxx 加强版完整数据，`AvatarEnhancedSkill/Rank/SkillTree` 提供前后描述，`AvatarEnhancedHintConfig` 提供强化摘要），converter 尚未接入（`enhanced` 硬编码为 null）。前端原预留的方案是"原始/强化切换 + 旧视图 diff 红绿对比"（`oldD`/`isDiffMode`/CHANGED 徽章/词级 diff），但项目迁移重构后页面已改为墨色分层 HUD 风格，红绿 diff 是旧设计的视觉遗产，不再适合。

## Decision

常规模式角色详情页采用**官方游戏内模式**展示强化数据：

1. **切换 + 纯数据替换**：保留吸顶工具条"原始 / 强化 V1"切换，**默认显示强化**（与游戏内默认开启一致）。强化模式下技能、行迹、星魂、`sp_need` 全部替换为加强版数据，**不渲染任何 diff 对比**——切回"原始"即见旧数据，对比价值由切换本身天然覆盖。
2. **强化摘要横幅**：`EnhancedDesc1-3` 渲染为"强化内容"横幅，**保留官方 `<color>` 橙色强调词**（`gameTagsToHtml` 渲染，不再 `stripAllTags`）。
3. **强化角标**：强化模式下，被强化的技能卡头部与星魂卡加金色角标（由 `AvatarConfigEnhanced.SkillList`/`RankIDList` 驱动，converter 随包输出）。
4. **范围**：仅常规模式（`/character/:id`）；货币战争模式无此数据源，不受影响。
5. **diff 全链路下线**：删除视图层 `oldD`/`oldSk`/`isDiffMode` 链路、CHANGED/NEW/REMOVED 徽章、红绿渲染、`removedSkills`/`removedEidolons`、`buildEnhancedOld`/`getRenderData.oldD`；删除 `src/lib/diff.ts`（`fmtDescDiff`/`wordDiff`/`hasParamDiff`/`hasTextDiff`/`paramEqual`）与其测试；删除 diff 专用样式与令牌软变体。`--diff-add`/`--diff-del`/`--diff-text` **保留**（`--season-live`/`--season-upcoming`/toast 错误色仍引用）。

## Considered Options

- **B. 保留 diff 对比**（原预留方案）：红绿对比 + CHANGED 徽章。被拒——与新页面视觉风格冲突；diff 价值可被"来回切换"天然覆盖；维护成本高（4 个组件 + 纯函数 + 样式 + 测试四处耦合）。
- **C. 攻略社区式平铺对比**：独立区块逐条列出"加强前 → 加强后"。被拒——与摘要横幅信息重复，且加长页面，移动端体验差。

## Consequences

- converter 的 `character_detail` 模块需接入：读取 `AvatarConfigEnhanced` 等 6 个源文件，输出 `enhanced: { skills, ranks, skill_trees, descs, sp_need, skill_ids, rank_ids }`（`skill_ids`/`rank_ids` 供角标）。
- `AvatarEnhancedSkill/Rank/SkillTree` 的 `DescBefore/DescAfter` **不输出**（切换"原始"即可见旧数据，无需双份描述）。
- 前端 `EnhancedBundle` 类型扩展 `sp_need`/`skill_ids`/`rank_ids`；`buildEnhancedView` 覆盖 `sp_need`；`renderData` 简化为仅返回强化视图。
- `fmtDesc` 简化：删除 `oldParams` 第三参数与红绿输出分支（唯一 3 参调用者 `fmtDescDiff` 已删除）。
- `docs/audit` 相关字段审计不受影响（`rated_rank_id`/`rated_skill_tree_id` 等字段语义不变，强化模式下按加强版 ID 自然匹配）。
