## 死链审计耗时优化（A+B+C，2026-08-12 晚）
- 背景：用户追问 CI 全量会不会走死链审计——确认 ci.yml（build-and-test + e2e）**不含**死链审计，只有 data-sync job 含；但 data-sync 的 convert --force 全量重写 → 旧目录指纹失效 + CI runner 无缓存 + CI IP 403 退避 → 每次全量 30-40 分钟。
- **A 内容签名复用**（核心）：缓存失效依据从目录 mtime 指纹改为 **URL 来源文件内容 sha1**。converter 输出确定性 → 全量重写但内容未变 → 签名不变 → 零网络复用；只有内容真变的模块重测对应 URL。本地实证：冷启动抽样 100（ok 99/env 1）→ 二跑零探测。
- **B CI 缓存持久化**：data-sync job 加 actions/cache（path temp/dead-links-cache.json，key run_id + restore-keys 前缀）跨 job 复用。
- **C 403 不重试**：403（数据中心 IP 拒用，2026-08-11 实证）直接判 env 不退避；仅 429/503 退避。
- 缓存老格式（fingerprint）自动判无效 → 冷启动全量一次后写新格式。抽样模式仍写缓存（支持分块推进）。
- 验证：抽样复用路径零探测 ✓；YAML OK ✓。
