# 0047. 出没样本只展示玩家可见关卡名（`StageConfig.StageName` 全面退场）

## 状态

`accepted`（**已实现**：`monster_extra.load_player_stage_names()` 新增，四类源；`load_appearances`
不再读 `StageConfig.StageName`；`public/data/cn/monsters/*.json` 全量重生成（2487 个文件变化）；
`pytest` 的 `TestPlayerStageNames` 5 例 + 详情页注记补口径；`e2e/layout-monster.spec.ts` 增两条哨
——硬编码规则的「自己名字不得作为关卡名上屏」（1003011 / 1003012）+ 数据派生的「无实名源 ⇒ 不产出 chip」，
并做负测（把 `StageName` 兜底临时加回 ⇒ 立刻红）；**决策 6 追加**「① 活动链样本名带活动名前缀」
（FightFest / Television / Summon / StarFight 有验证连接，BoxingClub / ElationActivity 无连接不加）。
**修订 [0046](0046-出没样本名改取活动表实名.md) 决策 1 / 2 / 3**）

## 1. 背景与问题

[0046](0046-出没样本名改取活动表实名.md) 只解决了「活动关卡的 `StageName` 是活动级常量」这一半：
有实名源的 6 个活动类型换成真名，无实名源且整类单值的类型不落样本，**其余类型仍用
`StageConfig.StageName`**。用户随后指出并追问：这种「以本怪名字命名」的关卡名是面向开发者的
敌方标识，对玩家只会造成困惑——要求全站盘点并找更好的展示数据。

盘点结论（目录 632 条，用一次性探针脚本核对，**脚本未入库**）：

- 544 条有 `appearances`（88 条无记录），其中 **440 条有样本**、104 条只有计数，样本共 **742** 个；
- **181 个样本（24%）的名字与该怪自己的 `name` 逐字相同**，落在 181 个页面上（118 个页面的样本
  **全部**是自己名字）。其中 **160 个与 `MonsterTemplateConfig.MonsterName` 是同一个 TextMap hash**
  （另 21 个是同文不同条目）⇒ 这些玩法的 `StageName` 字段就是**敌方标识**，不是关卡标题；
- 无玩家可见名的样本里，「别的怪名字」256 个、「阵营/风味名」71 个（`裂界造物` / `反物质军团` /
  `「完整」「错误」` 变体等）——它们同样不是玩家认得出的关卡名。

同时找到了**四类玩家可见名源**（全部要求精确 `StageID` 连接，见决策 1），合计覆盖 **501** 个样本。

## 2. 判定

`StageConfig.StageName` 在 VerseSimulation / Trial / Mainline / RogueRelic 等玩法里**不是关卡名**
（它是敌方标识，常与本怪同名；在活动类型里则是活动级常量或阵营名）。把它当作「出没关卡」展示，
要么与页面标题重复、要么显示另一个怪的名字，信息量为零或负 ⇒ **不作为样本名来源**。

## Considered Options

- **保留 [0046](0046-出没样本名改取活动表实名.md) 的「其余类型照旧用 `StageConfig.StageName`」**：放弃——盘点实测 181 个样本（24%）的名字与该怪自己的 `name` 逐字相同，其中 160 个与 `MonsterTemplateConfig.MonsterName` 同一 TextMap hash ⇒ 该字段在这些玩法里就是敌方标识。
- **用 `MappingInfo.ID == StageID // 100` 这条更全的折算**：放弃——实测 90 个 `FARM_ENTRANCE` 里只有 1 个存在 `ID*100+k` 关卡家族，且逐关核对 `ShowMonsterList` 与波次 **0 交集** ⇒ 是巧合；真外键只有 ③ 的 `MappingInfoID`。
- **把技术口径留在正文**：放弃——源表名 / 召唤链 / 随机编组是维护者语言，压到玩家面前只会劝退；移入默认收起的 `<details>`，且不用 `title` 提示（移动端没有 hover）。
- **无关卡名时留空、不写说明**：放弃——235 个页面（占 544 条的 43%）的真实边界必须显式说出，不能用沉默代替。
- **把活动名拼进 `name`**：放弃——数据层两个字段各管一件事，拼接发生在展示层，页面才有条件把活动名弱化。

## 3. 决策

1. **样本名只取玩家可见关卡名**（`load_player_stage_names`，四类源、按 `StageType` 互斥；
   解析不出名字的关卡**只进 `total`、不落样本**）：

   | 源 | 连接方式 | 实测覆盖（样本） | 例 |
   | --- | --- | --- | --- |
   | ① 活动关卡（[0046](0046-出没样本名改取活动表实名.md) 的 6 条链） | `EventID = StageID // 10` + 原值兜底 | 62 | 擂台赛•其一 / 「很多鸽子」/ 人山人海的桶 |
   | ② 终局四表 `ChallengeMazeConfig` / `ChallengeStoryMazeConfig` / `ChallengeBossMazeConfig` 的 `EventIDList1/2`、`ChallengePeakConfig` 的 `EventIDList` | **列表里直接装关卡 ID** → `Name` | 163 | 出故乡记其十 / 三幕架构其四 / 支配恶兽·难度01 |
   | ③ `CocoonConfig.StageIDList` / `FarmElementConfig.StageID` | `MappingInfoID`（真外键，100% 非空）→ `MappingInfo.Name` | 45 | 魔占之径 • 侵蚀隧洞 / 焦炙之形 • 凝滞虚影 |
   | ④ `StrongChallengeStage.EventID` / `SwordTrainingExam.StageID` | 精确 ID → `Name` / `EnemyName` | 28 | 长生久视的一梦 / 热血的云骑战士 |

   ②（终局层级名）与站点终局页同源同判据——终局页早已用这些表标注关卡名（[0031](0031-末日幻影层级敌方取实际战斗数据.md) /
   [0037](0037-忘却之庭虚构叙事详情页并入层级子tab编排.md)），本轮只是把它接到敌方页。
2. **类型闸**：②③④ 要求命中的关卡 `StageType` 属于该源（`Challenge` / `Cocoon` / `FarmElement` /
   `StrongChallengeActivity` / `SwordTraining`），跨类型的同名记录整条忽略（防 ID 空间巧合）。
3. **不做 `MappingInfo.ID == StageID // 100` 这条看似更全的折算**：实测 90 个 `FARM_ENTRANCE` 里
   只有 1 个存在 `ID*100+k` 关卡家族（非 FARM 的 923 里有 74 个），且逐关核对 `ShowMonsterList`
   与波次 **0 交集** ⇒ 是巧合；真外键只有 ③ 的 `MappingInfoID`。
4. **区块排版与文案分两层：「玩家读得懂的正文」+「维护者查得到的折叠口径」**（2026-10-06 按用户
   「重新设计排版、想想这些说明是否适合给玩家看」重做）：
   - 正文三行：① 计数（`出现在 N 个关卡`，数字走 HUD 字阶）→ ② 样本列表（活动名弱化字阶 + 关卡名，
     至多 3 条）→ ③ 一句人话说明——有样本时「关卡名取自游戏内（活动关卡 / 终局层级 / 侵蚀隧洞 · 凝滞虚影 /
     强敌挑战 · 剑试），至多列 3 处」；**无样本时「这些关卡在游戏内没有关卡名，只计入上面的数量」**
     （235 个页面的真实边界必须显式说出，不能用沉默代替）。
   - **技术口径从正文移入默认收起的 `<details>`「统计口径」**：源表名（`StageConfig`）、「召唤链」、
     「难度档 / 上下半场」「无限波次玩法的随机编组」都是维护者语言，压在玩家面前只会劝退；不用
     `title` 提示是因为移动端没有 hover。
   - 空态「暂无关卡出场记录」与折叠口径两种情况都渲染；AI 快照仍逐字读该块，不另算。
5. **`total` 与样本去重口径不变**：关卡波次 + 召唤链；同一 `StageType` 只取一关、关卡名不重复、
   至多 3 条（[0046](0046-出没样本名改取活动表实名.md) 决策 5 保留）。
6. **① 活动链的样本带活动名，落成独立字段 `samples[].activity`**（用户追加要求；2026-10-06 从
   「拼进 `name`」改为分列）：`name` 只放关卡名、`activity` 只放活动名，**拼接发生在展示层**——
   视图渲染为「活动名 · 关卡名」（活动名走弱化字阶，与关卡名分出上下文 / 值两级），AI 快照按同一
   格式与同一个分隔符（` · `，与关卡名内部的源文本 `•` 区分）拼接。数据层两个字段各管一件事，
   页面才有条件把活动名弱化。活动名的连接**按链分别验证**，给不出就不落 `activity` 键（宁缺不猜）：

   | 链 | 活动名连接 | 活动名 | 样本覆盖 |
   | --- | --- | --- | --- |
   | FightFest | `ActivityPanel.UIPrefab` basename == `StageType`（与 `load_event_sources` 同一约定） | 星天演武仪典 | 17/17 |
   | TelevisionActivity | `ActivityTelevisionStage.ActivityModuleID` → `ActivityPanel` | 惊梦电视台 / 晨昏卷隐 | 3/3 |
   | SummonActivity | `ActivitySummonGroup.ActivityModuleID` → `ActivityPanel` | 开拓，友谊魔法！ | 5/5 |
   | StarFightActivity | `ActivityStarFightGroup.ActivityModuleID` → `ActivityPanel` | 星芒烁变 / 星芒启明 | —（当前无目录样本） |
   | BoxingClub | ✗ 只有 20/97 个活动号能连到 `BoxingClubChallenge.StageGroupList → BoxingClubStageGroup.EventIDList`（样本关仅 4/19） | — | 不加 |
   | ElationActivity | ✗ 全库无 `ActivityModuleID` 连接 | — | 不加 |

   面板匹配用**最长前导**（`ActivityModuleID` 以 `PanelID` 开头，与取活动页签的约定同一条）。

## 4. 影响面

- `tools/converter/converters/monster_extra.py`：`load_player_stage_names` + 三个 `_absorb_*` 小件新增；
  `load_appearances` 删掉「整类常量名」判定与 `StageConfig.StageName` 兜底（`resolve_text` 不再参与样本名）。
- 数据：`public/data/cn/monsters/*.json` 重生成，**2487 个文件变化**。终态 = **501 个样本、309 个页面
  有 chip，235 个页面只有计数**；**自己名字样本 0 个**。
- 前端：`MonsterDetailView.vue` 出没区块重排（计数 → 样本 `ul` → 一句人话说明 → `<details>` 折叠口径；
  空态与「有计数无样本」两种说明分列）、`monster-detail.css` 的 `.nk-mob-appear__*` 分档；
  `src/services/types/monster.ts` 的 `MonsterAppearanceSample.activity?`。
- 快照：`tools/gen-ai-endpoints.mjs` 出没一行按同一格式拼「活动名 · 关卡名」。
- 测试：`pytest`（四类源逐项解析、类型闸、缺表只掉一源、无实名源关卡（含「关卡名 == 本怪名字」）不落样本、
  `activity` 独立落键）；
  `e2e/layout-monster.spec.ts`（chip 逐项等于数据（含活动名前缀）+ `1004015` 回归哨 + 自己名字哨 +
  「total>0 且 samples 为空 ⇒ chip 数 0 且说明行写明『没有关卡名』」，并做负测）。
- 文档：`docs/data/转换器字段映射.md` 的 monster_extra「出没」条目。

## 5. 后果

- 出没区从此只出现玩家认得出的名字（如「回忆其十五」「天人之形 • 凝滞虚影」「叩关赛•其一」）；
  同一个怪以前可能只显示敌人名，现在改为「该关的真实关卡名」，新源还腾出了原本被无源样本占掉的
  样本槽位（742 → 501 个样本，但**有名字的比例 40% → 100%**）。
- **235 个页面（占 544 条的 43%）只有计数、没有样本名**：这是源数据的真实边界——VerseSimulation /
  Trial / Mainline / LocalLegend / FinalityActivity / RogueChallengeActivity / RogueRelic /
  ExpeditionBattle 这些玩法在 `ExcelOutput` 里**没有任何玩家可见关卡名**（已扫全部 2240 张小表，
  只接受精确 StageID 连接）。注记已把这一点显式告诉读者。
- 若日后上游为这些玩法补了名字表，只需在 `load_player_stage_names` 加一条源，页面零改动。
