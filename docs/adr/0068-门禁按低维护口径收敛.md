# 0068 门禁按「低维护」口径收敛：push 守不可逆、夜间只冒烟、全量改手动

- 状态：Accepted（已实现）
- 日期：2026-11-23
- 相关：[testing.md](../agents/testing.md)（门禁分层唯一事实源）、[commands.md](../agents/commands.md)（命令与门禁挂载）、[UI质量验收标准.md](../audit/UI质量验收标准.md)（A5.6）、[memory/testing.md](../memory/testing.md)

## 背景

站点由单人维护、面向小众受众；GitHub Actions 对公开仓免费，所以**算力不是成本，注意力才是**。按这条约束复盘 2026-11 的门禁形状，量到的事实：

- 近期 42 次 CI 中 8 次红（19%），其中 **7 次来自夜间慢档**（`layout` 6 片 / `firefox` / `smoke`）；push 档只红 1 次且是真错误。
- 夜间红的构成：4~5 次是**某语言某页 4~15px 的裁切**（真缺陷、但影响面极小）、1 次是**时间耦合断言**（`layout-endgame-season.spec.ts` 用 `Date.now()` 推导赛季 `live/ended` 期望值，墙钟到点自己变红）、2 次 flake（图标可见性自愈、焦点像素截图 180s 超时）。
- **数据同步提交 8/8 零 CI**：bot（`GITHUB_TOKEN`）推送不触发 workflow，而它天天改 `public/data/**`；与此同时 CI **从不跑 `vite build`**（`static` 只有守卫 + `vue-tsc`），全仓最强的守卫——预渲染 1137 份快照 × 14 项断言与 AI 端点 7 项——只在 Vercel 部署时跑。
- 判据自身有维护成本：`clippedNoFallback`（截断须在 5 层祖先找到 `title`/`aria-label`）在法文 NBSP 与判据空白归一口径不一致时**假阳**，为此打的补丁本身就是一次缺陷；`@visual-detail` 73 条、`@i18n-detail` 20 条在任何 CI 档都不收集；`layout-i18n-overflow-alt.spec.ts` 整文件 **0 条被收集**却被计入「周跑覆盖」。
- 体量：产品代码 45,538 行；e2e 7,984 行 + 977 行 helper / 35 spec；测试相关文档约 136 KB（`docs/memory/testing.md` 单文件 62.8 KB）。

结论：失效模式排序里最该自动挡的（建不出站 / 数据坏）没有门，噪声最大的（版式微缺陷 + 环境耦合断言）天天在响。

## 决策

1. **push 档只守「不可逆 + 影响全体用户」**：`static`（视口标签机检 + `pnpm build`，即守卫链 + `vue-tsc` + `vite build` + 预渲染 / AI 端点断言，与 `vercel.json` 的 `buildCommand` 同一条链）、`unit-tests`（662 条 / 5s）、`guards`（可达 + 未捕获异常）。
2. **夜间档只留一次冒烟**：`invariants`（shell + a11y，`--workers=1` 避免 a11y 扫描与页面载入互相拖成 flake）、`smoke`（风险语言子集 + 长文案手机/桌面档）。
3. **全量档改手动**：`layout`（6 分片 × 2 project）与 `i18n-full`（13 语言 × 三档长文案）只在 `workflow_dispatch e2e_scope=full` 跑；删除原周跑工作流（ci-full.yml，已删）。
4. **删除不再付租的资产**：Firefox 项目与 `@cross-engine` 标签、像素基线（原 visual.spec.ts + e2e/snapshots，共 3.5 MB）、与 `-overflow` 重复且 0 条收集的 `-alt` spec、`test:e2e:update` 脚本。
5. **判据去环境知识**：删除 `clippedNoFallback`（不再要求判据读懂数据的空白编码 / 依赖 `title` 存在性）；改为「截断必须有可见提示（`text-overflow: ellipsis` 或 `-webkit-line-clamp`）」；硬裁切命中时由 `clipOffenders` 报出**越界源**（被裁容器里右缘越出它的最内层后代，排除可横滚祖先），使红灯自带定位。
6. **复访条件**：出现「用户可见缺陷却无人提前发现」≥2 次、或站点转为多人 / 商业化维护时，重新评估本口径（届时优先恢复的是 build 与数据契约，而不是版式矩阵）。

## 替代方案（被否）

- **保持现状（13 语言 × 3 档周跑 + firefox + 像素基线）**：否决。19% 红率里多数是微缺陷与假阳，每次红灯都要一次人工会话；而它守的「和上一版长得一样」在重构期本身就是反向目标。
- **只把 `pnpm build` 加进 CI，其余不动**：否决。补上了最大缺口，但夜间 6 片 layout + firefox 的噪声源仍在。
- **保留档位、只删用例**：否决。布局契约在「动版式 / 发版前」确实要用，问题是**不该在无人看时按 cron 常驻**——降频到手动即可，用例一条不删。
- **像素基线保留、只在发版前跑**：否决。基线判定依赖 jsDelivr 供图、字体与渲染环境，长期必然失效；视觉验收交用户 RunPreview + `layout-*.spec.ts` 的可执行断言更稳。
- **继续用「标签 + grepInvert」细粒度排除**：否决其扩张。已收窄到只服务两个仍有效的前缀（`@visual-detail` / `@i18n-detail` 冻结、`@viewport-pinned` / `@viewport-independent` 服务手机档去重），不再为「环境差异」新增标签。

## 后果

- **覆盖率是有意收窄并登记在案的**：13 语言 × 桌面/最窄档从「周跑」降为「手动 full」；XL 语言（cn/de/ru 之外）的桌面长文案在日常档不再逐页扫描。判断依据：这类失效模式的变量是**文本长度而非语言数量**，de/ru 已覆盖该维度。
- **首次在 CI 拥有 build 门**：数据同步后「页面还能不能建出来」这件事从「看 Vercel 部署状态」前移到 push 反馈。代价是同一链条跑两遍（CI 与 Vercel），接受——早期反馈与部署不可逆之间的差别值这个时间。
- **`@visual-detail` / `@i18n-detail` 仍冻结在 `E2E_DETAIL=1` 手动档**：本轮未逐条删除（73 + 20 条），下次触碰对应页面时顺手删，避免一次性大改引入语法破损。
- **门禁文档不再描述不存在的档位**：`testing.md` / `commands.md` / `UI质量验收标准.md` / `AGENTS.md` 同批更新；`docs/memory/testing.md` 顶部加了口径变更说明，旧条目中的条数与项目名按历史取证读。
- **320 最窄档暂无自动覆盖**：原 `-narrow` 是「一条 gross 用例循环 13 语言 × 5 详情族」且全条带 `@visual-detail`，实测 **0 条被收集**（长期假覆盖），已删。若真出现 320 专属破版，再按「一语言一条」参数化重加（复访条件）。
- **历史 ADR 仍引用已删资产**（像素基线、snapshots）：`node tools/check-doc-links.mjs` 会把它们计为「误删引用」。ADR 是历史记录，不回改；该检查本就仅手动、未进 CI。
- **新增手动 full 档入口** `pnpm test:e2e:full`（`tools/e2e-full.mjs`，内部注入 `SMOKE_SCOPE=all` + `I18N_OVERFLOW_ALL=1`），跨平台与 CI `i18n-full` job 同集。
