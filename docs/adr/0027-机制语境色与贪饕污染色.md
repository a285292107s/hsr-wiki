# 0027. 机制语境色与「贪饕」污染色

## 状态

`accepted`（已实现：`tokens.css` 领域层新增污染族 `--vor-500` / `--vor-300`；`/voracity` 子树、怪物详情侵蚀标记、终局污染徽标、终局目录卡「含污染」标记四处同源消费；`--eg-*` 与 `--vor-*` 同批登记进 [ui-design.md](../agents/ui-design.md) §2 领域层清单）

## 背景

4.6「贪饕」侵蚀/污染体系上线后，站点对它的**全部**视觉表达都消费 `--primary`：专题页 `/voracity`（吸顶进度条、secnav 激活项、卡片底纹与边框、数值强调位）加上怪物详情「受『贪饕』侵蚀」标记、终局详情页的污染等级徽标、终局目录卡的「含污染」标记。结果是这套机制在站内没有自己的颜色——它的读感完全等于「用户当前的强调色」，缺省即赤陶暖砖红。

游戏内这套机制有专门的主题色。取证（像素法：HSV 过滤 `V<0.15 / V>0.9 / S<0.25` 后 k-means，对比度按 WCAG 相对亮度）：

| hex | 来源 | 图上位置 |
|---|---|---|
| `#DF3D3D` | 侵蚀等级横幅原图（fandom `Voracity_Corrosion.png`） | 徽记纯红平坦填充（top1 簇 28.5%） |
| `#FF4242` | 同横幅另一语言版 | 徽记最亮色簇 |
| `#C40C6A` | 同横幅 + 4.6 官方公告 KV | 徽记周围洋红能量带（官方 KV 内 top1 簇 22.2%） |
| `#FC48AC` | 受污染敌人教程图 | 「被压制生命上限」血条 |
| `#66030C` | 同横幅 | 徽记暗部（mean `#820A1B`） |

即游戏内是**红徽记 + 洋红能量并存**，而洋红那半支才是画面主体。两项排除：教程文案里的 `<color=#f29e38ff>`（本地 TextMap 实测）是全局教程琥珀色而非机制专属色，且与 `--elem-fire #FF6B35` 几乎同色相；侵蚀增益图标 `IconBuffShield` 是通用盾图标，本身不带专属色。**颜色是这套机制唯一能承载身份的表达**。

三条既有约束构成边界：双色约束（同一时刻主题层只允许一个强调色相，[ADR 0011](0011-全局色彩管理-黑与紫-黑与金.md)）；领域色豁免（数据语义色不随主题）；四层令牌单向事实链（消费层只许 `var()` / `color-mix`，[ADR 0012](0012-色彩代码架构管理-事实链与三道闸门.md)）。

而「按语境换色」在站内**早已存在但没登记**：`--eg-maze/story/boss/peak` 是语义层字面 hex，终局各页面用 `[data-mode]` 把它局部赋给 `--eg-color`，secnav / 进度条 / 徽标全部走它——但 [ui-design.md](../agents/ui-design.md) §2 的领域层清单里没有 `--eg-*`，属登记缺口。

## 决策

**我们把机制专属色确立为一个登记在案的令牌类别「语境色」，并给「贪饕」污染落一支洋红族污染色。**

1. **污染色 = 官方洋红族**：基准位 `--vor-500: #C40C6A`、文字亮端 `--vor-300: #FC48AC`，落在**领域层**（不随主题与强调色切换）。亮端同时登记进 `tools/check-contrast.mjs` 的正文类令牌清单，黑底 ≥4.5:1 由门禁强制。
2. **一支色值、四处同源**：① `/voracity` 子树（数据面 + 结构强调位：卡片底纹与边框 tint、徽标、数值强调位、吸顶进度条、secnav 激活项）；② 怪物详情「受『贪饕』侵蚀」标记与回链；③ 终局污染徽标（楼层头 / 半场 / 单关）；④ 终局目录卡「含污染」标记。**③④ 从所属模式色 `--eg-color` 上摘下来**——污染是跨模式的同一机制，不该随所在页面变色。
3. **消费方式**：单一色值**不设子树别名**（与 `--eg-color` 的四色切换场景不同，污染只有一支），页面 CSS 直接 `var(--vor-500)` / `var(--vor-300)`；派生色一律 `color-mix(in srgb, var(--vor-500) X%, transparent)`。**基准位只承载非文字**（边线 / 底纹 / 进度条 / 大面积标识），**文字一律用亮端**。
4. **登记与术语**：`CONTEXT.md` 新增「语境色」「污染色」两条术语；`--eg-*`（终局四模式）与 `--vor-*`（污染）同批登记进 [ui-design.md](../agents/ui-design.md) §2 领域层清单；§3 明确「机制语境色不吃用户强调色」是双色约束的**边界**而非违规。

## 后果

**正面**

- 机制首次拥有可追溯到游戏内素材的身份色，且与用户强调色、终局模式色都不再混淆（与既有四色最小色相距离 22°）。
- 「语境色」从只在 CSS 里存在的隐式先例升为登记类别：后续机制（星启 / 位面 / 其它体系）按同一流程加，不必每次重议边界。
- 亮端进 `check-contrast.mjs` 正文类清单，颜色回归有门禁兜底（实测最差场景 = 着色片上的亮端，五套强调色下 4.97~4.99:1）。

**负面**

- 双色约束多一类例外：机制子树内会出现「用户强调色（导航/外壳）+ 污染色（页内强调位）」同屏两支色相。这是有意边界，但意味着「同一时刻只有一个强调色相」必须按**主题层**而非**页面**理解。
- 污染色是与主题无关的常量：游戏若改这套机制的配色，必须同批改令牌与本文的取证记录。
- 用户在设置页切换强调色时，`/voracity` 只有部分反馈（外壳与导航跟随、页内强调位不跟随），有被读成失效的风险——e2e 与文档都需要把这点写成规格而不是 bug。

**中性**

- 基准位 `#C40C6A` 在黑底 3.21:1、卡片上 2.70~2.81:1，只合非文字用法。这是「取官方洋红能量原值」而非「提亮到能当文字」的直接后果，文字位由亮端承担。
- 术语「污染色」与 4.5 Fate 联动「圣杯战争 · 污染等级 / 深度污染」无关，两者不共用此色、不互相内链（同形词纪律见 `CONTEXT.md`）。
- 取证用的图片来自 fandom 与官方公告 KV，**与站点图源无关**：上游 `tutorialpic` / `bufficon` 在 nanoka 全 404，站点教程图缺图是另一件事，本文不处理。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 纯红族「猩红」（基准 `#DF3D3D` / 亮端 `#FF4242`） | 读感最贴「不祥的猩红」，但与 `--eg-boss`（末日幻影玫瑰红 `#FB7185`）同色相族、与 `--diff-del #F87171` 同色相：污染标记恰恰渲染在**按模式着色**的终局页里，红上加红分不开；且基准位 4.34:1 连非文字用在卡片上都偏暗 |
| 红洋双承：徽记红与洋红能量各自成族 | 最贴游戏内观感，但一支机制两支色意味着令牌、门禁与「谁在哪一层」的判定全部翻倍，收益不抵复杂度 |
| 污染色做成强调色通道（路由级 `data` 属性驱动，像 `--th-*` 那样可切换） | 当前只有终局四模式 + 污染两类消费方，且污染色没有「多个候选」的需求；抽象成本高于收益 |
| 只改 `/voracity` 页内，不动怪物详情与终局标记 | 同一机制在两处不同色，读者会把其中一处当成别的东西；而终局污染徽标本来就被模式色盖住，正是本次要解决的主要混淆源 |
| 只加一支色、不做类别登记（不补 `--eg-*` 登记缺口） | `--eg-*` 已经这样存在了数个月且无人知晓；不登记等于把同一个问题留给下一支机制色 |
