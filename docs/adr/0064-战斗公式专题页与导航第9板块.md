# 0064. 战斗公式专题页与导航第 9 板块

## 状态

`accepted`（已实现：新增 `/formula` 单页专题并入 AI 快照契约；侧栏常规模式末尾追加第 9 项；公式内核落在 `src/lib/formula/`，页面为客户端可视化交互，无新增数据产物）。**2026-10-28 补记：区块表与链路表随展示迭代变更（决策本身不变，见文末补记）**

## 背景

站点已有大量「数值」但没有任何「数值怎么来」的解释：敌人详情有一块属性推导（`monster-stat` 系列），角色 / 光锥 / 遗器各自展示数值与倍率，玩家要自己拼出伤害公式。用户要求按 NGA《星铁数据机制通论(第2版)》（tid=36548192）整理一页，并明确要求「图表 + 动态交互，不要只有干巴巴的文字」。

三条约束决定形态：

1. **内容是机制而非条目**：伤害公式、乘区钳制、属性成长线型、行动值、削韧、命中判定，条目数固定（六类乘区 + 三套成长线型 + 三组判定），天然不属于配置驱动目录页，也不是单一实体详情。
2. **口径必须可自证**：公式里的每个可变量（角色 / 光锥 / 敌人属性、等级曲线、精英组倍率、技能倍率）站内已有官方解包数据（`public/data/cn/**`），页面应让玩家用**自己的角色/敌人**看曲线，而不是给一堆截图。原文 2023 年撰写（游戏 1.1），数值口径必须回到本站 4.6 数据源重新取。
3. **无图表依赖**：站点运行时依赖只有 5 件且明令不引 UI/图表库，图表只能手写 SVG；也因此公式与图表刻度都必须落到可单测的纯函数，否则数值错误无法被发现。

## 决策

**采用「单页专题 + 纯函数内核」承载战斗公式**：

- 路由 `/formula`，仅常规模式（`NORMAL_NAV_ITEMS` **末尾**追加第 9 项，排在 `/voracity` 之后）；`meta.depth = 1`，与 `/voracity` 同级。
- 页面分十区块：伤害链路／击破链路／欢愉伤害／真实伤害／属性成长／伤害乘区／治疗与护盾／速度与行动值／削韧·命中／实战计算器。基本单元是「控件 → 读数 + 联动流水」，乘区节点可点击切换公式说明。**区块内部的控件清单、图表形态与文案属可逆展示层，不写入本 ADR**（改动只在 `docs/memory/` 留坑位）。
- 四条伤害链路并列而非合并：直伤、击破（含超击破）、欢愉、真实伤害各自的乘区集合不同（击破不吃增伤且不能暴击、欢愉不吃攻击力与增伤、真实伤害不进任何乘区），合成一页会把「哪条链路吃什么」这个最常被算错的点糊掉。三条新链路**不画图**：它们的可变量对玩家是离散选项（属性 / 韧性档 / 好活数），流水读数已经给出全部答案，曲线没有决策价值。
- 机制常量（`10000` 行动值基数、`200 + 10×等级` 防御线型、`3.5 / 0.99 / 0.2` 三类钳制边界、属性击破倍率、韧性条长度系数、笑点区系数）集中收在 `src/lib/formula/constants.ts`——它们是战斗系统常量而非游戏数据，不属「禁止写死数据」的范畴；**一切随版本变化的数据（角色/光锥/敌人属性、等级曲线、精英组倍率、技能倍率）必须走本地 JSON loader**，禁止在代码里出现任何具体角色数值。
- **击破基数与欢愉基础值是「等级 → 数值」的系统常量表**（vendor `AvatarBreakDamage` / `ElationBasicLevelDamage`，各 1–101 级），与 `200 + 10×等级` 同属机制层而非条目数据，故与常量同置 `src/lib/formula/tables.ts` 并以单测锁 1/70/80 级三个锚点；升级上限或版本调表时须重跑 `query.py` 重导，不属「改一句数值」的展示迭代。
- 页面的可计算部分全部落到 `src/lib/formula/` 的纯函数并配单测；`src/lib/chart.ts` 只做刻度 / 路径字符串生成（`linearScale` / `niceTicks` / `linePath`），确保「图上没有 NaN」是可断言的。
- 该路由纳入 AI 可索引快照：`gen-ai-endpoints` 新增 `formula` 家族（12 语言分层），`check-ai-endpoints` 的 `singleFamilies` 与 `LAYERED_FILES` 同步登记，`vercel.json` 补默认语言 + 12 语言前缀两条 rewrite。
- UI 文案全部走词典，新增 `nav.formula` 与 `formula.*` 键，13 个语言包同步；公式表达式键（`formula.zoneFormula.*`）保留运算符与数字，只译词。

## 后果

**正面**

- 站内首次有「机制层」入口：任何进度条式的数值疑问都能落到一页公式上，并与角色/光锥/敌人图鉴互链。
- 公式与钳制边界进了单测（同级防御区 0.5、暴击期望、三类上限、行动值、破韧、命中概率），后续版本改数值口径会被测试拦住，而不是靠人眼核对截图。
- 玩家可用站内真实数据看曲线（选自己的角色 / 敌人），页面不依赖任何外部攻略图。

**负面**

- 导航从 8 板块扩到 9 板块：≥768px 仍全部平铺，**<768px 手机底栏按槽位函数折叠**，新项可能与 `/voracity` 一起进入「更多」抽屉；侧栏 DOM 锚点数变为 **10**（首页枢纽项 + 9 板块）。
- 新键 × 13 语言包是新维护面：后续改一句中文要同步 13 份译文。
- 页面是纯客户端计算，**AI 快照只能呈现公式与区块标题的静态文本**，交互与曲线对无 JS 的爬虫不可见；这是形式选择的固有代价，不视为缺陷。
- 图表为手写 SVG，无通用图表能力（缩放、图例交互、对数轴）沉淀；若后续第二处页面要图表，应把 `src/lib/chart.ts` 抽公共，而不是复制。
- 击破基数 / 欢愉基础值两张 80 项常量表进了源码：版本调表时要重导，不会自动跟随数据产物更新（单测锁了锚点，调表会被测出来，但改法是人工重导）。

**中性**

- 「战斗公式」是站点工作名（导航与 H1）；游戏内无此合成名词，正文用「伤害乘区 / 伤害修饰区 / 特殊乘区」等官方与社区通用说法。
- 原文对少数机制给的是图片与在线表格（分数段、遗器权重、敌人全技能倍率），本站不复刻这些表格：用可调曲线与本地数据替代，不搬运无法溯源的数字。
- 站内已有 `monsterStatBreakdown` 等敌人属性推导逻辑，本页**复用**而不重写；`levelStatValue` / `charStageForLevel` 等成长口径同样复用 `src/lib/format.ts`。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 配置驱动目录页（一条公式一卡 + 筛选） | 公式之间有严格乘法依赖，拆成独立卡片会丢掉「乘区只有乘法、彼此等价」这一核心认知；且目录页需要条目级快照断言，公式条目体积与交互能力都塞不进卡片 |
| 纯长文专题页（照搬 NGA 排版） | 用户明确要求「避免只有干巴巴的文字」；原文的线型图 / 倍率表都是静态图片，站内不能用外部图，长文还制造 13 语言包的巨量翻译 |
| 嵌入敌人详情或角色详情页 | 公式是跨实体的机制，挂到任一实体页都会让该页承担与自身无关的体量；且与新导航入口的诉求不符 |
| 新增 converter 模块产出公式 JSON | 公式是常量与算法，不是上游表数据；造一个 JSON 只会把可测的纯函数变成不可测的配置 |

## 补记（2026-10-28：区块表与链路表随展示迭代变更）

现行页面为**九区块**：直伤链路 / 击破链路 / 欢愉链路 / 附加伤害 / 真实伤害 / 治疗与护盾 / 速度与行动值 / 削韧·命中 / 实战计算器——「属性成长」与「伤害乘区」两块退场，「欢愉伤害」更名「欢愉链路」；伤害链路由四条增为**五条**（新增附加伤害：走完整乘区、可暴击，但不削韧、不回能、不触发「攻击后」判定）。区块表与链路表属可逆展示层（上文决策第 2 条已声明不写入本 ADR），改动只留坑位于 [docs/memory/data-semantics.md](../memory/data-semantics.md)；**决策本体不变**：单页专题 + 纯函数内核 + 不引图表库 + 无数据产物。
