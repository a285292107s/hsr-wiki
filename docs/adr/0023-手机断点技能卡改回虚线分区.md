# 0023. 手机断点技能卡改回虚线分区

## 状态

`accepted`（**收窄 [ADR 0022](0022-技能层级以行迹族为唯一来源.md) 的断点作用域**：图标列与折角层级线自本决策起**仅在 ≥768px（平板 / 桌面）生效**；**<768px（手机）**恢复旧版形态——图标内联标题行、子卡上沿 1px 虚线分区、12px 缩进）。

**ADR 0022 的族判定（`skill_trees[*].level_up_skill_id`）与桌面 / 平板几何继续有效**，其状态保持 `accepted`、**不标 superseded**；本决策只收窄其布局断点作用域。

## 背景

用户反馈（原话）：「角色详情页面技能卡当前排版的使用效率太低，改回原来用虚线隔开的样式」（限定手机断点）。

ADR 0022 定稿的「图标列 + 折角层级线」是**全断点**布局——它在手机断点同样把技能图标拆进一条独立列，并由该列承担全部层级线几何。手机视口的量化收益损失如下（375px 实测）：

| 项 | 实测 |
| --- | --- |
| 卡片内容宽 | 343px |
| 图标列占位 | 44px（`--nk-skill-rail`）+ 16px（`column-gap`）= **60px ≈ 17.5%**，恒定被占 |
| 该占位对无子卡技能 | **纯属无承载物空档**：忆灵技能 / 单卡族 / 大多数技能在 rail 里只有一个图标、没有任何线 |

`--nk-skill-gutter` 已在 ADR 0022「几何修订 2」中归零（全断点），图标左侧不再有可回收留白 ⇒ 手机端剩下的空档只能靠**让图标列在该断点退场**回收。

旧版手机形态（图标内联于标题行 + 子卡 `border-top: 1px dashed` + 10px 缩进）在 ADR 0022 落地时被一并删除，可从 `d4546e0^` 复原该实现。

## 决策

1. **断点边界**：本决策只作用于 `max-width: 767px`。**768–1023px（平板）与 ≥1024px（桌面）完全不变**，继续使用图标列 + 竖轨 / ├ / └ 折角层级线。
2. **图标内联**：手机断点 `.nk-skill__rail`（图标列）**不渲染**，技能图标回到 `.nk-skill__title-row` 内联（`flex` 行内、图标在左）。**必须换宿主才能内联**（`SkillCard.vue` 按 `(max-width: 767px)` 媒体查询切换图标宿主；桌面/平板仍渲染图标列）：`.nk-skill__rail` 与 `.nk-skill__title-row` 是**兄弟节点**，纯 CSS（含 `display: contents`）只能把图标变成 `.nk-skill__body` 的 grid item 堆在标题行上方（实测每卡 +44px），抬不进标题行的 flex 行。
3. **正文单列全宽**：`.nk-skill__body` 回到单列，正文吃满卡片全宽，回收上述 60px。
4. **子卡虚线**：手机断点的层级改由**子卡（同族形态技能）上沿的虚线分区**表达（`border-top: 1px dashed var(--line-2)`，语义与「技能层级线」并列）；**父卡与单卡族不加线**。
5. **子卡缩进 = 12px**（落 8px 栅格 / 4px 半步体系；旧版 10px 因非 4 的倍数被否）。
6. **子卡纵向间距沿用现行派生值** `calc(var(--nk-skill-rail) / 2)`（手机 = 22px），**不回**旧版的 18 / 12 固定值。
7. **虚线留白等距**：手机断点父卡内容体（`.nk-skill:has(> .nk-skill--child) > .nk-skill__body`）加 `padding-bottom: 13px`，令虚线上下各 22px（子卡 `padding-top` 只给线下方空隙，线上方原本只剩上一行内容自带余量，实测 9px ⇒「贴着上文」，用户复审指出）。**仅手机断点生效**，桌面/平板垂直节奏不变。

## 后果

**正面**

- 手机端回收 60px / 343px ≈ 17.5% 的恒定横向占位，且该占位对无子卡技能本来就是无承载物空档。
- 图标回到标题行后，「图标属于哪条标题」不再依赖图标列与标题行的横向对齐关系，缩放与字号变化时不会错位。
- 手机断点的层级仍由**数据推导的族关系**决定（虚线只画在子卡上沿），ADR 0022 的族判定继续是唯一事实来源。

**负面**

- **手机与桌面层级语言分家**：同一族在两种断点用两套视觉（折角线 vs 虚线分区），用户需理解两套；文档与 e2e 也要按断点分述。
- **「缩进 = 技能图标空间整数倍」这一 ADR 0022 定下的单位规则在手机失效**：手机改为 12px 视觉档位（不在图标边长的整数倍上），必须在 `CONTEXT.md`「技能图标空间」条目里标注例外，否则后续改动会按旧规则「纠正」回去。
- **手机断点消失的唯一视觉层级信号是虚线**：若虚线因色彩 / 对比度被改弱（例如 `--line-2` 被调暗、或虚线被当成装饰性分隔删除），手机端层级会直接不可读，而桌面断点看不出这个问题。
- **e2e 必须永久维护两套几何断言**（≥768px 折角几何 / <768px 虚线几何），断点回归的维护成本翻倍。
- **技能卡的 DOM 不再与断点无关**：图标宿主由一个 `(max-width: 767px)` 媒体查询驱动（含 resize 时的宿主切换），意味着「同一个技能卡组件在两种断点渲染两棵结构树」。好处是内联真的成立，代价是**任何读 DOM 的断言/探针都必须按断点给选择器**，且纯 HTML 快照（若将来加入）会只反映一种断点。

**中性**

- `src/styles/character.css` 内既有 3 处虚线（技能故事、对比模式）与本决策新增的子卡虚线同类；本决策把「技能卡子卡虚线分区」定为对 `achievement.css` 头部「禁虚线分隔（发丝线取代）」的**有意豁免**，但**不扩展**到成就页与其它页面的装饰性分隔（登记见 [docs/agents/ui-design.md](../agents/ui-design.md) §7）。
- 光锥详情页共用 `skill-card.css` 的技能卡原语，但手机断点块的选择器全部以 `.nk-char-page` 作用域声明（`SkillCard.vue` 的图标宿主切换也只在角色详情页的该组件内），故本决策不改变光锥页与对比模式的形态（由 e2e 的「光锥页未波及」断言兜住）。
- **图标 DOM 位置随断点变化**：桌面 DOM 仍是「图标列 + 内容列」两栏，手机 DOM 把图标挂进标题行；因此技能卡的两套布局不是同一棵 DOM 上的纯 CSS 分支（代价见负面第 4 条）。

## 替代方案

| 方案 | 为何未采用 |
| --- | --- |
| 全断点都改回虚线 | 平板 / 桌面的宽度不构成瓶颈（60px 在宽视口的卡片内容宽上占比不到一成，且折角几何在宽视口可读），却会丢掉 ADR 0022 花四轮定稿的折角几何与既有断言——代价与收益完全错配 |
| 保留图标列、只去掉层级线 | 仍然占 60px（页面实际可用的横向空间才是本轮的瓶颈），只省下视觉复杂度；图标列在无子卡技能上依旧是无承载物空档 |
| 手机也保留折角线，只去掉图标列 | 折角线失去图标锚点：竖轨原以父图标中线定位、折角原以子图标中线收口，无图标列后无线可收口，只能另造一套参考点 = 换一套几何语言且没有收益 |
