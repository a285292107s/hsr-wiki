## 坑位：dev server 不监视 public 新建目录（返回 index.html fallback 200）
- 现象：`pnpm dev` 运行中向 `public/data/cn/assets/` 新增 jpg 后，`curl` 该 URL 返回 **200 + 694 字节 index.html**（SPA fallback），既存 public 文件（characters.json 等）正常 → e2e waitImages 20s 超时、像素基线截到坏图。
- 根因：rolldown-vite 的 dev public 目录监视**不含启动后新建的子目录**（08-13 源文件缓存坑的同族变体，无 mtime 兜底）。
- 处置：**重启 dev server 即自愈**（kill 5173 监听进程后 pnpm dev）；不许写死规避（refresh-vite-cache 只覆盖源文件，public 新目录无效）。
- **连带纪律**：e2e 基线更新前若涉及「新增 public 资源」，先 curl 验证 dev 响应字节数 === 磁盘文件字节数，否则基线会存坏图（本次 currency.png 第一次 update-snapshots 即踩中，re-run 才正确）。
