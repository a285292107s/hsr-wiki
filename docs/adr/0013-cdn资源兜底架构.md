# CDN 资源兜底架构：健康探测与分层降级

## Status: accepted

## Context

全站数据（目录/详情 JSON）为本地随站部署，但图片（avatarshopicon / skillicons / 光锥 / 遗器 / 怪物等 17 类）与 Spine 动画（运行时 script + atlas/json/skel）均走外部 CDN（static.nanoka.cc / 官网源）。CDN 整体不可达时存在四类问题：

1. **manifest 阻塞**：`CatalogPage.load()` / `character store` 先 `await app.initManifest()`（CDN manifest.json，15s 超时）再加载本地数据——CDN 挂时每次进目录/角色页白等 15s，且失败无冷却，逐页重试。
2. **Spine 挂起无界**：`injectScript` 无超时（script onerror 在 TCP 黑洞时可能永不触发）；`createSpinePlayer` 的 success/error 回调与 scene `AssetManager.loadAll` 同样可能永不结算——Hero 动画按钮态无限悬挂。
3. **图片破图**：双源回退（官方 → nanoka）后 nanoka 仍失败时显示破图图标，无最终占位；CDN down 时数百张图逐张失败放大等待。
4. **无全局信号**：各消费方独立感知失败，无统一"CDN 不可用"判定与恢复机制。

## Decision

新增 `services/cdn/health.ts` 作为**全局 CDN 健康信号唯一来源**，配合分层降级：

1. **健康探测**（bootstrap 注册，fire-and-forget 不阻塞）：
   - `HEAD ${CDN}/manifest.json`（cache: no-store，3s 超时）——远小于 fetchJSON 15s，尽快给出短路信号
   - 失败 → `cdnDown` 置位并通知订阅方；down 状态下每 30s 后台重探直至恢复（恢复即停止探测）
   - 状态读取：`isCdnDown()`；订阅：`subscribeCdnHealth(fn)`

2. **等待有界**（所有 CDN 等待路径必须有超时）：
   - `injectScript`：单源 8s 超时（移除 script + 按失败结算，进入下一源）
   - `createSpinePlayer`：整体 20s 超时（释放已创建实例防 WebGL 泄漏）
   - `createScenePipeline`：`loadTimeoutMs` option（缺省 20s）——超时按全部层缺失结算 + 释放本管线；settleOnce 加幂等闸门防双结算
   - `initManifest`：CDN down 短路 + 失败 60s 冷却；`CatalogPage.load()` / `character store` 与 manifest **并行化**（本地数据不依赖 manifest 版本）
   - `loadSpineRuntime` / 图片委托：`isCdnDown()` 时直接短路，不做注入/逐图回退尝试

3. **视觉降级**：
   - 图片最终失败（回退源/首选源失败）→ 标记 `data-cdn-down`，CSS `visibility: hidden` 隐藏破图（布局占位保留，卡片渐变底承接）；CDN 恢复时自动重载全部已降级图片
   - Spine 全失败 → 既有静态立绘/渐变底承接（Hero 立绘为 background-image，静默失败不阻塞）
   - bootstrap 订阅健康信号：down → toast 一次提示降级；恢复 → toast 提示自动重载

## Considered Options

- **仅加超时不加探测**：各路径独立超时已能避免"卡死"，但 CDN down 时仍会逐图/逐源等待超时时间（数秒级），且破图图标无解。被拒——探测是低成本（3s 单请求）的高收益信号，短路能消除大量无效等待。
- **探测成功即停止，不做会话内周期监视**：正常态无需监视；会话内再次失效由新会话探测覆盖。采用。
- **恢复时全量重载图片**：`img[data-cdn-down]` 重设 src 重新请求；虚拟滚动重建的卡片天然重新走加载流程。采用（简单幂等，不引入队列/节流）。
- **manifest 失败后永久不重试**：CDN 短暂抖动后版本信息永久缺失。被拒——60s 冷却 + down 状态双重闸门，恢复后自动放行。

## Consequences

- 新增 `services/cdn/health.ts`（探测 + 状态 + 订阅）、`cdn/dom.ts` 扩展（最终降级标记 + 恢复重载 + 短路）、`spine/runtime.ts`/`player.ts`/`scene.ts` 超时兜底、`app store` manifest 短路冷却、`bootstrap` 探测与提示、tokens.css 隐藏破图原语。
- 目录页/角色页数据加载不再被 manifest 阻塞（并行化），CDN 挂时页面数据浏览完全正常，仅图片/动画降级。
- 新增测试：`cdn-health.test.ts`（探测/超时/重探/幂等）、`cdn.test.ts` 扩展（降级标记/短路/恢复重载）、`runtime.test.ts` 扩展（script 超时/down 短路）、`player.test.ts`（整体超时/error 结算）。
- 调试页（SpineAudit/SpineDebug）资源加载同样受 scene 超时约束（共用管线）；审核台 L2 渲染队列的 `spawnPlayer` 已有独立超时，不受影响。
- 后续新增 CDN 资源消费方（图片/Spine/JSON）必须：等待有界（超时）→ 失败可降级（占位/静态承接）→ 可复用 `isCdnDown()` 短路，禁止无超时 await CDN 请求。
