# 0055. 终局敌方卡显示关卡内血量（`hp` 单值 + 数制缩写）

## 状态

`accepted`（**已实现**：`monster_common.monster_hp_at` / `stage_context` + `endgame._monster_out` 落 `hp`
+ `EnemyCard` 立绘下方 + `fmtBigNumber`）。**修订 [0050](0050-出没样本带关卡语境与实战面板.md)
决策 5 与替代方案第 3 行**（「终局敌方卡不动」的成立前提被实测推翻），并收窄
[docs/memory/data-semantics.md](../memory/data-semantics.md) 的「合成单点」边界。

## 1. 背景与问题

用户要求：在终局敌方配置的怪物卡片上、**怪物立绘下方**显示该怪物的血量，数字按 `xx亿xx万xx`
的量级形式展示（便于看清 5–9 位数字）。

[0050](0050-出没样本带关卡语境与实战面板.md) 决策 5 明确否决过这件事，理由是
「终局敌方卡不动：**无等级语境**；且终局语境（忘却之庭类）本无精英组修饰」。
该前提**在当前 vendor 数据上不成立**（`query.py` 实测，2026-10-15）：

- 忘却之庭 1035 第 1 层两个半场的关卡行 = `Level 68 / HardLevelGroup 3 / EliteGroup 273`，
  第 3 层 = `73 / 3 / 275`，第 12 层 = `95 / 3 / 164`；
- 即终局关卡**逐关带完整三件套**，且难度组是 **3**（不是怪物自身默认的组 1）、
  关卡精英组非 1（组 164 生命倍率 **6.5**）——「无等级语境 / 无精英组修饰」两半都不成立。
  [ADR 0050](0050-出没样本带关卡语境与实战面板.md) §1 只核了 `FarmElement` / `Cocoon`，
  终局四张层级表未核，结论泛化错了。

口径本身仓内已有单点：`基准 × 维度修饰比 × Π精英组(自身 × 关卡) × 曲线[关卡难度组][关卡等级]`
（[ADR 0040](0040-怪物详情页战斗数值口径.md) / [0045](0045-怪物数值合成链补上实例修正值与默认等级.md) /
[0049](0049-怪物数值合成链补上怪物侧精英组倍率.md) / [0050](0050-出没样本带关卡语境与实战面板.md)），
差值只有「谁来算、算在什么落点」。

## 2. 决策

1. **数据落单值**：终局敌方条目增 `hp`（一位小数，取整口径见决策 2），
   在**转换期**由 `monster_common.monster_hp_at` 算好——终局轻形态**不带**合成链输入
   （`stats` / `stat_ratio` / `elite_group` / 曲线表都不进 payload），前端无从自行合成；
   这与 ADR 0045 决策 3「终局敌方卡在转换期并入 stance/speed、前端零合成逻辑」是同一取舍。
2. **算式与取整**：`monster_hp_at` = 决策 1 的四段链，**一位小数、半值向 +∞**——
   对齐前端 `Math.round(v*10)/10`（Python 内建 `round` 是 banker's rounding，`.5` 处逐值不同）。
   缺任一段（基准缺失 / 等级不可用 / 曲线缺组或缺行）**不落 `hp` 键**（宁缺不假，不显示 0）。
3. **关卡语境的落点**：`hp` 逐**关卡行**算——同一敌方在不同 `EventID` 下的等级 / 难度组 /
   精英组不同，故 `_stage_waves_monsters` 按事件逐条算，不是整场一个数。三件套的解析单点
   是 `monster_common.stage_context`（`monster_extra` 的出没样本与 `endgame` 的 HP 共用一份实现）。
   **期级合并列表**（`maze*.json` 的 season 级 `monsters`，供目录卡与 AI 快照）
   没有单一等级语境 ⇒ 不落 `hp`。
4. **展示口径（用户裁决）**：`EnemyCard` 立绘列内、**立绘下方**显示「HP + 数值」，
   数值取 **4 位分组缩写**：四舍五入取整 → 从低位起每 4 位一组 →
   低组**补足 4 位**（`8万0477`）、尾随零组不占位（`1亿` `1亿0001万`）、
   中间零组补位（`1亿0000万0001`，位置信息不丢）。
   单位**按站点语言取字形**：cn `亿/万`、cht `億/萬`、jp `億/万`、kr `억/만`；
   其余 9 种语言没有这套数制（把汉字单位搬过去没人读得出数制），回退 `fmtNumber` 的千分位原数
   （`2,723,431`）。单位表是**语言属性**，与语言列表同处（`lib/i18n/locales.ts`），不进 UI 词典——
   词典的键集是 13 语言对齐的，而这里**只有部分语言有值**。
5. **AI 快照不同步**（沿用 [0026](0026-污染等级进入终局玩法详情页.md) / 0050 取舍）：快照的「敌方配置」块取的是
   **期级合并列表**（无单一等级语境），且快照不复算数值 ⇒ 快照零改动、不出现第二份口径。
6. **「同一算式第二份实现」的边界收窄**：`monster_hp_at`（转换期，非交互单值）与
   `monsterStatAt`（前端，详情页等级滑条实时合成）是**两个落点、同一算式**，
   靠**同值字面量断言互锁**：`tools/converter/tests/test_monster_common.py` 与
   `src/lib/__tests__/monster-stats.test.ts` 各有一例钉住 `332818.7`
   （L95 / 难度组 3 / 曲线 294.42172 / 自身组 1.7 × 关卡组 6.5），两端漂移即红。

## 3. 影响面

- `tools/converter/converters/monster_common.py`：新增 `stage_context`（自 `monster_extra` 上移）
  与 `monster_hp_at` / `_hp_ratio` / `_js_round1`。
- `tools/converter/converters/monster_extra.py`：`_stage_context` 改为导入别名（去掉重复实现）。
- `tools/converter/converters/endgame.py`：`_load_stage_monsters_by_id` 透出 `level_group` /
  `elite_group`（缺位不落键）、`_monster_out` 增 `hp_ctx` 参数并落 `hp`、
  `_stage_waves_monsters` 逐事件传入语境；`_hp_tables` 进程内缓存两张共享表。
- `tools/converter/incremental.py`：`endgame` 登记 `HardLevelGroup.json` / `EliteGroup.json`
  （新的传递依赖）。
- 数据：`public/data/cn/maze{,_extra,_boss,_peak}.json` 增 `hp` 键 **9,807 处**（其余字段逐字不变；
  `*.catalog.json` 保持不动——目录卡字段白名单不含 `hp`）。
- 前端：`services/types/endgame.ts`（`MazeMonsterInfo.hp`）、`lib/format.ts`（`fmtBigNumber`）、
  `lib/i18n/locales.ts`（`BIG_NUMBER_UNITS`）、`components/EnemyCard.vue`、
  `styles/endgame-monsters.css` + `endgame-type-scale.css`。
- 测试：`pytest`（`stage_context` / `monster_hp_at` 的 Π 叠乘、缺位、取整、`_monster_out` 落键）、
  `vitest`（`fmtBigNumber` 四语言口径 + 同值字面量互锁）、
  `e2e/layout-endgame.spec.ts`（逐半场的 HP 文本 + 立绘列几何：列宽不得被反撑）。
- 守卫：`tools/check-ui-chinese.mjs` 的白名单理由补「数制单位字形」（单位在已白名单的 `locales.ts` 内）。

## 替代方案（被否）

- **前端合成（转换器只透出合成链输入）**：否——终局轻形态的 2,337+ 条敌方引用要各带
  `stats.hp` / `stat_ratio.hp` / `elite_group`，且每个场次节点还要带关卡三件套；
  前端另需加载 `monster-level-curve.json`（44.5 KB）+ `monster-elite-group.json`（89.6 KB）
  两张此前终局页不加载的表，并处理异步到位前的空档。为一个叶子数值付这些代价不值，
  且 ADR 0045 已为终局卡定了「转换期并入」的先例。
- **把 `hp` 也算进期级合并列表 / AI 快照**：否——期级列表没有单一关卡语境，只能任选一条关卡行，
  那是**编造**；快照沿用「不复算数值」的既定取舍。
- **13 种语言统一用 `亿/万`**：否——en/de/ru 等页面会出现汉字单位，玩家读不出数制；
  且会让非汉字语言包/界面出现中文（与多语言守卫的判据冲突）。
- **所有语言都用千分位原数**：否——`4,189,894` 这类 9 位数字在 104px 立绘列里必折行，
  与用户「看清」的诉求相反。
- **低组不补零（`8万477`）**：否——与「8 万零 477」同形，量级误读代价高于省下的两个字符。
- **保留一位小数（`272万3430.9`）**：否——「万」后挂小数不常见，且卡片是**扫读**场景；
  原始一位小数值仍在 payload 里可回溯。

## 4. 后果

- [0050](0050-出没样本带关卡语境与实战面板.md) 决策 5 与替代方案「给终局敌方卡加实战面板：否」
  **整条作废**；其决策 2（Π 语义）与决策 4（快照不同步）被本文承接并扩展到终局敌方卡。
- 终局敌方卡与怪物详情页对同一实例的数字不再可能「口径不同」：
  前者是**该关卡行等级**下的一位小数，后者是滑条任意档的实时值——同一算式、不同等级输入。
- 「终局无等级语境」这句话从此失效：`StageConfig` 逐关带三件套，
  凡「终局卡不显示某战斗数值」的新判断都必须先核这三件套，不能沿用 0050 的旧结论。
