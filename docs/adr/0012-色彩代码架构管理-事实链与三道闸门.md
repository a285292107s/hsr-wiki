# 色彩代码架构管理：事实链与三道闸门

## Status: accepted

## Context

ADR 0011 确立了色彩语义（黑阶 + 双色约束 + 领域豁免），但色彩代码的架构规则未定：门禁 `check-colors.mjs` 存在三处盲区——"假中性"豁免（三分量差 ≤25 即放行，`rgba(15,15,35)` 系深底色藏身于此）、`var()` fallback 裸色值不检查（NotFoundView 已 4 处）、SKIP_FILE 豁免面过宽（currency-* 收编后仍豁免）。同时 JS 侧颜色（SVG data URI 内联白、富文本 `<color>` 标签）与"导航语义金"（首页网关入口卡、交换按钮双色状态点）缺少显式规则——既会被误伤，也易被误扩展。

## Decision

1. **事实链单向依赖**：原始层（tokens.css 单文件分区 = 事实）→ 语义层/领域层（tokens.css 内映射）→ 消费层（页面 CSS + JS 模板字符串，只读 `var()` / `color-mix` / CSS 变量注入）。消费层禁止定义任何颜色事实；tokens.css 保持单文件不拆分，以区段注释分区（原始/语义/领域），门禁守住边界。
2. **门禁升级为规则豁免**（check-colors.mjs）：① 中性判定阈值从差 ≤25 收窄为 ≤4（纯黑/白/灰阶才豁免，暴露假中性）；② `var()` fallback 内色值纳入检查（fallback 必须为中性或令牌引用）；③ SKIP_FILE 收窄——currency-* 在 CW 收编完成后移出豁免，debug 诊断色（SpineAudit/SpineDebug）永久豁免。
3. **豁免三分类登记**（工具内常量区块，带理由引 ADR）：
   - **中性豁免**：纯黑/白/灰阶 + SVG data URI 内联白（物理限制——data URI 内无法 `var()`）
   - **领域色豁免**：`--rarity-*` / `--prop-*` / `--elem-*` / `--skill-*` 等数据语义色，机制由领域层令牌天然守住（ADR 0011 §4）
   - **导航语义豁免**：首页网关入口卡金色、交换按钮双色状态点——"金色=CW 模式"的导航标识，双色约束的导航例外
4. **JS 侧三规则**：① SVG 内联中性白豁免登记；② `var()` fallback 裸色值一律删除（tokens.css 在 `:root` 全局定义、变量必有值，fallback 为防御性残留）；③ 富文本 `<color>` 标签登记为**数据承载色**——游戏数据自带颜色，运行时透传 inline style，不参与令牌体系（与官方标签透传原则一致，见 ADR 0008/0010）。
5. **评审闸流程化**：新增颜色四步流程——查令牌 → 定层级 → 双色约束判定 → 落 tokens + 跑门禁，落 `docs/audit/色彩收口流程.md`（沿用字段审计流程模式）。

## Considered Options

- **拆分 tokens/color.css**：物理独立便于未来换肤，但量级尚小（约 100 行）、CSS 变量全局无隔离收益、引入 import 顺序成本。被拒——YAGNI，拆分动作本身不产生用户价值。
- **独立 color-policy.mjs 策略文件**：豁免清单与执行分离、可复用，但工具仅 99 行且无第二消费者。被拒——长出第二消费者（如 CI 徽章/文档生成）再抽。
- **保留中性灰 fallback（建灰阶白名单）**：NotFoundView 的 `#e2e8f0` 带蓝相、不在严格中性内仍需特判，白名单引入新灰阶定义。被拒——fallback 在"变量必有值"下是死代码，删除最干净。
- **豁免仅文档维护**：ADR/CONTEXT 人工记录——文档必然漂移，假中性会重新溜进。被拒——豁免必须在代码留痕、可评审。

## Consequences

- `check-colors.mjs` 重构为规则豁免模式：严格中性判定、fallback 检查、豁免三分类清单（常量区块）三个组成。
- NotFoundView 4 处 fallback 色值删除（保留 `var()` 裸引用）；CharHero SVG 内联白、format.ts `<color>` 透传登记入豁免清单。
- 实施顺序挂接 ADR 0011：阶段②页面收编完成后 currency-* 移出 SKIP_FILE；阶段③门禁升级 + `pnpm build` / `pnpm test` 全绿。
- 新增 `docs/audit/色彩收口流程.md`（评审闸四步流程）。
- 后续新增颜色一律走评审闸四步；豁免清单变更须同步更新 ADR 引用，防止豁免误扩展。
