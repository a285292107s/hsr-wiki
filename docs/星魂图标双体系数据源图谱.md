# 星魂图标双体系数据源图谱

> 分析对象：角色星魂（Eidolon / Rank）的图标数据源，跨 `AvatarRankConfig` / `AvatarStatusConfig` / `StatusConfig` 与 CDN 资源。
> 数据来源：`vendor/TurnBasedGameData`（ExcelOutput + TextMap）；资源存在性经 jsDelivr（官方 StarRailTextures fork）与 nanoka CDN 实测。
> 结论前置：**星魂图标存在两套独立体系**——`AvatarRankConfig.IconPath`（本体展示 / 技能卡强化栏）与 `AvatarStatusConfig.StatusIconPath`（战斗 buff 栏）。前者 E1-E6 引用齐全，后者仅覆盖有独立 buff 效果的星魂。

---

## 一、两套体系总览

| 体系 | 数据源表 | 字段 | 路径目录 | 覆盖范围 | 前端用途 |
| --- | --- | --- | --- | --- | --- |
| 本体展示 | `AvatarRankConfig`（+LD/Trial） | `IconPath` | `SpriteOutput/SkillIcons/Avatar/{id}/SkillIcon_{id}_RankN.png` | **E1-E6 六个引用齐全** | 星魂面板（`eidolonIconUrl`）+ 技能卡强化栏（`rk.icon`） |
| buff 栏 | `AvatarStatusConfig`（+LD）/ `StatusConfig` | `StatusIconPath` | `SpriteOutput/BuffIcon/Inlevel/Avatar/Icon{id}Rank{NN}.png` | 仅 21 角色部分星魂 | 战斗 buff 图标（前端未接，bufficon 分类已注册） |

## 二、AvatarRankConfig.IconPath（本体展示）

### 结构规律（全库 606 条验证，101 角色满 6 星魂）

- **E1 / E2 / E4 / E6**（机制星魂）：指向专属文件 `SkillIcon_{id}_Rank{1,2,4,6}.png`
- **E3 / E5**（纯技能等级加成星魂）：`SkillAddLevelList` 非空，`IconPath` **不引用 Rank3/Rank5**（全库 0 处引用），而是指向所加成主技能图标：
  - E3 = `SkillIcon_{id}_Ultra.png`（终结技型 ×38）/ `SkillIcon_{id}_BP.png`（战技型 ×63）
  - E5 = `SkillIcon_{id}_BP.png`（×38）/ `Ultra`（×62）/ `Normal`（×1）
  - 与 `SkillAddLevelList` 加成对象严格对应（如 1510：E3→151003 终结技+2、E5→151002 战技+2）

### 资源存在性（jsDelivr 官方仓库实测）

| 文件 | Rank1/2/4/6 | Rank3/5 |
| --- | --- | --- |
| `skillicons/avatar/{id}/SkillIcon_{id}_RankN.png`（jsDelivr） | ✅ 200 | ❌ **404（官方无文件）** |
| `SkillIcon_{id}_Ultra/BP/Normal.png`（E3/E5 引用） | ✅ 200 | — |
| **`ui/ui3d/rank/_dependencies/textures/{id}/{id}_Rank_{num}.png`**（jsDelivr） | ✅ 200 | ✅ **200（官方星魂展示源）** |

### 本体展示 E1-E6 全套的完整源

**官方仓库 `asbres/ui/ui3d/rank/_dependencies/textures/{charId}/{charId}_Rank_{num}.png` 收录 E1-6 全套（含 skillicons 目录缺失的 Rank3/5，1403/1510 实测全 200）**——这是星魂面板展示图片的官方源。nanoka `rank/` 分类（`rank/_dependencies/textures/{charId}/{charId}_Rank_{num}.webp`）为同构镜像（去 `ui/ui3d/` 前缀 + png→webp）。

> ⚠️ **路径体系差异（溯源陷阱）**：`ui/ui3d/rank/_dependencies/textures/` 是**客户端资源包物理路径**，在子仓库（TurnBasedGameData，124,031 个 JSON 全量扫描）中**无任何字段引用**——子仓库的星魂图标引用只有 `SpriteOutput/SkillIcons/...`（AvatarRankConfig）与 `SpriteOutput/BuffIcon/...`（AvatarStatusConfig）两类逻辑路径。`assets/asbres/spriteoutput/` 是 SpriteOutput 逻辑路径的镜像（可推导），但 `ui/ui3d/` 区独立于 spriteoutput 镜像，**无法从子仓库数据推导，只能靠资源仓库目录实测发现**。

```
官方（jsDelivr 首选）: https://cdn.jsdelivr.net/gh/a285292107s/StarRailTextures@main/assets/asbres/ui/ui3d/rank/_dependencies/textures/{charId}/{charId}_Rank_{num}.png
nanoka（回退）     : https://static.nanoka.cc/assets/hsr/rank/_dependencies/textures/{charId}/{charId}_Rank_{num}.webp
```

前端 `eidolonIconUrl(charId, rankNum)` 经 `cdnUri('rank', ...)` 自动双源解析（`JS_DELIVR_RULES` 已注册 `rank` 规则：官方首选 + nanoka 回退）。注意该目录与 `spriteoutput/` **平级**（`assets/asbres/ui/...`），前端以独立常量 `JS_DELIVR_UI3D_BASE`（`JS_DELIVR_BASE` 去掉 `/spriteoutput` 后缀）拼接，`resolve.ts` 对 rank 分类特判基址，`cdnFallbackFromPrimary` 按 `ui/ui3d/rank/` 标记反查。

## 三、AvatarStatusConfig.StatusIconPath（buff 栏）

### 结构

- 736 条（+LD 43 条），字段：`StatusID` / `StatusName` / `StatusType`（Buff/Debuff/Other）/ `StatusIconPath` / `StatusIconPathHighSize` / `StatusDesc` …
- 星魂 buff 图标命名：`Icon{id}Rank{NN}.png`，**位数不统一**：`Rank01`（1004/1015/1101/1102…）、`Rank4`/`Rank6`（1403）、`Rank02CD`（1224）、`Rank02_Time`（1310）
- 技能/行迹 buff 图标同目录：`Icon{id}BP/Ultra/Passive/SkillTree2/Maze/AssistSkill02…`、通用 `IconBuffXxx.png`

### 涉及角色（21 个，含 LD）

1004(01)、1015(01)、1101(01)、1102(06)、1112(01)、1205(06)、1220(02)、1224(02CD)、1310(02_Time)、1313(01)、1314(04)、1315(02)、1317(01)、1401(06)、**1403(4/6)**、1407(02)、1506(02)、1507(02)、1509(01/06)、8007(02)、8009(01)

## 四、前端使用约定（现状）

| 场景 | 实现 | 图标源 | 说明 |
| --- | --- | --- | --- |
| 星魂面板（EidolonsPanel） | `eidolonIconUrl(charId, num)` | rank 分类双源：jsDelivr 官方 `ui/ui3d/rank/`（E1-6 全套）+ nanoka 回退 | 与 `rk.icon`（buff 图标）不同源，勿混用 |
| 技能卡强化一栏（SkillCard ratedLinks） | `iconUrl(rk.icon)` | `rk.icon` = AvatarRankConfig.IconPath 映射 | E1/E2/E4/E6 → RankN；E3/E5 → 技能图标（设计如此） |
| 战斗 buff 图标（未接入角色页） | `cdnUri('bufficon', ...)` | AvatarStatusConfig.StatusIconPath | 资源未就绪，前端已有 SVG 占位机制 |

> 陷阱提醒：E3/E5 的 `rk.icon` 指向 Ultra/BP 是**官方设计**（非数据缺失），本体展示须用 `eidolonIconUrl`（Rank{num}，官方 `ui/ui3d/rank/` 源 E1-6 全套）；勿用 `rk.icon` 或按 `Rank{num}` 硬拼 `skillicons/avatar/` 目录（该目录 Rank3/5 官方 404）。
