# 0031. 末日幻影层级敌方取实际战斗数据

## 状态

`accepted`（**已实现**：`endgame.py` 的 `_load_boss_phases` 与 `floor_details[*].phases` 输出下线、`ChallengeBossMazeExtra` 移出 `endgame` 模块源表；`EndgameBossFloor.vue` 的层级节点改为只渲染上下半场（敌方取 `stage1/stage2`）；`EndgameTierce.vue` 给节点 1/2 补「同第 N 层 · 上半场/下半场」同源标注（**文案被 [ADR 0032](0032-星启节点按完整场次渲染.md) 收缩为「同第 N 层」**）。**修订 [ADR 0026](0026-污染等级进入终局玩法详情页.md) 决策 3 与 [ADR 0030](0030-末日幻影详情页层级星启子tab.md) 决策 2 的节点条款**）

## 背景

用户复核 `/endgame/boss/3020` 详情页，给出判据：**第 4 层应该只有上下半场；只有星启模式有 3 场战斗（= 第 4 层两场 + 星启附加关一场），且星启模式的挑战目标和奖励是另一套**。逐项核对后，页面与数据在三处不符：

1. **末层多渲染了一场**：层级节点原按 `floor_details[*].phases` 渲染（源 `ChallengeBossMazeExtra` 的 `MonsterID1/2/3`）。全库 22 赛季 × 4 层 = 88 条层记录里，`phases` 长为 3 的恰好 5 条 —— 正是含星启的 5 个赛季（3018 / 3019 / 3020 / 3021 / 3022）的第 4 层，其第 3 项与星启附加关（Tierce 表 `JEBMBCLBIOI` / `HFIAAGAKFMD`）同源。于是「阶段 3」在层 tab 里凭空成为该难度的第 3 场战斗。
2. **下半场敌方被换成指南别名**：`phases` 的第 2 项是 `ChallengeBossMazeExtra.MonsterID2`，在 3011 / 3016 / 3020 三个赛季共 12 层里登记的是「蛊言妄念的蚀心兽 `2033022`」，而该场战斗的实际敌方是「业火焚心的影将军 `2035012`」——层 tab 的下半场与星启 tab 节点 2 对同一场战斗显示两个名字（ADR 0029 的替代方案表早记过这条判据陷阱）。
3. **权威数据本来就在产物里**：`stage1/stage2`（`EventIDList1/2` → `StageConfig` 波次）88 层全部有敌方，且含护卫（如 3018 的杰帕德）与波次序号。对照站 nanoka 的 `/boss/3020` 数据同时带 `boss_monster_id2 = 203302204`（extra 口径）与 `event_id_list2.monster_list = [203501204]`（战斗口径），其页面显示的是后者（影将军）。

星启侧数据本身与用户表述一致、页面也已渲染：3 节点 = 末层上下半场同关卡 + 星启附加关；挑战目标 = `OGEOMCGNNMP` 3 档 + 满分档 `GNGENMHNLAH` 并入末位（末日幻影 6000 / 7800 / 9900 / 10200，对层级 3 档 4000 / 5200 / 6600）；通关奖励 = `EGEEJLHBALB` 8 项。

## 决策

1. **层级节点只渲染上下半场**：`EndgameBossFloor.vue` 遍历 `stage1/stage2`，标签为「上半场 / 下半场」，敌方、推荐属性、污染徽标全部取该半场字段；星启附加关不在层 tab 出现。
2. **`phases` 字段与 `ChallengeBossMazeExtra` 读取一起下线**：删转换器字段（`_load_boss_phases` 及 `_season_floors` / `_group_seasons` 的 `phases` 入参）、删前端类型 `MazeFloorDetail.phases`、把该表移出 `incremental.py` 的 `endgame` 模块源表清单。理由：该表逐项就是节点，节点 1/2 的取值可能是指南别名、节点 3 星启表已有，产物里留一个错口径字段只会被再次误用。
3. **星启 tab 标出同源关系**：节点 1/2 的行头补「同第 N 层 · 上半场/下半场」（N = 该赛季 `floor_details` 的最大层，与 Tierce 表的 `DLCKKJFMJOB` 同指；13 条星启记录实测两者逐条相等），节点 3 不标。**文案被 [ADR 0032](0032-星启节点按完整场次渲染.md) 修订**：节点改扁平场次卡后标题本身已写「上半场/下半场」，标注收缩为「同第 N 层」。**本条再被 [ADR 0033](0033-星启模式改单节点看板.md) 决策 9 修订**：用户裁决看板行头只留节点号，「同第 N 层」标注整体退场（`.nk-egd-tierce__nodefrom` 样式与 `nodeOrigin()` 一并删除）。

## 后果

**正面**

- 层 tab 的场次数与游戏内一致（每难度两场），末层不再出现星启附加关的重复卡片。
- 层与星启两处对同一场战斗显示同一个敌方（影将军），消除 12 层的别名错显。
- `ChallengeBossMazeExtra` 退出 `endgame` 的模块源表后，该表更新不再触发四份终局 JSON（`maze.json` 约 2.9MB 等）全量重转。

**负面**

- 层级敌方完全依赖 `StageConfig` 波次：上游若出现「只登记 `NpcMonsterIDList`、波次为空」的层，该半场会空渲染——实测 88 层无此情形，属已观测为零的风险，不做兜底。

**中性**

- **星启「回合限制」未改动**：`GNOOAGPBNLD`（回合）只存在于 `ChallengeMazeTierce`（忘却之庭 = 45），末日幻影 / 虚构叙事的 Tierce 表没有该字段，对照站同样不输出——现状（`countdown = 0` → 不显示）与上游一致，不是丢字段。三张 Tierce 表共有的 `PHOIICMCGIH`（5–11 的整数）与波数、怪物数、回合、目标数、满分档都对不上，上游结构与对照站都无法确定其语义，按「不硬列无标签数值」的先例记为**未解字段、不消费**（见 [docs/data/转换器字段映射.md](../data/转换器字段映射.md)）。
- 同源标注写在 `EndgameTierce` 里，对三种模式的星启区块一并生效（同一组件、同一事实：节点 1/2 就是常规末层上下半场）。另两种模式的星启区块是赛季级章节而非层级子 tab，是否要为它们改写文案（如改动措辞）留给后续。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 保留 `phases` 但层 tab 只取前两项 | 第 4 层场次数对了，但下半场仍显示指南别名「蚀心兽」，与星启节点 2 的「影将军」自相矛盾 |
| 保留第 3 项、只在层 tab 标注「星启附加关」 | 与「层 = 该难度的两场战斗」的游戏结构冲突，且星启 tab 已完整承载该节点 |
| 保留 `phases` 字段（标 legacy）只改前端 | 产物里留下会被再次误用的错口径；ADR 0029 已踩过一次同类判据 |
| 只对第 4 层特殊处理（前三层继续走 `phases`） | 前三层的 `phases[1]` 同样是指南别名（3011 / 3016 / 3020 共 9 层受影响），特殊处理只修一半 |
| 用 `PHOIICMCGIH` 当星启回合限制显示 | 语义无据：与源表任何可验证量都对不上，且对照站不呈现该字段 |
