# UI 令牌与样式

> 本域补 [ui-design.md](../agents/ui-design.md) 的盲区：该文件写「规则是什么」，本文件只写规则推不出的**静默失效坑位**与**判据的理由**——为什么这样判、不这样判会在哪一步踩到。

## 静默失效：不报错但结果错

- **`:has()` 写完必须量「实测命中几条」**：它与 DOM 里有没有同级兄弟强耦合，视图加一个同级元素（如 `<aside>`）就永久失效，且完全静默——选择器合法、守卫全绿。实例：`:has(…:last-child:first-child)` 自写下起从未命中。`catalog.css`
- **结构性派生一律用 `:has(> …)`，不要用兄弟/位置伪类**：父级竖轨写成 `.nk-skill:has(> .nk-skill--child)` 才只在真有子卡时渲染，单卡族/无族退化路径不出悬空线；网格同理，否则对比模式复用同一 `__body` 时会被改成两列。`character-skills.css`
- **跨层「开关 / 选项」类参数，落地后必须做一次运行时取证确认到达消费点**：漏传是静默退化。实例：未把 `firstStageLayers` 传到 `createScenePipeline`，分阶段加载静默退回单阶段，`build`/`test`/守卫全绿，唯一证据是网络时序。
- **目录卡的字段必须在映射层显式带出来**：`renderCard` 只拿到映射层构造的对象，读未映射字段恒为 `undefined` 且不报错——表现为 `title` 静默为空。`pages/item.ts`
- **只给部分属性写缓动等于没写**：未写的静默回落浏览器默认 `ease`。曾有 11 条此类声明；`.nk-tab` 曾有两条互相竞争的 transition，后写的生效。改后要静态检测「裸时长」为 0。
- **`:hover` 改过的属性必须在 `@media (hover: none)` 里同步复位**，且展开态单独重新声明（`.open:hover`）：该媒体块在文件末尾，同特异性下会盖掉基态，触屏上展开中的按钮掉色回灰。
- **`focus-visible` 共享组里的 `border-radius` 会改按钮本体圆角**：组内该声明本意是给 outline 定形，对无可见盒子的文字按钮无害；按钮一旦有了圆角盒，聚焦瞬间跳形。此类必须单列复位、不进共享组。
- **同权重档位规则混写会让断点规则被非媒体规则反压**：两个 CSS 的档位规则权重都是 0,3,0、靠源序判定；把手机档规则写成非媒体查询 ⇒ 平板断点内两条并列命中、后写的非媒体规则胜出。**每个断点每一档只允许一条声明**。
- **清理「被后写覆盖的声明」前先比特异性**：特异性更高的那份从来不是死代码。终局页 40 余条死声明中唯一必留的是 0,2,0 的那条，压不住收口块的 0,1,0。
- **`check-contrast` 只算「文字令牌 × `--bg`」**：文字落在 `--surface`/`--card`/着色片（tag·chip·激活段）上还要再降一档，这一层只有 axe（4 页 × 缺省色）兜底；两处都覆盖不到的组合必须人工按 sRGB 合成核算。
- **对比度必须取该元素实际解析出的背景色**：拿 `--bg`/`<body>` 当背景会系统性高估。实例：探针把手机底栏文字算成 7.3:1，而真实底色是底栏的 `#1e1c1d`，实际 4.07:1——背景取错让结论偏移一个量级。
- **带 alpha 的令牌必须先与紧邻像素合成再算对比度**：直接用 rgb 三元组会把文字算亮。
- **大字号的阈值不同**：≥24px（或 ≥18.66px 粗体）判 3:1 而非 4.5:1。hero 名称 43~54px 属此档，按 4.5:1 判会得出「名称也不达标」的假结论。
- **axe 默认标签只覆盖 WCAG 2.0/2.1 的 A+AA**：`wcag22aa` 新增规则（`target-size` 等）默认不跑，`enabled: false` 的规则会静默通过。声明「跑 2.2 AA」前必须显式 `withTags`。
- **口径声明与执行必须逐项对齐**：a11y spec 曾被 mobile 项目 `testIgnore` 排除 ⇒ 手机独有的对比度路径（底栏标签只在 <768 显示）从未进过流水线。须核规则集 × 视口 × 排除项三项。
- **`region` 命中数 ≈ 页面内容块数，不是「个别元素」问题**：正文没有 landmark 时一次命中 69~77 个节点，读屏用户只能从头听到尾。修法是三种态外层包 `<main>`。
- **有可见文字的图片必须装饰化（`alt` 与可见文字二选一）**：否则读屏念两遍。同一模板里两类槽的策略必须分开判——看它旁边有没有可见文字。
- **CSS 语法损坏不一定被守卫拦住**：少分号会让四条声明（`color` + `letter-spacing` / `font-weight`）静默失效。**三守卫全绿不等于语法正确**。
- **`tokens.css` 尾部无障碍三件套曾整块重复**（三个规则各两遍）——静默死代码，守卫不查。
- **`!important` 的 `transition` 简写会把 `transition-property` 整体限死为它列出的属性**：未列出的属性（opacity / transform）的插值被静默吃掉，表现为「动画没播」。判据 = computed `transition-property` 不含目标属性 + 零中间帧；**排查「动画没播」要先看 property，只看 duration/delay 会误判成「时长没生效」**。修法是收窄选择器（`*:not([class*="nk-view-"])`），不是拆成逐属性写法（实测不成立）。`src/styles/tokens.css`、`src/app/App.vue`
- **删掉一个「死样式/死层」会改变它曾遮住的另一层的可见度**：纯 A/B 差值只反映净效果，看不出「原来是它挡着」——左右渐隐 `::before`（`z-index: 1`）画在 inset `box-shadow` 之上，删掉后最外圈暗角反而更明显。**判死代码前先查它是不是某层的唯一遮蔽物。**`src/styles/character.css`
- **全局重置的双重静默失效**：① `#id 元素` 形态的重复副本特异性 (1,0,1) 会压死类选择器的间距；② 重置清单漏 `h4`/`h5`/`h6` 则 UA 的 `1.33em` 外边距泄漏。`src/styles/tokens.css`、`catalog.css`、`currency-hub.css`
- **删「页面级覆写」≠ 取消**：删掉整条规则会**回落到基线更重的值**（光锥 hero 的暗角是覆写基线两层更重的 inset，删规则反而更暗）。必须显式 `box-shadow: none` / `background: none`（`::before` 同理）。`src/styles/lightcone.css`
- **数字统一格式化时三类不得动**：① 标识符 ID（加千分位后更难核对）；② 数据正文里的数字（那是游戏原文，重排等于改写数据文本）；③ 已带单位的百分比 / 星级 / 费用。`src/lib/format.ts`
- **只在 hover / focus / active 才换色的元素，其文字对比度从未被默认态扫描覆盖**：「悬停后掉到 4.5:1 以下」只存在于交互态。须逐元素 `hover()` / `focus()` 后**在该状态**跑 `color-contrast`。

## 令牌收口与迁移

- **改主题色 = 必须全仓搜「为旧主色明度写的对比补偿」**：浅金时代沉淀了一批「浅底深字」补偿（`color: var(--blk-900)`、进度条渐变、局部令牌覆盖），换赤陶后白字才对。静态审查看不出「这条只在旧色下才对」，可靠办法是让 e2e 跑一遍。（ADR 0041）
- **与主题通道绑定的原始层色阶要逐个查消费点**：CW 候选色阶通道退场后，四族里只剩一族有消费者。
- **改底色必须与表面阶梯同批上移**：只改 `--bg` 会在某一亮度以上让 `--surface` 比页面更暗。（ADR 0021）
- **领域色不得引用别名层**：遗器徽章从 `--th-300` 改语义位 `--metric-val` 即此类纠正。
- **`--elem-*` 七个令牌全仓零消费者**：故「让角色页用上属性身份色」是零新颜色、零四步评审的改动；但扩展成 hero 整块会撞双色约束，需单独裁决。
- **页面级共享原语改造必须作用域化**：`.nk-title` 被六页消费。「改了某页 CSS 会不会波及别页」的第一步应该是**数根类名的写入方**（某根类全仓只有一处写入 ⇒ 天然不外溢），而不是先跑全量 e2e。
- **跨页借用的共享 class 只能是 `tokens.css` 已声明的原语**：借另一页的页面级 class，其 CSS 只随该路由 chunk 到达，跨页命中不了样式——**unseen 破相而不报错**。
- **`scrollbar-color` 写在 `#app` 上即可**（继承属性，一处覆盖全部滚动容器）；但**不要顺手加 `scrollbar-width: thin`**——细滚动条让容器宽出约 7px，虚拟网格格宽与像素基线连锁变化。
- **`::selection` 提为全局时页面级那份必须同时删除**（同一事实只留一处）；环境层同理收口成单点事实源，四个页根转透明。
- **刻度收口后 `calc(刻度 ± n)` 是离刻度值的藏身处**：它字面上引用了令牌，却把结果推离刻度。**复审刻度一致性时要专门扫 calc 表达式**，不能只查字面量。

## 字阶与圆角刻度

- **容差必须按量纲分层，否则会「压平有意的设计」**：一律 1.2px 容差 ⇒ 300+ 处进人工裁决队列（响应式 `clamp` 与特写尺寸必然超差）。终态：正文/界面字号 1.2px、标题与特写 4px、圆角 6px。
- **刻度 codemod 只写「就近落档」、不做等距化**：目的是让取值来自刻度，而不是借收口之名重新设计字号。
- **动字号前先找「谁按字号算过尺寸」**（槽高、行盒、图标盒、骨架代理盒）：槽高 = 本档主字上限 × 行距，骨架屏靠它代理固定盒高，改字号不改槽高 ⇒ 骨架↔就绪错位。该页有三套槽高，且**单字档与多字档各一个**（单字字号更大）。
- **改任何一处字号都要跑「全量数据 × 2 断点」的盒高中位数探针**：抽样集会因新档位占比算错（某档在抽样里 0 只）。同一页曾三次因字号改动而重测。
- **骨架与就绪的盒高必须同源消费单一令牌**：收口后就绪高 = `max(内容高, 令牌值)`，两态同框由构造成立，不再依赖「常量恰好等于内容高」这个 0.19px 级的巧合。
- **同类交互的「写法不同」比「用哪个值」更值得修**：同一类悬停曾横跨五个族五种时长 + 两种曲线。时长分档要由令牌承载，**契约从令牌读期望值**——改档不会让用例变红，只有组件自造值才会。
- **动效分档按「改哪些属性」归位**：卡片**表面**（border-color/box-shadow/transform/opacity）→ normal 档，**标签**与控件（color/background/filter）→ hover 档，图片放大 → zoom 档。
- **页面设计语言声明的档位必须能在实测里数出来**：某页头部声明三档圆角，实测出现 7 种。归一要**按语义归类比脚本盲替可靠**——同一个 6px 落在图标、chip、按钮上应分别归到内联档与容器档。
- **契约要跟着语言收窄**：从「非圆形且 >20px 即红」升级为四值白名单（容器档期望值从页面令牌派生）。**清理必须配契约，否则只是「这次干净」**。
- **全局 `--nk-radius-card` 与页面声明冲突时，第三条路是页面另立一名**，只动本页 CSS——不要为单页去改全局 token。`50%` 与胶囊是**形态**不是档位。
- **`--nk-prose-max` 必须按字号缩放且消费在承载正文的那一级**：`em` 按元素自身字号解析，落在容器级上会得到完全不同的每行字数。

## 几何与形态判据

- **「元素类型差异」的可见性取决于布局是否把文字盒拉伸**：UA 给 `<button>` 声明 `text-align: center`，单行/收缩盒里它是空转，纵向 flex 把子项拉满时才显形。故不能靠读样式表判定，要跨标签比对计算样式 + 做「改掉这个值再量 ink 位移」的差分。
- **任何 `max-content`/`fit-content` 轨，只要轨内元素的固有宽度由懒加载图决定，就必须写确定值**：图未加载时塌成文字宽、到达后涨到固有宽 ⇒ 同分区两张卡差 2.5 倍 + 首屏一次 144px 位移（CLS）。
- **flex item 的 `min-height: auto` 在 `overflow != visible` 时降为 0**：column flex 容器里唯一带 `overflow: hidden` 的子项会被压塌到几十像素——详情页 Hero 曾因此把页面主标题压到不可见，而既有详情页 Hero 恰好都没写 `overflow: hidden` 所以从未暴露。修法是给该子项 `flex: none`。
- **`auto-fill` 与 `auto-fit` 在固定条目数下行为相反**：`auto-fill` 在建轨阶段按可用宽度铺满、末行空轨**不收回**（宽屏下留一大块空白）；`auto-fit` 空轨塌缩。本仓惯例是 `auto-fill`（几百条目的卡片墙），**固定条目页必须用 `auto-fit`**。改列数时还要连带检查基线的「跨列 / 满行」规则（如 `:last-child:nth-child(odd) { grid-column: 1/-1 }`）——项数 % 列数 ≠ 0 时必然把末项顶成独立整行。
- **「名字是最长字段」的卡片，列宽下限必须由数据里的最长值反推**：不逐页翻，而是**把数据集里会出现名字全量喂给浏览器按真实字体测宽**，再与各断点可用宽度比较。
- **落点与命中判定不能取同一个边界值**：取同一个值会有 0.2~0.4px 抖动时判定翻转（「点附件、亮技能」）。修法是落点比偏移线多让出几像素——滚动少走几像素用户看不见。
- **锚点规则本身无解时要显式建状态，而不是继续调阈值**：页尾短区块永远排在长区块之后且已到滚动上限，任何「顶边越线」类规则都判不出它。正解 = 把「用户点到的就是当前的」建成显式状态。
- **凡「A 时刻算目标、B 时刻到达」的机制，都不能用静态窗口去校验，要用「到达信号」**：落点用「±24px 窗口」实测恒偏 40px（滚动过程中页面继续 reflow——懒加载图、字体、Spine 就绪）。正解是等滚动静默后复算，并覆盖 reduced-motion 分支（该分支没有滚动动画，必须自己释放）。
- **定位伪元素的包含块原点必须用真实哑元元素实测，禁止靠名词推导**：「padding box」有「外缘/内容区」两种口语含义。实测：包含块是宿主 padding box 的**外缘**，页面坐标 = `hostRect.top + css top`，**不加 padding**。
- **相对另一元素定位的装饰线，坐标必须相对同一个原点表达**：折角 `top` 相对 padding box、而注释里的「行顶」指卡顶 ⇒ 实现出来比图标中线低一个间距。
- **间距/尺寸类需求先把「单位 = 哪个既有令牌的整数倍」问定，再谈数值**：同一处缩进被连续三轮修正，前两轮都在数值层应答，从未问过单位/基准——用户的模型是「缩进必须等于既有尺寸的整数倍」。
- **方位词（正下方/中间/之下）必须当场落到具体参考点（哪条 x、哪条边）并配对比图**：靠形容词定几何，同一处会连续两轮来回改。
- **当既有形态在小视口上只剩「无承载物的结构」时，正确解是让结构在该断点退场，而不是继续调它的数值**（同一模式在留白归零、枢纽页、缩进三处共出现四次）。
- **`space-between` 在负剩余时静默退化**：它只在剩余为正时生效，负剩余会退回 `flex-start` 并把内容挤进 padding 区。「固定盒高 + 均分」必须同时保证内容总高 ≤ 盒内容高。
- **骨架只代理「盒子」，不代理「结构」**：写一个「结构忠实」的小骨架反而更糟——就绪面板在窄断点因换行会显著变高，忠实小骨架变成欠预留。正解 = 固定盒高（取实测中位数）+ 内距逐档对齐 + 间距交给 `space-between`。
- **两个宿主共用的版面事实（如底板）必须只声明一次**：分成两处必然漂移，表现为数据到位时凭空弹出一块暗板。盒高对齐前必须先对齐内距，否则会把内距差算成盒差。
- **「数据里有、UI 里没有」要当成缺陷来查**：查法 = 拿数据字段清单与卡片模板比对。
- **内容覆盖审计的价值在假阳性分类**，不在「报了多少条」：直接拿原始 JSON 串去 `innerText` 里 `includes` 会有 90% 噪声。四类必查——占位符模板（须用**渲染后的值**比对）、枚举键（须比对本地化标签）、折叠内容（须先展开取状态并集）、换行/富文本（`\n` → `<br>`、剥标签后两侧归一）。
- **触控命中区要按命中区量，不按视觉盒**：靠 `::before { inset }` 扩热区时只有 `elementFromPoint` 自中心向外扫才量得真实值；**扫得的是「自中心的半径」，命中宽高 = `left + right + 1`**，把视觉盒与半径相加会得出假值。
- **命中盒不能只看元素自身几何**：宿主是 `<label>` 时整块可点、是 `<div>` 时不可点——用真实点击落点验证。
- **铺量脚本里不要测命中区**（固定层遮挡 / 异步滚动下恒返回假数）；命中区交给逐组件专用探针。**宁可把指标留给专用探针，也不要在铺量脚本里出一个看似权威的假数字。**
- **铺量探针与契约探针必须共用一套豁免判据**（排除 `position: fixed` 层、排除「祖先 `overflow-x: auto/scroll`」内的元素），否则两边结论永远打架。
- **渐进增强的正确形态是「不支持 = 静态还原」，不是「不支持 = 停在末帧」**：`fill: both` + 时间轴驱动的动画在不支持滚动驱动动画的引擎上会跑完并停在末帧，媒体层位移恒为 36px——这不是「少个视差效果」而是构图永久偏移。凡此类动画都必须包 `@supports`。
- **越界判据不要豁免「被祖先裁剪」**：只豁免**用户可横向滚动到位**的祖先（`overflow-x: auto/scroll`），`hidden/clip` 不豁免；并先等过渡类消失再测量。
- **溢出列表若呈「整页同向位移」且首项带过渡 `-active` 类 ⇒ 过渡态假阳性**，不是布局缺陷；真溢出是局部元素、各处越界量互不相同。
- **容器的「不透明底色」与页面底色同值时，唯一可见效果是把 fixed 背景的环境光裁成一块矩形**——那是缺陷不是材质。**给区块加底色前先问「这层底色的可见效果是什么」**；上面有 fixed 背景/环境光层时，实测它被裁成了什么形状。`src/styles/endgame-detail.css`
- **网格里 `display: none` 的格子不占轨** ⇒ 自动布局的稀疏推进不可依赖；**后续格必须显式写 `grid-column`**，否则被甩回第一列并撑出横向溢出。`src/styles/endgame-detail.css`
- **flex 行内要让名称可压缩**：给 `overflow: hidden` 即取得自动最小尺寸 0；反向的 `flex-shrink: 0` 会让该元素的 ellipsis **完全失效**，整串越出列框压到相邻列。`src/styles/endgame.css`
- **异步补入的内容会撑高区块、把下方整体推下去** ⇒ 必须在「就绪态翻转」之前 await 取数，否则这段高度计入 CLS。`useCwReleaseShowcase.ts`、`ReleaseShowcase.vue`
- **CSS 分栏（`columns`）不要给子项覆写 `display` / `width`**：行本身是 flex 行，改成 block 会压成上下堆叠、整页反而变长；分栏只需 `break-inside: avoid`。`src/styles/endgame.css`
- **别把 UI 页签小图（144×144）用 `cover` 当背景大图**：先量 `naturalWidth` 与显示盒，放大 > 2 倍必然糊；背景用色彩/渐变，图标只在原尺寸内缩处用。`src/app/catalog/pages/endgame.ts`
- **同一页同类区块必须同左缘，判据取「盒左缘」而不是文字左缘**：区块标题自带 `padding-left` + `border-left`，拿文字左缘比会假红。`src/styles/currency-trait-detail.css`
- **「横向可滚」不等于「用户能找到」**：横滚容器必须给溢出提示，且提示**只在真溢出时出现**（用 `mask-image` 渐隐，不引入新颜色块）。`src/styles/catalog.css`
- **CLS 取证必须 dump 位移节点（`layout-shift.sources[].node`）**，只报数值查不出病根。图片**未解码时不产生盒子**：`max-width` 不定宽 ⇒ 首帧高 0、图到后整块下跳；修法是 `width: X%` + `aspect-ratio`，**不是 `min-height` 魔数**。

## 排查路径

- **CSS 的最小解析单元不是行，是 `{` / `}` / `;` 三个定界符**：按行解析会把多行选择器组的声明只记到最后一个选择器上（真命中 5 → 93）；跨行声明值的续行会被当成选择器；`stripComments` 替换成单个空格会删掉注释内换行导致行号前移（应替换成**等长空白但保留换行**）。
- **删死声明必须用「前后计算样式快照 diff」验收**：N 路由 × M 视口 × 逐选择器 computed style 做 before/after diff，零差异才算纯删——截图看不出 0.02rem 的差。
- **命中不都是缺陷**：`focus-visible` 收掉投影、断点反向补偿、粘性表头底色、主题变量分组这类刻意变体会命中重复选择器检查；工具的价值是把「谁会静默吃掉谁」摆上台面。
- **任何 CSS 候选实验都必须先自检「注入的规则真的存在且 computed 值随之改变」**：`addStyleTag` 会被 SPA 导航冲掉；`addInitScript` 注入的 `<style>` 实测根本没进 head ⇒ 「4 个候选全 FAIL」实为假失败。**「全 FAIL」比「全 PASS」更可能是探针坏了**；最可靠的是「临时改写真实文件 → 实测 → 还原 → 校验 hash」。
- **验证过渡类改动必须同时断言两件事：① 类名命中；② 存在插值中间帧**。仅断言前者会漏掉「动画被全局规则静默吃掉」这一整类缺陷，而它恰好让用户报告的观感问题**完全没被修好**。
- **先用「未修复态」确认探针真的会报错，再用它验修复**——否则无法排除「探针失灵导致假 PASS」。
- **采集计算样式要避开主题过渡窗口**：强调色在挂载后落到 `data-accent`，根节点会被临时加类并用 `!important` 覆盖所有组件的 transition；固定延迟后采集会读到它。
- **期望值必须从实际数值算出，不能凭语义直觉**：路由过渡方向曾两次按「目录互切应该平级」判断，而实际方向由 `meta.depth` 差值决定。
- **采样平滑滚动的断言必须轮询到稳定态**：固定 `waitForTimeout` 得到的是动画快照不是页面状态（同一动作的可达 `scrollTop` 多次运行差 20~40px，一度让人以为「改动没生效」）。用 `expect.poll`。
- **`complete` / `naturalWidth` / `currentSrc` 类断言前面必须有等待**，否则它的通过与否取决于跑在前面的用例。固定 sleep 常是这类断言的隐式契约——**删它之前必须审计所有「紧跟在它之后读取异步落地值」的地方**。
- **拍带 lazy 图的区块必须等到块内图片 `complete` 再截**，否则会把「还没加载」拍成「加载失败」并去修不存在的问题。
- **`locator.hover()` 会自动滚动**把元素滚进视口，虚拟列表随即重排 ⇒ 读到假的位移；改用手动 `mouse.move` + 只测完整落在视口内的元素。元素身份键用 `className + data-name/文本`，不要用 DOM 下标。
- **判 hover 抖动要比 `offsetTop/offsetLeft/offsetWidth/offsetHeight`**（不受 transform 影响，有意动效不会被误判）。
- **数据为空时元素可能整个不渲染**：多点采样脚本里任何 `querySelector` 未判空都会在跑到那条数据时整轮崩掉。
- **冻结动画源再取样**：Spine / parallax 必须隐藏，否则动画帧让相隔 1.2s 的两张截图差到 0.02+ 亮度；`color: transparent` 去字形**必须作用到后代**（有直接 `color` 声明的元素会压过父级，于是把字形本身当底衬，量出 `vsWorst = 1.0` 的假失败）；大图必须等 `Image.decode()` 完成再取样。
- **「最坏单像素」是包络不是判据**：同一批数据里它给出 1.02:1（听起来全页崩了），分布口径才给出真实形状。它能把「4% 的像素」讲成「整体不达标」，也能把「零遮挡」讲成「必须垫板」。
- **结论必须取「全部样本的最坏像素」而不是单只数据的均值**——单一样本实测会给出乐观偏差；AA 类判据要按逐字形像素的分布判（最坏值 + 失败占比并列）。
- **截图与量测冲突时，先问「两次观测是不是同一个状态」，不要挑一个信**：裁图在滚动进视口之后拍（图已加载），量测拍的是未加载态 ⇒ 两者都对。

## 坐标系与断点

- **base 改了 `display`，断点块里只写 `gap` 不会继承结构**：桌面网格化后手机断点必须显式回 `display: flex`。
- **走文档流的页不能用视口级 `margin: 0 auto`**：侧栏偏移后居中基准与侧栏避让页差一个侧栏宽，要用 `calc(offset + max(0px, (100vw - offset - detail-max)/2))`。
- **走文档流的详情页拿不到 `.nk-page--detail` 的侧栏避让，必须自己声明**：那份避让是 `position: absolute` + `left: var(--nk-content-offset)` 提供的，页面一旦改成文档流滚动（如敌方详情页要自己避让 <768 的固定底栏），整页就退回「版心以视口居中」⇒ **768~1279 视口被侧栏压住**（1024 实测 hero x=12、区块标题与 HP 值被裁，1280 起才偶然不重叠）。修法：页面容器 `padding-left: var(--nk-content-offset)`（该令牌 <768 为 0，无需媒体查询）。**这类缺陷不会报错、只在特定视口可见** ⇒ 新增/改造文档流页面时同批补一条「内容左缘 ≥ 侧栏右缘」的几何断言（`e2e/layout-monster.spec.ts` 有可抄的形态：读令牌落值 + 比 rect，而不是写死 x）。
- **避让一改，hero/骨架的固定盒高就要按断点重标**：内容区左缘右移会压缩可用宽度，图列驱动的 hero 高度随视口线性变化（敌方详情页避让后新增 1024~1149 档 314~358 的渐变），骨架屏不拆档就会在加载完成时整块下跳。
- **覆盖一个方向时必须只写该方向**：负外边距写成 `margin: -6px 0` 简写会把基线的 `margin-left: auto` 一起清成 0，靠右对齐的入口当场退回标签右侧。用 `margin-top/-bottom`。
- **改导航块序要连带查三处**：① 手机档分隔线是**按序画的**（修法是改画位置而非删线）；② 折叠算法按选择器量宽度预算，**改类名或换标签元素就会静默破坏底栏折叠**；③ 工具组在手机档是 `display: contents`，加减条目会改变底栏槽数，须按最窄档复测槽宽。
- **「改短文案」必须按最窄档复测**：底栏槽宽有隐性预算（`flex: 1 1 auto; min-width: 44px`、标签 `white-space: nowrap`），2 字变 4 字等于标签宽度翻倍。

## 工具链坑位

- **`String.replace(re, (match, p1, p2) => …)` 的回调第一参是整个匹配**：写成 `(num, unit)` ⇒ `unit` 恒为数字串、`parseFloat('0.82rem') = 0.82`，于是**只有 px 声明被映射、全部 rem 声明静默落进 leftovers**。
- **收口刻度必须同批收口注释**：所有「主字 3.2rem × 1.12 = 57.34」式注释会变成谎话，按仓库约定改成**引用令牌**。
- **PowerShell 的 `switch` 里 `continue` 只跳出 switch，不跳外层循环**：用它做「命中行 → 替换行」的 map 时替换后原文仍会被追加一次，静默产出**重复 CSS 声明**（后者覆盖前者）。改用显式标志或 `Hashtable.ContainsKey`。
- **整文件重写会污染「病态行尾」文件的 diff**：本仓四类行尾并存（`CR CR LF` 的源文件、每行尾多个 `CR` 的畸形态、正常 CRLF、纯 LF 的 `docs/**`）。用 `edit` 工具改前者会触发整文件重写（diff 由 29/1 膨胀到 181/153）。**病态行尾一律用「读原文 → 按原行尾切片 → 只替换目标行」的字节保真脚本。**
- **一条字号/刻度只允许一个声明点**：末块导入的收口文件是唯一声明点，前段凡是重述同一属性的都是死声明——**改它不生效**。
- **骨架/就绪这类「两处必须同值」的对，先找令牌而不是再算一遍常量**。
