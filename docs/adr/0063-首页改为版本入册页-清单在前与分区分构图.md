# 0063. 首页改为「版本入册页」：清单在前、分区分构图

> **取代** [ADR 0019](0019-枢纽页导航条回归与首页改为版本上新页.md) 决策 9（三分区各一行横向卡片带）与决策 11（首屏只承诺「报头 + 版本抬头 + 第一分区首行卡片」）。
> 0019 其余条款继续有效：两枢纽全断点渲染导航条、`/` 为版本上新、条目判据 = `release_version` 恰等于 `version_label`、跨模式只走侧栏「交换」、报头为一行文字（决策 12）。
> [ADR 0018](0018-枢纽页改为工具化入口页.md) 的禁止项（全屏媒体层 / 背景视频 / 立绘轮播 / 枢纽滚轮）继续有效——本决策不恢复其中任何一项。

## 状态

`accepted`（**已实现**：新数据层 `src/app/composables/use-home-release.ts`、重写 `src/app/views/HomeView.vue` 与 `src/styles/home.css`、7 个新 UI 词典键 × 13 语言、`e2e/layout-home.spec.ts` 重写；`pnpm build` 七守卫 + AI 端点守卫 exit 0）。

## 背景

首页在 ADR 0019 之后是「报头 + 版本号 + 角色 / 光锥 / 遗器三分区 + 页脚」，分区复用目录卡片模板，并对「恰 1 条」的分区额外展开成「大图 + 文案列」。上线后用真实渲染（1440×900 / 1920×1080 / 390×844，含 4.5 真实数据复现的常态版）复核，暴露出四个结构性问题：

| 问题 | 实测 |
| --- | --- |
| **常态版本没有主视觉** | 用 4.5 真实数据（2 角色 + 2 五星光锥）复现：三个分区全部退化为目录卡片带，卡片带 648px = 内容列 1252px 的 **51.8%**；整页正文 **70 个汉字**、6 个链接；「全部角色 →」距最后一张卡 **524px** |
| **版式只有两档，且两档都偏** | 件数 ≤1 → 撑成 541 / 610px 的「大图 + 806px 空文本列」；件数 ≥2 → 300px 目录卡。没有「2 件主角」这一档 |
| **首屏不交代全貌** | 1440 首屏内容覆盖率 24.5%（右侧 x≥850 仅 0.6%），首屏底部切在空白、滚动条宽 0；读者读完第一屏以为页面结束 |
| **手机丢失条目名** | <768 时条目名元素 `display:none`（w=h=0）——这是「复用目录卡 + 隐藏卡内名字」的补丁式做法的直接代价 |

同时，这 4 件条目自身携带约 6,900 字与约 28 张可用图（技能、星魂、2/4 件套效果、部位故事），首页只上屏约 117 字 / 5 图，第二屏没有任何纵深。

## 决策

1. **首页形态改为「版本入册页」**：报头 → **版本钢印**（版本号 + 「版本上新」+ 数据同步日期）→ **本期入册清单**（4~6 行：类型 / 名称 / 属性·星级，整行即链接）→ **站内即时搜索** → **双角色立绘封面**；其下依次为角色对页、光锥行、遗器双联、页脚藏书量。稀疏被写成「登记得清楚」，不再用「本次入库 N 件」把件数当卖点。
2. **三分区仍是内容轴，但每个分区有自己的构图**：角色＝对页（2 人并排；1 人时单卡上限 640px，不再横向拉满）；光锥＝横向行（左满级图 + 右技能名与描述）；遗器＝双联（套图 + 2 / 4 件套效果 + 4 部位名）。分区之间不共用版式，也**不再有**「≤1 才展开」的两态径。
3. **首页自有信息设计，不再复用目录卡片**：类型 / 名称 / 属性行、**星魂 6 枚图标**、2/4 件套效果与部位名都由首页直接渲染；因此也**删除了**「隐藏卡片内名字」的补丁（该补丁是手机丢名字的根因）。
   - **角色卡只展示星魂、不展示技能图标**：技能图标（3 枚 + 名称，34px）在 640px 卡宽下只能靠继续缩小才放得下，等于把空间平均分给两拨都看不清的小图；改为 6 枚星魂**铺满整卡宽**——所有断点统一 **3 列 × 2 行**（1440 单枚 ≈177px、单角色 640px 卡 ≈187px、390 手机 ≈99px；星魂原图 2048² 故放大不糊），把技能让出的空间整份交给星魂。判据：角色卡内不存在「非星魂的图标组」；星魂恰好 2 行；星魂图宽 ≥80px。
4. **首屏契约改写（替代 0019 决策 11）**：1440×900 与 1920×1080 内完整可见＝**报头 + 版本钢印 + 本期入册全部行**（按上限 6 行设计）；第一分区标题进入首屏（不要求卡片）。
5. **新增站内搜索（不新增依赖、不发新请求）**：首页把已加载的角色 / 光锥 / 遗器三份索引做内存过滤，输入即出结果（最多 8 条，跨三类），提交时跳第一条结果；无结果时落到 `/character?q=`（目录页已支持 `q` 查询参数）。
6. **页脚改为「藏书量 + 出口」**：角色 / 光锥 / 遗器总数由索引长度计算（当前 98 / 170 / 62），三项各为该目录页入口；格言保留在下方。页脚原语 `.nk-hub-footer` 与 `/currency` 共用不变。
7. **三处图像素材各司其职，禁止同一张图重复上屏**：首屏封面用**抽卡卡面**（`avatardrawcard`，1:1 带环境）、角色分区用**竖版立绘**（`avatarcutinfigures`，透明背景）、灯箱用竖版立绘原图放大；光锥用满级图（`lightconemaxfigures`），遗器用套图。封面只取角色、其次光锥（**不取遗器**——配件不适合当主视觉）。判据：同一条目的同一份图像素材在页面上只出现一次（命途/属性图标跨条目复用不在此列）。
8. **封面一次只显示一张，多张轮换而不并排**：封面容器是**单格叠放**，同一时刻只有一张 `data-active="true"`（其余 `opacity: 0` + `aria-hidden`）；张数 ≥2 时给出等量**指示点**（`aria-current` 标当前），每 5.2s 自动轮换，悬停 / 聚焦时暂停。
   - **`prefers-reduced-motion: reduce` 下不自动轮换**，只保留手动切换（用户主动点指示点仍生效）。
   - 与 [ADR 0018](0018-枢纽页改为工具化入口页.md) / 0019 禁止的「全屏媒体层 / 立绘轮播」的区别：轮换只发生在首屏封面**容器内部**——不占满屏、不接管滚动、不遮挡任何内容，且可暂停、可关动效；不是 0018 禁止的那种全屏轮播形态。
   - 判据：`[data-active="true"]` 恒为 1；未激活项 `opacity: 0`；指示点数 = 封面张数；reduced-motion 下等待一个周期后仍为同一张。
9. **数据判据不变**：条目仍取 `release_version` 恰等于 `version.json.version_label`（0019 决策 3/4/5 继续有效）。首页只读该字段，不关心它是差集推导还是权威字段。

## 后果

**正面**

- 首屏一次回答「这一版有什么（全部行）+ 我是谁（报头）+ 去哪（整行链接 + 搜索）」，常态版（2+2）与稀薄版（1+1+2）共用同一套结构，N=0/1/2/3+ 都有落点。
- 内容上屏量：当前 4.6 数据从 178 字 / 4 图 / 9 链接提升到 **392 个汉字 / 17 张图 / 11 个链接**（不含导航），遗器从「图标 + 名字」变为「套效果 + 部位名」。
- 手机端条目名、属性、技能/星魂与按钮全部可见；首屏含可见搜索按钮（旧版首屏无按钮）。
- 三个分区形态互不相同（对页 / 行 / 双联），不再是「三个同构分区」。
- 首页不再依赖「隐藏目录卡元素」来首页化，目录页与首页各自演进、互不牵连。

**负面 / 代价**

- 首页出现一套**自有卡片结构**（与目录卡 `renderCard` 并行），后续改卡片视觉要分别处理两处——这是为了「版面为 4~6 件设计」主动接受的重复，不是遗漏。
- `use-home-release.ts` 与 `use-release-showcase.ts` 并存：后者只服务 `/currency`（货币战争的两分区仍走目录卡带），两套数据装配逻辑需各自维护。
- 首屏契约与分区构图变化会使 `e2e/visual.spec.ts` 的 `home.png` 像素基线失效；基线刷新须在用户 RunPreview 确认后单独执行（本轮未跑 visual.spec）。
- 新增 7 个 UI 词典键（`home.ledger` / `home.releaseDate` / `home.searchAria` / `home.searchEmpty` / `home.searchPlaceholder` / `home.skills` / `home.eidolons`），13 语言 × 7 键的维护成本进入词典守卫。
- 搜索为内存过滤，只在三份索引加载完成后可用；索引加载失败时搜索随错误态一起隐藏（不提供降级站点搜索）。

**中性**

- AI 快照自动跟随：`pnpm build` 末步用同一份 DOM 生成 `dist/prerender/home.html`，首页快照正文与统计块已由守卫校验通过；本决策不新增可索引路由。
- 报头 `.nk-hub-masthead`、页脚 `.nk-hub-footer`、移动底栏、`--nk-content-offset` 避让均未改动，两枢纽外壳继续同构。

## 替代方案（被否）

| 方案 | 为何未采用 |
| --- | --- |
| 保留三分区卡片带，只调间距与字号 | 问题在构图不在数值：常态版没有主视觉、横向利用率 52%，调数值无法产生「这一版」的阅读节奏 |
| 恢复 ADR 0018 的板块索引 / 无侧栏形态 | 选路由导航条承担是 0019 的既定结论，且旧形态已被明确禁止回改 |
| 一件一屏全屏媒体（把 `pinned-poster` 直译） | 撞 0018/0019 的「禁全屏媒体层 / 立绘轮播」红线；且 N=1（当前 4.6）时叙事只有一站 |
| 只做「版本号 + 4 行清单」的纯文字收据页 | 首屏无图、无主物，4~6 件内容撑不起页面；与本轮「先有主视觉再谈清单」的判断相反 |
| 为搜索新增独立索引文件或搜索服务 | 三份索引本已随首页加载，内存过滤零请求、零依赖；新增索引会引入第二份数据事实源 |
| 把第二屏交给「上/下一版本对照」 | `release_version` 当前只有 4.5 / 4.6 有值（角色 95/98、光锥 165/170 为空串），对照类内容做不出来；等数据补齐后再议 |
