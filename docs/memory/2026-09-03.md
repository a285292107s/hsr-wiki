## Spine 官方条目 4.0 格式导出：4.2 运行时丢弃 legacy transform 继承字段 → 上身扭转（1512 知更鸟•晴歌）

- 触发：用户报告 1512（知更鸟•晴歌）spine「上半身被错误扭转了近 180 度」，并提示可对照原站活动页（e20260807version）重新提取。
- **排查路径（可复用）**：
  1. 静态一致性排除资源错配：atlas 页名 ↔ manifest textures 键逐字一致；骨架 JSON 全部 attachment region 在 atlas 有定义 → 资源本身自洽，排除「提取错文件」。
  2. 双运行时姿态探针（Node + spine-core，stub AttachmentLoader 返回真实 attachment + FAKE_REGION）：同一 JSON 分别用 4.0.31 / 4.2.43 解析 → setToSetupPose → apply idle → 对比关键骨骼世界矩阵。4.2 下上身链（bone3 及其子骨骼 shangshen_*）世界旋转比 4.0 基准多 ~106.74°/183.3°，即用户所见扭转量。
  3. 根因定位：37 根骨骼带 4.0 格式字段 `"transform": "noRotationOrReflection"`（不继承父骨骼旋转/反射）。spine-ts **4.2 解析器只读 4.1+ 的 `inherit` 字段、静默丢弃 `transform`** → 这些骨骼按 Normal 全继承解析。4.1.23 运行时仍用 transformMode 旧体系、认识该字段（探针数值与 4.0.31 逐骨骼一致）。
  4. 原站实锤（回答「为什么原站正常」）：活动页内嵌拼图工程 `pz_0gxSMfsWEq`，其 spine 运行时（chunk 727，4.2 系）JSON 解析器带 mihoyo 定制兼容补丁：`u.transform ? inherit=enumValue(Inherit, u.transform) : inherit=enumValue(Inherit, u.inherit)` —— 官方原版 spine-ts 4.2.43 没有这段。
- **受影响条目（判定方法：骨架 JSON 中按骨骼计数的 `"transform":"` 字段）**：1510（4.4，spine 4.0.58）、1512（4.5，4.0.58）、1513（4.5，"4.0-from-4.1-from-4.2-from-4.3.23"）。4.2 格式导出的旧条目（1321/1403/1415/1504 等）不受影响。
- **决策（不加第三运行时、不重提取、不改 vendor）**：manifest 官方条目新增可选 `runtime` 标记（1510/1512/1513 标 `"4.1"`），分派收口为 `services/api/spine.ts → spineRuntimeFor(entry)`（skel→4.1 / official 按标记缺省 4.2 / scene→4.2），生产角色页与 spine-lab 审核台共用。manifest version 17→18（两清单同步 bump，缓存键联动）。
- **坑位（必知）**：
  - 「spine-ts 4.2 向下兼容旧版 JSON」对骨骼继承字段不成立：4.0 格式的 `transform` 会被静默丢弃（无报错、骨架照常加载，仅姿态错）。未来抓取官方 spine 必须看骨架 JSON 的 `skeleton.spine` 版本串，4.0 系（含 "4.0-from-…" 前缀降级导出）一律在 manifest 标 `runtime: "4.1"`。
  - 官网活动页源码里嵌有每个 spine 的骨架元数据（`skeleton.spine` 版本串）与播放参数（scale/posX/posY/animation），比对提取参数时优先读 `pz_*.js` 的 config 包而非外层版本页（外层只是壳，spine 资产与运行时都在拼图工程 chunk 里）。
  - 两个 spine-manifest JSON 格式不同：official 为 2 空格缩进 CRLF，nanoka 为紧凑单行 CRLF——用 `JSON.stringify` 整文件重写会破坏换行/紧凑格式（守卫不查格式），编辑应做定向文本替换。
- **验证**：探针数值比对（4.1.23 ≡ 4.0.31 基准）；`pnpm test` 264 例全绿（api.test 新增 runtime 透传 + spineRuntimeFor 分派用例）；`pnpm build`（vue-tsc + 三守卫）通过；`pnpm build:lab` + `pnpm test:lab` 72 例全绿；check-spine-manifest 守卫新增 runtime 值合法性校验。视觉确认由用户完成：1512 dev 渲染恢复正常。
- **降级说明**：T2 预期的 e2e 未跑——改动为分派逻辑 + 清单数据，无模板/DOM 结构变化；像素基线仅覆盖首页（home-bg 场景未动）与角色列表页（无 spine），不受影响。
- **提取无误实证（当日追加核对）**：拼图工程 config（`pz_0gxSMfsWEq/config.*.js`）内嵌全部 14 个 spine 场景的骨架元数据。`zhigengniao_luodiye`（PC 落地页）= `spine:"4.0.58" hash:"8ec0ZGzUHko"`，与该 JSON 自报值逐字一致；manifest 1512 的 json/atlas URL 及三张纹理 hash 与官方 config 逐字节相同（config 资源 id 不带 .png 后缀、manifest 键按 atlas page 行带 .png，属约定差异非内容差异）。原站单页混用两种导出：pc/mob01-05 场景与 KV = 4.2.43 导出；角色落地页 = 4.0 系导出（luodiye PC/M = 4.0.58，shajin = 4.0-from-4.1-from-4.2-from-4.3.23 降级链），官方以单一 4.2 系运行时 + transform→inherit 补丁通吃。知更鸟另有 pc03（拼图交互场景）为 4.2.43 格式 547 骨骼骨架——wiki 按落地页口径提取 luodiye PC 无误，pc03/M 变体未提取属内容选择而非错误。
- **遗留**：1510/1513 建议用户 RunPreview 顺带视觉复核（同修复路径，探针已证明数据层面正确）。

## 研究线迁入主站 dev-only 路由 /debug（Spine Lab 独立子应用 → 主站侧栏「调试台」入口）

- **触发**：用户参照桌面 zzz wiki 项目的 dev-only 调试路由实践，要求研究线改为 dev only、在主站桌面断点导航条设置按钮上方加「调试台」入口；经确认方案为**迁入主站 dev 路由**（选项一，而非保 5174 外链）+ **入口可见断点 = 平板/桌面 ≥768px**（而非仅桌面）。
- **决策与实现（详见 docs/adr/0015）**：
  - `spine-lab/src/*` 全量迁 `src/app/debug/`（App.vue→DebugConsoleView.vue；相对导入 `../../src/x`→`../../x`）。spine-lab/docs 与 tools 保留。
  - 路由 `router/index.ts` 内 `if (import.meta.env.DEV) router.addRoute('/debug')`；侧栏入口 `v-if` 同文件 `const IS_DEV = import.meta.env.DEV`；`.ui-sidebar-debug` 手机 `display:none` + 排除出折叠测量（navW 与 DOM 槽位选择器都 `:not(.ui-sidebar-debug)`）。
  - lab 自建 base.css / toast 宿主 / CDN 健康探测自启删除：样式令牌主站全覆盖（54 变量 comm 为空）、toast 桥接 useAppStore、健康探测主站 bootstrap 已有。
  - lab data-file-index dev 中间件并入主 vite.config（build 端移除——/debug 不打包）；check-colors SKIP_FILE 改豁免 `debug/` 整目录；package.json 删 dev:lab/build:lab/test:lab。
- **坑位（必知，写码时防二次踩坑）**：
  - **Vue SFC 模板内禁止写 `import.meta.env.DEV`**：vue 模板编译器报 `import.meta may appear only with 'sourceType: "module"'`（SidebarNav 实测）。必须 script 侧同文件 `const IS_DEV = import.meta.env.DEV` 再模板 `v-if`。
  - **跨模块 dev 常量无法摇树 dynamic import**：`export const IS_DEV = import.meta.env.DEV`（debug/index.ts）+ router 数组 `...(IS_DEV ? [{component: ()=>import(...)}] : [])` → 生产产物仍含 DebugConsoleView chunk 79KB（Rollup 常量替换后 dead branch 里的 dynamic import 不触发模块消除，或 rolldown 按动态导入单独成 chunk 未剔除）。必须**本文件内** `if (import.meta.env.DEV)` 包裹 `router.addRoute` + `() => import(...)` 才整块摇树。dev 门控常量一律就近内联，禁止跨模块导出（本仓库其他页面同理）。
  - 摇树后主包仍残留侧栏 vnode 恒 false 分支（~150B 含 `/debug` 字符串 + `调试台` 文案 + `<svg>` 定义）——zzz wiki 同款量级，属接受项非缺陷（debug chunk 已彻底消失）。
  - check-colors 守卫原先的逐文件 SKIP（SpineKvSection/SpineAuditSection/…）是旧 `src/debug` 迁移残留——文件级豁免演进为 `debug/` 目录级豁免时，注意正则 `(^|[\\/])debug([\\/]|$)` 只命中目录（防误伤 `debug` 前缀普通文件——当前无）。
- **验证**：`pnpm test` 336 例全绿（原 264 + lab 迁入 72）；`pnpm build`（vue-tsc + 三守卫）通过，产物零 DebugConsole chunk；e2e layout + a11y 38 例全绿（新增 4 用例：桌面入口可见且位于设置上方 / 平板窄栏可见 / 手机隐藏 / /debug 可达四 Tab）。`/debug` KV 面板数据经 CDN，e2e 只断言静态结构未验证功能（lab 原有测试已覆盖引擎）。
- **遗留（需用户处理）**：桌面 4 张像素基线（home/character/endgame/currency）因侧栏新增「调试台」按钮需本机 `pnpm test:e2e:update =all` 刷新——视觉由用户 RunPreview 确认。
