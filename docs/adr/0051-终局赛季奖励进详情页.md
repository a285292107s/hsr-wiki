# 0051. 终局赛季奖励进详情页：逐层通关奖励 + 累计星数奖励线

## 状态

`accepted`（**已实现**：`endgame` 模块读 `RewardData` 并解析三张 `*RewardLine` 与 `ChallengePeakReward`；四模式产物新增 `floor_details[].reward` 与赛季级 `star_rewards`；详情页层面板头部新增「通关奖励」列、关卡面板之后新增赛季级「星数奖励」阶梯；`EndgameReward.vue` 成为奖励 chips 的唯一渲染件（星启面板同批切到它）；`incremental.MODULE_SOURCES['endgame']` 补 5 个源表）

## Context

用户提问「是否能关联挑战目标和奖励之间的关系，达成哪个挑战目标获得什么奖励」，并授权可行时迭代对应板块。盘点上游四张目标表与六张奖励表后，结论是**一半可行、一半不可行**：

1. **逐目标奖励不可解析**：`ChallengeTargetConfig`（130+ 条，仅忘却之庭侧）每条都带 `RewardID`（1001xx 段），但**该段在 `RewardData`（9,515 条）里一条都没有**——`ItemConfig` 也无同号条目，属本版数据里的悬挂字段。虚构叙事 / 末日幻影的目标表（`ChallengeStoryTargetConfig` / `ChallengeBossTargetConfig`）连 `RewardID` 字段都没有，异相仲裁的目标走 `BattleTargetConfig`（战斗条件，无奖励字段）。
2. **可解析的是两条链**：
   - **逐层通关奖励**：`Challenge{Maze,StoryMaze,BossMaze}Config.RewardID` → `RewardData`（每层一条，实测内容多为同层族共用同一份）。
   - **累计星数奖励线**：分组表 `RewardLineGroupID` → `Challenge{Maze,Story,Boss}RewardLine`（`StarCount` → `RewardID`）→ `RewardData`；异相仲裁走 `ChallengePeakGroupConfig.RewardGroupID` → `ChallengePeakReward`（按 `RewardType` + `TypeValue` 分档）。
3. **官方文案把「目标 → 奖励」的真实口径写死在玩法说明里**（`endgame_guide.json` 已在站内）：「通关忘却之庭并达成指定条件，可以获得『印记星数』。累计获得一定的星数后，可以领取『印记馈赠』」「通关虚构叙事并达到指定分数，可获得【故事星数】，领取【故事馈赠】」「异相仲裁…达成特定条件还可以获取额外的星级奖励」；实测**每层恰好 3 个挑战目标**（`floors × 3 == ChallengeTargetID 总数`，四模式逐期成立），即「1 个目标 = 1 星」。
4. `RewardData.Hcoin` = 星琼：全表 9,515 行**无一行**把星琼写成 `ItemID_1`（`ItemConfig` 1 = 星琼），而 32.6% 的行用它记星琼数量。

## Decision

1. **数据层（转换器只读，不改上游语义）**：`RewardData` → `{RewardID: [{id, num}]}`（六槽位；`Hcoin` 并入星琼 = 物品 1）；`*RewardLine` → `{GroupID: [(星数, RewardID)]}`；`ChallengePeakReward` 只取**两类有官方文案的星数档**（`MOB_STAR_REWARD` = 骑士星数 / `BOSS_STAR_REWARD` = 王棋星数）。输出：逐层 `floor_details[].reward`、赛季级 `star_rewards: [{star, items, label?}]`。
2. **档位按本期可达星数上限截断**：同一奖励线 Group 被层数不同的多期共用（10 层期与 12 层期同为 Group 2），上限取该期 `Σ ChallengeTargetID`（= 层数 × 3），超出上限的档位本期不可达，不输出。
3. **展示层（2026-10-07 补记修订）**：
   - **层头部「通关奖励」列**（每层的 `Challenge*MazeConfig.RewardID`）：与星启面板「星级目标｜通关奖励」同形；虚构叙事因多一栏赛季规则而变三栏（`.nk-egd-head--triple`）。
   - **层头部跨行「星级奖励」栏**：本赛季阶梯**按层序切片**随层展示（一行一档）；异相仲裁无层切片，改为赛季级头部整块（子 tab 之上），见下方补记。
4. **不上屏的档位**：`ChallengePeakReward` 的通关档（`MOB_PASS_REWARD`）、极限档（`BOSS_STAR_LIMIT_REWARD`）、彩色目标档（`BOSS_COLOR_TARGET_REWARD`）语义无官方文案（后两者发的是「异相仲裁•兵卒/骑士/城堡/帝王」勋章，与哪一档对应只能靠推），按「宁缺不猜」不上屏。
5. **共享渲染件**：奖励 chips 抽成 `EndgameReward.vue`（层头部 / 星启头部 / 星数阶梯每档共用，物品 id 经 `items.json` 单例映射），星启面板同批从内联模板切过来，避免三处各写一份。

## Consequences

**正面**

- 详情页首次能回答「打通这层给什么」与「达到几星领什么」，且两条链上的物品名/数量全部由上游解析，无自造数值。
- 「每层 3 个目标 = 3 星」「本期上限 = 层数 × 3」在转换期成文（截断逻辑单点），前端不重算。

**负面**

- **逐目标奖励仍然无解**：用户最初问的「达成目标 A → 奖励 X」在本版数据里做不到（`ChallengeTargetConfig.RewardID` 悬空）；页面只能给「累计星数」口径。
- 逐层通关奖励内容实测高度重复（忘却之庭 1035 十二层同载荷、永屹之城遗秘十五层两种、末日幻影四层一种），列在每层出现的信息量偏低。
- 异相仲裁的 6/9 类奖励档里只上屏 2 类，`maze_peak.json` 里其余档位数据仍在（只是无消费方）。

**中性**

- AI 快照不同步（沿用 [ADR 0026](0026-污染等级进入终局玩法详情页.md) 取舍）：`/endgame/:mode/:id` 快照来自 `*.catalog.json` 轻量条目，新字段不进 catalog，末步守卫无变化。
- 奖励物品的**名称与图标**仍是运行期经 `items.json` 映射（沿用星启通关奖励既有口径），转换器只落 id/数量。

## Alternatives considered

| 方案 | 为何未采用 |
|---|---|
| 逐目标标注奖励（把 `ChallengeTargetConfig.RewardID` 硬映射到某段编号规则） | 目标奖励段在 `RewardData` 为空，任何映射都是自造编号；宁可整体不做 |
| 把奖励线按层切成「本层满星 → 该档奖励」 | 需要「层序 ↔ 档位」的推断（奖励线只按累计星数计），跨赛季层数不一致时容易误导 |
| 星数阶梯放在首屏（hero 与子 tab 之间） | 档位常见 6–15 行，会把关卡内容推到首屏之外；用户刚在上一轮收口过头部区块 |
| 异相仲裁把 5 类档位全上屏 | 通关 / 极限 / 彩色目标三档无官方档位文案，只能自拟标签 |
| 前端运行时读 `RewardData` 自行解析 | 违反「文本与事实来自数据源、前端不做映射」的既有分工（同 ADR 0026 决策 1 的理由） |

## 补记（2026-10-07：星级奖励改为「随关卡展示」，逐层切片）

用户裁决「检查一下忘却之庭的星级奖励领取要求，你展示的内容有问题，然后把它放进每个关卡 tab 中」。核对结论与落法：

1. **领取要求复核（口径不变，展示粒度改）**：官方文案（TextMap）「通关忘却之庭并达成指定条件，可以获得『印记星数』。累计获得一定的星数后，可以领取『印记馈赠』」+ 数据 `ChallengeMazeRewardLine`（3/6/9… 档，星琼 60→80）确认：**判据是累计总星数、星数跨关卡通用**，不是「某层单独 3 星」；每层 3 个挑战目标 = 3 星，故**截止期每层满星正好推进一档**（忘却之庭 12 层 = 3..36 档；虚构叙事 / 末日幻影每层 3 目标但奖励线每星一档，故每层 3 档 1..12）。
2. **展示粒度：赛季级长阶梯 → 每层切片**。`_season_floors` 按**层序累计目标数**把赛季阶梯切给各层（`floor_details[].star_rewards`，切片在转换期算，前端不推层序）：层 tabs 的头部新增跨满整行的「星级奖励」栏（不再另占一列把头部挤成四栏），一行一档「N★ + 该档物品」+ 口径注记。赛季级阶梯块自此只在异相仲裁保留（其奖励按星数口径分组，与关卡无关）。
3. **附带项**：`EndgameView` 的赛季级 `EndgameStarRewards` 收成「仅 peak」一个实例；终局详情页的「奖励」现在是两层语义——`通关奖励`（每层，`Challenge*MazeConfig.RewardID`）与 `星级奖励`（按累计星数，逐层切片）。星启（tierce）tab 不展示星级奖励：它的 3 星与常规末层共享记录，档位已在末层 tab 上。
