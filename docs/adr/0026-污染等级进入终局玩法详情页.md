# 0026. 污染等级进入终局玩法详情页

## 状态

`accepted`（**已实现**：`endgame` 模块登记 `StageInvasionConfig` 并输出关卡级污染字段；四个终局模式详情页两级徽标 + 赛季级「污染等级」区块；终局目录卡加「含污染」标记；专题页「波及关卡」补赛季归属与跳转。同时修正 [ADR 0025](0025-贪饕污染专题页与导航第8板块.md) 替代方案表中「『污染』语义上不属于终局四模式」的论断。**污染侧的着色决策另见 [ADR 0027](0027-机制语境色与贪饕污染色.md)**：本文徽标与标记的色值自该轮起不再走 `--eg-color`）

## 背景

[ADR 0025](0025-贪饕污染专题页与导航第8板块.md) 把 4.6「贪饕」污染做成 `/voracity` 单页专题，并把「嵌入终局详情页」列为未采用方案，理由写作「『污染』语义上不属于终局四模式」。该理由**被上游数据推翻**：`StageInvasionConfig` 的 14 条记录以 `StageID` 指名的关卡，全部能在四张终局关卡表里命中（`EventIDList1/2` / `EventIDList`），即污染等级本来就是终局玩法的一个维度，而不是外挂于它的活动。

三条事实决定了形态：

1. **污染等级是关卡级属性**：判据为 `StageInvasionConfig.InvasionID`（1–3），描述在 `StageInvasionBuff.InvasionDesc` + `MazeBuff` 3034001–3034003。它落在「赛季的某一层的某一半场」，不是赛季级属性，也不覆盖整层。
2. **被污染怪物与页面敌方配置不是一回事**：末日幻影楼层只登记首领，被污染的小怪由机制额外加入，按怪物级 join 会漏判（这正是 0025 时期判「3020 仙客天狼与污染无关」的原因，实际其难度 03/04 上半场为污染等级 2）。因此污染怪物清单必须来自 `MonsterInvasionList` 本身。
3. ~~**末日幻影详情页渲染 `phases` 而非上/下半场**（`EndgameFloors.vue` 的 `modeKey === 'boss' && f.phases?.length` 分支），关卡级徽标只有挂在**楼层头**才能在四种模式下都稳定可见。~~ **本条前半句已被 [ADR 0031](0031-末日幻影层级敌方取实际战斗数据.md) 修订**：末日幻影层级改为只渲染上下半场、敌方取 `stage1/stage2`，`phases` 字段整体下线；「关卡级徽标挂在楼层头」这一半继续有效（楼层头徽标 + 展开后半场徽标两级不变）。

## 决策

**我们把「污染等级」作为终局玩法详情页的一个原生维度**：

1. **数据层**：`incremental.py` 的 `endgame` 模块登记 `StageInvasionConfig.json`；`converters/endgame.py` 在构造关卡时把侵入信息写入**关卡级**字段——`floor_details[*].stage1/stage2` 与异相仲裁的 `levels[*]` 携带等级与 `MonsterInvasionList` 解析出的被污染怪物。前端**禁止**再运行时 join `voracity.json` 做这层映射（单一事实源）。
2. **展示层（两级一致）**：楼层头（折叠态即可见）显示徽标并标注半场；展开后对应的半场标题（异相仲裁为 level）显示同级徽标。另新增赛季级「污染等级」区块，置于**「关卡层级」之前**并进 section nav：本季污染关卡汇总（层 / 半场 / 等级）+ 被污染怪物清单（按关卡分组，可跳敌人详情）+ 等级效果词条 + 回链 `/voracity`。等级效果词条只呈现 `StageInvasionBuff.InvasionDesc` 全文与等级图标——`MazeBuff` 3034001–3034003 的 `BuffName`/`BuffDesc` 四个 hash 在 `TextMapCHS` 缺失，无标签的裸数值等于自造语义，故不列。
3. **入口层**：终局目录卡在赛季名旁加文本徽标「含污染」（轻量条目需因此保留赛季级污染汇总）；`/voracity` 的「波及关卡」补出所属赛季与跳转，形成双向闭环——该映射由 **`voracity` 模块自己登记四张终局关卡表 + 四张分组表**算出，不读 `endgame` 产物（避免隐式模块顺序）。敌人详情页**不**改：维持「受『贪饕』侵蚀 · 等级 N」+ 回链专题页，避免把「关卡 → 赛季」映射复制到第三个模块。
4. **术语层**：`CONTEXT.md` 的「污染等级」判据由「愿力分档」修订为 `StageInvasionConfig.InvasionID`（愿力 4/10/40 降为同序说明），并新增「污染关卡」词条。

## 后果

**正面**

- 终局详情页首次能回答「这层这场有没有污染、多严重、污染了谁、什么效果」，并可从赛季跳到专题页、从专题页跳回赛季。
- 污染等级回归关卡级判据后，`voracity` 专题页与终局页共用同一个上游事实，不再有两处口径。
- 修正 0025 的旧论断，避免「3020 与污染无关」这类已被证伪的结论继续被引用。

**负面**

- `endgame` 模块的 `MODULE_SOURCES` 增加一张表：该表更新会触发四份终局 JSON 全量重转（`maze.json` 约 2.9MB、`maze.catalog.json` 约 0.5MB），增量收益被摊薄。
- 末日幻影「被污染怪物不在本页敌方清单里」是数据本身的形态，页面必须额外说明，否则读者会以为清单与敌方配置矛盾。
- 赛季级区块使终局详情页新增一个 section（影响 `buildEndgameSections` 的序号与既有 e2e 的区块数断言）。

**中性**

- **未发布赛季（`GroupName` 为空的 boss 3022）在 `maze_boss.json` 里照样带 `invasion` 与 `pollution`，而 `voracity` 的 `scopes` 里没有它**：可见性过滤只发生在「会变成可点击链接 / 会进入索引」的两处（目录页 `!info.zh → 跳过`、路由 `entry.zh` 为空即报错），全量产物不做逐赛季裁剪——否则要为污染单开一个特例（同赛季的层、敌方、增益都在产物里）。这是有意的边界，不是遗漏。
- **AI 快照本轮不同步**：`/endgame/:mode/:id` 的快照由 `*.catalog.json` 轻量条目生成，要带上污染维度需把赛季级污染汇总统进 catalog 条目 + 生成器 + 守卫三处；本轮按用户决策不做，代价是 AI 侧看不到该维度。后续若要补，属于本 ADR 决策 1 的延伸而非新决策。
- 同一套「污染等级」在材料本 / 大世界 NPC 怪物 / 差分宇宙周挑战各有平行表，站点只呈现终局侧；未来若扩面，应复用同一判据与术语。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 前端运行时 join `voracity.json` 的 `invasion.stages` | 每次进终局详情页多拉一份数据，且「关卡 → 赛季 / 层 / 半场」的映射逻辑落在前端，与「文本与事实来自数据源」的现有分工相悖 |
| 新建独立映射产物（如 `endgame_invasion.json`）供两侧引用 | 多一个产物与一处同步面，而映射所需的两张表本来就都在 `endgame` 模块的读取范围内的同一批上游数据 |
| `voracity` 改读 `endgame` 的输出产物拿赛季归属 | 产生「专题页依赖终局产物」的隐式模块顺序，单跑 `--only voracity` 会读到旧产物；四张关卡表本身很小，自读的代价低于耦合代价 |
| 只做楼层徽标、不做赛季级区块 | 等级含义与「污染了谁」只能跳去专题页看；末日幻影那类额外加入的污染怪物完全无从说明 |
| 只做赛季级区块、不做楼层徽标 | 层与半场对不上位，读者无法定位到具体关卡 |
| 同步进 AI 快照（本轮不做） | 需把赛季级污染汇总写进 `*.catalog.json` 并按目录条目判据同步生成器与守卫，超出本轮范围；记为取舍而非否决 |
