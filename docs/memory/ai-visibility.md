# AI 可见性与快照

> 本域 memory 的用途：记录 [ai-discoverability.md](../agents/ai-discoverability.md)（写「契约是什么」）与 [AI检索入口事实清单.md](../audit/AI检索入口事实清单.md)（写「厂商怎么说」，**外部快照、会过期**）都推不出的**坑位与判据**——尤其是那些不报错、守卫全绿、构建成功，但线上/快照结果已经错掉的静默失效。

- **快照是爬虫唯一可见的那一份，语言类缺陷只在快照上才算数**：SPA 页正常不代表快照正常——快照由 `tools/gen-ai-endpoints.mjs` 独立渲染。`check-ai-endpoints.mjs` 现逐份断言**无未解析文本令牌 `$t:…`**与**无原始词典键名**（键名取自源语言词典编译成一条正则逐份扫；vue-i18n 缺键时会把键名本身渲染到页面）。判据：正文出现 `$t:` 或 `itemType.ComposeMaterial` 这类串即失败。

## 静默失效：构建全绿但结果是错的

- **快照失真几乎从不报错，只在「改名 / 改口径 / 改数据源」时出现**：漏改一处引用旧变量名会让全部详情页渲染成目录页摘要，且守卫、类型检查、测试全绿。发布快照文本前必须与前端渲染口径逐字段比对。`tools/gen-ai-endpoints.mjs`
- **前端渲染器与快照生成器是两份实现，任何「前端保留 X」的口径都必须两侧各写一遍**：`fillParams` 曾把 `#N[i]%` 的 `%` 吃掉（`治疗量提高10。`），而前端 `fmtDesc` 是保留的——两边都没报错，只有线上文本是错的。`tools/gen-ai-endpoints.mjs`
- **禁止用 `git diff --stat` 行数证明「本次只做了追加」**：工作树叠着前序未提交改动时该口径恒不成立（曾出现 `+26/-107`，其中 -107 与本次改动无关）。改用锚点法：从 `HEAD` 抽出被改规则块的既有属性，去掉新增行后逐字比对。
- **对「入口有多少条内链」这类语法层断言：只要闭合标签存在，空内容也照样通过**。断言内链数量、分区数时必须同时断言**文本非空**，否则整块静默变空仍全绿。
- **专题页区块是快照正文的第二份清单，删区块漏改生成器会让快照留下已删内容**：`/formula` 这类专题页的「区块 → 段落」写在 `tools/gen-ai-endpoints.mjs` 的 `sections` 里，守卫只断言正文非空与无令牌残留，**不校验区块清单与页面一致**；只删 `FormulaView.vue` 时构建、守卫、e2e（若同步删了区块清单）全绿，而无 JS 爬虫仍读到已删区块。判据：区块的增删必须同轮处理四处——页面组件/区块清单、生成器 `sections`、e2e 区块清单、词典键；守卫能拦住「段落缺失」，拦不住「段落已过期」。
- **带开关的机制在最后一个消费方退场后必须重问「开关还有人用吗」**：`--eg-rail-w: 0` 这类「不画」开关会随着消费方清零变成死代码，而默认值继续伺候一个空集，且无任何断言察觉。

## 静默失效：覆盖率与守卫的盲区

- **只断言「每族生成文件数」查不出生成器静默漏条目**：`map` 中途异常、上限误用都会让条目少掉而文件数依然等于路由数。条目级覆盖率必须在快照正文里用稳定标记（`nk-snapshot__entry`）逐条计数，并把该类名从详情页导航性列表里排除。
- **枢纽页的条目级断言只能断言 ≥1，不能断言具体数**：判据（`release_version` 相等 / 赛季代际）一旦失效，枢纽页会静默变空态——`≥1` 正是为拦截这种空态而设，写死数字反而会随版本失效。
- **「守卫通过」什么都证明不了：必须做一次「故意弄坏它」的反向验证**：选择器写错、路径判断写错、条件永真都会静默通过。新增断言后手工把产物改成违规态跑一遍，确认如期判红再还原。`tools/check-ai-endpoints.mjs`
- **抽取式断言必须先证明「抽取命中了目标」：抽取结果为空串却判绿＝断言从未生效**。实测反例：`check-ai-endpoints.mjs` 用 `/<div class="nk-snapshot">([\s\S]*?)<\/div>\s*<\/div>\s*<\/div>/` 取快照正文，而快照实际只以**两层** `</div>` 收尾 ⇒ 正则恒不命中、正文恒为空串 ⇒「非 Han 语言不得出现中文可见文本」及其棘轮**自写入以来从未生效**（`tools/ai-han-baseline.json` 因此从未落盘，看上去反而像「残留为 0」）。通用判据：正文类断言要与「标记存在 + 抽取非空」绑定，抽取为空即判红；**正则里不要写死闭合标签的层数**（结构一变就恒空）。`tools/check-ai-endpoints.mjs`
- **按「已知坏形态的特征」写断言 = 只挡得住已经坏过一次的那一种**：判据要写成**白名单**（必须满足什么），不是「与已知坏特征不同即放行」。实测反例：`check-ai-endpoints.mjs` 断「LD 内嵌 URL 不得指向别的语言前缀」用的是黑名单（首段匹配 `^[a-z]{2,3}$` 且 ≠ 本语言），而真实缺陷形态是 `https://myhsr.wiki/encharacter/1503`——首段 `encharacter` 有 11 个字母，既不匹配也说不上「别的语言前缀」⇒ 12 个语言首页 × 4 条 ItemList URL 长期断链而守卫全绿。`tools/check-ai-endpoints.mjs`
- **URL 前缀改写禁止按字符串 `split/join` 拼接：`from` 的收尾斜杠是路径段分隔符**。实测：home 的 route 恰是 `/`（`from=https://myhsr.wiki/`），`…wiki/character/1503` 被粘成 `…wiki/encharacter/1503`。正确实现＝按路径段处理：LD 里同源 URL 一律改写到 `/<locale>/…`（`/` 站点根同样前缀化，它同时是首页自身 URL 与面包屑首项），**唯一豁免 `isPartOf` 的 WebSite 本体**（`url` 留在站点根）。`tools/gen-ai-endpoints.mjs`
- **`new URL()` 解析成功 / 请求返回 200 ≠ URL 指向正确资源**：`…/encharacter/1503` 语法合法、解析不报错、请求落 catch-all 还能拿到 200 外壳，因此「能解析 / 能 200 / 状态码全绿」类审计查不出这类拼接错误；判据只能是「路径必须落在预期前缀下」。`tools/gen-ai-endpoints.mjs`
- **「非缺省语言」不等于「不使用汉字的语言」**：把语言前缀目录一律当成「正文不得含汉字」会误伤日文与韩文——实测 jp 19/19、kr 5/19 个分层快照命中（日文汉字；韩国官方韩文用汉字注音 `세검(細劍)`）。判据必须按**脚本**划界（把合法使用汉字的语言显式排除），否则「修好抽取」的那一刻就是全量假红。残留计数仍走棘轮，兜住残留回涨。`tools/check-ai-endpoints.mjs`
- **守卫断言只锁「形状与必填项」，不锁具体取值**：取值随数据变，锁死必假红；范例＝只断言 `WebPage`/`Person`/`BreadcrumbList` 存在、`mainEntity` 指向同页 `Person`、`characterAttribute` 非空，不断言属性值等于什么。
- **汉字棘轮基线会被「译文没写完时先跑守卫」永久放宽**：实测新增多语言页面时先补源语言词典、12 个语言包尚未同步就跑了 `check-ai-endpoints`，分层快照里残留中文 ⇒ 守卫在基线文件缺失时**自动落盘** `tools/ai-han-baseline.json`（当时是 `{"ru":1}`），从此把「已坏」当基准，只降不升的棘轮被静默降级，而输出只是一行「基线已写入」。判据：凡新增多语言文案的改动，必须 13 个语言包补齐后再跑 AI 守卫；若中途跑过，先查该文件是否被新建（仓库本不该有它），有则删除后重跑。`tools/check-ai-endpoints.mjs`
- **配置类检查器若不进 `pnpm build`/CI，其计数基线会静默过期**：曾出现文件实际 7 处、基线写着 5 处而无人报错——凡「默认只报告」的检查器，其基线数字必须视为易腐项，改动后手动复跑。

## 快照正文：口径与保真

- **禁止为无数据实体合成通用句**：源 `desc` 为空且 `chara_info.stories` 全空时，前端渲染**空描述**，而生成器曾产出「X 是《崩坏：星穹铁道》的可玩角色。」——这是第二事实源，且把虚构文本写进了索引。摘要段仅源文本存在时输出，否则整段省略。
- **`<meta name="description">` 与正文摘要的规则相反**：正文可整段省略，但 meta 必须非空，用**数据字段拼装**（名称 + 稀有度/元素/命途），不得写通用句、也不得留空串。
- **「文本必须来自数据」还有半条：发布出去的文本必须已完整展开为可读文本**：参数展开不全就整段省略该字段（条目集合与 sitemap 不变），宁缺勿噪声——前端卡片本就不渲染该字段，或渲染成 `?` 残句。
- **裸 `#N` 的语义取决于该字段所属条目是否携带 `params` 语义**：携带（数组存在即便为空）即占位符、展不开须省略；不携带（角色 `desc`/`stories`、成就 `desc`、物品名、敌对 `intro`）即上游字面（如「天才俱乐部#81号会员」），**必须保留**。裸形态无法全局区分，守卫只能按页点名。`tools/check-ai-endpoints.mjs`
- **`{TEXTJOIN#61}` 与字面 `#NN` 编号属上游/转换器域，原样保留并单独立项，不得在本域「修好」**：它们与应用显示一致，改掉反而制造第二事实源。
- **空值整键省略，不留空串**：开拓者形态的 `name_en` 是 `{NICKNAME}` 占位符留下的空串，照搬会产出 `"alternateName": ""`——守卫须反向断言「键存在即必须非空」。
- **快照不做第二份算式**：怪物四维数值快照输出**模板基准值**并逐字标注「（模板基准）」，合成（基准 × 维度修饰比 × 等级曲线 + 实例修正值）留在前端单点。在生成器里实现第二份算式＝造第二个事实源，且必然与页面分叉。`src/app/views/MonsterDetailView.vue`
- **同一份数据的展示拼接也只做一次**：掉落/出没的关卡数、样本名拼接（如「活动名 · 关卡名」）必须在生成器里**复用页面已算好的值**，禁止在生成器里重算一遍——重算即分叉。
- **「同一份数据」还包括「同一份文件」，而轻量条目常常不是全量条目的子集**：终局快照生成器读 `*.catalog.json`（目录卡轻量条目），运行时读 `*.json`（全量表），而 `floor_details` / `countdown` / `clear_score` / `levels` 只存在于全量表 ⇒ 五个结构事实行在快照里整行消失，且「当期赛季」两边各取一份（生成器取排序首位、运行时取进行中的一期）——同一 URL 两个事实源，而类型检查、守卫、构建全绿。判据：生成器每个事实行的取值必须指到**与运行时同一份文件**，缺一份就显式读全量表，不要用「轻量 = 全量的前缀」推理。
- **字段缺失若被默认值接住，比整行缺失更有害：它会退化成一条**相反**的肯定事实**。终局快照的「星启模式」写成 `cur.tierce ? 含 : 不含`，而轻量条目没有 `tierce` ⇒ 快照对每一期都断言「不含」，运行时却按全量数据说「含」。判据：布尔类事实行必须区分「字段缺失」与「字段为假」，缺失即整行省略（与「空值整键省略」同一条），不得让 `undefined` 落进二选一的分支。
- **页面 ↔ 快照的对齐粒度要分事实与 chrome 两类**：**实体级事实标签必须逐字一致**（`<h1>`、实体名、事实行、一切数据派生文本）；**页面级 chrome 允许快照措辞更完整**（分区标题带括号说明、分组标签用全称、装饰性英文不进快照）。两处都保持现状，禁止互相搬字。
- **计数文案的复数选形也必须与页面同口径**：词典用 `|` 给单/复数（`{n} tier | {n} tiers`），页面走 vue-i18n 的 `t(key, { n })`——n=1 取单数、其余取复数（由 `src/app/__tests__/i18n.test.ts` 钉住）。生成器必须写成 `uiT(key, 兜底, { n }, n)`，**显式把 n 当 count 传**；漏传就恒取复数形式，n=1 时快照出现 `1 tiers`（页面是 `1 tier`），与「事实标签逐字一致」相冲且不报错。判据：脚本枚举 `uiT(` 调用点 × 13 语言词典是否含 `|`，**两侧都成立才需要传 count**（本站 45 处里只有 7 处符合，别按「所有 `{n}` 都要传」批量改）。`tools/gen-ai-endpoints.mjs`
- **文本上限是有意取舍，不得静默改成全量**：单实体文本上限（目录条目 4000 / 详情页 20000 字符）用于防止大文件把 dist 撑爆；截断行为是契约的一部分。
- **给快照加合成文案时，新增 i18n 键会撞汉字残留棘轮**：`ui()` 缺键回退中文，于是新键在 12 个非汉字语言的分层快照里就是一行中文，直接判红。首页统计块因此只用**既有词典键 + 纯数字**拼（目录名 + 条目数），不新增键、不写叙述句；确要写就必须 13 语言同批补齐译文。`tools/gen-ai-endpoints.mjs`
- **生成器里的文案表只能存「词典键 + 惰性求值的 helper」，不能在建表时直接调 `ui()`**：模块加载期 `currentLocale` 还是缺省语言，值会被当场求值并**冻结成中文**，于是非缺省语言快照里整片中文——而这类错误在常规断言下全部合法（正文非空、无 `$t:` 令牌、无原始键名），只有汉字棘轮偶尔兜住。`tools/gen-ai-endpoints.mjs`
- **空列表是「条目静默漏光」的伪装形态**：`<ul class="nk-snapshot__list"></ul>` 语法合法、任何计数断言都看不见它，故守卫显式禁止空列表，`catalogBody()` 对空 `items` 不落 `<ul>`。
- **给巨页加 `<h2>` 骨架不改条目集合**：`/item`、`/achievement` 的分组只加结构（`groupSections`），条目仍逐条带 `nk-snapshot__entry`；分组标签取不到时**构建失败**而不是造回退标签——空 `<h2>` 必被守卫拦，兜底命名则等于为数据里没有的分类自撰文本（同「禁止为无数据实体合成通用句」）。`tools/gen-ai-endpoints.mjs`
- **专题页的区块清单是三处并列事实源，而守卫只锁形状不锁区块数**：`/formula` 的区块同时写在 `FormulaView.vue` 的 `SECTION_DEFS`、`gen-ai-endpoints.mjs` 的 `formulaPages()` sections 与 `e2e/layout-formula.spec.ts` 的 `SECTIONS` 里；只删视图那一处时，快照仍为已删区块输出正文（页面没有、爬虫有），且用例继续按旧序号断言——`check-ai-endpoints.mjs` 只校验 h1 / 面包屑 / 内链 / 日期形状，区块数与标题集合无断言。判据：区块增删三处同批改，并同步 `ai-discoverability.md` 的区块清单；区块序号由数组下标派生，删中间区块后后续编号整体前移，用例与文案里写死的序号要一起改。`src/app/views/FormulaView.vue`

## 快照与就绪态类名耦合

- **快照的隐藏依赖 `html.js` 类，而该类由内联脚本在 `<head>` 首部同步添加**：规则是 `html.js #app > .nk-snapshot{display:none}`——只有 JS 用户隐藏快照。若把内联脚本移进构建产物或改为异步，JS 用户会先看到快照再被 Vue 覆盖，产生闪现；爬虫侧不受影响，故守卫不会报错。
- **切回 CSR 等价实现时首个要复制的机制是「`<head>` 内联 `document.documentElement.classList.add('js')`」**，它不是可选优化：缺了它就等于快照对 JS 用户可见。
- **归档旧的「就绪态类名耦合」方案（`prerender-ready` / `.is-ready`）**：曾用「快照在客户端就绪前保持可见，并由就绪类名隐藏」的思路，该方案为 `html.js` 同步脚本所取代；两份类名机制并存会互相矛盾——只保留 `html.js` 一条。

## 投递模型：产物布局服从平台求值顺序

- **Vercel 先命中文件系统、再走 rewrites，因此「有同名静态文件的路由」其 rewrite 永不生效**：`{"source":"/"}` 从不触发，因为 `/` 命中 `dist/index.html`（实测 1198 个路由全对、唯独 `/` 仍是空壳）。凡「路由 == 真实文件名」的条目（首页、robots、sitemap）都必须靠**写对文件本身**投递，不能只写 rewrite。
- **产物布局必须服从托管平台真实求值顺序，不能靠直觉；「构建产物都对」不等于「线上投递正确」**：改完必须用真实爬虫 UA 在生产/preview 上验收每一条路由。
- **catch-all 指向的「纯 SPA 外壳」必须与快照文件分离，并用下划线前缀登记为非快照**：`dist/prerender/_shell.html`（守卫跳过、不计入覆盖率与条目数）。外壳若被当成快照统计，覆盖率断言会整体失真。
- **rewrite 目标缺文件时回落 catch-all（返回外壳而非 404）**：因此未发布/不存在实体的 URL 行为与改造前一致，无回归——不要把这当成缺陷去「修成 404」，那会改变既有 URL 语义。
- **平台默认值 ≠ 平台行为：`trailingSlash` 未显式设置时，Vercel 一条归一化路由都不生成**。判据在 `@vercel/routing-utils` 的 `convertTrailingSlash`（`typeof trailingSlash === 'undefined'` 直接跳过），不能按「默认 false 就会去掉尾斜杠」推理。后果：`/character/1308/`、`/en/`、`/character/` 这类带尾斜杠的变体绕过全部 rewrite 落到 catch-all，与规范 URL 并存且返回 200 空壳——而**快照与 sitemap 都不含尾斜杠形态，所有守卫照旧全绿**。取证法：线上同一路径 ± 尾斜杠各取一次，两次结果不一致即中招。`vercel.json`
- **约定文件名入口（如 `/llms.txt`）最坏的形态是「文件不存在 + catch-all 兜底」**：它返回 200 的 HTML 外壳，于是既不是有效文件、也不是 404，任何只看状态码的审计都会判「文件在」。要么真放一份文本文件（`public/llms.txt`，随构建复制到 dist 根、由文件系统先于 rewrites 投递），要么让它 404；不要让它以 200 空壳存在。`tools/check-ai-endpoints.mjs`
- **软 404 的合格解是 `noindex`，不是 404**：catch-all 是客户端路由唯一的 200 通道（改成 404 会打断 SPA 路由），而 200 + 零正文在爬虫侧就是 soft 404。故 `dist/prerender/_shell.html` 本体带 `<meta name="robots" content="noindex">`，**公开快照一份都不带**。`vercel.json` / `tools/gen-ai-endpoints.mjs`
- **shell 的 `noindex` 必须在渲染快照前从模板里剥掉**：`template` 是同一份被用来渲染 1432 份快照的字符串；只在写 shell 时注入、读模板时原样带出的话，**二次构建会把 `noindex` 灌进全部快照**——而首次构建完全看不出来（那时的模板还没有它）。判据：任何快照含 `noindex` 即判红。`tools/gen-ai-endpoints.mjs`

## 可见性对齐（反 cloaking 的硬约束）

- **快照与 sitemap 的条目集合必须 = 应用真正展示的条目集合**：生成器必须施加与视图相同的过滤判据（`!zh` / `!name` / `in_book` 等），守卫则**独立**按同一判据从数据统计期望值——两边各自实现，靠契约同步。`src/app/catalog/pages/*.ts`
- **为「应用刻意隐藏的条目」兜底造文本 = 双重违规**：既违反「文本数据来源」硬约束，又把未发布内容写进索引。唯一例外是构造期非事实的筛选口径（如用户的 `localStorage` 性别变体设置）——`localStorage` 不是构建期事实，URL 与内容都真实，故保留全量。
- **新增可索引路由必须同步四处**：快照覆盖 + `vercel.json` rewrite + sitemap + 守卫期望；漏一处即构建失败或静默漏页。
- **应用与快照内容必须对所有 UA 一致（非 cloaking）**：任何「只给爬虫看」或「只给用户看」的差异化内容都不可接受；因此**列表层折叠、条目合并这类改动是契约级、跨模块的**，不能只改前端。
- **列表层折叠会同时牵动快照条目级断言与契约表**：把 632 条怪物折成 385 张身份卡要同步生成器、`check-ai-endpoints.mjs` 条目数断言与 `ai-discoverability.md` §2 表，属需开 ADR 的不可逆项。

## crawler UA、robots 与 sitemap

- **robots.txt 每个 AI 组必须自足声明 `Allow`，不能依赖 `User-agent: *`**：命中具体 UA 组时 `*` 组被**完全忽略、两者不合并**，故只在 `*` 里写放行等于对已点名 UA 无效。`public/robots.txt`
- **`Sitemap:` 行必须与生成器的 `SITE_ORIGIN` 同源，且改域时两处同改**：守卫断言一致；迁移自有域名后旧 origin 不得再作为 canonical/sitemap 源。`tools/gen-ai-endpoints.mjs`
- **`/prerender/` 必须 `Disallow`**：它是同一内容的第二份 URL；爬虫请求的 `/character/1308` 与 rewrite 目标无关，robots 只作用于请求 URL——因此 Disallow 它不影响正常收录。
- **禁止用 IP 封禁替代 robots，并在部署平台侧自查托管 bot 规则/挑战**：Cloudflare 对新建域默认屏蔽 AI 爬虫、Vercel 有一键 AI bot 规则集与 Deployment Protection；robots 写「允许」在这些前置层面前无效，JS/验证码挑战会让无头爬虫直接失败。
- **llms.txt 不是收录杠杆**：Google 官方明文忽略它，AI 爬虫流量中指向 `/llms.txt` 的比例可忽略；加它是零成本防御，不得挤占预渲染预算。`docs/audit/AI检索入口事实清单.md`
- **schema/JSON-LD 的价值是富结果与实体消歧，不是 AI 引用杠杆**：做它是为让机器读懂「这个页面是什么」，不要拿「提升 AI 引用」当立项理由。`tools/gen-ai-endpoints.mjs`
- **结构化数据的第一个问题是「这个页面是什么」，不是「加了多少字段」**：用 `Article` 描述角色数据页等于告诉机器「这是一篇资讯稿」，角色身份与属性都拿不到——应改用 `WebPage` + `mainEntity: Person`（`@id` 供页面内引用）。
- **字段要挑 schema.org 有定义的属性，不自己造类型**：角色属性走 `Person.characterAttribute`（其定义正是「虚构角色的某一方面数据」），拉丁转写名走 `alternateName`；`VideoGame` 会把「这个页面」说成「这款游戏」，自定义类型机器不认。
- **专题页用 `Article` + `BreadcrumbList`，不用 `CollectionPage` + `ItemList`**：专题页是异构条目的叙述性集合，写成 `ItemList` 等于强加「收录清单」语义，并与其 `nk-snapshot__entry` 计数必须为 0 的规则自相矛盾。
- **AI 检索入口没有提交/申诉页**：OpenAI 无任何提交入口，Perplexity 亦无官方收录申请——进入 ChatGPT 搜索的唯一官方路径是**允许 `OAI-SearchBot` 抓取**；主动入口只有 GSC（Google）与 IndexNow（Bing 侧，Google 未参与）。
- **站点所有权验证资产必须常驻，删任一即失去数据**：GSC 会周期性复验，且 DNS TXT 与 HTML 文件分属不同验证通道；换 token 必须同步改 shell 模板的 meta 与根目录验证文件两处。网域资源的 TXT 记录**不在仓库里**（NamesLink 控制台维护，清单见 [ai-discoverability.md](../agents/ai-discoverability.md) §5），且属性域名须逐字 `myhsr.wiki`：拼成 `myhrs.wiki` 得到的是另一个（未注册）域名的 token，加到正确域名上也永远验证不过。

## 页面元信息：title / og / JSON-LD

- **标题里没有主关键词是静默的**：当标题只由「页面名 + 品牌名」拼成时，游戏名一次都不出现，而页面、守卫、类型检查全绿——品牌名不承载搜索需求。判据：统计「标题含游戏名的快照份数」，为 0 即缺主关键词（关键词要**前置**，品牌排最后：标题被截断时丢的是尾部）。
- **标题与描述有两份实现，必须同批改**：快照侧 `gen-ai-endpoints.mjs` 的 `titleTail()`、前端侧 `src/app/seo.ts` 的 `pageTitle()`。只改一边 ⇒ 执行 JS 的爬虫读渲染后的 title、无 JS 的爬虫读快照 title，同一 URL 出现两个标题口径。曾真分叉：端局赛季详情页的客户端标题比快照少一段玩法名（`EndgameView`）。
- **静态模板里的 `og:*` 不会被生成器顺手覆盖**：生成器只 upsert 它点名的那几个字段，其余原样继承模板 ⇒ 改名 / 换品牌后模板里的 `og:site_name` 会继续挂着**旧项目名**，且没有任何断言察觉。判据：模板里每个 `og:*` 要么被生成器按页覆盖，要么在守卫里有同源/取值断言。
- **JSON-LD 的 `inLanguage` 硬编码时，语言前缀快照会全部自称缺省语言页**：JSON 完全合法，`JSON.parse` 断言与前缀 URL 断言都过。判据：逐份断言 `inLanguage === <html lang>`，且两者与 `og:locale` 由**同一个 culture** 派生。
- **`og:locale` 是 `语言_地区`（下划线），`<html lang>` 是 BCP 47（连字符）**：两侧都写死会在新增语言时静默错位。
- **hreflang 的值必须取 `culture`（BCP 47），不能取上游 `TextLanguageKey`**：`cht` / `jp` / `kr` 不是语言码（应为 `zh-TW` / `ja-JP` / `ko-KR`），Google 对无法识别的值**整条忽略**——日 / 韩 / 繁三个版本静默脱离 hreflang 簇，而「14 条 = 13 语言 + x-default」的计数断言照样全绿（**条数正确与取值合法是两个维度**）。ADR 0052 决策 1 要求取 culture，实现曾取 code 属分叉。`tools/gen-ai-endpoints.mjs`
- **`Article` 描述数据条目页＝把数据页说成资讯稿**：机器拿不到条目身份与属性。判据（可反向验证）：`Article` 只允许出现在叙述性专题页，数据条目页出现即判红；条目页必须是 `WebPage` + `mainEntity`（条目没有 schema.org 对应类型时落 `Thing`，**不要自造类型**）。
- **缺 `og:image` 不报错，只在分享出去时才看出来**：页面、守卫、构建全绿，平台只渲染纯文字卡片。判据：每页断言 `og:image` 存在且与本仓 origin 同源；站点级一张图即可，不必每页一张。
- **日期只写在可见文本里等于「这页没有日期」**：抽取器与搜索侧（DeepSeek Search 的 `date` 字段）只读结构化日期。判据：每份快照必须同时有可见 `<time datetime="{synced_at}">` 与 JSON-LD `dateModified`，且与 sitemap `<lastmod>` **同源**（三者都取 `version.json.synced_at`）。**守卫只断言前两处的存在与取值**——`lastmod` 的取值当前无断言（第 2 组只校验 URL 集合与同源），改口径时不会报错，属已知盲区。`tools/gen-ai-endpoints.mjs`
- **`dateModified` 会按「页面类型」漏，而不是按语言漏**：实测曾只有 `ldDataPage`（数据条目页）与 `ldArticle`（专题页）带它，恰好把首页 + 全部目录 / 枢纽 + 98 个角色详情漏在外面——JSON 合法、`JSON.parse` 断言全绿，线上就是「这批页面没有发布时间」。新增页面类型时必须同步该字段，守卫要写成「**每份快照**都必须有」而不是「抽样有几类」。`tools/gen-ai-endpoints.mjs`

## 无 JS 取证与死链审计

- **AI 爬虫基本不执行 JS，首屏无 JS 可读性是比 robots 更决定性的因素**：静态文件取证（去标签后中文字符数、内链数）才是本域可断言的部分；「页面在浏览器里正常」不构成 AI 可见性证据。`tools/check-ai-endpoints.mjs`
- **`tools/dead-links.test.ts` 只收集被登记的 URL 构造函数，未登记的一族会无声上线**：同类资源（如 `avatarRoundIconUrl`）漏进收集表时，死链审计永远查不出缺口——新增资源族必须同步登记进审计收集表。
- **以 HTTP 200 提供的占位图会绕过前端 error/挂起回退链**：上游用测试贴图顶替缺失资产时状态码全绿，「状态码检查」类工具（含死链审计）永远查不出——判据须比对**字节数/内容**而非状态码。
- **依赖目标服务器对探测 IP 响应的判定型任务，上 CI 前先实测该 IP 可用性**：CI 数据中心 IP 对 CDN 返回 403 会让全部 URL 判 env、缓存后每天重测，形成永远推不完的空转烧预算；死链是静态事实，保留本机按需跑即可。
- **jsDelivr 对探测有硬限流，并发与请求头都不能「优化」**：审计并发上限 3（UI 只允许 1/2/3），浏览器不得自定义 UA；429/503 退避重试（0/2s/5s），403 是持续信号（数据中心 IP）直接判 env、重试无意义；冷文件 302 → `raw.githubusercontent.com`，必须跟随重定向再判；HEAD 404 直接判 dead（省一半请求）。违反的形态是「探测越跑越慢直到全 env」，不报错。`src/app/debug/dead-links.ts`
- **死链结果只能靠本地缓存复用，不能指望 HTTP 缓存**：jsDelivr 的 404 带 `no-cache,no-store`，每次探测都会回源 GitHub ⇒ 已知结果落 localStorage，并用「来源 JSON 文件 sha1 签名」决定是否重测；来源文件内容变了（converter 重跑）就重测，签名一致则复用。来源文件读不到时必须标 `unreadable` 而不是静默丢签名，否则 `planProbe` 会把整族 URL 判成可复用。`src/app/debug/dead-links.ts`
- **JS 用户的「就绪/加载中」状态类与快照的关系必须在改测试前想清楚**：快照隐藏依赖 `html.js`，而页面自身的加载态由独立的渲染分支控制——两者混为一谈会导致「快照闪现」或「加载态被判定为内容缺失」两类误判。
