# 0069. 图片加载改为本地优先（本地 → jsDelivr → raw）

## 背景与问题

[0057](0057-图片资源自持与WebP入库口径.md) 把图标全量入库到 `public/data/assets/icons` 后，`LOCAL_ICONS_BASE` 一度被改为 build 档走 jsDelivr 项目仓库镜像（`cdn.jsdelivr.net/gh/a285292107s/hsr-wiki`），只有 dev 档走同源 `/data/assets/icons`；同时 `pnpm build` 末步 `prune-dist-icons.mjs` 把 `dist/data/assets/icons` 删掉，4,585 个图标（约 250 MB）不进部署。

该形态的代价与风险：

- **主源依赖第三方与跨境链路**：jsDelivr 在大陆直连慢（实测 1219 ms）且会 burst 限流（503/429 会被误判成真 404）。
- **50 MB ref 上限**：本仓远超 jsDelivr 的 ref 体积上限，冷文件会间歇 403（`Package size exceeded the configured limit of 50 MB`），必须靠 raw 回退兜底——即主源本身不稳定。
- **图标文件本就随仓库分发**：改走 jsDelivr 并未减少仓库体积，只是把「已提交的图」绕出去远端取一遍，多一跳跨境。

用户诉求：**图片从本地加载，jsDelivr 等方案作为备用**。

## 决策

1. **主源恒定为本站同源 `public/data/assets/icons`**（`LOCAL_ICONS_BASE = ${BASE_URL}data/assets/icons`），**取消按 `DEV` 分流**——dev 与 build 都直读同源文件。
2. **三级回退链：本地 → jsDelivr → raw.githubusercontent**。`CdnUri` 扩为 `{ primary, fallback, fallback2 }`：本地主源，`LOCAL_ICONS_DELIVR_BASE`（二级），`LOCAL_ICONS_FALLBACK_BASE`（三级）。`localFallbackFromPrimary` 返回 jsDelivr 二级，新增 `localFallback2FromPrimary` 返回 raw 三级。
3. **属性层表达为两跳**（**已由 [0071](0071-图片回退链改为失败时推导.md) 取代**：回退链改为失败时由主源 URL 推导，不再逐图内联属性）：`imgHtml` / `cdnImgAttrs` / `imgAttrs` 输出 `data-cdn-fallback`（jsDelivr）+ `data-cdn-fallback2`（raw）。`dom.ts` 的 `handleFailure` 逐跳降级：本地失败 → jsDelivr（保留 fallback2）→ raw → 占位；jsDelivr/raw 镜像自身失败沿链下一跳。
4. **图标随构建产物部署**：删除构建末步的 `prune-dist-icons.mjs` 并从 `build` 链摘除，`dist/data/assets/icons` 随部署上线。
5. **`index.html` 只保留 `dns-prefetch`**（jsdelivr + raw），去掉 jsdelivr 的 `preconnect`——主源同源无需跨域预连接。
6. `img-gate.ts` 的 `isGatedImageUrl` 已认 `LOCAL_ICONS_BASE`（现在 dev/build 都是站点相对路径），无需改判定；nanoka 相关保留不变。

## 替代方案（被否）

| 被否方案 | 否决理由 |
| --- | --- |
| 维持「jsDelivr 主源 + raw 回退」（现状） | 主源跨境慢 + burst 限流 + 50 MB ref 上限导致的偶发 403，用户可见破图；本地文件明明已在仓库里却不直接用 |
| 本地 → raw 两级，去掉 jsDelivr | raw 无体积上限但速度略慢、且是单点；保留 jsDelivr 作二级成本为零，多一层兜底 |
| 本地 → nanoka → jsDelivr → raw 四层 | nanoka 是外部 Cloudflare 域、目标网络常不可达，放二级反而在首跳失败时多耗一次超时；本地缺失时应直奔同仓库镜像 |
| 保留 `prune-dist-icons`（不要本地文件进部署） | 与「本地优先」直接矛盾：文件不进部署则本地主源必然 404，主源形同虚设 |

## 后果

- **部署体积**：`dist` 约 100 → **350 MB**（+ 约 250 MB 图标）。Vercel 走 Git 集成部署，无构建产物硬上限；但 Deployment Storage 按部署数累加，长期需注意（可用更短的部署保留期控制）。
- **大陆可用性**：首屏图标走同源，去掉跨境链路，LCP 与破图问题从根上缓解；jsDelivr 仅在本地缺文件（新版本图标尚未入库）时才被触达。
- **更新时效**：入库仍是构建期快照；上游新增图标「本地缺 → 回退 jsDelivr/raw」自动兜住，修正既有图标仍需重新入库。
- **守卫与测试**：`check-image-loading.mjs --strict` 不受影响；单测与 e2e 的 `data-cdn-fallback` 断言改为两级回退语义（`data-cdn-fallback` = jsDelivr，`data-cdn-fallback2` = raw）。

## 文档

本 ADR；[../memory/build-deploy.md](../memory/build-deploy.md)「图片分发」章节改写为本地优先；[0057](0057-图片资源自持与WebP入库口径.md) 的入库口径不变（本 ADR 只翻案其分发主源）。
