# 0032. 星启节点按完整场次渲染

## 状态

`accepted`（**已实现**：`_load_tierce` 的三个节点各输出完整场次内容（`damage` / `monsters` / `level` / `countdown` / `buff` / `invasion` + `origin` 场次键）；`EndgameTierce` 三节点改为层 tab 的扁平场次卡（`StageContent` + `EndgameBuffGroup` + `EndgameTraitGroup` + `EndgameFloorBuff`），按 `origin` 取赛季级 `buff_groups` / `boss_traits`；`MazeTierceNode` 类型抽出，`StageContent.label` 改可选；节点折叠 / 波次折叠与 `节点 N` / `NODE-0N` 编号退场，面板级「赛季增益」副本移入节点 3；**修订 [ADR 0028](0028-终局详情页父子层级刻度.md) 决策 1/2/3、[ADR 0030](0030-末日幻影详情页层级星启子tab.md) 决策 2、[ADR 0031](0031-末日幻影层级敌方取实际战斗数据.md) 的同源标注文案**；**决策 5 的中性条「节点 3 不落推荐属性」与决策 6 已被后续补全修订**——见下文「修订」；**节点 3 的 `buff` 已由 2026-10-02 修订补上**（来源 = 附加关 `StageConfig` 的 `_BindingMazeBuff`，见下文第二条修订）；**决策 4 的卡形（三节点纵排）与决策 7 的「卡形统一」已被 [ADR 0033](0033-星启模式改单节点看板.md) 修订**：星启侧改为节点子切换 + 单节点看板，数据层决策 1/2/3 不变）

## 背景

起点是一个已被否掉的方案：用户问「星启模式有没有必要和第 4 层 tab 合并到一起」。取证后合并没有必要（见替代方案表），但暴露出真问题——**重复的渲染可接受，重复的两场内容却不对等**：

1. **同源但不等量**：5 个含星启赛季（3018–3022）里 `tierce.nodes[1]/[2]` 与末层 `stage1/stage2` 的敌方数组**深度相等**（含波次）；而节点只带 `monsters`，层 tab 的半场带 `damage` + `monsters`。于是一场战斗在层 tab 有推荐属性、等级/回合、首领特性、可用增益，在星启 tab 只剩敌方卡——用户原话：「重复渲染是可以接受的，但是现在星启模式下，重复的两场数据不完整。」
2. **三模式同构**：13 个星启赛季（忘却之庭 4 / 虚构叙事 4 / 末日幻影 5）的 `nodes[1]/[2]` **全部**逐字等于各自最高难度关的 `stage1/stage2`（`DLCKKJFMJOB.Floor` = 该赛季最大层），层级目标 3 档 / 星启目标 4 档 / 通关奖励 8 项在三模式完全一致。补全写在共享的 `_load_tierce` 里就天然覆盖三模式，为末日幻影单开分支反而制造三处口径分叉。
3. **字段都在同一条记录上**：节点 1/2 的来源 `DLCKKJFMJOB` 指向的记录就是最高难度关记录本身，层 tab 半场用到的 `DamageType1/2`、`StageConfig.Level`、`ChallengeCountDown`、`MazeBuffID` 全在这条记录里；节点 3 的等级取 `HFIAAGAKFMD` 的 `StageConfig.Level`、回合取 `GNOOAGPBNLD`。**buff 分两处来源**：星启表 14 个字段里**没有自己的 buff 字段**——节点 1/2 取最高难度关记录的 `MazeBuffID`，节点 3 取附加关 `StageConfig` 自身的 `_BindingMazeBuff`（前者当时被记为推断项、后者当时整块缺席，**2026-10-02 修订**补齐并证实，见下文修订）。
4. **卡形不对齐**：星启那时是可折叠的「节点 / 波次」两级折叠树，层 tab 是扁平场次卡；同源内容两套版式，ADR 0028 也因此把星启「波次」定在子档——与层 tab 的「波标签 = 孙档」不一致。

## 决策

1. **节点即完整场次**（数据层）：`_load_tierce` 的节点输出与 `_season_floors` 的半场同口径——`damage`（`DamageType1/2`）/ `monsters` / `level` / `countdown` / `buff`（层级可用增益）/ `invasion`，另带 `origin`（`stage1` / `stage2` / `tierce`）。
2. **场次级集合按 `origin` 取，不复制进节点**：赛季级 `buff_groups`（赛季增益）与 `boss_traits`（首领特性）保持单一来源，前端按 `node.origin` 查表；这两项只有末日幻影产出，其余模式缺省即不渲染——同一组件不需要模式分支。
3. **节点 1/2 的增益与首领特性与第 4 层同源**：`origin = stage1/stage2` 取到的是与层 tab 该半场**逐字同一份**数据；节点 3 `origin = tierce` 取星启那一组。面板级那份「赛季增益」因此移入节点 3（同一份内容不允许在面板内出现两遍）。
4. **卡形统一为扁平场次卡**：父档行头 = 场次文案（上半场 / 下半场 / 星启附加关）+ 同源标注（同第 N 层）+ 等级/回合；子档体（`.nk-egd-children` 几何）= `StageContent`（推荐属性 + 敌方配置，标签留空由父档承担）+ 该场次赛季增益 3 条 + 首领特性 4 条 + 可用增益。节点折叠与波次折叠交互退场。（**本条的三节点纵排已被 [ADR 0033](0033-星启模式改单节点看板.md) 修订**：星启侧改为「节点子切换 + 单节点看板」，一次只渲染一个节点；父档/子档层级刻度不变。）
5. **节点编号退场**：`节点 N` / `NODE-0N` 不上屏——一个节点就是一场战斗，场次文案即其身份；同源标注收缩为「同第 N 层」（「· 上半场」由标题承担）。（**本条已被 [ADR 0033](0033-星启模式改单节点看板.md) 决策 9 修订**：用户裁决节点号重新上屏——子切换与看板行头都写「节点一/二/三」并带末波首领头像，场次文案与「同第 N 层」标注退场。）
6. **统计行保留**：面板顶部统计行的「推荐属性」是整场星启挑战的弱点（`LOJCIDLKPKG`），与节点逐半场弱点是两个口径（3020：整场 `Fire/Imaginary/Physical/Quantum` vs 上半场 `Physical/Fire/Ice/Quantum`），并存不冲突。（**本条已被下文修订推翻**：`LOJCIDLKPKG` 的所指是**附加关那一场**的属性、不是整场汇总；该数据补到节点 3 后，统计行的推荐属性与敌人等级一并移除，只留赛季级独有的回合/分数限制。）
7. **三模式统一**：补全与卡形都只改共享的 `_load_tierce` / `EndgameTierce` / `StageContent`，不为末日幻影另开分支。（**「卡形统一」的判据被 [ADR 0033](0033-星启模式改单节点看板.md) 沿用并延展**：星启侧的单节点看板同样落在共享 `EndgameTierce` 上，三模式一并生效；`StageContent` 因推荐属性上移而新增 `hideDamage`。）

## 后果

**正面**

- 同源两场不再「一边全一边残」：星启节点 1/2 的推荐属性、赛季增益与第 4 层上下半场**逐字同源**（`e2e/layout.spec.ts` 直接比对层 tab 抓下来的 `innerHTML` 与增益名单），首领特性、等级/回合、可用增益一并到位。
- 星启 3 个节点各自成为自洽的一场战斗：不再需要「节点 3 才挂首领特性」这类按节点序号特判的渲染逻辑（改为按 `origin` 取数据）。
- 三模式的星启区块共用一套卡形与字段口径，忘却之庭（`GNOOAGPBNLD` = 30/45 回合）与虚构叙事的场次差异由数据自身表达。
- 星启节点 3 的「附加关」身份第一次有了数据依据（等级 95 来自 `HFIAAGAKFMD`、回合 45 来自 Tierce 表），不再是靠 `idx === 3` 硬判。

**负面**

- **忘却之庭 / 虚构叙事的星启区块也被改形**：节点从可折叠 3 行变成 3 张扁平场次卡，页面纵向变长（虚构叙事每节点 7 敌 / 3 波），并失去「节点 + 波次」两级折叠这一层交互。这是「三模式统一」的直接代价（决策 7）。
- 星启「波次」的档位从子档降到孙档（ADR 0028 原按「节点 → 波次 → 敌卡」映射）；本次按 DOM 嵌套深度重新落位，与层 tab 的「半场 → 行 → 波标签」对齐，见修订说明。
- **节点 buff 分两处来源**（2026-10-02 修订后）：星启表没有自己的 buff 字段，节点 1/2 取最高难度关记录的 `MazeBuffID`、节点 3 取附加关 `StageConfig` 的 `_BindingMazeBuff`。上游若给星启表补独立的 buff 字段，两处取值都要重新对齐（已记入 [转换器字段映射](../data/转换器字段映射.md)）。
- **节点 3 的推荐属性与统计行曾是同一份值**（见修订）：`LOJCIDLKPKG` 一度在面板内出现两遍（统计行 + 节点 3 行）；修订后统计行的推荐属性与敌人等级一并移除，面板内只剩节点层那一份。1/13 赛季（3019）该字段与附加关关卡内登记敌方的韧性弱点不一致，见修订。
- **统计行在星启面板里通常只剩一项或为空**：忘却之庭只剩「回合限制」，虚构叙事只剩「分数限制」（且 `tierce.score` 为 null 时不渲染），末日幻影两者皆无——统计行整块随条件退场。
- 数据体量：39 个节点各带 `damage`/`level`/`countdown`/`buff`，三份产物合计新增约 6.4 KB（maze 2.5 / story 0.7 / boss 3.3），相对 2.9 MB / 704 KB / 496 KB 可忽略。
- `buff_groups` / `boss_traits` 仍是赛季级口径（层 tab 要用），节点侧读同一份数据：两处消费同一字段，改口径时必须一起看。

**中性**

- **节点 3 的推荐属性**：本轮补全时按「星启表只有整场挑战的弱点 `LOJCIDLKPKG`，没有逐节点弱点」判为不落，统计行承担该口径。**已被下文修订**：该字段就是附加关那一场的推荐属性，节点 3 落同一份。
- 星启面板顶部不再有「赛季增益」分组——它移进了节点 3；`.nk-egd-tierce__nodebody` 承担 `.nk-egd-children` 几何（原 `__nodebody-inner`）。
- `__nodecode` / `__nodesummary` / `__arrow` / `__wave*` 等折叠机件与样式退场，`renders.nodeSummary` 随之删除；`StageContent.label` 变可选（父档行头已承担场次文案）。
- 同源标注「同第 N 层」写在共享组件里，三模式的星启区块一并生效；对另外两种模式它落在区块内场次卡行头。
- AI 快照不受影响：`/endgame/:mode/:id` 快照由 `*.catalog.json` 独立生成（星启在快照里只占一行），本轮字段零变化。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 星启与「第 4 层」tab 合并成一个（根问题） | 层级同构性与入口可发现性代价过高：boss 模式下星启**只有 tab 一条入口**，且只在 5/22 赛季存在；tab 行无法预告它的存在（ADR 0030 的可发现性理由继续成立） |
| 节点 1/2 去重为「同第 4 层」引用行 + 跳转 | 用户判据：重复渲染可接受，缺的是内容不是结构 |
| 保留可折叠节点卡，只在卡内补齐字段 | 用户选「三节点全部改用层 tab 的场次卡原语（扁平无折叠）」 |
| 保留 `节点 N` 编号，把场次降为副标 | 用户选纯场次口径：「上半场」/「下半场」/「星启附加关」 |
| 只补推荐属性（最小补齐） | 用户选逐项对齐层 tab：推荐属性 + 首领特性 + 等级/回合 + 末法余烬 |
| 节点级不挂赛季增益（只在面板顶部挂一次） | 用户判据：「每个节点都有自己的赛季增益，节点 1/2 和第四层的赛季增益一样」 |
| 只补末日幻影，另外两模式保持现状 | 三模式同构、共享转换器与组件；分模式要加分支，且两处版式不同 |

## 修订（2026-10-01）：节点 3 补推荐属性 + 统计行只留赛季级项

**触发**：用户复核页面后问「末日幻影星启模式三个节点有各自的推荐属性，头部那条是什么」。取证结论——头部是星启表整场挑战的弱点 `LOJCIDLKPKG`，不是节点并集；而该值与节点 3 那一场的推荐属性本就是同一个口径，当初判「节点 3 没有逐节点弱点」判错了一半：**星启表确实没有逐节点字段，但节点 3 的推荐属性不需要逐节点字段**（表里只有这一场）。用户先后裁决两条：① 补节点 3 的推荐属性；② 移除面板头部的推荐属性与敌人等级，并给出判据原话——「**头部这里显示的属性推荐和敌人等级，其实是星启模式附加关卡的属性推荐和敌人等级**，所以让你删除了它，因为我们已经把对应的数据补在附加关卡上了」。

**决策 1（修订本文决策 6 与中性条）**：节点 3（星启附加关）的 `damage` = Tierce 记录的 `LOJCIDLKPKG`，与赛季级 `damage_types` 同值，经共享的 `StageContent` 原样渲染成「推荐属性」行（三模式一并生效）。**禁止从附加关敌方的韧性弱点推导**：3019 的附加关关卡（`HFIAAGAKFMD` = 420494）只登记了无弱点机制本体「心蕉如火的猴把戏」（`StanceWeakList` 为空），其 `MonsterConfig.SummonIDList` 里的「蕉研组的谐乐猴师 `3003015`」才是与整场弱点（火/冰/雷/虚数）逐项相等的首领——即**站点渲染的敌方与推荐属性分属上游两处登记**，按敌方推导会在该赛季落空、并可能在其它赛季多算。逢「推荐属性该不该显示」的判据一律回到关卡表/星启表，不回退到 `weak`。

**决策 2（同步收窄决策 6）**：面板顶部统计行**只保留赛季级独有的项**——「回合限制」（`GNOOAGPBNLD`，仅忘却之庭 = 45）与「分数限制」（`IDBJENCBJHM`，仅虚构叙事 = 99000）；**推荐属性与敌人等级从统计行移除**。**口径裁定（用户判据）**：面板级那两项的所指**就是附加关那一场**的属性与等级（同一个 `LOJCIDLKPKG`、同一个 `StageConfig.Level`，313370 等星启表字段都只有这一场），**不是整场挑战的汇总**——故它不是「叠加在节点之上的第三个口径」，而是节点 3 属性的一个副本；既然该数据已在附加关（节点 3）的场次卡上，面板级副本即冗余，删除。这同时纠正了本文决策 6 原来的措辞（「整场星启挑战的弱点」）：`LOJCIDLKPKG` 描述的是附加关这一场，只是恰好与赛季同值。该移除只对星启面板生效（层 tab 的层头从未有过这两项），节点层字段（`tierce.damage_types` / `tierce.level`）继续产出——AI 快照的「弱点」遍历用的就是它。`.nk-egd-tierce__val--elems` 随之退场。

**取证基数**：13 个星启赛季全部补上；其余 12 个赛季 `LOJCIDLKPKG` 与该关内登记敌方的 `weak` 逐项相等（节点 3 单敌），3019 是唯一例外。

**未做**：不追查 3019 「心蕉如火的猴把戏 vs 蕉研组的谐乐猴师」哪一方是游戏内实际出场 Boss（上游两处登记本身不一致），只按「推荐属性走星启表」收口；若后续证实附加关实际首领另有其人，回退点是 `_load_tierce` 里那一处 `LOJCIDLKPKG` 读取。

## 修订（2026-10-07）：统计行整条退场（两个赛季级项并入「通关条件」）

**触发**：用户裁决「通关条件上方 45,000 分数限制 SCORE 这张卡片已经没有存在必要了，移除」。

**决策**：面板顶部统计行（`.nk-egd-tierce__stats`）**整条删除**，不再渲染；`GNOOAGPBNLD`（回合限制）与 `IDBJENCBJHM`（分数限制）改由 [ADR 0051](0051-终局赛季奖励进详情页.md) 补记二的「通关条件」格承担（忘却之庭取回合上限、虚构叙事取通关分数线，同一份数据、同一处展示）。**判据**：这两个值本来就是赛季级独有的项、且「通关条件」格已把它们的**语义**写明（回合上限＝失败判据、通关分数线＝通关判据）——统计行与它并列即同一事实两处声明。三模式一并生效（忘却之庭 1036 的「45 回合限制」同批退场，值仍在通关条件格里）。

## 修订（2026-10-02）：节点 3 补上末法余烬（buff）

**触发**：用户复核页面后问「末日幻影详情页，星启模式，为什么节点三中末法余烬消失了」。

**取证**（两件事，先分清「从来没产出」与「被删掉」）：

1. **节点 3 的 `buff` 从未产出**：`_load_tierce` 的节点 3 分支只落 `idx/origin/damage/monsters/level/countdown/invasion`，没有 buff 那一行；改版前的星启面板（`9f7c403`）三个节点都不渲染末法余烬，per-node 的末法余烬是本文决策 1 才落地的，节点 3 那一格因此一直空着——前端 `EndgameFloorBuff` 的 `v-if="buff"` 让整块不进 DOM，看起来像「消失」。
2. **星启表确实没有 buff 字段，但附加关关卡自己登记了**：`StageConfig.StageConfigData` 里的 `_BindingMazeBuff`（`MazeBuffType = Level` / `IsDisplayEnvInLevel = true`）。5 个含星启赛季逐条等于该赛季层记录的 `MazeBuffID`——附加关 StageID / 绑定增益为 3018 = 420464 / `3110017`、3019 = 420494 / `3110006`、3020 = 420524 / `3110018`、3021 = 420554 / `3110017`、3022 = 420554 / `3110017`。即**游戏内附加关同样吃这份末法余烬**，本文决策 3 记的「推断项……游戏内未逐项证实」由此证实；节点 1/2 与附加关关卡在同一个赛季绑定的是同一个 BuffID。

**决策 1（修订本文决策 1/3 的 buff 口径）**：节点 3 的 `buff` 取附加关 `StageConfig` 自身的 `_BindingMazeBuff`（`_load_stage_monsters_by_id` 新增 `maze_buff`，`_load_tierce` 按 `HFIAAGAKFMD` 顺序取首个非空绑定，经同一份 `buffs` 表解析）。**不沿用层记录的 `MazeBuffID` 兜底**：跨记录推断正是本轮的问题来源，两者当前相等不代表将来相等，分叉时必须由关卡自身说话。节点 1/2 取值不变。

**取证基数**：5/5 星启赛季的附加关绑定 = 该赛季层记录 `MazeBuffID`（另两个模式的星启关卡无该绑定，故只有末日幻影受影响）；产物结构 diff 恰好 5 处新增（3018–3022 的 `tierce.nodes[2].buff`），除此外零差异。

**连带作废**：[ADR 0034](0034-终局节点详情面板字阶与区块节奏.md) 决策 4 与中性条把「节点三没有末法余烬」当作现状前提（区块节奏不随内容变化），该前提不再成立——决策 4 的规则本身继续有效。

**未做 / 回退点**：不回填其余赛季的同类推断；若上游给星启表补独立 buff 字段，回退点是 `_load_tierce` 节点 3 分支里那一处 `bid3` 读取与 `_stage_binding_buff`。

## 修订（2026-10-03）：节点 3 的 buff 补「关卡沉默时回退末层」兜底（忘却之庭 4 季）

**触发**：用户复核页面后问「忘却之庭详情页面，星启模式，节点三，缺乏记忆紊流」——与 2026-10-02 那轮同一句式（那次是末日幻影节点三缺末法余烬），根因却在数据的另一侧。

**取证**：

1. **产物缺口**：忘却之庭 4 个含星启赛季（1033–1036）节点 1/2 都带「记忆紊流」，节点 3 **四个赛季全空**；末日幻影 5 季节点三齐全（上轮补的），虚构叙事 4 季三节点皆空（其 `floor_details` 也无 buff，口径一致，不是缺口）。
2. **上游没有该绑定**：4 个附加关关卡（`HFIAAGAKFMD` = 30123123 / 30124123 / 30125123 / 30126123）的 `StageConfig.StageConfigData` 只有 `_Wave` / `_IsEliteBattle` / `_CreateBattleEvent` 三项，**无 `_BindingMazeBuff`**——所以「节点三只从关卡自身绑定取值」在忘却之庭是恒空分支，不是漏取。
3. **该增益是模式级的**：忘却之庭 57 季逐条比对，赛季级 `buffs`（`ChallengeGroupConfig.MazeBuffID`）与**每一层**的 `MazeBuffID` 逐条相等（1036 = `3030149`，4 个星启季 = 3030146–3030149），即上游用「每层都登记一遍」表达「整个模式都吃」。星启节点 1/2 就是该模式末层的上下半场，故带这份增益；节点 3（附加关）属同一模式、同一增益，游戏内同样生效——页面在同一 tab 内前两个节点有、第三个没有，是判据缺口而非事实差异。

**决策 1（修订 2026-10-02 修订决策 1 的「不兜底」）**：节点 3 的 `buff` 取值判据改为**关卡自身 `_BindingMazeBuff` 优先，附加关未登记时回退同赛季末层记录的 `MazeBuffID`**（与节点 1/2 逐字同源）。**与上轮禁令的边界**：上轮否掉的是「**有**关卡登记却改用层记录」——即用推断覆盖事实；本轮只填「关卡**沉默**」的空，`_BindingMazeBuff` 一旦存在仍以关卡为准（末日幻影 5 季取值逐条不变）。优先级不变、只在空位兜底，故两条规则不冲突。

**取证基数**：产物 diff 恰好 4 处新增（1033–1036 的 `tierce.nodes[2].buff`），`maze_extra.json` / `maze_boss.json` / `maze_peak.json` / 三个 `*.catalog.json`（目录卡只取 `tierce.{id, damage_types, countdown}`）零差异；虚构叙事 4 季仍全空——其层记录 `MazeBuffID` = `3031220` 未在 `MazeBuff` 注册（连层 tab 都没有 buff），回退值解析不出即不落字段，与「无增益」事实一致。

**风险与回退点**：回退源与未来可能出现的「附加关专属增益」冲突时仍以关卡为准，故唯一残留风险是上游**永不登记**却**确有**附加关专属增益——回退点是 `_load_tierce` 节点 3 分支里 `bid3` 的两行取值；若上游给星启表补独立 buff 字段，回退点同 2026-10-02。
