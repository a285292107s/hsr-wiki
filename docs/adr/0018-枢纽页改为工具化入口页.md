# 0018. 枢纽页由全屏媒体展示页改为工具化入口页

## 状态

`accepted`

> **2026-09-28 部分被推翻（见 [0019](0019-枢纽页导航条回归与首页改为版本上新页.md)）**：本 ADR 建立的**「无侧栏枢纽」形态**（`meta.bareNav` / `<html data-nav="bare">` / 内容区避让回退）与**决策 5 的首页形态**（`/` 首屏由板块索引承担）**已作废**——两枢纽页恢复导航条（全断点），`/` 改为版本上新页。
> **决策 1（两页共享品牌带 `.nk-hub-brand`）、决策 2/3（移除 KV Spine、CW 背景视频与 poster）、决策 4（移除枢纽滚轮）继续有效**。
> 下方正文按当时决策原样保留（历史记录，勿据其推断现状）；「枢纽页仍是 `meta.bareNav`」等中性后果段已随之失效。

> 本决策**推翻 ADR 0016 的前提句**（原文：「两个枢纽页（`/` 与 `/currency`）是全屏 KV/视频展示页，页面本身可滚但不承载浏览目的」），
> 并**移除 ADR 0016 决策 2 的「枢纽滚轮」通道**。
> ADR 0016 决策 1（侧栏「交换」→ 对方图签页）与决策 3（`/currency` 页内「枢纽返回行」）**继续有效**。
> ADR 0017 曾作废且明文「编号不复用」，故本决策占用 0018。

## 背景

枢纽页（`/` 与 `/currency`）此前是「全屏 KV / 视频展示页」：`/` 渲染官网 KV Spine 多层群像场景，
`/currency` 渲染官方活动页背景视频。两页都是 `meta.bareNav`（全断点不渲染侧栏），
**页面自身的索引就是全部导航**，而索引位于全屏媒体层之下。

实测（2026-09，冷缓存，1600×900）：

| 项 | 数值 |
| --- | --- |
| `/` 的 KV 场景（`home-bg`，4.6 五层） | 15 个 CDN 请求 / **8.23MB**（其中 PNG 6.6MB 不可压缩） |
| 外加 spine-player 运行时 | 587KB（gzip 107KB） |
| `/currency` 的 Hero 视频 | 本地随站 **5.09MB** + poster 79KB |
| 桌面首屏可用导航 | **0**（Hero `min-height: 100vh`，索引整体在首屏之下） |
| 鼠标滚轮下滚进入图鉴页 | 唯一「首屏直接可用」的交互，但**无任何屏幕提示**（仅手势） |

即：站点入口页的第一个视口是纯装饰，用户必须以「滚一屏」或「碰巧滚一下」为代价才能开始使用工具。
这与站点定位（数据展示型工具 wiki，会话形态是「落地 → 找角色 → 读数据」）直接冲突。

## 决策

**枢纽页是工具入口页，不是展示页：首屏优先让给板块索引，媒体层退场。**

1. **两页 Hero 统一为跨页共享原语 `.nk-hub-brand`**（声明于 `tokens.css`，与 `.nk-hub-footer` 同层同理由）：
   紧凑品牌带 = 英文副标 + 中文标题 + 定位副标，纯令牌渐变，桌面 200px / 平板 176px / 手机 148px。
2. **`/` 移除官网 KV Spine 场景 `home-bg` 与「随机五星立绘轮播」**：断点策略整体作废（不再有桌面/非桌面差异）。
3. **`/currency` 移除官方背景视频与 poster 兜底帧**（含视频状态机、后台标签暂停逻辑）。
4. **两页移除「枢纽滚轮」通道**：`useHubWheel`、`use-hub-wheel.ts` 及其测试一并删除。
5. **索引密度收紧**，`/` 在 1920×1080 首屏内可见**全部 8 行入口**（7 板块 + CW 网关行）；
   1440×900 首屏可见 ≥6 行。该数值由 `e2e/layout.spec.ts` 的可执行断言锁定。

跨模式通路在移除手势后**不出现空缺**（这是本决策可成立的关键）：

| 方向 | 可见通路 | 依据 |
| --- | --- | --- |
| `/` → `/currency` | 索引区 `CW_GATEWAY` 网关行 | ADR 0016 已确认 `CW_GATEWAY` 只存在于 `/` |
| `/currency` → `/` | 索引区末行「枢纽返回行」 | ADR 0016 决策 3；`bareNav` 深链下的唯一页内通路 |

枢纽滚轮移除的额外理由：品牌带形态下 Hero 仅 200px，滚轮劫持会把「从页面顶部正常下滚」
变成路由跳转——在手势的原始立论（「Hero 是全屏展示层、页面不承载浏览目的」）消失后，
它从「便捷通道」退化为「滚动陷阱」。

## 后果

**正面**

- **首页体积**：`/` 由 8.23MB + 587KB 运行时（+ 清单请求）降至 **0 媒体请求**；`/currency` 减少 5.09MB。
- **首屏可用性**：桌面首屏可用导航由 0 变为 8 行（1080）/ ≥6 行（900）。
- **两页结构同构**：品牌带与页脚均为跨页共享原语，「枢纽页结构角色相同」这一既有约定首次在
  媒体层上也成立（此前 Hero 媒体层因来源/断点语义不同而各自实现）。
- 少两处需要同步维护的动画契约：Spine 场景的断点重建、视频状态机与后台标签暂停。
- `nk-view-swap`（两枢纽互切）的过渡成本下降：不再有 WebGL 上下文重建与视频解码启动。

**负面**

- **放弃品牌视觉面**：首屏不再有官方美术素材，站点「游戏调性」的传达变弱，改由排版与令牌承担。
- **`/currency` 失去唯一的大型素材锚点**：该页此前靠视频建立「独立模式」的体量感，现仅靠黑金主题与文案区分。
- **两个资产文件成为孤儿**：`public/data/cn/assets/cw-hero.mp4`（5.09MB）与 `cw-hero-poster.jpg` 不再被引用，
  但**保留在库内作档案**——来源为官网活动页素材且无长期保留 SLA（同 ADR 0009 结论），
  删除后无法重新获取。它们不再被任何页面请求，只占部署体积。若要减小部署体积须另行裁决。
- **`initSpineSceneViewer` / `mountSpineScene` 失去生产消费方**（`/debug` 走 `createScenePipeline`）。
  保留为预留能力并在函数注释中显式标注「当前无消费方」，避免后续误据其推断页面行为。
- **`home-bg` 清单条目失去产品面消费方**：保留（调试台场景选择 + 历史存档条目 `home-bg-4.4/4.5` 同族）。
- **推翻既有硬策略**：`AGENTS.md`「首页 Hero 断点策略」整条作废，相关断点表、像素基线隐藏项、
  `docs/spine` 三篇文档的「枢纽页 Hero 背景」表述必须同批同步——否则文档会与实现互相打脸。

**中性**

- 枢纽页仍是 `meta.bareNav`（全断点无侧栏）：品牌带比 Hero 更矮，但**没有**改变「页内索引即导航」的形态，
  故本轮不动 `bareNav`（该形态是用户既有裁定，改它属另一决策）。
- 枢纽页文字入场动画保留（三段共用全局关键帧 `nk-fade`，错峰 0.2s/0.35s/0.5s + `backwards`），
  两页仍必须同时序。

## 替代方案

| 方案 | 为何未采用 |
| --- | --- |
| 保留全屏 KV，只把 Hero 高度收到 78vh 让索引露头 | 曾按此方向实施并验证：首屏能看到 1 行入口，但 8.23MB 媒体层与首屏装饰占比未变，只是缓解；工具站的价值是入口密度，不是「装饰少一点」 |
| 保留 KV，改为分阶段加载（先主背景层出画面再补角色层） | 同上：首视觉由 8.23MB 降到 2.15MB，但媒体层仍占满首屏。该优化已实施并回退——它是「保留 KV」前提下的优化，本决策取消了该前提 |
| 桌面保留 KV、仅移动端改品牌带 | 两页断点行为分叉，且桌面恰是工具使用主场景；`/currency` 的视频层同样无法只按断点解决 |
| 只改 `/`，`/currency` 维持视频 Hero | 两页结构角色相同是既有约定，只改一页会让互切（`nk-view-swap`）出现一边静态、一边全屏视频的失衡；且 5.09MB 视频的收益同样不成立 |
| 保留枢纽滚轮（仅降级视觉） | 手势立论依赖「Hero 是全屏展示层」；品牌带下留在 200px 区域内会成为滚动陷阱，且跨模式已有可见入口 |
| 顺手恢复两颗纽页的侧栏（让索引与侧栏并存） | `meta.bareNav`（全断点无侧栏）是用户既有裁定，且页内索引已完整承担导航，属另一决策，禁止顺带改 |
| 物理删除 `cw-hero.mp4` / `cw-hero-poster.jpg` | 源素材无长期保留 SLA，删除即永久失去；且删除它属部署体积取舍，与「首屏工具化」不是同一决策 |
