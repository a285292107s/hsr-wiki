# 0049 — 怪物数值合成链补上怪物侧精英组倍率

## 状态

`accepted`（**已实现**；修订 [0040](0040-怪物详情页战斗数值口径.md) 决策 1 的算式与决策 4 的注记表述，
承接 [0045](0045-怪物数值合成链补上实例修正值与默认等级.md) 的修正值位置；**决策 5 被 [0050](0050-出没样本带关卡语境与实战面板.md) 修订**——关卡侧精英组指派已落地）

## 1. 背景与问题

- 参考站（hsr.nanoka.cc）怪物页把 `MonsterConfig` 的两个原始分组字段直接上屏：**精英组**
  （`elite_group`）与**难度组**（`hard_level_group`）；我们只有后者的对应物 `level_group`。
- 米游社《星铁数据机制通论》（V1.1 第 2 版）§1.6 给出敌人五维公式：
  `属性 = 基础值 × 等级组系数 × 自身调整系数 × Π精英组别系数 + 自身调整值`。
  其中「Π精英组别系数」正是 ADR 0040 决策 4 搁置的「剧情与场景系数（社群术语修饰值 2）」的
  **身份**：它不是黑箱，就是 `EliteGroup.json`（1,423 组 × `{HPRatio, AttackRatio, DefenceRatio,
  SpeedRatio, StanceRatio}`）——倍率表在仓内 vendor 里，且难度组管「随等级变化的曲线」、
  精英组管「不随等级变的整体倍率」，两条独立缩放轴。
- 缺口：`MonsterConfig.EliteGroup` 未进转换、payload 与合成链。转换前影响面（实测分布）：
  2,722 条 MonsterConfig 里仅 27 条组号 ≠ 1，其中目录常规模板 5 个（100202003 / 100204007 /
  100205006 / 101201003 / 101203002，组 2 = HP×1.7 / ATK×0.8），其余为 9 位活动试用实例
  （组 100 / 140 / 142 / 705 等）。

## Considered Options

- **沿用「剧情与场景系数」这个措辞、不接 `EliteGroup`**（[0040](0040-怪物详情页战斗数值口径.md) 当时的选择）：放弃——参考站与文章公式逐位互证该系数就是 `EliteGroup.json`，措辞掩盖了可接入的事实。
- **只接怪物自身精英组、不接关卡侧指派**：本轮范围如此，但「同一只怪在副本里的实际面板」仍无从呈现——**该缺口由 [0050](0050-出没样本带关卡语境与实战面板.md) 补齐**。
- **以文章的组号表为准（组 3 = ATK 0.85 等）**：放弃——与现行 vendor 不一致（V1.1→4.6 漂移或文章笔误），一律以 vendor 实测为准。

## 2. 判定（验证链）

1. **参考站逐位验证（判定性证据）**：`/monster/1002050` 变体卡 `#100205006`（精英组 2 ·
   难度组 1，L95）显示 生命 51,203 / 攻击 574 / 防御 1,150 / 速度 132 / 韧性 60，与本仓数据
   独立折算 `102.3 × 1.7 × curve[95].hp = 51,202.88`、`18 × 0.8 × curve[95].atk = 574.41`
   逐位吻合（不含精英组的旧链得 30,119 / 718）⇒ **怪物自身 EliteGroup 参与合成**，
   参考站与文章公式一致。
2. **文章表格 ↔ 现行 vendor**：精英组 2 / 4 / 5 / 6 / 7 / 8 / 9 逐行吻合；组 3 文章写 ATK 0.85、
   现行 vendor 0.7（HP 1.3 一致，全表无 0.85+1.30 组合）⇒ V1.1→4.6 数值漂移或文章笔误，
   不影响「文章精英组别 = EliteGroup.json」的表身份判定。
3. **关卡侧指派链（vendor 实证）**：`StageConfig`（29,515 关）每关带 `EliteGroup +
   HardLevelGroup + Level`；`TreasureDungeonFloor.EliteGroup2 = 400` 命中 `EliteGroup.json`
   第 400 行（HP 0.664 / ATK 0.909）⇒ **怪物侧与关卡侧共用同一张倍率表**，文章的 Π（叠乘）
   由此而来。

## 3. 决策

1. **算式修订**（修订 0040 决策 1，承接 0045）：
   `值(等级) = 基准 × 维度修饰比 × 精英组倍率 × 等级曲线[难度组][等级] + 修正值`；
   韧性 = `韧性基准 × 精英组韧性倍率 + 修正值`（不入等级曲线链；当前被怪物引用的组韧性
   倍率全为 1）。
2. **payload 增 `elite_group`**（缺省 1）；**实例别名用自己的 config 记录、不继承模板**
   （与修饰比 / 难度组同一条坑位，测试锁死）。
3. **倍率表共享单文件** `public/data/cn/monster-elite-group.json`：全量 1,423 组落盘——
   关卡指派的组（隧洞组 3、花萼组 7 等）不被怪物配置引用，但关卡语境合成要用；
   详情页共享单例加载（与等级曲线同模式）。
4. **口径注记更新**：「模板基准 × 维度修饰比 × 精英组倍率（组 N）× 等级曲线（难度组 M）＋
   实例修正值；……未含**关卡侧精英组指派**（侵蚀隧洞、拟造花萼等副本的额外倍率）与剧情
   系数」。AI 快照四维标签不变（仍「模板基准」，快照不做第二份合成）。
5. **关卡侧逐关语境本轮不建模**：「N 关 M 级怪的实际面板」需要关卡选择语境的 UI 设计，属
   新功能而非口径修订；数据层（全量倍率表）已就位，后续只需接关卡 →
   (Level, HardLevelGroup, EliteGroup) 指派与 Π 叠乘。
6. **endgame 不动**：`_monster_out` 跳过键名单增 `elite_group`（与 stat_ratio / level_group
   同名单），终局敌方卡口径不变。

## 4. 影响面

- `monster_common`：新增 `_elite_group` / `load_elite_groups`；聚合输出增 `elite_group`。
- `monster_detail`：落 `monster-elite-group.json`；详情 payload 增 `elite_group`。
- 前端：`MonsterDetail.elite_group`；`items.ts` 增共享单例；`monster-stats.ts` 合成链加
  `eliteRatios` 入参、`monsterStanceValue` 加精英组韧性位；详情页加载 + 注记改写。
- 数值变化：2,722 条里 27 条实例的组内倍率 ≠1 维度变化；目录 632 条里 5 个模板
  （组 2：HP×1.7、ATK×0.8）；其余条目零变化。
- 测试：pytest（倍率表解析 / 别名不继承 / 详情透传 / 增量源登记）、vitest（合成链新段 +
  参考站镜像用例）、e2e `layout-monster` 新增精英组对照守卫（100205006，期望值数据派生）。
