# 角色数据还原样例：黄泉（Acheron / AvatarID 1308）

> 目的：以「黄泉」为真实样本，演示如何把分散在 `ExcelOutput` / `Config/` / `TextMap` 的数据**拼装成一张完整角色页**。
> 数据均直接取自本仓库（StarRailData 快照），未做任何人工编造。
> 涉及文件：`ExcelOutput/AvatarConfig.json`、`AvatarPromotionConfig.json`、`AvatarRankConfig.json`、`AvatarSkillTreeConfig.json`、`AvatarSkillConfig.json`、`AvatarBaseType.json`、`ItemConfig.json`、`Config/ConfigCharacter/Avatar/Avatar_Acheron_00_Config.json`、`Config/ConfigAbility/Avatar/Avatar_Acheron_00_Ability.json`、`Config/ConfigAnimEvents/Avatar/...`、`TextMap/TextMapCHS.json`。

## 7. 文本与图片还原说明

- **名称 / 技能描述**：字段为 `{"Hash": <数字>}`，查 `TextMap/TextMapCHS.json`（简中）或 `TextMapEN.json`（英文）即得中文/英文。描述中的 `<color=#...>`、`<unbreak>` 为游戏富文本标签，wiki 渲染时需清理或转换为 Markdown/HTML。
- **星魂名 / 行迹名**：字段为**字符串 token**（如 `AvatarRankName_130801`、`SkillPointName_1308101`），这些是 `TextMap` 的**键名**；`TextMap` 本身以该键的 xxhash 数值为键，因此需在构建流水线里对 token 计算 xxhash 后再查表（StarRailData 的 README 提供了 xxhash 的 JS/Python 实现）。
- **图片**：技能/立绘以 `SpriteOutput/...` 相对路径给出（如 `SpriteOutput/SkillIcons/Avatar/1308/SkillIcon_1308_Normal.png`），资源本体不在本仓库，需对接资源库 / CDN。

## 9. 还原过程中的坑（来自本样例）

1. **`AvatarSkillConfig` 同 `SkillID` 出现多条**：每个技能按等级/变体重复成数组项，去重后取一条即可（本样例去重得 130801/130802/130803/130804/130806/130807 及子技能 130814–130817）。
2. **突破行缺 HP 字段**：黄泉的 `AvatarPromotionConfig` 行无 `MaxHPBase/Add`，HP 取值需另查或确认口径。
3. **星魂材料 `11308` 不在 `ItemConfig` 主表**：它是角色专属「命星」，存于 `ItemConfigAvatarRank`（或 `ItemConfigAvatar`），需用对应表还原名称。
4. **子技能描述为空**：`啼泽雨斩 / 黄泉返渡` 的 `Desc` 为 `<None>`，实际文案在主终结技描述中，不要当成缺失。
5. **token 类名称需 xxhash**：星魂名、行迹名是字符串 token，不能像数值 Hash 那样直接查 `TextMap`，必须计算 xxhash 后才能命中。

## 10. 一句话结论

以黄泉（AvatarID 1308）为例，一个完整角色页 = `AvatarConfig`（身份/稀有度/属性/命途）+ `AvatarPromotionConfig`（突破与成长）+ `AvatarSkillConfig`（技能文案/图标）+ `AvatarSkillTreeConfig`（行迹）+ `AvatarRankConfig`（星魂）+ `AvatarBaseType`（命途名）+ `ItemConfig`（材料名），底层再叠加 `ConfigCharacter/ConfigAbility/ConfigAnimEvents` 还原逻辑与表现，所有文本经 `TextMap` 还原、图片经 `SpriteOutput` 路径对接。该流程对全部 ~70+ 可玩角色通用，仅 AvatarID 与具体数值不同。
