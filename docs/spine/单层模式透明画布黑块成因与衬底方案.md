# 单层模式透明画布黑块成因与衬底方案

> 关联页面：KV 场景验收台（`/debug` 的「KV 场景」标签）· `src/app/debug/SpineKvSection.vue`
> 实证对象：home-bg 场景（01_bg_pc 主背景 + 9 层角色，含 03_jizi_pc 打光层）

## 现象

单层模式（每层独立画布渲染）下，03_jizi_pc 层显示大面积黑块；合并渲染（单画布多骨架）下同一层正常。其他层（如 01_bg_pc、09_nvzhu_pc）在单层模式下无黑块。

## 根因：混合模式对透明 dst 退化

单层模式的画布初始为透明（rgba(0,0,0,0)）。spine-webgl 的 PolygonBatcher 混合表中 screen / additive 的 srcAlpha 系数为 GL_ONE（不依赖源 alpha），对透明 dst 混合时：

- **screen**（`ONE / ONE_MINUS_SRC_COLOR`）：`RGB = src·1 + dst·(1−src) = src + 0 = src` → 纹理被**原样写出**。打光蒙版贴图里大面积不透明纯黑区直接落地成不透明黑像素。
- **additive**（`SRC_ALPHA / ONE`）：`RGB = src·src.a + dst·1 = src·src.a` → 暗色高 alpha 像素（实测 rgba(36,8,13,213)）自身即暗，无背景可加，同样是黑块。

与预乘 Alpha 无关：官网 atlas 无 pma 字段、像素取证为直通 alpha，`premultipliedAlpha: false` 是正确配置（`docs/adr/0009-官网spine动画增量接入.md`）。

## 为什么只有 03_jizi_pc 中招

触发黑块需同时满足三个条件，03_jizi_pc 是唯一三层条件都齐的层：

1. **混合 slot 数量多**：15 个非 normal 混合 slot（S125~S137，additive×13 + screen×2）；
2. **打光贴图含大面积不透明纯黑区**（蒙版式打光设计：黑 = 不发光，亮 = 发光）；
3. **混合区域落在透明处**：打光（光晕/轮廓光）大多画在角色主体像素之外的区域，dst 为透明。

其他层不中招的原因分三类：

| 层 | 情况 | 为什么不黑 |
|---|---|---|
| 01_bg_pc（主背景） | 含 7 个混合 slot | normal 部分先铺满全画布（alpha=1），混合 slot 的 dst 已是自身真实画面 → 层内等效合并渲染 |
| 大多数角色层 | 无混合 slot | normal 对透明 dst 是正常 alpha 合成，透明处保持透明 |
| 09_nvzhu_pc | 仅 1 个 additive（S0） | 贴身软光（半透明渐变、紧贴角色主体，dst 基本是角色像素），退化效果肉眼不可辨 |

## 为什么合并渲染正常

单画布按层序绘制：01_bg_pc 先画铺满（dst 恒为真实画面，alpha=1），轮到 03_jizi_pc 的混合 slot 时：

- screen 黑区（src≈0）：`RGB = 0·1 + dst·(1−0) = dst` → 不改变背景，即「不加光」的蒙版语义正确表达；
- additive 暗区：`RGB = src·src.a + dst ≈ dst` → 对画面几乎无贡献；
- alpha 恒为 1（`src.a + 1·(1−src.a) = 1`），无半透明残留路径。

关键洞察：打光蒙版的黑色区域语义是「透明/无效果」，依赖既有画面的乘法/加法关系来表达；dst 缺失（透明黑）时公式退化为「原样写纹理」，黑色蒙版直接实体化。

## 解决方案（验收台单层模式）

### 1. 单层画布加不透明深色衬底

`createPlayer` 的 `backgroundColor` 由 `'00000000'`（透明）改为 `LAYER_BG = '0d1326'`（不透明深蓝，与舞台底纹同色系）。混合 slot 的 dst 非透明 → 退化黑块从根源消失，打光正常叠加在深色底上，预览接近真实观感。

副作用与补偿：

- **采样稳定性**：单层 player 开启 `preserveDrawingBuffer: true`，像素采样不受 rAF 暂停影响（否则读回可能拿到空帧）。
- **诊断语义**：实验（打光隐藏/显示、强制 normal）在衬底上的对比依然可见，且更贴近真实场景。
- **已过时（单层导出与透明对照均已移除）**：早期版本用「背景」单选组切回透明观察混合区，并靠 `stripLayerBg()` 抠色导出透明底叠加图；现单层模式固定衬底、**不提供导出**（`导出 PNG` 仅合并模式，直接导出合并画布）。黑块成因仍可按下文公式复算，无需透明对照。
  旧实现细节（保留结论）：逐像素抠色须比较衬底色是否精确相等（WebGL clearColor 为精确色值，getImageData 读回可精确匹配）；**禁用 `destination-out` 整块填充**——它不比较颜色，会把整个画布删空（实测踩坑）。

### 2. 保持合并渲染为验收基准不变

一键验收走单画布合并渲染 + 黑块检测（近黑不透明像素占比，≥3% 黄 / ≥6% FAIL，正常约 1.2~1.4%），不随单层衬底方案变化。

## 验证方式

1. 单层模式下切到 03_jizi_pc：黑块消失，打光正常叠加在深色衬底上；
2. 点「打光」隐藏混合 slot：画面只剩角色主体（黑块来源确认）；
3. 合并渲染一键验收：报告 PASS、nearBlack 占比正常；
4. 合并模式导出 PNG：得到合并渲染的验收图（单层模式无导出）。
