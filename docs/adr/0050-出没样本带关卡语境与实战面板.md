# 0050 — 出没样本带关卡语境与实战面板（「N 关 M 级」）

## 状态

`accepted`（**已实现**；承接 [0049](0049-怪物数值合成链补上怪物侧精英组倍率.md) 决策 5——
关卡侧精英组指派落地）

## 1. 背景与问题

- 0049 只接了怪物自身精英组；**关卡侧指派**（`StageConfig` 每关行的 `Level / HardLevelGroup /
  EliteGroup` 三件套）未建模，「同一只怪在副本里的实际面板」无从呈现。
- vendor 实证：29,515 关逐关带三件套；**凝滞虚影关卡（`FarmElement`，203 关）全部指派精英组 6**，
  与米游社《数据机制通论》「凝滞虚影使用精英组别 6（攻击 1.00 / 生命 1.40）」**精确互证**；
  拟造花萼（`Cocoon`）用组 2 / 3 / 29 与逐关专属组混合。文章的「隧洞组 3 / 花萼组 7」与现行
  vendor 不一致（V1.1→4.6 漂移）——**面板一律以 vendor 为准**。

## 2. 决策

1. **数据**：appearances 样本增关卡语境 `{level, level_group, elite_group}`——关卡行原值透传、
   缺位不落键；**合成留在前端**（`monster-stats.ts` 同一算式），转换器与 AI 快照不出现第二份实现。
2. **Π 语义**：面板 = `基准 × 维度修饰比 × (自身精英组 × 关卡精英组) × 曲线[关卡难度组][关卡等级]
   + 修正值`。新增纯函数 `monsterEliteRatiosProduct`（逐维叠乘、缺位维度按中性 1、整行缺位不参与）。
   韧性不入面板行（战斗数值区已有；当前被引用组的韧性倍率全 1）。
3. **UI**：出没样本 chip 升为两行小卡——关卡名行逐字不变（名字挂独立 span 供断言），第二行
   「等级 N · HP … / ATK … / DEF … / SPD …」**仅在四维全部合成成功时渲染**（曲线缺行 / 缺组 →
   该样本无面板，宁缺不假）。
4. **AI 快照不同步**（沿用 0026 / 0029 取舍）：快照不实现第二份算式，样本仍只出「活动名 · 关卡名」。
5. **终局敌方卡不动**：无等级语境；且终局语境（忘却之庭类）本无精英组修饰——与文章
   「忘却之庭的敌人未见修饰」一致。

## 3. 影响面

- `monster_extra.load_appearances` / `_stage_context`：样本透传三件套。
- 前端：`MonsterAppearanceSample` 类型、视图 `samplePanels` 计算 + chip 两行结构、
  `monster-detail.css` 面板行样式、AI 快照零改动。
- e2e：样本名断言挂 `.nk-mob-appear__sample-name`（chip 内新增面板行）；新增面板对照守卫
  （期望值由 payload + 双共享表独立折算，目标条目数据派生）。
- 数据：2,722 份详情的 `appearances.samples` 增键（带 Level 的关卡行几乎全部）。
