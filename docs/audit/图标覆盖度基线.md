# 图标覆盖度基线（ADR 0070）

> 由 `tools/check-icon-coverage.mjs` 判定，基线文件 `config/icon-coverage-baseline.json`。
> 每次「补图 / 新增引用 / 新增分类」后跑 `--write-baseline` 刷新本文件与基线 JSON。

## 一、判定口径

| 类别 | 含义 | 处置 |
| --- | --- | --- |
| **missing** | 引用了、解包盘也有源图，但没导出 | **必须补**（`ingest-icons.py --from-refs`） |
| **unsourced** | 引用了、解包盘与上游都没有 | 靠远端兜底，登记 `knownDeadRefs` 或接受占位 |
| **cdnBacked** | 分类设计上走 CDN（`uiart` / `rank` / `element` / `pathicon`） | 不计缺 |

门禁只卡**基线之外的新增缺口**：基线内已知缺口不阻塞，新增即 `pnpm build` 失败。基线文件只声明 `scope: site`；`--scope excel` 是诊断视图，**不可**带 `--strict` 进 build，也不可用它 `--write-baseline` 覆盖 site 基线。

## 三、已知的「不该归一」（重要，防回归）

以下在 `config/sprite-map.json` 里以 `ignoreLocal` / `ignoreReason` / `local` 模式固定，**改前必读**：

1. **`mostericon` / `monsterroundicon` / `monstermiddleicon` 同名不同图**
   `Monster_1002011.png` 在 `mostericon` 是 16,494 B、在 `monstermiddleicon` 是 62,345 B。归一是**有损**的，三者都路由到 `monstermiddleicon` 只是「给列表用」，原目录选择权在调用方。
2. **`gridfight-asset` 目录段必须全小写，`gridfight-equipment` 文件名必须保留大小写**
   `augmentbig/100101.webp` vs `GridFight_RoleBox1.webp`——两种相反口径，`afterFirstLower` 与 `leaf` 不能互换。
3. **`skillicons` / `bufficon` / `tutorialpic` 层级两侧不一致**
   导出侧压平（`skillicons`）或多一层（`bufficon`/`TutorialPic`），解包侧相反。分别用 `leaf` / `fullExact`。
4. **`rank` 无法镜像**
   唯一源是 nanoka `ui/ui3d/rank/_dependencies/textures`，本机解包盘无 `ui3d` 树。
5. **永久无源文件**
   `trace/IconCriticalDamage`（只有 `IconCriticalChance`）、`relicfigures/IconRelic{Body,Foot,Neck,Goods}`。

## 四、常用命令

```bash
# 看站点侧缺口（日常）
node tools/check-icon-coverage.mjs

# 看解包侧全量缺口
node tools/check-icon-coverage.mjs --scope excel

# 补站点侧缺的（含深底联系表人眼核对）
python tools/ingest-icons.py --from-refs --sheet temp/sheet-icons.jpg

# 补完刷新基线
node tools/check-icon-coverage.mjs --write-baseline

# 本机细分「有源可补 / 上游也无源」
python tools/ingest-icons.py --verify --scope site
```
