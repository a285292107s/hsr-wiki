# Dev Server 固定端口与严格失败策略

## Status: accepted（2026-09-03 端口号更新为 6188，strictPort 策略不变）

## Context

Vite 默认端口行为：`pnpm dev` 在被占用端口时**静默递增**端口（5173→5174→5175…），长期单实例开发下产生三类问题：

1. **端口堆积**：遗留 dev server 实例不被清理时，每次启动占用新端口，内存浪费且难以追踪（曾出现 5173~5175 连续堆积）。
2. **实例混淆**：浏览器标签页/缓存指向旧端口，容易连接错误实例；HMR 推送到旧实例造成"改动不生效"的假象。
3. **无提示**：端口递增静默进行，终端仅不显眼地打印新 URL，用户不易察觉端口已漂移。

**端口号更新（2026-09-03）**：原固定端口 5173 为 Vite 默认端口，用户多项目开发时易与他项目 dev server 撞端口（他项目沿用 5173 默认或静默递增至 5174）。改用冷门端口 **6188**（避开 Vite/常用工具默认段，已在机器上探测空闲）。strictPort 严格失败策略不变。

## Decision

`vite.config.ts` 的 `server` 配置固定端口并启用严格失败：

```ts
server: {
  port: 6188,
  strictPort: true,
  // ...
}
```

- 端口被占用时 `pnpm dev` **立即报错退出**（`Error: Port 6188 is already in use`，exit code 1），不做静默递增。
- 配套实践：启动 dev server 前先探测 6188 是否有已运行实例，**有则复用**；仅当无任何实例可访问时才新起，且新起实例验证结束后主动关闭。

## Considered Options

- **保持默认递增**：宽容默认，任何情况都能启动，但造成端口堆积与实例混淆。被拒——本项目为单实例长期开发，固定端口收益更高。
- **仅设 `port` 不设 `strictPort`**：Vite 中只设 port 时被占用仍会递增，与默认行为无异。被拒。
- **`strictPort` + 探测复用实践**：报错信息明确，配合"先探测再启动"的复用规范从根源杜绝堆积。采用。
- **换冷门端口（6188）**：避开 Vite 默认 5173 段（5173→5174 静默递增区），与他项目 dev server 撞端口概率大降。采用（2026-09-03）。
- **换回 5173（默认）**：与他项目默认端口冲突，违背本次改动初衷。被拒。

## Consequences

- 端口被占时 `pnpm dev` 立即以 exit code 1 退出，错误信息明确，逼使开发者关闭旧实例或复用。
- 开发流程固定为：探测 6188 → 有实例则复用（curl 验证可用性）→ 无实例才后台新起。
- 本地开发 / dev 内研究线调试台 = `http://localhost:6188/` 与 `http://localhost:6188/debug`（侧栏「调试台」入口同样可达）。
- Playwright webServer / baseURL 同步指向 6188（`playwright.config.ts`），e2e 自动探测复用该端口实例。
- 已实测验证（2026-08-10，端口 5173 时代）：有占用 → 立即报错退出；无占用 → 正常监听。端口号更新后 strictPort 行为不变。
