# 0044. 首领机制随敌方卡呈现（`boss_traits` 场次键 → `boss_guides` 模板键 + 阶段链路）

## 状态

`accepted`（**已实现**：`endgame` 模块的 `boss_traits` 退役、改为赛季级 `boss_guides`（**敌方模板键**）+ 敌方条目 `boss_guide` 指针，并同批消费 `MonsterGuidePhase` / `MonsterGuideSkill` / `MonsterGuideSkillText` 三张源表；新增共享件 `EndgameBossGuide.vue` 挂在 `EnemyCard` 卡内，`EndgameTraitGroup.vue` 与看板层「首领特性」区块整块退场；**同轮按用户裁决补上效果抵抗**：敌方详情卡新增 `debuff_resist` 行，新增本地图标分类 `statusimmune`（11 个 webp 入库）。**修订 [ADR 0029](0029-末日幻影赛季增益分场与首领特性.md) 决策 2 / 3、[ADR 0030](0030-末日幻影详情页层级星启子tab.md) 决策 2 的区块归属、[ADR 0033](0033-星启模式改单节点看板.md) 决策 3 / 12 的「整组一张卡片」、[ADR 0035](0035-末日幻影层tab改半场卡片与单看板.md) 决策 3 的看板块序**）

## 背景

用户先问「末日幻影的首领特性几个效果、绑定在哪个怪物身上、数据上看得出来吗」，随后裁决「把首领特性放进对应的怪物卡片中」，并在两项设计自由度上选择「特性下沉 + 阶段链路一次做完」「效果抵抗另议」。

取证（全量 22 季 / 191 个场次块，非抽样）：

1. **产物看不出归属**：`boss_traits` 只有 `stage1/stage2/tierce` 三个场次键，条目只有 `id/name/desc/param_list`——怪物归属在 `_stage_traits` 的合并去重里被丢掉；绑定关系只活在上游 `MonsterGuideConfig.MonsterID(//100) → TagList → MonsterGuideTag`。
2. **下沉后归属唯一**：191 个场次块**每块恰好 1 只波次敌方命中登记**（156 块 1 敌；20 块 2 敌都是「首领 + 杰帕德」，杰帕德无登记）⇒ 不存在必须合并的多命中场次。
3. **召唤物与首领同组**：命中登记的召唤物 **44 处全部与同场首领同组**（灭星兽的灾虐的右手 / 黎明的左手 / 反物质引擎、幻灭者的虚妄之母、影将军的蚀心兽）⇒ 若按整棵敌方树 join，同一组机制会在同一场里渲染最多 4 份。
4. **换键零丢失**：22/22 季**各层**首领的特性组 ⊆ 现有赛季级 `boss_traits` 覆盖的组（同模板跨难度同组，`MonsterGuideConfig` 每个模板 4 个难度实例的 `TagList` 逐字相同 21/21）。
5. **阶段链路齐全**：`MonsterGuideConfig.PhaseList → MonsterGuidePhase` 29 条（21/22 个首领引用：13 个 2 阶段、8 个 1 阶段、1 个 0），**29/29 有阶段说明与官方应对策略**；`MonsterGuideSkill(Text)` 57 + 57 条小节问答（如「如何高效削减首领幻影的韧性」）。三段文本均无 `#N[i]` 占位符、每招式恰 1 条文本。
6. **两个易混链路不入展示**：`DifficultyGuideList`（17/21 逐难度不同）与 `TextGuideList`（20/21）**逐难度不一致**，且 `DifficultyGuideList[0]` 与「坚防守备」的 Tag 描述**去标签后逐字相同**——同一事实两个展示位。

## 决策

**我们把首领机制从「赛季级场次维度」改为「随敌方卡走」，并把阶段链路一并接上**：

1. **数据层·模板键正文**：`_load_boss_guides` 把 `MonsterGuideConfig × MonsterGuideTag × MonsterGuidePhase(×Skill×SkillText)` 聚合为 `{敌方模板 ID: {"traits": [...], "phases": [...]}}`，赛季级落 `boss_guides`；`boss_traits` 退役。配置表缺该模板时仍用 `Tag.SkillID // 100` **唯一**反查补齐（影将军 `2035012` ↔ 蚀心兽 `2033022`），反查键与登记键指向同一块正文。
2. **数据层·指针**：`_attach_boss_guides` 给**波次清单里的**命中敌方条目写 `boss_guide`（模板 ID 字符串），**每一层都写**（机制随难度不变，但卡片要按当前层各自的条目取）；召唤物与护卫**不写**（决策依据 = 背景 3）。正文只落一份，不逐层/逐节点复制。
3. **阶段链路**：阶段条目 = 阶段名（自带「阶段一：…」）+ 机制说明 + 官方应对策略原文（自带「应对策略：」前缀）+ 小节问答（问句 + 答句）；不消费 `DifficultyGuideList` / `TextGuideList`（背景 6）。
4. **展示层·卡内两分区**：`EndgameBossGuide.vue` 在敌方卡内渲染「首领特性」与「阶段机制」两个分区，沿用卡内既有语言（上发丝线 + 上内距，与「弱点/抗性」「技能」「召唤物」同构），**不另套一层盒子**；看板层的「首领特性」区块整块退场（**不双显**，沿用「同一事实只出现一次」的既定判据）。四模式共用 `EnemyCard`，无指针即不渲染 ⇒ 零 `modeKey` 分支。
5. **前端只查表不推导**：前端 `guides[m.boss_guide]` 是同一 payload 内的字典查表，与 [ADR 0029](0029-末日幻影赛季增益分场与首领特性.md) 的「禁止运行时 join 源表」不冲突——**判据边界：跨数据源的推导一律在转换期；同一 payload 内的 id→条目查表是既有模式**（如 `buff_groups[node.origin]`）。前端不得按 `tpl` / `id // 100` 自行推导模板。
6. **效果抵抗：按用户裁决本地入库（原记「本轮不做」，同轮实施）**：`MonsterConfig.DebuffResist` × `MonsterStatusResistanceType`（`Type → IconImmune*.png`）→ 敌方 `debuff_resist[{key, value, icon}]`，**只随「敌方详情卡」形态输出**（末日幻影楼层 / 三模式星启节点 / 异相仲裁单关；轻形态与期级合并列表剥掉，与 `intro` / `skills` 同档）。展示 = 卡内「效果抵抗」行（图标 + 百分比），排在「抗性」行之后。
   - **上游没有文字名**（TextMap 搜「免疫冻结 / 免疫禁锢 / 免疫缠绕」等 0 命中；`MonsterStatusConfig` 里没有 `STAT_CTRL*` 同名 `ModifierName`，按后缀匹配只会得到「深寒 / 待岗 / 债务危机」这类无关状态）⇒ 图标只作装饰（`alt=""` + `aria-hidden="true"`），可读信息由行首标签「效果抵抗」与百分比承担，`title` 供鼠标查看；**禁止**自造状态名。
   - 图标在 nanoka 完全缺失（`trace/`、`bufficon/`、`avatarshopicon/`、`spriteoutput/ui/avatar/icon/` 四条候选路径 HEAD 全 404）、只在 jsDelivr `ui/avatar/icon/` 有 ⇒ 按用户裁决**下载入库**为新的本地分类 `statusimmune`（11 个 webp、约 28 KB；由 128×128 PNG 按 alpha 包围盒裁去透明留白后转码——原图字形只占画布中间一块，直接缩放会看不清）。该分类是**第二个 `jdPrimary` 分类**，`jdPrimary` 在这里的作用是让本地缺失时的回退落到 jsDelivr 而不是必然 404 的 nanoka。

## 后果

**正面**

- 页面首次能回答「这一战的首领有哪些机制、分几个阶段、官方怎么应对」，且信息落在读者正在看的那只怪上（此前站内任何页面都没有 `MonsterGuidePhase` 链路）。
- 卡内「效果抵抗」行让「这只首领吃不吃控制 / 持续伤害」一眼可读（196 条层级敌方 + 137 个星启节点 + 141 个仲裁单关带该字段）；11 个免疫图标随站入库（约 28 KB），不依赖外部镜像可用性。
- 体积可控：`maze_boss.json` 561 → 632 KB（+71 KB，含阶段正文与跨赛季重复）；若按场次逐层复制特性 + 阶段，代价从 +178 KB 起。
- 指针方案对「同场多怪」天然安全：命中数恒为 1，且召唤物结构上拿不到指针（`EndgameSummons` 不接收该 prop）。

**负面**

- e2e 是最大成本：`layout-endgame.spec.ts` 里 42 行命中中约 25 行锁的是「整组一张卡」的卡形 / 内距 / 字阶，全部失效并重写为卡内分区判据；块序断言由 4 块 → 3 块。
- 卡片高度显著增长：4 条特性 + 1~2 个阶段（含应对与问答）全落右栏，手机端卡片变长（视觉观感交用户 RunPreview）。
- 同一段正文在**同一份 `maze_boss.json` 内按赛季重复**（一个首领出现在多期时各存一份，实测 `traits` 196 条 / `phases` 85 条 vs 全局 68 / 29）：不把文件顶层结构改成 `{seasons, boss_guides}` 就无解，本轮不做。

**中性**

- 归属语义是「首领组」而不是单体：一组 `TagList` 可挂多个模板（1001 组挂幻灭者与其虚妄之母形态；1003 组挂灭星兽与其三个部件）。末日幻影每场 1 首领，观感等价；数据层表达不了「这条属于头、那条属于手」。
- 卡内两个分区的块序 = 名称/标签 → 弱点/抗性 → 图鉴介绍 → 首领特性 → 阶段机制 → 技能 → 召唤物（可逆的展示迭代，改序只动 `EnemyCard.vue` 一处）。
- AI 快照仍不同步（沿用 [ADR 0026](0026-污染等级进入终局玩法详情页.md) / 0029 的取舍）：`/endgame/:mode/:id` 快照来自 `*.catalog.json`，要带上首领机制需把该字段汇进 catalog + 生成器 + 守卫三处。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 全量下沉（每个敌方条目附完整机制条目） | 191 个场次块 × 4 条 = 764 个副本（+178 KB），同一段文字复制 764 份 |
| 只给怪物带 TagID 指针、正文仍留场次键 | 可行，但多一层 id→条目展平；且场次键方案依赖「各层首领组都被末层覆盖」这条隐含前提（本轮实测成立，换模板键后连前提都不需要） |
| 前端按 `m.tpl` / `id // 100` 自行推导模板 | 违反 0029 的禁令方向；alias 场景要靠 `SkillID // 100` 反查，而前端没有这两张源表 |
| 看板区块保留 + 卡内同时显示 | 同一事实出现两次（「记忆紊流」那轮的既定判据） |
| 把召唤物/部件也挂上机制 | 44 处命中全部与同场首领同组，一场会渲染最多 4 份同一组机制 |
| 效果抵抗继续记账、不上屏（决策 6 原案） | 用户裁决改为本地入库：图标仅 28 KB，而「哪些控制/持续伤害打不进去」是首领战的核心信息 |
| 顺带补 `DifficultyGuideList` / `TextGuideList` | 与首领特性同文（去标签逐字相同）、且逐难度不同 ⇒ 同一事实两个展示位 |
| 效果抵抗按 key 后缀自造状态名（`STAT_CTRL_Frozen` → 「冻结」） | 后缀匹配实测得到的是「深寒 / 待岗 / 债务危机」这类无关状态（`MonsterStatusConfig` 里没有该批类别记录），属自造文案 |
| 效果抵抗只走 jsDelivr、不本地入库 | 该批图标 nanoka 全缺，站点图标的常态可用性会挂在一个已停更的 fork 上；本地入库仅约 28 KB |
