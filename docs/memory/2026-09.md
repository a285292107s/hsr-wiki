## 2026-09-03

### Spine 4.0 格式骨架在 4.2 运行时下姿态错误（legacy `transform` 被静默丢弃）
- 现象：1512（知更鸟•晴歌）骨架「上半身被错误扭转近 180 度」，资源本身自洽（atlas 页名与 manifest 逐字一致、attachment 全有定义）。
- 根因：骨架 JSON 中 37 根骨骼带 4.0 格式字段 `"transform": "noRotationOrReflection"`（不继承父骨骼旋转/反射）；spine-ts 4.2 解析器**只读 4.1+ 的 `inherit`、静默丢弃 `transform`** → 这些骨骼按 Normal 全继承解析（探针实测世界旋转多约 106.74°）。4.1.23 运行时仍认识该字段，数值与 4.0.31 基准逐骨骼一致。官网原站正常，是因为其内嵌运行时带 mihoyo 定制补丁把 `transform` 映射到 `inherit`。
- 受影响判定方法：骨架 JSON 中按骨骼计数 `"transform":"` 字段；凡 `skeleton.spine` 为 4.0 系（含 `"4.0-from-…"` 前缀降级导出）一律在 manifest 官方条目标 `"runtime": "4.1"`。
- 决策（不加第三运行时、不重提取、不改 vendor）：manifest 官方条目新增可选 `runtime` 标记，分派收口 `src/services/api/spine.ts`（skel→4.1 / official 按标记缺省 4.2 / scene→4.2）；运行时版本常量见 `src/spine/constants.ts`；`check-spine-manifest` 守卫校验 runtime 值合法性。
- 坑位：两个 spine-manifest JSON 格式不同（official 为 2 空格缩进 CRLF，nanoka 为紧凑单行 CRLF）——整文件 `JSON.stringify` 重写会破坏格式且守卫不查，编辑必须做定向文本替换。
- 排查路径可复用：静态一致性排除资源错配 → 双运行时姿态探针（同 JSON 分别用 4.0.31 / 4.2.43 解析后比对关键骨骼世界矩阵）→ 字段级根因 → 原站实锤（活动页 `pz_*.js` config 包内嵌骨架元数据与播放参数；外层版本页只是壳）。

### 裁决：跨页共享原语命名中性化（.nk-hub-footer + --font-mono）
- 现象：货币战争枢纽页复用首页的 `.nk-home-footer` 与 `--home-mono`，而 `currency-hub.css` 与 `CurrencyHubView.vue` 的注释都写着「不抽 tokens 共享原语、判定为不共享」——声明与实现互相打脸；同一个等宽字体栈同时存在四种写法（全局 `--hub-mono`、字面量完全相同的 `--cat-mono`、8 处裸字面量）。

### 模式切换入口收敛为三条通路（页内按钮移除 + 赛季说明下线）

### 串行转场 → 交叉过渡（空窗消除）与「叠层方向」的实测翻转
- 交付：`App.vue` 去掉 `<Transition mode="out-in">`（串行转场 → 交叉过渡）；`tokens.css` 过渡段拆出独立的 leave/enter 规则（leave 0.26s 无延迟；enter 0.22s + `transition-delay: 60ms`，即错峰），三条降级通道（平级 fade / 手机 <768px / `prefers-reduced-motion`）同步为「交叉 + `transform: none`」。
- **重要根因（推翻了改造前的既有假设）**：原设计的「叠层方向靠 DOM 顺序天然成立（离场在上）」**是错的**。目录页 `#nk-catalog-app`（catalog.css:9）与首页 `#nk-home-app`（catalog.css:442）的**根元素本身就是 `position: absolute`**，`CatalogPage.vue` / `HomeView.vue` 直接渲染它们 → 交叉过渡时**两个视图节点同为 absolute、同为 `z-index: auto`**，绘制顺序退化为 DOM 顺序；而实测 Vue 3.5 的 DOM 顺序是 `[旧页, 新页]`（新节点插在旧节点之后，因旧节点带 transition hooks 被延迟移除）→ **不加干预时是「进场页在上」**，与目标相反。改造前 `mode="out-in"` 从不让两页同屏，所以这个潜在缺陷一直没暴露。
- 修法：给 `.nk-view-*-leave-active` 加 `z-index: 1`（**刻意的最小安全值**）。`#app`（tokens.css:639）为 `position: relative` 且**无层叠上下文**（`isolation:auto`/`transform:none`/`opacity:1`，实测）→ `1` 与侧栏 100000 / Toast 99999 在同一层叠上下文内比较，不可能盖住它们。**禁止在此处改 `isolation: isolate`**：那会让 `#app` 成为独立层叠上下文，截断页内 `z-index:10000` 的固定导航（本仓 `#app` 内确有 `.ui-sidebar` 用 10000），属回归。
- **探针方法论坑位（本轮最耗时的一条，务必复用）**：
  - **探针 URL 拼接坑（本轮让 Lead 与验证者双方都翻车的根因，最有沉淀价值的一条）**：`BASE` 字符串**禁止带尾斜杠**再拼路由。`'http://localhost:6188/' + '/character'` = `'//character'`，而 `//` 开头是**协议相对 URL（protocol-relative URL）**——`new URL('//character', 'http://localhost:6188')` 解析为 **host=`character`、pathname=`/`**（实测：`//character/1001` → host=`character`、pathname=`/1001`）。第一个路径段被当作 host 吞掉，浏览器实际请求的是另一个主机（失败或落到 SPA fallback 的 `/`），vue-router 于是在**未匹配路由**上渲染 NotFoundView，探针在 404 页上取证并输出「PASS」。**凡是多路由探针，必须在每个路由对开跑前断言「渲染的是预期组件」（如 `#nk-catalog-app` / `#nk-home-app`）+ 断言落地 path 等于目标 + 断言 `!document.querySelector('.nk-notfound')`**，否则会得到一整套漂亮的假证据。教训优先级：**加断言守卫比加采样密度更重要**——采样再密，采样对象错了就全是噪声。
  - **`transitionend` 不能靠 `#app` 上的事件委托捕获视图根节点的过渡结束**：Vue 在过渡结束时把离场节点从 DOM 移除，事件到不了委托监听器；且后代元素（卡片 hover 等）的 `transitionend` 会大量冒泡上来污染计数。可靠做法：① 在节点**自身**监听并用 `e.target === el` 过滤后代；② 用 rAF 逐帧记「首次失去 `-active` 类」的时刻作为过渡结束的可靠近似。
  - 用 `elementFromPoint(视口中心)` 做叠层判定时，必须同时确认命中的元素属于 leave 还是 enter 子树（`contains()`），只看 z-index 数值无法判定同 `auto` 时的绘制顺序。
- 验证（本轮实跑）：L1 静态全绿；L2 计算样式 **96/96 PASS**（桌面 enter delay=`0.06s`/dur=`0.22s,0.22s`、leave delay=`0s,0s`/dur=`0.26s,0.26s`、leave `z-index=1`、缓动 `cubic-bezier(0.16, 1, 0.3, 1)`；位移 fwd/back ±24px、fade ±8px）；L3 六组路由对（含 `/` ↔ `/character` 高危对）**零空窗**、`elementFromPoint` **LEAVING 命中率 100%**（进入段起步比离场段结束早 187–260ms）；降级通道 4 场景 × 2 高危路由对**全部 PASS**（手机/reduced-motion 下 leave 仍是 `absolute` + `z-index:1`，`transform: none`；媒体查询块刻意不重复声明 position/z-index，靠段内主规则继承，实测继承成立）；L4 `pnpm build` exit 0、`pnpm test` 22 文件/313 用例、`pnpm test:e2e:ci` 48 passed。

### 枢纽互切新增「模式置换过渡」通道（`nk-view-swap`）——命中正确的通道 ≠ 动画真的播放
- 交付：`App.vue` 新增 `isHubSwap`（`prevBareNav && route.meta.bareNav`，即「两页皆枢纽」）+ `transitionName` 插入第四分支 `nk-view-swap`；`tokens.css` 新增 `.nk-view-swap-enter-from/-leave-to`（±40px）、`-leave-active`（0.34s）、`-enter-active`（0.30s + `transition-delay: 80ms`），并并入既有 leave-active 的 `position:absolute; inset:0; z-index:1` 组与 reduced-motion 覆盖块。
- 起因：`/` 与 `/currency` 的 `meta.depth` 都为 0 → `beforeEach` 算出 `navDir = 0` → 落进位移仅 ±8px 的 `nk-view-fade`；而这次切换要翻转整个外壳主题（`data-theme="cw"` 黑金 ↔ 常规）+ 侧栏置换，是全站视觉变化最大的一跳，且由滚轮手势高频驱动（ADR 0016）。
- **判定必须用 `meta.bareNav`，禁止简化为「depth 相等」**：`/settings`、`/currency/settings`、NotFound、`/debug`（dev-only）也都是 depth 0。实测回归：`/settings`↔`/`、`/`→404、`/settings`→`/debug` **全部落 fade、零误命中**。
- **`from` 侧跨渲染周期追踪**：`transitionName` 在路由**已切换后**求值（`route.meta` 已是新页），故「上一页是否枢纽」必须自行记录。实现用 `watch(bareNav, (_v, old) => { prevBareNav.value = !!old; })`，初值 `prevBareNav = ref(bareNav.value)`（同一来源的同步 resolve，故首帧两者相等 → 不误判）。**禁止**把初值写成 `true`/`false` 常量：深链直达枢纽页时会凭空产生一次假置换。实测深链边界（`/`→`/character`、`/currency`→`/character`、`/currency`→`/settings`、`/currency`→`/currency/role`）**零假置换**。
- **本轮最有价值的坑位（严重，且它把上一轮的交叉过渡成果一并吃掉了）：`!important` 的 `transition` **shorthand** 会整体覆盖 `transition-property`，从而静默吃掉其他通道的动画。** `tokens.css` 的主题过渡规则 `.theme-transitioning, .theme-transitioning *, ... { transition: background-color 400ms …, color …, border-color …, box-shadow … !important; }`（HEAD 即有，非本轮引入）命中**视图根节点**后，把 `transition-property` 整体限死为仅那 4 个颜色属性——`opacity` / `transform` **根本不在其中**，于是视图的淡入淡出与位移**不做任何插值**，单帧跳到终值。实测：`/`→`/currency` 的 leave 节点 `t=600ms op=1.000 → t=605.9ms op=0.000 x=-40`（**一帧内塌掉**），enter 同理 `x=40 op=0 → x=0 op=1`；而对照 `/character`→`/character/1001`（不翻主题，`theme-transitioning` 帧数=0）`transition-property = "opacity, transform"`，**有中间帧插值**。唯一翻 `meta.cw` 的导航正是 `/` ↔ `/currency`，故**只有枢纽互切中招**。
  - **可复用判据**：`computed transition-property` **不含目标属性** + **无中间帧** = 被 `!important` shorthand 覆盖，而**不是**「时长没生效」。排查时序类问题**先看 `transition-property`，不要只看 duration/delay**。
  - **修法方向（Lead 已在真实文件上实测三候选，结论确定）**：做法是「临时改写该规则 → 用无拦截的干净探针逐帧取证 → 还原并校验字节一致」，绕开了 `addStyleTag` / `addInitScript` / `route.fulfill` 三种注入方式各自的不确定性。结果：
    | 候选写法 | 实测 `transition-property` | 中间帧 | 结论 |
    | --- | --- | --- | --- |
    | 现状（shorthand `!important`） | 四色，不含 opacity/transform | 0 | ❌ 硬切 |
    | A：拆成 `transition-property: bg/color/border/box-shadow !important` | 四色，**仍不含** | 0 | ❌ **不成立**——它仍把 property 限死为仅颜色，视图 opacity/transform 依旧被排除 |
    | B：**选择器收窄** `*:not([class*="nk-view-"])` | `opacity,transform` | **13** | ✅ 成立（首选：不动视图侧规则） |
    | C：视图侧补 `transition-property: opacity, transform !important` | `opacity,transform` | **14** | ✅ 成立（改动更小，但两份 `!important` 并存） |
    **故 B/C 均可，A 无效**；B 优先。

## 枢纽页工具化（ADR 0018）：一次被用户推翻的方案 + 两个只有取证才能发现的坑

## 页面底色重基（ADR 0021）：一次「看着像一行改动」的令牌迁移

**需求**：用户指出「页面底色恒为纯黑，不利于阅读」，要求先检索外部实践再给结论。检索结论（Material `#121212` / VS Code `#1E1E1E` / GitHub `#0D1117` / Apple HIG「soften white」）+ 纯黑伤阅读的三条机制（散光光晕、21:1 过对比、OLED 省电只在 OLED 且亮度是主因）→ 推荐 `--bg` 上移到 `--blk-850`。用户选定该方案并要求顺带修 `index.html`。

**决策前先做的实测（这步救了整件事）**：把候选底色喂给 `tools/check-contrast.mjs` 的副本（改路径指向临时 tokens 副本）算出真实比值，并写了个合成脚本复刻门禁的 `color-mix` + alpha 语义。两条结论：① 候选底色下对比度全绿（正文 17.03→15.18）；② **只改 `--bg` 会让 `--surface` 在 `#101012` 以上比页面更暗（层级反转）**——因为 `--surface` / `--card` 是半透明黑阶，明度来自与底的合成。于是方案从「一行改底色」升级为「底色 + 表面阶梯同批上移一档」，并顺带产出「承载位 / 压暗位」这条可机械执行的分类规则（承载位 850/800/750 提亮；压暗位 950/900 只做遮罩·暗角·scrim·洗色）。**教训：改底色类需求，先把候选值喂进现有门禁 + 亲手算一遍合成，再动手。**

**两个只有真跑才会暴露的坑（都记下）**：

1. **正则解析型门禁抓不到 CSS 语法错误**。我把黑阶说明扩成多行时，插入的 3 行注释落在原注释的 `*/` **之后**，成了无主文本。`check-colors --strict`、`check-contrast --strict`、`check-spine-manifest` **三个守卫全部 PASS**，直到 `pnpm build` 的 postcss 才报 `Unknown word 0022）：850`。**教训：给 CSS 加注释块必须确认插入点在 `*/` 之前；「守卫全绿」不等于「语法正确」，`pnpm build` 才是语法闸。** 修法：把前一段的 `*/` 改成句号，让注释连成一块。
2. **`src/styles/tokens.css` 被 git 判为二进制**（`git ls-files --eol` → `i/-text w/-text`），`src/app/App.vue` 同样，另有若干 `.ts` 为 `mixed`。根因是工作区文件含 **lone CR**（tokens.css 实测 CR 2741 / LF 1375，line ending 混着 `\r\r\n` 与 `\r\n\r`），git 见到 lone CR 即按 binary 处理。后果：**`git diff` 看不到行级 diff**，且 `Get-Content` 会把这类文件读成「隔行空行」（2742 行 vs 逻辑 1376 行），而 `read` / `grep` 工具展示的是折叠后的逻辑行号 —— 两套行号不一致，按工具行号去找磁盘行会错位。**本轮应对：改动前把 9 个目标文件备份到 `temp/`，改动后用「剥离 CR → 分行 → Compare-Object」自建规范化 diff 复核改动面（tokens.css 逻辑行 1335 → 1339，其余文件行数不变）；写盘统一用 `ReadAllText`/`WriteAllText` + `UTF8Encoding($false)` 做定点字面替换，绝不整文件重排，行尾字节数逐一对比确认未被重写。** 该污染是既存问题（非本轮引入），未在本轮顺手修（会变成不可评审的巨型 blob 变更）。

**执行方式**：38 条定点替换写成带**计数断言**的脚本（`temp/rebg.ps1`，期望 1/2/4 处不符即中止不落盘），一次通过；插入行用「捕获原行尾分隔符再插」的 MatchEvaluator，避免把 CRLF 文件写成 LF。

**门禁与验证（本轮实测）**：`check-colors --strict` exit 0；`check-contrast --strict` exit 0（常规 `--text` 15.18 / `--text-bright` 18.71 / `--primary` 4.11，CW 17.90）；`pnpm build` exit 0（含 `vue-tsc -b`）；`pnpm test` **298 passed**。合成复核：层级序「底色 < surface < card」两模式严格递增，且 ΔL 比改动前**更大**（常规 surface 3.96e-3→6.07e-3、card 5.42e-3→8.08e-3）。

**降级/未做（禁静默跳过）**：① **视觉表现未由 AI 判定**——像素基线 `e2e/snapshots/` 已由用户裁定后经 `pnpm test:e2e:update` 刷新（4 张全绿）；② `--nk-page-tint`（常规 5%→6% / CW 4%→5%）与 `--grain-opacity`（0.07→0.08，按「白噪点与底的绝对差收窄 ≈7%」的等感知还原值 ≈0.075 取 0.08）经用户裁定同批微调，两者都是「底色变亮后同强度不再同等可见」的连带项；③ `index.html` 的裸色值仍在 `check-colors.mjs` 扫描面之外（该脚本只扫 `src/`），本轮只做值对齐 + 就地注释，扩扫描面未做。

**后续最重要的一段：底色一动，「小字落在承载面上」的余量就没了（token 门禁看不到）**。`tools/check-contrast.mjs` 只算「文字 × `--bg`」；文字落在 `--surface` / `--card` / 着色 tag 上时对比度更低，这层只有 e2e 的 axe 扫描（4 页 × 缺省强调色）兜底。本轮实测：全量 `pnpm test:e2e:update` 直接红了——首页侧栏激活项英文小字（8px）由 5.27 掉到 **4.48**（差 0.02 破线）。随后我用自建探针把覆盖面扩到 12 个页面 × 10 套强调色，又查出 3 处新回归（`.nk-skill__tag` 4.09、`.nk-settings__kicker` 4.11、`.nk-seg__en` 4.20）与 3 处**存量**违规（`.nk-relic-effect__num` 3.18、`.nk-lc-rank-label` 3.58、`.nk-swatch__hex` 3.60）。

## 角色详情页「技能卡折叠开关」：裸文字 toggle 不构成可点性 + 三份等价 CSS 已发生文案漂移

**问题**：用户指出角色详情页「强化来源 / 技能预览 / 技能数据」三个按钮「看起来不像按钮」。

**根因两层，第二层才是真问题**：

1. 三处开关的 CSS 是**逐字复制的三份**等价声明（`.nk-skill__links-btn` / `.nk-skill__anim-toggle` / `.nk-skill__table-btn`），共同特征 `background: none; border: none; color: var(--text3); font-size: 0.625rem; padding: 4px 0` —— 无底、无框、10px 灰字，唯一状态反馈是 hover 变色，视觉上就是普通文字。
2. **复制粘贴已经造成漂移**：展开态文案三处不一致 —— `收起强化来源` / `收起数据` / 技能预览**文案不变**。等价声明一旦复制，行为就会各自演化；凡「某处样式/行为与同类不一致」，先查这几份是不是复制来的。

**修法**：三类开关收口为单点原语 `.nk-skill__toggle`（浅底 `color-mix(--blk-900 40%)` + 发丝描边 `--line-1` + 6px 圆角；展开态走主色描边 45% + 8% 淡底，与 `.nk-skill__anim-tab.active` 同语言；hover 只提亮描边与文字色，不 glow 不位移），文案统一为「收起 + 原名」。

**两个只有真改才暴露的坑**：

- **焦点环共享组里的 `border-radius: 4px` 会改按钮本体圆角**。`focus-visible` 组内的 `border-radius` 本意是给 outline 定形，对原先没有可见盒子的文字按钮无害；按钮一旦有了 6px 圆角盒子，聚焦瞬间会跳形到 4px。修法：该类单列复位自己的圆角，不进共享组。
- **`:hover` 改的属性必须在 `@media (hover: none)` 里同步复位，且展开态要单独重新声明**（`.nk-skill__toggle.open:hover`）。该媒体查询块在文件末尾，同特异性下会盖掉前面的 `.open` 基态 —— 触屏上展开中的按钮会掉色回灰。旧的文字按钮只改 `color`，所以只复位了颜色；本次新增 `border-color` 后必须一并复位。

**验证**：`pnpm build` exit 0（三守卫全绿 + `vue-tsc -b`）；`pnpm test` 304 passed；新增 e2e 断言把「可点外观」固化为可断言规格（`border-top-width: 1px` / `border-radius: 6px` / 背景非全透明 / `::after` 上下 `-8px` 撑 44px 热区 / 三处文案成对 / 展开态换色换描边），chromium + mobile-chromium 双 project 均过。视觉表现交用户 RunPreview 确认。

### 子技能进一步缩进 + 竖轨跨行不断（用户二次修正）
- **用户原话**：「进一步缩进子技能，让竖线可以从父技能下方延长」。上一轮已把行缩进恢复为 22/10（用户要求保留），本轮再推一档：桌面 **22→36px**、375 **10→16px**。
- **真正的缺陷（比缩进值本身更要紧）**：竖轨在**每张子卡边界断开 18px**。根因是子卡 `padding-top = --nk-skill-child-gap`（18px），而子卡 `::before` 竖轨 `top: 0` 只顶到 padding box 顶（= 卡体顶），不是卡顶——父卡竖轨下端（父卡体底 = 子卡卡顶）与子卡竖轨上端之间正好差一个 padding-top。实测真珠 1503：父轨 1344→1529.23、子1 轨 1547.23→1753.80、子2 轨 1771.80→1813.80，两处 18px 断点。
  - ⚠️ **该诊断已被下一轮实测推翻**：那两处「18px 断点」是取证 helper 坐标系错误造成的**假象**——用真实哑元元素实测，子卡 `top: 0` 的伪元素上端 = 卡顶 = 父卡体底，**接缝为 0**（1503 首子卡：父体底 302.23 = 卡顶 302.23）。`top: -child-gap` 属无效改动（与上一段竖轨同 x 重叠，肉眼无差别）。真正的缺陷在折角，见下。
- **连带缺陷（同一根因）**：折角 y 公式写成 `child-gap + rail/2`，而 CSS 注释自己写的是「y 在子图标中线（= 行顶 + child-gap + rail/2）」——注释里的「行顶」指**卡顶**，卡顶 + child-gap + rail/2 = 卡体顶 + rail/2 = 图标中线；代码的 `top` 却是相对**卡体顶（padding box）**的，于是实现出来比图标中线**低 18px**。实测子1 图标中线 1571.23 / 折角 1589.23，子2 中线 1795.80 / 折角 1813.80。
- **修法（`src/styles/character.css`，三处）**：① 子卡 `::before` 竖轨 `top: 0` → `top: calc(-1 * var(--nk-skill-child-gap))`，穿过 padding-top 顶到卡顶，与父轨/上一张子卡轨相接；② 子卡 `::after` 折角 `top` 去掉 `child-gap` 段 → `calc(var(--nk-skill-rail) / 2)`，落到图标中线；③ 末位子卡 `::before`（└）加 `top: calc(-1 * var(--nk-skill-child-gap))`，height 不变（`child-gap + rail/2`），竖轨自卡顶下延至图标中线收口。改后连续性：1344→1529.23→1753.80→1795.80，零断点；两折角均等于各自图标中线。
- **e2e 侧同步修的两个坑**：
  - ⚠️ **该条结论已被下一轮实测推翻（原文保留，用于识别回流）**：~~`pseudoBox()` 用 `hostRect.top + computedTop` 少算了宿主 `padding-top`（18px），已改为 `r.top + pt + top` / `r.left + pl + left`（`pt/pl` 取宿主 computedStyle）~~。真相：绝对定位伪元素的包含块是宿主 **padding box 的外缘**（border 为 0 时即卡片顶），页面坐标 = `hostRect.top + css top`，**不加 padding**；上一轮加 `padding-top` 反而把整套数值抬低一个间距，并直接导致折角公式被改错（折角落到子图标顶边）。**教训：「padding box」这个名词有「外缘 / 内容区」两种口语含义，禁止靠名词推导坐标——必须用真实哑元元素（与伪元素共享包含块）实测原点。**
  - 桌面专属用例（硬编码 indent=36 / 折角宽=46）在 `mobile-chromium` project 下会红（该 project 用 Pixel 7 视口、indent=16）。已给该用例加 `{ tag: '@viewport-pinned' }`（mobile project 用 `grepInvert` 跳过）。**教训：硬编码断点数值的用例必须钉死视口，否则会在另一个 project 里假失败。**

### 缩进单位定稿：一个技能图标空间（缩进被连续第三轮修正）
- **用户原话**：「我希望竖轨是从父技能的正下方延长，子技能缩进，应该缩进一个技能图标的空间」。
- **流程教训（同一模式第三次出现）**：前两轮我都在**数值层**应答——先提「保留 22px」、再提「推到 36px」，从未问过缩进的**单位 / 基准**是什么。用户的模型是「一个技能图标的空间」：缩进必须等于既有尺寸（图标边长）的整数倍，而不是凭观感调的像素值。→ **凡涉及间距 / 尺寸的追问，先把「单位 = 哪个既有令牌的整数倍」问定，再谈数值；只给数值的方案必然被同一个洞打回。** 这与 ADR 0019 轮的流程事实同源（见本文件「两枢纽页恢复导航条」一节）：用户两次否决都不是「数值不对」，而是「我提的形态本身没被验证」——**提方案时「该形态 / 单位是否该存在」与「数值调多少」必须并列给出。**
- **定稿规则**（Q14–Q16、Q18 采纳推荐项；**Q14 的落点随后被 Q19 推翻重定**）：竖轨 = 父图标**底边水平中点正下方**（x = 行体左缘 + `--nk-skill-gutter` + `--nk-skill-rail` / 2）；父轨自父图标底边下垂（取消 10px 短横与圆角）；子技能行缩进 = 一个**技能图标空间** = `--nk-skill-rail`（= 图标边长），删除移动端独立值；折角横段 = **半个**图标空间（故子图标左缘 = 父图标右缘）；兄弟纵向间距（Q18）= 半个图标空间，取代 18px 全断点常量；图标列左侧留白（Q17）由 20 / 16px 压到 10 / 8px（否决了我的「保留」推荐，方向仍是「更彻底」——与 ADR 0019 轮同款）。实测依据：原竖轨 x=356，父图标左缘 366 / 中点 390；子图标左缘 402、父图标右缘 414（重叠 12px）——「36px」从来不是图标边长的整数倍。决策全文与落地清单见 [ADR 0022](../adr/0022-技能层级以行迹族为唯一来源.md) 文末「几何修订」。

### AI 检索可见性：构建期预渲染快照（服务端 HTML 才是瓶颈）

- **机制结论（检索证据见 [ai-crawler-facts.md](ai-crawler-facts.md)）**：决定 AI 可见性的是**服务端 HTML 里有没有正文**，不是 robots / schema / llms.txt。实测：Vercel × MERJ 对 OpenAI 爬虫 5 亿请求**零 JS 执行**；Googlebot 与 GPTBot 的可见词数差为 0。改造前本站所有 URL（含详情页）返回同一份 **962 B 空壳**（正文 0 字、内链 0 条）——对 ChatGPT / Perplexity / Claude 等于不存在；`/robots.txt`、`/sitemap.xml`、`/llms.txt` 也不存在，被 `vercel.json` 的 catch-all 兜成 `index.html`（200 + `text/html`）。llms.txt 被 Ahrefs 13.7 万域日志证明 **97% 零请求**、Google 官方明文忽略；schema 被 Ahrefs 1,885 页 DiD 证明**不提升 AI 引用**（做它是为富结果与实体消歧）。→ 预算应投在预渲染与**独家数据**上，不是标记文件。
- **落地方案**：`pnpm build` 末步由 `tools/gen-ai-endpoints.mjs` 生成 1199 个 `dist/prerender/**.html` + `dist/sitemap.xml`，`vercel.json` 在 catch-all 之前用**明确 rewrite** 投递（并排除 `robots.txt`/`sitemap.xml`）；JS 用户拿到同一份 HTML（内联脚本加 `html.js` + `html.js #app > .nk-snapshot{display:none}`），Vue 挂载覆盖快照 → 内容对所有 UA 一致，不构成 cloaking。契约与断言见 [ai-discoverability.md](../agents/ai-discoverability.md)。
- **教训 1（口径对齐，被纠正一次）**：快照/sitemap 的条目集合必须 = **应用真正展示的条目集合**。首版给 `maze_boss` 3022（`zh` 空串的未发布占位行）兜底命名「玩法名+编号」——既违反「文本数据来源」硬约束，又把它写进 sitemap。修法：生成器与守卫**两侧各自**从 `pages/*.ts` 抽判据（`endgame.ts:190` 的 `!zh`、`item.ts:88` 的 `!name`、`currency-portal.ts:30` 的 `in_book`）→ 快照 1200 → 1199、`/item` 2606 → 2412、`/currency/buff` 84 → 83。**反例：为「应用刻意隐藏的条目」兜底造文本 = 双重违规。**（唯一例外：开拓者性别变体 98 全量保留——`localStorage` 用户设置不是构建期事实。）
- **教训 2（覆盖率断言的盲区）**：只断言「每族生成文件数」查不出**生成器静默漏条目**（map 中途异常 / 上限误用）——`/item`（2412 条）与 `/achievement`（1950 条）只有目录页这一层内容面，漏了没有任何断言会发现。修法：契约 §3 冻结稳定标记 `<li class="nk-snapshot__entry">`，守卫按标记逐目录计数断言相等（今日 12 目录合计 6129 + 枢纽 11），并断言详情页该类名 = 0（防污染导航性列表）。
- **教训 3（守卫与生成器的口径分歧要靠契约裁决）**：枢纽页分区是否算「收录条目清单」上一度相反（守卫 FAIL `home 0 < 1`）。裁决 = 枢纽分区属内容面、须带标记并断言 ≥1——判据失效会让枢纽页静默空态，正是要拦的回归。
- **教训 4（独立验证抓到生成器合成的实体事实）**：verifier 全量扫 1199 快照，命中 **10 页合成兜底句**——9 个角色（1224 三月七 + 8003…8010 开拓者各形态，源 `desc=""` 且 `chara_info.stories` 全 null，**前端 `CharHero.vue:33` 渲染空描述**）拿到「X 是《崩坏：星穹铁道》的可玩角色。」，`monster/5013090` 拿到「…的敌对物种。」与前端占位句「暂无图鉴介绍。」。修法：摘要段**仅源文本存在时输出**（否则整段省略）、空数据 section 整段省略、`<meta name="description">` 改由数据字段拼装（如 `三月七 · ★★★★ · 虚数 · 巡猎`、`破晓战队 · 精英`）→ **生成器不得为无数据实体合成通用句**（契约 §3）。
- **教训 5（同轮自查出的两个真缺陷，值得留档）**：① **影子回归**——把 `summaryPlain` 改名 `sourceSummary` 时漏改 `summary:` 行，导致**全部 98 个角色详情页**渲染成目录页摘要「星铁档案馆角色图鉴：共 98 名角色…」（改名必须全量搜旧名，别只改声明处）；② **`fillParams` 丢百分号**——`#N[i]%` 的 `%` 被正则消费后未补回，全站描述失真（`治疗量提高10。` → `10%。`、`攻击力140` → `140%`），前端 `fmtDesc` 是保留的。→ **快照文本保真度必须与前端渲染口径逐字段对齐，名字/参数展开是两类最容易静默失真的地方。**
- **教训 6（占位符保真：verifier 第二次点名，生成器 + 守卫双侧收口）**：目录层曾把未展开的 `#1[i]%` 直接发布出去（光锥 548 处 / CW 投资策略 285 处 / 羁绊 6 处）——既是噪声，又与前端不一致（前端卡片不渲染该字段，或经 `fmtDesc` 渲染成 `?` 残句）。修法：生成器新增 `txtSafe()` 按 `fmtDesc`/`fmtVal` 口径展开（含 `%`），**展开不全就整段省略该字段**（条目集合与 sitemap 不变）；守卫在同一扫描面新增 `#\d+\[[^\]]*\]` 零容忍断言，并明确**放行**上游字面 `#NN`（俱乐部编号）与 `{TEXTJOIN#61}`（转换器未解析的合并标记，与应用显示一致，属上游域）。→ **「文本必须来自数据」还有半条：发布出去的文本必须已完整展开为可读文本；参数缺失时宁缺勿噪声。** 后续 verifier 又抓到**裸** `#N` 残余（CW 投资策略 167/334 条 desc，应用渲染 `?`）：判据定为「**裸 `#N` 的语义取决于该字段所属条目是否携带 `params` 语义**」——携带（数组存在即便为空）即占位符、展不开整段省略；不携带（角色 desc/stories、成就 desc、物品名、敌对 intro）即上游字面、必须保留。守卫侧因裸形态**无法全局区分**字面与占位符，改为**按页点名**（`currency/item.html`、`currency/augment.html`）；已知边界：其它 params 语义族未被点名（生成器侧已通用判定，换页泄漏需人工扩表）。检查 3 最终为 **11 项断言**。
- **教训 7（线上实测才暴露的投递模型：Vercel 文件系统先于 rewrites）**：推送生产后用 GPTBot UA 实测，**1198 个路由全部正确，唯独 `/` 仍是 962 B 空壳**——`{"source":"/"}` 那条 rewrite **永不生效**，因为 `/` 命中 `dist/index.html`（旁证：`/prerender/x.html` 直连也由文件直接服务；`/character/99999` 因文件系统无对应文件才落到 rewrite）。修法：home 快照**同时写 `dist/index.html`**（与 `prerender/home.html` 同一字符串 → sha256 相同），纯 SPA 外壳移到 **`dist/prerender/_shell.html`**（下划线前缀 = 非快照，守卫跳过、不计入覆盖率/条目数），catch-all 目标改为它并加进负向先行断言。附带确认：**rewrite 目标缺文件时回落 catch-all**（返回外壳而非 404）→ 未发布实体 URL 的行为与改造前一致，无回归。→ **产物布局必须服从托管平台的真实求值顺序，不能靠直觉；「构建产物都对」不等于「线上投递正确」——必须用真实 UA 在生产环境验收。** 守卫检查组数 6 → 7（新增「外壳与首页」）。

### 技能图标右侧零间距：`--nk-skill-gutter` 只承担左侧（用户截图报障）

- **用户原话**：「技能图标和右侧技能名等内容挤在一起，请修复」（附 410×126 截图）。
- **根因（实测，非观感）**：`.nk-skill__body` 的两列网格是 `calc(rail + gutter) | 1fr`，而 `.nk-skill__rail { justify-content: flex-end }` 让图标**右对齐**在图标列内 ⇒ 图标右缘 ≡ 图标列右缘 ≡ 内容列左缘。`--nk-skill-gutter`（10/8）是**图标左侧**给竖轨的留白，右侧从来没有间距 → 三断点实测 `标题行左缘 − 图标右缘 = 0px`（1440 / 900 / 375 全为 0）。**教训：一个变量同时被当作「左留白」和「列间间距」用时，必然有一侧漏掉；列间间距必须由 `column-gap` 表达。**
- **修法**：`.nk-char-page .nk-skill__body:has(> .nk-skill__rail) { column-gap: 16px }`（16 = 8px 栅格主档）；并把 `--nk-skill-gutter` 只承担左侧写成 CSS 内硬约束。图标左缘 / 缩进 / 竖轨 x / 折角全部由图标列自身决定 ⇒ **不受 column-gap 影响**（点：图标在列内右对齐，加 gap 只把图标列右缘与内容列左缘拉开）。
- **顺带修的第二处挤**：`skill-card.css` 的 `.nk-skill__title { gap: 4px }`（技能名 → 普攻/单攻 标签行）→ **8px**。这是**共享原语**（光锥详情页同用），有意在单点改而不是页内覆盖——两页同语言同值；光锥页视觉同步变松，属本轮唯一跨页视觉改动。
- **横向代价（已实测，接受）**：内容列 −16px → 桌面父卡 838→822、375 子卡 199→183（12px 字号约 15 汉字/行）；`scrollWidth == innerWidth` 三断点无横向溢出。

## 角色详情 hero 修复：铭牌压图可读性 + 骨架屏断点结构失配（Lead 单线）

- **用户判据**：先答「hero 区域有什么奇怪的样式」；方案上**否掉了「给铭牌加暗角」**，改成**「给文字加个阴影」**——即保「去框化悬浮铭牌」语言、不加底板。
- **缺陷 1（就绪态，用户可见）**：`character.css` ≥1024 把铭牌绝对定位到 hero 左下（`left/bottom: 24px`、`width: min(520px,58%)`）且 `background: none`，而渲染内容（立绘 / Spine 动画帧）会伸进铭牌区 → 亮部文字糊掉。景元 1204 实测「智识」与命途图标压在白云上，命中像素 (255,255,253) 时 **2.56:1**（AA 需 4.5:1），且图标是 `<img>` 不吃 text-shadow。三月七 1001 因 Spine 未加载（静态立绘该处透明）看不出问题 → **受影响集 = 渲染内容左下为亮部的角色**。

- **本轮三次实测回归（根因同族：断点内覆盖既有规则时，简写 / 特异性 / DOM 位置三处各自会失效）**：
  ① 子卡上沿虚线最初写成 `.nk-char-page .nk-skill--child`（0,3,0）+ `border: none` 简写排在 `border-top` 之前 → 375px 实测 `border-top: 0px none rgb(226,232,240)`（被全断点基础规则 `:has(> .nk-skill--child) > .nk-skill--child`（0,4,1）与 `.nk-skill`（0,1,0）的 `border` 简写压掉）；修法 = 特异性不低于基础规则 + 只写上沿长写（`border-top-*` 三条）。
  ② 折角线的 `content: none` 同样被基础规则压掉 → `::before` 的 computed `content` 仍是 `""`（即真的画着一条竖轨）；修法 = 该组补上 `:has()` 形态的宿主选择器。
  ③ **`display: contents` 不能把图标抬进标题行**（本轮最贵的一处）：`.nk-skill__rail` 与 `.nk-skill__title-row` 是**兄弟节点**，拆箱后图标的布局父级是 `.nk-skill__body`（单列 grid），成了 body 第一个 grid item ⇒ 375 实测图标底边 = 标题行顶边（竖向重叠 **0.0px**，即图标堆在标题行**上方 44.0px**）、`closest('.nk-skill__title-row') === null`、每卡高 **+44.0px**；`order: -1` 只重排 grid 自动放置、无可观测效果。修法 = **换宿主**：`SkillCard.vue` 用 `(max-width: 767px)` 媒体查询决定图标渲染进标题行还是图标列（桌面 DOM 不变），`.nk-skill__body` 在手机断点 `display: block`。
- **教训（可执行）**：① **「对齐」类断言必须同时含横纵两轴**——我写的 `order === '-1'` 与「图标左缘 == 标题行左缘」在图标**堆叠在标题行上方**时**同样成立**（两者左缘都等于卡内容左缘），属假通过；独立验证补上「图标 top == 标题行 top」后才暴露。**只比一个轴的几何断言，等于没断言。** ② **换布局前先问「这两个节点是不是兄弟」**：`display: contents` 只去盒、不搬节点，跨兄弟宿主的内联必然要动 DOM（Vue 侧按断点切宿主）。 ③ 在断点块里覆盖既有规则时，必须逐条核对「简写 / 特异性 / 源序」三者，只靠源序在 `:has()` 这类高权重选择器面前不成立。
- **取证陷阱（本轮实测，勿再踩）**：Chrome 对**未被 `content` 生成**的伪元素，`getComputedStyle(el, '::before').width / height` 返回**声明侧**数值（曾据此误判「竖轨还在」）；只有计算 `content` 能判生成与否（`content: none` = 不生成、`content: ""` = 生成），且判定要用**像素 diff** 兜底（verifier 的 `content:none` 强注前后同元素截图逐像素比对：0 像素 vs 阳性对照 139 像素）。
- **降级/未做**：① 像素基线**未跑且不需跑**——`e2e/visual.spec.ts` 的 4 张基线（首页 / 角色图鉴 / 终局 / 货币战争 Hub）不含角色详情页；② `accessibility.spec.ts` **未跑**——其扫描面（`/`、`/character`、`/endgame`、`/currency`）不含角色详情页，且本轮零颜色令牌改动（新增虚线复用既有 `--line-2`）；③ 未跑 `mobile-chromium` project——新增手机用例自行 `setViewportSize(375)` 且已带 `@viewport-pinned`（按 `playwright.config.ts` 该标签从 mobile project 排除，避免同断言重复执行）；④ 只跑 Chromium 单引擎，跨引擎（Firefox / WebKit）未实测；⑤ 图标宿主切换的 `resize` 路径未单独取证（只在 `375 ↔ 1440` 之间切换页面加载态验证）；⑥ **视觉观感（虚线的粗细 / 缩进力度 / 图标内联后的疏密）交用户 RunPreview 确认**——AI 侧只交规格与计算样式证据。
- **教训**：① **「更彻底」方向的报障（用户第 4 次同款：留白归零轮、枢纽页两轮、缩进三轮）说明：当既有形态在小视口上只剩「无承载物的结构」时，正确解是让结构在该断点退场，而不是继续调它的数值**；② **断点作用域必须写进术语本身**——`CONTEXT.md` 原「技能层级线」只写「禁止与旧语言并用」（无断点边界），导致手机断点恢复虚线时会与术语表**直接冲突**；术语条目缺断点边界 = 后续改动必然踩。

### 图标回退链与真缺失占位：先锁回退、再上占位（用户报「图标真的缺失则显示占位图标」）

- **用户原话**：「调用agent team ，进行下一轮任务，如何图标真的缺失，则显示一个占位图标。」（`如何` = 「如果」；即「真缺失 → 显示占位图形」）
- **根因（分三层，都是结构问题而非资产问题）**：
  1. **回退链断在模板绑定层**（最要紧的一层）：`iconUrl()` / `skillIconUrl()` 只返回主源 URL，模板只绑 `:src` ⇒ 全局委托读不到回退源、`data-cdn-fallback` 形同虚设，主源一 404 就直接判死。实例：镜流 1212 强化技能图标的 `1{charId}` 伪目录名在 nanoka 不存在。
  2. **终态无语义**：「资产真缺失」与「CDN 不可用」共用 `data-cdn-down` → CSS `visibility: hidden` → 卡片渐变底承接，用户看到的是空白，既读不出「此处无图」也读不出「环境故障」。
  3. **离线不可判定（决定了修复位置）**：上游同一角色的同一图标自己就混用两套命名——1310 是 `SkillIcon_11310_*` 存在 / `SkillIcon_1310_*` 404，1212 恰好相反。converter 没有 nanoka 的文件清单，任何「数据归一」都只能修一半（且会把 1310 的 3 行从 nanoka 200 变成 404、多一跳回退）。而 jsDelivr 侧新旧命名全 200（三例共 5 行实测）⇒ **承重修复是前端的双源回退链**，数据归一只是减少回退跳数。
- **定稿规则**（决策全文见 [ADR 0024](../adr/0024-图标回退链与真缺失占位.md)）：
  1. 图标位走 `icons.ts::iconImgAttrs(url)` 的 `{ src, 'data-cdn-fallback' }` 双绑定（技能卡「技能图标 + 强化来源图标」/ 概览面板 / 对比面板三处），**禁止**再绑 `hideOnError`（会抢在回退前隐藏）。
  2. 首选源与回退源**都**失败后，全局委托换共享常量 `MISSING_ICON_SRC`（`cdn/placeholder.ts`：内联 SVG **描边问号**、中性灰），打 `data-cdn-placeholder`，原 URL 存 `dataset.cdnSrc`。**图形经一次用户裁定**：v1 是「方框 + 斜杠」，用户看后判「不好看」改为描边问号（原话「这个占位图标不好看，你用svg画个问号好了」）；同时明确**禁止 `<text>` 字形**（字体可用性随宿主变化，字形会偏移或缺失）。
  3. 占位是 opt-in 终态：`isCdnDown()` 短路（环境故障）**不上**占位；`data-cdn-noph` 是为将来「有意空图位」预留的入口（`dom.ts` 有分支、单测覆盖，**当前无生产写入方**）。自带语义兜底的图标面（物品卡立方体 / 遗器部位图 / 终局 buff 星形 / gridFight 属性图标）**无需打标**——委托在捕获阶段先跑、组件的元素级 `@error` 后跑且最后写 `src` ⇒ **组件胜**（已逐面核过，记为分工而非待办）。
  4. CSS 收窄为 `img[data-cdn-down]:not([data-cdn-placeholder]) { visibility: hidden }`（占位必须可见）。
  5. 降级态只有一个出口 `clearDegrade`（清 `data-cdn-down` / `data-cdn-placeholder` / `dataset.cdnSrc`），供真源自愈 `load` / `reloadDownedImages` / 组件接管后的 `load` / 换源观察者共用；占位路线的清降级判据是**「占位是否已实际加载」（`placeholderLoaded` 状态）而非 src 值**——占位自身那次 `load` 只置位，之后**任何**真源 `load`（含**同源重试成功**）一律清降级（清理前用 `!isPlaceholderSrc(img.currentSrc)` 排除仍是占位；`isPlaceholderSrc()` **只认 `data:image/svg+xml,` 前缀**，因属性回读可能被环境规范化）。**配套 `watchDegradedSrcSwap(img)`**（`MutationObserver` 观察 `src`）：已降级元素被组件换源后若新 `src` 既非记录的原失败源也非占位 ⇒ **先清降级**，让新源自己的 `error` 重走完整回退链；否则 `markDown` 首行的 `if (img.dataset.cdnDown) return` 早退、残留的 `data-cdn-placeholder` 又让 `img[data-cdn-down]:not([data-cdn-placeholder])` 不命中 ⇒ **可见破图**（实测 `naturalWidth=0` / `visibility:visible` / `src` 为失败 URL，同场景新建元素正常显示占位）。

- **教训**：① **占位不得盖住可恢复资产**——「真缺失」的判据是**回退链走完**（两源皆失败），不是「主源失败」；若先上占位再补回退，本来能加载的图（1212 在 jsDelivr 新旧命名皆 200）会被永久顶替成占位。**顺序必须是先绑回退、后上占位。** ② **必须先用用例锁住回退、再生效占位**：占位是改写 DOM 的终态副作用，一旦抢在回退前生效就不可逆，而「模板没绑 `data-cdn-fallback`」这一断点在视觉上与「资产真缺失」完全同形（都是占位）——故 e2e 的两条（回退必须加载成功且**不得出现占位** / 两源皆 404 时才占位且 `naturalWidth>0`）是占位的**前置门禁**，不是配套测试。 ③ 委托与组件自带兜底的**次序**（document 捕获先于元素 target、组件最后写 `src` ⇒ 组件胜）是浏览器事件模型决定的，且**优先级不可见**：任何在组件 `@error` 里提前 `return` 而不改 `src` 的写法都会让全局占位翻盘——这类「谁最后写 DOM」的分工不能靠代码自证，只能靠测试锁住，写在 ADR 里而不是留在实现里。
