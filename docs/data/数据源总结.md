# TurnBasedGameData 数据源总结

> 分析对象：`vendor/TurnBasedGameData/`（开源项目 StarRailData 的《崩坏：星穹铁道》官方发行数据解包，无二进制资源本体）
> **本文只记「有哪些数据、怎么用、坑在哪」**：ExcelOutput 的文件清单与逐表字段以 `tools/converter/DATA_CATALOG.md` 总索引及其 `DATA_CATALOG.parts/` 分片为唯一事实源（由 `gen_catalog.py` 从 vendor 生成），本文不复述。
> 数据探索一律走 `tools/converter/query.py`（`--schema` 字段全集与出现率 / `--search` TextMap 全文 / `--resolve` hash 还原），**禁止直接读取 vendor**。
> 文件数为快照统计口径，随版本增长；权威值见 `DATA_CATALOG.md` 头部。

## 一、顶层结构（五层）

| 目录 | 快照文件数 | 定位 | wiki 可用性 |
| --- | --- | --- | --- |
| `ExcelOutput/` | 2,185（权威值见 `DATA_CATALOG.md` 头部） | 策划配表：扁平记录数组 / 以 ID 为键的对象，字段为英文驼峰 | **主干数据源**（角色、光锥、遗器、物品、敌人、关卡、任务、成就、货币战争） |
| `TextMap/` | 29 | 多语言文本库，键为 xxhash 数字 ID | **主干数据源**（所有可见文案的唯一来源） |
| `Config/` | 113,707 | 引擎运行时配置与关卡数据（体量最大，占总量约 92%） | 底层还原：技能行为图、AI、动画事件 |
| `Story/` | 5,358 | 剧情表现脚本（Sequence 任务列表） | 台词需配 `TextMap` 才能还原 |
| `Stages/` | 2,826 | 战斗 / 副本场景物件布局（按章节组织） | 关卡地图可视化 |

> `Config/` 与 `ExcelOutput/` 的关系：`ExcelOutput` 是策划在 Excel 维护的配表，`Config` 是引擎消费的底层配置；两者通过 ID 与 `JsonPath` 关联（见 `docs/data/角色数据探索.md`）。

## 二、ExcelOutput（wiki 主干数据源）

### 2.1 通用特征

- **扁平记录数组**：多数文件为 `[ {字段…}, … ]`，少数为以 ID 为键的对象。
- **文本用 hash 引用**：可见文字存为 `{ "Hash": <xxhash> }`，须到 `TextMap/<语言>.json` 反查。
- **图片走资源路径**：图标/立绘为相对路径（如 `SpriteOutput/ItemIcon/900001.png`），资源本体不在 vendor。
- **变体后缀**：`*LD`（低配/精简派生表）、`*Trial`（试用）、`*Test`（测试）、`_BE_`（Beta）。
- **大文件**：`StageConfig`、`SpecialAvatarRelicMainValue`、`TalkSentenceConfig` 等单文件数十 MB，须按需流式读取，禁止整体载入。
- **字段与条数**：单表字段全集、条数、首条记录摘要优先 `python query.py <文件名> --schema`；需要浏览整簇表时，在 `DATA_CATALOG.md` 总索引按首字母开对应分片（**禁止整读全量索引**，约 30 万 token）；可选字段（出现率 <100%）须用 `query.py --schema` 确认。

### 2.2 分域索引（按功能域，非文件大小序）

- **角色养成**（`Avatar*`，角色 wiki 页主干）：主表 `AvatarConfig`(+LD/Trial/Enhanced)；突破 `AvatarPromotionConfig`；星魂 `AvatarRankConfig`；行迹 `AvatarSkillTreeConfig`；技能 `AvatarSkillConfig` / `AvatarUltraSkillConfig` / `AvatarServantSkillConfig`（忆灵）；属性与命途 `AvatarPropertyConfig` / `AvatarBaseType` / `AvatarCamp`；推荐 `AvatarRelicRecommend` / `AvatarEquipRecommend`；外观语音 `AvatarSkin` / `AvatarVO` / `AvatarPlayerIcon`。逐表字段与取数链路见 `docs/data/角色数据探索.md`。
- **光锥**：`EquipmentConfig`（主表）、`EquipmentPromotionConfig`、`EquipmentSkillConfig`。
- **遗器**：`RelicConfig`、`RelicSetConfig`、`RelicSetSkillConfig`、`RelicMainAffix*` / `RelicSubAffix*`。
- **物品 / 经济**：`ItemConfig`（含虚拟货币/材料/道具）及 `ItemConfig*` 派生表、`ItemCompose*`、`RewardData`、`Stamina*`。
- **敌人**：`MonsterConfig`、`MonsterSkillConfig`、`MonsterDrop`、`MonsterTemplateConfig`、`EliteGroup`。
- **关卡 / 战斗 / 副本**：`StageConfig`、`Maze*`（大世界/解谜）、`Challenge*`、`Raid*`、`BattleConditionConfig`、`BattleEventConfig`；纪行 `BattlePass*`。
- **任务 / 成就 / 剧情**：`MainMission` / `SubMission` / `QuestData` / `DailyMissionData`、`AchievementData` / `AchievementSeries`；剧情资产 `StoryLine` / `Performance*` / `TalkSentenceConfig`（文本在 TextMap）。
- **模拟宇宙 / 肉鸽**：`Rogue*` 各分支前缀（`RogueNous*` / `RogueDLC*` / `RogueMagic*` / `RogueTourn*` / `RoguePersona*` 等）+ `AetherDivide*`。
- **活动 / 限时玩法**：`Activity*` 框架表 + 每个活动独立前缀簇（`Alley*` / `Museum*` / `Chimera*` / `GridFight*` / `PlanetFes*` / `Tarot*` / `Fate*` 等）；**文件数占比最大，按需接入**，具体文件名用 `python query.py --list <关键词>` 列出。
- **社交 / 通讯**：`Message*`、`ChatBubbleConfig`、`Emoji*`、`Dialogue*`、`TextJoin*`。
- **地图 / 导航**：`MapEntrance*`、`AreaMap*`、`NavMap*`、`SubMap*`、`World*`、`TeleportConfig`、`MappingInfo`。
- **商店 / 卡池 / 充值**：`Shop*`、`Gacha*`、`Recharge*`。
- **图鉴 / 系统 / 演出**：`*Atlas*`、`Tutorial*`、`Func*`/`Function*`、`Setting*`、`Loading*`、`Performance*` / `CutSceneConfig` / `VideoConfig`。
- **常量 / 杂项**：`ConstValue*`、`Resource*`、`RetCodeError`；版本演进新体系 `Servant*` / `SpecialAvatar*`。

### 2.3 取数优先级

| 优先级 | 表（前缀） | 用途 |
| --- | --- | --- |
| 最高 | `AvatarConfig` / `AvatarPromotionConfig` / `AvatarRankConfig` / `AvatarSkillTreeConfig` / `AvatarSkillConfig` | 角色页：属性、突破、星魂、行迹、技能 |
| 最高 | `Equipment*` / `RelicConfig` / `RelicSetConfig` / `RelicSubAffixConfig` / `ItemConfig` | 光锥 / 遗器 / 物品页 |
| 高 | `MonsterConfig` / `MonsterDrop` / `MonsterSkillConfig` / `StageConfig` / `MazePlane` | 敌人页、关卡地图（注意 24MB 级大文件） |
| 高 | `MainMission` / `SubMission` / `AchievementData` | 任务 / 成就页 |
| 中 | `Rogue*` / `AetherDivide*` / `Shop*` / `Gacha*` | 专题页 |
| 按需 | `Activity*` 及各活动集群 / `TextJoin*` / `Dialogue*` / `Performance*` | 版本活动、剧情台词还原 |

**通用取数流程**：`query.py --list <关键词>` 定位表名 → 按需读 `DATA_CATALOG.parts/` 对应分片或 `query.py --schema` 取字段 → `query.py` 取记录 → 用 `JsonPath`/ID 关联 `Config/` 底层配置 → 用 `Hash` 关联 `TextMap/<语言>` 还原文案 → 用 `SpriteOutput/...` 路径对接资源库/CDN。

## 三、Config/（引擎底层配置）

### 3.1 根目录零散配置表

根目录的 `Config*.json` 为按配置类逐个导出的系统配置（`ConfigAvatar`、`ConfigLightCone`、`ConfigItem`、`ConfigMonster`、`ConfigSkill`、`ConfigStage`、`ConfigRogue`…）。部分已拆分为同名子目录（如 `ConfigAvatar` → `Config/ConfigAvatar/`），根目录仅保留尚未归类或仍为单表的配置项。

### 3.2 主要子目录（快照文件量降序）

| 子目录 | 内容说明 |
| --- | --- |
| `Level/` | 单个关卡的配置与场景数据（按关卡 ID 组织），体量最大 |
| `LevelOutput/` | 关卡数据的导出/编译产物，结构与 `Level/` 对应 |
| `ConfigEntity/` | 实体（Entity）定义：怪物 / NPC / 可交互物件在战斗与大世界中的参数 |
| `ConfigAbility/` | 能力/技能逻辑定义（行为图）：技能、普攻、天赋、秘技的施法流程 |
| `ConfigNPC/` / `ConfigProp/` | NPC 外观与对话绑定 / 场景道具定义 |
| `Activity/` | 活动相关配置表 |
| `LevelMapping/` | 关卡 ID → 地图 / 区域 / 资源路径的映射 |
| `ConfigAI/` | 怪物 / 单位的 AI 行为树与决策配置 |
| `ConfigAvatar/` | 角色与 NPC 的模型、动画、技能绑定配置 |
| `ConfigAnimEvents/` | 动画事件（按动画帧绑定音效 / 特效 / 表现） |
| `ConfigSkill/` / `ConfigCharacter/` | 技能配置表 / 角色基础属性与成长配置 |
| `ConfigSummon/` / `BattleLineupPage/` / `AssetPreload/` | 召唤物 / 战斗编队预设 / 资源预加载清单 |

> 另有历史或预留**空目录**（如 `BattleMode`、`CameraTemplate`、`ConfigBattleAction`、`ConfigInteract`、`ConfigObstacle`、`ConfigShop`、`ConfigTutorial`、`HeroData` 等）：当前快照未导出内容，遍历时须容错。

### 3.3 与 ExcelOutput 的分工

角色 / 技能 / 敌人 / 动画的**底层逻辑与表现**必须读 `Config/ConfigAbility`、`Config/ConfigAI`、`Config/ConfigAnimEvents`、`Config/ConfigCharacter`；数值与文案取 `ExcelOutput`。两层的关联键与调用链见 `docs/data/角色数据探索.md`。

## 四、Stages/（关卡场景布局）

按章节组织的战斗 / 副本**场景物件布局**（几何与摆放，非玩法逻辑）：

- `Stages/Outputs/<ChapterXX>/`：每章节一个目录，含 `ChapterPolymer.json` 等。
- `Polymer` 字段记录每个场景物件的 `Name` / `LayerName` / `AssetPath` / `Active` / `PosX/Y/Z` / `ScaleX/Y/Z` / 包围盒 `Bound`。
- 用途：关卡地图与美术布局还原；字段偏引擎底层。配合 `Config/Level*` 使用。

---

## 五、Story/（剧情表现脚本）

以 Sequence 任务列表描述过场、对话与镜头：

| 子目录 | 内容 |
| --- | --- |
| `Story/Mission/` | 主线 / 任务过场脚本，按任务 ID 建子目录；结构为 `OnInitSequece` / `OnStartSequece` → `TaskList`（`LevelPerformanceInitialize` / `PlayTimeline` / `EndPerformance` 等） |
| `Story/Discussion/` | 对话讨论脚本：角色站位与镜头 |
| `Story/BattlePerformance/` | 战斗演出脚本（Boss 战演出、特殊镜头） |

> 剧本内**不含实际台词**，文字一律引用 `TextMap` 的 hash，须结合 `TextMap/` 还原。

## 六、TextMap/（多语言文本）

- 以 **xxhash 数字 ID** 为键、本地化字符串为值；`README.md`（仓库根）说明了 xxhash 算法并提供 JS / Python 实现链接。
- 每种语言一个全量表（`TextMapCHS/CHT/DE/EN/ES/FR/ID/JP/KR/PT/RU/TH/VI.json`），另有 `TextMapMain*` 主线子集（体积更小）。
- **注意分片**：`TextMapKR` / `TextMapRU` / `TextMapTH` 已按体积拆成 `_0` / `_1` 两个文件，读取时不能假设「一种语言一个文件」；当前文件清单见 `DATA_CATALOG.md` 的 TextMap 节。
- 中文全量表约 46 万条（快照口径）；正文中的 `{NICKNAME}` / `<color>` / `#n[i]%` 等标签与占位符处理见 `docs/data/hsr-rich-text-tags.md`。

---

## 七、通用格式约定与坑

1. **`$type` 类型标记**：剧情 / 能力类文件用 `$type`（如 `"RPG.GameCore.TriggerAbility"`）标记 Unity `GameCore` 命名空间下的逻辑图（Gameplay Ability / Sequence）。
2. **文本永远是 hash**：任何 `{ "Hash": N }` 都须查目标语言的 `TextMap`；token 形式（如 `AvatarRankName_130801`）须先算 xxhash 再查表。
3. **图片永远是外链**：`SpriteOutput/...` 为逻辑路径，资源本体不在 vendor，须对接资源库 / CDN。
4. **ID 关联优先于文本匹配**：跨表关联用 ID（`AvatarID` / `JsonPath` / 能力名字符串），不靠名称匹配。
5. **大文件与大目录**：`TextMap`、`Config/Level`、`StageConfig` 等体积巨大，构建期须按需读取或建索引，禁止一次载入全部文件。
6. **空目录与变体后缀**：遍历 `Config/` 时须容错空目录；`_LD` / `_Trial` / `_BE_` 表语义不同，不可与主表混用。

---

## 八、一句话结论

`vendor/TurnBasedGameData` 覆盖**配表（ExcelOutput）、多语言文本（TextMap）、引擎配置（Config）、关卡场景（Stages）、剧情脚本（Story）** 五层；`ExcelOutput` + `TextMap` 是 wiki 内容生产最直接的两层，`Config` 负责底层逻辑与表现还原，`Stages` / `Story` 为专题与剧情页的辅助数据。字段级索引一律以 `tools/converter/DATA_CATALOG.md` 总索引及 `DATA_CATALOG.parts/` 分片为准（全量约 30 万 token，禁止整读）。
