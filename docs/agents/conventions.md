# 项目约定 — 代码规范 / 注释规范 / 决策落位

> AGENTS.md 的按主题子文件（主文件「任务 → 必读」路由表经相对链接引用）。存放跨文件、跨会话的写码与流程约定。**硬约束（MUST）与色彩令牌收口在主文件「强制规则」节**；UI / 样式约定见 [ui-design.md](ui-design.md)；验证职责边界见 [verification.md](verification.md)。

## 代码约定

- Vue SFC 统一使用 `<script setup lang="ts">`。
- 路由使用 `createWebHistory`（History 模式）——Vercel 支持 SPA fallback；Vite `base` 为 `/`（部署于域名根路径）。
- **样式相关的全部约定**（BEM 双前缀 `nk-` / `ui-`、样式分层与懒加载、`tokens.css` 令牌、不使用 CSS 预处理器）**收口于 [ui-design.md](ui-design.md) §1**——本文件不复述，避免双事实源漂移。
- 项目**不配置 ESLint / Prettier**：代码风格靠 vue-tsc 类型检查 + 本文件与主文件约定 + 代码审查保证，**禁止擅自引入 lint 工具链**。

## 文档体量（AI 可读性）

> 红线判据在主文件「强制规则」（生成期唯一来源）；本节给估算口径与拆分手法，不复述红线。

**体量估算口径**：token ≈ 中文字符数 + 非中文字符数 / 2.5。粗判不看精确值，只看量级：

| 单文件规模 | 定性 | 处置 |
| --- | --- | --- |
| < 1 万 token | 健康 | 直接整读 |
| 1–5 万 token | 偏重但可整读 | 允许；若持续增长需规划拆分 |
| > 5 万 token | 失去整读价值 | 必须拆（见下） |

**拆分手法（按内容性质二选一）**：

- **持续增长的生成物 / 索引**（数据目录、审计清单）：改成「KB 级总索引 + 按维度分片」，并在**生成器里**落分片逻辑（源头控制，避免人工拆完又被重新生成合回单文件）。总索引只放：定位流程、分片表、汇总数；明细全在分片。现例：`tools/converter/gen_catalog.py` → `DATA_CATALOG.md` + `DATA_CATALOG.parts/`。
- **按主题累积的复盘日志**（`docs/memory/`）：**按域组织**，不按月/按日——每份域文件对应一个 `docs/agents/` 子域（见 [memory/README.md](../memory/README.md) 的域索引），新增条目直接写进对应域。**禁止**新建按月/按日文件：AI 检索时想的是「改 Spine 要注意什么」，不是「09-03 发生了什么」，时序编号对检索无意义。域文件超过约 30 KB 时按该域内的主题再分小节；整目录超红线则拆域，**不要**退回时序分片。「验证数字」（用例数 / 耗时 / 断言计数）压进 commit message——memory 只留判据与坑位。
  历史：该目录原为 2026-08 ~ 2026-10 的按月/按日日志（约 750 KB / 173 节），已按域压缩折叠为 9 份（约 155 KB），`tools/tidy-memory.mjs` 的时序分片流程随之退场。

**防漂移细则**：

- 分片命名必须**可预测**（如按文件名首字母），让 AI 不读总索引也能猜到该开哪片。
- 生成类索引的分片目录要进 `tools/check-doc-links.mjs` 的跳过名单（自动生成物不做链接校验，避免每日 data-sync 制造噪声 diff）。
- 「总索引」本身禁止膨胀：只允许放定位流程、分片表、汇总数三类信息；发现它开始复述分片内容即为漂移信号，删回分片。

## 文档写法（高信噪比：文档是给 AI 的约束，不是给人看的汇报）

> 体量红线与拆分手法在上节「文档体量」；本节管**单个文档里写什么、不写什么**。判据一句：**AI 读文档是为了知道「能做什么 / 绝不能做什么 / 事实是什么」，不是为了了解背景故事。**

- **只写四类内容**：约束（禁止 / 必须）、判据（如何判定，含反例）、事实（当前状态与唯一落位）、坑位（踩过什么、为何这样绕）。**禁止**写：项目简介与发展史、章节导语、 morale / 动机感慨、「本文介绍了…」式自我描述、对读者常识的重述。
- **负向约束优先**：同一主题，「禁止 X（附唯一豁免 / 出处）」比「鼓励 Y」更能防止 AI 乱写；禁令要可判定（给出检查命令或反例），不写「尽量 / 建议 / 优雅地」。
- **产出粒度受任务约束**：禁止主动「补全 / 完善 / 规范化」用户未要求的文档或 README；用户要求改某文件时，只输出该文件的增量段落，**不要在交付里附带概论、前言、总结表**。
- **不在 Markdown 复述代码可导出的信息**：字段定义看类型文件（`src/services/types/`）、映射看 converter 代码、清单看注册表（`pages.ts` / `MODULES` / `MODULE_SOURCES`）；文档只写**代码推不出的裁决与边界**。重复抄录等于制造双事实源。
- **版本号禁入叙述性文档**：README / AGENTS.md / `docs/agents/` 子文件只写**选型名**（`Vue` / `Vite` / `Python`），**一律不写版本号**——版本是易漂移事实，抄一份就多一个会过期的源。需要版本时指向 `docs/agents/tech-stack.md`（全仓唯一允许内联版本号处，且其 `<!--ver:包名-->` 标记由 `tools/doc-audit.mjs` 与 `package.json` / `requirements.txt` / CI 工作流**逐字比对**，不一致即报）。同理「已修复」「已全部完成」类断言禁入（历史档案 `docs/adr/` / `docs/memory/` 不受此限——它们是当时的证据记录，抹平措辞等于篡改历史）。
- **可判定性自检**：写完一句问「删掉它，AI 会不会改错？」——不会就删（与「注释可删性判据」同源）。

## 注释规范

**注释可删性判据（唯一判据）**：只允许写「代码与数据都推不出、且 `docs/adr/` 或 `docs/` 里也不存在」的事实。凡读代码即可推理的内容——实现步骤、结构层级、命名已表达的意图、样式数值、类名与选择器的对应关系——**一律不得写成注释**。判不准时自问「删掉后，后续 AI 会不会据此改错代码」：会则留，不会则删。

- **允许保留**：外部资产的客观状态（上游 404 / 占位贴图 / 需回退某源）、字段来源与映射规则、上游数据特殊形态（旧 id 形式、哨兵值语义）、异步时序陷阱、运行环境特例、工具指令注释（`# noqa` / `# type: ignore` / `@ts-expect-error` / `@__PURE__` 等——这是指令，不是文档，**不得删除**）。
- **必须删除**：复述实现、设计意图与审美理由、历史沿革、纯分区横幅、跨文件重复的 SSOT 指针句，以及「禁止…/必须…」类约束——后者只要已被 ADR 或 `docs/` 承载，代码处即**不得重复**。
- **可能频繁改动的内容不得写注释**（样式数值尤其如此）：过期注释会主动误导后续 AI，其害大于利。

**落位分层**：术语进 `CONTEXT.md`；不可逆决策进 `docs/adr/`；踩坑与历史进 `docs/memory/`；其余一律不进注释。**禁止**以「注释第一读者是 AI」为由在代码里复述上述文档已承载的信息。

**换行符**：全仓文本文件行尾为 LF（`.gitattributes` 的 `* text=auto eol=lf` 锁定）。历史上双 CR（`\r\r\n`）曾在 35 个文件上累积并导致整文件 diff，**禁止**引入任何 LF→CRLF 的批量转换。

## 决策落位（ADR 门槛）

ADR **仅用于「不可逆 / 跨模块架构决策」**——不符合该门槛的决策（单文件配置、数值调整、流程细节）写入 `docs/memory/` 复盘日志或 commit message 正文，**不新增 ADR**。

**可逆性判据（唯一问法）**：推翻这条改动，返工成本是否限于展示层、且不改动任何下游契约？是 → 不开 ADR。

**ADR 必填字段（四件套，缺一不可入库）**：

| 字段 | 管什么 | 反模式 |
| --- | --- | --- |
| 背景 | 遇到了什么问题（含数据事实） | 写动机故事 |
| 决策 | 选了什么、判据是什么 | 只写「做了 X」不写为何 |
| **替代方案与原因** | **否决了哪条路、为何不走**（防 AI 以后重走老路） | 省略——AI 下次照样试方案 B |
| 后果 | 正面 + 负面清单（含退场 / 孤儿键 / 双写） | 只写好话 |

章节名自由（替代方案 / Alternatives considered / Considered Options / 否决项均可），但**实质内容必须在场**；正文行文已隐含旧方案与理由的（如「旧版双通道…砍掉」），视为合规，不强制改标题。**但「合规」与「可机械判定」是两件事**：`node tools/doc-audit.mjs` 只认**结构化落点**——`## 替代方案（被否）` 一类标题，或 `**Considered Options**` 一类加粗字段；仅有行文暗示而无结构化字段的会报「疑似缺失待复核」，由人判断是补小节还是确认合规。索引 [docs/adr/README.md](../adr/README.md) 的 Status 与修订链同步维护，`check-adr-index.mjs` 双向校验。

正反例（判断锚点，非穷举）：

- **不开 ADR**（→ `docs/memory/` 一段 + commit message 正文；不同步子文件）：首页板块顺序、卡片圆角 / 间距 / 字号取值、区块形态（横排卡片改竖排列表）、文案措辞。
- **开 ADR**：条目入选口径（如版本增量 vs 赛季代际）、路由与 URL 形态、同一字段由 converter 还是前端写入、令牌新增层级或别名语义。
- **落到子文件而非 ADR**：新增目录页要登记的清单、新增令牌类别、e2e 新分层、新增命令。

三路落位的完整原则与 memory 记录纪律以主文件 [AGENTS.md](../../AGENTS.md)「文档分级（可逆性路由）+ 重构期模式」节为准——**本文件只给判据与正反例，不复述路由表**。

## commit message

使用 Conventional Commits 风格（`feat:` / `fix:` / `chore:` 等，与 data-sync 自动化提交一致）；流程细节类决策写入 message 正文。

## 字段筛选

字段筛选遵循 `docs/audit/字段价值审计流程.md`：AI 生成解读卡（字段名 → 人话语义 → 证据 → 置信度 → 价值建议），人工裁决分档。该流程为**三道防错闸门**，判据与分级符号以该文件为准，本文件不复述：

- 闸门 1（单向门）：AI 无权判「排除」档，只能建议「必收」与「待定」。
- 闸门 2（字段基线兜底）：StarRailRes / 官方 wiki 基线有而本地无的字段必须标「待定」。
- 闸门 3（误杀率校准）：误杀率超阈值即收紧 AI 排除权限。
