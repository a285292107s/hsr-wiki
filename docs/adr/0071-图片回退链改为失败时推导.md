# 0071. 图片回退链改为失败时推导（取消逐图内联的 fallback 属性）

## 背景与问题

[0069](0069-图片加载改为本地优先.md) 决策 3 把三级回退链「在属性层表达为两跳」：`imgHtml` / `cdnImgAttrs` / `imgAttrs` 逐图输出 `data-cdn-fallback`（jsDelivr）+ `data-cdn-fallback2`（raw），由 `dom.ts` 的 `handleFailure` 读取并逐跳降级。该形态的问题：

- **属性是纯冗余副本**：回退源完全由主源 URL 决定（`cdnFallbackFromPrimary` / `localFallbackFromPrimary` 是纯函数），`handleFailure` 里本就保留 `|| localFallbackFromPrimary(src)` 的现场推导分支——属性存在与否，推导结果都一样。
- **HTML 体积**：每张图多出约 240–290 字节（两条完整回退 URL，基址各占 79/84 字符），目录页动辄数百张图，首屏 DOM 与卡片模板串同步承压。
- **表达力不足导致真 bug**：`imgAttrsPair` 只发一跳（没有 `fallback2`），走它的图在 jsDelivr 失败后直接落占位；[0024](0024-图标回退链与真缺失占位.md) 的「模板必须同时绑两个属性」还留下一整类失效——属性漏绑即静默失去回退（`docs/memory/data-semantics.md`、`docs/memory/architecture.md` 各记了一条）。
- **属性名撞车**：`handleFailure` 把降级前的原地址记在 `data-cdn-src`，而该属性正是闸门（[0069](0069-图片加载改为本地优先.md) 决策 6 的 `img-gate`）的接管凭据，二者互相覆盖。

## 决策

1. **回退链只在运行期推导**：`src/services/cdn/resolve.ts` 新增 `nextFallbackFrom(src)` 作为唯一跳转判据——本地主源 → jsDelivr 镜像 → raw 镜像 → 终止；nanoka 主源 → jsDelivr 旧档 → 终止；官方原图 → nanoka。
2. **jsDelivr 规则地址是终点，不再反查 nanoka**：`cdnFallbackFromPrimary` 仍保留 jsDelivr ↔ nanoka 双向反查（供 `resolveCdnUri` 声明与测试），但 `nextFallbackFrom` 在 jsDelivr 规则地址上返回空——否则 nanoka 与 jsDelivr 会互相回退成环（两个 404 地址无限重试）。
3. **取消逐图内联属性**：`imgHtml` / `cdnImgAttrs` / `imgAttrs` 只输出主源。`data-cdn-fallback` **仅保留为显式覆盖**（`imgAttrsPair`，首页立绘这类「回退源不由 URL 决定」的少数位点），`data-cdn-fallback2` 彻底退场。删除 `cdnImgFallbackAttr` / `localFallback2FromPrimary` / `lib/icons.ts` 的 `iconImgAttrs`。
4. **降级记录属性改名**：`data-cdn-src` → `data-cdn-degraded-src`，与闸门的接管凭据解耦。

## 替代方案（被否）

| 被否方案 | 否决理由 |
| --- | --- |
| 维持两跳属性（0069 决策 3 原形态） | 属性是纯函数结果的副本，体积代价换零信息量；且 `imgAttrsPair` 的第二跳缺失、属性漏绑静默失效两类问题只能靠「记得绑」维持 |
| 属性只输出一跳（`data-cdn-fallback`），第二跳现场推导 | 半改：仍要求每个模板绑属性，仍留跳数截断与漏绑风险，收益只有一半字节 |
| 用元素上的 hop 计数器防 nanoka ↔ jsDelivr 成环 | 需要在元素上留状态、且状态会随组件换源过期；镜像跳由 URL 形态即可判定终点，无需计数 |
| 保留 `data-cdn-src` 兼作降级记录 | 与闸门凭据同名，闸门接管与降级记录互相覆盖，排障时无法判断该属性归谁写 |

## 后果

- 目录卡片与详情视图的 `<img>` 输出缩短约 240–290 字节/张（运行期渲染）。预渲染快照不含图片位（目录与详情都由客户端挂载），因此快照体量不变。
- 「回退属性漏绑即失去回退」这一类失效从结构上消失：回退能力只取决于主源 URL。
- 远端主源（nanoka）失败后最多再试一跳 jsDelivr 旧档，不再回退回 nanoka；`jdPrimary` 分类的「jsDelivr 主源 → nanoka」方向在当前分类表下不可达（所有分类都有 `local` 分支）。
- e2e 断言改读 `data-cdn-src`（`e2e/layout-character-skill-data.spec.ts`、`layout-currency.spec.ts`、`layout-endgame-board.spec.ts`）；回退能力由「图片渲染成功且无占位」间接证明，不再由属性存在证明。
- 文档：[../memory/build-deploy.md](../memory/build-deploy.md) 的「三级链在属性层表达为两跳」改写为运行期推导；[0024](0024-图标回退链与真缺失占位.md) 决策 1 的双属性绑定要求作废。
