# 字段价值审计流程

> 背景：源数据（vendor/TurnBasedGameData）字段冗余且命名难懂（英文驼峰），AI 辅助筛选时最怕「有价值的字段被错过」。本流程以「AI 生成解读卡 + 人工裁决 + 三道防错闸门」的方式，系统性地审计源表字段是否值得进入转换器输出。
>
> 术语定义见 CONTEXT.md「数据筛选」小节。

## 审计边界（按模式拆分）

项目有两种玩法模式，数据源完全隔离，审计必须分开跑：

| 模式 | 源表 | 字段基线 | 语义校准 |
|------|------|----------|----------|
| 常规模式 | AvatarConfig / AvatarSkillConfig / AvatarRankConfig 等 | StarRailRes 索引 JSON（字段差集） | 米游社官方 wiki（Playwright 抓取渲染后页面） |
| 货币战争（CW） | GridFightRoleBasicInfo / GridFightRoleStar / GridFightFrontSkill 等 12+ 张表 | **无社区格式可抄** → 以米游社官方 wiki 展示内容为基线 | 米游社官方 wiki + 人工游戏知识 |

优先级：常规模式剩余源表先审完，再进入 CW 模式。CW 字段语义不可套用常规模式直觉（如 HealOrShieldDisplay 曾被误作角色定位，实为续航动效标识）。

## 触发时机

- **新源表接入**：转换器新增模块前，对目标源表跑一次全字段审计
- **版本演进**：游戏更新引入新字段（每日数据同步 CI 后），对受影响模块跑增量审计
- **存疑表驱动**：docs 存疑表积累待补字段后，统一审计补全

## 执行流程（五步）

1. **确认真实字段全集**：`query.py --schema` 已支持全量字段统计（含出现率，2026-08-02 修复，历史教训见 `docs/audit/字段审计-AvatarSkillConfig.md` F1）。直接用它获取字段全集与出现率；出现率低于 100% 的字段即为可选字段，需重点关注。
2. **收集证据**：每个字段收集值分布（唯一值数 + 样例）、TextMap 上下文（`query.py --resolve/--search`）、字段基线对比（StarRailRes GitHub 仓库索引 JSON）。
3. **生成解读卡**：AI 为每个字段产出「字段名 → 人话语义 → 证据 → 置信度 → 价值建议」五元组。
4. **人工裁决**：人工只裁决 ⚪ 待定与 🟡 可选字段（同意/改档）；🟢 必收与 🔴 排除 AI 给出建议，人工抽查。
5. **产出归档**：解读卡落 `docs/audit/字段审计-<表名>.md`；🟡 字段进**存疑表**（即 `docs/audit/角色转换模块字段分析.md` 的「存疑」节，其中 #5 为「下一阶段字段补充清单」，不是独立文件）；⚪ 字段待游戏内确认后归位。

## 四档分级标准

| 档位 | 判定标准 | 项目案例 |
|------|----------|----------|
| 🟢 必收 | 玩家可见、wiki 应展示，转换器已输出或应输出 | SkillTag、SPBase、SkillDesc |
| 🟡 可选 | 对玩家有价值，但展示形态待定 → 进存疑表 | StanceDamageDisplay、LevelUpCostList |
| 🔴 排除 | 内部字段 / 无区分度（全常量）→ 不输出 | SPMultipleRatio（恒 0.5）、CoolDown（恒 -1） |
| ⚪ 待定 | 证据不足，需游戏内 UI 确认 | SkillNeed 的完整语义、ShowDamageList |

## 三道防错闸门

### 闸门 1：排除必须高置信度（单向门）

AI 判 🔴 排除，必须同时满足：

1. 证据类别明确，且仅限机器可复核的四类之一：
   - ① 值分布全常量（全表唯一值，如 SPMultipleRatio 恒 0.5）
   - ② 官方隐藏标记（HideInUI 等）
   - ③ 内部 ID 段规则
   - ④ 仅被内部字段引用
2. 置信度为「高」。

不满足任一条件 → **强制降级为 ⚪ 待定**。AI 可以自由判 🟢 必收与 ⚪ 待定，但没有资格擅自判 🔴 排除。

### 闸门 2：字段基线兜底（防静默消失）

- 常规模式：将 StarRailRes 仓库索引 JSON 的字段集与本地输出做差集；
- CW 模式：以米游社官方 wiki（bbs.mihoyo.com/sr/wiki）实际展示的数据区块为基线（JS 渲染，需 Playwright 抓取）；
- **「基线有、本地无」的字段一律标记 ⚪ 待定**，AI 无权判 🔴 排除；
- 例外：有明确的有意排除理由（如 ADR 0008 废弃 SkillEffect 枚举）时，标注理由后归档，不算遗漏。
- 图片资源不在此闸门内：CDN 不可枚举，图片存在性以引用站实际请求过的路径为准（独立专项）。

### 闸门 3：误杀率统计（校准 AI 权限）

- 每张表审计结束时统计：AI 判 🔴 的字段数 vs 人工改判数；
- 误杀率 ≤ 5% 才允许沿用本流程；超过则收紧 AI 排除权限（下一张表所有 🔴 一律人工确认）。
