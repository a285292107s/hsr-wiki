# 0061. 强化形态入口收敛为 hero 与内容区之间的三选一卡片组

## 状态

`accepted`（**已实现**：`composables/use-enhanced-form.ts` + `character/EnhFormCards.vue` +
`styles/character-enhance.css`）。**修订 [0010](0010-角色强化展示范式.md)** 的三态入口形态
（该文决策 1 的吸顶工具条切换与 Update 段的「第三个按钮」均被本文化替），
强化摘要与强化角标两条决策保持不动。

## 1. 背景与问题

用户先反馈「部分角色有增强形态（如镜流），优化 DOM 结构，重构增强形态的 UI 展示」，
随后指出重构中途出现的结构问题：强化模块被写成带编号的 `01 对比` 区块，与同屏的 `01 SKILLS`
编号撞车，且 hero 区的形态入口与该模块里的切换控件是同一状态的两个入口。

## 2. 事实（镜流 1212，2026-10-19 实测）

- 三种视图的**覆盖范围不同源**：原始 / 强化各覆盖全部内容（技能 7 / 星魂 6 / 行迹 18），
  对比只渲染真实字段变化项（技能 6 / 星魂 3 / 行迹 3，`sp_need` 该角色无变化）。
  即对比是「过滤视图」，不是第三种内容形态。
- 对比态整页覆盖面收缩：导航收窄为技能 / 附加 / 星魂三块，
  其余区块（加成 / 光锥 / 队伍 / 遗器 / 档案 / 配音）整体隐藏。
- hero 底到 `00 STATS` 顶的空白：1440 档 48px、390 与 320 档各 40px。
- 强化摘要文本此前在**全站**（含 cn）被 `<unbreak>` 转义串污染：converter 用
  `clean=False` 取 `~raw` 变体，而 `gameTagsToHtml` 只认 `<color>` / `<unbreak>` 标记，
  `&lt;unbreak&gt;` 原样上屏。改走清洗变体后 13 语言包同步获得干净文本
  （`~raw` 键随之退场，语言包键数不变）。

## 3. 决策

1. **唯一入口放在 hero 与内容区之间**：三张并排卡片，占据上述 40~48px 空白所在的槽位
   （`.nk-forms-slot`，与内容列同宽同内距）。形态控件决定整页数据形态，
   参考点必须在页面最上方；插在任何内容区块之间都会让「它管哪些区块」变得可争。
2. **三选一、严格互斥**（用户裁决）：不拆分「形态组 + 对比开关」，三卡平级、等高，
   任意时刻恰有一张 `aria-pressed`。选对比即离开形态态，选形态即离开对比态。
3. **卡片不占区块编号**：形态控件不承载数据，`SECTION_IDX` 只发给承载数据的区块。
   旧形态（`01 对比` 标题 + 模块内 tab）整体退场，同屏不再出现两个 `01`。
4. **对比卡带变化计数**：卡面显示「N 项变化」（`buildCompare` 实时算，
   技能 + 星魂 + 行迹 + `sp_need` 变化项之和），解释对比态「内容为什么变少」。
5. **强化摘要跟随选中态**：仅在强化态与对比态列出（两者都以强化数据为基准），
   原始态不列；摘要退化为卡片组下方的一行要点，不再占独立区块。
6. **hero 不承载形态信息**：hero 的「强化形态」徽标整块退场（用户裁决），
   形态信息只在卡片组一处出现；页面不再有第二个指向形态的入口。
7. **状态互斥在 store 收口**：`setEnhKey` 退出对比、`setCompareOn(true)` 进对比，
   卡片组只调这两个动作，不在组件里复制互斥逻辑。
8. **条目级角标全部退场**（用户裁决）：技能卡与星魂卡的「V1」强化角标、
   对比模式下每张变化卡的「变化」角标一并删除。理由：形态状态已由卡片组一处表达，
   逐条角标是在每个条目上重复同一个页面级事实；对比态本身就只渲染变化项，
   逐卡再标「变化」是第二次同义重复。故 `enhMark` / `enhLabel` 整条 prop 链路
   （View → SkillsPanel / SkillCard / EidolonsPanel）退场，不留空壳。
9. **登记清单落 base id**：`enhanced.<key>.skill_ids` / `rank_ids` 由转换器换算成
   **基础 id**（`去掉 _ENHANCED_ID_OFFSET`）后再输出，与 `ranks` 的键、`Rank.id`、
   `skills` 的键同一命名空间。详见第 7 节。

## 4. 替代方案（被否）

- **hero 形态行 + 模块内切换控件（重构第一版）**：同一状态两个入口，且模块占 `01` 编号。
  被否——正是用户指出的重复感与编号撞车的来源。
- **hero 形态组 + 区块行头对比开关（可叠加）**：语义最贴「观察开关」，但同一开关会在
  2~3 个区块行头重复出现，且用户明确要求视觉上「一眼可识别」的唯一入口。
- **三卡但形态组与对比卡分组（可叠加）**：用户裁决改为严格互斥，不采用。
- **hero 保留「强化形态」徽标作为跳到卡片组的快捷键**：首轮保留过，用户裁决移除——
  卡片组本身就在首屏可见范围内，跳转入口的价值不抵它带来的「又一处强化标识」。
- **对比作为独立详情页/独立路由**：对比只在强化数据存在时有意义，且需与形态联动，
  多一条路由与一份快照成本，收益为零。

## 5. 后果

- 新增 `EnhFormCards.vue` 与 `useEnhancedForm`；删除重构期短暂存在的 `EnhFormSwitch.vue`。
- `character-enhance.css` 的 `nk-enh-tabs*` / `nk-enh-notes*` / `nk-enh-module__*` /
  `nk-hero__forms*` / `nk-skill__enh-badge` / `nk-eidolon__enh-badge` 全部退场，
  改为 `nk-forms*`；`character-compare.css` 的 `nk-cmp-badge` 与
  `character-hero.css` 的 `nk-hero__badge--enh` / `nk-hero__badge-mark` 一并删除。
  吸顶条（`nk-enh-bar`）样式不动。
- 词典新增 `char.enhHint` / `char.changedCount` / `char.compareHint`
  （`char.compareHint` 最终未上屏，仅作占位；`char.enhHint` 同理），
  并把 `char.enhModeAria` 的文案改为「形态切换」（13 语言同步）。
  `char.enhForm` 仍被卡片组的 `aria-label` 使用。
- `<768px` 三卡改两列流式排布（第三张独占一行），触控高度 ≥44px 由 e2e 钉住。
- 判据落在 `e2e/layout-character-enhance.spec.ts`：三卡计数、两处旧入口退场、
  三类强化/变化角标均不存在、卡片组位于 hero 与首个内容区块之间、
  任意时刻恰一张按下、「01 对比」不出现、窄档不溢出。

## 7. 补记：登记清单的 id 命名空间（2026-10-19）

`AvatarConfigEnhanced.SkillList` / `RankIDList` 登记的是**强化版 id**（`1121201`），
而 `d.ranks` 的键与 `Rank.id` 是**基础 id**（`121201`），两者相差固定的 `1_000_000`。
首版转换器把这两张清单原样落进产物，导致星魂角标的 `rank_ids.has(rk.id)` 恒为假
（实测镜流 6 个星魂一个都点不亮，技能侧则因前端先做 `baseSkillId()` 换算而正常）。

裁决：**产物的登记清单统一落基础 id**，与同包内其余 id 字段同一命名空间；
前端 `lib/compare.ts` 需要强化版 id 时用新增的 `enhancedIdOf()` 反推。
两侧偏移常量必须同步修改（转换器 `_ENHANCED_ID_OFFSET` / 前端 `baseSkillId` &
`enhancedIdOf`），单测各钉一条逆运算断言。实测 10 个强化角色的两张清单逐条满足该偏移。
