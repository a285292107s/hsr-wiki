# 0066. 物品图鉴口径：只收背包物品，剔除活动内嵌系统对象

## 状态

`accepted`（**已实现**：`tools/converter/converters/items.py` 新增 `EXCLUDED_ACTIVITY_SUBTYPES`（16 个
子类型）并在 `_is_excluded` 里整类拒收；`items.json` 与 13 份 `i18n/*/items.json` 重生成。**本轮
不动 `Virtual` 活动货币（36 条）与任务道具（669 条）**，见「已知边界」）

## 1. 背景与问题

用户提出物品图鉴「数量非常巨大」，要求判断哪些物品没有展示必要（例如只在内部使用、玩家察觉不到）。
改动前口径：`ItemConfig` 2,941 条 → 转换器剔除 `Display` / `Pet` / 8 种可外观 `Usable` 子类
（335 条）→ `items.json` 2,606 条 → 前端再丢无名条目（194 条）→ 页面展示 **2,412 条**。

盘点（一次性探针，只读 `ExcelOutput`）：

- **`isVisible` 不能当「玩家可见」判据**：2,670 条里有 `isVisible=true` 的只有 2,270 条，而星琼 /
  信用点 / 古老梦华 / 开拓力这些最重要的货币全都没有该字段——它表达的是「是否占背包格子」。
- **不存在批量幽灵条目**：把 2,412 条逐条对 2,100 张表的 `ItemID` 引用扫过，无任何引用且无用途 /
  描述 / 背景的只有 3 条（列车基金、探索积分 ×2）。噪音不在「死数据」，在**类型**。
- **噪音主体是活动内嵌系统对象**：这些子类型在展示口径内呈现出三重一致——**用途文案覆盖率 0**（真
  物品几乎都有官方「用途」）、**无独立获取途径 / 商店 / 合成链**，描述统一写成「在「XX」玩法中
  用于…」。玩家能在活动界面里看到它们，但它们从不以「物品」形态进背包。
- **按「无 `ItemID` 引用」判死会误杀任务道具**：任务道具 669 条里 485 条无任何表引用（发放与消耗
  在任务脚本里），而它们是玩家真实持有的背包物品。

## 2. 决策

**按子类型整类剔除**，判据 = 该子类型在展示口径内满足「用途文案 0 + 无独立获取链 + 描述限定在
某玩法内」。剔除名单（16 个，共 810 条，其中 689 条本会展示）：

| 子类型 | 条数（展示） | 实际是什么 | 玩家在哪见到 |
| --- | --- | --- | --- |
| `TravelBrochurePaster` | 252 | 「游梦手册」数字贴纸 | 活动手册页面 |
| `PlanetFesItem` | 128 | 展会活动资源（金币 / 钻石 / 灵感点 / 入场券） | 活动商店与任务 |
| `ChessRogueDiceSurface` | 80 | 模拟宇宙骰面 | 模拟宇宙骰面 UI |
| `DiceCombatAvatar` / `DiceCombatDice` | 61 | 「银河战力党」对局卡牌与曜彩骰 | 活动对局 |
| `AetherSkill` / `AetherSpirit` | 51 | 「以太战线」芯片与以太灵 | 活动对局 |
| `MuseumStuff` / `MuseumExhibit` | 54 | 博物馆员工与展品 | 活动博物馆界面 |
| `ElfRestaurantItem` | 18 | 小精灵餐厅食材与妖精金币 | 活动餐厅界面 |
| `HipplenOutfit` | 17 | 活动角色装扮染料 / 饰品 | 活动换装界面 |
| `FightFestSkill` | 12 | 斗技「战术秘籍 / 战术饮料」 | 活动战斗内 |
| `RogueMedal` | 10 | 差分宇宙「概率艺术馆」奖章 | 模拟宇宙图鉴 |
| `IdleLiveItem` | 4 | 游戏直播活动代币 | 活动直播界面 |
| `MatchThreeV2` / `PixAirMaterial` | 2 | 单个活动道具 | 活动内 |

**不动的易误伤项**：`ForceOpitonalGift`（命途行者的赠礼 / 星海宝藏 / 忆持光匣，真背包礼包）、
`FindChest`（可无限使用的寻宝道具，有来源有用途）、任务道具、阅读物、全部材料 / 消耗品 / 掉落。

## Considered Options

- **用 `isVisible` 过滤**：放弃——星琼 / 信用点 / 古老梦华 / 开拓力都没有该字段，会把账号货币整批
  砍掉。
- **按「无 `ItemID` 引用」判死**：放弃——任务道具 485 / 669 条无表引用（由任务脚本发放与消耗），
  会把玩家真实持有的背包物品当幽灵条目删掉。
- **逐条维护名字 / ID 黑名单**：放弃——每个版本都会新增活动内嵌对象（贴纸、展会资源、活动货币），
  黑名单永远追不上；按子类型整类拒收才是稳定判据。
- **给活动内嵌对象开独立分区或筛选（保留但默认收起）**：放弃——它们在游戏内也没有「物品」归属，
  开分区等于让玩家去一个游戏里不存在的分类里找东西；且会新增一套导航入口。若日后确有收集向需求，
  再按内容域单开页面，不塞回物品图鉴。
- **连 `Virtual` 里的活动货币（36 条）与任务道具（669 条）一起砍**：放弃——前者只影响少量活动货币、
  后者是真实背包内容，两者都属口径灰区，本轮由用户口径决定「先只剔活动内嵌对象」。

## 3. 影响面

- 数据：`public/data/cn/items.json` 2,606 → **1,796** 条；13 份 `i18n/*/items.json` 6,099 → **4,357** 键。
- 页面：物品页展示 **2,412 → 1,723**（-28.6%）；子类型筛选与用途筛选选项随数据自动收缩；卡面结构不变。
- AI 快照：`item` 条目级覆盖按数据实时统计（1,723/1,723），守卫与 sitemap 无需改断言。
- 前端零改动：过滤只发生在转换器，`src/app/catalog/pages/item.ts` 未改。

## 4. 后果

- 物品图鉴只剩玩家真能拿在背包里的东西；**用途文案覆盖率从 66.7% 升到 94.3%**，卡面副行基本不再
  需要回退子类型。
- 负面：贴纸 / 骰面 / 展品 / 以太灵等内容在站内查不到。它们本就是活动内收藏物，若日后要做，应作为
  活动内容单独成页，而不是回到物品图鉴。
- **判据是子类型级、且未登记的新子类型默认保留**（宁多显示不漏数据）：上游新增活动内嵌类型时需要
  在 `EXCLUDED_ACTIVITY_SUBTYPES` 登记一次——漂移模式是「多显示」而非「静默删数据」。

## 5. 已知边界

- `Virtual` 48 条中仍有 36 条是活动货币 / 系统计数（宇宙碎片、技能点、灵感、拟合值、猜想、金币、
  等价钻钞、成就点数、发展资金、列车基金、2810xx 段活动代币…），玩家在活动界面可见但不在背包。
- 任务道具 669 条（占展示 38.8%）是最大的一块，属真实背包内容但检索价值低。
- 两者都待用户口径；若要处理，前者按 ID 段 / 账号货币白名单剔除，后者需要先定「任务道具算不算物品
  图鉴内容」。
