# 0021. 页面底色上移一档（`--bg`：blk-950 → blk-850）与黑阶用法方向

## 状态

`accepted`（**已实现**：tokens 重基 + 页面级承载面上移 + `index.html` 首帧兜底对齐均已落地；验证记录见文末「相关」）

> 本决策**修订 [ADR 0011](0011-全局色彩管理-黑与紫-黑与金.md) 决策 1 中「`--bg` 取最黑一级」这一句**：页面底色不再是黑阶的绝对最黑档，而是「承载位」的第一档。
> ADR 0011 的其余条款（黑阶为深色表面唯一事实来源、黑阶无色相、主色经 `color-mix` 注入、双色约束、领域色豁免）**继续有效**。

## 背景

用户反馈：**页面底色恒为纯黑，不利于阅读**，要求检索外部实践后给出更优底色。

**外部实践（均为深灰基面，无一用纯黑）**：

| 来源 | 阅读面底色 | 层级做法 |
| --- | --- | --- |
| Material Design 暗色主题 | `#121212` | 承载面靠叠加白 5 / 7 / 8 / 9 / 11% 提亮，而非阴影 |
| VS Code Dark+ 编辑区 | `#1E1E1E` | — |
| GitHub 暗色默认画布 | `#0D1117` | — |
| Apple HIG | 「soften the color of white backgrounds」「prefer the system background colors」 | — |

**纯黑伤阅读的机制**：① 暗底使瞳孔放大，散光人群（约 47%，BOIA 引 H. Locke）出现字形边缘光晕（halation），深底浅字还要额外对抗抗锯齿（本项目 `#app` 开了 `-webkit-font-smoothing: antialiased`，笔画更细）；② 纯黑 + 纯白 = 21:1，远超 WCAG 最低线（4.5:1）而落进「过对比」区间，Smashing 的暗色可访问性综述明确建议改用深灰；③ 纯黑在 OLED 上的省电收益只在 OLED 且屏幕亮度是主因（NN/g 实测），本项目是数据阅读型 Wiki，收益远小于舒适度代价。

**本项目实测（改动前）**：`--text-bright` 21.00:1 / `--text` 17.03:1 / `--text2` 8.19:1；`--surface` 合成 `#100c0b`（ΔL 3.96e-3）、`--card` 合成 `#14100f`（ΔL 5.42e-3）——卡片与页面仅约 1.10:1 的分离度，层级几乎全靠发丝边框与纸感颗粒撑。

**关键实测（决定了本决策不是「一行改底色」）**：`--surface` / `--card` 都是**半透明黑阶**，其明度来自与底色的合成。只改 `--bg` 而不动阶梯时，扫描结果：

| `--bg` | `--surface` ΔL×1000 | `--card` ΔL×1000 |
| --- | --- | --- |
| `#000000` | +3.96 | +5.42 |
| `#0A0A0B` | +1.46 | +3.73 |
| `#0D0D0F` | +0.61 | +3.16 |
| `#101012` | **−0.37（反转）** | +2.46 |
| `#121214` | **−1.13（反转）** | +1.90 |

即越过 `#0D0D0F` 后 `--surface` 会比页面**更暗**（侧栏、抽屉、`--surface` 组件读成「陷下去」）。故底色与表面阶梯必须**同批上移一档**。

## 决策

1. **页面底色上移一档**：`--bg: var(--blk-950)` → `var(--blk-850)`（`#121214`，≈ Material 的 `#121212`）。**常规与货币战争两模式共用同一档**（黑阶仍是唯一事实来源，变的只是语义层把哪一档分配给「页面底」）。
2. **黑阶用法方向制度化（承载位 / 压暗位）**，新增原语 `--blk-750: #1E1E22`：
   - **承载位**（逐级提亮，禁反序）：`850` 页面底色 → `800` 承载面（外壳 / 面板 / 条 / 牌 / 图窗）→ `750` 卡片面（`--card` 及其卡内垫底）。
   - **压暗位**：`950` / `900` 只用于**媒体遮罩、暗角内影、scrim、hover 洗色**——「比页面更暗」就是它们的语义。**禁止把 `950` / `900` 当承载面**：底色上移后它们比页面更暗，会读成空洞。深色文字（`color: var(--blk-900)`，用于亮底 chip 上）同样保持不动。
3. **表面阶梯随之同步上移**：`--surface` 基色 `900 → 800`（alpha 85%→88%，CW 88%→90%）；`--card` 基色 `850 → 750`（alpha 70%→80%，CW 72%→82%）；外壳三条 `--nk-shell-bg` / `--nk-sheet-bg` / `--nk-header-bg` 基色 `900 → 800`（两主题各一份）。alpha 微调是为了让「合成后」的层级差不低于改动前。
4. **页面级承载面按同一规则上移**（≥70% alpha 的板 / 条 / 牌 / 图窗 / 卡内垫底）：`900 → 800`、`850 → 750`。≤62% 的洗色 / 遮罩 / 暗角 / scrim 与媒体叠加层不动（它们的方向本就是「压暗」，且感知差 ≤1.06:1）。
5. **`index.html` 首帧 / overscroll 兜底底色与 `--bg` 对齐**：`#0F0F23` → `#121214`。该值是 ADR 0011 已判淘汰的「蓝紫调假黑」残留（`git log -S` 显示自 2026-07-26 起未再改动），会在 CSS 未加载的首帧与移动端 overscroll 时露出，与 `#app` 之间形成色差接缝。

## 备选（未采纳）

- **只改 `--bg`（保留原阶梯）**：被上表实测否定——`#101012` 起 `--surface` 反转，层级比现状更差。
- **底色保持纯黑，只压过对比**（把 `--text-bright` 从纯白降到 94% 白）：能缓解光晕，但不解决「死黑 + 长时间阅读」本身；本项目颗粒层注释「化开纯平死黑」已是同类补丁，再叠补丁不如改底色。
- **提到 `#1E1E1E`（VS Code 档）及以上**：实测该底色上 `--surface` ΔL ≈ 0（层级塌），要继续保层级得把卡片推到 `#2B272A` 一类，与「立绘为主的暗色画廊」气质冲突，也让发丝线 + 颗粒那套克制材质语言失真。**否决理由不是审美，是层级成本。**

## 后果

- **对比度全线下移但全绿**（`check-contrast --strict` 实测）：常规 `--text` 17.03→**15.18**、`--text-bright` 21.00→**18.71**、`--text2` 8.19→**7.30**、`--text3` 6.22→**5.54**、`--metric-val` 8.98→**8.00**、`--primary` 4.62→**4.11**（主色文字验收线 3:1，仍达标；**注意**：`--primary` 已低于 4.5:1，日后若把它当正文级文字用即不达标）。CW 侧 `--text` 20.09→17.90。
- **层级差反而增大**（合成实测）：常规 `--surface` ΔL 3.96e-3 → **6.07e-3**、`--card` 5.42e-3 → **8.08e-3**；CW 5.24e-3 → 8.35e-3、6.92e-3 → 10.85e-3。层级序「底色 < surface < card」两模式均严格递增。
- **两处承载面辅助值同批微调**（底色变亮后「同强度不再同等可见」）：`--nk-page-tint` 常规 `5% → 6%`、CW `4% → 5%`（目录页顶部主色晕染，维持同等可见度）；颗粒层 `--grain-opacity` `0.07 → 0.08`（白噪点与底的绝对差由 17.9 收窄到 16.6 ≈ −7%，按等感知还原值 ≈0.075 取 0.08 留余量；仍是唯一调参位）。
- **视觉判定交用户**：像素基线（`e2e/snapshots/`）由 `pnpm test:e2e:update`（内置 `--update-snapshots=all`）刷新，刷新记录见「相关」。
- **`index.html` 仍是门禁盲区**：`tools/check-colors.mjs` 的扫描根是 `src/`，首帧兜底那行裸色值不受守卫约束。本决策只做值对齐 + 就地注释声明「须与 tokens.css 的 `--bg` 同步」；扩扫描面属另一件事，未在本轮做。
- **本决策不动的东西**：领域色、双色约束、强调色切换链路、`--hero-bg-*` 兜底渐变（其暗端与 `var(--bg)` 收束关系自动跟随）、媒体暗角内影（`inset` 阴影保持 `blk-900`）。

## 可访问性后果与连带修复（本轮实测）

底色与表面同时提亮，把「**小字落在承载面上**」的对比度余量吃掉了——而 `tools/check-contrast.mjs` 只算「文字 × `--bg`」，这条路径它看不到。

**取证方式**：① 全量 `pnpm test:e2e:update` 的 axe 扫描（4 页 × 缺省色）；② 自建探针覆盖 12 个页面（含 `a11y` 用例未扫的详情页/设置页）× 10 套强调色；③ **A/B 判别**——运行时用 `addStyleTag` 注入「重基前」的令牌定义，同页对比，据此把「本轮回归」与「存量违规」分开。

**判定结果**：

| 页面 · 节点 | 重基前 | 重基后 | 结论 |
| --- | --- | --- | --- |
| 首页 · `.ui-sidebar-link__en`（8px，侧栏激活英文小字） | 5.27（axe 通过） | **4.48** | **本轮回归** |
| `/lightcone/23055` · `.nk-skill__tag`（10px，`--text3` 落在着色 tag 上） | 通过 | **4.09** | **本轮回归** |
| `/settings` · `.nk-settings__kicker`（11px，`--primary` 当小字） | 4.62 | **4.11** | **本轮回归** |
| `/settings` · `.nk-seg__en`（8.3px，`--text3` 落在激活段上） | 通过 | **4.20** | **本轮回归** |
| `/relic/134` · `.nk-relic-effect__num`（11px，`--primary`） | 3.76 | 3.18 | 存量（本轮加重） |
| `/lightcone/23055` · `.nk-lc-rank-label`（11px，`--primary`） | 4.17 | 3.58 | 存量（本轮加重） |
| `/settings` · `.nk-swatch__hex`（9.3px，`--metric-val` 62% 混色） | 3.82 | 3.60 | 存量（本轮加重） |

**修复（四条，均已落地并复测）**：

1. **`--text3` 提亮**：`#7C8DA6 → #8A9BB4`。最严承载面（着色 tag `#2e2c2f`）由 4.10 → **4.90**，页面底 5.54 → **6.62**，仍严格低于 `--text2`（保持三级层次）。这是**系统性**修法：`--text3` 遍布元信息小字且常落在卡片/着色片上，逐处换色会漏。
2. **`--primary` 当小字用 → `--metric-val`**：执行 ADR 0011 后果段既有规则（「直用 `--primary` 的文字位改走亮端」）。本轮改 5 处：`.nk-secnav__btn--active`（**全站原语**，12px 激活态区块导航）、`.nk-lc-rank-label`、`.nk-relic-effect__num`、`.nk-slider__val`、`.nk-settings__kicker`。
3. **小字混色下限**（按 `ui-design.md` §3 规定的「10 套强调色重测」执行）：`.ui-sidebar-link--active .ui-sidebar-link__en` 的 `--metric-val` 混色 `85% → 92%`（逐色阶最低 4.59 → **5.10**，axe 实测 0 违规）；`.nk-swatch--on .nk-swatch__hex` `62% → 80%`（3.60 → **5.08**，存量顺带修）。
4. **复测**：首页 × 5 套常规强调色、`/currency` × 5 套 CW 强调色、12 个页面 —— **color-contrast 违规归零**；全量 e2e `44 passed`。

**未修（存量，非本轮引入，另立清单）**：① `image-alt` 25 处（技能/遗器/配队图标缺 `alt`）、`label` 6 处（技能等级滑条 `input` 无 label）、`aria-required-children` 3 处（`div[aria-label]` 直接包 `button`）——都是与颜色无关的存量 a11y 缺陷，落在 `a11y` 用例未覆盖的详情页/设置页；② 其余 `color: var(--primary)` 小字落点（hover 态与页面局部标签，按 `check-contrast` 的「主色文字 ≥3:1」验收线仍达标，按 WCAG 小字 4.5:1 则不足）——建议后续以「新增 `--primary-text` 语义令牌 + 全量替换文字位」或按处换 `--metric-val` 单独处理。
