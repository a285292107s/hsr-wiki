## 「贪饕」污染色：机制语境色进令牌体系（ADR 0027）——**取证推翻了口述色相**

- **用户原话**：「讨论一下颜色的问题。贪饕污染，游戏内有专门的主题颜色，是代表不详的猩红色」。
- **事实核查（决定了整轮边界）**：① 站内**没有任何机制专属色**——`/voracity` 全页（吸顶进度条、secnav 激活项、卡底纹与边框、数值强调位）加怪物详情「受『贪饕』侵蚀」标记、终局污染徽标、目录卡「含污染」标记**全部消费 `--primary`**，即读感等于用户当前强调色（缺省赤陶）；② 数据里**没有权威色值**——教程富文本强调色是全局琥珀 `<color=#f29e38ff>`（且与 `--elem-fire #FF6B35` 几乎同色相），侵蚀 buff 图标是通用 `IconBuffShield`，颜色是这套机制唯一能承载身份的表达；③ 素材取证（子代理，HSV 过滤 `V<0.15/V>0.9/S<0.25` + k-means + WCAG 对比度）得到**红徽记 + 洋红能量并存**：徽记 `#DF3D3D`/`#FF4242`、洋红能量 `#C40C6A`（官方 4.6 公告 KV 内 top1 簇 22.2%）、受污染敌人血条 `#FC48AC`、徽记暗部 `#66030C`。
- **最重要的教训**：**「游戏内有专门的主题颜色」这类需求，用户口述的色相不能照抄**——它可能是记忆里最抓眼的一小块（红色徽记），而画面主体与官方宣发的主体其实是另一支（洋红能量）。取证与口述不一致时必须**当场指出**并把选择交回用户（Q8 卡片），照抄会让页面读成「另一个模式色」的近亲。第二条同源教训：**污染标记恰恰渲染在按模式着色的终局页里**，所以选色的第一道验收是「与 `--eg-boss` 玫瑰红 `#FB7185` 分不分得开」，而不是只看单页观感——纯红族正是因此落选（同色相族、红上加红）。
- **9 项决策走卡片收敛**（Q1–Q9）：新领域语义族 + 页面语境色（一份色值两处身份）/ 从游戏素材取样推导 / 覆盖四个面（`/voracity` 数据元素、怪物详情标记、终局徽标与赛季级区块、目录卡标记）/ 分两档（基准位 + 文字亮端 ≥4.5:1）/ `/voracity` 只染数据面 + 结构强调位（不动 hero 与页面底色）/ 登记为「语境色」类别并补登既有 `--eg-*` / 新增 ADR / 本轮文档 + 实现。
- **交付**：`tokens.css` 领域层新增污染族 `--vor-500: #C40C6A`（基准位，仅非文字）+ `--vor-300: #FC48AC`（文字亮端，进 `check-contrast.mjs` 正文类清单）；`voracity.css` 全页 22 处强调位改走污染族（含新增 secnav 激活项与章节序号覆盖）；`endgame.css` 目录卡「含污染」标记、`endgame-detail.css` 污染徽标与赛季区块回链、`monster-detail.css` 侵蚀标记同批从 `--eg-color` / `--primary` / `--metric-val` 摘下。落盘 [ADR 0027](../adr/0027-机制语境色与贪饕污染色.md) + [ADR 索引](../adr/README.md) + `ui-design.md` §2/§3/§5/§9 + `CONTEXT.md` 两条术语（语境色 / 污染色）。

## 末日幻影详情页：赛季增益分场 + 首领特性（ADR 0029）

- **用户原话**：「末日幻影详情页修正，赛季增益6个，是上半场3个，下半场3个。关卡效果没有展示，例如：坚防守备 首领幻影受到的伤害降低50%。弱点击破后，行动额外延后，受到的伤害提高100%。」（附对照站 `hsr.nanoka.cc/boss/3020`）
- **取证先行**：用 kimi-webbridge 打开对照站读**渲染后文本**取得逐条真值（难度 01/04 的节点 1/2 + 星启模式各带「赛季效果 3 条 + 关卡效果 4 条」），据此确认两件事：① 赛季增益按场次下发（`ChallengeBossGroupExtra.BuffList1/2/3` = 上半场/下半场/星启模式，各 3 条，扁平 6 条口径不变）；② 对照站的「关卡效果」= `MonsterGuideConfig × MonsterGuideTag`（`TagList` → 名称 + 简述 + `ParameterList`），站点完全没有消费这两张表。
- **join 判据（易错点）**：机制按**敌方模板**登记（`MonsterID // 100`），但**配置表的敌方 ID 未必等于战斗敌方**——业火焚心的影将军战斗模板 `2035012`，配置表登记的是蚀心兽 `2033022`（同图标 `Monster_2033020`、同机制组 1012xx），直接按模板 join 会让天狼系赛季下半场整场漏机制。补法是 `MonsterGuideTag.SkillID // 100` **唯一**反查（技能 ID = 模板 ×100 + 技能序号），并加唯一性闸门——技能 ID 会被多个首领共享（`100401410`），不唯一即放弃。21 个已发布赛季 × 上下半场覆盖率全绿（「杰帕德」一类未登记机制的护卫不产出条目，正确）。
- **术语同名不同指（用户当场改判）**：游戏内教程（TextMap `7039255158974959772`）把每期的「末法余烬」称**关卡效果**、把随难度追加的首领机制称**首领特性**（`12677071358133122013` 同义）；对照站把后者也标成「关卡效果」。先按用户原话与对照站口径落地，用户随后裁决「采用官方术语，就叫首领特性吧」→ 区块名、数据字段（`level_effects → boss_traits`）、类型（`MazeLevelEffect → MazeBossTrait`）、渲染函数与 CSS 类（`.nk-egd-effect* → .nk-egd-trait*`）、section id（`effects → traits`）同批改名，`CONTEXT.md` 词条与 ADR 标题一并换；站点内**不再**用「关卡效果」指本词条。楼层内的「可用增益」（末法余烬）仍未改名，留在 ADR 替代方案表里记账。教训：**代码/字段/CSS 名跟着术语走，别只改标题**——否则下一轮读代码的人会以为是两套东西。同批用教程文本校正了 `CONTEXT.md` 的末日幻影词条：两场战斗游戏内文案作「节点一/节点二」，源表 `EventIDList1/2` + `BuffList1/2` 与忘却之庭/虚构叙事同构；`ChallengeBossMazeExtra` 逐项对应节点（与 `tierce.nodes` 同源），不是「首领形态」。
- **坑位（自检截图时发现，属通用教训）**：**新增一层 flex 包装 = 改变了子元素的尺寸解析**。`display:flex; flex-direction:column` 里，子项若带 `margin-left/right:auto` 就**不满足 stretch 条件**，`max-width` 直接退化成 shrink-to-fit——`赛季增益` 卡片瞬间从 952px 变成按内容收缩且**各组宽度不一**（实测 692/684/692 与 839/549/839）。修法是给列表显式 `width:100%`（块级父容器下原本靠 stretch 生效，加 wrapper 后失效）。教训：**加包装层后必须量一次几何（left/width 各分组对比），别只看「有没有内容」**。
- **取证陷阱复现**：kimi-webbridge 的**元素截图在后台标签页全黑**（同页实测 `visibilityState=hidden`、`getAnimations().length=0`、卡片 `opacity=1`），不是页面缺陷；改用 Playwright（前台）元素截图才拿到有效画面。
- **验证**：`pytest tools/converter/tests` **292 passed**（新增 6 条：分场分组 / 模板直连 / 技能反查 / 反查二义与直连优先 / 场次去重 / 赛季级挂载）；`pnpm test` **344 passed**（26 文件，新增 `buffs.test.ts` 6 条）；`pnpm exec playwright test e2e/layout.spec.ts --grep "endgame"` **12 passed**（含新增 `/endgame/boss/3020` 两条：上半场/下半场/星启模式三组各 3 条 + 首领特性 12 条 + 坚防守备渲染 50%/100% + 无横向溢出，桌面与手机断点）；`e2e/accessibility.spec.ts` **7 passed**（含 `/endgame/boss/3021`）；`check-colors` / `check-contrast --strict` 双绿；`pnpm build` exit 0（三守卫 + `vue-tsc -b` + AI 端点守卫 **7/7 PASS**，快照 1200）；转换器重跑**四份产物字节一致**（确定性）；`buff_groups` / `boss_traits` 只出现在 `maze_boss.json`，目录卡与 AI 快照字段零变化。
- **降级/未做**：① **AI 快照本轮不同步**（沿 ADR 0026 取舍：要进 catalog + 生成器 + 守卫三处），记账在 ADR 0029 中性条；② `visual.spec` 未跑（无基线变更需求，AGENTS 禁全量）；③ 未跑全量 `layout.spec`（只跑受影响用例：endgame 组 + a11y）；④ 视觉观感（效果卡左侧模式色竖条与分组胶囊）交用户 RunPreview；⑤ 场次标签用用户口径「上半场/下半场」，与游戏内「节点一/节点二」并存，如需改为官方文案是一处常量 + 一处 e2e 断言。

## 星启模式要不要并进第 4 层 tab → 真问题是「同源两场内容不对等」（ADR 0032）

## 星启头部推荐属性是什么 → 节点 3 补上自己的推荐属性（ADR 0032 修订）
