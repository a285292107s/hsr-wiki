# 0070. 图标工具链：单一映射真源 + 按引用集同步 + 覆盖度门禁

## 1. 背景与问题

[0057](0057-图片资源自持与WebP入库口径.md) 把图标全量入库到 `public/data/assets/icons` 后，工具链一直只有「按分类转码」这一种模式：

```
python tools/ingest-icons.py --category <分类>
```

它的隐含假设是**「导出分类名 = 解包 SpriteOutput 首段目录名」**。2026-11-25 全量核查证明这个假设处处不成立：

| 事实 | 数值 | 口径 |
| --- | --- | --- |
| 解包数据里的 SpriteOutput 引用 | **23,317** 条去重 | 扫 2,317 个 ExcelOutput JSON |
| 实际导出（与引用命中） | **6,445** 条 | 按当时 25 个分类的映射 |
| **引用了但没导出** | **16,872** 条 | 72.4% |
| 解包盘 spriteoutput | 114 个目录 / 50,116 png / 10.8 GB | 目录度量 |
| 站点转换产物实际引用 | **2,287** 张 | 扫 `public/data/**` 4,377 个 JSON |
| 其中没导出（会破图） | **423** 张 | 394 有源可补、27 叶名在别处、2 连源都没有 |

根因不是工具写得差，而是三处结构性错位：

1. **分类名是自造的**（`gridfight-asset`、`monstermiddleicon`、`uiart`），与解包目录没有一一对应，映射只能靠人临时想 → 「归错分类」；
2. `DEFAULT_SRC` 指向 `StarRailTextures/assets/asbres/spriteoutput`，而解包盘后来多了一层 `ui/`，**工具没有任何自检**，直接报「源目录不存在」或静默转错；
3. 唯一能发现缺口的是临时 PowerShell 脚本（不进仓库、不进守卫链），所以 6,296 条漏文件、72 个目录从没导出过，而 `pnpm build` 一直全绿——`check-image-loading.mjs` 只查「代码里怎么写 `<img src>`」，**不查「src 指向的文件在不在」**。

## 2. 决策

### 决策 1：单一映射真源 `config/sprite-map.json`

所有「SpriteOutput 相对路径 → 导出分类 / 本地相对路径」的换算，只写在这一个 JSON 里。**三方共读**：

- `tools/ingest-icons.py`（Python，转码）
- `tools/check-icon-coverage.mjs`（Node，门禁）
- `src/services/cdn/sprite-map.ts`（TS，运行期路径解析）

结构：`routes` 有序路由表（`first` 首段 + 可选 `sub` 子路径 + `local` 归约模式），末尾 `fallback`（当前 = `uiart` 透传）。`local` 模式共 9 种：`leaf` / `leafLower` / `afterFirst` / `afterFirstLower` / `afterSub` / `fullExact` / `lowerDirs` / `element` / `pathicon`。

**路由顺序是语义的一部分**：带 `sub` 的路由必须排在同类 `first` 的无 `sub` 路由之前（`gridfight/equipment` 必须早于 `gridfight` 兜底）。此约束由单测机械校验。

### 决策 2：`ingest-icons.py` 增「按引用集同步」模式

```
python tools/ingest-icons.py --verify                    # 只核对，不转码
python tools/ingest-icons.py --from-refs --dry-run       # 只打印待补清单
python tools/ingest-icons.py --from-refs                 # 补站点实际引用但缺的（默认 scope=site）
python tools/ingest-icons.py --from-refs --scope excel   # 放宽到解包全量引用
```

配套改三处：

- **源根探测式**（治静默失败）：`HSR_TEXTURES_ROOT` 环境变量 → 桌面默认路径，按 `sourceRootCandidates` 依次探测，全不中则打印所有尝试路径后退出；
- **不重复落盘**：若某文件「同叶名已在别的分类导出」则跳过（`uiart` 兜底最容易重复）；
- **CDN 豁免**：`cdnBacked` 分类（`uiart` / `rank` / `element` / `pathicon`）计入「设计上走 CDN」，不算缺。
- **路由本体必须一并回传**：`route_ref()` 返回 `(category, local_rel, route)` 三元组。同一分类可被多条 `sub` 路由产出（`gridfight-icon` ← `traiticon/icon` 与 `traiticon/miniicon`），只回传分类会让反推源路径时永远拿第一条路由 → 误报「无源」。这是本批实修的一个真实 bug（60 张 `*S` 迷你图标曾因此误判）。

### 决策 3：覆盖度门禁用**基线制**，进 `pnpm build`

新增 `tools/check-icon-coverage.mjs`，作为第 9 个守卫接入 `check-guards.mjs --strict`。

之所以是基线制而非「现算 missing 必须为 0」：**CI 上没有本机解包盘**，无法判断「缺的这个文件到底有没有源图」。故判据改为：

> 缺口 = 引用了、导出目录没有、且不属豁免（`cdnBacked` / `ignoreLocal` / `knownDeadRefs` / 同叶名可借）。
> 全部已知缺口记在 `config/icon-coverage-baseline.json`；**新增**缺口 → 构建失败；缺口减少 → 提示刷新基线。
基线当前 **2 条**，均为 `gridfight-icon/traiticon/miniicon/{101102S,200802S}`。
**2026-11-25 复核更正**：这两条**不是「上游没有」**——`index/game.map`（游戏 bundle 原始容器）里**有**它们，只是**本地导出没做**（导出不完整，见 [../audit/TurnBasedGameData引用缺口归因.md](../audit/TurnBasedGameData引用缺口归因.md)）。所以它们是「可补」而非「永久无源」：`--from-refs` 在源盘补齐后会自动消失。

> 口径修正（2026-11-25 第二稿）：首版曾记「62 条全为无源」，后查实其中 60 条是工具 bug——
> `route_ref` 只回传分类、plan 阶段用 `next()` 取「该分类的第一条路由」反推源路径，
> 于是 `traiticon/miniicon` 的图被拿 `traiticon/icon` 去拼，永远找不到。修法是路由命中时
> 一并回传 route 本体（见决策 2）。修后 60 张已补，剩余 2 张是「game.map 有、本地导出缺失」——工具在无解包盘的 CI 上归为「上游也无源」，但实际可补（见决策 3 与归因文档）。

### 决策 4：TS 侧读同一份映射（**不改目录布局**）

新增 `src/services/cdn/sprite-map.ts` 暴露 `spriteLocalRel(path)` / `isCdnBacked()` / `SPRITE_MAP_CATEGORIES`。

**本决策刻意不动** `public/data/assets/icons` 的目录布局，也不重写 `src/lib/icons.ts` 里现有的 6 处字符串改写。原因：全量搬迁 4,214 个文件是高风险动作（`git mv` + 二级镜像仓库同步 + 6 个解析函数同改 + e2e 全跑），收益只是「目录形态更整齐」，与「消缺口」是两个独立目标。本 ADR 只解决后者。

映射真源先落成、并由单测锁住三点：① 每条路由的语义；② 与 `CDN_CATEGORIES` 分类集合一致；③ 路由顺序约束。待到真要搬目录时，`sprite-map.json` 已是现成的迁移清单。

## 3. 实测约束

| 事实 | 数值 |
| --- | --- |
| 修复后站点侧 missing | **0**（共补 **129 张**：首批 69 = `gridfight-affix` 33 + `skillicons` 35 + `bufficon` 1；后修路由 bug 又补 60 = `gridfight-icon` 的 `*S` 迷你图标） |
| 修复后站点侧 unsourced | **2**（`gridfight-icon/traiticon/miniicon/{101102S,200802S}`；`game.map` 里有、**本地导出缺失**，补齐后即消失） |
| 站点侧 cdnBacked | 763（`uiart` 透传类，`endgame` 主题图/属性图标等） |
| 解包侧（scope=excel）缺口 | 4,167（其中「有源可补」2,949、`tutorialpic` 1,510 / `itemfigures` 905 / `bufficon` 783 / `avatarroundicon` 467 等，均为「Wiki 不展示的表内图」，**不补**） |
| 解包侧 cdnBacked | 12,356 |
| 转码参数 | 仍是 `quality=82` + `method=6`（ADR 0057 决策 2/4 不变） |

**已确认的「不该归一」**（写进 map 的 `ignoreLocal` / `ignoreReason`，防止后人再踩）：

- `mostericon` / `monsterroundicon` 三个目录**同名不同图**（`Monster_1002011.png`：16,494 B vs 62,345 B），归一到 `monstermiddleicon` 是**有损**的，必须保留官方原目录选择；
- `gridfight-equipment` 的文件名**必须保留大小写**（`GridFight_RoleBox1.webp`），`gridfight-asset` 的目录段**必须全小写**（`augmentbig/100101.webp`）—— 两种相反口径，只能逐分类声明；
- `skillicons` / `bufficon` / `tutorialpic` 在导出侧与解包侧的层级**不一致**（压平 vs 多层、多一层 vs 少一层），`fullExact` 与 `leaf` 必须分开；
- `rank` 唯一源是 nanoka 的 `ui/ui3d/rank/_dependencies/textures`，本机解包盘**无 `ui3d` 树**，无法镜像；
- `trace` 的 `IconCriticalDamage`、`relicfigures` 的 4 个通用部位图标（`IconRelicBody/Foot/Neck/Goods`）解包盘全树无源。

## 4. 替代方案（被否）

| 被否方案 | 否决理由 |
| --- | --- |
| 把 16,872 张全量补导出 | `Quest`(4,156)、`Rogue`(1,938)、`Emoji`(493) 等是 Wiki 不展示的表内图，只把 `dist` 再撑大几百 MB，换 0 收益 |
| 门禁判据用「missing 必须为 0」 | CI 无解包盘 ⇒ 无法区分「有源可补」与「上游也无源」，会把那 2 条永久无源项当失败 |
| 为过门禁放宽 `localFiles` 白名单 | `tutorialpic` 只收 3 张、`uiart` 只收 25 张是 0057 决策 3 ① 的**刻意取舍**（全量 960 MB），不是缺陷 |
| 把 `sync-icons` 自动跑进 `build` | 转码分钟级且需人眼核对（0057 决策 5）；`build` 只跑只读的覆盖度检查（秒级） |
| 本批就搬 4,214 个文件到镜像目录 | 风险高、收益低，且与「消缺口」目标正交；见决策 4 |
| 让 `check-icon-coverage` 直接读 `CDN_CATEGORIES` 当分类清单 | `uiart` 走独立解析器不在 `CDN_CATEGORIES`；两套清单必须由单测对齐而非合并 |

## 5. 后果

- **缺口可视化**：`node tools/check-icon-coverage.mjs` 随时给出「当前缺口 / 有源可补 / 上游也无源 / cdnBacked / 基线内已知 / 新增 / 已消失」，`--scope excel` 看全量；
- **防回退**：新增 `<数据里写了个没人导出的图标路径>` 会让 `pnpm build` 失败；
- **补图一条命令**：`python tools/ingest-icons.py --from-refs`，不再需要手工 `git mv` 或猜分类；
- **改映射只改一处**：`config/sprite-map.json`；Python / Node / TS 三端由单测锁住一致性；
- **仍未解决**：`src/lib/icons.ts` 里的 6 处字符串改写与 `sprite-map.json` 是**并行**的两套逻辑（虽然语义相同且有单测对拍），真正去重需要搬目录——留作后续独立 ADR；
- **基线需人工刷新**：补完一批图后跑 `--write-baseline`，否则「已消失」的缺口会一直提示。

## 6. 操作契约

**日常补图**（站点报破图 / 新版本上线后）：

```bash
node tools/check-icon-coverage.mjs                 # 1. 看缺什么
python tools/ingest-icons.py --from-refs --dry-run  # 2. 看补什么
python tools/ingest-icons.py --from-refs --sheet temp/sheet-icons.jpg  # 3. 补 + 出深底联系表人眼核对
node tools/check-icon-coverage.mjs --write-baseline # 4. 刷新基线
```

**新增分类**：只改 `config/sprite-map.json` 的 `categories` + `routes`，然后跑单测（会断言与 `CDN_CATEGORIES` 对齐、路由引用的分类均已登记）。若该分类要参与本地优先加载，还需在 `src/services/cdn/base.ts` 的 `CDN_CATEGORIES` 登记。

**判定「是真缺还是设计如此」**：先看 `sprite-map.json` 里该分类有没有 `cdnBacked` / `ignoreLocal` / `ignoreReason`，再看 `knownDeadRefs`；都没有才是真缺。
