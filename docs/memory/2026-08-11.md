## safe-delete shim 适配（WorkBuddy 环境，重要）
- `NODE_OPTIONS=--require=genie-safe-delete.cjs`（有 CODEBUDDY_SESSION_ID 时注入）劫持 fs rm → 移入回收站；**OS 临时目录（os.tmpdir() 等）命中 `shouldUseNativeDelete` 豁免 → 原生直删**；非豁免路径 trash 失败会 fail-closed 抛错（"Some operations were aborted"，Windows 文件占用等）。
- 适配：`playwright.config.ts` 的 `outputDir` 改为 `path.join(os.tmpdir(), 'hsr-wiki-e2e-results')` → 命中豁免通道，e2e 不再因清理 test-results 崩溃。pnpm 的 `_tmp_*` 不在豁免（Git Bash 下 pnpm add 偶发失败，PowerShell 可绕）。

## 破图断言方案演进（visual.spec.ts）
- 迭代：渲染态收集 → 重载重试 → **HTTP 探测（最终）**：页面 img 加载失败的 URL 用 `page.request.head`（6 并发）探测，非 2xx 才算真死链。
- 根因链（2026-08-11 实证）：character 页真实渲染 301 张 CDN 图 → jsDelivr burst 限流 → 部分 img 立即失败且**浏览器不自动重试**（等 40s 仍 80 张）→ 单独 new Image()/curl 同 URL 成功 → 渲染态判断结构性不可行，必须独立连接 HTTP 探测。
- 代理验证：本机 Clash 7890（系统代理 + 环境变量都在）；Playwright headless **默认不继承代理**（27% 图失败）；显式配 proxy（bypass localhost）后 broken 仍是 80 → **代理不改善 burst 限流**，非代理问题。
- 真死链确认：avatarshopicon 部分 ID（1009/1013-1016 等）GitHub 源真 404，converter 图标路径与仓库文件不匹配——待数据修复决策。
