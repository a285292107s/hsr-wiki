# 转换器字段映射（数据源表 → 输出 JSON）

> 单一事实源：各 `tools/converter/converters/*.py` 的表→字段→输出映射。**代码里只留 ≤12 行指针 + 禁止/必须类硬约束**，完整映射以本文件为准（避免改映射时三处不同步）。
> 数据边界：`vendor/TurnBasedGameData` 禁止直读（`AGENTS.md` 数据边界）；探索走 `query.py` / `DATA_CATALOG.md`。

## release_version — 版本上新判据（characters.py / light_cones.py / relics.py）
- 字段：索引条目上的 `release_version`（形如 `"4.6"`）。前端首页「版本上新」的**唯一**判据 = 该值恰等于 `public/data/cn/version.json` 的 `version_label`。同一字段两种来源，前端不区分（ADR 0019 决策 3/4）。
- `characters.py` / `light_cones.py`（角色 / 光锥）= **与上一版已提交输出的 id 差集推导**，纯函数在 `tools/converter/release_version.py`：基线 = 覆盖输出前读到的 `public/data/cn/characters.json` / `public/data/cn/light_cones.json`；基线已有该 id → 沿用其值（基线缺 `release_version` 字段 → 空串）；当前有而基线没有的 id → 写**当前版本号**；基线文件不存在（首次转换 / 本地首跑）→ 全部空串；条目一旦打标即跨版本保留（同版本重复运行幂等，不重算）。
- 当前版本号来源：`tools/converter/converters/version.py` 的 `read_source_version_label()`（子模块 HEAD 提交标题 → `version_label`）。**禁止**复制一份提交标题解析、**禁止**读上一轮 `version.json`（比当前数据落后一版）。
- `relics.py` = 源数据权威 `RelicSetConfig.ReleaseVersion`（遗器不走差集，不依赖基线完整性）。
- 已知失真（ADR 0019 后果）：CI 中断跨过多个版本时，多版新增会一起算作「本版本」；上一版快照里已预载的条目（如光锥 23063）会被算在更早的版本上，从而不出现在本版本上新里。
- 历史引导（一次性）：`tools/converter/backfill_release_versions.py` 按 git 历史版本快照的「首次出现版本」回填；**需要完整 git 历史**，CI `fetch-depth: 1` 下不可用；最早可追溯快照（4.4.0）内已存在的条目留空串（不猜）；默认只补空串，不覆盖机制启用后由 convert 打的标。

## is_season_new — 货币战争「本赛季新增」判据（currency.py / currency_catalog.py）
- 字段：`currency/role.json` 条目与 `currency/traits.json` 条目的布尔 `is_season_new`。CW 枢纽页「本赛季新增」只读该字段过滤（ADR 0020 决策 3/4）；与 `release_version`（常规模式首页的版本增量）**口径互斥，禁止混用**。
- 判据 = **赛季代际差集**：当前代名册 − 上一代名册。纯函数在 `tools/converter/season_delta.py`（`prev_generation` / `mark_season_new` / `apply_season_new`）。
  - 角色：源 `GridFightRoleBasicInfoOld`（198 行，`ExistSeason` 101/102/103 标代）分代；当前代名册 = `GridFightRoleBasicInfo` 中 `IsInBook=true` 的角色（与输出条目同口径）。两表 id 体系不同，**按 `AvatarID` 比**。
  - 羁绊：源 `GridFightTraitLayerOld`（378 行，`TraitID`）分代；当前代名册 = `GridFightTraitBasicInfo` 全体（即 `traits.json` 的条目）。
- 「上一代」= 同一张 `*Old` 表内 `ExistSeason` 的**最大值**（当前 103）。禁止取最小值 / 首行 / 多代并集（并集会把更早几代的新增也算成本代新增）。
- 降级：`*Old` 表缺失 / 为空 / 有效代际 < 2 → **全部 false + `logger.warning`**，禁止退化为全 true；旧代有、当前代无的 id（羁绊会轮换出）被忽略，不影响其余标记（差集是单向的）。
- 覆盖域仅**角色 + 羁绊**；装备 / 环境 / 策略既无 `*Old` 代际表、版本差集实测为 0，**禁止**为它们新造判据（ADR 0020 决策 3）。
- 能力边界（ADR 0020 后果）：**代际内补充不可分辨**——同代内先后下发的批次（如 4.3 的 Archer 并入代 103）无法单列；跨代小补丁（4.6 的双倍晋升点 / 吞噬词缀）在 CW 五个图鉴域的表中毫无痕迹。本机制只识别到**代际粒度**。
- 增量依赖：`incremental.MODULE_SOURCES` 的 `currency` / `currency_catalog` 必须声明对应的 `*Old` 表，否则名册换代时模块不重跑、标记静默过期。

## 装备图鉴 · 名称解析失败过滤（currency_catalog.py `_convert_equipment`）
- `GridFightItems` 中 `ItemName` 解析为空的条目（TextMap 缺该 hash；如 `350108`：name/desc/category 全空、图标沿用旧 id）**整条过滤**，禁止输出无名占位卡（ADR 0020 决策 9）；过滤名单经 `logger.warning` 打印，禁止静默丢弃。

## endgame.py — 终局内容（忘却之庭 / 虚构叙事 / 末日幻影 / 异相仲裁）
- 源：`vendor/TurnBasedGameData`（与 CDN 同源，本地转换）。分组：`ChallengeMazeConfig`(GroupID 100+)、`ChallengeStoryMazeConfig`(2001+)、`ChallengeBossMazeConfig`(3001+)、`ChallengePeakConfig`(ID 101+)。
- 排期（ADR 0038）：按三张分组表 `ChallengeGroupConfig` / `ChallengeStoryGroupConfig` / `ChallengeBossGroupConfig` 的 **`ScheduleDataID` 指针**直查排期记录，旧「`ScheduleID - 200000` = 赛季 GroupID」编号推断废弃——迷宫 1034/1035 的指针 `291015/291016` 已脱离该约定。忘却之庭记录在 `ScheduleDataChallengeMaze` 缺失时**回退 `ScheduleDataGlobal`**（先登记者胜）；虚构/末日只查各自 `ScheduleDataChallengeStory` / `ScheduleDataChallengeBoss`。**单边日期原样保留**（1034 仅 BeginTime、1035 仅 EndTime，两期交替分界不在静态数据里，禁止用邻接赛季补全）。占位过滤：任一已知端点年份 ≥2030 丢弃；End 早于公测 2023-04-26 为 beta 测试期（打 `test` 标、不落日期）；仅 Begin 且早于公测丢弃；Begin<公测但 End≥公测的跨公测排期保留（组 117 形态）。异相仲裁无排期段，`live_*` 留空。
- 赛季统计：组内全层聚合（最大层/阶段数/回合上限/弱点属性去重 + 逐层弱点 floor_damage）。
- buffs：忘却之庭取 `MazeBuffID`(ChallengeGroupConfig)；虚构/末日取 `BuffList`(ChallengeStoryGroupExtra / ChallengeBossGroupExtra 前两阶段)；虚构战意(Fever)另取 `SubMazeBuffList`。
- 赛季增益分场（ADR 0029，仅末日幻影）：`ChallengeBossGroupExtra` 的 `BuffList1/2/3` 按场次（`stage1`=上半场 / `stage2`=下半场 / `tierce`=星启模式）落 `buff_groups`；**扁平 `buffs` 口径不变**（仍是 `BuffList1+2` 的并集 6 条，目录卡与 AI 快照沿用）。
- 首领机制（ADR 0044 修订 0029，仅末日幻影；游戏内文案「首领特性」，对照站称「关卡效果」）：`MonsterGuideConfig`(MonsterID→TagList/PhaseList) × `MonsterGuideTag`(TagName/TagBriefDescription/ParameterList) × `MonsterGuidePhase`(PhaseName/PhaseDescription/PhaseAnswer/SkillList) × `MonsterGuideSkill`(SkillName/SkillTextIDList) × `MonsterGuideSkillText`(SkillDescription) 聚合为 `{敌方模板: {"traits": [...], "phases": [...]}}`，赛季级落 **`boss_guides`（模板键）**；命中登记的**波次敌方**条目写 `boss_guide`（模板 ID 字符串，**每一层都写**，正文只一份），**召唤物不写**（44 处命中全部与同场首领同组，挂了会把同一组机制在一场里渲染多份）。**判据是敌方模板**（`MonsterID // 100`；各难度实例的 `TagList` 与 `PhaseList` 逐字相同，实测 21/21），配置表缺该模板时用 `Tag.SkillID // 100` **唯一**反查补齐——**禁止**按实例 ID 或 `ChallengeBossMazeExtra` 的 `MonsterID1/2/3` 序号取值：影将军战斗模板 `2035012` 在配置表里登记为蚀心兽 `2033022`，按实例/序号会整场漏判或换错敌方。未登记机制的敌方（普通精英/护卫）不产出条目。**不消费** `DifficultyGuideList` / `TextGuideList`（实测 `DifficultyGuideList[0]` 与「坚防守备」的 Tag 描述去标签后逐字相同，且两者逐难度不同）；阶段三段文本与招式文本实测无 `#N[i]` 占位符、每招式恰 1 条文本，故不落 `param_list`。
- 层级敌方（末日幻影，ADR 0031）：只取 `stage1/stage2`（`EventIDList1/2` → `StageConfig` 波次）；`ChallengeBossMazeExtra` **不再读取**（该表逐项=节点，末层第 3 项就是星启附加关、第 2 项为指南别名），`floor_details[*].phases` 字段与 `incremental.py` 里的该表登记一并退场。
- monsters：各层 `StageConfig` 波次 `EventIDList1/2 → MonsterList` → `MonsterTemplateConfig`（名称/头像 icon `ManikinImagePath` basename 经 monstermiddleicon CDN）；韧性 `StanceWeakList` / 抗性 `DamageTypeResistance` / 图鉴 `MonsterIntroduction` / 分类 `Rank` → 普通/精英/准首领/首领；阵营 `MonsterCampID`；技能 `SkillList`。**效果抵抗**（ADR 0044）：`MonsterConfig.DebuffResist`（Key=状态类别，如 `STAT_CTRL_Frozen`）× `MonsterStatusResistanceType`（Type→`IconImmune*.png` basename，前端经本地分类 `statusimmune` 加载）→ `debuff_resist[{key, value, icon}]`；**上游只有图标没有文字名**，无图标/未登记的 key 跳过，**只随 `full=True` 详情卡形态输出**（`_lean_monster` 与轻形态剥掉）。**注意**：关卡表 `NpcMonsterIDList` 仅为代表怪（61 个，缺约 2/3），波次才是完整配置（176 个）。
- 逐层 `floor_details`：层序号/官方层名/回合上限/上下半场属性与敌方/层级增益/挑战目标；永屹之城遗秘(组100)无 Floor 字段，按 ID 升序取序号（`floors` 键仍为最大层数统计，勿混）。
- 挑战目标 `targets`：`ChallengeTargetID` → `ChallengeTargetConfig`(clean_text) + `ChallengeTargetParam1`。
- 异相仲裁 `peak`：每期 3「骑士」试炼 + 1「王棋」；`ChallengePeakGroupConfig`(PreLevelIDList/BossLevelID) + `ChallengePeakConfig` + `ChallengePeakBossConfig`(HardTitle 如「将杀王棋•绝境」/HardEventIDList/HardTarget/HardTagList)。**单关敌方（含绝境变体）走 `full=True` 全字段**（`intro` 图鉴介绍 + `skills` 技能名/标签），与末日幻影楼层同口径——详情页单关面板以敌方详情卡渲染（`StageContent`，ADR 0043 补记）；**期级合并列表 `monsters` 仍是轻形态**（`_lean_monster` 去 `wave`/`intro`/`skills`），它只服务目录卡代表阵容与 AI 快照，与另外三种模式的期级列表同口径。
- 星启 `tierce`：三表 `ChallengeMazeTierce` / `ChallengeStoryMazeTierce` / `ChallengeBossMazeTierce`；关联 `DLCKKJFMJOB` = 常规最后一关 ID；目标表按模式分走；满分档 `GNGENMHNLAH`(虚构 99000) 并入 targets 末；通关奖励 `EGEEJLHBALB`。**季节级 `damage_types`（`LOJCIDLKPKG`）与 `level`（`HFIAAGAKFMD` 的 `StageConfig.Level`）的所指是附加关那一场**（星启表字段只描述这一场，不是三节点汇总），前端已不再在面板级展示这两项（只随节点 3 的场次卡显示）——`damage_types` 仍被 AI 快照的「星启模式 · 弱点」遍历消费。
- 星启节点（ADR 0032，三模式同构）：3 节点各输出**完整场次内容**——节点 1/2 取 `DLCKKJFMJOB` 所指记录（实测即该赛季最大层记录）的 `DamageType1/2` + `EventIDList1/2` 波次 + `StageConfig.Level` + `ChallengeCountDown` + `MazeBuffID`；节点 3 取 `HFIAAGAKFMD` 的波次与 `StageConfig.Level` + Tierce 表的 `GNOOAGPBNLD`（回合，仅忘却之庭有）+ **推荐属性 `LOJCIDLKPKG`**（与赛季级 `damage_types` 同值：星启表只有这一处推荐属性口径，**禁止**从附加关敌方的韧性弱点推导——3019 的附加关关卡内登记的是无弱点机制本体「心蕉如火的猴把戏」）。另落 `origin`（`stage1`/`stage2`/`tierce`）作为**场次键**：前端按它取赛季级 `buff_groups`（赛季增益），不复制进节点（该项仅末日幻影产出，其余模式缺省即不渲染）；**首领机制不走场次键**（按敌方模板键的 `boss_guides` + 敌方 `boss_guide` 指针，见上一条与 ADR 0044）。**末法余烬（`buff`）分两处来源**：星启表 14 个字段里没有自己的 buff 字段——节点 1/2 取最高难度关记录的 `MazeBuffID`，节点 3 取附加关关卡自身的 `StageConfig.StageConfigData._BindingMazeBuff`（由 `_stage_binding_buff` 提取，`_load_stage_monsters_by_id` 随 `level`/`waves` 一起带出）；**附加关未登记该绑定时回退同赛季末层记录的 `MazeBuffID`**（ADR 0032 2026-10-03 修订：末日幻影 5 季实测两处逐条相等 = 3018/3021/3022 `3110017`、3019 `3110006`、3020 `3110018`，节点 3 命中绑定分支；忘却之庭 4 季的附加关**无该绑定**（`StageConfigData` 只有 `_Wave`/`_IsEliteBattle`/`_CreateBattleEvent`），靠回退补上「记忆紊流」3030146–3030149，否则同一 tab 内节点 1/2 有、节点 3 无；虚构叙事 4 季回退值 `3031220` 未在 `MazeBuff` 注册 → 仍不落字段）。
- 混淆字段名（解包变量）：`PHFMCACHFIJ`=星启关 ID / `LOJCIDLKPKG`=弱点 / `GNOOAGPBNLD`=回合（**仅 `ChallengeMazeTierce` 有**，末日幻影/虚构叙事的 Tierce 表无该字段 → `countdown` 为 0 属正常，勿当成丢字段）/ `OGEOMCGNNMP`=目标 ID 组 / `JEBMBCLBIOI`=敌方 ID。`PHOIICMCGIH`（三张 Tierce 表共有，5–11 的整数）**语义未解**：与波数/怪物数/回合/目标数/满分档均对不上，对照站亦不呈现 → 不消费、不硬列。**另有 5 个字段未消费**（语义未验证，勿凭名字猜）：`EMNJGCPDIFF`（逐条变化的 30xxxxx 整数，13 条两两不同，`StageConfig` 无此 ID）、`IMCMJHAMMKK`（同表常量：maze 101913 / story 102113 / boss 101713）、`LCHKKJDBLGM`（13 条全为空数组）、`MLMEGBLDFKE`（13 条均为 `[200001]`）、`OGALGHMIIAH`（与 `EGEEJLHBALB` **同序同 ItemID、只是不带 `ItemNum`** → 疑似奖励预览清单；奖励口径仍以 `EGEEJLHBALB` 为准）。
- 污染等级（`StageInvasionConfig`，ADR 0026）：判据是 **`StageID ∈ EventIDList1/2`（异相仲裁为 `EventIDList`，星启为 `HFIAAGAKFMD`）**，命中的半场/单关/星启节点输出 `invasion = {level(=InvasionID), stage_id, monsters[]}`；**禁止改用怪物 ID 匹配**——末日幻影楼层只登记首领，被污染者是首领的召唤物（由机制额外加入），按怪物 join 会整层漏判。`monsters` 只收录 `monster_common` 已注册者（未注册的实例 ID 无名称/图标，跳过而不落空对象）。赛季级 `pollution = {count, levels}` 由 `_apply_pollution` 从条目自身节点算出并按 `stage_id` 去重（星启节点 1/2 与常规末层同关卡，不得按节点数计数）；`endgame_catalog` 原样透传该字段，供目录卡「贪饕污染」标记。**未发布赛季（`GroupName` 为空，如 boss 3022）的全量产物同样带污染字段**：可见性过滤由目录页（`!info.zh → 跳过`）与路由各自承担，与产物是否携带该赛季数据无关；只有 `voracity` 的 `scopes` 需要过滤（它会变成可点击链接）。
- 召唤物（ADR 0036，2026-10-02 修订为**按召唤者归属**）：源 `MonsterConfig.SummonIDList`（**实例怪物 ID** 列表）。`_load_summon_index` 建 `{召唤者实例: [被召唤实例]}` 索引，`_stage_waves_monsters` 在生成每个敌方条目时调用 `_monster_summons`，把该实例自己的召唤物挂到**该敌方条目**的 `summons[]` 上 → 逐条轻形态 `{id, tpl?, name, icon, polluted?}`（`_summon_out`；未注册实例跳过，`polluted` = 该实例命中同场次 `invasion.monsters` 时的 `InvasionID`）。落点＝层上下半场、星启节点、异相仲裁单关与其 `hard` 绝境变体的敌方条目；无召唤物不落字段，**场次级 `summons[]` 不再产出**。同一召唤物被同场多个敌方列出时在各条目里各出现一次（各自都具备该召唤能力，非歧义）。**禁**用模板级并集或全库反查召唤者（同模板多实例共用一张召唤表，570 个被召唤实例里 200 个全库有多个候选召唤者）；`MonsterConfig.json` 早已在 endgame 模块增量源表内，无需新增登记。
- 输出：`public/data/cn/endgame*.json`。

## achievements.py — 成就

## monster_common.py — 敌方信息聚合（endgame 赛季敌方 / monster_detail 共用）
- 源：`MonsterTemplateConfig`(名/头像/分类 Rank/阵营/韧性 StanceBase/基础属性) / `MonsterConfig`(弱点 StanceWeakList/抗性 DamageTypeResistance/图鉴 MonsterIntroduction/技能 SkillList/**维度修饰比 Mod*Ratoio/难度组 HardLevelGroup/精英组 EliteGroup**) / `MonsterCamp` / `MonsterSkillConfig`(名/标签/类型/伤害类型/攻击类型/描述含 #N[i] 富文本/参数列表) / `HardLevelGroup`(等级曲线，详见下方战斗数值口径) / `EliteGroup`(精英组倍率，详见下方战斗数值口径)。
- 输出 `{模板ID: {name, icon, figure, weak, resist, rank, camp, intro, skills, stance, stats, stat_ratio, level_group, elite_group, debuff_resist}}`（`stance_modify` / `speed_modify` **非空才落键**）：`icon`=ManikinImagePath 末段(前端 monstermiddleicon) / `figure`=ImagePath 末段(前端 monsterfigure) / `skills` 全量(endgame 仅取名称+标签)。**实例别名** `MonsterConfig.MonsterID`(如 200401009) ≠ 模板 ID 时指向同模板，使波次引用直接命中。
- **场景修正值（`{Stance,Speed}ModifyValue`，ADR 0045）**：实测 472 / 369 个实例非空（值如 +30 / −44；`*ModifyRatio` 全 2722 条**恒为 1**），实例**以自己的记录为准且不得继承模板的**（模板有值而实例无值时继承会凭空多出一个修正）。口径：`值 = 基准 × 维度修饰比 × 等级曲线 + 修正值`（**加在曲线之后、不再被缩放**），韧性不入曲线链故为 `基准 + 修正值`。落点分工：详情页原值进 payload、由前端按等级滑条实时合成；`endgame._monster_out` **在转换期并入** stance/speed 并跳过原始键（敌方卡无等级语境）；`_lean_monster` 无需再剥；`voracity` 只用聚合表作键集，不受影响。
- **战斗数值口径（[ADR 0040](../../docs/adr/0040-怪物详情页战斗数值口径.md) + [ADR 0045](../../docs/adr/0045-怪物数值合成链补上实例修正值与默认等级.md) + [ADR 0049](../../docs/adr/0049-怪物数值合成链补上怪物侧精英组倍率.md)）**：`stats` 是**模板基准值**（无想面具线型基数），不是任何等级的战斗值。前端合成：`战斗值(等级) = stats × stat_ratio × elite_ratio × level_curve[level_group][等级] + 修正值`；曲线共享单文件 `monster-level-curve.json`（{难度组 → 等级 → {hp,atk,def,speed}}）与精英组倍率共享单文件 `monster-elite-group.json`（{精英组 → {hp,atk,def,speed,stance}}，**全量 1,423 组**——关卡侧指派的组不被怪物配置引用，均由 `monster_detail` 落盘），详情 payload 只带 `stat_ratio`（**实例别名用它自己的 config 记录**——同模板不同档正靠这几项区分，实测 1002011 hpR=1 / 100201101 hpR=0.266667、1002050 精英组 1 / 100205006 精英组 2）、`level_group`、`elite_group`（缺省 1）与两个修正值。缺位静默中性 1；难度组缺位的怪物前端回退基准值展示；**默认等级 = 该难度组曲线的最高档**（实测 2722/2722 个怪都在组 1、上限 100）；精英组 ≠1 的仅 27/2722 条（目录常规模板 5 个，组 2 = HP×1.7/ATK×0.8）。关卡侧精英组指派已随 [ADR 0050](../../docs/adr/0050-出没样本带关卡语境与实战面板.md) 落地（出没样本带 `{level, level_group, elite_group}`、前端 Π 叠乘合成，见 monster_extra 段）。`endgame` 轻形态 **跳过** `stat_ratio`/`level_group`/`elite_group`（终局敌方卡不合成战斗值），但修正值已并入 stance/speed。

  - `invasion.stages[*].scopes` = 该污染关卡所属的**终局赛季与位置**（ADR 0026），由本模块自读四张关卡表 + 四张分组表算出，**不读 `endgame` 产物**（避免隐式模块顺序，单跑 `--only voracity` 不会读到旧产物）：层级表按 `EventIDList1/2` → `{mode, season_id, season_name, half: stage1/stage2, floor, title}`；星启附加关按 `HFIAAGAKFMD`（赛季由 `DLCKKJFMJOB` 反查）→ `half: tierce`；异相仲裁按 `EventIDList` → `{half: level, title}`（赛季 = 期 GroupID，由 `ChallengePeakGroupConfig` 的 `PreLevelIDList`/`BossLevelID` 反查）。同一关卡可属多赛季（420533/420534 同属 3021 与 3022），故 `scopes` 为**列表**；`season_name` 缺省的未发布赛季**不输出**该作用域（与目录页 `!info.zh → 跳过` 同判据，避免站内死链）。
- 连带输出：`monsters/{id}.json` 可选块 `invaded`（`{invasion_ids, stages}`，按**模板归属**写入——同模板的实例别名页同值），供敌人详情的「受『贪饕』侵蚀」标记与 `/voracity` 回链；`monster_detail` 的 `MODULE_SOURCES` 因此新增 `StageInvasionConfig.json`。

## light_cone_detail.py — 适配角色反向索引（`recommend_chars`）
- 源：`AvatarEquipRecommend.json` + `AvatarEquipRecommendLD.json`（`{AvatarID, EquipmentList}`），与 `character_detail.py` 的 `lightcones` **同一张表**，本模块只做**反向**读取。
- 输出 `light_cones/{id}.json.recommend_chars: [{id, rank}]`：`rank` = 该光锥在该角色推荐列表中的**顺位**（1 起，与角色页 `REC.` 序号同源）；列表按 `(rank, id)` 排序保证产物稳定可 diff；同一 `AvatarID` 在两个文件中重复登记时以 **LD 后写为准**（与 `character_detail.equip_by_id` 的字典覆盖同序）；无推荐记录输出 `[]`。
- **两个模块各读一次同一源表**（不互读产物，避免 `--only` 单跑时的隐式顺序依赖）：正反两面若口径分叉，角色页「推荐光锥」与光锥页「适配角色」会互相矛盾——改一侧必须同步另一侧。
- 消费方：光锥详情页「适配角色」区块（名字由前端从 `characters.json` 反解）与 AI 快照同名区块（`tools/gen-ai-endpoints.mjs` 的 `lightconePages`，用 `linkList` 默认 `entry=false`）。

## character_detail.py — 角色拉丁转写名（`name_en`，ADR 0039）
- 源：`AvatarConfig.json` + `AvatarConfigLD.json` 的 `AvatarName`（TextMap Hash 引用）→ **TextMapEN** 直查（`textmap.resolve_text_en`）。同一字段的中文侧走 `TextMapCHS` + `clean_text`（`{NICKNAME}`→开拓者），**两侧共用同一 Hash，但清洗规则不可共用**——EN 侧不做字面量 xxhash 回退、不做中文标签清洗，否则译名会被 `{NICKNAME}`→「开拓者」污染。
- 输出：`characters/{id}.json.name_en`。**占位符判据**：解析值以 `{` 开头（开拓者 10 个形态 8001–8010 的 `{NICKNAME}`，玩家命名）→ 输出**空串**；消费方按缺字段处理（不渲染），**禁止**回退成中文或拼造译名。
- 加载与增量：TextMapEN 55.9MB，`ensure_textmap_en()` 按需加载（不随 `load_textmap()` 常驻）；该文本表已登记进 `incremental.MODULE_SOURCES.character_detail`，否则英文表更新时模块不重跑、字段静默过期。
- 实测覆盖：`AvatarConfig` 94 + `AvatarConfigLD` 4 已实装角色 EN 全量命中，仅上述 10 个占位形态为空。
- 消费方：角色详情页 hero 名称族的拉丁注音（`CharHero.vue`）；列表端点 `characters.json` 本轮不写该字段。

## endgame_guide.py — 终局玩法说明（IntroData → 玩法页规则正文）

| 源表 | 读取字段 | 输出 |
| --- | --- | --- |
| `IntroData.json` | `Desc`（按 `◆…◆` 分节）、`ID` | `modes[key].sections[]`（`title` = 分节标题、`text` = 该节正文**逐字**） |
| `ChallengeGroupConfig.json` | `MazeBuffID`（单值，非空计 1） | `modes.maze.system.count`（众数） |
| `ChallengeStoryGroupExtra.json` | `BuffList`（3 条） | `modes.story.system.count` |
| `ChallengeBossGroupExtra.json` | `BuffList1`（3 条） | `modes.boss.system.count` |
| `ChallengePeakBossConfig.json` | `BuffList`（3 条） | `modes.peak.system.count` |

输出 `public/data/cn/endgame_guide.json`：

```
{ "modes": { "<maze|story|boss|peak>": {
    "key", "label", "en", "intro_id", "sections": [{ "title", "text" }],
    "system"?: { "name", "count", "choice" } } } }
```

判据常量（`test_endgame_guide.py` 锁定，禁止散落）：

- `INTRO_ID`：maze→2（同文副本 44 不取，测试断言二者逐字相等）、story→115（**新版**；71 为改版前口径）、boss→93、peak→167。
- `_BUFF_SYSTEM`：记忆紊流 / 荒腔走板 / 终焉公理 / 裁决象限——**取值必须命中该模式 `sections` 的标题**，未命中则 `logger.warning` 且不落 `system`（宁可缺，不自造）。
- `_CHOICE`：`fixed` / `per_team` / `per_stage` / `per_king`（展示文案在前端 `src/app/endgame/guide.ts` 的 `CHOICE_LABEL`，转换器只出枚举）。
- `label` 由首个分节标题派生；`en` 无数据源，取常量并由前端 `ENDGAME_MODES` 对齐。

**实现注记（与方案文档 `temp/endgame-mode-pages-plan.md` 的差异）**：`IntroData` 正文里的换行是**字面量** `\n`（两字符，全站数据同此约定），因此分节不能按「行首 `◆`」锚定，改用不依赖行边界的 `◆…◆` 标记切分；peak 的 `count` 源字段是王棋扩展表 `ChallengePeakBossConfig.BuffList`（`ChallengePeakConfig` 无该字段）。
