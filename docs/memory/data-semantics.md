# 数据口径判据

> 本文件是**数据口径域**的坑位手册：哪些字段是权威源、哪些值不能当事实读、合成链与连接键的边界在哪。按主题组织，与按时间组织的 `2026-*.md` 复盘日志互补——日志回答「当时怎么想通的」，本文件回答「再做一次会踩在哪」。ADR 已写明的决策只保留 ADR 没写的那半句。

## 版本上新与赛季代际

- **常规模式首页的「新」= `release_version` == `version.json` 的 `version_label`；货币战争的「新」= 赛季代际差集。两套口径禁止混用**：写错就是静默空页或满页假新，且页面不报错。`tools/converter/season_delta.py`
- **按版本 id 差集做货币战争必然得空页，别重试**：该模式内容在赛季上线时一次性下发，4.4→4.5 五域全 0。判据要改用 `GridFightRoleBasicInfoOld` / `GridFightTraitLayerOld` 的 `ExistSeason` 最大一代。
- **`*Old` 表每代名册是累积的（代103 含代101/102 全部角色），差集才是新增**：把「某代名册」当「那一代新增」会得出错误的批次归属。`query.py --where` 单条结果字段是字母序，按字段正则配对会跨记录，必须整表 dump 后 `JSON.parse`。
- **只有角色 / 羁绊两域有代际表**：装备 / 环境 / 策略既无 `*Old`、无赛季字段，版本差集也实测为 0；不要为它们新造判据（ADR 0020）。
- **赛季号不上屏**：当前代编号 1 与旧代 101/102/103 是两套体系，显示数字会误导（外部认知里 4.4 是「第三次扩充」）。文案写「本赛季新增」即可。
- **代际差集的分辨率边界是固有的**：代内小补充会被并入该代名册（4.3 的 Archer 混在代103），4.6 的词缀在五个图鉴域毫无痕迹——这一层只有外部公告能提供，**不要试图从数据里挖**（ADR 0020 负面条）。
- **`*Old` 缺失或代数 < 2 必须落空集（全 false）+ 告警，禁止退化为全 true**：退化为全 true 等于整页假「新增」。
- **「当前 / 本期」这类时钟性判据不能复用「列表排序首位」**：排序回答「最新」，不是「正在生效」；取首位会把未开始的那一期当现状陈述。应用与列表同源的状态函数筛「进行中」，无进行中时回落最新一期并如实标注。
- **源数据里的 `Release` 布尔全为 true，不能用来区分版本或过滤预载**：它不承载版本次元。
- **差集口径有已知失真**：仅文案微调的条目会被算在更早版本上（如 4.5 已存在的光锥），故「本版本上新」缺它是判据的失真而非 bug——不要为它加特例。

## 目录卡字段与渲染

- **目录卡的字段必须在映射层显式带出来**：`renderCard` 只拿到映射层构造的对象，`item.desc` 在模板里恒为 `undefined` 且**没有任何报错**（`title` 静默为空）。加字段 = 映射层 + 卡片模板两处同批改。
- **「数据里有、UI 里没有」要当缺陷查，而不是当「设计上不放」**：查法 = 拿数据字段清单与卡片模板逐项比对（物品的 `desc` / `bg_desc` 就是这样发现的）。已判定有意不渲染的要记账（光锥 `desc` 只有 9 种文本、全是命途套话）。
- **扩检索域必须同时定命中分档，否则新内容会埋掉精确同名**：把描述并进 `searchText` 后搜「信用点」，同名卡会排到第 8 位、首屏是描述里提到它的别的物品。排序按「名字前缀 > 名字包含 > 仅描述命中」稳定排序。
- **卡面判据是「名称 + `IconPath` stem」，不可用立绘、不可用裸图标 stem**：立绘是 per-变体的（冰锋 4 条按立绘会拆成 2+2）；裸图标 stem 对应多个名称（`Monster_1003010` = 银鬃尉官 / 银鬃尉官（完整）/ 邓恩，是不同怪物）。判据单点在 `src/lib/monster-family.ts`，列表与详情共用。
- **同族「差分」必须覆盖页面会渲染的全部字段**：只比行内展示的几格，会在「抗性 / 图鉴介绍 / 立绘不同而那几格相同」时谎报「与当前档一致」（借力球 8001031/8001032 只差图鉴介绍）。行内高亮可取子集，标签必须列全量差异。
- **同图不同名的量级：632 条里 92 个图标 stem 被多个名字共用、涉及 397 条**；但这**不是重复数据**——149 个同名簇里 148 簇连技能都不同。同族判据含名称，故它们仍是不同的卡。
- **靠「多显示几个字段」压不平撞脸**：名称+分类 400 → 最全字段仍 2；加字段只能压到 ~105。且 `level_group` / `stat_ratio` 在同族里全为 1，**没有现成的难度档字段可当标签**，任何序号都是自己派生的。
- **聚合记录增键会自动漏进 endgame / voracity payload**（`endgame.py` 轻形态按 key 透传）：给列表加字段时要么直取共享聚合表不新增键，要么把新键显式加进跳过名单。忘了这一步不会报错，只是产物变大且口径漂移。
- **`endgame` 的轻形态与全形态必须分开**：期级合并列表只服务目录卡代表阵容与 AI 快照，跟着变全字段等于把 10 期的重复介绍再存一份。卡片类改动要「形态 + 数据」一起验收——只看 DOM 会漏掉 `skills: 0 / intro: false`，卡片不报错只会空着。

## 出没样本名与活动出处

- **`StageConfig.StageName` 不是关卡名**：在多数玩法里它是敌方标识（181/742 个样本与本怪自己的 `name` 逐字相同，160 个同一 TextMap hash）；在活动类型里它是活动级常量或阵营名（FightFest 134 关共用一个文本，而那个文本是同一活动里的另一只敌人）。把它当关卡名展示必然误导（ADR 0046 / 0047）。
- **别设「标签覆盖率 / 占比阈值」来筛占位名**：阈值即自造判据。也别用「标签 ∈ 本关波次名单的敌方名」这条看似更准的判据——它会误杀官方式名号（「蛮神，疯王，纷争的化身」「「灯塔」」都不等于任何敌方名）。
- **有实名源就只用实名源、查不到就不落样本**：回退即重现要修的问题；`total` 照计，页面写「这些关卡在游戏内没有关卡名」。四类玩家可见名源：活动 6 条实名链、终局四张层级表、`MappingInfoID` 真外键（隧洞 / 虚影）、强敌挑战与剑试。
- **`MappingInfo.ID == StageID // 100` 是巧合，不是外键**：90 个 `FARM_ENTRANCE` 里只有 1 个存在 `ID*100+k` 家族，逐关核对名单 0 交集。真外键只有 `MappingInfoID`。
- **按源取名的连接键各不相同**：活动链是 `EventID = StageID // 10`（并退回原值兜底，覆盖「关卡号 = 活动号」的单关特例）；终局四表的 `EventIDList*` 里直接装关卡 ID。
- **活动名走「面板与关卡类型同名」约定，不是硬编码**：`ActivityPanel.UIPrefab` basename == `StageConfig.StageType`；面板匹配用**最长前导**。给不出连接的链就不落 `activity` 键（宁缺不猜）——BoxingClub / ElationActivity 属此列。
- **活动名与关卡名分列两个字段，拼接发生在展示层**：`name` 只放关卡名、`activity` 只放活动名，视图渲染「活动名 · 关卡名」，AI 快照用同一分隔符。数据层一个字段管一件事，页面才有条件把活动名弱化。
- **同屏不出现两个相同的数**：活动内关卡数只在 ≠ 上方总数时写，相等时改说「全部关卡都在「X」活动里」。
- **等级单档不写区间**：全档同等级会渲染成「等级 85–85」。页面 `eventLevelText` 与快照 `eventLevelRange` 必须同一口径。
- **「官方复用技能组」证不了，不要写**：技能集按 ID 全不同，按「同名 + 同标签 + 同描述」比对也有 22/26 个活动敌人与同伴不同；立绘在 92 个同卡面组里只有 2 组不同。站点能证的只有「同卡面图标」与「立绘是否相同」（ADR 0048）。
- **`art_shared` 要按维度分支，不能一句话断言**：`figure` 真 →「卡面与立绘与「X」共用」；假 →「同卡面图标，立绘不同」。同卡面分组的 92 个多名字组里 90 组立绘一致、2 组不一致。
- **判据必须下沉到数据层**：视图只有自己的详情与目录 `icon`，比不了同伴的立绘（同伴的 `figure` 只在各自详情里）——这正是旧实现用图标 stem 推「共用美术」并写出过度断言的原因。全集必须用与目录页同源的 `monsters.catalog_rows()`。
- **`figure=false` 分支当前不上屏，但别当死代码删**：备注块只在有 `event` 的页面渲染，而该分支的条目都没有 `event`。删了会在数据变化时退回过度断言。
- **给用户结论时必须分清「源字段事实」与「我的解释」**：把「只出现在 FightFest 活动专用关卡里」说成「幻象遭遇战」是推断而非数据。解释要么明确标注为推断，要么不写。

## 精英组 / 修正值与合成链

- **`/monster/:id` 曾直出的是模板基准值（HP 69.75 / ATK 18），不是任何等级下的战斗值**：完整链条 = `基准 × 维度修饰比 × 精英组倍率 × 等级曲线 + 实例修正值`，四条腿的表都在仓内，只是转换器没接上（ADR 0040 / 0045 / 0049 / 0050）。
- **修正值加在曲线之后、不再被缩放**：`190 − 44 = 146`；若先加减再乘曲线会得到 132。反推方式是与参考站同族多档逐位对照（韧性 90+30=120、360−120=240、190+56=246 全部吻合）。
- **「加法位置无据可验」这类结论要先查参考站再下**：社区参考站是判定「另一个实现怎么做」的一等证据。另注它只接受模板 ID 路由（实例 ID 返回 404），变体在模板页内展开。
- **韧性不入等级曲线链**：`韧性 = 韧性基准 × 精英组韧性倍率 + 修正值`。这解释了详情页里韧性为何单独占一行（拖等级滑条它不变）——**布局上的偶然形态一旦被新口径赋义，就必须把含义写进注记**，否则读者只能猜。
- **「场景系数」不是黑箱，就是 `EliteGroup.json`**：难度组管「随等级变化的曲线」，精英组管「不随等级变化的整体倍率」，两条独立缩放轴。怪物侧与关卡侧**共用同一张倍率表**。
- **关卡侧面板的 Π 是「怪物自身组 × 关卡指派组」叠乘**：`StageConfig` 每关带 `Level + HardLevelGroup + EliteGroup` 三件套。凝滞虚影（`FarmElement`）203/203 关全指派组 6，与《数据机制通论》互证——**这是关卡侧指派语义的坐实证据**。
- **`Cocoon` = 拟造花萼、`FarmElement` = 凝滞虚影**（别按字面猜成隧洞）：这两个名字对错会写进面向读者的口径注记。
- **社群文章的系数表要逐行对表再引用，不能整表照抄**：文章是 V1.1、库是 4.6，组 3 的 ATK 已漂移（文章 0.85 / vendor 0.7），且花萼的组号实测为 2/3/29 混合。**面板一律以 vendor 为准**。
- **别名变体必须用自己那条 config 记录的修饰比 / 难度组 / 精英组，不得继承模板**：`{**out[tpl], '_tpl': ...}` 这种别名兜底会连模板的比值一起复制过去，而同模板的档位变体正是靠这些值区分的（`1002011 hpR=1` vs `100201101 hpR=0.266667`）。
- **缺位按中性 1，绝不按 0**：0 会把一条 HP 显示成 0，比「没有数据」更误导。难度组缺位则回退「仅展示档案基准值」的降级态，不假数值。
- **缺位的静默中性化只做一半仍是静默错**：缺位要 write 日志或文案，不能悄悄按 1 过。
- **`HardLevelGroup.Level` 是 int，JSON 键必须 stringify 后再比较**：忘了 `str(lv)` 会让去重 / 查表直接 miss。
- **默认等级要取「该怪难度组曲线的最高档」，不能写死 100**：组上限不是 100 时，滑条 max 与值不一致会取不到曲线行 → 整页静默回退基准值却仍标「等级 100」。
- **等级曲线 / 倍率表必须单独落盘 + 共享单例加载，不能内联进详情 payload**：2722 份 × 45KB 不可承受（ADR 0040 决策 2）。
- **曲线文件必须在详情循环之前写出**：顺序错了详情会读到空表。
- **`monster_common` 读的表变了就是依赖变了**：它读 `HardLevelGroup.json` 之后，`monster_common` 与 `monster_detail` 都要登记进 `incremental.MODULE_SOURCES`，漏登记会被 AST 覆盖测试抓住——别等 CI。
- **同一算式不许有第二份实现**：合成单点在前端 `monster-stats.ts`，转换器与 AI 快照都不做；怪物详情快照的四维数值**不做合成**，标签写「（模板基准）」。改口径时页面注记与快照标签必须同批改。
- **四维未齐全时不渲染部分面板（宁缺不假）**：曲线缺行 / 缺组 → 该样本无面板。
- **给终局敌方卡加实战面板是错的**：终局没有等级语境，且忘却之庭类语境本无精英组修饰。

## 连接键与身份

- **配置表里的敌方 ID ≠ 战斗里的敌方 ID**：机制按**敌方模板**（`MonsterID // 100`）注册，而关卡配置登记的是另一个号（业火焚心的影卫配置 `2033022` vs 战斗模板 `2035012`）——按 ID 直连会漏配。改成用 `MonsterGuideTag.SkillID // 100` 反查，并加唯一性闸（技能 ID 会被共用，如 `100401410`）。
- **污染名单登记的是实例，不是模板**：按 `tpl` 匹配会把同模板的**未污染**实例一并标错（实测 1036 三只被污染实例里只有两只能按 ID 命中，按模板会把第三只的同模板兄弟也标上）。判据与转换器 `_polluted_index` 同源。
- **末日幻影有固有边界**：boss 楼层的 `invasion.monsters` 与 `stage.monsters` 零命中（该层只登记首领，被污染小怪由机制额外加入）——这些怪物只能以**召唤物**形式带徽标。忘却之庭 / 虚构叙事 / 异相仲裁则有实例级命中。
- **污染等级是关卡级属性，不是赛季级**：判据 = `StageInvasionConfig.InvasionID`（1–3）。展示层已两度收窄到「只挂被污染的那一只」——**用户要的是标签挂在怪物身上，不是汇总入口**（ADR 0026 两次补记）。
- **把「保留某区块」写成 ADR 结论会多一次回扫**：推断（「删掉会让『这期污染了谁』无从查起」）被用户直接否掉。不确定的保留理由不要写成既成结论。
- **「污染」是同形词，必须区分两套**：4.5 起 Fate 联动的「圣杯战争·污染等级 / 深度污染」与「贪饕」侵蚀无任何关联，混称会制造错误事实（ADR 0025）。
- **首领机制的归属只活在上游表里**：`boss_traits` 只有场次键、条目无怪物标识——「产物看不出归属」是数据层的形态，不是漏字段。
- **状态词条的命名约定桥是启发式联结，不是外键**：`ModifierName = 怪物配置名[_SkillTriggerKey]_效果后缀` 会跨怪同名（`Monster_W1_CocoliaP1_00` 家族里混着托帕幻象）。**宁可少归、不可错归**——把别人的状态挂到这只怪身上比少列一条更糟。加「同名闸」后 304/706。
- **判据口径要写清是「token 唯一」还是「模板唯一」**：token 天然被同族多模板共享，两个口径差 3 倍（445/632 vs 98/706）。
- **同名同描述的重复行只能按渲染签名去重，不能按名称**：同名但描述不同的行是真数据（不同技能 / 参数的分别登记）。
- **描述里的 `#N[i]` 是动态属性，不是「本仓暂时没接」**：`ReadParamList` 只有键名、没有数值 ⇒ 这些描述永远渲染不出数字。仓内既有缺参纪律是「整段省略，不落残缺占位与 `?`」（`src/lib/format.ts → refsResolved`）——转换期就不落。**别自己发明 `?` 或补 0**。
- **「某字段是不是某物品」可以直接判**：`RewardData` 里 `ItemID_1 ≡ 1` 的行数为 0，而 `ItemConfig` 1 = 星琼、32.6% 的行用 `Hcoin` 记数量 ⇒ 两者是同一货币的两种记法，解析时并入物品 1。
- **`ChallengePeakReward` 的档位只能上屏能证的两类**：其余档对应的勋章「哪一档发哪一枚」只能靠推，不上屏，数据留产物里。

## 口径注记与降级态

- **口径注记必须与数字同屏，禁止把数字渲染成「这就是游戏内数值」**：数值是「模板基准 × 维度修饰比 × 精英组倍率（组 N）× 等级曲线（难度组 M）＋ 实例修正值」，并写明未含什么。
- **同屏不要摆两套口径**：数字已含修正就不再单独标「另有修正」——一个含修正、一个提示未含，必被误读（ADR 0045 决策 6）。
- **改口径时页面注记与 AI 快照标签必须同批改**：快照是事实表，不复算，但标签口径要一致。
- **角色面板随「等级 + 突破档位」两个变量变，展示时必须绑定一个突破口径**：`AvatarPromotionConfig` 每档的 `Base/Add` 是**该档自己的曲线**（档 k 的曲线 = `base_k + add × (等级 − 1)`），相邻档 `Base` 恰好递进 `8 × Add` ⇒ **突破会立刻加面板**（满突破 6 次累计 +48 级份；这也是 Lv.80 面板 = `base_6 + add × 79`、而不是首档曲线外推的原因）。所以「Lv.N 的面板」不是单一值：本站取**上限 ≤ 该等级的档位数**那一档（＝每档上限一到就突破的标准路径，Lv.20 显示的是突破 1 之后的值），并在读数里标出档位。**不能取「上限 ≥ 该等级的最小档」**——那条读法意味着「过了上限才跳档」，不是任何可达状态（要升到 Lv.71 必须先突破，届时面板已经跳过）。
- **快照不同步是有意的取舍，不是遗漏**：`/endgame/:mode/:id` 快照来自轻量 catalog 条目，新字段不进 catalog 就不进快照——沿用同一取舍要明写，否则会被当成漏做。
- **新增区块必须先与「现有区块已经说了什么」对账**：阶段行 48 条里 36 条与本体弱点/抗性同数据 ⇒ 覆盖率涨了、**信息量为零甚至为负**（同一屏重复同一事实）。判据是「这条信息在别处是否已上屏」，不是「这个字段是否还没展示」。`tools/converter/converters/monster_extra.py`
- **`MonsterAtlasExtraPhase(s)` 是「图鉴条目的额外立绘形态」表，不是阶段表**——上屏前三条判据都要过：① 它按 `TemplateGroupID`（图鉴条目）挂，**整组共享**，不区分变体；② **上游没有阶段号**：`PhaseID` 只是组内行键（4015011 两行行序与立绘序号相反；3025010 的 `PhaseID=1` 行立绘名就写着 `_Phase2`），游戏真正的阶段号在 `MonsterSkillConfig.PhaseList`（技能→阶段）与首领攻略 `MonsterGuideConfig.PhaseList`→`MonsterGuidePhase.PhaseName`（官方名如「阶段一：浮翠流丹」），都不在这张表里；③ 源表 **12 条 (组, 阶段) 行里 11 条**与该条基准成员（`id === atlas_group`）的 `MonsterConfig` 弱点/抗性逐字相同——那 11 条只是同一实体的另一套模型（`ManikinPrefabPath` 不同），唯一例外是神主日那条（「哲学的胎儿」星期日 = 七属性全弱零抗性，与游戏内「造物的工」明写的「拥有全属性弱点」互证）。**故形态块只渲染「含新信息」的行**：丢与本体同值的 → 丢「**名字命中同条目成员**」的 → 丢「与基准成员同值且自身无名字/介绍」的。**第二条最容易被漏**：形态行里的名字若能在同 `TemplateGroupID` 的目录成员里找到，那个形态**本身就有一个条目页**（`4034013` 的「无缘黎明」卡厄斯兰那 = 条目 `4034015`，连 `MonsterConfig` 的弱点/抗性都逐字相同）——摆到本页会把「别人的弱点」说成本怪的第二形态/阶段，而它的入口本来就在「图鉴族」互链里（撤块必须同时确认互链仍在）。**`PhaseID` 不得当阶段号上屏**（会写成「阶段 1」，而它实际可能是阶段三）。**要真阶段号就用 `MonsterGuideConfig.PhaseList` → `MonsterGuidePhase.PhaseName`**：阶段名自带「阶段一：…」前缀（实测 36 条阶段行里 28 条有前缀、且前缀序号与 `PhaseList` 顺序 **100% 一致**），是站内唯一有来源的阶段号；该装配与末日幻影敌方卡的 `boss_guides` 同一函数（`converters/monster_guide.load_boss_guides`，按 `MonsterID // 100` 聚到模板），敌方详情页只取阶段段落 `guide_phases` 上屏「阶段机制」段（实测 22/632 个目录条目有），**`traits`（首领特性）不进详情 payload**。**编号与名字必须分开呈现**：页面用 `PhaseList` 顺序占编号位（`阶段 N`），把名字里那句前缀剥掉——同一行说两遍「第几阶段」会被读成两个不同的东西；**剥前缀前必须校验前缀序号 == 顺序**（不一致就原样保留，宁可重复不可标错号），另有 8 条名字**根本没有前缀**（单阶段条目，如「末日歧途的盗火者」），全靠编号位才看得出是第几阶段。
- **「无法解析」与「上游本就为空」在页面上完全同形**，只能靠产物 diff 区分：降级态与空态若不分别渲染，读者无法分辨「本站没接」与「官方没有」。
- **降级态清空判据是状态位（如 `placeholderLoaded`），不是 src 取值**：用 src 判断会在图还没加载时误判为已降级。
- **缺图判据 = 回退链走完（两个源都失败），不是「主源失败」**：只按主源判会把还在回退的文件误报为死链。
- **占位图是 opt-in 的终态，`isCdnDown()` 的短路不得触发它**：CDN 探针失败不是「该显示占位」的理由。
- **`isPlaceholderSrc()` 只认 `data:image/svg+xml,` 前缀**：换占位实现要同批改这个判定。
- **`data-cdn-fallback` 曾因模板没绑定而完全失效**：`iconUrl()` / `skillIconUrl()` 只返回主 URL，回退属性写了也没人读 —— 资源被静默判死。加回退属性后必须确认模板真的绑定了它。
- **占位符判定必须发生在 `clean_text` 之前**：顺序反了会把 `{NICKNAME}` 变成「开拓者」，得到假的英文名。
- **`resolve_text_en` 仍要过 `clean_text`**：不能因为走的是英文分支就跳过清洗。
- **全量产物不做逐赛季裁剪是有意边界**：污染数据里未发布赛季照样带 `invasion` / `pollution`，可见性过滤只发生在「会变成链接 / 会进索引」的两处——否则要为污染单开特例。
- **`figure=false` / 未上屏分支要留正确表述**：删「当前不渲染」的分支等于在数据变化时退回过度断言。

## 数据管线与增量

- **只改转换器代码不改源数据 ⇒ 增量转换会静默输出「跳过（未变更）」**：`incremental.py` 的签名只看**源文件** mtime/size。改完转换器必须 `python tools/converter/convert.py --only <模块> --force`。
- **转换器改了读哪些表，就要同批登记 `MODULE_SOURCES`**：AST 覆盖测试会抓（`test_module_sources_cover_static_loads`），漏登记则源数据变更不触发重跑，产物静默陈旧。
- **单文件单点放置不足以证明覆盖**：`30126123` 只存在于 `ChallengeMazeTierce`，同类字段还散在 `HFIAAGAKFMD` 与 `ChallengePeakConfig.EventIDList` 里。
- **夹具要按判据的 AND/OR 语义造**：出没样本去重是「类型**与**名都不同才加」——造两条同类型样本，第二条会被静默跳过（只在 IndexError 时暴露）；名称源的类型闸还会拒掉跨类型行。
- **「未消费字段」里可能藏着正解**：被记为「同表常量、语义未验证」的 `IMCMJHAMMKK` 其实是本模式奖励族里的 RewardID。判据 = 先看该常量是否落在该模式已知奖励 ID 段内，再用 `query.py RewardData --where` 验证。**遇到「同表常量」不要直接归档为未解，先当外部 ID 试着解一次**。
- **同一奖励线 Group 会被层数不同的多期共用（10 层期与 12 层期同为 Group 2）**：不截断会多出本期不可达的档位。上限 = 该期 Σ 挑战目标数，在转换期单点截断，前端不重算。
- **反推外部实现时，浏览器读参考站的渲染后 DOM，别抓 HTML**：它是 JS 站，HTML 里没有数。

## 命名与术语裁决

- **术语冲突由用户按官方口径裁决，不要自己发明折中词**：「关卡效果 vs 首领特性」最终取官方术语（`level_effects → boss_traits`，`.nk-egd-effect* → .nk-egd-trait*`）。
- **官方文案里已有的口径要先读**：`endgame_guide.json` 明写「达成指定条件获得星数，累计星数领取馈赠」，据此可判定「每层恰好 3 个挑战目标 ⇒ 1 个目标 = 1 星」。
- **措辞要按官方原文逐条校准，不要沿用内部简写**：「固定生效」应为「随层生效」（官方：仅在当前关卡内生效）；「每场战斗选 1 条」应为「每场首领挑战前选 1 条（上/下半场各一套）」；「本期 N 条」应为「每期 N 条」（条数是常青规格，带「本期」会把它说成每期数据）。
- **条目名跨期恒定的玩法，别给它造「本期」的概念**：忘却之庭全期去重只有 1 个名，所谓「本期 1 条」是假时钟加复述。
- **「满分档不是第 4 颗星」**：星级目标（3 个节点目标 ↔ 3 星）与满分档（棱彩星条件）是两种东西，混在一列会让玩家以为有 4 颗星。
- **官方组号（`TemplateGroupID`）与「同族变体」是细化关系、不是并列**：官方组从不把一族拆开（跨 ≥2 个官方组的族为 0），但官方组是「同一图鉴条目的各具名形态」（可把可可利亚与托帕幻象并成 8 个形态、113 个多成员组里 12 个连卡面图标都不同）。**改用官方组当族会出现「两张不同的图互为变体」**，且 38 个多成员族因组号为空而失去分组（正是最刺眼的冰锋 ×4、无尽寒冬之槊 ×8）。
- **官方组号本身可作第二个更粗的维度**（形态族、含 `AtlasSortID` 官方序），与「同族变体」并存互不干扰——但这是新维度，不是替换。
- **`StageType` 的中文枚举全仓无文本源**：不要为展示硬造标签，也不要靠它给读者解释活动类型。
- **人工权重（如「特写哪一条」「偏袒哪一条」）没有判据时就不要有**：2 条时按 `picked[0]` 决定谁独占大名字，纯由数据顺序决定，读者读起来像漏了一条。判据要收窄到有据可依的档位（如「恰 1 条」）。
