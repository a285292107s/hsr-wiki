# UI 令牌与样式

> 本域补 [ui-design.md](../agents/ui-design.md) 的盲区：该文件写「规则是什么」，本文件只写规则推不出的**静默失效坑位**与**判据的理由**——为什么这样判、不这样判会在哪一步踩到。

## 静默失效：不报错但结果错

- **`:has()` 写完必须量「实测命中几条」**：它与 DOM 里有没有同级兄弟强耦合，视图加一个同级元素（如 `<aside>`）就永久失效，且完全静默——选择器合法、守卫全绿。实例：`:has(…:last-child:first-child)` 自写下起从未命中。`catalog.css`
- **结构性派生一律用 `:has(> …)`，不要用兄弟/位置伪类**：父级竖轨写成 `.nk-skill:has(> .nk-skill--child)` 才只在真有子卡时渲染，单卡族/无族退化路径不出悬空线；网格同理，否则对比模式复用同一 `__body` 时会被改成两列。`character-skills.css`
- **跨层「开关 / 选项」类参数，落地后必须做一次运行时取证确认到达消费点**：漏传是静默退化。实例：未把 `firstStageLayers` 传到 `createScenePipeline`，分阶段加载静默退回单阶段，`build`/`test`/守卫全绿，唯一证据是网络时序。
- **目录卡的字段必须在映射层显式带出来**：`renderCard` 只拿到映射层构造的对象，读未映射字段恒为 `undefined` 且不报错——表现为 `title` 静默为空。`pages/item.ts`
- **只给部分属性写缓动等于没写**：未写的静默回落浏览器默认 `ease`。曾有 11 条此类声明；`.nk-tab` 曾有两条互相竞争的 transition，后写的生效。改后要静态检测「裸时长」为 0。
- **`:hover` 改过的属性必须在 `@media (hover: none)` 里同步复位**，且展开态单独重新声明（`.open:hover`）：该媒体块在文件末尾，同特异性下会盖掉基态，触屏上展开中的按钮掉色回灰。
- **`focus-visible` 共享组里的 `border-radius` 会改按钮本体圆角**：组内该声明本意是给 outline 定形，对无可见盒子的文字按钮无害；按钮一旦有了圆角盒，聚焦瞬间跳形。此类必须单列复位、不进共享组。
- **同权重档位规则混写会让断点规则被非媒体规则反压**：两个 CSS 的档位规则权重都是 0,3,0、靠源序判定；把手机档规则写成非媒体查询 ⇒ 平板断点内两条并列命中、后写的非媒体规则胜出。**每个断点每一档只允许一条声明**。
- **清理「被后写覆盖的声明」前先比特异性**：特异性更高的那份从来不是死代码。终局页 40 余条死声明中唯一必留的是 0,2,0 的那条，压不住收口块的 0,1,0。
- **`check-contrast` 只算「文字令牌 × `--bg`」**：文字落在 `--surface`/`--card`/着色片（tag·chip·激活段）上还要再降一档，这一层只有 axe（4 页 × 缺省色）兜底；两处都覆盖不到的组合必须人工按 sRGB 合成核算。
- **对比度必须取该元素实际解析出的背景色**：拿 `--bg`/`<body>` 当背景会系统性高估。实例：探针把手机底栏文字算成 7.3:1，而真实底色是底栏的 `#1e1c1d`，实际 4.07:1——背景取错让结论偏移一个量级。
- **带 alpha 的令牌必须先与紧邻像素合成再算对比度**：直接用 rgb 三元组会把文字算亮。
- **大字号的阈值不同**：≥24px（或 ≥18.66px 粗体）判 3:1 而非 4.5:1。hero 名称 43~54px 属此档，按 4.5:1 判会得出「名称也不达标」的假结论。
- **axe 默认标签只覆盖 WCAG 2.0/2.1 的 A+AA**：`wcag22aa` 新增规则（`target-size` 等）默认不跑，`enabled: false` 的规则会静默通过。声明「跑 2.2 AA」前必须显式 `withTags`。
- **口径声明与执行必须逐项对齐**：a11y spec 曾被 mobile 项目 `testIgnore` 排除 ⇒ 手机独有的对比度路径（底栏标签只在 <768 显示）从未进过流水线。须核规则集 × 视口 × 排除项三项。
- **`region` 命中数 ≈ 页面内容块数，不是「个别元素」问题**：正文没有 landmark 时一次命中 69~77 个节点，读屏用户只能从头听到尾。修法是三种态外层包 `<main>`。
- **有可见文字的图片必须装饰化（`alt` 与可见文字二选一）**：否则读屏念两遍。同一模板里两类槽的策略必须分开判——看它旁边有没有可见文字。
- **CSS 语法损坏不一定被守卫拦住**：少分号会让四条声明（`color` + `letter-spacing` / `font-weight`）静默失效。**三守卫全绿不等于语法正确**。
- **`tokens.css` 尾部无障碍三件套曾整块重复**（三个规则各两遍）——静默死代码，守卫不查。
- **`!important` 的 `transition` 简写会把 `transition-property` 整体限死为它列出的属性**：未列出的属性（opacity / transform）的插值被静默吃掉，表现为「动画没播」。判据 = computed `transition-property` 不含目标属性 + 零中间帧；**排查「动画没播」要先看 property，只看 duration/delay 会误判成「时长没生效」**。修法是收窄选择器（`*:not([class*="nk-view-"])`），不是拆成逐属性写法（实测不成立）。`src/styles/tokens.css`、`src/app/App.vue`
- **删掉一个「死样式/死层」会改变它曾遮住的另一层的可见度**：纯 A/B 差值只反映净效果，看不出「原来是它挡着」——左右渐隐 `::before`（`z-index: 1`）画在 inset `box-shadow` 之上，删掉后最外圈暗角反而更明显。**判死代码前先查它是不是某层的唯一遮蔽物。**`src/styles/character.css`
- **全局重置的双重静默失效**：① `#id 元素` 形态的重复副本特异性 (1,0,1) 会压死类选择器的间距；② 重置清单漏 `h4`/`h5`/`h6` 则 UA 的 `1.33em` 外边距泄漏。`src/styles/tokens.css`、`catalog.css`、`currency-hub.css`
- **删「页面级覆写」≠ 取消**：删掉整条规则会**回落到基线更重的值**（光锥 hero 的暗角是覆写基线两层更重的 inset，删规则反而更暗）。必须显式 `box-shadow: none` / `background: none`（`::before` 同理）。`src/styles/lightcone.css`
- **数字统一格式化时三类不得动**：① 标识符 ID（加千分位后更难核对）；② 数据正文里的数字（那是游戏原文，重排等于改写数据文本）；③ 已带单位的百分比 / 星级 / 费用。`src/lib/format.ts`
- **只在 hover / focus / active 才换色的元素，其文字对比度从未被默认态扫描覆盖**：「悬停后掉到 4.5:1 以下」只存在于交互态。须逐元素 `hover()` / `focus()` 后**在该状态**跑 `color-contrast`。
- **落在单轴滚动容器之外的伪元素不报错，只是永远不渲染**：`overflow-x: auto` 会把另一轴的 `visible` 按规范算成 `auto`，padding box 之外一律裁掉。`.nk-secnav__btn--active::after` 写 `bottom: -7px`（本意是挂到吸顶条底边、与容器边框对齐）⇒ 三个消费页（角色 / 货币战争角色 / 贪饕）**从未渲染出激活下划线**，静默到只剩一层颜色差。按钮高度又恒等于导航盒高度（导航盒被按钮撑满），所以任何 `bottom: -N` 都必然落在盒外。修法是让落点落在按钮盒内（`bottom: 0`），判据取**计算值** `parseFloat(getComputedStyle(el,'::after').bottom) >= 0`——**别拿 `scrollHeight > clientHeight` 当判据**：同一宿主上还有一条 `::before { top/bottom: -7px }` 的隐式热区，它独自就能把 `scrollHeight` 顶高 7px，改完落点后该比值依旧超 7px。
- **「挂载时算一次」的溢出 / 断点判定会永久停在初值：布局在挂载后还会变**：实测角色页吸顶导航的可视宽在挂载后由 560 变 648（首帧与稳定态差 88px），一次性计算把「本来不溢出」的 768–1023 档永久挂上「还有内容」的渐隐——提示相反的事实。正解是跟着布局走（`ResizeObserver` 观察容器盒宽覆盖视口 / 滚动条、观察首个子项宽覆盖字型替换），**不能拿 `document.fonts.ready` 当布局稳定信号**：实测它在目标元素挂载前就已 resolve（同一采样点上 `document.fonts.status` 已是 `loaded`），挂 `await` 等于什么都没等。判据要挑**只有该档能观测到**的视口——≥1024 的基础规则本就是 `none`，在那里断言永远绿。
- **`min-height` 撑高的 flex 按钮里，`align-items: baseline` 会把内容钉在行首**：单行 flex 容器把基线组放在行首、多余空间全落到尾部 ⇒ 44px 的触控按钮里文字墨迹停在 0~16（上留白 0 / 下留白 28），吸顶条下半截是一整片空档。而「按钮高 44 + 条高 47」两条断言在**贴顶与居中两种形态下都成立**，抓不到它——判据必须取**墨迹的上留白与下留白之差**（≤2px）。修法只有 `align-items: center`：**`align-content: center` 治不了**（对 `flex-wrap: nowrap` 的单行容器无效，实测零变化）。代价是索引号由基线对齐变盒心对齐，实测位移 1.5px。

## 令牌收口与迁移

- **改主题色 = 必须全仓搜「为旧主色明度写的对比补偿」**：浅金时代沉淀了一批「浅底深字」补偿（`color: var(--blk-900)`、进度条渐变、局部令牌覆盖），换赤陶后白字才对。静态审查看不出「这条只在旧色下才对」，可靠办法是让 e2e 跑一遍。（ADR 0041）
- **与主题通道绑定的原始层色阶要逐个查消费点**：CW 候选色阶通道退场后，四族里只剩一族有消费者。
- **改底色必须与表面阶梯同批上移**：只改 `--bg` 会在某一亮度以上让 `--surface` 比页面更暗。（ADR 0021）
- **领域色不得引用别名层**：遗器徽章从 `--th-300` 改语义位 `--metric-val` 即此类纠正。
- **`--elem-*` 七个令牌全仓零消费者**：故「让角色页用上属性身份色」是零新颜色、零四步评审的改动；但扩展成 hero 整块会撞双色约束，需单独裁决。
- **页面级共享原语改造必须作用域化**：`.nk-title` 被六页消费。「改了某页 CSS 会不会波及别页」的第一步应该是**数根类名的写入方**（某根类全仓只有一处写入 ⇒ 天然不外溢），而不是先跑全量 e2e。
- **跨页借用的共享 class 只能是 `tokens.css` 已声明的原语**：借另一页的页面级 class，其 CSS 只随该路由 chunk 到达，跨页命中不了样式——**unseen 破相而不报错**。
- **`scrollbar-color` 写在 `#app` 上即可**（继承属性，一处覆盖全部滚动容器）；但**不要顺手加 `scrollbar-width: thin`**——细滚动条让容器宽出约 7px，虚拟网格格宽与像素基线连锁变化。
- **`::selection` 提为全局时页面级那份必须同时删除**（同一事实只留一处）；环境层同理收口成单点事实源，四个页根转透明。
- **刻度收口后 `calc(刻度 ± n)` 是离刻度值的藏身处**：它字面上引用了令牌，却把结果推离刻度。**复审刻度一致性时要专门扫 calc 表达式**，不能只查字面量。

## 字阶与圆角刻度

- **容差必须按量纲分层，否则会「压平有意的设计」**：一律 1.2px 容差 ⇒ 300+ 处进人工裁决队列（响应式 `clamp` 与特写尺寸必然超差）。终态：正文/界面字号 1.2px、标题与特写 4px、圆角 6px。
- **刻度 codemod 只写「就近落档」、不做等距化**：目的是让取值来自刻度，而不是借收口之名重新设计字号。
- **动字号前先找「谁按字号算过尺寸」**（槽高、行盒、图标盒、骨架代理盒）：槽高 = 本档主字上限 × 行距，骨架屏靠它代理固定盒高，改字号不改槽高 ⇒ 骨架↔就绪错位。该页有三套槽高，且**单字档与多字档各一个**（单字字号更大）。
- **改任何一处字号都要跑「全量数据 × 2 断点」的盒高中位数探针**：抽样集会因新档位占比算错（某档在抽样里 0 只）。同一页曾三次因字号改动而重测。
- **骨架与就绪的盒高必须同源消费单一令牌**：收口后就绪高 = `max(内容高, 令牌值)`，两态同框由构造成立，不再依赖「常量恰好等于内容高」这个 0.19px 级的巧合。
- **同类交互的「写法不同」比「用哪个值」更值得修**：同一类悬停曾横跨五个族五种时长 + 两种曲线。时长分档要由令牌承载，**契约从令牌读期望值**——改档不会让用例变红，只有组件自造值才会。
- **动效分档按「改哪些属性」归位**：卡片**表面**（border-color/box-shadow/transform/opacity）→ normal 档，**标签**与控件（color/background/filter）→ hover 档，图片放大 → zoom 档。
- **页面设计语言声明的档位必须能在实测里数出来**：某页头部声明三档圆角，实测出现 7 种。归一要**按语义归类比脚本盲替可靠**——同一个 6px 落在图标、chip、按钮上应分别归到内联档与容器档。
- **契约要跟着语言收窄**：从「非圆形且 >20px 即红」升级为四值白名单（容器档期望值从页面令牌派生）。**清理必须配契约，否则只是「这次干净」**。
- **全局 `--nk-radius-card` 与页面声明冲突时，第三条路是页面另立一名**，只动本页 CSS——不要为单页去改全局 token。`50%` 与胶囊是**形态**不是档位。
- **`--nk-prose-max` 必须按字号缩放且消费在承载正文的那一级**：`em` 按元素自身字号解析，落在容器级上会得到完全不同的每行字数。

## 几何与形态判据

- **`<input>` 放进 flex 行必须写 `min-width: 0`**：表单控件的 `min-width: auto` 解析成**固有宽**（Chromium 下 `input[type=range]` 约 129px），flex 收缩下不去 ⇒ 窄视口（320px）上英文/印尼文的较长标签把这一行顶出容器，再被页面根的 `overflow-x: hidden` 静默吃掉（实测 `hardClipX` en +11px / id +3px，元素是 `.nk-skill__slider > input`，右缘 329 > 320）。`flex: 1` 不解决这件事——`flex-basis: 0%` 只作用于「可收缩」，而收缩下限由固有宽决定。判据：横向溢出量不大（≤ 一个滑条的固有宽）且只在长译文语言出现时，先量「越界后代的固有宽」而不是调容器宽度。
- **「元素类型差异」的可见性取决于布局是否把文字盒拉伸**：UA 给 `<button>` 声明 `text-align: center`，单行/收缩盒里它是空转，纵向 flex 把子项拉满时才显形。故不能靠读样式表判定，要跨标签比对计算样式 + 做「改掉这个值再量 ink 位移」的差分。
- **任何 `max-content`/`fit-content` 轨，只要轨内元素的固有宽度由懒加载图决定，就必须写确定值**：图未加载时塌成文字宽、到达后涨到固有宽 ⇒ 同分区两张卡差 2.5 倍 + 首屏一次 144px 位移（CLS）。
- **flex item 的 `min-height: auto` 在 `overflow != visible` 时降为 0**：column flex 容器里唯一带 `overflow: hidden` 的子项会被压塌到几十像素——详情页 Hero 曾因此把页面主标题压到不可见，而既有详情页 Hero 恰好都没写 `overflow: hidden` 所以从未暴露。修法是给该子项 `flex: none`。
- **`auto-fill` 与 `auto-fit` 在固定条目数下行为相反**：`auto-fill` 在建轨阶段按可用宽度铺满、末行空轨**不收回**（宽屏下留一大块空白）；`auto-fit` 空轨塌缩。本仓惯例是 `auto-fill`（几百条目的卡片墙），**固定条目页必须用 `auto-fit`**。改列数时还要连带检查基线的「跨列 / 满行」规则（如 `:last-child:nth-child(odd) { grid-column: 1/-1 }`）——项数 % 列数 ≠ 0 时必然把末项顶成独立整行。
- **「名字是最长字段」的卡片，列宽下限必须由数据里的最长值反推**：不逐页翻，而是**把数据集里会出现名字全量喂给浏览器按真实字体测宽**，再与各断点可用宽度比较。
- **落点与命中判定不能取同一个边界值**：取同一个值会有 0.2~0.4px 抖动时判定翻转（「点附件、亮技能」）。修法是落点比偏移线多让出几像素——滚动少走几像素用户看不见。
- **锚点规则本身无解时要显式建状态，而不是继续调阈值**：页尾短区块永远排在长区块之后且已到滚动上限，任何「顶边越线」类规则都判不出它。正解 = 把「用户点到的就是当前的」建成显式状态。
- **凡「A 时刻算目标、B 时刻到达」的机制，都不能用静态窗口去校验，要用「到达信号」**：落点用「±24px 窗口」实测恒偏 40px（滚动过程中页面继续 reflow——懒加载图、字体、Spine 就绪）。正解是等滚动静默后复算，并覆盖 reduced-motion 分支（该分支没有滚动动画，必须自己释放）。
- **定位伪元素的包含块原点必须用真实哑元元素实测，禁止靠名词推导**：「padding box」有「外缘/内容区」两种口语含义。实测：包含块是宿主 padding box 的**外缘**，页面坐标 = `hostRect.top + css top`，**不加 padding**。
- **相对另一元素定位的装饰线，坐标必须相对同一个原点表达**：折角 `top` 相对 padding box、而注释里的「行顶」指卡顶 ⇒ 实现出来比图标中线低一个间距。
- **间距/尺寸类需求先把「单位 = 哪个既有令牌的整数倍」问定，再谈数值**：同一处缩进被连续三轮修正，前两轮都在数值层应答，从未问过单位/基准——用户的模型是「缩进必须等于既有尺寸的整数倍」。
- **标题字号决定「它上方多小的字会被读成 eyebrow」**（tasteskill `inspect.mjs` 的判据）：候选上限 = `min(18px, 标题字号 × 0.5)`，窗口 = 标题上方 `min(140, max(72, 标题字号×1.1))`。故 32px 的标题会把 15px 的分区入口算成候选（`min(18,16)=16 ≥ 15`），28px 的标题则把它排除（`=14 < 15`）。要压住这类误判有两条路：把标题收到 28px 以下，或把上方那段文字放大到 18px 以上。**末行同理**：`<600` 档 headings 门槛是 22px，24px 的页脚收束语会把上一分区的 11.5px 条目名读成压在其上方的标签——页脚收束语取 20px 即整类消失。
- **枢纽页品牌带的四处装饰是同一类坑，改底色时要一起清**：径向/线性渐变底、暗角 scrim（`linear-gradient` 透明→底色）、标题 `text-shadow`、`__supra` HUD 小字副标。替代物是**一个色调档**（`background: var(--surface)`，比页面底色 `--bg` 亮一档），不是新的装饰。`__scrim` 这类「为了在渐变上压字而存在」的元素，在底色变平色之后必须连同规则一起删除——留着就是一整块无来由的遮罩。
- **共享卡片自带的三处机器感会随页面一起被判罚，但只能在页面作用域内收敛**：`nk-idx-card` / `nk-lc-card` / `nk-relic-card` 内部的等宽字（星标数 / 技能名 / 套装标签）、`text-shadow`（艺术图上压字的投影）、渐变遮罩与稀有度渐变底，在首页登记区会被门禁逐个记成 mono / text-shadow / gradient / outlined-box。判据：这些是**共享原语**，目录页仍是原形态，故只在 `#nk-home-app` 内重述为「平色 + 正文体 + 无投影」；`nk-relic-card__plate` 的 1px 上下双线尤其要留意——板宽一旦 ≥240px 就直接多出一条 hairline 判罚（这是首页登记架轨宽上限的由来）。
- **大图的「原分辨率」比「画布尺寸」重要**：首页单条目分区的主图取 `avatarcutinfigures`（1560×1650 裁到 4:5）与 `lightconemaxfigures`（904×1260），而不是卡片图源（376×512 / 348×408）——后者在 389px 板上就已经是 1.03× 向上采样。选图时先量包围盒：`lightconemaxfigures` 的 alpha 包围盒等于整张画布（可直接用），`avatarcutinfigures` 只有画布的一半左右（必须裁，否则板上一半是空的）。
- **去掉渐变之后必须补材质，否则页面会读成「纯色块」**（用户实测反馈）。顺序是：先确认是不是自己把质地盖掉了——`--surface` / `--card` 这类承载面写成**不透明**时，`#app::after` 的纸感颗粒与 `#app` 的环境光影都被压在下面（颗粒层是 `position: fixed; z-index: 100001`，本身不会被遮，被遮的是下面那些有色的环境层）。两步都做才成立：① 承载面改**半透明**（`color-mix(in srgb, var(--surface) 76%, transparent)`），② 地面铺一张**这个主体自己的**真实材质图（首页＝游戏自己的 Wiki 背景 `bgpic/BgWiki`，1600×900、均亮度 32/255）。判据不是「看着有质感」而是可算的：把材质图 **12px 盒式模糊后取最亮区域**，该处对 `--text2` 仍须 ≥4.5:1（BgWiki 实测 5.23:1，`--text` 9.02:1）——够用就**不要叠 scrim**，因为 scrim 是渐变，会立刻多一条机器感；同时这张图本身算一张真实图片，正好补上「图像下限」。
- **滚动容器上的 `background-attachment` 语义与直觉相反**：`#nk-home-app` 是滚动容器，默认的 `scroll` 表示背景贴在**元素盒**上（内容滚动时背景不动，正是「地面」要的效果），`local` 才是贴着内容一起滚。用错会得到「背景跟着内容滑走」或「背景被拉成内容总高」。
- **方位词（正下方/中间/之下）必须当场落到具体参考点（哪条 x、哪条边）并配对比图**：靠形容词定几何，同一处会连续两轮来回改。
- **当既有形态在小视口上只剩「无承载物的结构」时，正确解是让结构在该断点退场，而不是继续调它的数值**（同一模式在留白归零、枢纽页、缩进三处共出现四次）。**注意：本判据在「整卡形态」这一级上有过一次用户裁决的反向覆盖**，见下方「断点专属形态退场」一条——两者不冲突：留白 / 缩进 / 装饰结构是**数值与支撑物**层，该退场；而「整个卡片长什么样」是**产品形态**层，用户要的是全断点一套。
- **判据的适用层级必须与用户问的层级对齐，否则「更省空间」会得出反向结论**：上一条的量化论证（手机档行式卡回收 60px / 343px ≈ 17.5% 横向占位）在**卡片形态**这一级被用户明确否决——用户原话「把手机断点下的排版，改成和桌面断点下用同一套，手机断点下，角色详情页面不再使用独立的排版布局」。教训：省空间是**手段**，不是目标；当用户说「要同一套」时，任何「窄屏更省空间」的论证都不是理由。
- **断点专属形态退场时，必须顺着它把「为它而生的配套」一并退场，否则留下的是双重装饰**：手机行式目录卡是无底无框、靠发丝线分隔的，因此首页版本上新带里曾为它补过一层表面（`padding: 8px 10px` / 1px 边框 / `--card` 底 / 圆角 / `min-height: 0`）。卡回到网格卡（自带 `::after` 边框 + 3:4 立绘）后，这层补表面变成**双描边 + 立绘被 padding 挤变形**。查法 = 退场时 grep 该卡的**所有**手机档声明位（不止它自己那个文件，还有复用它 `renderCard` 的宿主）。
- **「骨架与就绪同列同距」会被通用骨架规则从后源位劫持，而两边的选择器集合不对称**：骨架元素同时带两个类（`nk-skeleton__grid nk-idx-grid`），就绪网格只带一个（`nk-idx-grid`）。于是任何写在骨架族的通配规则（`--nk-grid-gap`、`grid-template-columns: repeat(2,1fr)`）都命中骨架、命中不到就绪 ⇒ 骨架 2 列 174px 对就绪 2 列 172px、320 档更是骨架 2 列对就绪 1 列。判据 = **给骨架族规则加 `:not(<就绪网格类>)`**，或让该页的 gap/列数显式重述。`src/styles/catalog.css`
- **「同一套排版」的验收必须断言形态指纹，不能断言「有网格 + 无溢出」**：行式卡形态本身也是「网格的 1 列 + 无溢出」，故弱断言在改动前后**都满分通过**——它锁不住这次需求。可判定的指纹需取「不随列宽变化」的四项：`display`（block 网格卡 vs flex 行）、立绘框 `aspect-ratio`、文字层 `position`（叠压 absolute vs 流式 static）、`<picture>` 双源是否存在；列数只作**单调相对关系**断言（视口变窄不得增列），不写绝对值。
- **圆头像与商店立绘的同名陷阱**：`avatarroundicon/1513.webp` 与 `avatarshopicon/1513.webp` **文件名同形**，只有目录段不同。断言「图源没按断点切」时比文件名等于没比，必须比 `currentSrc` 的**目录段**。
- **`flex: 1` 会让 `flex-wrap` 永不触发**：`flex: 1` 是 `flex: 1 1 0%` ⇒ 假定尺寸（flex-basis）恒为 0，容器**永远**判定「放得下」，折行分支一次都走不到。表现为「加了 `flex-wrap: wrap` 却没有任何换行」。要让「放不下才折行」成立，项必须写 `flex: 1 1 auto`（basis `auto` ⇒ 假定尺寸 = max-content）。本仓实测：卡名与星标同行时星标固定吃掉 42.4px（列宽 172px ⇒ 名字只剩 100px、整列宽的 33%），改成 `1 1 auto` + `flex-wrap` 后 12/13 语言的卡名截断归零，而 cn/cht/kr/jp 的卡体高度与改前**逐值相同**（不换行时不改变渲染）。`src/styles/catalog.css`
- **`flex-wrap` 的换行单位是「直接子项」，故语义上不可拆的组合必须自己包成一项**：改前「图标」与「标签文字」是容器直接子项、之间只有 `gap` ⇒ 行尾放不下时图标留在上一行、文字掉到下一行（换行单位细到了「图标 / 文字」）。包成一个 `inline-flex` 项后，换行单位才是「一项元信息」。
- **标点不能作为 flex 直接子项参与折行**：分隔符写成一个独立子项时会独自留在行末或被推到行首——行首的 `·` 命中 CJK 行头禁则（实测折行时 100% 命中：en 38/38、ru 82/82、de 74/74）。正解是挂到**前一项的 `::after`**（行尾 `·` 读作续行标记）+ `:not(:last-child)` 兜住无后继项的情形。
- **断点档位可能「倒挂」：更大屏的一档反而更窄**：`--nk-grid-min` 在 768~1023 档取 150 ⇒ 768 档实测列宽 153.5px，**比 390 档的 172px 还窄**，于是同一张卡在平板上的文字比手机上更挤（实测 768 档 en 9 张 / pt 11 张 / de 9 张卡名被 clamp，同样这些卡在 390 档只 3~8 张）。**断言「列数随视口变宽单调不回跳」不能发现它**——档位间的绝对值倒挂与单调性正交。判据 = 逐档记录**列宽绝对值**并跨档比对，而不是只比列数。
- **稀有度角标要「斜向折角飘带」时，绝不能让带身盒旋转——旋转盒的变换后包围盒会顶大祖先的 `scrollWidth`**：把带身 `rotate(45deg)` 放进 `overflow: hidden` 的立绘里，视觉上没问题，但立绘的 `scrollWidth` 会涨 ⇒ 直接命中 `e2e/layout-i18n-overflow.spec.ts` 判据①（`overflowX ∈ {hidden,clip}` 且 `scrollWidth > clientWidth + 1` 且无 ellipsis/clamp 且文本 ≥2 字）⇒ 报 `portrait +40px "★5"`。**给中间层加 `overflow: clip` 或 `clip-path` 只是把失败从立绘转移到那一层**——`clip-path` 既不产生滚动溢出区、也不阻止后代溢出向上传播。正解 = **带身盒与文字盒都保持轴对齐**，斜向形状由 `clip-path: polygon()` 在「与立绘右上角重合的轴对齐正方形」内切出，只把**带内文字**旋转；两盒都不出立绘盒 ⇒ `scrollWidth` 不涨。几何：记盒边长 S，带身边线 `y = x - S + m1` / `y = x - S + m2`，盒内四点为 `(S-m2,0) (S-m1,0) (S,m1) (S,m2)`，带身中心 = 四点均值 = `(S-(m1+m2)/4, (m1+m2)/4)` 即文字锚点。`src/styles/catalog.css`
- **角标尺寸别只写百分比——百分比盒 + 有上限的字号会让「填充率」随卡宽漂移**：带身盒取卡宽固定百分比时，带身垂直宽随卡宽线性增长，而字号受**层级约束**有上限（名字必须仍是卡上最大的字）⇒ 300px 卡上带身宽 53px 而文字仅 12px、填充率 22%，116px 卡上却是 48%，「跨尺寸节奏一致」当场不成立。修正是给盒边长也加 px 上限（`clamp(56px, 62%, 104px)`），把「字号已触顶而带身仍在变宽」那一段消掉，填充率收敛到 49%–55%。**判据 = 逐档算「字号 / 带身法向厚度」的比值，而不是只看某一档是否好看。**
- **新配色的对比度若不在 `check-contrast.mjs` 覆盖范围内，必须单列取证**：该守卫只算 `--text*` / `--primary` 对 `--bg`，角标「深墨文字 × 稀有度填充」这种**元素内配对**它一律不看。实测深墨 `--blk-900` 对 3★/4★/5★ 填充为 7.78 / 5.26 / 11.85:1，均过 4.5:1。**别把「守卫全绿」当成「新配色也验过了」。**
- **卡内「星级 → 名称 → 元信息」的层级要让位给**长语言**，不能按中文长度定版**：星标与卡名同行时星标固定吃掉约 42px（列宽 172px ⇒ 名字只剩 100px、整列宽的 33%），德语 / 俄语 / 葡语名普遍比中文长 30% 以上。正解是把**星级移出文字流**（挂到立绘右上角作 `position: absolute` 角标，`__portrait` 加 `position: relative` 作包含块），让卡名独占整列宽，并把文字层 padding 上沿从 34px 收到 26px 抵消角标腾出的空间。**判据 = 卡体高度与卡名 clamp 数按语言统计**，而不是「看起来是否整齐」。
- **「不换行 + ellipsis」不是长语言的解**：元信息（元素 / 命途）改成 `nowrap` + ellipsis 后实测 6045 张里 **497 张（8.2%）被截**、最长截掉 37px（`Электрический`）——因为触屏没有 hover，被截的元信息就是永久读不到。改回 `flex-wrap: wrap` + `gap: 2px 6px` + `line-height: 1.2` 后**截断归零**，代价只是卡体高一点。判据 = **换行代价为零时优先换行**（与 P2 分级一致）。
- **「名字 clamp 数」是本轮最灵敏的跨语言版面指标**：13 语言 × 6 档共 7254 张卡，修复前残余 89 张、修复后 **4 张（0.1%）**；且这 4 张全是同一个真实长名（ru `Дань Хэн: Освободитель Пустошей`，自然宽 277.7px / 盒宽 148~188px，需 3 行），属**真名而非缺陷**（有 `title` 复原）。**注意**：修复前那 89 张里有 15 张是 fr/de/pt 的**占位符串**（`{M#Pionnier}{F#Pionnière}·…` 天然更长）——**版面指标里混着数据缺陷时，必须先把数据缺陷剔掉再谈版面**，否则会为不存在的问题改版。
- **`space-between` 在负剩余时静默退化**：它只在剩余为正时生效，负剩余会退回 `flex-start` 并把内容挤进 padding 区。「固定盒高 + 均分」必须同时保证内容总高 ≤ 盒内容高。
- **骨架只代理「盒子」，不代理「结构」**：写一个「结构忠实」的小骨架反而更糟——就绪面板在窄断点因换行会显著变高，忠实小骨架变成欠预留。正解 = 固定盒高（取实测中位数）+ 内距逐档对齐 + 间距交给 `space-between`。
- **两个宿主共用的版面事实（如底板）必须只声明一次**：分成两处必然漂移，表现为数据到位时凭空弹出一块暗板。盒高对齐前必须先对齐内距，否则会把内距差算成盒差。
- **「数据里有、UI 里没有」要当成缺陷来查**：查法 = 拿数据字段清单与卡片模板比对。
- **内容覆盖审计的价值在假阳性分类**，不在「报了多少条」：直接拿原始 JSON 串去 `innerText` 里 `includes` 会有 90% 噪声。四类必查——占位符模板（须用**渲染后的值**比对）、枚举键（须比对本地化标签）、折叠内容（须先展开取状态并集）、换行/富文本（`\n` → `<br>`、剥标签后两侧归一）。
- **环境层只做光影、不做纹理（本项目类型的判据；取代此前 `tokens.css` 的「点阵而非直线网」判据）**：曾两轮尝试给 `#app` 加纹理底纹（120px 点阵、24px 方格纸网格），两轮结论一致——**档案型数据站不该有纹理底纹**。理由是可推演的：纹理要成立，要么它是主角（满屏主视觉），要么它有足够强度被读成图案；而本站有 1204 条数据路由、内容密度高，纹理只能压到**页面发丝线 `--line-1/2`（白 7% / 13%）之下**才不抢亮度，压到那个量级后它就在可感知下限附近，观感上近乎不可见——**投入（推导 + 贴图 + 守卫）与收益（几乎看不见）完全不成比例**。结论：质感预算交给 `#app::after` 的纸感颗粒（`--grain-opacity`，SVG `feTurbulence`，全站已生效）与内容本身。**判据**：一个视觉元素若必须压到"低于页面已有的最弱结构线"才能不冲突，它就不该存在。（上游判据的旧表述见 [ADR 0051](../adr/0051-终局赛季奖励进详情页.md) 对它的引用，按当时决策原样保留。）
- **参照站要分别量「UI 层」和「内容层」，别把插画的质感当成 UI 手法**：实测《明日方舟：终末地》官网两处（首页、页脚）**都没有噪点纹理**——全站 `feTurbulence` 0 处、无噪点伪元素、无混合模式噪点；首页背景是纯白 `rgb(255,255,255)` + 一张 KV 插画，页脚是**纯色 `rgb(37,39,38)` 且逐像素零噪点**（三个采样区块相邻像素差均为 `0.000`、色值范围宽度为 0）。用户感知到的"颗粒感"全部来自插画本身（内容区相邻差 29.8，UI 纯色区 1.79）。**手法**：拿参照站时先分别量「UI 纯色区」与「内容区」的高频噪声，两者差一个量级就说明质感在内容里，不在 UI 系统里——照搬 UI 只会得到"白底 + 一张图"的占位感。
- **「网格线在两点中间渐隐」只能烧进贴图，CSS 渐变表达不了**：那条衰减是**沿一条 1px 线的长度方向**变透明度——`radial-gradient` 只按**距离**、`conic-gradient` 只按**角度**分配强度，两者都没有「沿长度」这一维。实测：两个节点径向渐变画出来是**一片模糊方块**（4× 下像马赛克）、锥形渐变画出来是**风车三角纹**，都不读作线。要这个形态只能生成小尺寸贴图把衰减写进像素再平铺。
- **「看起来是透视网格」不一定是透视**：远处变密是 `perspective` + `rotateX` 的特征，但**均匀网格 + 低不透明度 + 小模数**在缩略/截图里同样读成「远处挤在一起」。判定必须查计算样式而不是肉眼：`perspective` / `transform` / canvas 三处任一非空才是真透视（实测 miHoYo 官网全页 `perspectiveCount = 0`、`canvasCount = 0`，网格是 23×23 PNG 平铺——连渐变都没用）。反推参数前先确认实现族，否则会照着一套不存在的参数去调。
- **别把「渲染摩尔纹」当成设计去复刻**：1px 线落在**非整数 pitch** 上会与像素栅格周期性错位，产生「交点重、段中轻」的起伏（官网 `background-size: 0.23rem` 在 1440px 下 = 19.17px，正是非整数）。但 1× 下四种模数（19.17 / 21.33 / 23 / 24）**肉眼几乎无差别**，起伏只在 −5% 亮度差量级——它做不成稳定的设计特征。
- **深色底上复刻「浅底暗线」时，要对齐的是亮度差而不是线色**：官网线 `rgb(233,239,246)` 相对底色 `rgb(248,249,251)` 只差 5~7 lum（读感＝几乎看不见的精密感）。把它同不透明度搬到黑底上不成——同一支浅色在黑底上比底色亮 230 lum 量级，会从「底纹」变成「明显的亮网格」。**照抄色值必失真，反推差值才对。**
- **素材层的推导参数必须有守卫，否则必然静默漂移**：贴图由脚本生成却把输出手抄进 CSS 时，改参数忘抄（或反之）会**继续用旧贴图、没有任何报错**。同理，形态退化（如线中段衰减过狠导致交点变孤立亮点）时**所有既有守卫都不看贴图像素**（色彩守卫只看裸色值、对比度守卫只算文字令牌 × `--bg`），只有截图放大才看得出来。**新增这类守卫必须实测两条失败路径都能拦住（构造漂移 + 构造退化），否则等于没有。**
- **触控命中区要按命中区量，不按视觉盒**：靠 `::before { inset }` 扩热区时只有 `elementFromPoint` 自中心向外扫才量得真实值；**扫得的是「自中心的半径」，命中宽高 = `left + right + 1`**，把视觉盒与半径相加会得出假值。
- **命中盒不能只看元素自身几何**：宿主是 `<label>` 时整块可点、是 `<div>` 时不可点——用真实点击落点验证。
- **铺量脚本里不要测命中区**（固定层遮挡 / 异步滚动下恒返回假数）；命中区交给逐组件专用探针。**宁可把指标留给专用探针，也不要在铺量脚本里出一个看似权威的假数字。**
- **铺量探针与契约探针必须共用一套豁免判据**（排除 `position: fixed` 层、排除「祖先 `overflow-x: auto/scroll`」内的元素），否则两边结论永远打架。
- **渐进增强的正确形态是「不支持 = 静态还原」，不是「不支持 = 停在末帧」**：`fill: both` + 时间轴驱动的动画在不支持滚动驱动动画的引擎上会跑完并停在末帧，媒体层位移恒为 36px——这不是「少个视差效果」而是构图永久偏移。凡此类动画都必须包 `@supports`。
- **越界判据不要豁免「被祖先裁剪」**：只豁免**用户可横向滚动到位**的祖先（`overflow-x: auto/scroll`），`hidden/clip` 不豁免；并先等过渡类消失再测量。
- **溢出列表若呈「整页同向位移」且首项带过渡 `-active` 类 ⇒ 过渡态假阳性**，不是布局缺陷；真溢出是局部元素、各处越界量互不相同。
- **纵向硬裁切必须「墨迹越界 **或** 元素布局盒越界」两档并取（少任一档都会错，两端都实测踩过）**：只看 `scrollHeight > clientHeight` 会把**已变换**后代（`rotate(45deg)` 装饰 + 放大图）算进可滚动区 ⇒ 假阳性（该区域在 `hidden`/`visible` 下**截图逐字节相同**，即无内容被裁）；只要求「元素后代布局盒越界」则**漏报纯文本裁切**——文本节点没有元素后代，而 `line-height: 1.12` 让行盒 33px < 内容 37px 这类**中文也命中**的缺陷正是如此。墨迹用 `Range.getClientRects()` 逐矩形比内容盒。判据自检必须含四条路径：真装饰放行 / 纯文本裁切报出 / 「装饰撑高 + 内层真超框」报出 / 正常文本放行。
- **`-webkit-line-clamp` 的 `scrollHeight > clientHeight` 是设计内行为，不是硬裁切**：被 clamp 掉的第 3+ 行本就计入 `scrollHeight`。判据必须先 `isClamp` 排除，再看墨迹——实测 858 个 clamp 元素「两行都完整渲染、越出盒 0 个、最小余量 0.10px」，把它当 P0「修」等于推翻既有的省略语义。
- **只写一个轴的 `overflow` 会静默改写另一个轴**：`overflow-y: visible` 与 `overflow-x: hidden` 并存时，规范把 `visible` **计算成 `auto`** ⇒ 容器仍可滚动。构造「不可滚动」的对照组必须写 `overflow: clip`（两个轴一起），否则实验臂与对照臂等价，会得出「修复无效果」的假结论（实测两臂同为 12/12）。
- **「文字不溢出」只修了一半，另一半是「换行后内容变高，底部工具组是否还够得着」**：`margin-top: auto` 的尾组在视口变矮时被推出视口**且永久不可达**（实测侧栏主标改换行后内容高 +114px，657~720 档新增 4~5 项不可达）。可达性判据＝`scrollIntoView` 后 `elementFromPoint(中心)` 命中自身；`getBoundingClientRect` 在视口外仍给非零 rect，**不能**用作可达证据。
- **铺量探针必须有「内容就绪门」，骨架退场 ≠ 内容到位**：目录卡在数据取回后才渲染，固定 sleep 会把「卡片未渲染」记成「零缺陷」（实测漏掉一整个语言档的 25 张卡名截断）。判据＝轮询 `document.body.innerText` 长度连续两轮不变且超阈值，再等两帧。
- **`page.addStyleTag({ id })` 的 `id` 被 Playwright 忽略** ⇒ 用 `getElementById` 做 A/B 清理时「注入的 before 样式」会残留进下一轮 after，把缺陷误记为 0（假阴性）。改用 `style[data-*]` 标记 + `remove()`。
- **共享工作区里「跨窗口的计数差」不构成因果归因**：同一选择器的 before/after 若采于队友改动先后（如侧栏宽度/换行）两侧，差值里同时含代码效果与版面漂移。要么用**同仪器 A/B**（同页面同扫描函数，唯一差别＝是否注入原声明），要么只给结构性结论。窗口未变时也要先证明（本项目实测 `--nk-content-offset` 未变，据此推翻了「内容区被挤窄」的假设）。
- **按类名前缀做归属/分簇时，键必须是该族独有的类名**：把共享的网格类（如 `nk-cat-grid`）放进某族的键里，会把**别的族**的卡算进该族计数（实测 A 族 390 档 112 条里 77 条其实是 B 族的 `nk-cw-*`），并据此写出错误的 before/after。
- **`<html>` 上的 `overflow: clip` 会让「整页横向溢出」断言恒为 0，从而查不到「被撑出列框」这类缺陷**：容器无裁剪时越出的子项直接压到相邻列上，而 `scrollWidth === clientWidth`。**判据必须落在容器与子项的几何相对关系上**（子项右缘 ≤ 所属容器右缘），不能只测页面级溢出。本仓实测：终局目录页列头（一行 4 个都不可收缩的项、可用宽仅 243px）145/208 个列头被撑破、最重 de +216px，而该页的页面级断言一直全绿；既有注释还把这个现象记成了「检测口径问题」——那是误判。
- **同一个模板不可同时当 aria-label 与可见文本**：读屏看不到「该元素紧邻什么」这层视觉相邻性，故 aria 模板常自带名字（`Guía de {name}`）；而可见文本若也带名，就会把紧邻的元素名再说一遍，宽度涨成「名宽 + 前缀」。实测 i18n 迁移时误把 aria 模板当可见文本 ⇒ de 徽章 268px > 列头可用 243px，**单项即超整行预算**。可见文本用短标签（`egd.guideLabel`）、aria 用含名模板，分工固定。
- **「只改文案」或「只改布局」常常单独都不够**：同一次溢出可能来自两条正交根因，必须分别实测。本例中「含名模板换短标签」后 de 仍越出 171px（模式名 `Schiedsspruch der Gegensätze` 自己就 285px > 可用 243px），而「只给容器加 `flex-wrap`」也仍留 2 处（单徽章一项放不下一整行）⇒ 文案与布局两处都要改。
- **「加宽容器」不是万能解**：本例把列加宽到 459px（4 列降 3 列）后仍留 47 处压叠——容器宽了，长译文也能长得更长。判据：先量「最坏语言下内容固有宽 / 可用宽」，若最坏项**单项**就超过整个可用宽，加宽只能靠牺牲列数换，应改换行 / 分档。
- **「参差」是**整排**性质，逐列治不好，必须让并排各项共用行轨**：列头「折几行」若由各列自己的内容决定，并排四列就各折各的（实测 33/156 组合参差），表现为「有的列徽章在第一行、有的在第二行」。治法 = 列项跨父网格两条轨（列头 / 列表）+ `grid-template-rows: subgrid` 认领之，则轨高 = 该排最高列头。**只给容器加 `flex-wrap` 治不了**——它恰恰是参差的成因；**只把徽章压到第二行反而更糟**（14/48 → 23/48），因为第一行自己也在逐列折行。`src/styles/endgame.css`
- **「整排统一」必须写成条件式（放得下就一行），别写成固定两行**：共用行轨只保证「同排等高」，**不保证**「该一行时就是一行」。列头内部若写成 `grid-template-rows: auto auto` + 徽章恒 `grid-row: 2`，那就是**无条件两行**——cn 的「名+en」自然宽仅 95~198px、宽列可用 249px+ 明明放得下，却仍占两行、行 1 与徽章之间空一大段（实测 cn 在全部 12 个宽度都是 81px）。正确形态是**两列网格**：列 1 元信息（可换行）、列 2 徽章，行轨 `1fr` ⇒ 轨高由**共享轨**决定，整排放得下就一行（~52px），某列过长才整排等长。**「是否升为两行」由共享轨高决定、不是逐列各判**，因此无需知道兄弟列内容、也不需要按语种写规则。`src/styles/endgame.css`
- **列头里「价值不大」的项就是纯成本**：条目计数（`nk-eg-col__count`，`margin-left: auto` 撑到右端）在列头这个「一行 4 个不可收缩项、可用宽仅 243~299px」的稀缺空间里，既不帮决策也不帮导航（玩家要的是「这期有哪些玩法」而不是「各有多少条」），却占着一个不可收缩位、把元信息行右端顶住。移除后元信息只余名 + en。**判据：列头每个元素都要能回答「它在帮用户做什么决定」**，答不出即是可删项——列头宽度是全站最紧张的一处，别把「有数据」当成「该展示」。`src/app/catalog/pages/endgame.ts`
- **判据缺了「放得下就必须一行」，无条件两行也能全绿**：只断言「排内四项参差为 0 / 越界为 0 / 徽章不被拉宽」时，固定两行结构**满分通过**——这四条都不关心「本来该一行」。必须补两条互补断言：① 该排元信息**视觉行数为 1**（按子项底边聚类）⇒ 列头盒高必须回到一行量级且徽章与文字**纵向重叠**；② 有列过长 ⇒ 排内四项参差为 0。**「参差 0」与「形态正确」是两件事**，前者只是后者的一半。`e2e/layout-endgame.spec.ts`
- **数「文字行数」必须用 `Range.getClientRects()`，不能数子元素的盒底**：子项是 flex 项（blockified），**名字自己折成两行时它的盒底仍只有一个** ⇒ 按盒底去重恒得 1 行，判据把「两行」误判成「放得下」。这个仪器 bug 一度被一个并排子项掩盖（存在时那个项停在第 1 行、名字占第 2 行，两者盒底不同，侥幸得 2 行），**把并排子项删掉后同一仪器立刻开始假红**——看着像布局回归，其实是仪器一直错。`Range` 取到的是真正的文字行盒（一行一个 rect），按纵向重叠合并即得行数，对 `en` 与 `name` 基线对齐的情形也对。**仪器错与布局错要分开归因**：先证明仪器在已知真值上读数正确，再拿它判布局。`e2e/layout-endgame.spec.ts`
- **`subgrid` 认领行轨后，列项的那一列必须显式钉成 `minmax(0, 1fr)`**：只写 `grid-template-rows: subgrid` 时内部那一列是隐式 `auto` 轨，其最小尺寸函数是 min-content，会被最长的列头项撑开 ⇒ **列头盒比列框还宽**（实测 headW=383 vs colW=288，最大 +345px）。原块级形态下盒宽恒等于列框，故这是改用 `display: grid` 带进来的静默回归、`minmax(0, …)` 关掉下界即消除。`subgrid` 只约束**行**轨，列的收缩性不会被它顺手解决。
- **越界判据必须逐层量「盒 vs 容器」，只量子项会漏掉中间层的撑破**：拿「子项 vs 列头盒」当判据时，列头盒自己被撑宽到 383px 也判不出来——子项相对它并不越界。**每加一层布局盒就要多一条「该盒 ≤ 父容器」的断言**。同一个探针在补上这一层后才从「34/48 命中」显出真相。`e2e/layout-endgame.spec.ts`
- **`container-type: inline-size` 不能挂在 subgrid 子项上**：挂了会让该元素成为容器、行轨塌陷（实测列头由 81px 炸到 383/556/896px）。要按自身宽度做条件分支时，挂在**内层**（列头）上，而不是跨轨的列项上。
- **容器查询的阈值以容器\*\*内容盒\*\*为准，且换来的收益要按「列宽档」而不是「视口档」折算**：同是 4 列档，列宽随视口从 261px 变到 464px，收益与列宽挂钩、与视口不挂钩（写视口断点必然在某几档空转）。列头内距合计 16px，故 `max-width: 300px` 对应列宽 ≈316px。判据：阈值两侧都要有实测档位证明「该触发的触发、不该触发的分毫不动」。
- **窄列隐藏「全语言共有的占位项」能降高度，但容器查询选不出「真正受益的那些列」**：英文副题在四种模式下全语言都存在、是稳定的宽度开销，隐藏它确有效（**并且它常常是「宽列能否回到一行」的前提**：cn 保留 EN 时元信息自然宽 198px，而窄列可用仅 151~191px ⇒ 一行放不下、仍是两行；隐藏后降到 95px，各档全部放得下）。**但阈值只能按列宽切，而「EN 是否多撑一行」还取决于模式名多长**——同列宽 261px 下 13 语言里只有 6 种真省一行，另 7 种（cn/cht/jp/kr/fr/de/pt）省 0 行却一并被隐藏。容器查询看不见「名多长」这个变量，故「隐藏」这一档**天然会误伤一部分语言**；收益是真的，精确性是假的。- **三种「不隐藏 EN」的替代方案实测都不成立（留档以免重走）**：① `flex: 0 1 auto` + `min-width: 0`（让 EN 收缩）⇒ 收益 0，因为 `flex-wrap: wrap` 下 EN **优先换行**而不是收缩；② `flex-wrap: nowrap` + EN 收缩 ⇒ 收益 0、且列头**更高**（名被迫折行，89px 比不隐藏还高）；③ `nowrap` + `min-width: 3ch` 同上。结论：在「`wrap` 容器里降行数」这个目标下，**只有 `display: none` 能真正减少行数**，收缩类方案一个都换不来高度。**「省高度」与「都显示」二选一，没有第三态**。
- **别按语种写规则**——语种只是列宽的代理：ru 在 480/1920/2560 是单行、在其余档是两行，按语种写必然在部分档位判错。
- **同一个组件的多个宿主宽来源不同 ⇒ 视口断点必然判错，此时容器查询不是优化而是正确性手段**：角色卡（`.nk-idx-card`）同时被目录网格（随 `--nk-grid-min` 与列数）、首页品牌带（`min(300px, 82vw)`）、枢纽带（定宽 `190px`）三处复用。实测 390 视口下目录卡副行 148px、首页卡 276px——**同一视口、同一组件、两种结论**。判据：只要「一个组件被 ≥2 个宽度来源不同的宿主复用」，按视口写的条件就必在其中一处错。`catalog.css`
- **「放不下就换一种表达」比「让它折行」更能根治折行**：`.nk-idx-card__meta`（属性 + 命途）在窄卡上必然折行——去掉分隔点后仍余 841 张，因为 ru `Электрический` + `Разрушение` 两个官方名光文字就 156px，而手机 2 列档副行只有 148px，**是文字自身放不下，不是装饰占位**。改为「副行 <196px（13 语言叉积最坏需求宽）时只留图标、文字转 sr-only」后折行归零。要点：① 阈值必须取**全语言叉积最坏值**而非当前语言实测值，否则切语言会改变卡片密度；② 文字转 sr-only 而非 `display: none`——`alt=""` 的语义是「此处无需替代文本」，它在窄卡上恰是唯一的属性文本载体，删掉文字等于该信息从无障碍树消失；③ 容器查询块必须写在基础规则**之后**，它不提升特异性，写在前面会被同特异性基础规则静默盖掉。`catalog.css`
- **`flex-basis: 100%` 会把该 flex 项拉成整行宽，不是「让它单独占一行」**：主尺寸变成容器宽 ⇒ 徽章胶囊被拉成横条（实测 624/624 个被拉宽，最宽 588px vs 自然宽 82~157px），而**子项越界类断言全绿**——被拉宽不是越界，这类变形只有量「元素自身宽 vs 自然宽」才看得见。要「贴到末行且保持自然宽」须用 grid：`align-self: end` + `justify-self: end`。`src/styles/endgame.css`
- **容器的「不透明底色」与页面底色同值时，唯一可见效果是把 fixed 背景的环境光裁成一块矩形**——那是缺陷不是材质。**给区块加底色前先问「这层底色的可见效果是什么」**；上面有 fixed 背景/环境光层时，实测它被裁成了什么形状。`src/styles/endgame-detail.css`
- **网格里 `display: none` 的格子不占轨** ⇒ 自动布局的稀疏推进不可依赖；**后续格必须显式写 `grid-column`**，否则被甩回第一列并撑出横向溢出。`src/styles/endgame-detail.css`
- **flex 行内要让名称可压缩**：给 `overflow: hidden` 即取得自动最小尺寸 0；反向的 `flex-shrink: 0` 会让该元素的 ellipsis **完全失效**，整串越出列框压到相邻列。`src/styles/endgame.css`
- **异步补入的内容会撑高区块、把下方整体推下去** ⇒ 必须在「就绪态翻转」之前 await 取数，否则这段高度计入 CLS。`useCwReleaseShowcase.ts`、`ReleaseShowcase.vue`
- **CSS 分栏（`columns`）不要给子项覆写 `display` / `width`**：行本身是 flex 行，改成 block 会压成上下堆叠、整页反而变长；分栏只需 `break-inside: avoid`。`src/styles/endgame.css`
- **别把 UI 页签小图（144×144）用 `cover` 当背景大图**：先量 `naturalWidth` 与显示盒，放大 > 2 倍必然糊；背景用色彩/渐变，图标只在原尺寸内缩处用。`src/app/catalog/pages/endgame.ts`
- **同一页同类区块必须同左缘，判据取「盒左缘」而不是文字左缘**：区块标题自带 `padding-left` + `border-left`，拿文字左缘比会假红。`src/styles/currency-trait-detail.css`
- **「横向可滚」不等于「用户能找到」**：横滚容器必须给溢出提示，且提示**只在真溢出时出现**（用 `mask-image` 渐隐，不引入新颜色块），并且**方向要对**——静态只挂一侧的渐隐是方向盲的：横滑到中段时左端文字被硬切（实测「加成」→「|成」），滑到末尾后右端又在渐隐已经滑到头的末项。状态由容器上的一条 `data-*`（start / middle / end / none）+ 被动滚动监听写入，CSS 按状态切三段渐变；**不要用 `animation-timeline: scroll()`**（滚动驱动动画 Firefox 不支持，缺 `@supports` 门时它按普通时间轴跑完并停在末帧）。`src/styles/catalog.css`、`src/styles/character-enhance.css`
- **横滚条里的「当前项」高亮必须由条自己滚进可视区**：高亮由页面滚动驱动而条不跟着滚 ⇒ 10 项里靠后的高亮**永远**在条外（实测页面滚到中段时高亮项 left 442、导航可视区只有 16~374），用户读到哪一节在条上完全不可见。判据取「高亮项相对导航可视区的左右内缩都 ≥ 渐隐带宽度」，**不是「`scrollLeft > 0`」**（后者只要滚过一像素就绿）；跟随还要给用户让路——手指按在条上或刚滚过（实测 1.2s 窗口）时不抢位置。
- **CLS 取证必须 dump 位移节点（`layout-shift.sources[].node`）**，只报数值查不出病根。图片**未解码时不产生盒子**：`max-width` 不定宽 ⇒ 首帧高 0、图到后整块下跳；修法是 `width: X%` + `aspect-ratio`，**不是 `min-height` 魔数**。
- **把文字放进「宽度由图片钉死的窄列」（图下方标注位），两道换行规则缺一不可，且只有第二道能被中文验证**：① 去掉 `nowrap`——`nowrap` 的文字按 max-content 撑 `auto` 轨，会把这一列连图带列一起撑宽、挤窄相邻列（本例 es / fr / pt / ru 的徽标宽于 104px 立绘）；② `overflow-wrap: anywhere`——`white-space: normal` **只在空格处断行**，德语复合词 `Korruptionsstufe` 实测 ink 108px，在 104 / 84px 列里是**单个不可断词**，整体放不下就溢出列框，而该列无裁剪 ⇒ 直接压到相邻列上。判据：`overflow != visible` 的溢出探针看不见它（列自身 `scrollWidth > clientWidth` 才看得见），只跑缺省语言的用例也看不见它。`src/styles/endgame-pollution.css`
- **`flex-wrap: wrap` 的容器里，一个 flex 项仍可能把容器撑破——因为「能换行」只保证它独占一行，不保证这一行装得下**：项默认 `min-width: auto`（= min-content）不可收缩，项自身 min-content 一旦超过容器可用宽，它就原样溢出。实测：`.nk-egd-summon`（图 26px 不可缩 + 名 + 污染徽标）在 390px 手机档 min-content 232px > 可用 214px，长译文名让整行拒绝收缩，溢出沿 `__list → __summons → __data` 撑破敌方卡（en 4 / es 40 / fr 28 / pt 25 / ru 21px）。**三个「看起来该有用」的修法实测全部无效**（给行内徽标加换行 / 列表 `inline-flex` 改 `flex` / 行 `min-width: 0`——真正不可缩的是行内的名字）；有效解是给该行加 `flex-wrap: wrap`，让**徽标**在名字需要整宽时落到次行。**判据必须逐容器量 `scrollWidth`**：`html` 上有 `overflow: clip` ⇒ 页面级溢出恒 0，既有溢出守卫与 `noUnknownOverflow` 全绿。
- **「溢出清零」不等于「修好了」——断长词的两种写法会把行压成竖排，且溢出指标对此完全无感**：`overflow-wrap: anywhere` / `break-word` 确实能把上述溢出清零，代价是名字被压到 min-content 逐字断行（实测 es 名宽 34px、**12 行**逐字竖排；en / de 6 行），比原溢出更难读。**溢出是「量」的问题，断成竖排是「读不了」的问题。**故凡「让文字可断」的修法，必须同时量**该文字的渲染行数**（`Range.getClientRects()` 或盒高 ÷ line-height）与**它的可用宽是否被前一项挤没**；只看 `scrollWidth` 会把逐字竖排判成修好了。`src/styles/endgame-pollution.css`
- **扫「多语言溢出」时，点完 tab 不等稳定就把中间态记成缺陷 = 假阳性；反之，A/B 不真撤声明 = 假阴性**：前者实测同一 tab 组合在 700ms 采样报「溢出 19/35px」、稳定态恒 0（也有反例：换了等待时序后同一页稳定报 17px，**必须两次都验**才敢定性）；后者更隐蔽——把「改动已生效」的页面当基线，会把改动自己造成的退化记成基线本来的样子（本例差点据此保住把名字压成逐字竖排的错解）。故契约里量之前先 `waitForTimeout`，A/B 对照必须**真的撤下被测声明并重跑**。
- **块序按「信息周转率」排，不按「业务上它和谁成对」排**：终局赛季页曾把奖励板（通关条件｜通关奖励 / 星级目标｜星级奖励）放在关卡面板首块，理由是奖励与通关条件成对；但奖励载荷**逐期恒定**（忘却之庭 1033–1036 十二层同载荷、回合上限恒 30；虚构叙事 / 末日幻影同样逐期重复，见 [ADR 0051](../adr/0051-终局赛季奖励进详情页.md)），而增益与敌方配置逐期变——用户裁决整块垫到面板底部。判据：**跨期不变的信息让它垫底**，首屏留给当期会变的内容；下沉前先确认它承载的可达信息在别处已有一份（本例「回合上限」已在半场卡片上，故下沉不损失可达信息）。`src/app/endgame/EndgameFloor.vue`、`EndgameTierce.vue`、`EndgamePeak.vue`

## 排查路径

- **CSS 的最小解析单元不是行，是 `{` / `}` / `;` 三个定界符**：按行解析会把多行选择器组的声明只记到最后一个选择器上（真命中 5 → 93）；跨行声明值的续行会被当成选择器；`stripComments` 替换成单个空格会删掉注释内换行导致行号前移（应替换成**等长空白但保留换行**）。
- **删死声明必须用「前后计算样式快照 diff」验收**：N 路由 × M 视口 × 逐选择器 computed style 做 before/after diff，零差异才算纯删——截图看不出 0.02rem 的差。
- **命中不都是缺陷**：`focus-visible` 收掉投影、断点反向补偿、粘性表头底色、主题变量分组这类刻意变体会命中重复选择器检查；工具的价值是把「谁会静默吃掉谁」摆上台面。
- **任何 CSS 候选实验都必须先自检「注入的规则真的存在且 computed 值随之改变」**：`addStyleTag` 会被 SPA 导航冲掉；`addInitScript` 注入的 `<style>` 实测根本没进 head ⇒ 「4 个候选全 FAIL」实为假失败。**「全 FAIL」比「全 PASS」更可能是探针坏了**；最可靠的是「临时改写真实文件 → 实测 → 还原 → 校验 hash」。
- **验证过渡类改动必须同时断言两件事：① 类名命中；② 存在插值中间帧**。仅断言前者会漏掉「动画被全局规则静默吃掉」这一整类缺陷，而它恰好让用户报告的观感问题**完全没被修好**。
- **先用「未修复态」确认探针真的会报错，再用它验修复**——否则无法排除「探针失灵导致假 PASS」。
- **采集计算样式要避开主题过渡窗口**：强调色在挂载后落到 `data-accent`，根节点会被临时加类并用 `!important` 覆盖所有组件的 transition；固定延迟后采集会读到它。
- **期望值必须从实际数值算出，不能凭语义直觉**：路由过渡方向曾两次按「目录互切应该平级」判断，而实际方向由 `meta.depth` 差值决定。
- **采样平滑滚动的断言必须轮询到稳定态**：固定 `waitForTimeout` 得到的是动画快照不是页面状态（同一动作的可达 `scrollTop` 多次运行差 20~40px，一度让人以为「改动没生效」）。用 `expect.poll`。
- **`complete` / `naturalWidth` / `currentSrc` 类断言前面必须有等待**，否则它的通过与否取决于跑在前面的用例。固定 sleep 常是这类断言的隐式契约——**删它之前必须审计所有「紧跟在它之后读取异步落地值」的地方**。
- **拍带 lazy 图的区块必须等到块内图片 `complete` 再截**，否则会把「还没加载」拍成「加载失败」并去修不存在的问题。
- **`locator.hover()` 会自动滚动**把元素滚进视口，虚拟列表随即重排 ⇒ 读到假的位移；改用手动 `mouse.move` + 只测完整落在视口内的元素。元素身份键用 `className + data-name/文本`，不要用 DOM 下标。
- **判 hover 抖动要比 `offsetTop/offsetLeft/offsetWidth/offsetHeight`**（不受 transform 影响，有意动效不会被误判）。
- **数据为空时元素可能整个不渲染**：多点采样脚本里任何 `querySelector` 未判空都会在跑到那条数据时整轮崩掉。
- **冻结动画源再取样**：Spine / parallax 必须隐藏，否则动画帧让相隔 1.2s 的两张截图差到 0.02+ 亮度；`color: transparent` 去字形**必须作用到后代**（有直接 `color` 声明的元素会压过父级，于是把字形本身当底衬，量出 `vsWorst = 1.0` 的假失败）；大图必须等 `Image.decode()` 完成再取样。
- **「最坏单像素」是包络不是判据**：同一批数据里它给出 1.02:1（听起来全页崩了），分布口径才给出真实形状。它能把「4% 的像素」讲成「整体不达标」，也能把「零遮挡」讲成「必须垫板」。
- **结论必须取「全部样本的最坏像素」而不是单只数据的均值**——单一样本实测会给出乐观偏差；AA 类判据要按逐字形像素的分布判（最坏值 + 失败占比并列）。
- **截图与量测冲突时，先问「两次观测是不是同一个状态」，不要挑一个信**：裁图在滚动进视口之后拍（图已加载），量测拍的是未加载态 ⇒ 两者都对。

## 坐标系与断点

- **base 改了 `display`，断点块里只写 `gap` 不会继承结构**：桌面网格化后手机断点必须显式回 `display: flex`。
- **走文档流的页不能用视口级 `margin: 0 auto`**：侧栏偏移后居中基准与侧栏避让页差一个侧栏宽，要用 `calc(offset + max(0px, (100vw - offset - detail-max)/2))`。
- **走文档流的详情页拿不到 `.nk-page--detail` 的侧栏避让，必须自己声明**：那份避让是 `position: absolute` + `left: var(--nk-content-offset)` 提供的，页面一旦改成文档流滚动（如敌方详情页要自己避让 <768 的固定底栏），整页就退回「版心以视口居中」⇒ **768~1279 视口被侧栏压住**（1024 实测 hero x=12、区块标题与 HP 值被裁，1280 起才偶然不重叠）。修法：页面容器 `padding-left: var(--nk-content-offset)`（该令牌 <768 为 0，无需媒体查询）。**这类缺陷不会报错、只在特定视口可见** ⇒ 新增/改造文档流页面时同批补一条「内容左缘 ≥ 侧栏右缘」的几何断言（`e2e/layout-monster.spec.ts` 有可抄的形态：读令牌落值 + 比 rect，而不是写死 x）。
- **避让一改，hero/骨架的固定盒高就要按断点重标**：内容区左缘右移会压缩可用宽度，图列驱动的 hero 高度随视口线性变化（敌方详情页避让后新增 1024~1149 档 314~358 的渐变），骨架屏不拆档就会在加载完成时整块下跳。
- **覆盖一个方向时必须只写该方向**：负外边距写成 `margin: -6px 0` 简写会把基线的 `margin-left: auto` 一起清成 0，靠右对齐的入口当场退回标签右侧。用 `margin-top/-bottom`。
- **改导航块序要连带查三处**：① 手机档分隔线是**按序画的**（修法是改画位置而非删线）；② 折叠算法按选择器量宽度预算，**改类名或换标签元素就会静默破坏底栏折叠**；③ 工具组在手机档是 `display: contents`，加减条目会改变底栏槽数，须按最窄档复测槽宽。
- **「改短文案」必须按最窄档复测**：底栏槽宽有隐性预算（`flex: 1 1 auto; min-width: 44px`、标签 `white-space: nowrap`），2 字变 4 字等于标签宽度翻倍。
- **量 DOM 几何来算布局 ⇒ 结果被「当前状态」自锁**：`recomputeFold` 原先读 `.ui-sidebar` 内各元素的 `offsetWidth` 算折叠，而该盒的宽又由折叠结果决定——且量到的「固有宽」等于**该语言标签的像素宽**，于是槽位数被译文长度决定（390px 实测 cn 5 项 / pt 3 项）。**判据：布局算术的输入必须全部来自「视口 / 令牌 / 常量」这三类与自身状态无关的量**。现在取 `clientWidth`（= 视口宽）与 `--nk-nav-*` 令牌，槽位数成为纯视口函数。
- **`flex-basis: auto` 让「元素内容的长度」渗进布局分配**：并列项只要写着 `flex: 1 1 auto`，其固有宽就是内容宽，任何「按宽度取前 k 个」的算法都会随文案长度漂移。并列且需等分的槽位应写 `flex: 1 1 0`（并显式 `min-width: 0` 覆盖基类的 `min-width`，否则拒绝收缩反而撑破容器）。
- **预算里扣掉的必须是「盒宽」不是「线宽」**：分隔线写 `width: 1px` 但带 `margin: 0 3px`，实际占 7px。按 1px 扣会连续低估 6px × 条数，槽宽悄悄落到 44px 触控下限以下（实测 43.3px）而任何断言都不报错。
- **折叠项「留在 DOM 里用 CSS 藏」还是「不渲染」是契约级差异**：前者让 e2e 能用「底栏里找得到该 href」断言入口可达，后者必须改成「底栏直连 **或** 抽屉内可达」（`e2e/layout.shared.ts` 的 `navEntryReachable`）。改成不渲染时，所有「`.ui-sidebar a[href=…]` 存在」式断言都会在窄档变红——**那不是缺陷，是判据过时**。
- **「全量放得下就不预留溢出入口」是有序的两段判断**：一上来就预留「更多」槽，会让原本刚好铺满的档位退化（CW 6 槽位 → 5 项 + 更多）。先判全域、再判折叠。

## 工具链坑位

- **`String.replace(re, (match, p1, p2) => …)` 的回调第一参是整个匹配**：写成 `(num, unit)` ⇒ `unit` 恒为数字串、`parseFloat('0.82rem') = 0.82`，于是**只有 px 声明被映射、全部 rem 声明静默落进 leftovers**。
- **收口刻度必须同批收口注释**：所有「主字 3.2rem × 1.12 = 57.34」式注释会变成谎话，按仓库约定改成**引用令牌**。
- **PowerShell 的 `switch` 里 `continue` 只跳出 switch，不跳外层循环**：用它做「命中行 → 替换行」的 map 时替换后原文仍会被追加一次，静默产出**重复 CSS 声明**（后者覆盖前者）。改用显式标志或 `Hashtable.ContainsKey`。
- **整文件重写会污染「病态行尾」文件的 diff**：本仓四类行尾并存（`CR CR LF` 的源文件、每行尾多个 `CR` 的畸形态、正常 CRLF、纯 LF 的 `docs/**`）。用 `edit` 工具改前者会触发整文件重写（diff 由 29/1 膨胀到 181/153）。**病态行尾一律用「读原文 → 按原行尾切片 → 只替换目标行」的字节保真脚本。**
- **一条字号/刻度只允许一个声明点**：末块导入的收口文件是唯一声明点，前段凡是重述同一属性的都是死声明——**改它不生效**。
- **骨架/就绪这类「两处必须同值」的对，先找令牌而不是再算一遍常量**。
