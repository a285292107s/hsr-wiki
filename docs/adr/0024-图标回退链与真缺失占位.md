# 0024. 图标回退链与真缺失占位

## 状态

`accepted`（**已实现**：图标位改走双源回退绑定 `data-cdn-fallback`；双源皆失效后由全局委托换「图标占位」；converter 侧同批把 `1{charId}` 伪目录归一前移到源路径级）

## 背景

用户原话：「调用agent team ，进行下一轮任务，如何图标真的缺失，则显示一个占位图标。」（`如何` = 「如果」）——诉求是**真缺失时必须有视觉出口**，而不是只留破图 / 空白。

改动前的三个结构缺陷：

1. **回退链断在模板绑定层**：`iconUrl()` / `skillIconUrl()` 只返回**主源** URL，模板只绑 `:src` ⇒ 全局委托读不到回退源（`data-cdn-fallback`），主源 404 后直接判死。
2. **终态无语义**：「资产真缺失」与「CDN 不可用」共用同一终态（`data-cdn-down` → CSS 隐藏 → 卡片渐变底承接），读起来就是空白——既不表达「此处无图」，也不区分环境故障。
3. **离线判定不了**：converter 无法判定「nanoka 上真存在的文件名」——上游同一角色的同一图标自己就混用两套命名，两个方向都实测到了：

| 角色 | `1{charId}` 伪目录名 | 归一后的角色名 | nanoka 实测 |
| --- | --- | --- | --- |
| 1310 | `SkillIcon_11310_*` | `SkillIcon_1310_*` | **旧名 200 / 新名 404**（归一后多一跳回退） |
| 1212 | `SkillIcon_11212_*` | `SkillIcon_1212_*` | 旧名 404 / 新名 200 |

两套命名**互为反例** ⇒ 「数据归一」永远只能部分修复；而 **jsDelivr 侧新旧命名全 200**（1310 / 1205 / 1212 三例共 5 行实测）⇒ 承重修复只能是**前端的双源回退链**，数据归一的作用是让多数图标少一跳。

## 决策

1. **图标位绑双源**：`src/lib/icons.ts` 的 `iconImgAttrs(url)` 返回 `{ src, 'data-cdn-fallback' }`（回退源由 `cdnFallbackFromPrimary` 反查），消费方 `SkillCard.vue`（技能图标 + 强化来源图标）、`OverviewPanel.vue`、`ComparePanel.vue` 必须**同时**绑这两个属性；**禁止**再绑 `hideOnError`（会抢在回退前隐藏）。
2. **终态换占位**：全局委托在首选源与回退源都失败后，把 `src` 换成共享常量 `MISSING_ICON_SRC`（`src/services/cdn/placeholder.ts`：内联 SVG 描边问号、中性灰），并打 `data-cdn-placeholder`；原 URL 存 `dataset.cdnSrc`。
3. **占位是 opt-in 的终态**：`isCdnDown()` 短路（环境故障）走 `markDown(img, true)` 不换占位——满屏占位比留白更吵，且恢复链会整页重载；`data-cdn-noph` 是同类 opt-out 入口（`dom.ts` 有分支、单测覆盖，但**当前没有生产代码写入它**，见「分工与优先级」）。
4. **隐藏规则随之收窄**：CSS 由「`data-cdn-down` 一律隐藏」改为 `img[data-cdn-down]:not([data-cdn-placeholder]) { visibility: hidden }`（占位必须可见，真缺失才有视觉出口）。
5. **降级态只有一个出口**：`clearDegrade(img)`（清 `data-cdn-down` / `data-cdn-placeholder` / `dataset.cdnSrc`）供四条路径共用——真源自愈 `load`、CDN 恢复的 `reloadDownedImages`、组件接管后的 `load`、换源观察者 `watchDegradedSrcSwap`。占位路线的清降级判据是**「占位是否已实际加载」（`placeholderLoaded` 状态）而非 src 值**：占位自身那次 `load` 只置位、不做清理；**占位已加载之后的任何真源 `load`**（含**同源重试成功**，即 `src` 等于记录的原失败源的情况）**一律清降级**（清理前用 `!isPlaceholderSrc(img.currentSrc)` 排除仍是占位的情况）。监听必须**常驻**——**禁止** `{ once: true }`：真实浏览器里占位自身那次 `load` 与组件接管那次是两个独立事件，一次性监听会被前者消费掉。
   **配套 `watchDegradedSrcSwap(img)`**（`MutationObserver` 观察 `src`）：已降级元素被组件换成新源时，若新 `src` 既不是 `dataset.cdnSrc` 记录的原失败源、也不是占位 ⇒ **先 `clearDegrade`**，把元素还原成普通图片，让新源自己的 `error` 重新走完整回退链（含重新落占位）。缺了它，`markDown` 首行的 `if (img.dataset.cdnDown) return` 会早退、不再重新判定 ⇒ 可见破图（见「后果 · 负面」）。
6. **数据侧只做部分修复**：converter 把技能 / 忆灵技能 / 星魂 / 行迹（含 enhanced 包）的 `1{charId}` 伪目录归一**前移到源路径级**并单点收口到 `_map_skill_icon = map_icon_path(_normalize_tree_icon(...))`——目标不是「改对文件名」，而是「把命名统一到一套，剩下的 404 交给前端回退链」。

## 后果

**正面**

- 真缺失有了视觉出口：中性占位（描边问号）读作「此处无图」，与「CDN 故障留白」在视觉上可区分。
- 1310 / 1212 两套命名互为反例的情况下图标仍能加载——jsDelivr 对新旧命名都有资产，回退链把「离线不可判定」转成「运行期多一跳」。
- 恢复链仍能还原真源：`dataset.cdnSrc` 让被占位顶替的 URL 在 CDN 恢复后重载。
- 技能 / 星魂 / 行迹三处 `--official-icon-paths` 下的归一静默失效同批修掉（见「负面」第 3 条，本轮已收口）。

**负面**

- **委托会改写 DOM 的 `src`**：`dataset.cdnSrc` 是恢复的**唯一来源** ⇒ 任何清 `src` / 重建节点 / 克隆 DOM 的路径（v-html 重渲染、虚拟滚动复用）都会让恢复链丢源；新增图标消费方必须走 `iconImgAttrs`，**禁止**自己拼 URL 或覆盖 `src`。
- **占位与组件自带兜底的次序竞态（结论：组件胜，但优先级依赖一条不可见顺序）**：全局委托在 **document 捕获阶段**先跑，组件的元素级 `@error` 后跑且**最后写 `src`** ⇒ 有组件级兜底的图标面（物品卡立方体 / 遗器部位图 / 终局 buff 星形 / gridFight 属性图标）以组件为准，全局中性占位**不会**盖掉它们。代价是这条优先级完全依赖「捕获先于 target + 组件后写 `src`」这一隐含顺序：**任何在组件 `@error` 里提前 `return` 而不改 `src`（或把 `src` 写回同一个失败源）的写法，都会让占位胜出**。故必须有测试兜底——本轮是 `cdn.test.ts` 的路线用例（含「占位 → 组件换源 → `load` → 标记全清」）+ `e2e/layout.spec.ts` 两条 1212 断言。
- **`--official-icon-paths` 模式的归一陷阱**：该模式下 `map_icon_path` 产出 `skillicons/avatar/{id}/...` 前缀，若归一发生在映射**之后**就匹配不到、**静默跳过**（技能 / 星魂 / 行迹三处同款洞）。本轮 converter 把归一前移到源路径级并单点收口修掉；日后任何绕过 `_map_skill_icon` 的新图标构建路径都会复现该静默失效。
- **数据归一会让部分图标多一跳回退**（实测 1310 的 3 行由 nanoka 200 变为 404；1205 `1120508` / 1212 `1121209` 两命名在 nanoka 均 404）⇒ 可用性现在**依赖 jsDelivr 与前端回退链**，任一失效即破图。这是有意用「命名统一 + 运行期回退」换「离线不可判定」的代价。
- **占位图形是 data URI**：内部不能用 `var()`（故取固定中性灰，由 `check-colors` 对严格中性豁免），且随容器缩放 —— 宿主必须自行保证占位尺寸。
- **跨浏览器/环境差异被固化进实现（两个独立约束，都不可回退）**：① 占位自身 data URI 的 `load` 与组件接管那次在真实浏览器里是**两个独立事件** ⇒ 监听必须**常驻**，且清理判据必须是**状态**（占位是否已实际加载）而不是 src 值：**禁止**改回 `{ once: true }`（一次性监听会被占位自身那次消费掉），也**禁止**用「`src` 是否等于 `dataset.cdnSrc`」当「不必清」的依据——**同源重试成功**会被误判成不必清而残留降级态；② `src` / `currentSrc` 回读可能被环境规范化（未编码的 `<>`），故占位判定只认 `data:image/svg+xml,` **前缀**（`isPlaceholderSrc()`），**禁止**全串精确比较。
- **残留标记的实际危害与修法（已修）**：降级标记残留时，若该元素被组件换成新源后又失败，实测呈 `naturalWidth=0` / `visibility:visible` / `src` 仍为失败 URL ⇒ **可见破图**——两个成因叠加：`img[data-cdn-down]:not([data-cdn-placeholder])` 被残留的占位属性挡住（`:not()` 不命中），且 `markDown` 首行的 `if (img.dataset.cdnDown) return` 早退、不再重新落占位。修法 = **`watchDegradedSrcSwap(img)`**：`MutationObserver` 观察 `src`，当元素带 `data-cdn-down` 且新 `src` 既非记录的原失败源、也非占位时**先 `clearDegrade`**，把元素还原成普通图片，让新源自己的 `error` 重新走完整回退链（含重新落占位）。该路径被 happy-dom 的同步语义掩盖、**只有真实浏览器能复现**，故定稿前由独立验证在**真实 Chrome** 上复测；同场景下新建元素本就直接落占位，故此前未被发现。

**中性**

- `data-cdn-down` 的语义未变（仍是「已降级」标记），新增的只是「降级后是否显示占位」这一分支。
- 本轮作用面**限定为图标位**（技能图标 / 附加能力 / 强化来源图标 / 对比模式）：其它自带语义兜底的图标面不改，其分工与优先级见下节。

## 分工与优先级（已证成，非待办）

全局中性占位只服务**没有任何组件级兜底的图标面**（本轮 = 角色详情页技能图标 / 附加能力 / 强化来源图标 / 对比模式）。有组件级兜底的站点一律**组件胜**——全局委托在 document 捕获阶段先跑，组件的元素级 `@error` 后跑且最后写 `src`；组件的兜底源 `load` 后触发统一清降级（`clearDegrade`），委托留下的 `data-cdn-down` / `data-cdn-placeholder` / `dataset.cdnSrc` 全部退场，元素按组件自己的语义显示。逐面核对：

| 面 | 组件级兜底 / 处理 | 与全局占位的关系 |
| --- | --- | --- |
| 物品卡（`item.ts` 的 `onerror` + `catalog.css` 的 `is-broken` / `.nk-item-card__noimg`） | `onerror` 给 img 加 `is-broken` → `display: none`，同容器兄弟节点显示立方体线框 | img 被隐藏 ⇒ 占位不可见（最坏情况「`src` 已被换成占位但元素隐藏」= 视觉零变化） |
| 遗器部位图（`RelicView.vue::onPieceImgError`） | 元素级 `@error` 后改 `img.src` 为本地落盘的通用部位图标（local-first 白名单内） | 组件最后写 `src` ⇒ 显示语义兜底图标而非通用占位；其 `load` 触发统一清降级（`clearDegrade`），故无残留标记 |
| 终局 buff 星形（`renders.ts` 五处 `BUFF_ICON_FALLBACK`） | 同机制（组件内联 `@error` 换 data URI 源） | 组件胜 |
| gridFight 属性图标（`gridFightPropIconUrl` + 视图 `hideOnError`） | 组件隐藏 | 与物品卡同类 |
| Hero 立绘 | 走 CSS `background-image` | 无 `error` 事件，委托管不到 |

**仍留的一条真待办**：`data-cdn-noph` 属性当前**没有生产代码写入**——本轮实际生效的 opt-out 只有 `isCdnDown()` 短路的 `markDown(img, true)`。该属性是为将来「有意空图位」预留的入口（`dom.ts` 有分支、单测覆盖），**不得**在文档或断言里写成已启用。

## 替代方案

| 方案 | 为何未采用 |
| --- | --- |
| 只改数据（converter 全量归一命名） | converter 离线判定不了 nanoka 真存在的文件名（1310 与 1212 互为反例），且归一后 1310 的 3 行在 nanoka 反而 404 ⇒ 既修不完，又把「本来能加载的资产」交给运气 |
| 只做占位、不做回退链 | 占位会盖住本可恢复的资产（1212 在 jsDelivr 新旧命名皆 200）⇒ 用「缺图」的视觉替换掉能加载的真图，比空白更糟 |
| 组件级各写一份占位（每个组件在自己的 `error` 里换） | 三处消费方重复同一逻辑；且与全局委托的回退链抢时序（capture 先于 target），必然出现「组件还没换、委托已换」的竞态 ⇒ 占位必须单点声明、由委托统一决定 |
