# 0025. 贪饕污染专题页与导航第 8 板块

## 状态

`accepted`（**已实现**：新增 `converters/voracity.py` → `public/data/cn/voracity.json`；新增 `/voracity` 单页专题并入 AI 快照契约；侧栏常规模式追加第 8 项；敌人详情加「受『贪饕』侵蚀」标记与回链。**替代方案表第 3 行的理由已被 ADR 0026 推翻**：污染等级本就是终局玩法的关卡级维度，本 ADR 的形态决策不变）

## 背景

4.6 上游快照（`game_version 4.6.0`，`synced_at 2026-09-28`）含一整套此前未转换的「贪饕」侵蚀/污染体系：活动面板 `ActivityPanel` 10190 + `ActivityVoracityInvasion*`、关卡侵蚀 `StageInvasionBuff/Config`（敌方 `MazeBuff` 3034001–3034003、玩家支援 3034011–3034013）、状态词条 `StatusConfig` 66002001「饕噬」等、教程图文 `TutorialGuideData` 1050101/1050201/1050202、货币战争位面词条 `GridFightAffixConfig`。「贪饕」的怪物与赛季条目早已在站（`monsters/5034010`、`5023020`、`5014030`；忘却之庭 1033/1035/1036、异相仲裁 7/8/10），但**机制本身在站点完全缺席**（`tools/converter/incremental.py` 的 `MODULE_SOURCES` 未登记上述表）。

三条约束决定了形态：

1. 站点既有页面形态只有三类——配置驱动目录页、实体详情页、枢纽页；本内容是「一次活动 + 一套跨模式机制」，既不是目录（条目仅 20 余条且异构），也不是单一实体。
2. 污染数据跨终局战斗绑定（`ChallengePeakBattle_GluttonyAbility_*`）与货币战争位面词条两个域，塞进 `endgame` 或 `monster_detail` 会破坏模块边界。
3. 站点另一套同名概念（4.5 起 Fate 联动「圣杯战争·污染等级 / 深度污染 / 污染词条」，`FateArea.json` 等）与「贪饕」侵蚀无任何关联，混称会制造错误事实。

经逐项确认（12 项决策）：交付形态 = 单页专题 + 数据层；范围 = 活动与愿力 + 关卡侵蚀 + 状态词条 + 教程图文 + 位面词条五块；Fate 污染不收录、只作区分说明；展示全字段（等级/参数/图标/波及关卡/怪物名单内链）；路由与入口 = `/voracity` + 侧栏常规模式第 8 项（追加在末尾）；数据产物 = 新建 `voracity` 模块单文件；纳入 AI 可索引快照；教程图新增 `tutorialpic` CDN 分类（实测命中前走中性占位）；敌人详情加标记与回链；写本 ADR；验证级别 T2。

## 决策

**我们采用「单页专题」作为第三种页面形态**：`/voracity`（H1「贪饕污染」）承载 `public/data/cn/voracity.json` 的全部污染条目，按「活动与愿力 / 关卡侵蚀 / 状态词条 / 教程图文 / 货币战争位面词条」分区渲染；数据由新模块 `converters/voracity.py` 单独产出，不与 `endgame` / `monster_detail` 混表；侧栏常规模式在**末尾**追加第 8 项入口；敌人详情对名单内怪物显示「受『贪饕』侵蚀」标记并回链专题页；该路由纳入 `gen-ai-endpoints` / `check-ai-endpoints` / `vercel.json` 三处快照契约。

## 后果

**正面**

- 4.6 的「贪饕污染」首次在站内可读、可检索、可被 AI 快照引用，并与已有贪饕怪物/赛季条目互链成网。
- 数据边界单一模块：后续版本补数只跑 `--only voracity`，增量判据不受其他模块影响。
- 「污染」两套体系的区分写进 `CONTEXT.md`，避免同一词被合并叙述。

**负面**

- 导航首次从 7 项扩到 8 项：≥768px 全部平铺（侧栏 140px 可容纳 4 字标签），**<768px 手机底栏从末尾开始折叠**，新项在窄屏最先进入「更多」抽屉（侧栏 DOM 锚点数为 **9** = 首页枢纽项 + 8 板块，勿把两者混为一谈）；`e2e/layout.spec.ts` 的折叠/前缀断言仍成立，其注释与 `e2e/accessibility.spec.ts` 的页面清单已同步。
- 专题页是新形态：AI 快照契约（`docs/agents/ai-discoverability.md` §2/§3/§4）必须为它单列一行并明确**不用** `nk-snapshot__entry` 条目级断言（该标记的语义被守卫按「12 个目录页 + 枢纽页」定义），否则会把专题页的列表误计入覆盖率。
- 教程图走新 CDN 分类 `tutorialpic`：nanoka 未命中时只有中性占位，视觉完整度依赖外部源；该分类与 `jsDelivr` 规则无关，属新增维护面。
- 敌人详情标记依赖「实例 MonsterID → 模板 ID」解析（`MonsterConfig` 映射）：解析不到的名单项不显示标记，页面与数据存在可见差集。

**中性**

- 愿力是二相乐园玩法的通用计量而非本机制独有概念，专题页只呈现其在污染循环中的分档作用。
- 「贪饕污染」为站点工作名（H1 与导航文案），游戏内并无此合成名词：活动名取官方「镇伏『贪饕』，汇聚愿力」，机制名取官方文案里的「『贪饕』侵蚀污染」。
- 图标口径**按消费方分族**（不统一成一种）：`affixes[*].icon` 与源表 `IconPath` 同形走 `gridFightIconUrl`，其余 icon / 教程图走 `buffIconUrl` / `tutorialPicUrl` / `monsterIconUrl`；映射见 [docs/data/转换器字段映射.md](../data/转换器字段映射.md) voracity 段。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 仅数据层（converter 输出 JSON，前端不展示） | 用户看不到内容；且新可索引路由的守卫成本不会因此减少 |
| 做成配置驱动目录页（一条一卡 + 筛选） | 条目少且异构，「玩法说明 + 波及关卡 + 数值参数」塞进卡片会丢上下文，还要为一页新增目录 ID 与快照条目级断言 |
| 嵌入现有页面（终局详情 / 敌人详情加标记与说明段） | 当时据「污染不属于终局四模式」判定改动分散且会形成多处第二事实源。**该前提已被 ADR 0026 证伪**（14 个污染关卡全在终局关卡表内）：专题页继续承载活动 / 状态 / 教程 / 位面词条，终局侧的关卡级维度由 0026 以 converter 单源方式补齐，两者不互为第二事实源 |
| 把 4.5 Fate「圣杯战争·污染」一并收录 | 两套机制无关联，合并会把专题主题从「贪饕污染」漂移成「污染总览」，需额外转 Fate* 表 |
| 不新增侧栏项，只靠内链进入 | 页面几乎不可达，与站内「内容必有入口」的现状不一致 |
