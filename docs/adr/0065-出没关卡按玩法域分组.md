# 0065. 出没关卡按玩法域分组（7 域 + 域内子模式）

## 状态

`accepted`（**已实现**：`monster_extra.load_appearances` 产出 `groups[]` + `_appearance_submodes`
+ `_APPEARANCE_DOMAINS`；`MonsterDetailView.vue` 出没区块改为「计数 → 玩法域 → 子模式 → 各域样本」；
`monster-detail.css` 增 `.nk-mob-appear__group*` 一组；13 语言新增 `mob.dom.*` / `mob.sub.*` /
`mob.appearModes` 并改写 `mob.appearSourceNote` / `mob.appearCensus`；`gen-ai-endpoints.mjs` 出没行带域；
`pytest` 12 例（域拆分 / 类型闸 / 兜底 / 子模式 / 样本槽位）+ `e2e/layout-monster.spec.ts` 域结构断言；
`public/data/cn/monsters/*.json` 全量重生成 2,722 份 + 13 份 `i18n/*/monsters.json`。**取代
[0047](0047-出没样本只展示玩家可见关卡名.md) 的「至多 3 条样本」与「单一 total」形态，样本名判据与
`total` 口径一字未改**）

## 1. 背景与问题

用户提出出没区块的两个极端：「有的敌人没有出没关卡，有的敌人出现在超多的关卡中」，要求从源数据
一步步向上检索，判断这些关卡能否被梳理成玩家可认知的结构。

盘点（一次性探针，未入库；只读 `ExcelOutput`，未写 `vendor` 与产物）：

| 事实 | 数字 |
| --- | --- |
| 出没记录（模板 × 关卡） | 68,169 条 / 29,515 个关卡 / 33 种 `StageType` |
| 单怪 `total` | 中位 13、p90 433、最大 2,324；`>200` 的 87 个、`>1000` 的 16 个 |
| 目录页 | 632 条，544 条有记录、**88 条无记录** |
| 有名字的记录 | 12,302 / 68,169 = **18.0%**（[0047](0047-出没样本只展示玩家可见关卡名.md) 的 501 条样本） |
| 单域页面 / 多域页面 | 301 / 243 |

旧形态（[0047](0047-出没样本只展示玩家可见关卡名.md)）只给「出现在 N 个关卡」+ 至多 3 条样本，
于是 `2024011`（丰饶玄鹿·完整，9 关：模拟宇宙 4 + 差分宇宙 5）只剩一句「出现在 9 个关卡。」，
而 `2022010`（魔阴身士卒，2,324 关）的 2,324 是个无法解释的数字。

## 2. 判定

把 2,253 张表按 `StageID` 反向扫一遍（一次性探针），玩家的可认知结构分三层，**只有第一层是全覆盖**：

| 层 | 判据 | 覆盖 | 结论 |
| --- | --- | --- | --- |
| L1 玩法域 | `StageConfig.StageType` | **100%**（33 种值全覆盖） | 可做 |
| L2 子模式 | 终局四表 / `CocoonType` / `FarmElementConfig` | 终局 1,623/1,695、常驻 917/959 + 203/203 | 可做，仅这两域 |
| L3 关卡名 / 章节 / 期数 | 精确 `StageID` 连接 | 18.0%，且全落在 L2 的两域 + 活动 | 主线、模拟宇宙、差分宇宙、角色试用**无解** |

断裂点有实测证据：主线 20,075 关在 2,253 张表里**只有掉落表 `PlaneEvent` 引用**（99.6%），该表字段
只有 `EventID / WorldLevel / DropList`，天生不带名字；模拟宇宙 2,405 关只多一张 `RogueMonster`
（`EventID → NpcMonsterID`，同样是敌人而不是关卡名）。`MainMission.ChapterID` 存在，但没有任何表把
Mainline StageID 接到 MainMission；`RogueAreaConfig` 有「第一世界…」与区域怪物表，但没有任何字段
指向 VerseSimulation 的 StageID。

88 个「无出没」也不是数据缺口：28 个只出现在开发测试关 `StageTestConfig`、22 个敌人在别的玩法自己的
怪物表（`GridFightMonster` / `RogueMonster` / `NPCMonsterData` / 差分宇宙位面饰品）、38 个无任何表
引用（AI 召唤子体如丰饶玄莲、合体部件如喰云之首）。

## Considered Options

- **给主线补章节（按 `MainMission.ChapterID` 或关卡 ID 段）**：放弃——无外键；按 ID 段推等于自造判据，且实测 mainline StageID 段与章节不构成映射（`2041` / `2042` 两段各 1,900 关却横跨多期）。
- **把 `StageConfig.StageName` 请回来当关卡名**：放弃——[0047](0047-出没样本只展示玩家可见关卡名.md) 已裁决它是敌方标识（181/742 样本与本怪同名、160 个同 TextMap hash）。
- **只保留 `total`、把样本列到 6–10 条**：放弃——不解决「2,324 是什么」；样本仍挤在同一个平面，玩家读不出「这只怪主要在主线剧情出现」。
- **按 `StageType` 原样上屏（33 行英文枚举）**：放弃——维护者语言，且没有中文标签源（[0047](0047-出没样本只展示玩家可见关卡名.md) 已登记这一点）。
- **把模拟宇宙与差分宇宙并成一个域**：放弃——`2024011` 这类只活在两个宇宙玩法里的敌人会退回「出现在 9 个关卡」，正是本次要修的那句话。
- **把「战斗教学」也做成独立域**：放弃——27 个页面、70 条记录，独立成域不值得一行；落 `other` 兜底（`other` 同时承担上游新增枚举的兜底职责）。

## 3. 决策

1. **payload = `appearances: {total, groups[]}`**（`samples[]` 不再挂在顶层；`total` 口径与
   [0047](0047-出没样本只展示玩家可见关卡名.md) 完全一致）：
   `groups[] = {key, count, subs?, samples?}`，`subs[] = {key, count}`。
   域按 `count` 降序、平手按固定域序；子模式同样降序 + 固定序——**排序确定性是快照可复现的前提**。
2. **7 个玩家域 + 1 个兜底**（`StageType → key` 单点映射，未登记值落 `other`）：

   | key | 玩家侧 | 收哪些 `StageType` |
   | --- | --- | --- |
   | `mainline` | 主线剧情 | `Mainline` |
   | `simulated` | 模拟宇宙 | `VerseSimulation` / `RogueChallengeActivity` / `RogueEndlessActivity` |
   | `divergent` | 差分宇宙 | `RogueRelic`（差分宇宙的位面饰品提取） |
   | `endgame` | 终局挑战 | `Challenge` |
   | `farm` | 常驻副本 | `Cocoon`（拟造花萼 / 侵蚀隧洞 / 历战余响）、`FarmElement`（凝滞虚影） |
   | `trial` | 角色试用 | `Trial` |
   | `activity` | 活动 | 18 个 `*Activity` / `FightFest` / `BoxingClub` / `TreasureDungeon` / `Heliobus` / `SwordTraining` / `LocalLegend` / `ExpeditionBattle` 等 |
   | `other` | 其他玩法 | `BattleCollege`、`PunkLord` 与任何未登记的新枚举 |

   实测记录占比：主线 62.7% / 活动 11.9% / 终局 10.4% / 模拟宇宙 9.0% / 常驻 4.4% / 角色试用 0.8% /
   其他 0.5% / 差分宇宙 0.3%。
3. **域内子模式只给终局与常驻**（两域都是「同一关卡在配置表里有层级归属」）：
   - 终局：`ChallengeMazeConfig` / `ChallengeStoryMazeConfig` / `ChallengeBossMazeConfig` 的
     `EventIDList1/2` 与 `ChallengePeakConfig.EventIDList` → `memory` / `fiction` / `apocalypse` /
     `anomaly`；四表实测互斥（零重叠）、覆盖 1,623/1,695，**余 72 关只落 `endgame`、不臆造子模式**。
   - 常驻：`CocoonConfig.CocoonType` → `calyx`（`TYPE_NORMAL`）/ `cavern`（`TYPE_RELIC`）/
     `echo`（`TYPE_WEEK`），`FarmElementConfig.StageID` → `shadow`；实测 917/959 有 Cocoon 归属，余 42 关只落 `farm`。
   - **类型闸**：同一关卡 ID 被别的玩法的表列进来时按 `StageType` 拒收（与 [0047](0047-出没样本只展示玩家可见关卡名.md) 决策 2 同一条）。
4. **样本槽位改为「每域至多 2 条」**，同域内按「子模式 or 活动名」去重（= 同一活动只出一条），
   于是同一域里的多个难度档不再互相挤掉样本；页面上限从 3 条变 6 条（终局 / 常驻 / 活动三类可能同时有名）。
   实测：样本从 501 条增到 **657 条**（317 个不同关卡），有 chip 的页面仍是 **309**、只有计数的仍是 **235**
   ——**本次只改可读性，不改「谁有名」**。
5. **域与子模式上屏的是 UI 词典键，不是上游枚举**：`mob.dom.*` / `mob.sub.*`。其中 12 个能溯源到官方
   术语（主线剧情 / 模拟宇宙 / 差分宇宙 / 角色试用 / 活动 / 忘却之庭 / 虚构叙事 / 末日幻影 / 异相仲裁 /
   拟造花萼 / 侵蚀隧洞 / 历战余响 / 凝滞虚影 走 `tools/fill-ui-messages.py` 的 LABELS 自动取 13 语言官方
   译文），3 个站点自造（终局挑战 / 常驻副本 / 其他玩法）走 AUTHORED，`mob.appearModes` 同理。
6. **正文文案按新形态重写**：`mob.appearSourceNote` 改「每个玩法至多列 2 处；没有关卡名的玩法只显示数量」，
   `mob.appearCensus` 补「玩法按关卡所属玩法归档」，删掉 `mob.appearSamples`（进 `REMOVED_KEYS`）。
7. **AI 快照同一结构**：出没一行改为「N 个（域 计数 / 域 计数 … ；如 关卡名 / 关卡名）」，域取前 4 个，
   样本取前 2 条——快照是事实表，不解释、不排序以外的加工。

## 5. 后果

- 「超多关卡」变成可解释的数字：`2022010` → 主线剧情 1899 · 模拟宇宙 208 · 终局挑战 154（忘却之庭 138 /
  虚构叙事 9 / 末日幻影 4）· 活动 35 · 常驻副本 21（凝滞虚影 14 / 侵蚀隧洞 7）· 角色试用 6 · 其他玩法 1；
  87 个大怪的头部域计数占其中位 69.7%，拆开后第一行就把量级说清楚了。
- `2024011` → 「9 个关卡 · 2 个玩法（差分宇宙 5 / 模拟宇宙 4）」，不再是信息真空。
- **边界没有变**：235 个页面仍然只有计数（其中 202 个是单域），88 个页面仍然没有出没记录。前者是上游
  没有名字源，后者是这些模板不进 `StageConfig` 波次；域分组只保证「有的数字都能读懂」，不制造名字。
- 若日后上游给主线/模拟宇宙补了章节或区域外键，只需在 `_appearance_submodes` 加一条源、在 `groups.subs`
  多一个键，页面零结构改动。
