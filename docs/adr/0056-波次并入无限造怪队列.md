# 0056. 虚构叙事波次并入无限造怪队列（`StageConfig.MonsterList` 只是配置预览）

## 状态

`accepted`（**已实现**：`tools/converter/converters/endgame.py` 新增
`_stage_infinite_group` / `_infinite_groups` / `_placeholder_templates`（均进程内缓存），
`_load_stage_monsters_by_id` 对声明 `_StageInfiniteGroup` 的关卡先把预览槽位按怪种去重、
剔除占位美术模板，再按位并入 ∞ 造怪队列怪种；`incremental.py` 的 `endgame` 模块登记
`StageInfinite{Group,WaveConfig,MonsterGroup}.json` 三张表；`public/data/cn/maze_extra.json` /
`maze_peak.json` 与各自 catalog、语言包同批重生成，`maze.json` / `maze_boss.json` 逐字节零变更；
`pytest tools/converter/tests/test_endgame.py::TestInfiniteWaveMerge` 7 例。

**决策 7/8 系首版发布后的修订**（用户提供游戏内节点预览截图：3 波 × 3 格、等级 85）：
首版按「预览槽位保序保留（含波内重复）」合并，2026 每半场得到 6/3/3；截图证明游戏内是 3/3/3）

## 1. 背景与问题

用户问「`/endgame/story/2026` 每个波次怪物数量和类型，对得上吗」。核对结论分两口径：

- **站点当前口径与上游逐条一致**：关卡 `ChallengeStoryMazeConfig.EventIDList1/2` →
  `StageConfig.MonsterList`，8 个半场每半场 3 波、波次怪物数 5/1/1，逐波 ID 序列（含波内重复）
  与上游完全相等；id / 名称 / 阶级 / 弱点 / 抗性 / 阵营 **56/56 零差异**；波数 3 与 `_Wave=3` 一致。
- **同一批关卡自引用另一套表，站点零消费**：`StageConfigData._StageInfiniteGroup` → 
  `StageInfiniteGroup.WaveIDList` → `StageInfiniteWaveConfig.MonsterGroupIDList` →
  `StageInfiniteMonsterGroup.MonsterList`。最后一张是**造怪队列**：2026 每半场第 1 波 26 条
  （首个是「虚构集合体」8003060）、第 2/3 波各 41 条，队列里比站点多 1/2/2 个怪种。
- **官方教程原文**（TextMap `1191649273845450124`）：「「虚构叙事」中的所有战斗有轮数限制……
  战斗结束前，敌人被消灭后会<不断补充>」⇒ 队列才是战斗内实际出现的怪种来源，
  `MonsterList` 是开战前的配置预览。
- **是系统性差距，不是本季异常**：27 期（2001–2027）共 215 个虚构叙事关卡全部声明 ∞ 组，
  每期 8 个半场全有缺口；`2011` 期起第 1 波出现「虚构集合体」（与图鉴实装 2.7 吻合）。
  ∞ 表此前**全仓零消费**（`converters/` 无读取点、`incremental.MODULE_SOURCES` 未登记）。
- **两张表不是包含关系**：`8003060`「虚构集合体」在整个 vendor 里
  **0 / 99,393** 个 `StageConfig` 波次槽位、只出现在 140 个 ∞ 造怪组 ——
  「波次名单里没有它」推不出「它不是战斗内的敌方」。

## 2. 判定

**是本站的口径缺陷**：把「配置预览」当成了「该波会出现的敌人」。虚构叙事战斗内敌人被消灭后会
持续补充，预览槽位（5/1/1）不代表该波实际阵容；因组建队与弱点规划要看的恰恰是后者。

**二次判定（决策 7/8 的由来）**：补齐队列怪种后仍与游戏内不符——站点 6 格 vs 游戏 3 格。
差异有两处来源：① 预览槽位里的**同波重复**（`A,B,C,A,B`）被逐槽渲染成 5 张卡；
② 队列首位那 1 个「虚构集合体」既无独立美术、游戏内也不显示。
游戏内节点预览的口径是**每波每种敌人一格**，故上面两处都要按怪种收敛。

## Considered Options

- **只加文案说明、不补数据**：放弃——用户裁决采用补全口径。
- **用 ∞ 队列替换 `MonsterList`**：放弃——预览槽位（含波内重复，如 `A,B,C,A,B`）是官方预览形态，
  与页面上其它模式同源同结构；且队列含补位重复（26 条只 4 个怪种），逐条上屏会渲染重复卡。
- **新增「补充怪种」字段 + 前端分区**：放弃——要为新增分区自造 13 语言 UI 译文（与「不写死中文 /
  不自造译文」相抵），且同一波的怪种本就该在一处呈现。
- **按 ∞ 波数新建波次**：放弃——关卡自身声明的 `_Wave` 才是波数（实测 1,961/1,962 与预览波数相等）；
  「∞ 波数更多」的 23 个早期关卡里 **16 例尾部波次就是前序波次的重复**，材质化会造出游戏里
  没有的「第 N 波」。
- **预览槽位保序保留（含波内重复）**：放弃——这是本 ADR 首版采纳的形态，被游戏内节点预览截图推翻：
  2026 第 4 层节点每波只出 3 格，而站点渲染 6 格（`A,B,C,A,B` 五个槽位 + 并入的队列怪种）。
  配置预览的槽位重复是**给引擎摆位用的**，不是给玩家看的阵容；玩家看的是「这一波有哪几种敌人」。
- **硬编码 ID 排除「虚构集合体」**：放弃——`8003060` 是上游 ID，写死会在上游换表时静默失效；
  且同类载具不止一个（见决策 8 的判据命中 2 个模板）。按数据判据（占位美术）排除才自洽。
- **采用**：在 `_Wave` 声明的波数内按位合并；**合并前先把预览槽位按怪种去重**，
  并剔除**占位美术模板**（无独立美术的机制载具，如「虚构集合体」）；
  ∞ 多出的尾部波次不落并 `warning` 留痕。

## 3. 决策

1. **判据** = `StageConfigData._StageInfiniteGroup` 存在。终局四模式实测：虚构叙事 215 关、
   异相仲裁 5 关、虚构叙事星启附加关 12 关带它；忘却之庭 1,199 关 / 末日幻影 168 关 **0 条**
   （故这两个模式产物零变更）。
2. **合并粒度 = 怪种**（队列去重保序）。队列是补位序列，逐条落会渲染重复敌方卡。
3. **合并范围 = 关卡声明的波数**（预览非空波次数量）。`∞ 波数 > 关卡波数` 时尾部不并入 +
   `logger.warning` 留痕（7 例尾部非重复，见「后果」的已知边界）。
4. **落点 = `_load_stage_monsters_by_id` 的 `waves`**，故层上下半场 / 星启节点 / 异相仲裁单关 /
   期级合并列表 / catalog / AI 快照**同源同口径**；不新增字段、不改类型、不改前端与 i18n。
5. **不消费** ∞ 表的 `MaxMonsterCount` / `ParamList` / `EliteGroup`（语义未验证：`MaxMonsterCount`
   与队列长度并不总相等）——只记入字段映射的「已看过、未消费」。
6. **不覆盖 [0046](0046-出没样本名改取活动表实名.md) 决策 5**：怪物「出没」样本的 `total` 仍不含
   无限编组池（`monster_extra.load_appearances` 直读 `StageConfig`，本轮未动）。
7. **波次粒度 = 怪种集合**（用户裁决，取代首版的「槽位保序保留」）：声明 `_StageInfiniteGroup` 的
   关卡，其**全部**波次都按首现序去重后再合并——游戏内节点预览每波每种敌人只出一格，
   而 `MonsterList` 的槽位会重复（2026 第 1 波 `A,B,C,A,B` 五个槽位只 3 个怪种）。
   去重是**关卡级**的，不按「该波有没有队列」分期：46 个关卡的 ∞ 组波数少于关卡波数
   （如 `425001` 关卡 3 波而 ∞ 组 1 波），只处理被并入的那几波会让同一关卡一半去重一半不去重。
8. **剔除占位美术模板**（用户裁决「虚构集合体改成不显示」）：判据 = `MonsterTemplateConfig` 的
   `IconPath` / `RoundIconPath` / `ImagePath` 任一 basename 为 `Monster_Unknown.png`
   （源路径 `SpriteOutput/BattleEventIcon/`）。实测全表 632 条**恰 2 条**命中且三条路径同时占位、
   `ManikinImagePath` 另借 8001010 的头像：`8003060`「虚构集合体」与 `5013090`「破晓战队」
   ——两者同为 Elite、共用 `XP_Minion01_00.prefab`，是**机制载具**而非可辨识敌人
   （`8003060` 在 `StageConfig` 全库波次槽位里 0 次、只出现在 140 个 ∞ 造怪队列首位；
   `5013090` 只在 7 条主线关卡露面、不在任何 ∞ 队列）。这类模板上屏会显示别只怪的头像
   （`8003060` 的 `icon` 就是 `Monster_8001010`），与游戏内预览不一致。
   剔除只发生在声明 ∞ 的关卡上，并 `warning` 留痕（命中模板 + 关卡数）。
9. **未声明 ∞ 的关卡不做上述两步**：那里的波次是**有限的出场名单**，槽位重复是官方排布
   （忘却之庭 1,254 个波次带波内重复）——是否也按怪种上屏见「待裁决」。

## 5. 后果

- 虚构叙事 2026 每半场波次怪种数 **3/3/3**（每半场 9 条）——与游戏内节点预览逐波一致
  （用户提供截图：3 波 × 3 格、等级 85）。首版口径为 6/3/3，合并前为 5/1/1。
- 全量实测（HEAD ↔ 本次产物）：`maze_extra` 231 个波次内容变化、`maze_peak` 19 个；
  `maze.json` / `maze_boss.json` **逐字节零变更**（未声明 ∞ 的关卡不受两步影响）。
- 「虚构集合体」`8003060` 在 `maze_extra.json` / `maze_extra.catalog.json` 中出现 **0 次**
  （此前 186 / 34 次）；全仓 `monsters.json` 与 `monsters/8003060.json` 不受影响（图鉴是另一模块，
  该敌人仍可在怪物详情页查到——剔除的是「关卡波次上的展示」，不是图鉴收录）。
- 期级 `monsters` 54 → 53（2026）；`final_monsters` 为 `8024013 / 5024014 / 402301002 /
  201302012`——首版（含「虚构集合体」）下它曾被 `8003060` 挤占（该连带效应随决策 8 消解）。
- AI 快照的「N 名敌方」与赛季详情敌方清单同步（读同一份产物，无生成器改动）。
- 忘却之庭 / 末日幻影页面与产物零变更；异相仲裁期级清单 10 期里 4 期变全、代表阵容零变化。
- **已知边界（记录备查）**：
  1. 23 个虚构叙事早期关卡（`_Wave=2`）的 ∞ 组有 3 个波次，其中 7 例第 3 波不是前序波次的重复
     ⇒ 按本 ADR 不材质化、只 warning。若后续确认它们是真实第三波，需另开决策（届时要一并核对
     `_Wave` 是否也需要改口径）。
  2. **待用户裁决**：未声明 ∞ 的关卡（忘却之庭 1,254 个波次、末日幻影 0 个）仍有波内重复槽位
     （如 `A,B,A,B`）。本 ADR 决策 9 保持原样，理由是那里的波次是有限出场名单；但游戏内预览是否
     也按怪种合并，本轮**无截图证据**，不擅自扩大口径。
  3. **待用户裁决**：`_placeholder_templates()` 的判据（占位美术）同时命中 `5013090`「破晓战队」，
     它在 7 条**主线**关卡（`205110550`–`205110556`）的波次里出现。那些关卡不声明 ∞，
     故本轮不动；主线是否也该剔除是另一域的口径问题。

## 6. 待用户裁决（本轮不做）

1. **未声明 ∞ 的关卡是否也按怪种合并**（见「已知边界」2）：忘却之庭有 1,254 个波次带波内重复
   （如 `A,B,A,B`），当前逐槽渲染。截图只覆盖了虚构叙事，故不扩大口径。
2. **主线关卡里的同类占位载具是否也剔除**（见「已知边界」3）：`5013090`「破晓战队」
   在 7 条主线关卡的波次里出现，判据与 `8003060` 完全同类。
