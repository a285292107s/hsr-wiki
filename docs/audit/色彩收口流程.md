# 色彩收口流程（评审闸）

> 依据 ADR 0011（语义：黑阶 / 双色约束 / 领域豁免）与 ADR 0012（架构：事实链 / 三道闸门）。
> 本流程是「新增颜色」的必经评审闸：任何新颜色进入代码前，必须走完四步并跑通门禁。

## 四步流程

### 第一步 · 查令牌

新增颜色前，先在 `src/styles/tokens.css` 三层令牌中检索：

| 层 | 令牌族 | 用途 |
|---|---|---|
| 原始层 | `--ph-*` / `--gold-*` / `--blk-*` | 色阶事实（Purple Heart 紫 / 金阶 / 中性黑阶） |
| 语义层 | `--primary` / `--bg` / `--surface` / `--card` / `--text*` / `--border*` / `--nk-*` 外壳族 / `--accent`（主色梯度端） | 主题映射，随主题切换 |
| 领域层 | `--rarity-*` / `--prop-*` / `--elem-*` / `--skill-*` / `--eg-*` / `--diff-*` / `--season-*` / `--cw-*` / `--crole-*` / `--ctrait-*` / `--hero-bg-*` | 数据语义色，不随主题 |

**已有可用令牌 → 直接引用，流程结束。**

### 第二步 · 定层级

没有可用令牌时，按「数据语义 / 主题映射 / 色阶事实」判定归属：

- **数据语义色**（游戏内约定、字段含义色）→ 领域层新增令牌（如 `--cw-*` 族）
- **主题映射色**（随主题变的面板、强调、文字）→ 语义层，且必须从原始层派生（`var()` 或 `color-mix`）
- **色阶事实**（新的色相家族）→ 原始层（需评审：新色相家族意味着新的主色族或领域语义族）

**原始层禁止直接消费**：页面 CSS 只能引用语义层/领域层令牌。

### 第三步 · 双色约束判定

新增/调整颜色时对照 ADR 0011 双色约束：

- 常规模式 = **黑与紫**：主题层（背景/表面/强调）禁止第三色相；金色仅允许出现在领域色豁免位
- 货币战争 = **黑与金**：主色位 = `gold-500` 金属金（唯一发光位），文字强调位 = `gold-300` 亮金，语义金 = `gold-600` 暗铜
- 领域色豁免（不参与约束）：星级 / 属性 / 元素 / 技能类型 / 强化角标 / 文本高亮——常规模式保持金色
- 导航语义豁免：网关卡 / 交换按钮的「金色=CW 模式」标识（登记于 check-colors.mjs，见 ADR 0012 §3）
- `--accent` 必须是主色族成员（常规 `ph-400` / CW `gold-600`），禁止恢复独立色相

### 第四步 · 落 tokens + 跑门禁

1. 令牌落入 `tokens.css` 对应区段（原始层 / 领域层 / 语义层各自分区内）
2. 页面 CSS / JS 一律 `var()` / `color-mix` 引用；**禁止裸色值**（豁免见 ADR 0012：严格中性三分量差 ≤4、SVG data URI 内联白、var() fallback 必须中性或令牌）
3. 跑 `node tools/check-colors.mjs --strict` 必须全绿
4. 若确需新增豁免：必须在 `check-colors.mjs` 豁免登记区块登记（带理由 + ADR 引用），并同步 ADR

## 门禁与回归

- **本地**：`node tools/check-colors.mjs --strict`（每次颜色变更后必跑）
- **CI**：`.github/workflows/ci.yml` 已纳入该检查（push/PR 自动拦截）
- **视觉回归**：常规 + CW 双主题截图对比（重点：主色强调位、黑阶表面层次、领域金不受影响）
